#+title: Runtime integration mechanism benchmarks

Run from the Beam Lisp checkout root, with no other owned BEAM job:
#+begin_src sh
mkdir -p "$HOME/tmp/runtime-integration"
TMPDIR="$HOME/tmp/runtime-integration" timeout -k 15 2400 ./bin/bl run bench/runtime-integration/run.bl > "$HOME/tmp/runtime-integration/mechanisms.log" 2>&1
python3 bench/runtime-integration/summarize.py "$HOME/tmp/runtime-integration/mechanisms.log"
#+end_src
Apply the repository's memory ceiling when running. All fixtures are disposable;
no application/customer store, external embedding or LLM service is involved.

Runs record source revision/dirty state, compiler key, ERTS/Elixir and scheduler
count before the trials. The first archived run predates this metadata receipt;
it used the integration working tree and is retained as preliminary evidence.

* What is measured
- Negative query reuse: 1,000 entities, all blocked, ten identical queries per
  trial. Counterbalanced ABBA/BAAB execution; record elapsed time, caller
  reductions, real store operations and returned rows. Check result parity and
  relevant negative-write invalidation outside timing.
- Definition selection: 100 projections selecting two real definitions from
  tables containing 128 or 2,048 unrelated AST payloads. Compare the previous
  materialize-then-select strategy with Env/selected_ns_definitions. This is
  metadata work, not the duration of an entire source compilation.
- Native index economics: fresh Fjall stores with 100 and 1,000 entities. Include
  initial writes, complete construction, every advance-call latency, authoritative
  query-plus-sort reads, ordinary cached query-plus-sort reads, direct index reads,
  and maintained writes. The ordinary control is essential: a fast result cache
  can make constructing an index a loss even when it beats uncached scans.
- OS ownership: five trials of 20 actual port/flock acquire-release operations.
  This is an absolute safety cost, not a comparison with a Python lock prototype.

* Interpretation
The fixtures execute explicit run functions after their modules load. Performing
store work inside a required module initializer can deadlock its writer against
the loader; that is not part of a timed query trial.
Native advance latency includes caller/queue and completion telemetry, so it is
an upper observation for writer occupancy here, not a hard real-time guarantee.
The runtime records commit-inclusive writer time internally for adaptation.
Native JSON reduction counts are VM-wide; negative-query counts are caller-only.
Construction amortization from reads alone excludes ongoing writes and is not an
automatic production admission threshold. Runtime policy also debits writes and
never counts cache hits as expensive fallback demand.

These are mechanism controls on a shared host. Full application HTTP readiness
and browser URL-to-DOM measurements are separate Knowledger harnesses. Neither
microbenchmark ratios nor timings from earlier prototypes are page-load claims.
