* SDK metadata reuse
The native owner stores one decoded ownership inventory as individual rows.
Every independent lookup reads current inventory bytes. A complete-unit check
captures those bytes once and uses that same immutable input for all members;
the following check captures fresh bytes. Current source, executable bytes and
loaded module identities remain admission requirements.

This removes repeated complete ETF decoding and complete-map copies for each
row. Parsing costs one traversal per changed inventory; retained row lookup
costs depend on the requested row. Reading and comparing current bytes still
has a cost proportional to their length. The implementation does not rely on
timestamps to authorize reuse.

The inventory accepts at most 16 MiB of encoded input, 32,768 rows and a 32 MiB
serialized module map. BEAM artifact metadata has a separate 32 MiB serialized
data budget and bounded entries. Saturation declines memoization. These are
data budgets, not exact process RSS limits. Cache data grants no code custody.

* Mechanical release checks
The release startup runner uses private XDG directories and a neutral project.
It checks fresh/cold startup, zero SDK source compilation, retention of actual
SDK actors and persistent ownership of the first default request. Its optional
runtime regressions exercise metadata, inventory cache behavior, contention,
framework lifecycle, generated actor inventories and application packaging.
The release workflow enables these regressions for every target.

Runtime host checks preserve prepared SDK source/artifact pairs. They stage
edited hosts privately, verify that SDK retention keeps the edited AOT loaded,
and start the normal supervised owner collector. Sealed SDK ownership is
qualified with a complete SDK build. An unsealed build image supports explicit
SDK compilation; a sealed image cannot be edited underneath its inventory.

* Native owner lock ordering
A full SDK qualification captured an actual lock cycle during realm indexing.
A worker held a physical-module fence while waiting for an Env source-cache
reply. Env was claiming an unmanaged native start and waited for that worker's
fence. Neither process could proceed.

Custody-changing private owner turns now try the complete sorted module fence
set and the capacity fence before changing state. Contention releases all
acquired fences and retries outside the owner turn. Receipt rows are selected
again inside each attempt. Native launch cleanup skips contended rows. SDK
retention uses the same complete fence acquisition rule. Read-only observations
stay independent of these mutation fences.

Two deterministic tests hold each fence while starting a real native server,
wait for the owner's attempted acquisition, and require the holder to obtain an
Env reply before releasing its fence. The server must then start and serve a
request. The focused tests pass 4 tests and 14 assertions; broader contention,
framework, native start and realm indexing checks also passed. A framework test
now waits for the actual queued registration request before suspending its
sender, eliminating a separate fixture race.
