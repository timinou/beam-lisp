* Cache GC: command context was lost at the host task boundary
The exact CI failure reproduces locally with the checkout launcher: the
parallel sweep leaves four generations instead of three. The test configures
=BEAM_LISP_AOT_CACHE_DIR= through System's command-local environment overlay,
then launches raw host =Task.async_stream= workers. Host tasks do not inherit
the process dictionary. Workers therefore store and sweep another cache root.
This explains why a bare main-control VM with global OS settings passed.

The fixture conveys the actual caller context with =Env.convey= and checks each
worker's actual cache directory before storing. It explicitly establishes the
local overlay even in bare test VMs. The deletion and successful-store
assertions remain. Changing all host tasks to convey implicitly would change
host semantics; the existing build worker already conveys explicitly.

A separate production defect is the single ={root,time}= throttle slot:
interleaving A, B, A gives A a second deletion budget inside the same interval.
The repair uses bounded per-root timestamps, rechecks under a local root lock,
and avoids locking for an ordinary throttled store. A short publication lock
prevents concurrent roots losing timestamps. Saturation declines optional
cleanup instead of evicting live throttle entries. Throttles remain per VM;
this does not claim cross-process lifetime protection for shared generations.
A regression alternates roots and requires the second A generation to survive.

* SDK/runtime key queries computed discarded dependency keys
=AOT.ns_closure_hash= reaches =BuildPlan.key_for= for each namespace. That
function plans the namespace's complete graph, computes every member's key,
then selects one root key. The build driver repeats this for every selected
source. Sharing parsed source bytes does not eliminate these discarded folds.

The canonical planner now accepts an optional requested-root set. The ordinary
whole-build plan still computes every key. A single-namespace query uses the
same key-of function, coverage predicates and cycle handling, selecting only
the requested key. The compatibility memo uses this selection too.

Full-versus-selected controls cover interface references, macros, missing
sources and cycles. A 40-node chain query performs exactly one key fold rather
than 40. This removes the sum of all dependency closure-key folds per query;
it does not claim linear complete planning: graph closure materialization and
per-namespace resolver traversals remain.

* Compiler-child handoff custody
A parent-owned writer lock alone is insufficient for an external SDK child:
a killed request can drop the parent lock while the child still uses staged
sources. Claims now publish a unique cohort while excluding earlier readers.
A compiler child takes shared generation custody FIRST, then shared workspace
custody, and compares the exact claim before bootstrap or compilation. Both
resources stay with that child VM until exit. A replacement writer cannot
restage while a child is alive; a child starting after replacement refuses
before work. This also closes the GC window before child-language startup.

The Source claim helper uses the same protocol for focused controls. Killing
the writer with a live child excludes replacement; after child exit acquisition
succeeds. A stale cohort never executes its callback. The final four-driver
