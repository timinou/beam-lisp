## Implemented and verified

### Automatic private first/filter fusion

```clojure
(first (filter (fn [x] (> x 3)) (lists/seq 0 1000)))
```

The central optimizer recognizes the ordinary compiler ANF. It proves a materialized scalar source and a closed total predicate, reserves a bounded amount of generated code, and emits the existing halting kernel. A live `filter` binding is captured once. A runtime identity guard checks the callable selected at arity two; a failed guard invokes that captured callable with the already-evaluated original arguments. No source annotations or manually declared resolution markers grant authority.

The supported domain is deliberately narrow: proper scalar literal lists, ascending literal integer `lists/seq` sources, and literal one-argument predicates over scalar literals/parameters/locals/comparisons/if. Shared/escaping lazy values, resources, unknown helpers/captures, partial predicates and unproved sources stay baseline. Matching false/nil elements are preserved. Predicate proof work is capped at64 nodes, literal-list analysis at128 elements, and each consumer reserves64 nodes from the existing cumulative descriptor budget.

The enabled and reference fixtures compile into DISTINCT module atoms. Using one module name would make both `apply/3` thunks call the last-published optimized image and invalidate a differential benchmark.

### Safe selective corpus reuse

The base already reused unchanged embedding columns after unrelated transactions. This branch preserves that behavior and closes missing validity axes:

- a future durable pointer cannot answer a historical db value;
- a durable pointer binds its actual view and missing legacy view authority means rebuild;
- history/since/valid-time views use shared authoritative assembly and native constructors, without reusing or polluting complete-column slots/artifacts;
- complete-column marks are not attested from a restricted view;
- an ordinary similarity query still reads **zero embedding rows** after an unrelated write, and returns the same two hits.

This is the existing `datom.query.corpus` facility, not a new cache registry or generalized `datom/q` result memo. General query/policy certificates and live actor skipping remain FUP158. The zero-row result proves preserved selective reuse, not a new speedup over base. Native rows do not measure all bytes/seeks/provider work.

Tests use the existing `store-fjall/open-fresh` constructor. Opening `/tmp/x` only to obtain a suffix acquires an unintended shared native lease and collides with other test processes; the constructor owns the naming convention without that probe.

### Realm code-lifetime foundation

Realm drain retires code with `soft_purge`, not hard purge. Namespace, body, initializer and server modules are inventoried. Deleted modules with busy old code disappear from `code/all_loaded`, so a retirement inventory retains them until the code lease ends. Repeated drain cannot reset numbered body allocation while a lease is active. Once old code is actually purged, body names are reused rather than continually minting new atoms.

A real unowned caller survives close/repeated drain, old code remains until the caller finishes, and subsequent purge/name reuse is checked. The test observes the active body module, not the public callable shim. This is a foundation for AOT; it does NOT change the realm loader to cache/replay namespaces.

## Proof gates still pending

These are explicit deferred capabilities, not implementation claims:

- **FUP155 — per-segment realm AOT through the real loader.** Target-env compilation/replay, segment-keyed actual resolved closures, non-global body/init naming, initialization/failure/concurrency, reload behavior and macro/provider compile authority still need their own real-loader gate. The research adapter is not promoted as a second loader.
- **FUP158 — generalized query/policy read certificates and certified live skipping.** Arbitrary providers, cross-store policy/expiry and actual actor fairness/batching are not inferred from column marks. Existing manual-attrs refusal remains.
- **FUP159 — maintained authorized ranking and total-work admission.** No general bounded-query promise, fake count, global6*k correctness claim, or new query/page API is added. Candidate, visibility, native bytes/seeks/history and provider work must all be accounted for before promotion.
- **FUP160 — existing Env/kernel specialization.** The added wrapper is permanently rejected; any specialization must beat the already-memoized baseline.
- **FUP161 — cross-realm canonical sharing.** Conditional on remaining duplicate cost after safe per-segment real-loader integration; no speculative relocation.

No new Knowledger browser/render benchmark or full test suite was run. Runtime fixture savings, selective native-row reuse and project-startup benefits are different measurements; do not substitute one for another.
