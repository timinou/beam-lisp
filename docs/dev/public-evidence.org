#+TITLE: Check new public evidence before pushing

The repository's public evidence checker refuses actual Lisp source units whose
leading namespace declaration belongs to the private products =knowledger= or
=foundry=. It scans the NEW Git objects reachable through every commit in a
publication range. Removing or sanitizing an archive at HEAD does not remove its
original blob from the range. Filenames and archive member suffixes do not decide
whether source is private: renamed members are inspected as raw bytes.

#+begin_src sh
python3 -m unittest discover -s scripts/tests -p test_public_evidence.py
python3 scripts/check-public-evidence.py --base origin/main --head HEAD
#+end_src

A refusal reports the blob identity and a fixed category/namespace, never source
payload. Do not copy a private source unit into a public fixture to test it. Tests
use synthetic two-line source units in temporary HOME directories. An ordinary
public probe declaring its own namespace and containing quoted private namespace
examples passes. Comments, shebangs, BOM and namespace metadata cannot conceal a real
leading declaration.

* Optional local pre-push hook
=scripts/hooks/pre-push= reads Git's ordinary update lines. Existing branches scan
local minus the exact remote tip; new branches scan unpublished objects against
that remote's already-known tracking refs. Deleted refs add no content. Missing
required objects, shallow history or malformed input refuse. Local replacement
refs/grafts cannot hide the actual publication graph. Refresh tracking refs normally before
publishing a new branch if the local remote view is stale.

The checker does not install or replace hooks and does not change Git config.
If no =core.hooksPath= is configured and =.git/hooks/pre-push= does not exist, a
maintainer can explicitly copy the source hook there. If a hook/config already
exists, compose it manually and preserve its input: Git supplies the ref updates
on stdin, so two consumers need the same captured update lines. Never replace
another hook merely to enable this check. Git's =--no-verify= can bypass local
hooks; CI runs the range check again before either native build job.

* Bounded inspection and limits
Supported containers are raw tar and gzip/bzip2/xz streams. Compression and tar
are inspected in memory without extracting or executing members. Unsafe paths,
links/devices/FIFOs, duplicate members, trailing tar payload, concatenated
compressed streams, unsupported containers such as ZIP/zstd/7z/RAR, and budget
exhaustion refuse. Archive recursion is limited to three container layers;
gzip+tar consumes two. Limits are 64 MiB per blob/expanded stream, 16 MiB per
member, 256 MiB total inspected bytes, 16,384 members and 65,536 range objects.
These deliberately conservative limits may require smaller evidence batches.

This is a narrow source-publication guard, not a universal privacy or secret
scanner. It does not inspect compiled BEAM instructions, encrypted/custom binary
formats, arbitrary prose, credentials, source encoded in strings, transformed
source with no leading namespace declaration, remote artifacts or Git LFS object
contents. Unknown containers refuse when recognizable by magic or member name;
unrecognized opaque encodings remain outside coverage. Review public evidence
before committing it as well as before pushing it.

Already published history is a separate remediation decision: this checker does
not delete history, move refs, amend commits, upload artifacts or push anything.
