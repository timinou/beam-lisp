* Changes and complexity
1. Open a cold index owner; index consumers request the build. Diagnostics use
   lightweight source/IR helpers without the codebase database or SMT stack.
2. Refresh SDK lifetime discovery only after producer receipts change.
   Canonical byte/code checks remain at admission. SDK AOT initializers use
   the same global ownership as SDK source initializers.
3. Parse/lower once and share the document across summaries, type/arity
   diagnostics, emission checks and lint. Growth runs only when requested.
4. Use the existing byte-bounded finite-value cache, scoped by environment,
   source bytes, definitions and native code generation. Serialize the exact
   finite context once: repeated normalization had inflated a tiny entry to
   roughly 50 KB. Unknown/overlapping publication declines retention.
5. Replace rules-by-nodes lint scans with literal-head buckets plus wildcard
   candidates. Convert reader trees once, removing quadratic subtree conversion.
   Resolve each distinct callee/arity once while retaining all source locations.
6. Replace whole-subtree hashing at every IR node with bottom-up hints and
   bounded exact verification. Hashes never authorize reuse or prove identity.
   Budget exhaustion reports incompleteness rather than a false proof.
7. Keep the compiler OS process across project edits. Retire executed realms
   before changed definitions run; preserve document-only analysis realms.
   Prune excluded directories before walking them.
   Installed command-capable drops also run their first default request in the
   persistent VM, avoiding a parallel temporary command VM and discarded state.
8. Reuse manifest parsing for identical actual bytes, without timestamp trust.
   Parse one immutable captured snapshot; malformed/missing/changed files refuse
   or reparse normally.
9. Keep execution locks out of read-only lease observations. Positive namespace
   observations use the live Env-owned ETS mirror without an Env actor round trip.
10. Route SDK cache restoration by the same tier key used by emission. Build
    drivers use the build key; looking under the compiler key misses valid units.
    Filter seed forwarders by attributes/exports before disassembly and validate
    each seed lambda table once, preserving validation for macro-only units.
    The loader restores build-tier units through the existing complete-unit
    cache path before publishing receipts or running initializers. A shipped
    SDK intentionally omits the development compile.beam_lisp file; treating
    that omission as a source fallback left Build's body unloaded.
11. Reuse complete boot units on runtime-only host regeneration when compiler
    identity, membership and every digest match. From-scratch checks bypass reuse.

* Concurrency finding
A native OTP watchdog captured stacks without depending on Env.
Env was inside record_owned_start!/owned_start_creator_chain, waiting for a
module lock through code_lease_active?. A request held that lock in transfer_code!
while waiting for Env's private source-label bookkeeping. Cache maintenance
timeouts were downstream symptoms.

The exact-ticket reader now checks logical closure before and after its physical
row observation. Complete ticket rows are inserted atomically. This reader grants
no invocation or custody capability. Execution and mutations retain their fences.
A deterministic test holds the module lock while asking Env to observe the ticket.

* Cost model
Let N be document nodes, F functions, R lint rules, C(n) applicable rules at a
node, S project source bytes and U the admitted SDK unit closure.

- Document projections share one parse/lowering instead of repeating whole
  document work for each consumer or symbol (previously up to O(F*N)).
- Reader conversion costs O(N) rather than reconverting every subtree (O(N^2)
  for a chain). Literal-head dispatch replaces N*R candidates with sum C(n);
  candidate order is merged once per head, not sorted at every source node.
- Emission hints visit nodes bottom-up once; exact verification is charged a
  bounded multiple of node count. Identity remains exact, and exhausted work
  reports incompleteness. Maps/sets, grouping and span ordering add their normal
  collection costs; this is not a blanket strict linear-time claim.
- Unchanged SDK refresh is O(1) receipt revision observation. New admission
  still verifies the complete relevant closure U; this work is not skipped.
- Request source discovery still reads actual S bytes. Project changes retire
  executed realms rather than discarding the entire compiler VM. This preserves
  compiler state while keeping new executions fresh.
