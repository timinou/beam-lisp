#+TITLE: Changes you can read, run, and verify

* A change is a program with a receipt

=dev.change= replaces one top-level =def= or =defn= in one =.bl= file.
An executable =.bl.org= journal holds the request, proposal, checks and Babel
=#+RESULTS:= blocks. Application source remains canonical; the journal is a
program that changes it, not a second copy to keep synchronized.

The lifecycle is =plan → preview → verify → authorize → apply → receipt=.
The API returns ={:ok value}= or ={:error reason}= tuples. Unwrap a successful
result before passing its value to the next operation.

* One complete, disposable change

Run this trusted document from the repository root after building Beam Lisp:
=bl doc run docs/dev/executable-changes.bl.org=.
It creates only its own temporary fixture, checks real command execution,
applies one edit, repeats it safely and proposes its inverse. The command
=true= demonstrates process verification, not a language behavior test; the
cell separately checks exact source bytes. Use your feature's test command
for a real application change.

#+begin_src beam-lisp :id guarded-change
(ns guide.dev.changes (:require [dev.change :as change]))

(defn require-ok [result]
  (if (= :ok (elem result 0))
    (elem result 1)
    (throw (ex-info "Change refused" {:result result}))))

(defn check! [condition message]
  (when (not condition) (throw (ex-info message {}))))

(let [root (str (System/tmp_dir!) "/bl-change-guide-" (erlang/unique_integer (list :positive)))
      target (str root "/fixture.bl")
      before "(ns guide.fixture)\n; preserve this comment\n(defn answer [] 1)\n(defn sibling [] :same)\n"
      expected "(ns guide.fixture)\n; preserve this comment\n(defn answer [] 2)\n(defn sibling [] :same)\n"]
  (File/mkdir_p! root)
  (File/write! target before)
  (try
    (let [basis (Base/encode16 (crypto/hash :sha256 before) (list (tuple :case :lower)))
          plan (require-ok
                 (change/plan {:id "answer-2" :workspace root :target "fixture.bl"
                               :selector "guide.fixture/answer" :expected_hash basis
                               :replacement "(defn answer [] 2)"
                               :verification {:argv (list "true") :timeout 5000}}))
          preview (require-ok (change/preview plan))]
      (check! (= before (File/read! target)) "Preview wrote source")
      (check! (= expected (:candidate_bytes plan)) "Unexpected candidate span")
      (let [evidence (require-ok (change/verify plan))
            authorization {:id (:id plan) :candidate_hash (:new_hash plan)}
            applied (require-ok (change/apply! plan evidence authorization))]
        (check! (= expected (File/read! target)) "Application differs from candidate")
        (require-ok (change/apply! plan evidence authorization))
        (check! (= expected (File/read! target)) "Replay changed the result")
        (require-ok (change/receipt (:id plan) root))
        (let [inverse (require-ok (change/undo! (:id plan) authorization root))]
          (check! (= before (:candidate_bytes inverse)) "Inverse is not the original source"))
        {:preview :read-only :apply :verified :replay :safe :inverse :proposed}))
    (finally (File/rm_rf! root))))
#+end_src

* What the boundaries mean

** Plan and preview

A proposal names an existing workspace, relative =.bl= path, definition selector,
whole-file SHA-256 basis, same-named replacement definition and stable edit ID.
Planning reads but never evaluates source. The lexical scanner checks balanced
parentheses, brackets, braces, strings and comments; quoted/discarded definitions
are not targets. Unsupported or ambiguous shapes refuse rather than guessing.
Only the selected span changes. Surrounding Unicode, comments and newlines survive.
This scanner is not a language typechecker: compilation/tests provide that proof.

Preview returns the proposed diff and hashes. It does not run a command or write
application source. A candidate and a passing test receipt are different things.

** Verification

Verification copies the workspace, refuses symlinks, installs the candidate in
that copy and executes an allowlisted argv command there. Use =(list ...)= for
argv in Beam Lisp. The host controls executable allowlisting; proposal data
cannot supply its own policy. Successful evidence is persisted and binds the
edit ID, basis hash, candidate hash, command and toolchain versions.

The default runner requires Linux systemd user services. A transient service
owns the verifier and descendants, with =MemoryMax=, no swap, and a runtime
limit. Output is capped at 1 MiB. The service is stopped on exit/timeout. A
missing executable/manager or failed command refuses; launcher success is not
substituted for the command's exit status.

A copied workspace and resource limits are *not a hostile-code sandbox*.
Commands still have the operating-system user's filesystem/network privileges.
Use only trusted verification commands. An injected host test runner is also
trusted, not a capability boundary available to untrusted proposal data.

** Apply and recovery

Application requires explicit edit-ID/candidate-hash authorization. It checks
the plan's bytes and the persisted verification evidence, not a caller's forged
success map. Under the cooperating-writer lock it checks the source again,
writes an intent record, replaces the file by same-directory atomic rename,
and records application. File and parent-directory synchronization provide the
Linux durability boundary; existing source permissions are preserved.

Receipts live in =.beam-lisp/change-journal/=. Repeated IDs must identify the
same transition. An intent with original bytes means not applied; candidate
bytes mean applied; any third hash means conflict. A stale lock after a crash
refuses new writers; inspect the receipt and establish that its owner is gone
before clearing the lock. No automatic lock theft is attempted.

Undo returns a new inverse *proposal*. It requires the current after-hash and
must pass the usual verification/authorization before application. It cannot
silently erase later edits.

** Document execution and runtime reload

=bl doc run= executes trusted arbitrary code. Babel boundaries identify code
and owned output; they do not sandbox a cell or authorize file writes. Reading
proposal maps through =plan= is inert; executing arbitrary Org cells is not.

Source files, receipts, document result spans and the running namespace image
are separate resources. This source-only API does not reload the live image,
provide multi-file atomicity, rename callers, or edit literate target cells.
Non-cooperating writers and arbitrary external side effects are outside the
transaction boundary. Refusal is preferable to pretending those effects can
be rolled back.
