#+title: Runtime speedups: implementation, evidence and boundaries
#+status: Production integration; final SDK/application acceptance pending

This document is for a developer learning why loading and navigation became
cheaper. Mechanism measurements below are not whole-page speedup claims.
The implementation lives upstream in Beam Lisp; Knowledger supplies its loading
policy and an optional release-package path, not cache annotations or inventories.

* 1. Application packaging and the production startup barrier
Files: priv/lib/application/package.bl, priv/std/bl/loading.bl.
Commits f9ff2f19 and f02606cb.

The release builder follows actual namespace declarations from the entry, snapshots
the complete dependency closure and compiles libraries through the ordinary build
driver. It never evaluates the executable entry. The runtime and builder share
Loader/replayable_source?: unknown top-level effects/macros stay source-only.
Admitted definitions replay their normal initializers. This fixes an upstream bug
where a stale artifact could hide an unsupported top-level effect (009a8f21).

The immutable directory is published under an OS lease by rename. Its manifest
binds entry/root/source bytes, every shipped file, compiler identity, fixed host
module MD5s, native hashes and ERTS/Elixir versions. Installation rejects drift,
extra files, symlinks and wrong SDKs before running application initializers.
Trusted deployment supplies release authenticity; the manifest is not a signature.

Production verifies and preloads this closed inventory before executing main.
Without a package it still discovers and preloads normally. Development ignores
the package and remains lazy or optionally warms after startup. Cancelled work
cannot report successful initialization. Applications need no function lists.
Compilation can execute library compile-time effects, so package in a release
process. Format 1 explicitly supports standalone VMs, not global artifacts in realms.

Evidence: application.package 27 assertions, including two fresh consumer VMs,
artifact code-path verification, preserved source effects and authority refusals;
system.loading 58 assertions. Package construction also rejects invalid dependency paths/oversized closure and
exclusively owns a random staging directory (8fcbb552); 35 assertions now pass.
Actual app SDK/HTTP/browser acceptance is pending.

* 2. Executed definition tracking instead of full-table extraction
Files: priv/host/env.bl, priv/host/aot.bl. Commit 9c20eb34.

Env records definition names at successful publication while an AOT collector is
active. The compiler selects precisely those definitions instead of materializing
an inherited namespace table and then filtering it. Generated definitions enter
through the same publication boundary as ordinary definitions. Nested compilation
masks the parent collector across compilation AND emission and restores it finally.
With no collector active there is no retained AST copy or tracing stream.

Anchored mechanism benchmark at 6229edf0: 100 projections of two real
definitions, with 128 unrelated ASTs: median 1,028,204us -> 21,385.5us (48.08x).
With 2,048 unrelated ASTs: 4,705,731us -> 11,376.5us (413.64x). These numbers
isolate extraction, not compilation.
The practical benefit is that accumulated unrelated definitions stop inflating this
part of release building, AOT compilation and reload.

Loader context is also explicit: search/fixed/load paths, ambient roots and
admission scopes cross Env/convey boundaries and restore the worker's prior scope,
including failure paths. Missing legacy fields clear stale worker context.

* 3. Broader safe realm AOT admission
Files: priv/host/aot.bl; existing realm cache authority. Commit 9c20eb34.

A finite structural recognizer admits local zero-argument defining macros whose
body is exactly one quoted def/defn. The resulting definition must still pass the
existing closed expression gate. Arbitrary expansion is never executed as proof.
Parameterized, duplicate, reserved, effectful and body macros decline admission.
Compiler/context/source/realm identity still controls actual reuse.

Evidence: 25 realm assertions include a real generated macro with zero compilations
on its second load in another environment. This eliminates repeated compilation
for that admitted class; it does not make arbitrary macros cacheable.

* 4. Query-result reuse with complete negative-read authority
Files: priv/lib/datom/query/read-plan.bl, engine.bl, relation.bl.
Commits d015324c and 7a090345.

The existing bounded result cache now recognizes a closed logical query grammar,
including every branch of not/not-join/or/or-join. Empty answers have dependencies
too: inserting/retracting a previously missing fact can change them. Actual scan
work admits expensive empty and selective answers; tiny point queries retain the
cheap path. Unknown predicates/providers/rules/raw database escapes execute normally.

Validity includes committed attribute bases, database/schema/store identity,
publication fences and an atomic stored-attribute/provider-registry generation.
A provider registered during lookup invalidates an apparently reusable answer;
the registry's generation is checked again after execution. Registry replacement
also changes authority. No caller annotation asserts what arbitrary code reads.

Evidence: positive reuse 56, negative/selective reads 16 and the actual emitted
provider-registration race 5 assertions passed together in batch-9. The race test
forces registration during an otherwise valid retained lookup and gets the computed
answer rather than stale stored data.

Mechanism benchmark: 1,000 blocked entities, ten repeated negative queries,
counterbalanced trials anchored at 6229edf0. Uncached median 32,582ms ->
retained 87.114ms (374x); caller reductions 619x fewer; store rows 20,000 -> zero. This intentionally costly
fixture isolates avoided scans. Earlier 64-row positive-join regression measured
8.28x fewer caller reductions; the cheap-query control changed by about 0.77% in
that run. Shared-host timings are not production latency guarantees.

* 5. Measured index admission and adaptive writer work
Files: priv/lib/datom/query/rank-demand.bl, rank-build.bl, datom/conn.bl.
Commits d015324c and 056a49fe.

Three requests no longer automatically justify building an index. The engine
records actual costly fallback work over a bounded window; cache hits buy nothing.
It ignores initial warm-ups and debits forecast construction and maintenance cost.
Completed commit-inclusive builds calibrate per-row cost outside the writer's
optional-cache publication path. Page/write costs begin as conservative forecasts,
not portable measured constants.

Construction targets 20ms writer turns, begins at one entity, adapts up to 16 and
retains peak observed cost. Empty checkpoints cannot teach it that real entities
are cheap. One atomic native store operation cannot be interrupted, so this is
an adaptive scheduling target rather than a hard latency deadline.

Evidence: demand 22, writer budget 12 and native rank correctness 79 assertions
passed. The anchored ordinary-cache controls below supersede the preliminary
uncached-only comparison. Construction and maintained writes can erase the read
benefit. Native advance-call latency includes caller queueing and completion
telemetry, not just writer residency.

* 6. Cancellation and safe code lifetime
Files: priv/std/proc/admission.bl, priv/host/loader_server.bl, env.bl,
priv/boot/lower.bl, priv/lib/vm/core.bl. Commit 9c20eb34.

Admission carries a local owner PID and monotonic deadline. Loader.Server checks
it before shared effects. Once accepted, initialization drains, including nested
loads: a caller timeout cannot safely undo partially published shared code.
Queued and accepted loader callbacks acquire physical-module leases automatically.
Explicit Env/with_code_lease protects other retained callbacks.

Publication and retirement use the same module lock. Leased modules decline
retirement/third-generation replacement; dead owners are reclaimed under the lock.
Reload compiles first, then publishes under this fence. It no longer force-purges
callbacks executing old code. vm.core delegates retirement to that same authority.
There is no latency ratio: the benefit is avoiding unsafe reload and work admitted
after its owner/budget ended. Wider automatic lifetime transfer remains a follow-up.

* 7. OS-owned endpoint leases
Files: priv/lib/os/lease.bl, priv/lib/vm/net.bl. Commits 389586f1, 6e91d767.

A port-owned helper holds a real flock descriptor. Owner/VM death closes stdin
and releases it; a stopped helper keeps its ownership. vm.net separates startup
serialization from listener lifetime and transfers the latter to the acceptor.
Lock inodes persist, stale cleanup is generation-fenced and each new bind rotates
credentials. Age never grants ownership. Paths are argv values, not shell text.
Unsupported POSIX/flock hosts fail closed.

Evidence: 51 assertions include SIGSTOP, owner death, competing starts, transfer,
stale cleanup and credential rotation. Actual acquire/release costs about 12.82ms
per operation in the anchored five-trial measurement. This buys correct ownership;
it is not a speedup over the earlier Python lock prototype.

* How the measurements work
bench/runtime-integration/run.bl executes explicit benchmark functions after module
loading, in one owned VM. Query and extraction trials are counterbalanced, verify
answer parity and retain raw observations. Native tests use disposable fresh Fjall
stores and count initial writes, full construction, deep reads and maintained writes.
See bench/runtime-integration/README.org for commands and caveats.

A separate Knowledger HTTP harness checks real main readiness/live/login and preload
receipts using the pinned SDK. Its browser harness uses external Playwright Chromium
to measure authenticated address-change-to-DOM navigation. Chromium is the browser
running the application; Beam Lisp does not implement a browser renderer.

* Logic-module review and authority choices
system.publication reads actual emitted clauses, dispatch, body modules and
bindings; system.publication-closure closes those edges with finite limits. Its
API explicitly does not certify purity, termination or read closure. Consequently
it cannot justify caching an arbitrary query function or cancelling accepted
initializers. system.footprint classifies emitted effects, while typed/codebase
metadata describe signatures and source structure. None substitutes for executed
negative reads or an OS-held ownership descriptor. The integration uses closed
query grammar, structural macro recognition, Env publication fences and descriptor
ownership at their respective boundaries. Unknown evidence declines optimization.

* Anchored control: clean revision 6229edf0
The complete second run records compiler/VM/source identity. Raw receipts are in
evidence/mechanisms-6229edf.log. Host contention changed wall time considerably:
negative reuse 32.58s -> 87.11ms per ten calls (374x), with 619x fewer caller
reductions and the same 20,000 -> zero store rows. Extraction selected TWO real
definitions, not three; ratios were 48x (128 unrelated entries) and 414x (2048).

The ordinary-cache control prevents a misleading index claim. At 100 entities,
cached query+sort was faster than the direct index (5.08ms vs 11.36ms). At 1000,
it was 15.50ms vs 9.91ms, but full construction cost 24.70s: 4,426 read-only hits
to repay, ignoring maintained writes, which rose from 10.65ms to 69.34ms each.
Observed advance-call p95/max reached 97.63/585.10ms. Those include caller/queue
and shared-host effects and demonstrate why the 20ms target is not a guarantee.
Automatic policy measures actual fallback work; cheap cache hits buy no indexes.
The actual OS acquire/release median was 12.82ms in this more contended run.

The post-writer-admission native run is archived separately as
=evidence/native-writer-32e5a2cf.log= with its summary. At 100 entities, ordinary
cached reads took 4.95ms versus 11.94ms through the index; at 1000 they took
12.27ms versus 27.75ms. Construction cost 2.66s/26.04s. Neither trial has a
read-only repayment point. Maintained writes at 1000 rose from 12.21ms to
32.72ms. Advance-call p95/max reached 84.53/531.05ms at 1000. This confirms
that the index mechanism needs conservative admission, not unconditional use.
Batch-10 passed all 167 assertions across admission, physical code leases,
public writer cancellation, concurrent writes, connection lifetime and rank
correctness. These are mechanism measurements, not whole-app latency claims.


* Store-writer admission extension
The actual datom writer now composes an immediate caller/30-second queue budget
with any inherited request. Both must remain live before mutation. Caller and
accepted worker own physical leases for the queued wrapper and callback; worker
ownership survives caller death. Once accepted, cancellation context is cleared,
so the transaction drains rather than abandoning partially committed effects.
This applies automatically to HTTP and job callers. Ordinary reads execute in
their caller process, so they do not form another orphaned shared writer queue.

Batch-10: 167 assertions in six isolated files passed, including real public
transactions skipped after queued owner death or inherited expiry, successful
commit after accepted owner death, worker-held leases and continued writer health.
Existing concurrent writes, connection retirement/draining and native rank tests
also pass. No forced cancellation is added to an already accepted transaction.
Wider lifetime transfer for arbitrary retained actor callbacks remains in FUP.org.
