#+title: Realm-bound application packages
#+status: Native regressions green; benchmark and installed acceptance pending

* Mechanism
Format 2 records the exact realm identity/declaration, namespace physical homes,
dependency closure hashes, finite compiler authority and emitted module names.
Build derives this information automatically from the loader. SDK namespaces
remain ordinary dependencies; only the existing finite local AOT admission set
is compiled. A realm declaring any tier shadow retains source evaluation for all
local units; unsupported macro/effect forms also retain source evaluation.

Installation verifies the runtime and every packaged byte before atomically
registering environment-local providers. It does not prepend realm artifacts to
the VM-wide code path. Loading rechecks compiler, closure, home and artifact
bytes before publication, then runs the ordinary initializer in the consuming
environment. Missing live local source uses the immutable snapshot; changed or
wrong-namespace live source refuses replay. Environment destruction removes
providers; realm module retirement includes Body and Init companions.

* Expected benefit and deliberate boundary
Moves admitted local compilation into the release build. Fresh environments
still initialize values/effects independently. Packages bind exact logical realm
keys; this is not a portable arbitrary-key relocator. Broad macro/shadow support
and sharing one artifact across differently named realms are not claimed.

* Validation / measurement
realm_package_test covers distinct physical homes, wrong realm/global install,
source drift, per-environment values, source-free fallback, no global code-path
mutation, changed provider declaration and post-install byte tampering.
realm-packages.bl compares source, a separately primed ordinary AOT cache and
package verification plus loading in six counterbalanced orders. Build cost is
reported separately. Every timed load has an untimed result oracle; elapsed and
caller reductions are separate metrics. Results are pending the coordinated
host/compiler rebuild and are not yet speedup claims.

* Native integrated checkpoint
On the corrected native floor cb63667b, realm-package regressions pass 95
assertions, zero failures/incoherence, including two fresh child VMs. Existing
application-package and realm-AOT-reuse controls pass 41 and 25 assertions.
The fixture forks its prepared SDK environment, preserving library declarations
while each consuming realm owns its own values/providers. The first fixture
failure and green rerun remain archived under evidence/package-first-run.log
and evidence/realm-rerun.log. Benchmark and installed SDK/application acceptance
remain separate gates; these assertions do not establish a startup ratio.
