#+title: Synchronous worker dependencies during initialization

* Contract
Loader.Server owns initialization order and partially published namespace state.
A synchronous worker callback can request a lazy dependency without acquiring
loader ownership. Loader.Server/worker_call supplies a callback wrapper carrying
an unforgeable, temporary causal alias. The real loader selectively services
that reference while its monitored proxy waits for the synchronous worker call.
Ordinary competing loader calls stay queued until the initializer completes.

datom.conn applies this automatically at its conveyed Agent boundary. App authors
can initialize a connection inside a library without arranging dependency warmup.
Other synchronous worker integrations can use the same generic API. The worker
callback must complete within the call; retained callbacks need a different lifetime.

The API conveys registered Env scopes automatically:
#+begin_src clojure
(BeamLisp.Loader.Server/worker_call
  (fn [delegate]
    (Agent/get_and_update worker (delegate callback) timeout)))
#+end_src

The delegate accepts a one-argument callback. Outside the loader it preserves the
ordinary synchronous Agent call and its existing Env conveyance. During an
initializer the sequence is:
1. Loader.Server creates a scoped alias and starts a monitored waiting proxy.
2. The proxy submits the conveyed callback to the actual worker.
3. A lazy load in that callback sends its request to the scoped alias.
4. Loader.Server executes that request itself and replies to the worker.
5. Worker completion returns through the proxy; Loader.Server closes the alias
   and resumes the initializer.

This resolves loader dependencies across the adapted synchronous boundary.
Arbitrary application cycles between independent actors still require their own
protocol: the loader does not execute competing initializers or arbitrary mailbox
traffic to guess how those actors should progress.

* Ordering and lifetime
| State | Allowed transition | Authority |
| Initializing | Synchronous handoff | Real Loader.Server |
| Waiting for worker | Causal nested load | Matching handoff reference |
| Nested load | Nested synchronous handoff | Real Loader.Server, new reference |
| Worker completed | Resume initializer | Monitored proxy outcome |
| Owner or proxy gone | Refuse dependent load | Process monitors |

The owner closes the alias in finally, so stale delegated requests cannot leave
executable messages in its mailbox. Nested loads execute on the real loader process, preserving its partial namespace
cycle guard. Registered Env scopes are conveyed and restored. A worker never
receives the loader's ownership flag. A guardian stops a waiting proxy when the
loader dies, including a normal exit. Accepted Agent operations retain their own
admission and executable lifetime rules and are not killed by proxy cleanup.

* Validation plan
- Source-compiled isolated host probe: causal owner identity, partial state,
  competing-load exclusion, nested handoffs, exception cleanup and expired wrapper.
- Fresh VM: required library initializer opens/transacts/closes a datom connection;
  prove completion without priming the worker's dependency closure.
- Bounded reproduction: ordinary blocking Agent call stalls its nested loader
  request; cooperative handoff completes that same shape.
- Benchmark warm direct calls, ordinary calls through worker_call and initializer
  handoffs, reporting distributions and reductions. Startup deadlock avoidance is
  a liveness improvement, not a promise to reduce normal initialization time.

The paired benchmark uses eight alternating rounds of 100 calls for each of five
controls: ordinary conveyed Agent call, adapted ordinary call, initializer with a
blocking dependency-free call, initializer with an adapted dependency-free call,
and initializer with an actual causal nested load. It records wall time, caller
reductions and all-VM reductions. The ordinary ratio isolates adapter cost; the
initializer ratio isolates monitored handoff cost. The causal control includes an
extra loader operation and is reported separately. A 100ms timeout contains the
unadapted dependency cycle and verifies the timeout class before recording it.

Integrated results and acceptance receipts follow below.

* Focused evidence
The source-compiled host probe and system.model transition extractor report 26
passing assertions across two files (receipt initializer-probe-5.log). The model
checks the actual selective receive has exactly three scoped transitions, with
no wildcard or unrelated-call arm. Native-floor integration and benchmarks are
separate acceptance steps.

* Public raise boundary
Public erlang:raise/3 consumes a built frame list. Compiler-generated raw catch
rethrows carry the semantic ANF operand :stack-format :raw; the descriptor
validator restricts that operand to erlang:raise/3 with three arguments. The
lowerer invokes the public BIF for ordinary source calls and emits raw_raise
only for the explicit internal representation. The reference interpreter uses
the same distinction. The fresh-child regression checks error, throw and exit
replay with exact frame preservation, plus unmatched typed-catch propagation.

* Integrated acceptance (2026-10-09)
Validated against the integrated native floor cf579e2e with the public raise
child source-path correction 985aaa51 and benchmark loop correction 3d097b43.
All jobs ran sequentially under an 8GB memory / 2GB swap cgroup, with scratch
under home. The initial grouped run passed 19,171 assertions in six files:
worker handoff 22, protocol model 5, gensym parity 18,949, ANF 40,
reproducible AOT 7 and Loader.Server 148. Its public-raise child fixture failed
because it omitted the runtime source search root; this was a genuine failed
batch, not a green acceptance receipt. After correcting only that fixture, the
focused public-raise rerun passed both assertions with no failures/incoherence.

The real cold datom initializer completed connect, transact, query and close
without preloading worker dependencies: INITIALIZER_CONNECTION_OK 45658966
microseconds. The 45.66s includes dependency loading/compilation on this host;
it proves completion of the deadlock shape, not a cold-start speed comparison.

The paired benchmark completed all 40 samples (8 alternating rounds, 100 calls
per mode), proved the unadapted cycle times out at 100,277 microseconds, and
proved a subsequent causal call still succeeds. Its first invocation failed
before sampling because dotimes is unavailable; replacing it with doseq/range
produced the complete receipt. Raw receipts and the strict summary are under
=evidence/=. Per-call sample medians:

| Mode | Wall microseconds | Caller reductions | VM reductions |
| Ordinary conveyed call | 9.275 | 139.86 | 369.67 |
| Adapted ordinary call | 8.775 | 235.605 | 464.705 |
| Initializer blocking, no dependency | 29.73 | 492.815 | 1316.93 |
| Initializer adapted, no dependency | 44.40 | 493.37 | 1820.46 |
| Initializer adapted, causal nested load | 71.505 | 495.315 | 2830.36 |

Alternating paired wall ratios are 1.080 for ordinary adapter/direct and 1.497
for initializer adapted/blocking. The median-of-ratios differs from the ratio
of marginal medians because of scheduling variation. Ordinary overhead is small
but adds reductions; initializer handoff adds roughly 14.7 microseconds in these
controls. Causal mode performs additional nested loader work. The improvement is
removing an unbounded dependency deadlock, not making every actor call faster.
VM reductions include participating workers; caller-only counts hide that work.
