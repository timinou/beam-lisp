#+title: Portable compiler support authority

* Problem and implemented boundary
A realm package reuses compiled executable code, so its release certificate must
identify the compiler that produced it. Stage module MD5s and nine arithmetic
operators were insufficient. For example, compile-each executes =(apply list ...)=;
=list= is a first-class Env fetch with Core fallback. Replacing =core/list= or
redirecting =compiler/list= through a refer changes compilation without replacing
any compiler module.

A bounded structural projection now starts from canonical Sugar, Compiler, Lower
and ANF definitions. It follows static calls, first-class global references and
captured external functions through canonical Core, RT, Reader, ReaderNode and
Diag definitions. Quoted =:lit= / =:plit= payloads and source annotations are not
executable dependencies. Each actual nonmaterializing global lookup binds its
relevant alias/refer declarations, including their absence, and its actual value.
Support implementation evidence names canonical Body modules; unrelated Core/RT
shim export additions do not enter the certificate. Exact seeded RT closure
identity and recursively portable captured environments are admitted; unknown
namespace providers, unsupported definitions and process-bound values decline.

The projection is bounded at 4,096 queued definitions, 8,192 unique fetches,
1,000,000 structural walk terms, depth 256, and the shared portable-value budget
of 100,000 terms/depth 64. It neither evaluates deferred values nor invokes user
callbacks. Publication epoch and namespace generations fence a coherent read;
they are not included in the portable hash. Raw interop replacement of generated
shims remains outside the generated publisher contract.

* Measurement and release tradeoff
Twenty alternating old/new full-authority samples in one fresh VM measured:

| Certificate                         | Median ms | Min ms | Max ms |
|-------------------------------------+-----------+--------+--------|
| Previous incomplete support stamp   |     6.837 |  2.350 | 13.718 |
| Transitive support projection       |    46.893 | 32.564 | 70.525 |

This change adds correctness coverage, not a speedup. Full recertification costs
about 40.06 ms more on this pressured shared host. These are descriptive warm
measurements, not confidence intervals or end-to-end startup results. Repeated
package validation may warrant a bounded local memo keyed by publication epoch
AND current support-module executable fingerprints. Epoch alone is insufficient
because physical publication can precede namespace metadata publication.

Raw logs, probe source snapshots and the machine-readable summary are under
=evidence/compiler-support-*=. The source snapshots contain the exact worktree
paths used for this isolated experiment.

* Bounded memo removes repeated structural work
The release implementation now retains exactly ONE last-entry Process value,
under a key containing the actual native AOT module identity. It stores the Env
identity, exact closed namespace generation/lifetime evidence, portable hash,
and sorted actual executable MD5 vector. No per-Env keys or persistent_term
cache accumulate. The observed normal entry held 10 namespace dependencies and
26 module fingerprints; enforced limits are 128 names and 256 modules.

The dependency set includes actual lookup candidates and alias/refer targets.
Qualified re-export chains are read without materializing values, with the same
environment-first candidate precedence as Env fetch. A hit takes the generated
publisher's sorted physical module fences and validates namespace evidence and
actual module MD5s before/after. A miss traverses metadata outside those fences,
under the global publication epoch coherence fence, then validates under physical
fences before publishing the one entry. Unrelated application namespace init
changes the global epoch but leaves a valid hit intact. The stored projection
epoch is diagnostic evidence, not a hit key or part of the portable hash.

** Measured hit cost and validation
Twenty consecutive verified memo hits measured median *69 microseconds*, minimum
34 and maximum 625 microseconds, versus the earlier 46.893 ms median uncached
projection. The descriptive ratio is about 680x for repeated verification. The
samples came from separate prototype phases on a pressured shared host; this is
not an end-to-end startup speedup or a paired confidence estimate. First misses
still perform the structural projection, once per relevant process/environment
and after relevant support changes.

The final isolated probe proved unchanged hit hashes, no structural refresh on
unrelated namespace initialization, compiler literal/Core list/alias/refer
invalidation with restoration, same portable hash across a fork and fresh VM,
backing Reader-node module publication invalidation, and destroyed scope refusal.
The backing fixture restores the original bytes in finally. Permanent regressions
cover these boundaries in realm_package_test and env_publication_generation_test.
Final combined probe included compiling updated Env and AOT: 49.119 seconds,
218.3 MiB peak memory / 57.5 MiB swap. The separate fresh process passed in
18.634 seconds. These service runtimes include cold startup and prototype work.

** Bugs found by the prototype
The first lifecycle assertion exposed an upstream API bug: rebinding a destroyed
Env can produce a global-only read chain, so namespace_generations previously
certified the live global fallback despite a dead current Env identity. It now
checks the current Env's lifetime independently of the computed chain. The fork
itself always produced the same portable hash. This is a production correctness
fix, not a relaxed assertion.

A subsequent code-publication fixture failed restoration because code/get_object_code
returns a charlist filename while publish_binaries expects a binary. The fixture
now converts it before restoring. The reduced ABI existed only in the isolated
owned VM, which exited; it did not affect any shared app process. Raw failures,
diagnosis, fixed probe source, green receipts and measurements are preserved as
=evidence/compiler-authority-memo-*=. No source or floor was changed in the
integration checkout by these isolated probes; the integration owner performs
final floor and regression validation separately.
