#+title: Measured maintained-index economics and retirement
* Contract
Indexes remain disposable accelerators: ordinary query evaluation is always
available. Telemetry never establishes query correctness or source authority.
Construction admission now uses measured peak page/write cost when available.
Ordinary query controls include actual result-cache hits, separately from build
demand: a cache hit still never pays construction demand.

Completed indexes collect generation-specific economics in the bounded optional
cache. Read savings use the cheapest observed ordinary execution minus measured
page cost, floored at zero. Writes charge a commit-inclusive upper bound: the
whole transaction, not an unsupported claim of isolated incremental index cost.
Three maintenance samples and at least 30 seconds are required; maintenance
must exceed twice accumulated observed savings. Window is five minutes.

Policy requests retirement outside the source writer. The writer independently
checks exact live generation and complete status, atomically marks it aborted
and records a five-minute cooldown in a bounded durable ledger (at most five
recent identities). Optional cache loss cannot bypass this durable refusal.
Clock changes affect cooldown policy only, never query authority.

Existing optimistic reader checks reject the aborted header immediately.
Ordinary writes advance cleanup for one aborted index per transaction; each
turn reclaims bounded nodes/members with a durable DFS checkpoint. Existing
query workers also resume cleanup. Registry capacity is returned at completion.
Idle stores retain finite aborted storage until their next write/query.

* Validation pending
- Demand transition tests: cheap cached controls, grace, samples, profitable use,
  expiry, malformed sample, peak calibration.
- Real store regression: wrong generation cannot retire; valid retirement
  revokes page reads; ordinary writes remove all physical nodes and members;
  authoritative query parity and durable cooldown prevent immediate rebuild.
- Native mixed workload: baseline writes, maintained writes, ordinary cached
  reads versus indexed reads, retirement/cleanup work and post-retirement writes.
  No promised universal speedup; cleanup itself has a measurable temporary cost.
