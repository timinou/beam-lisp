#+title: Transferable executable ownership

* Contract and boundaries
Env registrations acquire sorted physical-module fences before publication.
Transfer replaces exact owner/ticket rows under those same fences; stale handles
cannot unregister accepted work. Invocation acquires an independent executing
lease before leaving the fence, so concurrent unregister cannot interrupt effects.
Queued dead owners and released registrations decline. Dead rows are reclaimed by
module admission/retirement and the 65,536-row capacity sweep; acquisition uses a
shared capacity fence, including across disjoint module sets.

Core spawn/spawn-link/spawn-monitor and future acquire before creating the worker,
transfer to its PID, and publish a start message. A parent monitor prevents an
unpublished worker from waiting forever. Accepted plain children survive caller
death; linked children and Task futures retain their ordinary OTP link semantics.
The worker releases in finally; hard death is reclaimed by existing dead-owner
cleanup. The wrapper module and callback's direct physical module are protected.

proc.queue retains its perform callback for the queue process lifetime and
transfers explicit perform dependencies at each worker handoff. Prelude-to-init
staging is consumed from that process's dictionary, replacing a global callback
atom that survived stopped queues and collided across environment-local names.
web/serve
uses its existing listener bootstrap's lifetime to retain router/log callback
modules, and each accepted request holds an independent execution lease.
proc.callback provides explicit register!/transfer!/invoke!/unregister! for other
retained callbacks, conveys the registering environment, and accepts explicit
extra modules for executable dependencies captured inside values.

This does not trace arbitrary closures or automatically protect callbacks hidden
inside application state. It does not change OTP cancellation/link behavior or
promise hard interruption of accepted effects. It protects installed executable
generations, not a snapshot of remote-call dispatch: remote calls may resolve to a
newly published generation, as before.

* Validation and measurements
Native integration passes 68 assertions across async callback, HTTP listener and
queue registration files, with zero failed/incoherent wards. Existing code lease,
Refs, durable queue, HTTP request, namespace generation, realm retirement and
database connection lifetime controls pass another 347 assertions. The first
run's invalid descriptor comparison and unconveyed raw fixture child are fixed;
both failed and green receipts are retained under evidence/ownership-*.log.
Overhead measurement remains the next acceptance gate. No speedup is assumed:
this is reload correctness with registration/worker cost.

* Repeated immutable executable publication
Under the same physical-module fences, Env compares generated executable MD5s
with the installed current generation and skips identical loads. Per-environment
initializers still replay in the loader; a no-op still checks scope liveness.
This avoids creating a redundant third generation merely because another realm
initializes the same package while callbacks retain old code. Different bytes
still refuse a leased third generation. Duplicate-module batches refuse before
mutation, preventing no-op filtering from changing ambiguous last-write ordering.
The original installed filename remains on a no-op; code/which is not an artifact
provenance receipt when executable code is already installed.

* Measured overhead
Six counterbalanced spawn trials of 100 operations each measure raw spawn at
4.070 us, conveyed spawn at 8.405 us and executable-owned spawn at 25.175 us
median per operation. Relative to conveyed spawn, ownership adds 16.770 us
(2.995x wall ratio). Caller reductions are 36.65 / 88.65 / 761.505 respectively;
these exclude child reductions. Six alternating invocation trials of 1,000 calls
measure the trivial direct callback at 0.0535 us and registered invocation at
15.6955 us: 15.642 us added. The large 293x ratio reflects the trivial baseline,
not a page or request slowdown. Registration protects accepted execution before
unregister/reload; normal completion leaves the lease registry at its baseline.
Raw rows and strict completeness/result summary are in evidence/async-benchmark*.
