#+title: Transferable executable ownership

* Contract and boundaries
Env registrations acquire sorted physical-module fences before publication.
Transfer replaces exact owner/ticket rows under those same fences; stale handles
cannot unregister accepted work. Invocation acquires an independent executing
lease before leaving the fence, so concurrent unregister cannot interrupt effects.
Queued dead owners and released registrations decline. Dead rows are reclaimed by
module admission/retirement and the 65,536-row capacity sweep; acquisition uses a
shared capacity fence, including across disjoint module sets.

Core spawn/spawn-link/spawn-monitor and future acquire before creating the worker,
transfer to its PID, and publish a start message. A parent monitor prevents an
unpublished worker from waiting forever. Accepted plain children survive caller
death; linked children and Task futures retain their ordinary OTP link semantics.
The worker releases in finally; hard death is reclaimed by existing dead-owner
cleanup. The wrapper module and callback's direct physical module are protected.

proc.queue declares its perform callback modules at worker handoff. web/serve
uses its existing listener bootstrap's lifetime to retain router/log callback
modules, and each accepted request holds an independent execution lease.
proc.callback provides explicit register!/transfer!/invoke!/unregister! for other
retained callbacks, conveys the registering environment, and accepts explicit
extra modules for executable dependencies captured inside values.

This does not trace arbitrary closures or automatically protect callbacks hidden
inside application state. It does not change OTP cancellation/link behavior or
promise hard interruption of accepted effects. It protects installed executable
generations, not a snapshot of remote-call dispatch: remote calls may resolve to a
newly published generation, as before.

* Validation and measurements
Pending bounded regression and overhead benchmark, coordinated through the root
agent's single owned BEAM slot. No speedup claimed: this is reload correctness at
bounded registration/worker overhead.
