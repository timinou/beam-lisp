#+TITLE: Finite compiler data

* Build trees, not delayed work

Compiler traversals use eager lists, vectors and maps. =nil= represents an
empty collection. =BeamLisp.CompilerData= refuses lazy collections rather than
running their thunks. Literal values remain data, even when they contain keys
such as =:op= or =:body=.

The public language =map= and =range= remain lazy. The eager helpers belong to
compiler-owned transformations; they do not change user sequence semantics.

* Map and concatenate

#+begin_src beam-lisp :id finite-eager-map
(BeamLisp.CompilerData/eager_map (fn [x] (* x x)) [1 2 3 4 5])
#+end_src
#+RESULTS: finite-eager-map
: (1 4 9 16 25)


#+begin_src beam-lisp :id finite-eager-concat
(BeamLisp.CompilerData/eager_concat (list [1 2] nil [3 4] [5]))
#+end_src
#+RESULTS: finite-eager-concat
: (1 2 3 4 5)


Callbacks execute in collection order. A callback exception stops traversal
and retains its original exception class. A malformed collection is refused
before its elements reach the callback.

* Keep forcing explicit

#+begin_src beam-lisp :id finite-lazy-refusal
(try
  (BeamLisp.CompilerData/eager_map inc (range 10))
  (catch ArgumentError e :refused))
#+end_src
#+RESULTS: finite-lazy-refusal
: :refused


A caller that owns a finite lazy sequence can choose to realize it explicitly:

#+begin_src beam-lisp :id finite-force-first
(BeamLisp.CompilerData/eager_map (fn [x] (* 2 x)) (to-list (range 5)))
#+end_src
#+RESULTS: finite-force-first
: (0 2 4 6 8)


* Measure separate lifetimes

=compiler-retention-probe.exs= in =!tasks/artifacts/= checks repeated small and
large compilation units. It counts lazy memo registrations, checks emitted byte
hashes, and reports process memory, VM memory, native memo statistics and loaded
module counts separately. Each batch has one measurement GC.

Temporary compiler trees become unreachable after use. User lazy values retain
shared native memo ownership while reachable. Loaded BEAM code has a separate
lifetime: term garbage collection does not unload a module, and closures may
still need its code. Zero compiler memo registrations is not a total VM memory
limit.
