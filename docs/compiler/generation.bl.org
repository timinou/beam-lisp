* Three identities, one receipt

A running self-hosted compiler has three independently useful identities:

- =source.codegen_key= hashes the toolchain source and codegen inputs currently
  on disk.
- =seed.manifest_sha256= identifies the committed bootstrap manifest. The seed
  is the previous-generation floor used to start a fresh build.
- =loaded.modules= reports live =module_info(:md5)= fingerprints for
  =Compiler=, =Lower=, and =Anf=. Separately, =object_code= reports the
  code-path file's SHA-256 and whether its code matches the live module.
  An in-memory hotpatch can differ from the file on disk.

=source.memoized_codegen_key= is the VM's cached source-key snapshot, not
proof of loaded code. The live module fingerprints establish that identity.

=BeamLisp.Generation.receipt/0= returns these fields separately. A changed
source key does not claim that an already-running VM loaded the change.

(select-keys (BeamLisp.Generation/receipt) [:source :seed :loaded])
#+end_src

* Hotpatch receipts

=BL_HOTPATCH= recompiles named boot namespaces and swaps their emitted modules
inside one VM. A namespace appears in =hotpatched_namespaces= only after all of
its emitted BEAM files load successfully.

#+begin_src sh
BL_HOTPATCH=compiler,lower mix test test/beam_lisp/generation_semantics_test.exs
#+end_src

A hotpatched receipt proves an in-memory development run. It does not prove the
committed seed. Bootstrap proof requires a fresh VM started from regenerated
seed bytes, followed by a receipt from that VM.

* Call position is callability-based

An unqualified local in call position does not use ordinary lexical shadowing
when a linked global has the same name. If the local value accepts the supplied
arity, the local runs. Otherwise the linked global runs. With no linked global,
the local is invoked directly and an invalid value or arity fails.

#+begin_src beam-lisp
(defn choose [x] [:global x])
[(let [choose (fn [x] [:local x])] (choose 1))
 (let [choose 7] (choose 1))
 (let [choose (fn [x y] [:local x y])] (choose 1))]
#+end_src
#+RESULTS: choose
: [[:local 1] [:global 1] [:global 1]]


The result is =[[:local 1] [:global 1] [:global 1]]=. This migration preserves
that rule; changing it is a language-design decision, not a compiler cleanup.

The semantic gate observes runtime values and failures for local/global calls,

* Canonical live/AOT vertical fixture

Generated body, shim, initializer companion, and provenance modules are complete
ANF descriptors. The shared boundary is:

- =BeamLisp.Ns.Anf.module(name, clauses, exports, attrs, ann)= validates the
  canonical descriptor.
- =BeamLisp.Ns.Lower.descriptor->beam(descriptor)= returns ={module, bytes}=.
- =BeamLisp.Ns.Lower.module->core(descriptor)= exposes the validated Core term.

Initializer source remains reader input and is compiled directly with
=BeamLisp.Ns.Compiler.compile-node(form, env)=. Requires, namespace metadata,
function links, value/macro replay, =put_ns_defs=, and provenance readers are ANF
clauses; no generated path quotes Elixir syntax or invokes =normalise=.

#+begin_src beam-lisp :id canonical-module-vertical
(ns compiler.canonical-vertical)
(def init-count (atom 0))
(def captured 40)
(defn classify
  ([n] :when (pos? n) [:positive (+ captured n)])
  ([_] [:non-positive captured]))
(defn collect [x & xs] (cons x xs))
(defmacro twice [x] (list '+ x x))
(swap! init-count inc)
{:guard [(classify 2) (classify 0)]
 :variadic (collect 1 2 3)
 :macro (twice 4)
 :initializers @init-count}
#+end_src
#+RESULTS: canonical-module-vertical
: {:guard [[:positive 42] [:non-positive 40]], :macro 8, :variadic (1 2 3), :initializers 1}


Expected value is
={:guard [[:positive 42] [:non-positive 40]], :variadic [1 2 3], :macro 8,
:initializers 1}= per successful namespace generation. Direct evaluation is a
new execution each time. Repeated =ensure_loaded= in one Env uses the loaded
namespace marker and does not replay; a fresh Env and explicit successful reload
each initialize independently. A throwing initializer leaves the namespace
unmarked; caller retry may repeat already-performed effects.

Each module-publication step compiles its descriptors before loading or writing
its modules. Source evaluation and initializer side effects are separate and
are not rolled back. Immutable body modules load before companion/public modules. A compile
failure leaves the old namespace and Env bookkeeping intact. A public load
failure reports all affected module IDs and does not commit namespace state;
already loaded immutable bodies are harmless staging residue. Disk files use
temporary-file replacement, and the outer AOT cache publishes its freshness
manifest only after the complete artifact list succeeds.

The focused consumer guard is =test/beam_lisp/anf_emit_test.exs=: it exercises
both live definition and disk compilation, checks guard/multi-arity behavior and
provenance/init entry points, and rejects =quote do=, =quote-node=, =normalise=,
=Code.compile_quoted=, =:elixir_compiler.quoted=, and =Module.create= in all
three generated-module consumers.


* Canonical eval path

=eval_form= compiles a source form to bl-ANF, wraps it as the body of a fresh
throwaway =run/0= clause, and packages the single clause in a complete
version-1 module descriptor.  =lower/descriptor->beam= compiles that descriptor
to a BEAM binary, which is loaded with =code:load_binary=.  The module is then
called and its result returned.

#+begin_src text
eval_form(form, env)
  → compile-node(form, env)             ; form → bl-ANF node
  → a/module(mname, [run/0-clause], …)  ; node → canonical descriptor
  → lower/descriptor->beam(descriptor)  ; descriptor → {mod, bytes}
  → code:load_binary + apply(mod, run, [])   ; load, call, return value
#+end_src

The module is KEPT loaded because the returned value — a macro fn, a =def='d
lambda — may be a closure whose code lives in it.  Keeping the module alive
keeps the code reachable.  This is the only eval path; there is no interpreted
fall-through and no Elixir-quoted alternative.

The same =descriptor->beam= compilation path handles every module kind:
live namespace generation, AOT caching, server modules, record modules,
and future native-eligible modules.  No path reaches the BEAM from a quoted
Elixir AST, a =normalise= call, a =quote-node= builder, or any module form
other than the canonical descriptor.
