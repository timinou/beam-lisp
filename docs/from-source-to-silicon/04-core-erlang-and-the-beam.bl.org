#+TITLE: 4 · Core Erlang and the BEAM
#+STARTUP: showall

* The last mile is someone else's

The BEAM does not run Erlang source, or Elixir source, or beam-lisp source.
It runs =.beam= files, and the road to a =.beam= goes through *Core Erlang* —
the BEAM's simplest real input language: functions, patterns, let, case,
calls. No macros, no syntax sugar, no module system worth the name.

beam-lisp's backend is a translator from bl-ANF to Core Erlang. It lives in
=priv/boot/lower.bl=, it is written in beam-lisp, and it is small, because the
IR is small: seventeen op constructors in, a handful of =cerl= calls out.

Then the translator's output goes to one Erlang stdlib call:

#+BEGIN_SRC erlang
:compile.forms(core_module, [:from_core, :binary, :return])
#+END_SRC

That call is the BEAM's own code generator — the same one that compiles
Erlang itself. It is the entire non-beam-lisp portion of the pipeline. There
is no Elixir compiler anywhere on this road.

* The lowering is a table, not a program

Read =lower-anf= in =priv/boot/lower.bl=. It is one =cond=:

| bl-ANF op | Core Erlang it becomes |
|-----------+------------------------|
| =:lit= | a literal term |
| =:var= / =:let= | a Core variable / a Core =let= |
| =:global= | a call to =BeamLisp.Env.fetch!(ns, name)= |
| =:remote= | a Core call, module and function as atoms |
| =:apply= | a Core =apply= — calling a value |
| =:if= | a =case= with one guarded clause: =X when X =:= false or X =:= nil → else=, catch-all → =then= |
| =:case= | a Core =case= — patterns lower to Core patterns |
| =:fn= | a Core =fun= |
| =:try= / =:recv= | Core =try= / =receive= |
| data ops | Core tuple/map/cons constructors |

One op in, one constructor out. The =:ann= maps ride along unread — today the
backend trusts the IR; pages 6 and 7 are about what happens when it starts
*reading* the annotations.

The =:if= row deserves a second look. A naive lowering of "truthiness" emits
the =else= branch twice (once for =false=, once for =nil=) — and because a
=cond= nests one =if= inside another's else, a 15-branch =cond= would lower
its last branch 2¹⁴ times. The guarded-clause encoding collapses both falsey
tests into one clause, so every branch lowers once. Compilers are full of
these: the difference between correct and unusable is one encoding decision.

* One namespace, many modules

A namespace does not compile to one BEAM module. It compiles to a *topology*:

#+BEGIN_SRC text
BeamLisp.Ns.MyApp        ← the shim: one tiny forwarding function per var
BeamLisp.Ns.Body.MyApp   ← the body: the real code
BeamLisp.Ns.Init.MyApp   ← init: replays the namespace's def VALUES at load
#+END_SRC

Why the split? *Redefinition.* When you redefine a function, the old
definition may still be running — a closure created a minute ago, a process
mid-loop. BEAM modules replace atomically, so reloading "the" module would
yank the old code out from under them. Instead, a redefinition makes a /fresh
body module/ and repoints the shim. Old closures keep their old body module,
which is never loaded again and so never purged. New calls get the new code.
Nobody is interrupted; nothing is stale.

You can see the topology on disk after a build:

#+BEGIN_SRC sh
ls _build/dev/lib/beam_lisp/ebin | grep Elixir.BeamLisp.Ns.Core
#   Elixir.BeamLisp.Ns.Core.beam        — shim
#   Elixir.BeamLisp.Ns.Body.Core.beam   — body
#   Elixir.BeamLisp.Ns.Init.Core.beam   — init
#+END_SRC

* Reproducible bytes

Build the same source twice and you get the same =.beam=, byte for byte —
all 303 modules of a full build. This is a *tested property*
(=aot_reproducible_test.exs=), not a hope. It costs something real: the
compiler cannot use global counters for fresh names (a parallel build would
interleave them), cannot iterate maps in atom-creation order (depends on VM
history), cannot let "what was compiled earlier in this VM" influence
anything. Every emitted byte is a function of the source alone.

The payoff is a cache that can be trusted blindly — same key, same bytes —
and diffs that mean what they say.

* Try it

1. Find =lower-anf= in =priv/boot/lower.bl= and pick one op. Follow it into
   the =cerl= call. The =cerl/*= functions are OTP's own Core Erlang builder
   API — =:cerl.c_call=, =:cerl.c_case=, and friends.
2. Build the project (=mix compile.beam_lisp=), pick a namespace, and find
   its three modules in =_build/dev/lib/beam_lisp/ebin/=. Which one is small
   (the shim)? Which one is big (the body)?
3. In a running session, define a function, keep a closure to it, redefine
   the function, and call both. The closure sees the old definition; new
   calls see the new one. That is the body-module topology working.
