#+TITLE: 2 · Reading and compiling
#+STARTUP: showall

* Two steps, not one

When you hand beam-lisp a file, two different things happen, and keeping them
apart is the key to everything else in this series.

*Reading* turns text into /forms/ — data structures that mirror the text.
Compiling turns forms into /meaning/ — code that runs.

#+BEGIN_SRC text
"(+ 1 2)" ──reader──▶ a list of three things: the symbol +, 1, 2
                      ──compiler──▶ a program that adds 1 to 2
#+END_SRC

The reader is =priv/boot/reader.bl=. The compiler is
=priv/boot/compiler.bl=. Both are beam-lisp.

* Code is data, literally

The reader does not build a mysterious compiler-internal tree. It builds
ordinary beam-lisp values — the same values you can make by hand:

#+BEGIN_SRC clojure
(read-data "(+ 1 2)")
;; => a list: (symbol "+", 1, 2)

(first (read-data "(+ 1 2)"))
;; => the symbol +
#+END_SRC

A list whose first element is a symbol /means/ "call this" — but only when the
compiler says so. As a value, it is just a list. You can cons onto it, map over
it, store it in an atom. Programs are values; that is the whole trick.

* What the compiler does with a form

Compile is one big dispatch on the shape of the form:

- A *literal* (number, string, keyword) compiles to itself.
- A *symbol* resolves: is it a local binding (=let=, function parameter)? A
  function interned in some namespace? An unknown name is a compile error,
  with the file and line attached.
- A *list* is a call. If the head names a special form (=if=, =let=, =fn=,
  =case=, =receive=, =quote= …) the compiler has a dedicated rule for it. If
  the head names a *macro*, the macro runs first — its output is compiled
  instead. Otherwise it is an ordinary function call.

That is the entire algorithm. Roughly four thousand lines of beam-lisp, most
of which is care about patterns, guards, destructuring, and error messages —
the dispatch above is the skeleton they hang on.

* Macros happen before anything else

A macro is a function =form → form= that the compiler calls /while
compiling/. When you write

#+BEGIN_SRC clojure
(when (ready? x) (launch! x))
#+END_SRC

the compiler never sees =when=. It sees what the =when= macro returns:

#+BEGIN_SRC clojure
(if (ready? x) (do (launch! x)) nil)
#+END_SRC

and compiles /that/. You can watch this happen. Reader forms carry position
metadata, so peel it off first — what remains is the bare form the compiler
works on:

#+BEGIN_SRC clojure
(ns demo (:require [compiler :as c]))

(def raw  (first (BeamLisp.Ns.Reader/read_string "(when (ready? x) (launch! x))" nil)))
(def form (reader-node/node-form raw))   ; peel the position metadata

(c/macroexpand_1 form "demo")
;; => (if (ready? x) (do (launch! x)) nil)
#+END_SRC

That =if= is exactly what =priv/boot/core.bl='s =defmacro when= says it
produces — and it is all the backend ever sees of =when=.

The comfortable surface of the language — =when=, =cond=, =->=, =doseq=,
=defn= with docstrings and attr-maps — is a library of these rewrites
(=priv/boot/sugar.bl= and the prelude), not compiler features. Consequence:
everything downstream of macro expansion only ever meets a dozen special
forms. The backend's whole world is a dozen shapes. Hold that thought for
page 3.

* Namespaces are where names live

A =defn= does not create a method on an object or an entry in a global dict —
it /interns a var/ in a namespace. Namespaces are the unit of code loading:
=(ns my.app (:require [other.ns :as o]))= declares the namespace, loads what
it needs, and installs the short alias.

At runtime the =Env= (a small Elixir module, part of the runtime the language
stands on) holds the table: namespace → name → var. Interning a new
definition under an old name /replaces/ the var — and every new caller gets
the new code immediately. That is hot code reloading, and it is why the
repository's own compiler can be recompiled while it is running. Page 5 shows
why that matters existentially.
