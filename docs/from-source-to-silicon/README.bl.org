#+STARTUP: showall

* What this series is

You are holding a language that compiles itself. Not "is written in itself,
with a little help from a compiler written in something else" — the reader,
the compiler, and the backend that emits BEAM bytecode are all beam-lisp
source files, compiled by beam-lisp, living in this repository as =priv/boot=
and =priv/self=.

This series walks the whole road, in order, from a blob of text to running
native code:

* The thirty-second version

#+BEGIN_SRC text
text ──reader──▶ forms ──compiler──▶ bl-ANF ──lower──▶ Core Erlang ──:compile.forms──▶ .beam
       (bl)           (bl)               (boot/lower.bl)        (Erlang stdlib)
#+END_SRC

Every arrow but the last is beam-lisp code reading beam-lisp data. The last
arrow is the BEAM's own code generator — the same one Erlang itself uses —
reached through a single stdlib call. That call is the entire "other language"
in the pipeline.

Then, for the fragments of a program that are proven safe and hot, there is a
second road off the IR: bl-ANF nodes carry proof annotations, and a proof-
directed offload path compiles them to native machine code. That road is
measured, gated, and honest about what it can't yet do — page 7 tells that
story with numbers.

* Who this is for

The curious. You do not need to know Erlang, Elixir, Lisp, or compilers. Each
page starts from zero and builds. If you do know compilers, skim pages 1–2 and
settle in at page 3 — that is where the unusual decisions begin.
