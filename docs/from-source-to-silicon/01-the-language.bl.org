* beam-lisp in one paragraph

beam-lisp is a Lisp that runs on the BEAM — the virtual machine that runs
Erlang. That means your programs are made of the things Lisps are made of
(lists, symbols, functions, macros, immutable data) and they /run/ the way
Erlang programs run: millions of cheap processes, messages instead of shared
memory, supervision instead of defensive coding. Clojure programmers will feel
at home with the syntax; Erlang programmers will feel at home with the
semantics.

You do not need to install anything beyond this repository. Every example on
this page runs with:

#+BEGIN_SRC sh
mix beam_lisp.run path/to/file.bl
#+END_SRC

* Values are values

Numbers, strings, keywords (atoms that start with =:=), lists, vectors, maps.
Data is immutable: "changing" a map makes a new map.

#+BEGIN_SRC clojure
(ns hello)

(def person {:name "Ada" :age 36})
(println (assoc person :age 37))   ; => {:age 37, :name "Ada"}
(println person)                    ; => {:age 36, :name "Ada"} — untouched
#+END_SRC

* Functions, and functions of functions

#+BEGIN_SRC clojure
(defn greet [name]
  (str "hello, " name "!"))

(println (greet "curious reader"))  ; hello, curious reader!
(println (map inc [1 2 3]))          ; (2 3 4)
#+END_SRC

=defn= names a function. =fn= makes an anonymous one. =map=, =filter=,
=reduce=, =comp=, =partial= — the usual Clojure toolkit is in the prelude,
and the prelude itself is beam-lisp source you can read: =priv/boot/core.bl=.

* Pattern matching instead of branching

=case= picks a branch by the /shape/ of a value:

#+BEGIN_SRC clojure
(defn area [shape]
  (case (first shape)
    :square (* (second shape) (second shape))
    :circle (* 3.14159 (second shape) (second shape))))

(println (area [:square 4]))   ; 16
(println (area [:circle 1]))   ; 3.14159
#+END_SRC

The same matching works in =let= (to take apart a value) and in =receive=
(to select messages). Guards add a test a pattern alone cannot express:
=([n] {:when (> n 0)} ...)=. And one name can carry several arities — a
different parameter /count/ picks a different body:

#+BEGIN_SRC clojure
(defn sum
  ([a] a)
  ([a b] (+ a b))
  ([a b c] (+ a b c)))

(println (sum 1) (sum 1 2) (sum 1 2 3))   ; 1 3 6
#+END_SRC

* Processes: the BEAM part

A process is a running function with a mailbox. You =spawn= one, send it a
message with =erlang/send=, and it picks messages out of its mailbox with
=receive= — by pattern:

#+BEGIN_SRC clojure
(ns ping)

(def server
  (spawn (fn [] (receive
                  [:get caller] (erlang/send caller 42)
                  other          (println "huh?" other)))))

(erlang/send server [:get (erlang/self)])
(println (receive n n))   ; 42
#+END_SRC

The mailbox is not a queue you drain top-first: =receive= /selects/ the first
message that matches a clause. Messages that match nothing stay put. This one
rule is the heart of every Erlang system ever written, and it is the reason
beam-lisp exists: to put that rule inside a Lisp.

* Macros: the language extends itself

=defmacro= writes a function from code to code, run at compile time. The
compiler is one small core of special forms (=if=, =let=, =fn=, =case=,
=receive=, =quote= …) plus a macro library written in beam-lisp that grows the
comfortable surface — =when=, =cond=, =->=, =doseq= and friends are macros,
not compiler features.

That matters for everything else in this series: because macros expand to the
small core before the compiler sees them, the /backend/ only ever has to
understand the small core. Page 3 shows what that core becomes.

* Try it

1. Write =fib= (with =cond=) and print its first ten values.
2. Write a process that answers =[:double n]= with =2*n=, forever. (Hint:
   wrap the =receive= in a =loop= … =recur= — tail calls never grow the
   stack.)
3. In the =receive=, what happens to a message that matches no clause?
   Check your answer by sending =server= a message like =:welp= and then a
   =[:get …]= — which one is answered?
