#+title: Milestone 2 — bounded subscriptions and resynchronization
#+status: Change delivery verified; broader lifecycle audit continues

* Read snapshots first
Every delivery carries current bounded snapshots. Consumers can replace their
read model directly; they never need to replay an unbounded event log. A second
callback argument carries changes, departed scopes, actual skipped-delivery
counts and delivery sequence. Existing one-argument consumers keep working.

#+begin_src beam-lisp
(ns ^:js subscription.walkthrough
 (:require [js.observation :as observation]))
(def dispose
 (observation/subscribe
  (fn [snapshots delivery]
   ; A host consumes native snapshots; ordinary BL can explicitly convert them.
   (.log js/console (.-coalesced delivery)))
  #js {:interval 1000 :active (fn [] (not (.-hidden js/document)))}))
(dispose)
#+end_src

Browser access stays in the annotated namespace. Native state stays native;
BL snapshot history stays in an ordinary atom. The interop boundary refuses
putting persistent BL collections into an unconverted JavaScript property.

* Changed, removed, reset
=runtime.observation/changes= compares native or browser-shaped BL snapshots.
The output names upserts and removals. First observation, changed scope, missing
sequence evidence or a backwards sequence requires a reset from the current
snapshot. An unchanged peer sequence does not fabricate changes.

#+begin_src beam-lisp
(ns changes.walkthrough (:require [runtime.observation :as observation]))
(observation/changes
 {:scope {:realm "project-a"} :sequence 1 :resources [{:id "job-a"}]}
 {:scope {:realm "project-a"} :sequence 4 :resources [{:id "job-b"}]})
#+end_src

The sequence gap is two unseen samples. It does not prove packet loss: another
reader may have sampled the same source. =:coalesced= counts actual timer ticks
skipped because this subscriber still had a pending host delivery. Do not
conflate these two measurements or turn unknown transport loss into zero.

* No growing delivery queue
Ordinary synchronous callbacks finish in the sampling turn. If a host callback
returns a promise, the subscription permits only that one pending delivery.
While it is pending, ticks allocate no additional snapshots; they increment a
counter. The next eligible tick obtains current snapshots and changes, which
resynchronizes without replaying stale work. There is no async/await scheduler
or second actor registry here: promise settlement is only a browser host leaf.

=dispose= closes the timer and reader exactly once. Callback failure closes
both and invokes optional =onError=. A late promise rejection after disposal
cannot reopen the subscription or notify a removed view. The caller owns any
external side effects it starts; disposal does not claim to cancel an arbitrary
JavaScript promise or preempt a synchronous callback.

* Bounds and lifecycle
32 resources/readers/peers per hub, 128 KiB per report, 96 KiB resource-data
budget, six-second peer expiry, 250–60000 ms intervals. Each change scope admits
at most 128 rows. Actor state remains authoritative in its actual runtime.
Cross-tab data remains descriptive; local actions require a current owned handle.
