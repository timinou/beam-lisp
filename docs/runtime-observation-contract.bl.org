#+title: Milestone 1 — a bounded view of the actual owner
#+status: Native query implementation verified; cross-target audit in progress

* Start with the owner
An observation is a read, not a capability. Native hosts capture their current
realm with =vm.observation/capture= and request at most 128 resources. The actual
membership still lives in =vm.owner= and its ordinary =proc.reg= registry.

#+begin_src beam-lisp
(ns observation.walkthrough
  (:require [vm.observation :as observation]))
(def scope (observation/capture))
(observation/snapshot scope 16)
#+end_src

Read =:scope= before interpreting =:resources=. Physical =:vm= counters cover
all projects in that BEAM. =:realm= and process rows cover the captured realm.
A foreground host sees its capturing process only. A trusted host must perform
its existing authentication/capability checks before exposing the projection.

* What changed
Previously the host fetched every realm member, then kept the first 128. Now
the existing registry maintains declared-key indexes in the same state and
transaction as its entries. A VM query selects the existing VM index, reads its
size without enumeration, and traverses only the requested number of rows.
Indexes contain lookup keys; they are not another ownership registry.

=:query :examined= reports how many candidates the request inspected. For a
single declared key, =:total= is exact even when rows are truncated. Arbitrary
predicates have a 4096-candidate traversal budget; =nil= total means unknown,
not zero. Samples are bounded current views, not stable paginated snapshots.
No cursor pretends that concurrent registrations form an immutable generation.

Registry replacement also reuses its existing process monitor. Unregister/death
retracts the entry, derived indexes and monitor together. An invalid public
sample limit is rejected before sending a request to the owner.

* Identity and authority
| Target/resource | Identity scope | Meaning / authority |
|-----------------+----------------+---------------------|
| Native process | physical runtime, capture epoch, realm, printable PID | descriptive; controls use the trusted host's actual owner |
| JS actor | JS runtime instance plus actor PID | actual :procs entry, not a report registry |
| Browser resource | browser session UUID plus disposable registration ID | local live handle may resolve its declared actions |
| Pooled Worker | reporting resource plus fresh physical pool ID | actual pool record; actor PIDs qualified beneath it |
| Peer tab | reported browser session | expiring read-only data; no remote control grant |
| Frontend generation | immutable content identity | host-admitted candidate; opening creates a separate session |

Never turn a printable ID from an observation into an unrestricted kill/restart
operation. Worker and browser reports do not merge native realm authority.

* Target support
| Counter | BEAM host | JavaScript actor | Browser resource / Worker |
|---------+-----------+------------------+---------------------------|
| Actual owner relationship | realm membership / standard private work | explicit actor owner edges | physical resource owner; cached actor report |
| Process status / mailbox length | available while process lives | runtime state, count only | only through reported actor snapshot |
| Reductions / process memory | BEAM process counters | unavailable | unavailable |
| Physical VM aggregate | separately labelled | unavailable | unavailable |
| Audio / frame / preparation timing | domain report | domain report | Pelagic diagnostics with clock/source labels |
| Physical speaker/display latency | unmeasured | unmeasured | requires device measurement |

No observation module assumes that a Worker has a DOM or that an AudioWorklet
has BroadcastChannel. Browser resource reporting is optional host machinery;
the actor's direct read projection does not depend on a channel or the editor.

* Try the registry directly
#+begin_src beam-lisp
(ns registry.walkthrough (:require [proc.reg :as reg] [vm.owner :as owner]))
; A host already owns a realm; do not create a second registry for inspection.
(owner/sample-members "your-owned-realm" 8)
#+end_src

A returned =:truncated true= asks the UI to show the limit. A missing counter
asks the UI to show unavailable. Neither should be formatted as zero.
