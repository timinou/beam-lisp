#+TITLE: The wire, and the three seams it closes
#+STARTUP: showall

* The one grammar both halves speak

Everything that crosses the network in a split app has a declared shape, and
that shape is data. One file, =priv/lib/split/wire.bl=, says what a shape
means — and the SAME file runs on both sides: natively in the BEAM authority,
and compiled to JavaScript inside the browser half. So "is this a valid
item?" has exactly one answer.

| shape                 | a value of it                                        |
|-----------------------+------------------------------------------------------|
| =[:text min max]=     | a string of min..max Unicode codepoints              |
| =[:int min max]=      | an exact integer in range (inside ±(2^53−1))         |
| =:exact=              | an integer of any size                                |
| =:bool=               | true or false                                        |
| =[:one-of k …]=       | one of the listed keywords                           |
| =[:list max T]=       | a vector of at most max values of T                  |
| =[:record {k T …}]=   | a map with exactly these keys                        |
| =:name=               | another named shape (may recur through a list)        |

#+begin_src beam-lisp :id grammar
(ns split-doc-3 (:require [split.wire :as wire] [split.web :as web] [split]))

(def types
  {:item [:record {:id [:int 1 999] :name [:text 1 12] :kids [:list 4 :item]}]})

(defn ok? [v] (wire/wire-ok? types :item v))
(println "a leaf              " (ok? {:id 1 :name "Oat milk" :kids []}))
(println "a small tree        " (ok? {:id 1 :name "Plan" :kids [{:id 2 :name "Step" :kids []}]}))
(println "an extra key        " (ok? {:id 1 :name "x" :kids [] :secret 1}))
(println "a name too long     " (ok? {:id 1 :name "Thirteen chrs" :kids []}))
(println "too many children   " (ok? {:id 1 :name "x" :kids (vec (repeat 5 {:id 2 :name "y" :kids []}))}))
#+end_src
#+RESULTS: grammar
: a leaf               true
: a small tree         true
: an extra key         false
: a name too long      false
: too many children    false
: :ok


* Seam one: what may leave the server

A handler may keep anything in its state — a counter, an audit trail, a
password hash. What leaves is the state /projected/ onto the snapshot shape:
records keep only the keys their shape names, all the way down. Nothing a
handler stores can leak by accident, because the projection has no place to
put it.

#+begin_src beam-lisp :id projection
(def state {:id 1 :name "Plan" :owner-email "ana@example.com"
            :kids [{:id 2 :name "Step" :kids [] :internal-note "rewrite"}]})
(println (wire/wire-project types :item state))
#+end_src
#+RESULTS: projection
: {:id 1, :name "Plan", :kids [{:id 2, :name "Step", :kids []}]}
: :ok


* Seam two: the same meaning on two runtimes

Shared functions run on BEAM and in JavaScript, so any difference in meaning
between the runtimes would let a browser's check disagree with the server's.
Text length was one: =count= of a string counts /graphemes/ on BEAM and
UTF-16 units in JavaScript. The wire therefore never asks =count= — it
measures codepoints, the one length both runtimes agree on, and the parity
suite (=research/js-actors/order-parity.bl=, case =text-codepoints=) runs the
same expressions on both and requires equal answers.

#+begin_src beam-lisp :id text
(doseq [[label s] [["abc" "abc"] ["two bananas" "🍌🍌"] ["e + combining accent" "e\u0301"] ["é, one codepoint" "é"]]]
  (println (str label ": count " (count s) " · codepoints " (wire/wire-text-length s))))
(println "three bananas fit [:text 1 3]:" (wire/wire-ok? {} [:text 1 3] "🍌🍌🍌"))
#+end_src
#+RESULTS: text
: abc: count 3 · codepoints 3
: two bananas: count 2 · codepoints 2
: e + combining accent: count 1 · codepoints 2
: é, one codepoint: count 1 · codepoints 1
: three bananas fit [:text 1 3]: true
: :ok


On BEAM, =count= of "e" plus a combining accent is 1 (one grapheme) while
it holds two codepoints; in the browser, =s.length= of two bananas is 4 (four
UTF-16 units) while they are two codepoints. The codepoint column is the one
both runtimes print.

When the two runtimes still disagree somewhere the parity suite has not yet
reached, the server's answer wins: the browser's guess is replaced, and the
disagreement shows up as a correction, never as wrong data.

* Seam three: who is asking

A browser never says who it is inside a proposal. The transport decodes the
proposal by the contract — a proposal with an =actor= key has the wrong keys
and is refused — and stamps the person from a session cookie it signed
itself. The authority then asks the app's own =:allow= with that person.

#+begin_src beam-lisp :id actor
(def tiny (split/app "tiny" '{:wire {:b [:record {:n [:int 0 9]}]} :server {:snapshot :b}
                              :intents {:bump {:params {:by [:int 1 3]}}}}
                     {:server {} :intents {}} {}))
(def honest {"request" 1 "revision" 0 "digest" (:digest tiny) "nonce" "doctab003:1" "op" "bump" "args" {"by" 2}})
(println "honest   " (first (web/decode-proposal tiny honest)))
(println "claims to be ana" (web/decode-proposal tiny (assoc honest "actor" "ana")))
#+end_src
#+RESULTS: actor
: honest    :ok
: claims to be ana [:bad 400 :malformed-proposal]
: :ok


* Recursion, bounded

A shape may name itself, but only through a list (the empty list ends every
value, so a finite one always exists), and no value may nest deeper than 24
lists and records. The same bound is in the JS codec; =verify-outline.mjs=
checks the two agree.

#+begin_src beam-lisp :id depth
(defn chain [d] (if (zero? d) {:id 1 :name "leaf" :kids []} {:id 1 :name "n" :kids [(chain (dec d))]}))
(println "max depth" (wire/wire-max-depth))
(println "11 levels (22 containers):" (ok? (chain 10)))
(println "13 levels (26 containers):" (ok? (chain 12)))
#+end_src
#+RESULTS: depth
: max depth 24
: 11 levels (22 containers): true
: 13 levels (26 containers): false
: :ok
