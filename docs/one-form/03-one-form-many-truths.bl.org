#+TITLE: One form, many truths
#+STARTUP: showall

* The compiler's IR is the one place a fact about your program lives

A program becomes one intermediate form, bl-ANF. That form is not just what the
backend turns into machine code — it is where /everything known about the
program/ is recorded, on each node's =:ann=:

- *where it came from* — the full source span (line, column, end), so an error
  points a caret at the exact expression and a stack frame names your file;
- *what it proves* — its footprint (what it touches), whether it halts, the
  shapes its value can take;
- *who it talks to* — the functions it calls, resolved across the whole program.

One structure, read by everyone. There is no position table on the side, no
per-engine copy of the program, no re-derivation of a fact another pass already
found.

* Facts cross function boundaries

Because each function has a summary and the summaries are propagated across the
call graph, a fact known about one function flows to everyone who calls it. A
caller's footprint includes its callees'. A caller's return shape follows from
its callees'. A type error that only appears /across/ a call — passing a
keyword where a number is required, through a helper — is caught:

#+begin_src beam-lisp :id interproc
(ns demo (:require [system.typecheck :as tc]))
(println (count (tc/check-source "(defn mk [] :kw)
                                  (defn use [] (erlang/+ 1 (mk)))")))
#+end_src

#+RESULTS: interproc
: 1
: :ok

One warning: =+= receives =mk='s keyword return. A checker looking at =use= in
isolation sees only =(erlang/+ 1 (mk))= with =(mk)= an unknown — and stays
silent. The whole-program view knows =mk= returns a keyword, and speaks.

* A proof says what it did — and what it did not

A verification is only as honest as its coverage. When the checker can model
every transition of a process, it says so; when a transition's next state is
beyond what it can express, it says /that/ too, rather than quietly proving less
and reporting success:

#+begin_src beam-lisp :id honest
(ns demo (:require [system.core :as sys] [z3]))
(def port (z3/open))
(def r (sys/verify-process port
         (first (BeamLisp.Reader/read_string
           "(defserver ^{:invariant (>= balance 0)} acct
              (init [] (ok {:balance 100}))
              (handle-call [:withdraw amt] [_ {:keys [balance]}] :when (<= amt balance)
                (reply :ok {:balance (- balance amt)})))"))))
(println (pr-str {:holds (:holds r) :complete (:complete r)}))
#+end_src

#+RESULTS: honest
: {:complete true, :holds true}
: :ok

=:holds true= with =:complete true= is a total proof. A server whose next state
is computed by a helper the checker cannot translate would come back
=:complete false=, naming the transition it left unverified — a partial proof
that never masquerades as a whole one.

* Why it holds together

Every engine reads the same IR the backend reads, writes its findings back onto
the same nodes, and consumes what the others wrote. Position, proof, and call
graph are one channel. A fact is computed once and reused — so the answers agree,
the error messages point true, and adding a new kind of reasoning means teaching
one pass, not walking the program a new way.
