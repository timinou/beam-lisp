#+TITLE: The surface walks are gone
#+STARTUP: showall

* One tree, walked once

Before position lived in the IR, an engine that wanted to point at a mistake had
two choices, and it took both. It walked the compiled form to reason about
meaning, and it walked the /surface/ syntax tree a second time to recover a line
and column to print. Two walks of the same program, kept in step by hand.

Now every node carries its own source span. So the second walk is not just
redundant — it was the *worse* of the two. This is the story of deleting it.

* Termination points at the loop, from the loop

The termination checker used to enumerate loops by walking the surface tree, on
the theory that only the surface form knew where a loop was written. It did not:
the surface loop node carried no populated position, so the one place that
rendered a termination error /hard-coded/ the column. The real position was
sitting on the compiled loop the whole time.

Now the checker walks the compiled program. A loop desugars to a scaffold whose
=:ann= carries its exact span; the verdict carries that span straight through:

#+begin_src beam-lisp :id termination-pos
(ns demo (:require [termination :as term]))
(def v (term/check-source "(ns m)
                           (defn spin [n]
                             (loop [i n] (if (keep? i) (recur (inc i)) i)))"))
(def r (first v))
(println (pr-str {:status (:status r) :has-position (contains? (:pos r) :line)}))
#+end_src

#+RESULTS: termination-pos
: {:status :rejected, :has-position true}
: :ok

The verdict is =:rejected= (a count-up loop with no bounding guard), and it
carries a real position — read from the IR, not recovered by a parallel walk of
the syntax. The surface enumeration that used to do this is deleted. A loop
written *inside* a function is found by the same walk, because the checker
descends into the compiled function body where the loop actually lives.

The trusted escape hatch moved too. A =^{:decreasing}= measure the author
asserts is a termination proof; it now rides on the loop's =:ann=, the same
channel as position and every other fact. The checker reads trust and location
from one place.

* Substitution keeps its position

Some proofs rename a variable before checking — an invariant written about =st=
must be checked against the state variable the process actually uses. The old
way turned the predicate back into text, edited the string, and re-read it.
The round-trip worked, but it threw the positions away: a caret on a renamed
predicate pointed nowhere.

Now the rename walks the node tree directly. A matching symbol is replaced in
place, its source position preserved; the surrounding form is rebuilt from its
renamed children. Nothing becomes a string and comes back. So an invariant
proven after substitution still points a caret at the text the user wrote — and
a server that violates it is caught with a real location, whether the invariant
was written as metadata or as a clause with its own name for the state.

* What one channel buys

Deleting the second walk is not a tidy-up. It removes a whole class of bug: two
walks that can *disagree* — enumerate different forms, compute different
positions, drift as the compiler changes. With one tree carrying meaning and
position together, an engine cannot point at the wrong place, because there is
only one place to point at. The compiler, the error printer, and every proof
engine now read the same span off the same node. That is the invariant the
one-form design was for.
