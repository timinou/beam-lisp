#+TITLE: Position lives in the IR
#+STARTUP: showall

* One form knows both what it means and where it came from

A beam-lisp program is compiled into one small intermediate form, bl-ANF —
a tree of nodes, each a plain map with an =:op= and its operands. Every node
also carries an =:ann= map: its *annotations*. Among them is the node's source
position — where in the =.bl= file that exact piece of code was written.

This is the whole idea: the form the compiler reasons about, the form the
backend turns into machine code, and the form an error message points at are
the *same form*. There is no separate "position table" kept on the side. A node
knows what it means and where it came from, together.

* What a node's position looks like

Every node built from real source text carries, in its =:ann=:

| key         | meaning                                    |
|-------------+--------------------------------------------|
| =:line=     | the line the form starts on                |
| =:col=      | the column it starts at                    |
| =:end-line= | the line it ends on                        |
| =:end-col=  | the column just past its last character    |
| =:file=     | the source file it came from               |

Start /and/ end — so the position is a full *span*, not just a point. That span
is what lets a diagnostic underline the whole offending expression instead of
tapping a single caret at its first character.

A node conjured out of thin air — the output of a macro, say — honestly carries
no position. The truthful answer to "where in my file did this come from?" is
"nowhere; a macro wrote it," and the node reflects that by simply omitting the
keys.

* Pointing at code

Because the position travels with the node, anything holding a node can point a
reader at the exact source. =errors/node->warning= turns a node into a warning,
and =errors/render= draws it with an underline the width of the span:

#+begin_src beam-lisp :id caret
(ns demo (:require [compiler :as c] [errors]))

(def node (c/compile-node
            (first (BeamLisp.Reader/read_string "(erlang/element 9 t)"))
            (c/new-env "demo")))

(def warning (errors/node->warning node "index out of range"))
(println (errors/render "demo.bl" "(erlang/element 9 t)" warning))
#+end_src

#+RESULTS: caret
: demo.bl:1:1: index out of range
:   1 │ (erlang/element 9 t)
:     │ ^^^^^^^^^^^^^^^^^^^^
: :ok

The underline spans the whole form — twenty carets under twenty characters —
because the node's =:ann= knows the form runs from column 1 to column 21. No
guessing at token boundaries; the reader measured it once and the measurement
rode along.

* One channel, many readers

The same position in =:ann= serves everyone who needs to point at code:

- *The backend* stamps =:line= and =:file= onto the emitted BEAM code, so a
  runtime crash's stack frame names your =.bl= file and line.
- *The proof engines* (allocation, termination, types) attach their findings to
  the very same nodes, so a proof and its source location are one object: "this
  allocation, proven at =foo.bl:42:7=".
- *The error printer* draws carets and underlines from it.

One position, written once by the reader, read by all. When you want to know
where a node lives, you ask the node — never a bookkeeping table kept in
parallel.
