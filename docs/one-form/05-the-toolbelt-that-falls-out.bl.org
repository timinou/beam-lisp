#+TITLE: The toolbelt that falls out of one form
#+STARTUP: showall

* One substrate, many tools

The one-form work made bl-ANF the single carrier of everything known about a
program: where each node came from (=:ann= span), what it proves (footprint,
termination, return type), and who it calls (the whole-program call graph in
=system.analyze=). That substrate is not just cleaner internals — it is a
*platform*. A whole class of developer tooling that used to be "write a new
engine" collapses to "read a field."

This document specifies six such tools. Each is backed by a working prototype
under =research/= with measured results; each names what it deletes and what it
newly enables. The through-line: these are not six features, they are six
*projections of the same substrate*, and they share machinery deliberately.

Read the numbers as claims you can re-run — every prototype is a `.bl` file with
a runnable demo.

* Tool 1 — Trivia-preserving structural rewrite (the deodorant upgrade)

** The problem it fixes

=deodorant/fix-source= splices =(pr-str fixed)= at a smell's span. =pr-str=
re-renders the whole matched subtree on one line, destroying multi-line shape
and every comment inside. Measured on the engine tree: a sweep dropped =ir.bl=
249→238, =model.bl= 364→340, =smt.bl= 533→496 lines — comments gone. So the
blanket "fix every idiom across the codebase" the doctrine wants is unusable;
only single-line smells splice cleanly.

** The fix, from first principles

Every reader node now carries a full span ={:line :col :end-line :end-col}=. A
rewrite rule's capture variables (=?x=) bind to whole sub-*nodes*. So instead
of re-printing a capture, we slice its *original source bytes* out of the file
and splice them into the new skeleton; only the rule's own literal tokens are
newly rendered. Everything the rule did not name stays byte-identical.

** Measured (=research/structural-rewrite/=)

Rewriting =(if (not P) A nil)= → =(when P A)= on a multi-line body with a
comment:

- =fix-source= → =(when-not (empty? items) (do (filter good? items)))= — the
  =do= block collapsed, the =; keep the good ones= comment *gone*.
- span-rewrite → the =do= block and its comment preserved byte-for-byte; only
  =if=→=when= is new text.

** What it becomes

Fold =:render= (compose original slices) into every =deodorant= smell beside its
=:pattern=. Then =deodorant fix --all= is a first-class command: every idiom fix
across every =.bl= file, comments and formatting intact. This is also the engine
behind the LSP =codeAction= (quick-fix) below — one rewriter, two surfaces.

* Tool 2 — A language server that is not a server

** Why the LSP split dissolves

A conventional LSP has two halves that do not trust each other: a language
server that re-parses text to answer positional questions, and a host editor
that owns the truth. beam-lisp has no such split — *the compiler is the
analyzer*. Position, inferred types, effect footprints, termination, and the
call graph already live on the IR. A "language server" is a thin index-by
-position over that, and every request is a few lines (=research/lsp/lsp.bl=).

** The full first-party LSP surface

*Ready now* (prototype implements, measured): =hover= (inter-procedural type
under the cursor), =publishDiagnostics= (every engine warning, positioned),
=documentSymbol= (each fn + its proven summary), =definition= (resolve through
the graph), =references= (graph-based — a callback IS a reference, not a grep
hit).

*Small extension, same substrate*: =completion= (symbols in scope from the env,
ranked by summary return type), =rename= (the structural node-walk from the
=subst-sym= cutover, applied file-wide via the call graph), =codeAction= (every
deodorant smell is a quick-fix; Tool 1 makes the edit trivia-safe), =inlayHint=
(inferred return tags + effect markers), =documentHighlight=, =foldingRange= and
=selectionRange= (straight from node spans), =semanticTokens= (op kind per node).

** What LSP has no words for (measured in the prototype)

LSP is a fixed menu designed around a syntax-only server. These need *proofs the
compiler computed*, so no LSP can express them:

- *proof-hover* — point at a fn, see ={pure terminates footprint returns}=.
- *native-eligibility gutter* — a green light for "this can go native," refusal
  names the failed theorem (Tool 5).
- *effect-footprint lens* — the resources a fn touches, inline.
- *"prove this invariant" code action* — drive =system.core/verify-process=
  from the editor and get =holds/complete= back (Tool 4).
- *termination lens* — the ranking variable, or why none exists.
- *impact analysis* — the transitive blast radius of a change (references go one
  hop; this goes all of them).
- *"why is this =any=?"* — trace the return-tag inference back to its source.
- *live-reload-aware diagnostics* — the reload engine already knows what a change
  breaks; surface it as you type.

** Two shipping forms

1. In-executable: =bl lsp hover FILE:L:C=, =bl lsp diagnostics FILE= — the
   intelligence with a CLI skin.
2. A ~100-line stdio JSON-RPC shim mapping LSP methods to these functions, so
   any editor talks to the beam-lisp compiler directly. The shim is dumb; the
   compiler is smart.

* Tool 3 — deodorant, coalesced into one linting surface

Tools 1 and 2 make =deodorant= more than a smell-fixer. Today it detects idioms
and (partially) rewrites them. With the span-preserving rewriter and the
whole-program graph, it becomes the project's single *lint + codemod* command:

- *detect* — the existing smell registry, plus semantic lints the graph now
  affords: dead functions (=analyze/dead-fns=), unreachable branches (from the
  type checker's provably-false guards), arity mismatches (=codebase=), effect
  violations (a fn annotated pure that footprint says is not).
- *fix* — the trivia-preserving rewriter (Tool 1), so every fix is reviewable.
- *report* — positioned via =:ann=, rendered with the one caret renderer.

This is coalescing, not new surface: =deodorant=, =codebase=, =system.analyze=,
and the type checker already exist; the graph lets them share one =lint= verb
instead of three ad-hoc entry points.

* Tool 4 — Model checking over bl-ANF (delete the last surface translator)

** The last surface-coupled engine

=system.smt/translate= walks the *surface* reader-node tree. It is the last
engine reading syntax instead of the IR, at two costs: it re-implements operator
resolution (a macro-expanded or qualified operator is a different surface shape
and is missed), and it cannot see through a call — a guard =(safe? balance)= for
a pure helper =safe?= becomes =:untranslatable=, and a transition whose next
-state is helper-computed is *silently dropped* (the Phase-4 soundness hole).

** The ANF translator (=research/model-anf/=)

Reading ANF fixes both. Operators arrive pre-resolved as =:remote [mod fun]= →
one small total table. A user call is a clear =(RT/invoke (:global f) args)= — so
if =f= is *proven pure* (=system.analyze= footprint = ∅), we look up its ANF body
and *inline it*, substituting the arguments.

Measured:

| predicate | surface SMT | ANF-SMT |
|-----------+-------------+---------|
| =(>= balance 0)= | =(>= balance 0)= | =(>= balance 0)= |
| =(safe? balance)= | =:untranslatable= | =(>= balance 0)= — inlined |
| =(>= (margin balance reserved) 0)= | untranslatable | =(>= (- balance reserved) 0)= |

And end-to-end through Z3, a server whose safety margin is a pure helper:

| obligation | z3 | meaning |
|------------+-----+---------|
| =I ∧ amt≥0 ∧ amt≤margin ∧ b'=b-amt ⇒ I[b']= | *unsat* | invariant preserved *through the helper* |
| same, guard dropped (control) | *sat* | invariant can break — z3 finds it |

** What it deletes

Once the ANF translator covers the model fragment, =system.model= /
=system.core='s surface =delaborate= round-trips and the surface =translate= walk
are redundant. =verify-process= reads the defserver's compiled ANF; guards and
next-states translate from =:remote=/=:if=/=:lit= directly. The
=delaborate=-for-DISPLAY use stays (rendering a guard for a human); the
=delaborate=-then-translate PATH dies — the same cutover shape as termination and
=subst-sym=.

* Tool 5 — Proof-directed native offload, made inter-procedural

** The relationship to the ongoing native road

=docs/memory-policy/05-proof-directed-native-offload= defines offload
eligibility as a conjunction of four theorems: =footprint = ∅ ∧ terminates ∧
sorts ⊆ NIF-safe ∧ bounded-work=. =research/lowerers_spike= already proved the
*lowering* (145× pixel blend, byte-identical) by delegating eligibility to
=system.footprint= and =termination=. The missing piece was that eligibility was
*per function*: a function calling a helper could not be judged, because the
helper was an opaque callee (footprint = =:opaque-world=).

** The win (=research/native-eligible/=)

=system.analyze= computes each summary with every callee's summary substituted —
the footprint closure. So a caller of a pure helper is itself pure, and whole
call *trees* become offloadable. Measured:

| fn | verdict | theorem |
|----+---------+---------|
| =step= (calls pure =dist2=) | *eligible*, "whole tree offloadable" | pure via closure ∧ terminates ∧ sort |
| =noisy= (calls =log-it=) | refused =:impure= | IO propagates up |
| =mk-kw= (returns =:kw=) | refused =:sort= | =:kw= ∉ NIF-safe |

=step= is the MMORPG hot-path shape — a spatial step calling a pure distance
helper — offloadable *only because* =dist2='s purity flowed through the closure.
The model swarm's =softmax → exp= is the same shape (its open question is SIMD
width, PLAN-087, orthogonal to eligibility).

** What to build

=memory.native/eligible= reads the summary and adds the two theorems the summary
does not yet carry: the sort check (=system.smt/sort-of-tags= over return/arg
tags — prototyped) and the work bound (count loop-body ops against the
termination measure — =work ≤ k·measure₀=). Then =^{:native true}= on a var, or a
namespace flag, opts a proven fragment into the =lowerers_spike= pipeline.

* Tool 6 — Why one proof pays twice (the explanation)

Tools 4 and 5 are the same key opening two doors. Both were blocked by one wall:
*an opaque callee*. A guard that calls a helper was =:untranslatable= to SMT; a
function that calls a helper was =:opaque-world= to native eligibility. The
inter-procedural footprint closure removes that wall once, and both tools walk
through:

- *native*: a pure helper's callers become offloadable (footprint closes over
  the call).
- *verification*: a pure helper's callers become provable (the helper's pure
  body inlines into the SMT formula).

The inline is *sound precisely because it is gated on the footprint proof*. A
pure helper has no effects to model, so substituting its body into a formula
changes nothing about the world — it is a pure value computation, exactly what
SMT reasons about. An impure helper is correctly *not* inlined; it stays
=:untranslatable=, honestly. So the same =footprint = ∅= fact gates both native
offload and SMT inlining. One proof, two payoffs — and every further "see
through the call" capability (partial evaluation, constant folding across calls,
purity-based memoization) is the same key again.

* The shared machinery (this is one system, not six)

| tool | reads | shares with |
|------+-------+-------------|
| structural rewrite | =:ann= end-spans | LSP codeAction, deodorant fix |
| LSP | =:ann= + =analyze= summaries | every engine's warnings |
| deodorant lint | smell registry + graph | rewrite (fix), analyze (dead-code) |
| model-over-ANF | ANF + footprint closure | native (same purity gate) |
| native offload | =analyze= summaries | model (same purity gate) |
| the explanation | the footprint closure | tools 4 and 5 |

Position lives in the IR; proofs live in the IR; the call graph is one pass. Add
a new capability by teaching one pass, and every tool that reads the substrate
inherits it. That is the dividend of one form — the tools are cheap because the
truth is in one place.

* Build order (dependency-honest)

1. *structural rewrite → deodorant* (Tool 1 → 3). Self-contained; unblocks the
   blanket idiom sweep and the LSP quick-fix. No engine changes.
2. *LSP core* (Tool 2). Pure projection; ship as a CLI first, then the JSON-RPC
   shim. Depends only on existing =analyze=/=:ann=.
3. *ANF-SMT translator* (Tool 4). Land beside the surface translator, prove
   parity on the model corpus, then cut over =verify-process= and delete the
   surface =translate= + =delaborate= round-trips.
4. *inter-procedural eligibility* (Tool 5), wired into the =lowerers_spike=
   pipeline behind =^{:native true}=. Depends on the summary (exists) + the sort
   theorem (prototyped) + the work bound (small).
5. Tool 6 is not built — it is the invariant the other tools preserve: every
   "see through the call" is gated on the footprint proof.

Every prototype for the above lives under =research/= and runs today; the
numbers in this document are their output.
