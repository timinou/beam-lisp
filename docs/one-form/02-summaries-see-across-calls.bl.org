#+TITLE: Summaries see across calls
#+STARTUP: showall

* Every engine hits the same wall — and one pass tears it down

An engine that reasons about a function hits a wall at a call to /another/
function. "What does this allocate?" — unknown, it calls something. "Does this
return a keyword?" — unknown, the value comes from elsewhere. "Is this loop
bounded?" — unknown, the bound is computed by a helper. Each engine fails at the
same place, for the same reason: it has no description of what the callee does.

A *summary* is that description. For every function, computed once from its
bl-ANF body:

| field         | what it records                                   |
|---------------+---------------------------------------------------|
| =:footprint=  | which resources it touches, and how               |
| =:terminates= | whether every loop in it is proven to halt        |
| =:returns=    | the set of value-shapes it can return             |
| =:calls=      | who it calls                                       |
| =:edges=      | who it calls, /resolved/ — names, not guesses      |

One pass builds a summary for every function and propagates them across the
call graph until they stop changing. After it settles, a function's footprint
includes its callees' footprints, its return shape flows from its callees'
returns, and its call edges are resolved — even the ones made through a function
passed in as an argument.

* The call graph is complete, including higher-order calls

A function handed to another function as a value — a callback — is still an
edge. The pass follows which functions flow to which call positions, so a
function reached /only/ through a parameter is correctly seen as reachable:

#+begin_src beam-lisp :id higher-order
(ns demo (:require [system.analyze :as analyze]))

(def summaries
  (analyze/analyze
    "(defn inc2 [n] (erlang/+ n 1))
     (defn apply-twice [f x] (f (f x)))
     (defn main [] (apply-twice inc2 5))"))

(println (pr-str (:edges (get summaries "apply-twice"))))
(println (pr-str (analyze/reachable summaries ["main"])))
#+end_src

#+RESULTS: higher-order
: #{"inc2"}
: #{"apply-twice" "inc2" "main"}
: :ok

=apply-twice= never names =inc2= — it calls =f=, its parameter. Yet the edge
=apply-twice → inc2= is found, because =inc2= is the only function that flows
into =f= at the one call site. And =inc2= shows up as reachable from =main=,
so a dead-code sweep correctly leaves it alone.

* Sound, and honest about what it cannot know

The graph is a careful over-approximation: it never misses an edge it could
have found, and never invents one it cannot justify. A function truly chosen at
run time — pulled from a table, decided by input — has no static answer, so its
call site resolves to nothing rather than to a guess. "I don't know" is a valid,
recorded answer; a fabricated edge is not.

* One truth, many readers

Because the summaries are one shared structure, the engines stop disagreeing.
The allocation analysis, the termination check, the type flow, and the
reachability/dead-code queries all read the same call graph and the same
per-function facts. A fact is computed once and reused everywhere — instead of
each engine walking the program again and re-deriving a poorer version of the
same answer.
