#+title: Canonical collections inside actor frames: the first cutover experiment
#+status: PROTOTYPE VERIFIED; full compiler cutover remains open

* What this establishes
The existing actor machine can invoke the compiled canonical runtime's =first=,
=rest= and =count= through the BL ABI. The fixture replaces those three prelude
definitions with wrappers around compiler-described exports. User code still
writes ordinary collection calls alongside =rt-spawn-owned=, =rt-send= and
=receive= in the same namespace. There is no message bridge for collection calls,
collection conversion, second scheduler or alternate value model.

The check includes string first/count and vector first/rest in a child actor,
then receives the results in its owner. String first distinguishes the canonical
implementation from the older actor prelude, which refuses strings. After boot,
the actual actor registry contains zero actors. Generated imports are checked
against the compiler-produced export names and fixed arities.

* Run the experiment
Use a compiled normal JS frontend containing canonical =rt= and =core= modules.
This research fixture uses local file URLs and is deliberately not a browser
release or a production build option.

#+begin_src sh
BL_CANONICAL_MODULES=/absolute/frontend/out \
BL_CANONICAL_PROTOTYPE=/tmp/bl-canonical-actor-prototype \
./bin/bl --cold run research/js-actors/canonical-runtime-prototype.bl
BL_CANONICAL_PROTOTYPE=/tmp/bl-canonical-actor-prototype \
node --test test/js/canonical-actor-prototype.test.mjs
#+end_src

* The initialization issue we found
Importing =ns/rt.mjs= as the graph root produces a cycle: rt imports core, core
imports seeded, and seeded calls rt/seed-core before its export initializes.
The ordinary frontend enters through core in the correct order. The prototype
emits one canonical-ready module that imports core first and reexports rt.
The actor bundle imports that module automatically. A production linker must
own initialization order and portable artifact URLs; application authors must
not have to preload core or know this cycle.

* What still prevents claiming a complete cutover
- Replace all remaining duplicate prelude semantics, including numeric and
  exception behavior, callable collections and dynamic application.
- Make ordinary namespaces compile into the canonical actor profile while
  preserving host callbacks, initialization, recursion and scheduling fairness.
- Infer higher-order callback suspension contracts. Non-suspension alone does
  not prove purity, bounded cost or termination; it cannot justify bypassing
  cooperative scheduling for arbitrary recursive or lazy operations.
- Generate canonical links from compiler authority without the research
  fixture's explicit selection/wrappers, and test native/browser/Worker graphs.
- Run the full language differential suite and Pelagic against the resulting
  pinned compiler, then delete the superseded production paths.

The experiment is evidence for the linking architecture, not a throughput or
physical audio/video latency measurement. The production runtime is unchanged.
