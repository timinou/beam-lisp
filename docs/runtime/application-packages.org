#+title: Verified application packages

* Behavior
Production startup can load a precompiled, closed library inventory before the
entry program runs. Development stays lazy or warms asynchronously after startup.
This is a general Beam Lisp facility; applications do not list functions or add
cache annotations. The initial supported deployment is a standalone VM.

* Build
A release program requires application.package and invokes:
#+begin_src clojure
(application.package/build! "path/to/main.bl" "/absolute/new-release" [])
#+end_src
The third argument contains optional startup roots beyond the entry's ordinary
requires. The builder discovers dependencies from actual source declarations,
snapshots their bytes, compiles admitted library units with the normal build
driver, and retains unsupported units as source. It never evaluates main.bl.
Compilation can execute library compile-time effects; build in a release process.
The destination must not exist. An OS-owned publication lease serializes builds;
a temporary sibling directory becomes visible by rename after verification.

* Runtime policy
#+begin_src clojure
:loading {:environment-env "APP_ENV"
          :development :lazy :production :startup
          :package-env "APP_PACKAGE"}
#+end_src
APP_ENV=production APP_PACKAGE=/absolute/new-release selects the package.
Without APP_PACKAGE, ordinary production discovery and eager loading still work.
Development ignores the package selection. :development :async warms only after
the entry returns, with owner/deadline admission before each shared initializer.

Before initialization, the loader checks the package format, compiler identity,
actual host module identities, ERTS/Elixir versions, native byte hashes, entry and
root identity, live source drift, and the exact shipped file inventory. Unexpected
files, changed bytes, symlinks and special files decline installation. A mismatch
fails startup rather than silently mixing releases. Deployment supplies trusted
release authenticity; hashes are not signatures.

* Replay authority
The runtime Loader and release packager share whole-unit syntactic admission.
Known defining forms have normal AOT initialization; unknown top-level effects or
defining macros stay on the source path. This also prevents a stale artifact from
hiding a source initializer. Definitions may have effectful initializers: those
expressions are replayed by the ordinary AOT definition initialization contract.

* Current boundary
Global artifact names are supported only in standalone VMs. Realm-bound builds
and installs fail explicitly. A future realm package format must bind emitted
module homes and resolver authority rather than copy global modules into a realm.
Package format 1 is SDK-specific and immutable; rebuild after changing its SDK,
application closure or entry. No runtime cache is accepted as release authority.
