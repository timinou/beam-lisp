#+TITLE: Lazy realization: one recipe, shared answers
#+STARTUP: showall

* A recipe becomes a value

A lazy sequence stores work to do later. Asking for an element forces that work.
A successful result is memoized: every reader of that node sees the same answer.

#+begin_src beam-lisp
(assert (= [1 1]
           (let [xs (map inc (range 3))]
             [(first xs) (first xs)])))
#+end_src

Sharing is local to one BEAM VM. Passing a lazy value to another process shares
its memo cell; sending it to another machine does not share native memory.

* One caller owns an attempt

The memo cell holds a versioned state:

| State | Meaning |
|-------+---------|
| pending | Recipe has not completed |
| running | One caller owns an attempt; other callers wait |
| completed | Readers reuse the saved answer |
| failed | Producer failure; a later force may retry |
| terminal | The recorded refusal cannot be retried as ordinary production |

A claim is atomic. The owner claims before executing producer effects, then
publishes and notifies waiters through the same force protocol. Owner loss is
reported rather than leaving waiters asleep forever.

Producer exceptions retain their kind, reason and original frames. A retryable
failed force may execute the producer again. Design producer effects for that
possibility; memoization is not a transaction rollback.

* Reduce without replaying a prefix

A reducer can stop early by returning a reduced value. The general reduction
path walks memoized chunks, preserving everything it has already realized.
A later reader continues from that prefix instead of executing it again.

Trusted full consumers, such as count and list collection, can claim a complete
recipe. They coordinate with ordinary force callers; they do not create a
second ownership mechanism. Remembering a complete answer can retain storage
proportional to the sequence length.

* Admit memory before publication

Creation and admitted value publication reserve growth against the cache's
accounted-byte budget. One atomic occupied counter covers saved values and
in-flight reservations, so concurrent publishers cannot both spend the same
space. Replacement releases the old credit; failed or lost publications
release their reservations.

If production has already happened but the result cannot be admitted, the
budget refusal becomes terminal. Repeating count or first does not rerun those
producer effects. Raising a limit does not turn that completed attempt back
into an unexecuted recipe.

Accounted bytes estimate retained terms. They are not process RSS or a bound on
every external resource reachable from a value. A live root intentionally keeps
its saved values alive; a memory budget is not permission to evict them.

* Ask a small question cheaply

=LazyMemo.peek= returns only the state tag and version. Checking whether a node
is pending therefore does not copy its complete saved answer.

A peek followed by a full read must validate the version. Another caller can
publish between those operations. Full-state read and memo-state APIs remain
available when the complete value is needed.

* A cursor is a position, not a mutable iterator

A finite-input walk shares one native root. Each position is an immutable
=root + index= token; reading the same position twice gives the same chunk.
Chunks are bounded by element count, and the input index is built once rather
than rescanning or copying each tail. A single large element can still be large
in bytes. The root keeps its input storage alive while any position needs it.

* Collect only unreachable cycles

Cells record their resource dependencies. Publication keeps cycle reachability
and graph insertion inside the existing atomic graph boundary. The collector
counts reference occurrences, including closure captures; uncertainty fails
open by retaining the candidate rather than freeing a reachable value.

Measure both work and lifetime: producer calls, native operations, reservations,
retained bytes, live cells and collector anomalies. Repeat-consumer tests should
also check the answer and absence of repeated producer effects.
