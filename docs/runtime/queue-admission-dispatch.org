#+TITLE: Native admission and dispatch increment — source only, unqualified

These APIs are authored on backdesk/native-budget-fairness from exact b50e9f1f.
They are not part of qualified 9d runtime. No behavior receipt is claimed here.

* Declaration
#+begin_src clojure
{:admission {:max-outstanding 300
             :scopes [{:keys [:work/property] :max 100}
                      {:keys [:work/property :work/provider :work/integration] :max 40}]}
 :dispatch {:mode :round-robin
            :group [:work/property :work/guest]
            :max-groups 128}}
#+end_src
Numbers are explicitly configured local resource allocations, not provider
quotas. Both policies default absent, preserving legacy normalized declarations.
Missing or oversized captured scope refuses new work; guest-supplied budget
identities must never replace the application's trusted captured binding.

* Native writer guarantees
try-enqueue! resolves retained enrollment and outstanding ticket before capacity.
Conflicting enrollment still throws. A new full admission returns :deferred and
writes no job/ticket/enrollment. Count is derived from this journal's native
queued/running/held facts, not a mutable shadow counter. Explicit retry counts
other outstanding work and excludes only the original retried job itself.
Held unknown effects remain obligations; cancelling them is still forbidden.

Datom reconcile {:defer reason} retains the pending projection intent and its
original owed identity. drain! reports :deferred separately from :failed and
:applied. Its consumer must rerun on actual native capacity release/repair; a
full queue is not a successful enrollment and must never return :target or :skip.

For configured native-owner dispatch, preparation remains outside the queue
writer. Actual claim rechecks current due/lease, partition/exclusion facts and
round-robin order inside the writer, then advances the persisted queue cursor in
that same transaction. Lost claims/future jobs spend no turn. Within a group,
oldest due and then stable job ID wins. Cursor survives store reopen.

* Activation and migration
Boot/activation validates outstanding scope fields before installing policy.
Lowering limits does not evict/rewrite accepted work. Existing groups may drain;
new groups wait if their bound is full. Changing admission scope keys or dispatch
group keys across live retained generations requires explicit identity migration;
changing numeric allocations with the same keys does not. Closed initial policy
enablement must validate the actual legacy rows. No hidden hotel:demo fallback.

* Explicit remaining implementation boundaries
Per-journal admission is not a global provider cap. Required shared authority
must cover configured send/media/admin groups without assuming their independent
store writers are one transaction. A reservation must precede enrollment; a crash
in between leaves an owned unresolved reservation, never an optimistic free slot.
Enrollment proof and effect outcomes stay in the original queue journals. Release
requires terminal/fenced enrollment plus actual owned-body lifetime evidence;
lease expiry alone cannot free a physical slot or prove an effect absent.

Current :concurrency still bounds logical claims, not expired-but-live bodies.
A separate physical lifetime bound and native death/completion wake are required
before advertising a hard physical concurrency guarantee. Do not add a past-lease
1ms timer spin, repeat an uncertain effect, or kill a body merely to free a budget.
