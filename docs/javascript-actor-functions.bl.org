#+title: One function machine for JavaScript namespaces
#+status: Implemented function frames; kernel/package cutover in progress

* Start with an ordinary function
#+begin_src beam-lisp
(ns example)
(defn sum [n]
  (loop [left n result 0]
    (if (zero? left) result (recur (dec left) (+ result left)))))
#+end_src
Build with =bl js build example=. JavaScript calls the exported function and
receives its result synchronously. No actor annotation is needed. The compiled
function also exposes the existing actor callable ABI: a scheduler runs exactly
that function's generator factory with its own runtime and bounded turn budget.
Calls from another compiled function use frames directly, without packing a
message, converting values, or starting another scheduler.

* What changed
The ordinary namespace emitter and in-page evaluator now emit functions with
=H.blFn= factories. Loops yield to the frame machine; tail calls replace their
frame; other calls push frames. Literal/collection construction, patterns,
interop expressions and compiled core links remain the ordinary compiler's.
The adapter in =priv/lib/js/actor/module.mjs= supplies a host-result boundary.
It contains no mailbox, runnable queue, collection algorithm or actor registry.

JavaScript's fixed-arity callback convention still permits surplus callback
arguments. The entry wrapper discards them; calls between BL functions retain
strict arity selection. Multi-arity and variadic calls retain the BL ABI.
A protected call remains a call frame until catch/finally has completed; tail
replacement is emitted only when the function's return destination permits it.

* Host results and actor turns
A synchronous host entry drives the same machine to completion, with a finite
50-million-step ceiling. Attempted suspension or exhaustion raises and runs a
bounded cleanup reserve. This runtime check is not a compiler proof of
non-suspension, purity, bounded time or termination. Explicit proven callback
entrypoints continue to require system.suspension evidence.

The module control context does not consume browser input. An actor invoking
its exported factory supplies the actual actor runtime, preserving its caller's
turn budget. A synchronous JS call does not create a schedulable process.

* Evidence
=test/bl/js_actor_module_test.bl= builds the fixture through public bl.js and
runs five actual Node contracts: canonical collection/callback behavior,
10,000 loop iterations split over turns, 10,000 non-tail recursive calls without
JS stack overflow, 100,000 tail calls with fewer than ten retained frames, and
catch behavior across a frame call.

The common-emitter kernel experiment additionally compiles the existing BL
kernel and an owned parent/child selective receive through js.emit. Run:
#+begin_src sh
./bin/bl run research/js-actors/common-emitter-prototype.bl
node /tmp/bl-common-kernel/out/common.mjs
#+end_src
It currently links the module fixture's canonical values at its explicit /tmp
location. This is a research experiment, not a relocatable package interface.
The legacy actor emitter/prelude and package linking still need replacement;
these passing checks alone do not complete that cutover.
