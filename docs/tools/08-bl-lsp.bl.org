#+TITLE: 8 · bl lsp — the compiler as an IDE, in the terminal
#+STARTUP: showall

* Point the drop at a file, read what the compiler proved

Editors talk to a "language server" to get hover text, diagnostics, an outline of
a file. beam-lisp's language server (=lsp.bl=) computes those answers as a pure
projection of the compiler's analysis — the same summaries the prover and the
native-offload gate read. =bl lsp check FILE= renders that analysis for a
terminal: the diagnostics an editor would underline, then every definition with
the facts the compiler *proved* about it.

#+begin_example
$ bl lsp check sample.bl
── sample ──
  diagnostics: none
  symbols (3):
    add
        → float|int  pure  terminates  ◆ native
    noisy
        → nil|bool|float|…  effects  terminates  ·
    step
        → float|int  pure  terminates  ◆ native
        calls: add
#+end_example

Each definition shows its inferred return type, whether it is =pure= or has
=effects=, whether it =terminates=, and a =◆ native= badge when it is eligible to
be compiled to a native NIF. =step= carries =calls: add= — the resolved call
edges.

* The badges are proofs, not guesses

The report is a thin renderer over =lsp.bl='s analysis functions. Nothing here is
heuristic — every badge is read straight off a summary the compiler computed.

#+begin_src beam-lisp :id badges
(ns demo (:require [lsp]))
(def prog (str "(defn add [x y] (erlang/+ x y))\n"
               "(defn step [p] (erlang/* (add p 1) 2))\n"
               "(defn noisy [x] (do (IO/puts \"hi\") x))"))
(println (pr-str
  {:add-native   (:eligible (lsp/native-eligible prog "add"))
   :step-native  (:eligible (lsp/native-eligible prog "step"))
   :noisy-native (lsp/native-eligible prog "noisy")}))
#+end_src

#+RESULTS: badges
: {:add-native true, :step-native true, :noisy-native {:reason :impure, :footprint {:opaque-world :W}, :eligible false}}
: :ok

=step= is native-eligible even though the badge is a per-function fact — because
its only callee =add= is pure, that purity flows through and the whole call tree
is offloadable. =noisy= is refused, and the refusal names the theorem that failed
(=:impure=) and the exact effect that broke it (=:io {:stdout}=). A green light
you can trust and a red light that explains itself.

* The outline shows what each definition provably does

=document-symbols= is the same data an editor's outline view uses — but enriched
with the proof summary, so the outline shows not just *what* is defined but what
each definition *does*.

#+begin_src beam-lisp :id symbols
(ns demo (:require [lsp]))
(def prog (str "(defn add [x y] (erlang/+ x y))\n"
               "(defn step [p] (erlang/* (add p 1) 2))\n"
               "(defn noisy [x] (do (IO/puts \"hi\") x))"))
(def syms (into {} (map (fn [s] [(get s :name) (dissoc s :returns)])
                        (into [] (lsp/document-symbols prog)))))
(println (pr-str {:add (get syms "add") :step (get syms "step") :noisy (get syms "noisy")}))
#+end_src

#+RESULTS: symbols
: {:add {:calls [], :name "add", :terminates true, :pure true}, :step {:calls ["add"], :name "step", :terminates true, :pure true}, :noisy {:calls [], :name "noisy", :terminates true, :pure false}}
: :ok

* Where it fits

=bl lsp check= is the one-shot, editor-free form: run it in a script, a CI gate,
or just to read a file. The exit code is =0= when the file is clean and =1= when
it has diagnostics, so it drops straight into a pre-commit hook. The full
editor-facing surface (hover, go-to-definition, completion, the proof-hover) is
all in =lsp.bl=; wiring it to an editor over JSON-RPC is a thin transport on top
of these same functions.
