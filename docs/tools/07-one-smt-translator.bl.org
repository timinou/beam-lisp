#+TITLE: 7 · One SMT translator, over the IR
#+STARTUP: showall

* Two translators became one

To ask the z3 prover a question about beam-lisp code — "can this balance go
negative?", "does this function's output stay in range?" — the code has to be
turned into an SMT formula. Until now there were *two* things doing that: an old
one that read the surface syntax (the reader tree, the shape you typed), and a
newer one that read bl-ANF (the compiler's resolved intermediate form). Two ways
to do one job is exactly the redundancy worth removing.

The surface reader is now gone. =system.smt= reads bl-ANF and nothing else, and
the separate =anf-smt= module is folded into it. One translator.

* Why the IR is the better thing to read

Reading the compiler's resolved form is not just tidier — it can answer
questions the surface reader physically could not.

** Operator resolution is free

The compiler already mapped every way of writing an operator — =>=​=, the
qualified =erlang/>=​=, a macro that expands to either — down to *one* resolved
form. The surface translator matched operators by their written NAME, so a macro
or a qualified call it did not recognise was missed. The IR translator sees the
one resolved node, so all those spellings collapse to the same thing for free.

** It can see through a function call

This is the real win. A guard like =(safe? balance)=, where =safe?= is a small
pure helper, was *opaque* to the surface translator — it could not look inside
the call, so it gave up (=:untranslatable=) and the check was silently skipped.
The IR translator inlines a proven-pure helper's body into the formula:

#+begin_src beam-lisp :id inline
(ns demo (:require [system.smt :as smt]))
(def program "(defn margin [b r] (erlang/- b r))\n(defn safe? [b] (erlang/>= b 0))")
(println (pr-str
  {:surface-gives-up (smt/of-source #{"balance"} "(safe? balance)")
   :ir-sees-through  (smt/of-source-inlining program ["balance"] "(safe? balance)")
   :nested-helper    (smt/of-source-inlining program ["balance" "reserved"]
                                             "(erlang/>= (margin balance reserved) 0)")}))
#+end_src

#+RESULTS: inline
: {:surface-gives-up :untranslatable, :ir-sees-through (>= balance 0), :nested-helper (>= (- balance reserved) 0)}
: :ok

The surface path gives up; the IR path models =safe?= by its actual computation,
=(>= balance 0)=, and =margin= by =(- balance reserved)=. A whole class of
invariants that call helpers becomes provable instead of silently skipped.

* The same answers, proven before the old code was deleted

Deleting a working path is only safe if the replacement gives the same answers.
Every kind of formula the old translator produced — arithmetic, the boolean
connectives =and=​/​=or=​/​=>=, enum datatypes, collection-length reasoning,
and multi-clause function lowering — was checked against the new one by asking
z3 whether the two could ever differ. For all 22 cases the answer was *no*
(=(not (= old new))= is unsatisfiable), so they denote the identical term. Here
are three representative shapes still agreeing today:

#+begin_src beam-lisp :id agree
(ns demo (:require [system.smt :as smt] [smt :as sl]))
(println (pr-str
  {:arithmetic (sl/emit (smt/of-source #{"a" "b"} "(>= (* a b) (+ (mod a 7) (* 2 b)))"))
   :define-fun (sl/emit (smt/defn->define-fun
                          "(defn sign ([n] :when (pos? n) 1) ([n] :when (neg? n) -1) ([n] 0))" "Int"))
   :collection-length (sl/emit (smt/of-source-len #{"c"} #{"c"} "(> (count (conj c 1)) (count c))"))}))
#+end_src

#+RESULTS: agree
: {:arithmetic "(>= (* a b) (+ (mod a 7) (* 2 b)))", :define-fun "(define-fun sign ((n Int)) Int (ite (> n 0) 1 (ite (< n 0) (- 1) 0)))", :collection-length "untranslatable"}
: :ok

The full differential proof lives in =research/smt-unified/parity.bl=; run it
and z3 re-certifies all 22 on the spot.

* One place where the form changed (and why it is fine)

Reading the IR means some surface spellings no longer survive — the compiler
rewrote them before the translator ever sees them. =(=> X Y)= (logical
implication) is the clearest case: the compiler desugars it to =(or (not X) Y)=,
so that is what the translator emits.

#+begin_src beam-lisp :id implies
(ns demo (:require [system.smt :as smt] [smt :as sl]))
(println (sl/emit (smt/of-source #{"a"} "(=> (> a 0) (> a -1))")))
#+end_src

#+RESULTS: implies
: (or (not (> a 0)) (> a (- 1)))
: :ok

=(or (not X) Y)= *is* =(=> X Y)= — same truth table, and z3 confirmed the two
are equal in the parity corpus. The proof is identical; only the surface spelling
of the formula differs. That is the one visible cost of reading the resolved form
instead of the syntax, and it buys the see-through-a-call capability above.
