#+TITLE: 5 · Native offload, inter-procedural
#+STARTUP: showall

* Which functions may become native code?

The BEAM runs native code as a NIF, outside the safety net: no per-process heap,
no preemption, no garbage collector. So the question "which functions may become
NIFs?" is the question "which functions can we *prove* will not freeze a
scheduler, crash the node, or starve their neighbours?" =docs/memory-policy/05=
answers it with four theorems: a function is offloadable when it is *pure*
(footprint = ∅), *terminating*, its values are *NIF-safe sorts* (machine ints,
reals, bools, binaries), and its *work is bounded*.

The first three are shipped engines. What changed is that they now run over the
whole program, so the verdict is *inter-procedural*.

* A call tree, not just a leaf

Before whole-program analysis, a function that called a helper could not be
judged: the helper was an opaque callee, so its caller's footprint collapsed to
"touches everything" and the caller was refused as impure — even when the helper
was provably pure. =system.analyze='s footprint closure removes that wall: a
caller of a pure helper is itself pure, so whole call *trees* become offloadable.

#+begin_src beam-lisp :id verdicts
(ns demo (:require [native.eligible :as el]))
(def src (str "(defn dist2 [dx dy] (erlang/+ (erlang/* dx dx) (erlang/* dy dy)))\n"
              "(defn step [x y] (dist2 (erlang/- x 1) (erlang/- y 1)))\n"
              "(defn noisy [x] (do (io/format \"~p~n\" [x]) (erlang/+ x 1)))\n"
              "(defn mk-kw [] :kw)"))
(println (pr-str
  {:dist2 (:note (el/eligible src "dist2"))
   :step  (:note (el/eligible src "step"))
   :noisy (:reason (el/eligible src "noisy"))
   :mk-kw (:reason (el/eligible src "mk-kw"))}))
#+end_src

#+RESULTS: verdicts
: {:step "calls only-pure helpers — whole tree offloadable", :dist2 "leaf kernel — direct native", :noisy :impure, :mk-kw :sort}
: :ok

=step= is the key result: it is offloadable *only because* =dist2='s purity
flows through the summary. =noisy= is refused for the IO it does; =mk-kw= is
refused because a keyword is not a machine sort. Every refusal names the theorem
that failed — never a silent fallback.

* The shape the workloads take

This is the pressure-tested case from page 7. An MMORPG server's hot paths —
spatial-hash steps, distance checks, pathfinding — are scalar loops that call
small pure helpers, exactly the =step → dist2= tree; Cranelift already matches
hand-written Rust there. A model-routing swarm's hot path is =softmax → exp=
over wide vectors, the same tree shape; whether it gets native speed is the
open SIMD question, orthogonal to eligibility.

* The relationship to everything else

The proof that gates offload — footprint = ∅ — is the same proof that lets the
model checker inline a helper (page 4). One fact, computed once over the call
graph, opens two doors: a pure helper's callers can go native, and a pure
helper's callers can be proven. That is the dividend of putting position,
proofs, and the call graph on one IR.
