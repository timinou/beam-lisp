# live — the browser proof

The headless `.bl` tests (`test/bl/live/`) prove the whole server-side loop:
render, diff, socket, auth, session, two-tab convergence. This directory closes
the one thing they cannot — **does a real browser apply these patches?** — by
driving a real Chromium with Playwright against the JS client.

## What it proves

1. **`client.spec.js` › real ops** — loads `priv/lib/live/client.js` into Chromium,
   mounts the fixture's first HTML, then applies the **exact patch ops the
   beam-lisp differ produced** (from `fixture.json`, generated by
   `gen_fixture.bl` — the same `priv/lib/live/diff.bl` the server uses). After each
   step the DOM's HTML is asserted equal to the server's rendered HTML. So the
   JS client is proven against the *real wire*, not hand-written ops:
   insert · move · text · remove all round-trip.

2. **`client.spec.js` › keyed reorder preserves nodes** — tags a DOM node, applies
   a `move` op, and asserts the *same node* survived the reorder (its marker
   rides through). This is the property a string diff structurally cannot
   achieve: a reorder moves DOM nodes instead of rewriting them.

3. **`connect.spec.js` › the socket lifecycle defaults** — the differ's client is
   only half of `client.js`: `connect()` also owns liveness. With a fake
   WebSocket (no server) it pins the defaults every shell relies on — a
   `["ping"]` heartbeat within `heartbeatMs` (30 s by DEFAULT, which is what
   beats the server's 120 s idle timeout in `web/upgrade`) and auto-reconnect
   after a close with no opts — plus the two opt-outs (`{heartbeatMs:0}`,
   `{reconnect:false}`), and the SESSION id (`live-sid`) that makes a reconnect
   RESUME the server-side session instead of re-mounting it: it rides on every
   socket URL and is identical across a reconnect, while a fresh `connect()`
   mints a new one. Against the pre-heartbeat client, the three default claims
   fail and only the two opt-outs pass — which is the point.

## Run it

```sh
# 1. regenerate the fixture from the real differ
bl run test/browser/gen_fixture.bl > test/browser/fixture.json

# 2. install the Playwright test runner matching the cached browser
cd test/browser
npm install --no-save @playwright/test@1.62.0

# 3. run against a real Chromium
PLAYWRIGHT_BROWSERS_PATH=~/.cache/ms-playwright npx playwright test
```

Expected: `10 passed` (3 differ + 7 lifecycle).

## Why not Phoenix here

`beam-lisp` is the language repo; the Phoenix/LiveView transport lives
downstream (the spell `:interface` app). This proof needs neither — it exercises
the client and the wire directly, which is exactly the seam a downstream host
would wire to a channel. The server half (mount → patch push → event) is proven
in `test/bl/live/socket_test.bl`; this proves the client half in a real browser.
The two meet at the JSON op protocol, which `interop/->json` serializes and this
test replays.
