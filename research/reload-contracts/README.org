#+TITLE: Contract-derived code, message and data evolution
#+DATE: 2026-10-12
#+STATE: INVESTIGATION AND EXECUTABLE CHARACTERIZATION — production design proposed

* Goal
One Beam Lisp evolution mechanism, consumed by ordinary reload, Foundry releases
and Omega. Application authors write ordinary handlers, schemas and existing
contracts. Compiler/runtime ownership, checks, version plumbing, inventories,
leases and journals are upstream work. A domain author supplies a conversion
only when the intended meaning cannot be derived safely from existing contracts.
No Knowledger-specific migration coordinator or duplicate hand-maintained shapes.

* Current implementation boundaries
| Mechanism | Actual responsibility | Limit |
| reload/coherence and commit | source bundle names, removals, type warnings and require cycles | per-definition publication; no complete inferred message/state/data contract |
| reload/activate! | fresh namespaces plus one FIFO proc.evolve owner transition | explicit resolve/spec; not an atomic multi-owner publication |
| reload.generation | sealed immutable dependency graph and whole-graph lifetime | code identity/lifetime alone does not establish message/reply compatibility |
| reload.migrate | declared SMT model/invariant checks and transformation previews | does not migrate mailboxes or bind supplied runtime fn to supplied SMT model |
| proc.evolve | state migration/check, request upcast, input validation, leases and retirement | requires supplied predicates; owner-state rehearsal is not future message coverage; no automatic old reply adaptation |
| proc.transition | bounded queue/owner rehearsal, revision recheck, activation/adoption/drain | observed inventory only; does not prove all future input |
| datom.migrate | speculative remediation/checks, writer-bound commits, identity and batch ledger | schema tightening checks currently must be supplied explicitly |
| typed/system | type/effect/transition/publication evidence | shallow tags or unknown summaries are not closed structural contracts |

* Executable investigation
[[file:contract_boundary_test.bl][contract_boundary_test.bl]] is a research probe, not a production implementation.
It derives a boolean matcher from the existing system.model patterns/guards and
uses the native server compiler to enforce the fixture's stateless guard. It
does not introduce a second pattern interpreter or execute the business body.
The source-string synthesis is deliberately temporary: production extraction
must use post-expansion canonical compiler descriptors/ANF, preserve spans and
provenance, include contributed clauses and reuse backend matching semantics.

It demonstrates these boundaries:
1. A known finite pattern/guard can reject wrong tag, vector length, value type,
   nil and range without a handwritten application accept predicate.
2. Tag coverage alone cannot certify payload shape.
3. Native compilation enforces a guard before callback parameters but treats a
   post-parameter guard as body expressions. system.model recognizes BOTH as
   guards. The prototype initially failed four desired rejection assertions,
   exposing this disagreement rather than validating automatic safety.
4. js.actor/lower-arm rejects the pre-parameter guard as a malformed parameter
   vector; the post-parameter guard remains in the ordinary body. This is a
   parser/lowering agreement issue, not a limitation to waive for migration.
5. A weak manual accept predicate allows an invalid field to enter a handler,
   perform an effect, then fail. Catching an exception preserves actor state but
   cannot undo effects already performed by its body.
6. A candidate with a bad message upcast passes current owner-state rehearsal
   and activation; subsequent input validation refuses its converted request.
7. Converting an old request does not guarantee the old caller's reply shape:
   current proc.evolve returns the candidate reply directly to that caller.
8. A declared identity SMT expression can verify while an unrelated runtime
   migration function returns the wrong shape. Current proof-scope labels are
   honest; they cannot become publication authority for arbitrary runtime code.
9. Historical duplicate data previews as clean when adding a unique schema
   constraint without an explicit check. The repeated unique check detects it.
   This probe does not apply the unsafe schema change.

These gaps are reproduced/characterized, not fixed by making this test green.
The implementation must replace their characterization with desired behavioral
regressions before advertising inferred evolution safety.

* Proposed system
** 1. One compiler-owned boundary descriptor
Consolidate callback parsing and guard placement across the native compiler,
proc.server clause-plan, system.model and JS lowering. Analyze the actual
expanded/compiled declarations, not an independently interpreted source subset.
Include call/cast/info/control messages, actual patterns, structural required
fields, literal tags, exact/open collection semantics, pure guard conditions,
request/reply shapes, state requirements and referenced Datom schema/contracts.
Record code/ABI identity, source spans, target backend and inference modality.
Do not infer required fields merely because a body reads them: optional reads
and open maps must retain their actual semantics.

Use existing typed/system/codebase facts and checked ANF summaries. Resolve
cross-namespace call and producer-consumer edges by binding identity. Dynamic
targets or opaque predicates stay unknown; they do not acquire permission from
a similarly named namespace or a trace containing only successful examples.
Version/fingerprint the complete contract and its compiler/guard semantics.

** 2. Ordinary definitions acquire managed behavior upstream
Compiler/server/queue/client adapters derive and register contracts, stable owner
identity, producer generation and callback graph ownership. The lifecycle derives
participants from actual owned runtime registrations and the sealed graph;
source declarations alone cannot prove that every physical producer is owned.
Foundry consumes this inventory instead of requiring a product-maintained map
of migration participants. Stable state cells/resources retain their owners.

Generate lightweight ingress/dispatch checks from the same pattern machinery;
reject wrong shapes before invoking a handler or submitting an external effect.
Keep authentication/authorization distinct. Raw OTP send can physically reach a
PID, so the receiver is the enforcement boundary, not just the generated client.
Unsupported control envelopes also refuse safely. Casts have no synchronous
reply; refusal is observable rather than a fabricated sender acknowledgment.

Separate message shape from state-dependent readiness: a valid request whose
guard is temporarily false is not necessarily malformed. Selective receive may
intentionally retain a valid message for a later state. Managed protocol inference
must cover the complete known machine, not drop everything unmatched by the
current receive. Unknown raw receive machines need an explicit protocol/drain.

** 3. Derive a compatibility plan, not a guessed transformation
Compare old/new contracts over all reachable producers/consumers, including old
captured callers and replies. Automatically reuse identity adapters when proven
safe. A widened input contract is insufficient if reply or state requirements
break old clients. Stage compatible old/new protocol paths before publication.
For supported finite/SMT fragments, synthesize only transformations discharged
against the actual compiled transformation IR and both boundary contracts.
Compile proof and execution from the same representation; never accept an
unrelated handwritten SMT description as evidence for a runtime fn.

Renames, units, ownership transfers and duplicate-resolution policy cannot be
guessed from field names. One nearby pure domain conversion or existing explicit
mapping supplies the missing meaning. Unknown/unbounded transformations require
an acknowledged drain, preserved old handler or clear refusal. Unknown is not
the same as an invalid application; it limits the claimed automatic upgrade.

** 4. Derive schema checks and commit authorizers
Infer existing-data checks from declared schema tightening: uniqueness,
cardinality, value types and supported reference constraints. Reuse Datom's own
schema/value semantics. Existing domain invariants add checks without duplicate
deployment declarations. Do not invent tenant policy from attribute names.
Preview remediation and actual constraints, then revalidate under the live writer
before the atomic migration/ledger commit. Preserve bounded backfill and cursors.
Default conflict behavior is refusal; never silently deduplicate/delete data.
Expand/dual-read/backfill/contract is generated only where contracts establish
its validity. Cross-store consistency requires a separate declared cut.

** 5. One reload evolution plan and execution path
Unify the public reload flow around prepare/analyze/rehearse/activate/drain, with
development and production authority policies. Reuse reload.generation,
proc.evolve, proc.transition, datom.migrate and Foundry's durable orchestration;
do not build competing mailboxes, queues, schema engines or operation journals.
Legacy mutable development publication remains explicitly narrower until migrated.

Rehearse persisted jobs, actual current owner state and supported live-message
inventory. Bind receipts to code, contracts, basis/inventory marks and physical
owner revisions. Recheck before durable publication intent. Keep admission
validation/fences active for future messages; a snapshot cannot certify them.
Install compatible protocols through owner FIFO barriers and publish the router
with durable recovery. Partial multi-owner activation must remain compatible
with old traffic and restartable; it is not one global atomic actor transaction.
Drain leases/old clients/jobs before adapter/code/schema retirement.

External provider intent/receipt/idempotency remains proc.queue's responsibility.
No contract inference makes an external API transaction atomic with Datom.

** 6. Foundry as the operator view and deployment authority
Consume the generated plan/inventory. Show affected boundary, check evidence,
compatibility, publication, draining dependencies and recovery separately.
Unknowns name the exact unsupported construct; invalid examples show content-free
shape diagnostics. Preserve seven stages and only fresh, authorized actions.
Knowledger contributes its ordinary domain code/schema and meaningful conversions;
.foundry.bl declares deployment policy, not a parallel upgrade implementation.

and base before commit at a chosen musical boundary. Its existing compiled Node
test passes both scenarios in this review. This is an excellent reusable
prepare/recheck/commit pattern, not general state/message HMR.

Share compiler-owned boundary descriptors, inferred evidence, generation fences,
ownership and candidate admission between native and JS. Execution stays backend
specific: native FIFO actor transitions versus JS turn/Worker/resource boundaries.
Do not rewrite opaque suspended JS generator frames or live audio resources.
Preserve old execution or adopt at an acknowledged safe point; unsupported
changes may still need explicit session reload. Editor use/unuse resource
ownership is useful for exact UI/subscription cleanup, not database authority.

Omega's older spikes/live-image.bl.md describes reload/attach as live message
migration; current upstream deliberately refuses attached previews at commit.
Update that historical walkthrough during adoption rather than relying on it
as current runtime behavior. No Omega source or live world was modified here.

* Implementation and validation order
1. Repair parser/guard/model/backend agreement and make adversarial parity tests
   green against actual native and emitted JS execution.
2. Compiler-owned descriptors and generated ingress/reply/state contracts; verify
   wrong tag/arity/missing fields/types/nested collections/captures and no effects
   before rejection. Keep state readiness and selective receive semantics intact.
3. Closed cross-namespace compatibility, same-IR adapter proof and automatic schema
   checks; counterexamples for reply changes, shadowing, opaque predicates,
   conflicting aliases and invalid migration outputs. Test solver unknown/timeouts.
4. Automatic runtime inventory and unified reload execution, using existing
   owners/queues/journals. Inject future arrivals, stale proofs, partial activation,
   cancellation, process death/restart and duplicate/late acknowledgments.
5. Accept actual packaged Knowledger and an isolated Omega consumer before claiming
   a general solution. Continue the backup/configuration/host-handover plan using
   the same descriptors; no production or live Omega world test writes.

Zero repeated app plumbing is the target; zero CPU cost is not promised. Derive
at compile/package time, cache by exact identity, and fuse validation with existing
dispatch where safe. Benchmark valid/rejected messages, queue admission, migration
preflight, startup, retained memory and both native/JS boundaries. Report measured
cost and conservative refusal separately from speedups.
