#+TITLE: Isolated authenticated SDK constructor controls

* Boundary and setup
These .bl.txt files are inert input data, not deployed SDK declarations. Do not
copy them into the shared main tree. In a separately captured archive used by one
parent-serialized native VM, copy each to its exact namespace-selected SDK path:
priv/std/research/constructor/NAME.bl (with declaration-kind named accordingly).
A complete current compiler-owned SDK unit receipt is still required; a caller
stage-sdk? option and this fixture location are not independent ownership proof.

Keep the files through VM shutdown. Removing a physical source while its SDK
proof/retention remains live invalidates that proof. No production instance is
involved. probe.bl prints bounded result/refusal/context/provider observations;
it does not treat arbitrary exceptions as passing tests. Set its output under
HOME/tmp using BL_CONSTRUCTOR_SHADOW_OUTPUT. The parent harness must run the
real recursive stage_sdk_dependency! producer for requires before direct staged
compilation, rather than manually prewarming or initializing the provider.

* Required observations
- local-native and local-protocol: opaque local identity must refuse rather than
  interpreting the same-named Core source helper.
- referred-protocol and refer-all-protocol: an explicit or public refer-all
  opaque identity keeps its provider ownership; no Core source/primitive fallback.
- explicit-loader: an explicit Source Loader/ensure_loaded call refuses before
  effects; compiler-generated private metadata readiness guards remain distinct.
- core-positive: legitimate Source Core identity compiles without provider init.
- declaration-kind: self-quoted syntax compiles without cyclic initializer
  compilation; inspected's explicit throwing expander is never invoked merely
  to qualify a quoted name. Actual macro expansion still keeps privacy/order gates.
- provider: declaration metadata/emission can be prepared; loaded_ns and runtime
  registry remain unchanged until separately authorized ordinary initialization.
