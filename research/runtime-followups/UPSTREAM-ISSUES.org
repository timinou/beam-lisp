#+title: Upstream issues exposed by the follow-up prototypes

* Loader resolution context is omitted from worker conveyance
Evidence: application packaging initial unchanged build rebuilt 3/18; one
facade closure stamp disagreed with the planner's caller-context stamp.
Env.capture/bind omit :bl_search_dirs, :bl_fixed_dirs and :bl_load_paths even
though build/pmap-ordered documents conveying search roots. Project :paths
works around it and gives unchanged build=0.
Fix: registered loader snapshot in Env.capture/bind, immutable root order and
identity; restore all prior scopes in finally; legacy tokens clear stale scopes.
Do not copy arbitrary process dictionary or confer extra capability rights.
Regression: caller-only sibling resolution in spawned workers, distinct roots
for same namespace, nested conveyance/failure restoration, no-op build, correct
emitted stamp. Package release must pass this before relying on transient roots.

* Realm composite cache key collides with source-provenance contract
Evidence: evidence/realm-probe.log traces real local AOT.compile_source calls:
three consecutive fresh environments using identical expanded source and realm
all compile once. This is a reproducible loss of reuse, not merely noisy time.
AOT.ensure_loaded_local computes a composite key from module/realm/context/source
closure, then passes it to compile_and_publish -> AOTCache.store.
AOT.emit_module stamps bl_source_hash with ns_closure_hash, NOT the composite key.
AOTCache.valid_keyed_entry compares a facade's bl_source_hash with the entry key;
store therefore declines publishing these realm entries. Generic module tests
can miss this because non-namespace cache clients use digest-only validation.

Design: separate cache selection identity from expected source provenance.
Provide an explicit authority descriptor with compiler key, entry key and exact
facade->source-closure map; preserve current strict validation for ordinary
source-keyed entries. Realm client supplies its composite entry key and the real
source closure. Manifest records/validates both identities. Do NOT make source
provenance optional, rewrite source stamps to realm hashes, or silently relax
all facade validation. Include macro provider/code-generation identity in the
selection key when expanded-source admission is implemented.

Validation: real namespace facades in real realms; compile count 1 then 0,
then target-env initialization on every fresh environment. Different realm or
compiler context must separate entries. Wrong source/compiler stamp, swapped
facade, corrupt bytes and cross-realm selection must miss. Preserve strict live
source drift checks. Benchmark cold miss separately from true warm hit, then
repeat the macro-expansion admission experiment. Existing prototype shows no
realm speedup and should not justify broadening the gate yet.

* Native rank admission needs a writer budget as well as demand
1000-row staged build takes 36.574 s, with a worst observed turn 1.715 s. Read
savings amortize only after ~1586 reads before future writes. Existing finite
build steps are not a latency bound. Time-budget each writer turn and pause
between turns; measure p95/p99 normal transaction delay under concurrent reads.
Do not admit the slower 100-row index. Use observed maintenance economics and
bounded admission queues. No fixed collection-size threshold alone suffices.
