#+title: Runtime follow-up experiments: evidence and implementation decisions
#+status: Research; not shipped production behavior

* What was measured
Pinned SDK 24db70e9; Beam research base f90a9aa2; application base 5cbe58ad.
Prototypes use real compiler/loader, Env, datom ETS/Fjall, processes, BEAM code
retirement and Linux locks. Small fixtures isolate mechanisms, not whole-app
startup or browser navigation. Whole-VM reductions include background VM work.
A shared host produces large timing variation. Four samples per variant (ABBA)
unless explicitly stated; medians are observations, not confidence intervals.
All scratch is under /home/user/tmp. Raw failed experiments are retained.

* 1. Application AOT packaging — first production priority
Producer compiles 16 real Knowledger date/i18n libraries plus two generated
namespaces (256 leaf functions), using existing build/run. Emits 39 BEAM files;
build took 25.785 s, 1.350 billion reductions. Package directory about 787 KB,
including its manifest and auxiliary files. Unchanged second build compiles zero.
Consumer relocates the package and loads it with no fixture source path, strict
AOT, zero observed eval_string/3 or AOT.compile_source/2 calls. Initializers run
in the target process environment, once despite repeated require. Locale and
function results match source execution. Byte tampering is rejected before launch. Additional controls (separate from
benchmark trials) pass: runtime compiler mismatch refuses before initialization;
live-source drift raises the expected strict stale-AOT error before initializer.

Observed target-loading medians:
| Control | Control ms | Package ms | Samples/variant | Ratio |
| Forced source compilation | 610.992 | 71.978 | 4 | 8.49x |
| Normal repair, empty artifact cache | 1867.477 | 56.267 | 2 | 33.19x |
| Normal repair, warm artifact cache | 197.969 | 173.691 | 4 | 1.14x |
Warm-cache reductions fall from 511260 to 171551, about 66%; warm wall time is
noisy and does not establish a large improvement. Cold reductions fall from
100941959.5 to 171549.5. Globally disabling repair/clearing caches also changes
premeasurement boot, so process-wall ratios are not attributed to packaging.
Call tracing observes entrypoints, not every recursive compiler operation.
These are NOT full Knowledger server or Chromium measurements.

Production seam: build the application dependency closure during release; ship
an immutable inventory of BEAM hashes plus compiler/native ABI identity; verify
before readiness; run normal target-environment initialization before serving.
Keep dev source loading/reload. Make this a general build/launcher policy; app
configuration selects prod startup preload. No handwritten per-function hints.
Do not bake user data, secrets, production env values or sockets into artifacts.
Manifest digest checks detect corruption, not malicious replacement of both
manifest and binaries; deployment supplies the trusted release authority.

Upstream issue discovered: build workers lose caller-only Loader source scopes.
First attempt with with_search_dir rebuilt three units on an unchanged build;
one facade carried a mismatching closure key. Project :paths fixes this fixture.
Env.capture/convey carries project/env metadata but omits loader process keys.
Integration should convey a registered immutable resolution snapshot, restored
in finally, rather than copy arbitrary process dictionary entries. Test sibling
requires, nested worker roots, failure restoration, distinct project roots and
unchanged build=0. Retain this regression before adopting app-wide packaging.

* 2. Generated-definition tracking
Actual Env.put_ns_definition call tracing observes ordinary and macro-generated
definitions; lexical-only tracking misses generated. Benchmark projects the two
selected names from real Env tables with 128 or 2048 inherited definitions.
At 2048 entries, 100 projections fall from 5025.055 ms to 10.246 ms (490x);
reductions 10931516 to 133309 (98.8% fewer). At 128, 566.320 to 11.770 ms.
Synthetic inherited AST payloads deliberately stress full-table enumeration.
Trace capture plus fixture compilation costs 239.298 ms; this is not incremental
production tracker overhead, and must not be omitted when assessing cold use.

Production seam: record names at definition publication, including macros,
bulk publication and replacements. Scope collector to namespace/environment and
compilation generation; publish metadata atomically with definitions. Abort drops
the collector. This makes cost proportional to definitions produced, without
requiring app developer annotations. Do not ship tracing as the collector.

* 3. Broader realm admission
Manually expanded macro fixture is admitted by existing finite syntax gate;
original custom macro source is declined. system.footprint analyzes LATENT bodies
through system.ir/scaffold-inner: pure arithmetic passes, File.write is refused.
codebase indexes 67 functions using typed core signatures. This analysis itself
cost 813.117 ms and 6.728 million reductions in the experiment.

The measured expanded candidate is slower: 5260.062 ms versus 5008.445 ms;
37.293 versus 23.753 million reductions. No realm speedup is established. A
separate consecutive-candidate compile trace probes actual cache reuse.

This is an exploration of expanded IR admission, not arbitrary macro safety.
Every fresh realm must still replay target-env initializers. Broader admission
requires compiler-emitted expansion authority and complete macro-provider closure,
plus compiler/global-generation/realm identity. Effectful or opaque expansion
must decline before evaluating source effects. The fixture is deliberately
manually expanded; no automatic macro admission was added to the runtime.

* 4. Executed dependency/result authority
Real datom ETS projection reuses existing structural dependency certificates.
After unrelated audit writes, 20 projections at 1000 entities read 40000 rows
when recomputed versus zero with reuse. Medians 3743.982 versus 179.805 ms
(20.82x); reductions 38582608 to 1198325. Timed result equality checks still walk
returned rows, so these results include an O(N) oracle and are conservative for
constant-time reuse. Relevant score writes and negative-read insertion invalidate.

Production seam: interpreter/query executor emits read descriptors for a CLOSED
supported plan; certify store identity, transaction prefix, relevant attributes,
negative reads, executed providers, code generation and exact authorization.
Check current identity/policy on every access, even a cache hit. Unsupported
queries decline. Existing structural adapter is not a cache for arbitrary code.
Knowledger benefit: repeated list/card projections after unrelated transactions;
no extra filtering declarations, and user isolation remains enforced centrally.

* 5. Adaptive index economics
Actual native Fjall store measures unindexed writes, staged rank construction,
maximum writer turn, scan/sort versus deepest ten-row page and maintained writes.
Use evidence/summary.json for medians and read-only amortization; small collections
can make indexed reads slower. At 100 rows, ten reads take 23.235 ms scanning
versus 46.029 ms indexed; construction costs 1.479 s. At 1000 rows, ten reads
take 328.860 versus 98.242 ms (3.35x); construction costs 36.574 s. Read-only
break-even is approximately 1586 reads, far beyond a fixed three-request trigger.
Maximum observed writer turn is 350 ms / 1715 ms at 100 / 1000 rows. Ten writes
cost 112.715 ms unindexed versus 1279.731 ms maintained at 1000 rows; this
single pair is an observation, not a stable maintenance-overhead estimate.
A fixed query count cannot be an economic policy.

Production seam: collect observed scan cost and staged build/maintenance cost;
admit only when conservative expected reuse pays for construction AND writes.
Budget each writer turn; suspend/evict low-value indexes with hysteresis. Retain
scan fallback and exact ACL scope keys. Estimate benefit from runtime counters,
not developer hints. Read-only break-even omits future writes and is a lower-bound
planning estimate, not a production admission decision.

* 6. Cancellation and code leases
Real process queue has 90 dead request owners and ten live owners. Guarded
admission declines dead work and preserves identical live checksum; accepted
work must drain even when its requester later disappears. BEAM old-code test
holds generation 1 while loading generation 2: soft_purge refuses active code;
old call completes after release, new calls use 2, then retirement succeeds.
Queue medians fall from 7289.668 to 643.475 ms (11.33x); reductions fall
from 138273140 to 13803795, approximately 90% fewer, matching 90 skipped jobs.
Atomics pair benchmark estimates a primitive lease cost, not full API overhead:
10000 iterations take 44.941 ms baseline versus 69.654 ms with pairs, observed
increment 2.471 microseconds/pair; timing noise makes this only a rough estimate.
The new queue test kills owners before admission; post-admission owner-death
needs an explicit integration regression beyond this old-code drain check.

Production seam: attach owner/deadline tokens at entry, propagate through async
loader/query jobs, check before admission. Once accepted, finish shared work and
publication; detach dead waiters. Lease executable generations across callbacks
and queued closures; monitor owner death and release in finally. Defer retirement
rather than forced purge. App developers inherit this through runtime boundaries.

* 7. Endpoint leases
Private Linux flock + Unix socket adapter replaces expiry guesses with OS-owned
ownership. Persistent lockfile is never unlinked; unique socket/token, atomic
manifest publication and inode/token-fenced cleanup protect replacements.
Eight acquisition batches median 11.377 microseconds/op. Eight crash restarts
median 146.881 ms including starting a fresh Python process. Paused live owner
blocks competitors, SIGKILL releases ownership, stale cleanup preserves successor,
and graceful cleanup removes endpoint/manifest. No product TTL speed ratio claimed.

Production seam: VM manager holds the lock descriptor for its full lifetime,
publishes token/socket after bind, and checks ownership on cleanup. Supervisor
owns recovery, removes stale sockets only under exclusive ownership, and detects
unsupported network-filesystem lock semantics. Prototype targets local Linux.
This improves crash/reload recovery correctness more than normal page latency.

* Logic tools and proof boundaries
system.ir/footprint, codebase and typed inspect actual compiled/source structure.
veritas, with an opened Z3 context, checks finite idealized admission/lease policies
(actual reported engine: oracle, not SMT) and a lexical-tracker
counterexample. Formula proofs are not proofs of the runtime implementation,
resource cleanup, arbitrary macro purity, or all race interleavings. Real negative
controls and mechanism tests remain the implementation evidence.

* Reproduction
AOT: application-aot.py --app <app-worktree> --baseline source --samples 4;
repeat with current-cold (2 samples minimum) and current-warm (4), optionally
--reuse the first home scratch directory. Driver bounds each VM at 8 GiB/600 s.
Declare source roots in the producer project. Artifact consumers declare none.
Others: from the pinned app cwd, FOLLOWUP_ONLY=<area> TMPDIR=<home-scratch>
bl run -p <beam-worktree> <beam-worktree>/research/runtime-followups/run.bl,
under timeout 600 and ulimit -v 8388608. Areas metadata, realm, dependencies,
index-economics, lifetimes, logic. One VM at a time. endpoint-leases.py is standalone.
summarize.py evidence/*.log emits raw observations and grouped medians, excluding
first realm candidate warmup. Preserve failed logs separately from passing gates.
