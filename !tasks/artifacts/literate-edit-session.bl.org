#+TITLE: A conversation that edits a file

* The change

*You:* Make the literal-key lookup idiomatic. Preserve the comment and the
neighboring function. Show the proposal before writing, and check the result.

*Assistant:* I can use the existing `deodorant/fix-source` structural rewrite.
This demonstration owns exactly one fixture, not application source. Run from the
Beam Lisp repository root with `bl doc run !tasks/artifacts/literate-edit-session.bl.org`.
The executable below previews, checks, applies, and verifies the edit. A rerun
accepts only the original fixture or its exact expected result; unrelated changes
are refused. It evaluates the candidate in a disposable command process before
writing. This is not a sandbox or a concurrent/crash-safe transaction coordinator.

#+begin_src beam-lisp :id edit-proof
(ns poc.literate-edit.session
  (:require [deodorant :as d]))

(defn check! [condition message]
  (when (not condition) (throw (ex-info message {}))))

(let [path "!tasks/artifacts/literate-edit-fixture.bl"
      before "(ns poc.literate-edit.fixture)\n\n; This comment and the sibling function must survive unchanged.\n(defn option [m] (Map/get m :x))\n(defn untouched [m k] (Map/get m k))\n"
      expected "(ns poc.literate-edit.fixture)\n\n; This comment and the sibling function must survive unchanged.\n(defn option [m] (:x m))\n(defn untouched [m k] (Map/get m k))\n"
      current (File/read! path)
      proposal (d/fix-source (d/all-rules) before)
      candidate (:source proposal)]
  (check! (or (= current before) (= current expected)) "Refusing unrelated fixture contents")
  (check! (= (:changed proposal) 1) "Expected exactly one structural rewrite")
  (check! (= candidate expected) "Proposal changed unexpected source bytes")
  (check! (= current (File/read! path)) "Preview unexpectedly changed the file")
  (println "PREVIEW: (Map/get m :x) -> (:x m); sibling and comment preserved")
  (check! (= (list 7 9)
             (BeamLisp/eval (str candidate "\n(list (option {:x 7}) (untouched {:x 9} :x))")))
          "Candidate behavior failed before application")
  (check! (= current (File/read! path)) "Source changed since preview")
  (when (= current before) (File/write! path candidate))
  (check! (= expected (File/read! path)) "Written bytes differ from proposal")
  (check! (= (:changed (d/fix-source (d/all-rules) (File/read! path))) 0)
          "Second structural pass is not a no-op")
  (println "VERIFIED: values 7 and 9; exact bytes; second pass is a no-op")
  {:status :verified :rewrite-count 1 :checks 8 :rerunnable true})
#+end_src

*You:* What if somebody edits the function while you are thinking?

*Assistant:* This fixture refuses unexpected content and checks it again before
writing. There is still a check-to-write race. The production companion needs a
workspace lock shared by all participating writers, expected hashes, a durable
receipt and recovery. A Markdown cell alone cannot provide those guarantees.

*You:* Can I rerun our conversation tomorrow?

*Assistant:* Yes for this fixture: the exact expected result is accepted and no
source rewrite occurs. The same verification runs again. In a general edit journal,
each operation needs a stable identity and an applied receipt so yesterday's cell
cannot overwrite tomorrow's work.
