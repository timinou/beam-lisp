#+TITLE: Caller-owned operations across immutable releases
#+STATE: ACCEPTED native SDK primitives; product acceptance tracked separately

* Node-local mutex
proc.mutex/with! uses existing exact native lock tickets, scoped by application
identity, and runs the action on its caller. There is no application Agent
retaining callbacks or requiring a state handoff. Reentrant calls and thrown
actions release correctly; killed holders cannot block a replacement forever.
No distributed-consistency or FIFO guarantee is implied.

* Atomic result/value exchange
reload.state/get-and-update! performs a pure compare-and-set retry on an
initializer-owned shared cell, returning a result independently of next state.
A function/opaque executable value cannot be retained. Contention may repeat
the pure step; never submit provider effects inside it. This is suitable for
one-use authorization records, not effectful job submission.
