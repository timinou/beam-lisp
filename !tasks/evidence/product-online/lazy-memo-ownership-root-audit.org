* Concrete source findings
- =priv/host/env.bl=: =callback_modules= inspects callable arms/module identity,
  not captured arbitrary data. =retain_code!= / =insert_code_lease!= publish rows
  shaped ={(module, pid, ticket), true}=. Those rows contain NO function or lazy
  value. This rules out a closure retained in that code-custody index itself.
- =priv/std/proc/callback.bl=: =register!= returns an invoke/convey closure to its
  caller. =priv/host/env.bl:convey= captures the function and Env token in that
  returned closure; caller/domain storage may retain it intentionally. There is
  no separate native creator-lifetime function registry in this path. This does
  not prove that every application registration is eventually released.
- =priv/host/refs.bl=: task/spawn startup transfers a module ticket and conveys
  the actual task closure/context to its worker; accepted work owns them until
  actual completion. A timeout/caller exit is not completion or cleanup proof.
- =priv/boot/compiler.bl:assemble-fn= emits ordinary native/self-applied functions
  or the explicit multi-arity descriptor. It does not automatically register each
  function through proc.callback or Env.convey.
- =priv/host/aot.bl:constructor_register_callable!= roots every interpreted native
  function in its invocation's private =:callables= map (limit 16,384).
  =constructor_interpret=, the =:fn= branch, creates closures over lexical env,
  constructor state/metadata, clauses and node context. =interpret_constructor!=
  erases the frame in =finally= on normal/exception completion. Whether retained
  values elsewhere outlive a frame must be measured, not assumed.
- =priv/host/lazy_memo.bl:deps_clean_remember!= keeps up to 16 resource-free captured
  values per process by identity. This is a real bounded-count BEAM data root;
  its bytes are not bounded by that count. Only dependency-empty values enter
  this cache, so it cannot directly retain recognized native memo resources.
- =priv/host/lazy_memo.bl:estimate_bytes= measures full pending thunk/recipe terms
  using =erts_debug.flat_size=. =priv/host/lazy_seq.bl:new= stores those closures
  in native memo state. If a real lazy cell captures an interpreter function,
  its full metadata capture is copied/charged; code leases do not cause that copy.
- =native/lazy_memo/src/lib.rs:MemoCell= has id/read_only/version/touched/state,
  with no creator PID. =native/lazy_memo/src/collector.rs:register= stores raw
  pointer entries, not a permanent ResourceArc. Native liveness follows actual
  resource references and the collector's conservative census.
- The MemoCell destructor decrements =retained_bytes= before enqueueing OwnedEnv
  reclamation. A high =pending_reclaims= can explain RSS lag but cannot by itself
  explain =retained_bytes= remaining at the 512 MiB admission ceiling.

Current native Source actors also deliberately hold their original graph/context
in private actor state until authenticated adoption or actual DOWN. That is an
explicit actor lifetime root, separate from a lease row storing a closure, and
was not established as the executing new implementation in 145.

* Root 146 instrumentation targets
At bootstrap, fixture compilation, each test start/end and interpretation exit:
record actual native module MD5/artifact SHA256, LazyMemo =retained_bytes=,
=live_cells=, =pending_reclaims=, =op_new= / =op_new_fast=, and collector
enabled/runs/collected counters. Compare after same-caller GC plus bounded reclaim
wait; separately compare after a controlled worker's actual exit. Log only bounded
counts/sizes, not captured source/arguments or full process dictionaries.

Check private constructor-frame existence/callable counts before/after each
interpretation and bounded size samples of clean-capture values. Persistent frame
rows after normal completion would contradict the current finally contract.

* Unproven hypotheses and limits
Metadata-heavy native closures copied into real lazy cells are a concrete possible
amplification mechanism, not the established cause of 145. Large clean-capture values
may contribute BEAM RSS; an actual retained native graph, compilation/namespace
metadata root, collector behavior, and deferred reclamation remain distinct
possibilities. No hypothesis is a measured leak or justification to increase the
cache ceiling, drop accepted work, weaken ownership, or disable the safety gate.
No source/runtime edits, native launches, production operations or deployments
were performed for this audit.
