* Expanded native calls and exact initializer execution
Source rewriting is no longer generation authority. Structural source planning
admits only literal target/list candidates against explicit native grants. Actual
post-expansion ANF proves the resolved Core proper-list constructor and native
module/function/arity. Unknown or shadowed constructors refuse before effects.
The original argument-list expression remains the case subject; exact proper-list
matching supplies evaluated arguments to a direct native call. Flattening arguments
could change Core exception/effect order, so allocation is deliberately preserved.
The same checked IR is executed; initializer macros are not compiled twice.
Legacy reload.static-call's standalone source utility remains for compatibility,
but generation execution no longer depends on its restricted source grammar.

The native order probe compares original and specialized execution, including
side effects around an exception. BL does not promise left-to-right call argument
evaluation; preserving actual behavior is the requirement. The first test assumed
that guarantee and was corrected using observed reference execution. No compiler
language-order contract was silently changed.

* Immutable callback registries
reload.registry-data validates finite data and explicit namespace/function names.
configuration.registries is generation-owned immutable data, included in graph
identity. Callback namespaces become graph roots automatically. Missing/noncallable
references and unknown field atoms refuse before publication. Callback metadata
and private state never retain arbitrary executable closures.

reload.registry/lookup resolves against exactly the selected graph. Old and new
releases can retain different implementations/configuration concurrently. Managed
register! refuses; publication is an ordinary candidate/configuration release.
Development registration stores the same data/reference shape under the existing
legacy state seam, with no managed fallback and no new atoms for registry names.
Delayed users still require ordinary owned task/callback lifetimes.

Foundry discovers configuration references in its sealed artifact inventory.
Knowledger's built-in Google/Microsoft maps remain static, while custom provider
lookup uses this generic registry. The obsolete persistent_term executable table
and unused upload dependency are removed. No product upgrade coordinator is added.
