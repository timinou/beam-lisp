#+title: Native lazy memo pressure reclamation
#+date: 2026-10-15

* Scope and observed cause
Root's selected-floor-95 native diagnostic found large dead native memo cycles
while the allocation-count collector had not run. Process GC alone cannot break
resource-to-resource cycles. CompilerData's letfn walker was one concrete cycle
producer (being fixed independently); the native cache must also handle legitimate
application cycles without requiring developers to avoid them.

* Batch 1: pressure collection at the existing budget boundary
priv/host/lazy_memo.bl now runs exactly one calibrated collect_cycles round after
caller GC when admit! actually reaches the byte ceiling, and on the first
exchange_version_admitted :over_budget. Only the same version/value publication
is retried. Producers are never replayed, live data is never evicted, and the
budget is never raised. Disabled/failed calibration remains conservative: the
normal budget refusal still applies. The existing 25ms deferred-reclaimer grace
starts AFTER collection. The graph scan itself is not a realtime latency promise.
Healthy, below-budget paths perform no new collection work.

New test/bl/lazy_pressure_cycles_test.bl uses actual native atom cycles with
1MiB eager tuple state, an independently rooted live cycle, counted lazy producers,
real child DOWN acknowledgements, and native byte/cell/collection counters. It
covers admission reclamation, pressure created inside a producer before result
publication, and live-only admission/publication refusal with unchanged cell
version/state. Receipts print bounded elapsed time and counter differences.
The small cycle is below the proposed 16MiB automatic-growth floor; every pressure
case additionally asserts that actual occupancy reached its budget before the
boundary. Unexpected autonomous collection makes that precondition fail visibly,
rather than silently treating an unexercised path as passed.

** Validation status
Source delimiter/try-shape checks and git diff --check pass. Native execution is
PENDING root's serialized coherent-host/NIF validation. No runtime performance,
Hera, application, or production acceptance is claimed here.
Suggested one-VM focused order: host_lazy_memo_test.bl, lazy_pressure_cycles_test.bl,
lazy_budget_test.bl. Existing ref_cycles_test.bl is a broader, slower collector
regression and can follow within the same capped VM if resources permit.

* Batch 2: accounted growth scheduling
Pending implementation: retain the count trigger and add amortized byte-growth
demand on fresh allocations and committed positive state growth. Use the same
calibrated collector worker, never a graph scan under mutation locks. Recheck
arrivals during a round so a request cannot disappear when the latch clears.
