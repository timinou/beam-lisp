#+TITLE: Application-scoped live sessions and exact graph lifetime
#+DATE: 2026-10-12
#+STATE: PASS — scoped lifetime/reconnect; session evolution remains gated

* Failure and boundary
The fixed SDK =live.app= session registry used one literal name and a SID-only
relation. The reconnect principal check does not distinguish two application
instances with the same principal. Managed registry identity must include the
stable application instance, while remaining unchanged across source releases.

The first native fourteen-assertion regression draft passed nine and failed
five. It exposed two concrete framework defects: native
Server startup rejected standard OTP global names produced by =proc.instance=,
and a fixed SDK actor storing sealed app callbacks did not automatically retain
their complete graph. The generic OTP name fix has a separate host regression;
the application must not hide that failure by silently returning nil.

* Implementation
=live.app/sessions= resolves/starts the registry through =proc.instance= and
uses the actual registry PID for =proc.reg= calls. A startup exception is treated
as a double-start race only when an existing scoped winner really exists.
=start-session= obtains the registry before starting a socket and stops its
newly created socket if registration fails.

The actual =app-socket= actor captures its current complete generation before
mounting or subscribing. Its native registration is owned by its real PID;
normal death, fatal death and failed initialization cancel that ownership.
Retirement evidence prunes dead registrations. There is no dummy callback,
extra keeper process, callback swapping or inferred shutdown authority.
Ordinary non-managed callers keep their legacy registry identity.

* Regression
=test/bl/live/scoped_session_test.bl= uses actual public WebSocket initialization
with two sealed application identities, the same principal and known SID, then
a newer generation of one application. Seventeen assertions cover isolated
registries/session PIDs/trees, same-instance reconnect to the physical old PID,
unchanged old callbacks, retirement blocked until the session ends, and new
candidate session creation through the same data-only registry after retiring
the old graph. Existing app-context and reconnect tests run alongside it.

The actual MAIN source launcher with the officially regenerated host floor
passed all seventeen scoped-session assertions, twenty-one app-context and
fourteen resume assertions. The same ten-file native batch also passed native
Server ABI 181, host freshness 25, bootstrap generation 17, seed completeness
14, generation 132 and initializer factory 30. Its only failures were two
new host-test calls using OTP startup ={:local, atom}= as a client reference;
OTP clients use the atom. That fixture is corrected and its separate host-name
rerun is owned by the host agent. No session assertion is weakened or skipped.

The whole coordinated batch took 63.748 s and peaked at 808.9 MiB with zero
swap; these are batch resource figures, not a session speedup benchmark. Raw
log: =/home/user/tmp/managed-factory-validation/host-proof.log=. No additional
BEAM was started for this change, and no deployed instance was touched.

* Remaining session evolution gate
Lifetime preservation is not actor migration. An active session can retain its
old graph indefinitely. A full online product upgrade must explicitly evolve
its descriptor/state protocol or perform an acknowledged reconnect/drain that
preserves drafts, rechecks authorization and observes old subscriptions closing.
Router publication alone does not establish session drain or old graph retirement.
