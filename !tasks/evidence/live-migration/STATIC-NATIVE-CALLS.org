#+title: Conservative static native-call specialization
#+date: 2026-10-12

* Implemented
=reload.static-call/specialize= returns the exact original =:source=, separate
=:compile-source=, occurrence-ordered string target inventory and rewrite count.
It lowers only literal keyword module/function calls with an explicit Core
=(list ...)= argument expression. Compilation still authorizes every target
against the exact native inventory and rejects hazards; rewriting grants no
capability. No source is evaluated and no native target atom is allocated.

The transformation removes only tokens and argument-list delimiters. It leaves
comments, Unicode codepoints, quoted data and argument evaluation order intact.
Codepoint spans avoid grapheme/byte index confusion. Analysis is bounded to
1 MiB, depth 32 and 100,000 nodes. Boolean scans use a linear cons worklist;
wide over-budget collections refuse before worklist expansion. Unexpected
rewrite errors raise a typed refusal rather than pretending no rewrite occurred.

* Conservative proof prerequisites
Namespace refer/rename/import ambiguity, a definition of =list=, unknown eager
initializer calls/macros and unknown top-level forms disable specialization.
Bindings or borrowed bare =list= symbols disable the enclosing form. Only
explicit compiler intrinsic forms and expression collections are traversed;
unknown body calls/macros and reader prefixes remain opaque. Multi-arity
functions remain unchanged. The caller provides the full BL namespace inventory
to rule out native/BL resolution ambiguity.

Compilation-time macros remain the existing trusted compiler boundary, not a
sandbox. The generation compiler's final ANF audit must reject hidden runtime
namespace mutation before publication; the initializer proof must prevent
executing such functions before initialization. Unchanged code still goes
through those generation checks.

* Validation
The focused native =test/bl/reload/static_call_test.bl= suite passed in the
single coordinated MAIN-source VM recorded at
=/home/user/tmp/managed-factory-validation/product-next.log=.
Generation's integration suite passed 17 assertions, including real evaluation
order/effects, target authorization, hazard refusal and original-source digest
identity. Focused pure tests cover comments and Unicode, quoted code, local and
global shadowing, namespace conflicts, unknown macros, dynamic arguments,
reader prefixes, transparent refusal and all three analysis bounds.

Initial validation exposed an unsupported three-argument =conj= and quadratic
worklist concatenation on the wide-budget fixture. Both were corrected; the
focused suite then completed normally. This is correctness and bounded-work
proof, not a measured product startup speedup or a sealed Knowledger release.
