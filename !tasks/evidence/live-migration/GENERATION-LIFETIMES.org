#+title: Sealed application graph lifetime and warm-cache repair
#+date: 2026-10-11

* Validated reusable fixes
** Warm AOT replay and code publication
- Cached initializer replay is owned by the consuming environment and exact
  artifact/module identity. Replaying the same installed unit is a no-op;
  a separate environment initializes independently; changed bytes initialize.
- A partially failed initializer remains failed in that scope. Retrying cannot
  silently repeat already-performed side effects.
- Before third code publication, native module publication uses soft purge and
  refuses when unleased old code is still executing. It never implicitly kills
  the old worker to install the third version.
- Native regression: test/bl/aot_replay_lifetime_test.bl, 3 tests, 13 assertions.
** Ward environment lifetime
- All three public Ward runners destroy their warm base after their eagerly
  realized result, including lazy source iteration failure. Warm-base setup
  failure also destroys the allocated environment.
- Native regression: test/bl/reload/ward_worker_test.bl, 5 tests, 26 assertions.
** Measurement and limitations
- Focused native run: 51.810 s, 296.2 MB peak, zero swap; both files above green.
  Log: /home/user/tmp/sealed-generations/new-native/focused-fixed.log.
- This is a correctness/lifetime proof, not an application loading speed claim.
  The generation extension had three new-fixture errors in this same run and
  is being corrected separately. Seed default-floor freshness requires official
  regeneration after host source changes.
- No production deployment or mutation occurred.

* Integration in progress
- Compiler-audited immutable callback values, definition macros and first-party
  owner descriptors, with full graph leases and initializer runtime bindings.
- Owner evidence proves code lifetime only. A server descriptor lease does not
  prove state/message evolution or authorize actor termination. Retiring an old
  graph must wait until its long-lived owners transition or stop safely.
- Runtime handles are separate from sealed artifact identity. Only the original
  live initializer owner can share them with an unpublished candidate.
- Fresh namespace/module atoms remain lifetime-budgeted; retirement cannot reclaim
  BEAM atoms. Exhaustion requires runtime handover rather than unsafe reuse.
