#+title: Sealed application graph lifetime and warm-cache repair
#+date: 2026-10-11

* Validated reusable fixes
** Warm AOT replay and code publication
- Cached initializer replay is owned by the consuming environment and exact
  artifact/module identity. Replaying the same installed unit is a no-op;
  a separate environment initializes independently; changed bytes initialize.
- A partially failed initializer remains failed in that scope. Retrying cannot
  silently repeat already-performed side effects.
- Before third code publication, native module publication uses soft purge and
  refuses when unleased old code is still executing. It never implicitly kills
  the old worker to install the third version.
- Native regression: test/bl/aot_replay_lifetime_test.bl, 3 tests, 13 assertions.
** Ward environment lifetime
- All three public Ward runners destroy their warm base after their eagerly
  realized result, including lazy source iteration failure. Warm-base setup
  failure also destroys the allocated environment.
- Native regression: test/bl/reload/ward_worker_test.bl, 5 tests, 26 assertions.

* Actual product integration still bounded
- Definition macros may expand only to checked definitions; immutable initializers
  use a small compiler-ANF constructor proof, not an arbitrary factory whitelist.
- General computed factories, dynamic apply, raw spawn/timers, custom supervisor
  MFA children, mutable top-level initializers and product persistent_term globals
  remain refused. They require explicit audited managed ownership/construction.

  owners and prove durable queue inventories; code leases alone do neither.

* Current Knowledger source integration report (read-only, 2026-10-11)
- Newly supported: ordinary immutable definitions, callback maps/inline closures,
  trusted definition macro expansions such as live.app/defscreen, native bare
  defserver modules and checked native supervisor child descriptors.
- live.bl's app-value is a defn; it does not require arbitrary top-level factory
  evaluation. Product globals need explicit runtime-resource cells; reload.state
  provides the generic legacy/managed seam and root is integrating that seam.
- Raw producer calls remain in spawn-pass! and start-sync-loop!. The source seal
  deliberately refuses them until a managed producer API retains full graph
  context, records ownership and supplies a retirement/transition protocol.
- log-pretty-shape still performs dynamic Env/fetch + Rt/invoke. Login test probing
  computes erlang/apply module operands. Such lookup needs static sealed targets
  or relocation to a trusted fixed runtime service; dynamic dependency escape
  remains refused. Literal apply could be separately audited before admission.
- library-owner now has full code-lifetime proof, but registry/subsystem names
  remain VM globals. App-scoped queue identity alone does not scope every custom
  registry, dispatcher, watcher or session. Cross-app ownership must be explicit.
- Retaining an old generated OTP callback module means swapping an evolve user
  handler alone cannot retire its original graph. A native shared descriptor
  dispatcher/context transition or explicit owner handover is still needed.
- Framework live.app performs top-level web/asset loading for client-js. Treat
  fixed SDK framework code/assets as an explicit artifact boundary; admitting
  arbitrary computed product defs is not a safe substitute.
- A full sealed Knowledger graph and real production online transition have NOT
  been demonstrated by these foundation tests. No Hera changes were made.
- Further actual product constructors: live/intents calls
  workflow-procedure-performer, and knowledge-intents invokes the two performers
  factories before merging callback maps. These need bounded interprocedural ANF
  construction proof even though app-value itself is already a defn. They remain
  refused by the current constructor-only initializer proof.
- Ordinary @ deref source is now rewritten by sealing its actual reader operand;
  a new regression covers aliased/direct qualified operands and quoted @ data.
- Final source audit also mirrors native reflection/global-resource hazards in
  expanded ANF, so a definition macro cannot accidentally inject an Env lookup,
  compiler/code publication call or raw persistent_term access behind the source
  scanner. Static compiler-inserted Loader.ensure_ready names must be sealed or
  explicitly fixed runtime namespaces. This is still not a hostile-code sandbox.

- Native reflection correction: ordinary first-class/keyword calls lower to
  Rt/invoke. ANF therefore permits that compiler scaffold while checking its
  global/module references. Explicit BeamLisp reflection in source or expanded
  definition macro output is refused before lowering. This avoids a false
  refusal for ordinary sealed callback maps and runtime binding handlers.
