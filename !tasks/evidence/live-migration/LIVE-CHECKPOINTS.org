#+title: Live logical checkpoints and data-owner handover

* Contract and integration boundary
Fjall 2.11.2 exposes tracked MVCC snapshots, but no physical live-checkpoint
operation. Copying a live LSM directory is not a backup. The native implementation
exports raw ordered KV bytes from one tracked snapshot into a separate private
engine; Datom indexes, schema and basis metadata are copied together.

Public =datom.store= capability:
- =checkpoint-capable? store=; transparent profiling wrappers preserve support,
  semantic overlays and unsupported stores do not invent it.
- =capture-checkpoint! store=: exact native source claim and MVCC snapshot, no
  destination filesystem I/O. Source write mutex covers only snapshot capture.
- =begin-checkpoint! cursor destination=: fresh private sibling stage and exclusive
  target-engine flock. Source is never reopened.
- =checkpoint-step! artifact {:chunk-size 4096 :max-chunk-bytes 2097152}=: bounded
  rows and copied KV bytes; oversized single entries refuse without advancing.
- =finish-checkpoint! artifact=: require exhausted scan, stable target writes,
  engine shutdown, fsync tree/receipt, Linux atomic no-clobber rename and parent
  fsync. Returns ={:status :complete :kind :logical :path ... :source ...
  :sequence ... :entries ... :bytes ... :durability :stable}=. Repeated finish
  returns the same receipt. =BL_CHECKPOINT_V1= records numeric identity and the
  hex-encoded source path; this file is metadata, not a full-product manifest.
- =abort-checkpoint! artifact= removes only its own private stage. A publication
  already made is preserved; if parent fsync failed, retry finish to establish
  its stable receipt. =release-checkpoint! cursor= is idempotent; accepted exports
  own independent snapshot pins. GC cleanup runs on native cleanup threads.
- =checkpoint! store destination opts= is the yielding convenience runner with
  between-chunk progress/cancellation callbacks and guaranteed capture cleanup.

A product coordinator must capture ALL declared store cursors and the immutable
blob/CAS inventory under one declared-owner boundary before releasing it, then
begin/stream exports outside that boundary. A per-store cursor alone does not
prove cross-store or database/blob consistency. Mutable blob contents need their
own stable capture protocol. Unsupported destination publication platforms fail
closed; there is no overwrite fallback.

Chunk bounds describe copied KV bytes; the engine still materializes one entry
before its size can be checked. Snapshot retention can increase compaction/disk
pressure while export is active. Native file operations share BEAM dirty-I/O
scheduling; final fsync can delay unrelated I/O even though no source writer lock
is held. Benchmarks must separate capture time, chunk latency and final sync.

* Runtime and data-owner handover
A captured cursor/export pins the exact source engine and its inode flock. A
second process cannot become its writer until all source references and snapshot
pins are released. Within one OS process an additional open joins the same engine,
never a second writer. The test explicitly proves the old exact claim survives
capture/export and is released after completion and cursor release.

Production hot code evolution keeps the existing data owner alive. Moving that
owner to another VM requires an explicit routing/proxy drain, final admission
fence, outstanding-cursor cancellation/drain and actual native flock release;
a checkpoint is not a transferable writer lease. No two-writer handover is
implemented or claimed here.

tracked snapshot excludes later inserts/replacements/deletes, capture performs no
destination I/O, staging refuses a second engine, incomplete/oversized export

This removes the source writer lock from export, but proves no robust tail win:
final fsync occupies the shared dirty-I/O lane and delays source native writes.
An accepted follow-up moves finalization to an owned native background worker
and waits for a tagged completion outside that lane; acceptance requires a fresh
benchmark. These are bounded local measurements, not production HTTP results.
