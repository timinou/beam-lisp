#+TITLE: Durable jobs and managed message retirement
#+DATE: 2026-10-10
#+STATE: CHECKPOINTS AND GENERATION ADOPTION VALIDATED; NATIVE OWNER TRANSITIONS ADDED

* Ownership and store lifetime
proc.queue remains the queue engine. Its default ETS store survives a queue
process restart, not a BEAM restart. =attach-store!= binds an existing dedicated
persistent Datom connection before first use; the application/native lifecycle
owns opening and single-writer authority. No second storage owner is introduced.

* Identity and protocols
Each new job has a random stable =:job/id=, source identity, optional parent,
original payload protocol and optional generation. Each claim has a fresh random
attempt identity and the existing owner fence. Metadata lives in datoms and is
reconstructed when reopening the connection. Legacy jobs use protocol 1.

Workers see original metadata and the adapted execution protocol/generation.
Unary upcasts and validation execute before claiming; unsupported payloads remain
owed rather than being silently failed, discarded or repeatedly consuming retries.
No declaration update clears failures or held work. Explicit retry runs in place,
retaining source/protocol/identity and lifetime attempt count with a new retry
budget. Reconcile delegates to the queue instead of minting a differently typed
job after deployment.

* Attempt fence
Expired-lease reclaim now compares running state AND owner as well as deadline.
Previously an old snapshot could revive an already-settled job if its lease field
had not changed. Queued claims also compare their observed attempt counter.
=commit-attempt!= validates running state, owner/attempt and unexpired lease in
the queue store writer before applying effects to that SAME connection.
External provider effects cannot become atomic with the queue transaction.

* Retirement scope
Managed proc.evolve owners refuse raw versioned calls. Callers acquire opaque
client leases, drain and release them. Retirement closes new acquisitions and
all registered queue protocol admissions before querying live and durable
references. Failed/held/unknown durable states count as retained dependencies.
A contiguous legacy adapter prefix is released only when both counts are zero;
waiting preserves admission fences. Registrations are monotone and sealed after
successful retirement. Arbitrary boolean predicates cannot authorize retirement.

This proves the registered managed scope only. The release inventory must bind
all managed queues. Arbitrary writes to storage or unmanaged external producers
are outside this contract. Unmanaged owners retain their existing API and refuse
adapter retirement. Multi-store reads/commits are not a single atomic transaction;
monotone admission closure makes the subsequent zero observation safe for the
registered producers. Runtime boot must reconstruct declarations/bindings from
the sealed release before admitting traffic.

* Validation
Validated queue_protocol_test, evolve_test, reconcile_test, queue_test and
async_queue_ownership_test in one capped VM, HOME scratch: 45 tests, 240
assertions, zero failures/errors. Runtime 39.0s, memory peak 249.5MB, zero swap. Connection recovery
is exercised from datoms; full abrupt OS-process recovery belongs to the sandbox
acceptance harness and is not claimed by the in-process reconstruction test.

* Provider checkpoints and sealed producer defaults
=begin-effect!= writes an intent before submission and returns a stable provider
idempotency key. A repeated intent returns =:reconcile=, including across claims;
only explicit provider-confirmed =:absent= permits submitting again. Submitted,
uncertain and incomplete effects hold jobs, preserve uniqueness tickets and block
adapter retirement and pruning. =record-effect!= and =reconcile-effect!= require
an unexpired current attempt; receipts are bounded to 64KB and are not emitted
as diagnostic/UI payloads. The provider query itself remains domain-specific.

Queue producer defaults come from the automatically conveyed sealed generation
=:protocols= and =:digest=, ahead of mutable current declarations. A missing
sealed producer contract refuses enqueue; conflicting generation overrides
refuse. Legacy callers retain declaration defaults. This prevents old request
closures from relabeling old payloads as the latest protocol after publication.

Native =declarations= discovers registered queue connections and reports protocol,
generation, store identity and dependency inventory. Failed reads are explicit,
never an empty dependency proof. The release builder owns which managed queues
belong to a given application.

Two more upstream race fixes accompany in-place retry: automatic retry retains
its uniqueness ticket, and prune selection/deletion uses the same writer turn as
retry so an old terminal snapshot cannot delete newly owed work. Settlement also
reads checkpoint state in its writer turn so it cannot race past a new provider
intent and incorrectly finish the job.

The no-contract current-protocol worker path avoids a migration child-process
fence; the bounded adapter fence is paid only when actual validation/adaptation
is needed. New metadata is native queue behavior, not repeated app call-site
plumbing.

* Required generations and adoption
Jobs now distinguish immutable producer =:job/generation= from required dispatch
=:job/required-generation=. Dispatch refuses a mismatched required generation;
persisting a digest is not treated as permission to execute under newer code.
An explicit =adopt-generation!= operation validates/upcasts payload under a
bounded fence, revalidates the unchanged nonrunning job in its writer, and writes
converted payload, required generation and exact migration receipt together.
Original generation/protocol/payload remain unchanged. Pending provider effects
refuse adoption. Replays match the receipt; stale observations refuse.

=fence-generation!= durably closes one exact producer generation independently
of protocol, so newer compatible producers keep admitting work. Inventory reads
one snapshot and includes original =:generations=, dispatch =:required-generations=,
unversioned counts and generation fences. Parent orchestration may conservatively
wait for original generations or use declared adoption receipts to drain required
generation references. Unknown unversioned work is explicit, never ignored.

* Stable storage boundary
Fjall journal commit and power-loss durability are distinct. Critical provider
checkpoints, generation/protocol fences and adoption receipts now call the native
=datom.store/Durable= synchronization boundary before returning success. A sync
failure propagates without returning permission to submit or collect. Repeated
intent reads also synchronize before authorizing their result. Memory fixtures
report =:durability :volatile= explicitly; production orchestration must require
a durable backend. =commit-attempt!= reports a guarded journal commit, not a
power-loss durability receipt.

A test-only Store/Durable spy verifies that intent is already written when sync
runs, that sync refusal prevents =:submit=, that uncertain state remains for
reconciliation and that generation fences synchronize. This is boundary-ordering
evidence; real filesystem durability remains the backend/sandbox acceptance test.


* Follow-up validation and measurements
2026-10-10 focused run: queue_protocol_test, evolve_test, reconcile_test,
queue_test, async_queue_ownership_test and live-upgrade-queue benchmark completed
56 tests / 434 assertions with zero failures and zero errors. Capped single VM,
HOME scratch; runtime 1m43.722s, peak 323.4MB, no swap. The deliberately invalid
evolution-state fixture logs its rejected child exception as expected.

The warm source-checkout benchmark completed 100/100 plain jobs and 100/100
adapted jobs with zero held/failed jobs. Plain throughput: 10.08 jobs/s;
enqueue p50/p95: 12.272/52.796ms. Adapted throughput: 11.03 jobs/s;
enqueue p50/p95: 15.033/25.010ms. These are shared-host scenario measurements,
not a controlled baseline comparison; the adapted result is not a speedup claim.
The benchmark includes existing queue scans, Datom writes, server wakeups and
no-op worker bodies. Real provider/network latency and filesystem checkpoint
sync cost are excluded by these memory-backed scenarios.

Final review additionally found that preparation precedes claim, allowing a
nonrunning job adoption to race between those steps. Claim now revalidates the
observed required generation, adoption receipt and converted payload in the
same writer turn as its existing CAS. This also refuses A -> B -> A changes.
A deterministic regression proves a stale pre-adoption snapshot cannot claim,
while a freshly read snapshot can. This last regression awaits the next native
batch; the preceding throughput measurements predate this final writer guard.

A sealed generation must declare its queue even when enqueue explicitly names a
protocol. An override may replay a declared queue protocol, but cannot invent an
undeclared queue outside the sealed release inventory. Legacy defaults remain.


Receipted adoption now wakes the queue through the existing Datom subscription:
=:job/required-generation= and =:job/adoption= join =:job/at= in the watched
attribute set. Previously incompatible queued work could stay asleep after
adoption until an unrelated enqueue. The original scheduled timestamp remains
unchanged. A live-owner regression adopts the only pending incompatible job and
checks that it completes without another enqueue; queued with the final batch.


* Final queue regression and restart evidence
The generation agent's fresh native batch exercised the final stale-adoption
claim guard and live-owner adoption wakeup with no queue failures/errors. Its
combined 57-test batch had two unrelated application binder fixture errors;
there is no claim that the entire combined batch passed. Repeated queue scenarios
completed all 200 jobs, zero held/failed: plain 24.69 jobs/s, enqueue p50/p95
6.389/11.126ms; adapted 25.23 jobs/s, 6.944/11.270ms. These remain shared-host
scenario measurements rather than a before/after speedup.
