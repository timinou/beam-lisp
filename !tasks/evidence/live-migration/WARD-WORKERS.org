#+TITLE: Fatal test worker containment
#+DATE: 2026-10-10
#+STATE: VALIDATED IN DEFAULT ISOLATED NATIVE MODE

* Failure and correction
Foundry restart validation exposed a general runner defect: an initializer's
linked OTP failure can kill the test worker before it sends its result. Ward
previously spawned an unmonitored worker and waited only for a result message,
so a dead worker appeared hung until the default 300-second deadline.

Ward now starts a native owned, monitored worker, preserving environment and
executable ownership. It matches results by exact worker PID and termination by
exact monitor/PID. Fatal termination returns an incoherent =worker-exit= report
with the printable reason immediately. Foreign result and DOWN messages cannot
be mistaken for this file. Successful reports remove their monitor. Timeout
kills and awaits the exact worker, then flushes only its own late result.

The caller owns the isolated file scope and destroys it in finally, even when
an uncatchable kill bypasses the worker's cleanup. Its deadline is captured
before spawning, so a test changing BL_TEST_TIMEOUT cannot change its own bound.
This fixes validation reliability; it makes no page-load speedup claim.

* Targeted validation

healthy file execution, destroyed-scope capability refusal, foreign result/DOWN
isolation and completed worker termination before returning a timeout.
=ward_isolation_test.bl= and =ward_diag_test.bl= guard existing clean-mailbox and
contamination-observer behavior. They run in one capped native batch with the
Foundry host/review/online and Nix/render checks.

* Follow-up outside this patch
=ward/run= and =ward/run-sandboxed= currently create warm-base forks without an
explicit end-of-summary destroy. Their lifetime cleanup deserves a separate
bounded improvement; this patch owns the per-file worker scope boundary.
