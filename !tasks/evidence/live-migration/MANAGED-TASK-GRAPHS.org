#+TITLE: Complete code ownership for core tasks
#+DATE: 2026-10-12
#+STATE: Focused native validation passed; immutable SDK acceptance pending

* Problem and implementation
Core =spawn=, =spawn-link=, =spawn-monitor= and =future= already use the native
owned-start handshake: retain before creating the process, transfer to the actual
child before publishing execution, and release on normal completion, cancellation
or owner death. They are not raw Erlang producers.

The previous lease included only the thunk's physical module, the native wrapper
and explicit extra modules. A thunk could call another sealed application module
which was neither currently executing nor retained. That dependency could be
retired while the child waited, despite the callable thunk still existing.

Both =BeamLisp.Refs/spawn_owned= and =future_exec= now retain the entire current
managed generation graph automatically. Ordinary tasks keep their existing
explicit dependency semantics. There is no new developer annotation, API/export
or compiler-key change. The official native host floor must be regenerated before
using these source changes, and a new immutable SDK must be built for consumers.

* Regression design
=test/bl/reload/managed_spawn_test.bl= creates a real two-module sealed graph.
The spawned task waits in the entry module while its dependency has never run.
After the request lease ends, direct dependency retirement and graph retirement
must both refuse. Releasing the child must execute the old dependency correctly
and allow retirement. The same case covers futures; cancellation must release
all graph modules. Existing =async_code_ownership_test.bl= remains required for
transfer, submitter death, cancellation, capacity and failed-start semantics.

* Limits
A complete code lease prevents executable use-after-retirement. It does not
change an actor's state, stop perpetual pollers, migrate provider attempts or
provide shutdown authority. Those require explicit versioned evolution/drain.

* Native validation
The officially regenerated floor changed only Refs.beam and its manifest.
Generation took 50.357 s, peak 249.6 MiB; verified installation took 5.500 s,
peak 207.5 MiB, no swap. All eighteen managed task assertions passed with this
floor. The separate native foundation batch passed the existing forty-nine
async-ownership assertions, plus generation132, factory30, static-integration17
and host-freshness25. A later mixed product batch passed this file but exposed
unrelated product fixture/parser errors; that batch is not reported as green.
The source compiler key stays unchanged because no code-generation ABI changed.
A new immutable SDK and consumer acceptance are required separately.
