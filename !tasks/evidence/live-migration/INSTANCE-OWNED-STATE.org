#+TITLE: Instance-owned state, tables and delayed callbacks
#+DATE: 2026-10-12

* Implementation
reload.state/cell! centralizes first-use Atom creation for ordinary execution.
Managed execution returns only an initializer-declared Atom; a missing resource
refuses and never uses a VM-global fallback.

proc.instance scopes locks/registry identities by application instance. Registered
names are OTP global term references, avoiding dynamic per-instance atoms; source
generation digest is excluded so a publication cannot create a second owner.
Registration does not grant lifecycle authority or migrate actor callbacks.

proc.table/hold-owned! creates unnamed ETS under an explicit live local initializer
owner and stores its handle in the caller's declared Atom. Short-lived callers
and dispatcher deaths cannot remove the table. Lost tables/dead owners refuse;
accepted work cannot disappear behind automatic recreation of an empty table.
This is in-memory lifetime protection, not node-restart durability.

proc.callback/register! automatically retains all modules of the current managed
graph, in addition to callable arms and explicit extra modules. A callback's own
physical module alone does not protect its transitive dependencies. Ordinary
callbacks retain their existing explicit dependency contract. Unregistration
stops new invocations while accepted executions retain independent leases.

* Validation
Source checkout, one capped VM, 6 GiB limit, zero swap. Focused rerun:
- reload/state_test: 16 assertions.
- proc/instance_test: 12 assertions, two applications and stable same-app names
  across different prepared generations, conflict preservation and dead-owner miss.
- proc/owned_table_test: 14 assertions, caller lifetime, separate cells, explicit
  lost lifetime refusal, forbidden global/heir overrides, 12 concurrent first users.
- proc/managed_callback_test: 5 assertions. A nonexecuting transitive dependency
  cannot retire while registered; old callback still executes; unregister cancels
  further calls and permits graph retirement.
- Existing async_code_ownership_test: 49 assertions.

The combined run also passed generation132, initializer factories29, application
context21 and resume14. The independently new scoped-session fixture still had
failures at this checkpoint; it is not included in the accepted result above.
Whole-run duration about56.4s, peak725MiB. These are correctness/lifetime proofs,
not production latency measurements or full Knowledger online acceptance.
