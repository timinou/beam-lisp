#+TITLE: Fjall same-process reopen waits for completed retirement
#+DATE: 2026-10-10

* Failure and invariant
A final Arc loses its strong count before its value destructor finishes. Fjall's engine destructor can still be joining background threads and syncing its journal while the StoreClaim weak reference is already dead. The old registry pruned that weak entry, then a same-process reopen attempted a second flock and incorrectly reported another OS owner.

The registry now distinguishes live, retiring and absent claims. A final StoreClaim field signals a condition-variable latch after its engine and directory flock have both dropped. Registry entries retain the same latch without retaining the engine. Reopen waits only for its own retiring path, outside the registry mutex, then retries normal claim selection. Genuine ownership by another OS process still refuses; no sleeps, forced GC, time-based guessing or lock bypass exists.

* Validation
- Rust native suite: 6 tests passed, including deterministic blocked destructor regression. The test blocks engine destruction after its last Arc dies, invokes the same generic registry lookup used by production, proves it selects retirement instead of absence, then verifies reopen's real flock succeeds only after destructor release.
- Existing release-order test still proves engine teardown runs while the flock is held.
- Existing registry pruning test still proves completed dead claims do not accumulate.
- Native lifecycle/source validation with rebuilt NIF is pending at this commit; exact packaged SDK acceptance must use the rebuilt artifact.
