#+title: Explicit worker and test execution scopes
* Accepted 2026-10-08
Env.capture/bind carries the explicit diagnostics scope with environment,
project and command overlays. Missing/nil fields clear stale worker context;
arbitrary process dictionary data is not conveyed. Refs spawn/future no longer
maintain a second, partial conveyance implementation. Caps remain registry-derived.
TestRT.declarations brackets suite source loading with a process-local marker.
Inline run-tests trailers return zero totals during declaration; Ward/native
shared/native async runners then execute once. Standalone evaluation executes
its trailer normally. Nesting/errors restore the previous marker. Top-level
smoke forms remain executable. No per-file edits or app annotations required.

* Benefits and limits
A fixture with an inline trailer has one execution instead of two during suite
loading, including expensive compiler probes and stateful fixtures. This is
measured by executable side-effect counts, not a claimed 2x whole-suite speedup.
Diagnostics transport covers all Env-token workers, with automatic stale-scope
clearing. No browser latency or shared warm-runtime enablement is claimed.
