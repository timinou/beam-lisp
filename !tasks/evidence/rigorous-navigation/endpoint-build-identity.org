* Failure and method
vm.net bound its socket using the caller's paths/build-id, then serve-conn
reread build-id in a spawned connection process. Process-local OS overlays do
not automatically exist in raw spawn_monitor workers. The endpoint and worker
therefore disagreed about their own build. The ordinary vm.client handshake
includes :build and was rejected; older fixture requests omitted it and worked.
This explains control-client failures without blaming socket permissions.

The bind operation now captures paths-map :build and passes that immutable value
through accept-loop and serve-conn. Ready and restart_required use the same bound
identity. Changing an ambient environment cannot relabel an existing endpoint.
No extra namespace lookup, app declaration or per-connection environment copy is
required. Token/tree checks are preserved. This is not proof of loaded bytecode
identity or permission to enable shared warming by default.
