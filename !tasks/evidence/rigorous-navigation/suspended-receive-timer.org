#+TITLE: Contended lock waits under suspension: runtime isolation and mailbox retry
#+DATE: 2026-10-08

* Problem and scope
A forced paused-reader integration test intermittently remained in
Process.sleep(1) after erlang.resume_process, despite publication finishing and
the requested scope lock row being absent. Actual lock-entry tracing confirmed
the correct key; reductions remained 498 across a later 100 ms observation.
This did not establish an ordinary navigation failure. The forced suspension
exposed a runtime interaction that must not invalidate the publication test.

* Isolation
research/navigation-next/suspended-receive-timer-probe.exs uses only OTP/Elixir,
no Beam Lisp application, ETS locks, provider modules or compiler. It observes a
waiting child, suspends it, waits 3 ms, resumes and waits 100 ms for completion.
Every child is killed in finally. Run with a single capped VM and home TMPDIR.
The probe reports its OTP and Elixir versions. Current host: OTP 29, Elixir 1.20.2.
Results are finite experiments, not a claim about every OTP release or schedule.

Workspace suspended-sleep-probe-r4.log:
- dynamic Process.sleep(1) stalled at cycle 6;
- constant receive-after 1 stalled at cycle 71;
- an unrelated mailbox wakeup failed to recover either within another 100 ms;
- a uniquely tagged start_timer mailbox event completed all 500 cycles.
Earlier independent runs also reproduced both timeout forms. Retain negatives.

* Chosen integration
Env.wait_for_local_lock_retry starts a 1 ms timer and selectively receives only
its exact reference with the private retry tag. No receive-after timer is used.
Uncontended acquisition retains the same ETS insert_new path and allocates no
timer or message. Contention adds a timer event; no reduction in contention cost
is claimed. Dead-owner recovery still deletes only the exact observed ticket.
Timer messages target the waiting process; process death prevents retention of
an orphan mailbox. Other caller messages must remain untouched.

The publication regression repeats whole-table, selected-entry and count reads
10 times each, verifies the captured lock key/owner, and publishes while the
reader is suspended with its namespace lock held. Success requires each reader
to return the old metadata after resumption. A focused check preserves a foreign
retry-tagged timer event. Source seed/gate acceptance is pending at this writing.
This does not grant cancellation, executed-code purity or code-version leases.

* Runtime documentation boundary
OTP documents receive-after timer suspension since OTP 28 and PID-targeted BIF
timer suspension since OTP 29:
[[https://www.erlang.org/doc/apps/erts/erlang.html#suspend_process/2][erlang:suspend_process/2]].
Thus start_timer is not claimed immune to suspension by specification. The chosen
path avoids the particular receive-timeout stall observed here; its 500-cycle
probe and repeated actual-lock tests are finite validation. No OTP source patch
or global suspension policy is included. Debugger suspension is outside ordinary
application execution and cannot authorize cancellation or forceful teardown.
