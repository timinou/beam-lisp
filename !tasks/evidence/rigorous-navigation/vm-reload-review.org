* Per-request context and capture ownership
The sequencer conveys each submitting caller's registered Env scopes. Env restores
its previous worker scopes after execution. Capture owns one StringIO process;
finally restores the group leader and closes that process on success or failure.
No application wrapper or additional developer annotations are required.

Regression: exec_context_test.bl produced four context assertion failures before
conveyance. The first cleanup fixture had an asynchronous owner-stop race; it now
uses synchronous GenServer.stop. The corrected focused gate passes 19 assertions
across exec_context_test, exec_start_test and env_convey_scope_test. It checks two
successive caller identities, actual StringIO process death, output and group
leader restoration after success and exception. This is correctness/resource
work, not a measured navigation wall-time improvement.

* Sequencer-owned admission and nonblocking progress
Progress has a dedicated native server and a protected ETS snapshot. Observation
creates no tables. Admission records a ticket and forwards the original GenServer
reply address to the sequencer without waiting for its work. Only the sequencer
retires accepted work; caller death preserves accepted effects. Owner death clears
tickets and replies to waiting clients. A FIFO tracks the oldest outstanding
submission with amortized constant-time queue operations rather than sorting all
pending entries. Nested self-submission refuses rather than deadlocking.

The focused gate vm-reload-reviewed-gate.log passes 107 assertions across five
files: queue/lifecycle 14, context/resources 9, startup 3, logic protocol 4 and
reload reconciliation 77. Actual runtime barriers exercise 32 waiting callers,
caller kill, sequencer kill, client wakeup, restart and nonblocking status. These
are finite concrete scenarios, not a proof of all BEAM schedules.

* Logic review: subscription preservation
Veritas finds and shrinks the old snapshot-reset pruning protocol to
snapshot -> subscribe -> prune. Its replay loses the new subscriber. Removing
only observed dead members from the current set is witnessed across 250 seeded
histories; that sampling is not exhaustive proof. Z3 independently checks the
nonnegative queue conservation equation under explicit admission/retirement
premises. Neither model establishes arbitrary effect purity or permits cancellation.

* Watcher integration
The compiled watcher now calls reload/apply-change, which stages and optionally
commits in one sequencer turn. It explicitly rebinds the submitting reload target
inside that turn. Original exception class/value/stack are transported as data
through the sequencer and re-raised at the boundary; generic guarded execution
must not silently change the watcher's error contract.

reload-handoff-gate.log: 270 assertions (handoff 5, reconcile 77, progress 14,
compiled watcher differential/filesystem corpus 174). A further actual compiled
watcher probe uses a blocked sequencer and verifies no staging before release,
publication into the explicit target and the malformed-source error tuple.
reload-watcher-actual-failure-final.log: 8 assertions pass. Ward already binds a
reload target, so the restoration assertion compares the previous binding rather
than incorrectly assuming :global. The initial incorrect fixture expectation is
retained in the workspace failure log.

This closes the default watcher handoff gap; it does not serialize every manual
stage/commit API user or provide multi-definition runtime rollback. The source
comments now state that bundle coherence precedes per-definition publication.
Official host seed regeneration and packaged acceptance are separate gates.

* Index worker request scopes
