#+TITLE: Framework navigation phase measurements
#+DATE: 2026-10-08
#+STATE: ACTIVE

* Measurement contract
The live framework emits opt-in live.phase/completed records for guarded-world
resolution, screen invocation, socket view invocation, lazy realization, diff,
style shipping, SSR HTML and WebSocket serialization. Costs are microseconds and
reductions in the executing process. Durations are inclusive: view contains
worlds/screen, and lazy screen work can occur later during realization. Never
sum nested phases as independent costs. Worker work is not attributed to the
calling process's reductions. Loader/compile/query-worker attribution remains
pending; a long view alone does not prove compilation is the cause.

The schema admits eight fixed phase labels and numeric costs, with existing
bounded execution identifiers. It carries no routes, query text, principal data
or rendered contents. Disabled execution checks diagnostics enablement and runs
the body directly, without timing closures, IDs, clocks or reduction samples.
Sinks remain opt-in. There is no retained event buffer in the framework.

* Validation
live-phase-gate.log passes 194 assertions across measure (14), actual socket
(118), actual SSR style (20), HTTP around (5), diagnostics (37). Measure tests
check exactly-once bodies, unchanged return/exception behavior, no disabled
emission and enabled numeric/schema fields. Existing live gates establish patch,
CSS and HTTP behavior parity; they do not establish production overhead or speed.

* App integration
The isolated browser-validation-serve fixture enables the sink only when
KNOWLEDGER_PERF_PHASES=1. Its output is capped at 4096 phase records and its count
saturates. This fixture starts no background sync/provider workers. Source-gate
validation and packaged acceptance must remain explicitly separate.
