* Why namespace-only detachment was insufficient
A cached compilation unit can contain multiple physical providers. A lazy table
in any scope can still point at a provider that another scope reloads. Detaching
only the requested namespace or enumerating existing references without locking
new registrations leaves schedules that read new code as old metadata. The
Veritas protocol model refutes both partial detachment and unlocked attachment.
These are lifetime counterexamples, not proofs of native execution purity.

* Chosen mechanism
All normal generated native publication enters Env.publish_binaries!, including
Link bodies/shims, AOT emission and cached replay. A complete prepared batch
acquires sorted unique physical module locks. It freezes every matching old lazy
literal provider reference, one scope at a time, before loading replacement code
under the current scope's retirement fence. Lazy pointer registration shares the
same module lock; a missing provider becomes an owned empty snapshot. Initializers,
compilation and file reads remain outside the short scope fence.

Lock order is namespace (if already owned), then sorted physical modules, then
one scope at a time. Detachment must not acquire namespace locks. Readers that
captured a lazy root before waiting re-read the actual root inside its owner scope
fence, so the old literal has become an immutable table when they resume.
Uncontended local locks retain ETS insert_new/exact-ticket deletion. Dead owners
are reclaimed by deleting the exact observed row, preventing stale-key deletion.
Only contention allocates a uniquely matched timer event; see
[[file:suspended-receive-timer.org][the runtime isolation receipt]].

Cache replay now prepares every {beam, original filename} pair before admission.
Its internal API takes namespace plus modules/directory arguments (arity4).
Retired replay raises before user initialization. The application probe adapter
supports both arity3 (old packaged SDK) and arity4 (new source).

* What was validated
Single and multi-namespace cache units preserve old scope metadata. Missing
providers do not become future lazy aliases. Whole-table, selected-entry and
count readers each pass10 forced suspended schedules; tracing verifies the exact
scope key/reader owner, publication completes while the reader owns its namespace
lock, and resumption returns old metadata. Killing a real pointer writer while it
owns the module lock does not strand later publication. Foreign timer events
remain in the caller mailbox. Existing lifetime, generation, incremental metadata,
namespace, Link, emitter, cache, closure and host probes all pass in the same VM.

* Negative evidence and limits
Earlier namespace-only integration failed multi-unit preservation; earlier
Process.sleep-based waiting intermittently stalled paused readers. Independent
OTP/Elixir probes isolate the timer interaction; constant receive-after also
stalls, whereas the tested tagged timer message completed500 cycles. A first new
seed attempt rejected an interop spelling in a guard before seed publication;
the corrected Beam Lisp == guard compiled and the full gates above passed.
Workspace physical-provider-reader-*.log and physical-provider-mailbox-seed.log
retain those negatives. Do not aggregate failed invocations into a green run.

No ordinary page-load latency reduction is established here. The unchanged
uncontended ETS mechanism has separate earlier finite microbenchmarks; contention
cost is not claimed lower. These locks are node local and make no FIFO guarantee.
Error or death during a multi-module native load does not roll back modules
already loaded. Raw host interop/on_load is outside this generated-code boundary.
There are no executed-graph leases, cancellation authority, AOT realm isolation
or default warming changes. Those remain later plan stages.
