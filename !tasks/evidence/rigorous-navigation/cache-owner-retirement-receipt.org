#+title: Native connection owner retirement
* Accepted 2026-10-08
Production connection release drains the writer, removes ownership entries,
then collects only the connection and (when present) guard registry heaps.
An idle Agent otherwise retains its previous resource-bearing state/callback
as garbage even though its live state no longer refers to the database.
No GC is introduced in query or transaction paths. Caller-held db values
continue to own their native handles by design.
* Evidence
cache-lifetime-phases.log: bare/identity release; connect/transaction/corpus
retain the external OS lock. cache-lifetime-registry-gc.log: all five release
when the two idle owner heaps are collected.
cache-owner-retirement-final-gate.log: 3 files,54 assertions,exit0:
negative raw ETS root4, production derived-cache ownership23, lifetimes27.
External Python directory flock uses distinct blocked exit73; unexpected
probe errors fail. Control holds an actual raw Store in parent-owned ETS;
positive releases while parent-owned caches survive and reopens durable data.
* Correction and limits
The previous same-VM reopen assertion was insufficient: Fjall shares weak
claims inside one OS process. Resource-neutral cache keys are valid, but did
not alone establish physical release. This receipt supersedes that claim.
No release-latency percentile or global registry-size scaling is measured.
No arbitrary global GC, native vector reclamation or crash/powerloss guarantee.
The first retirement run had a reader error; preserved as evidence, not green.
