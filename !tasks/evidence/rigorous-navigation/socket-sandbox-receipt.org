#+title: Socket validation remains unavailable in this sandbox
* Observed failure
The newly merged real app :around socket fixture stalls after reaching listener
startup, before client connect. Source confirms live.app/serve should return;
there is no evidence that the API intentionally blocks. Own stalled VMs were
interrupted/reaped with exit130. Failed experiments are preserved in socket logs.
A direct Python socket.socket().bind(('127.0.0.1',0)) returned PermissionError,
errno1 Operation not permitted. The Rust Unix-socket test also returned EPERM.
Thus actual listener/browser validation is unavailable under current permissions.
This does not establish the exact cause of Bandit's stall or a product failure.
* Fixture experiments
A prototype attempted to own the actual Bandit PID and shared Conn for cleanup.
First versions used unsupported with-redefs and unqualified self; both were
corrected. The final link-difference version reached listener startup and stalled.
It is not accepted or committed as a product fix: original upstream fixture is
restored byte-for-byte, preserving the other author's test. Logs remain evidence.
Stack diagnostics sanitize argument-bearing frames into arities. Early output
filtered too much; broader output was truncated by IO.inspect's default limit.
No passing socket evidence or browser timing is claimed.
* Required next validation
On a socket-capable runner, start on an OS-assigned port, own/stop the listener
and shared Conn, assert :around executes exactly once and status/body survive.
Diagnose listener startup with untruncated safe stacks. Separately pin test-worker
bounds and verify timeout/caller-death drain. Port collision/ignored listener
errors in live.app/serve warrant an independent lifecycle fix and packaged gate.
