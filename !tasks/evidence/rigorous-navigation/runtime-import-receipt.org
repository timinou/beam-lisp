#+title: Sealed runtime import and ordinary source-pin selection
* Accepted importer change
Importing a verified sealed file now publishes its BUILD_INFO source-key in the
normal source index. A clean commit pin can reuse the already extracted build,
without a second 360-source SDK/native build or application-specific override.
Only canonical 40-digit lowercase commits and optional 12-digit dirty suffixes
are indexed; metadata commit must agree. Dirty imports cannot satisfy clean pins.
Unversioned imported files remain usable by build ID. No global default changed.

* Limits
No deployment or shared-main promotion. No measured browser/navigation gain.
Import hashes archives during extraction; subsequent selection retains existing
store trust semantics. This does not introduce cryptographic authenticity,
harden existing short build IDs, or repair pre-existing payload tampering.
