#+TITLE: Bundled Erlang default boot: child tooling without application workarounds
#+DATE: 2026-10-08

* Defect and implementation
SDK35d1e3e3 passed30 of32 packaged files; two raw-Elixir-child fixtures failed
before application code because host Elixir finds bundled erl on PATH, and that
erl expects root/bin/start.boot. The release assembled only explicit named boots.
Preserve the first packaged failures in Knowledger's native-provider receipt.

release.write-default-boot! derives bin/start.script from the same start_clean
app set, substituting built-in ROOT/lib for the launcher's RELEASE_LIB variable,
then uses systools.script2boot. Assembly refuses a failed default-boot generation.
Explicit eval/start launchers retain their existing named boots and variables.
Default bundled Erlang carries application paths without starting the application;
no app developer changes, child environment scrubbing or test skips are needed.

* Source validation
release.test passes457 assertions in default-boot-source-release.log. The new
fixture checks direct bundled erl exit/status, available Env code, unstarted
beam_lisp, and then repeats the actual boot after renaming the temporary release.
The temporary tree is restored in finally, under the home TMPDIR.
