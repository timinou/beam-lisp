#+title: Listener ownership and retirement acceptance
#+date: 2026-10-08

* Actual counterexamples and fixes
Killing the accept loop left its caller-owned listening port open: liveness
probing still succeeded and replacement binding was refused (four failures).
The acceptor now acquires the listening port through the checked handoff; its
exit closes the port. A short-lived starter can exit without closing a listener.
Metadata publication now precedes acceptance; failed rename raises, closes the
bound socket, removes its pathname and cleans the temporary metadata file.

Retiring an old handle after replacement removed the new socket/token/metadata
(three failures). Each binding now records an OS-pid/ref generation. Retirement
closes its own port, then checks that generation under the binding lock before
unlinking files. Legacy handles without evidence close only their own port.

* Accepted source checks
Listener ownership file: 14 assertions passed, including dead acceptor recovery,
short-lived starter, metadata-rename failure and old-handle retirement.
Together with handoff 17, startup 18 and endpoint identity 6, the final combined
invocation passed 55 assertions across four files. Runtime source is unchanged
since that invocation. Earlier starter fixture errors were incorrect use of
Env.convey's documented unary host ABI; corrected tests use a unary callback.
The original counterexample logs and final combined result are retained.
Together with prior preboot/model/isolation gates, eight distinct source files
have 324 accepted assertions. This is not packaged/browser adoption evidence.

* Exploratory probe and remaining admission assumptions
A requested backlog of 1 with 132 held connections did not reproduce a failed
liveness probe on this host: all 132 connects succeeded. The exploratory code
and log are separate from production regressions; do not claim saturation or a
measured production timeout from them.
Source review still finds two admission assumptions needing their own batch:
probe errors currently conflate definite refusal with uncertainty, and the
cross-OS startup file lock recovers by age. A rigorous follow-up should use a
three-valued probe and an OS-lifetime advisory lease, tested with independent
processes and killed BEAM actors. Do not claim generation fencing solves an
unbounded suspension or forcibly stolen start-lock critical section.

The early SDK build was deliberately stopped before export so these fixes can
share one packaged acceptance cycle. Its zero exit on SIGTERM is not build
acceptance; completion requires an actual sealed export and its validation.
