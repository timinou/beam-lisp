* Change
datom.migrate derives uniqueness, cardinality-one and value-type checks from
:migration/grows using datom.schema's existing semantics. Authors no longer
repeat those declarations as :migration/checks. Explicit domain checks remain.
Shared constraints over an attribute use one query result in each preview.
Duplicate explicit/derived checks are deduplicated. Invalid schema declarations
refuse before remediation/partial writes. Writer-bound apply! and final step!
reuse the same derived checks; incomplete backfills do not stamp completion.

Changed composite tuple derivation is deliberately refused pending a complete
prospective-schema preview. An empty new tuple attribute is not evidence that
its derived values will satisfy uniqueness. No arbitrary duplicate is deleted.
Checks remain proportional to affected attribute data; this does not establish
a bounded large-data final writer turn or full online schema planning.
