* Implementation
Env owns two tables: an application-partitioned ordered membership index and
per-application revision/count/close receipts. A source-defined collector starts
as the third runtime supervisor child after language initialization. Native
server/supervisor start and existing evolve/shared-queue initialization register
automatically from their captured application context and retained code lease.

proc.inventory joins each role to existing native component evidence. No
unsupported calls are sent to arbitrary actors. A public participant carries
its PID, role, application, origin generation and precise capability; it omits
leases, callback closures and tickets. Receipts remain opaque VM observations.
An incomplete or duplicate paged receipt cannot pass complete-index recheck.

Collector restart preserves Env-owned rows, changes incarnation, recounts and
restores monitors. Native death invalidates observations immediately and cleanup
prunes exact source/evolve evidence; source graph leases are explicitly released
by their dead owner's exact ticket. Accepted workers retain independent leases.
Explicit close writes an Env-owned exact-ticket receipt first, so closing a role
survives collector failure even if its containing PID stays alive. Malformed
handles cannot create close receipts. No shared-variable-table sweep is added.
Queue stores, declarations and accepted work are preserved.
