* Design
Generate boolean admission functions directly from the canonical defserver
:defn-clause maps. Preserve each pattern and guard; replace the body with true
and add an unconditional false fallback. No source-string synthesis, duplicate
pattern interpreter, handler execution or handwritten accept predicate.
The same compilation includes proc.server contributions after expansion.

Expose only pattern/guard/source evidence in __bl_contract__/0. Bind observations
to the complete native module MD5, so even a body-only change invalidates an old
receipt. proc.contract/check rechecks identity before and after evaluation. This
detects changed code; it does not itself retain code or authorize publication.
The sealed generation and its existing native leases own lifetime separately.

Admission takes actual message, sender and state. A state guard false now does
not establish that the message is permanently malformed. Implicit OTP ignore/
crash defaults are not declared consumer clauses. A deliberate user catch-all
really accepts everything at this boundary. Handler-body requirements, reply
compatibility and state invariants remain unknown unless separately established.

* Validation design
- Concrete native patterns: tuple/vector alternatives, exact vector arity,
  required map keys with open-map semantics, field types, nil and numeric ranges.
- Verify helper calls have no handler effects; compare with real native callback
  execution over 100 reproducible Veritas histories (seed 1337).
- Check proc.server contributed callbacks and absent callback kinds.
- Change only a callback reply and require the old receipt to refuse.
- Native/JS guard grammar is tested separately through actual emitted Node code.

* Next authority gates
Do not turn this API into a proof of whole-program compatibility. Derive request,
reply and state relations from checked IR; preserve unknowns. A supplied SMT
model does not certify an unrelated runtime migration function. Bind proof and
execution to the same immutable compilation before using proof for publication.

The existing generation owner registry proves graph lifetime, not actor-state
evolution. Build on that physical registration and proc.evolve/transition; do not
add an application-maintained owner map. A generic native owner kernel must keep
standard call/cast/info/continue, initialization, shutdown, timeout and accepted
old-client semantics before ordinary servers can acquire transparent evolution.
Raw OTP delivery and old reply contracts must be covered explicitly. Multiple
actor transitions remain independently ordered FIFO turns, not one transaction.
