* Matched registration branch experiment
100 identical native actors per batch, four paired alternating batches. Both
paths retain the same one-module graph and use the same Env fork depth. The
control uses the existing unscoped app context, which skips registration; the
enabled case supplies an app ID. This isolates the registration branch, not
common bridge lookup, code leases, environment conveyance or total app startup.

| Packaged native-entry prototype |57.215|127.170|69.955|

Source versus SDK uses different CLI project environments; do not infer a runtime
speedup from that cross-environment comparison. Four batches are a small startup
probe, not a latency SLO. Actor state/resources and real product graphs require
their own acceptance. Ordinary message dispatch still adds no inventory check.

For the SDK fixture, 100 actors occupy about1.023MB aggregate process memory
before diagnostic GC in the unscoped case and2.718MB in the scoped case. The
sampled scoped process drops to5904–8920bytes after an explicit diagnostic GC;
the control sample is5752bytes. Source samples retain different project scopes
and therefore have larger dictionaries. The experiment implements NO forced GC
policy; idle heap allocation is not equivalent to permanently retained objects.
These counts exclude registry/ETS/monitor heaps outside the sampled actors.

* Artifact bug found and fixed
The full SDK built from47c38fa4 passes415source compilations,419primed source
records and packaging verification. Operational validation rejects it: packaged
CLI entered an AOT namespace whose shim could bootstrap Env before application
supervision. There was no runtime Supervisor or owner collector. Starting the
application later then failed with already_started Env.

provisioning fallback, native readiness, dispatch and exits. The compatibility
bl.cli/main also delegates the shared policy for already-started callers.
