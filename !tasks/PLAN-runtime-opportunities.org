** Next AOT batch: implementation boundaries confirmed by source inspection
=AOT.load_unit_in_snapshot= currently finds explicit defn names syntactically;
=AOT.unit_defs= then materializes =Env.ns_defs= and scans body-module identity
to include generated functions. =Env.selected_ns_definitions= already provides
coherent projection of a known name set. Therefore the proposed replacement is
a dynamically scoped compilation journal at successful definition publication,
capturing namespace/name pairs including macro-generated definitions. Nested
dependency loads must have independent journals and restore their caller's
journal in a finally block. Failed publications must not enter the journal.
The emitted artifact should project the union of explicit and recorded names.

Required negative controls: unrelated inherited definitions, two files sharing
a namespace, nested require, generated defn/multimethod/record helpers, repeated
definitions and failed compilation. Compare exported definitions, values and
initializer effects on cold compilation and artifact reload. Arbitrary
top-level effects are an unresolved packaging admission question; source
inspection alone does not establish their replay correctness. Do not admit
new packaging forms until those controls pass.

* Namespace-source authority and declaration scanning
The loader now resolves a source path using the same declared-namespace check
as source_content and source_hash. A project configuration named env.bl is
skipped when resolving the standard-library env namespace. Previously the
bytes could come from std/env.bl while provenance was calculated from the
configuration path, allowing a wrongly stamped artifact to circulate in cache.
Cache fetch/publication now checks namespace facade source/compiler attributes
without running code. A digest-valid stale entry is a miss, a correct publisher
can replace it, and a stale publisher cannot overwrite the repair. Build-log
freshness additionally requires the primary library facade's planned stamp.
Native/generic cache payloads keep their digest contract. Multi-namespace
entries conservatively miss if the one supplied closure key cannot justify all
facades. Source changes between separate resolution reads remain a follow-up.

The declaration scanner previously joined the entire remaining file for every
line, including comments and ordinary code. It now constructs that suffix only
for a possible namespace head. Same-VM pinned-host benchmark, ABBAABBA, four
samples per algorithm/case, 59,036 bytes with 1,000 comment lines before a late
namespace declaration:
| Case | Old median | New median | Speedup | Fewer reductions |
| Matching declaration | 28.5295 ms | 0.435 ms | 65.59x | 98.850% |
| Absent namespace | 35.102 ms | 0.422 ms | 83.18x | 98.851% |
All 16 results matched the expected answer. Both algorithms used identical host
emission; compilation was outside the samples. This measures late/absent ns
scanning, not whole startup or navigation; an early declaration need not speed
up. Correct path resolution adds source validation IO compared with the old
incorrect path-only lookup. Net application impact remains to be measured.
