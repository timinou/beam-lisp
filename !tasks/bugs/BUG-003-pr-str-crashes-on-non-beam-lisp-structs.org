* Symptom

=pr-str= on a value containing an Elixir struct that is not one of
beam-lisp's own types crashes:

#+begin_src clojure
(pr-str {:error (ex-info "boom" {})})
#+end_src

#+begin_example
** (Protocol.UndefinedError) protocol Enumerable not implemented for
   BeamLisp.ExInfo (a struct)
    lib/beam_lisp/rt.ex:1372: BeamLisp.RT.print_str_map/1
#+end_example

* Root cause — read from source

=rt.ex:1372= =print_str_map= enumerates the value with =Enum.map=.
Plain maps are Enumerable; structs are maps but are NOT Enumerable
unless the module derives it. beam-lisp's own types (Vector, LazySeq)
implement Enumerable, which is why the gap went unnoticed: every
struct the printer had ever met was one of ours.

Any error value crossing a process boundary hits this — e.g. a caught
=BeamLisp.ExInfo= sent as a message and printed on arrival. That is
the exact shape of a fence/failed-RPC result, so the printer crashes
precisely when you are trying to report a failure.

* Fix sketch

=print_str_map= (or the dispatch that reaches it) should print any
struct that is not a known beam-lisp type via =inspect= — or treat
=%{__struct__: mod}= as opaque data: =#mod{:field v …}=. Decide which
and test with a non-beam-lisp struct (ExInfo is a convenient fixture).

* Acceptance

- =(pr-str {:error (ex-info "boom" {})})= returns a string, does not raise.
- A struct from a plain Elixir module (e.g. =%URI{}=) prints without raising.
- beam-lisp's own types still print as before (regression guard).

* Resolution

=print_str=’s =%{__struct__: mod}= clause now routes a non-record struct to
=inspect= instead of =print_str_map=. One rule, no special case: a host struct
is opaque, =inspect= is honest about it, it is BOUNDED (a huge payload cannot
flood a log), and the clause directly above — the one for references — already
made that same choice for that same reason.

Two alternatives were considered and DECLINED, both recorded here because the
next reader will think of them:

- **print an exception as its message.** =(str e)= inside a catch handler is
the dominant use, and a message reads better there. But =ex-message= already
answers that question, and printing only the message drops the =ex-data= a
failure may carry. The division of labour — =str= shows the value, =ex-message=
shows the message — is worth more than the prettier one-line case.
- **keep the map rendering for structs that enumerate as key/value pairs**
  (a parsed JSON object prints as ={…}= today). No source in this repo produces
  such a value, so the branch would have been dead code preserving a behaviour
  nothing depends on.

Acceptance is pinned by =test/bl/print_test.bl= (8 tests, 30 assertions): the
error-in-a-map shape, a host struct alone and nested in a collection, =str= of a
caught error, every beam-lisp value shape, a record still printing as
=#ns/Name{…}= (the branch that must NOT be swallowed), and — added when this met
the same fix on =main= — a MapSet and a Date.Range, the two structs that are
Enumerable and therefore look printable.

Still open, deliberately: the printer remains HOST code, so the language cannot
extend it (a struct from a new library prints without touching Elixir, but a
beam-lisp rendering for one does not). Moving it into beam-lisp is
=FUP-063-move-the-call-table-and-the-printer-out=, with the route verified
(beam-lisp can already call =kernel/inspect= and intern vars).

* Merged with the same fix made independently on main

=main= had reached this clause on its own, with
=if Enumerable.impl_for(r), do: print_str_map(r), else: inspect(r)=. That closes
the reported case — an exception is not Enumerable — and leaves its sibling
open: a MapSet and a Date.Range ARE Enumerable and yield ELEMENTS, while
=print_str_map= destructures PAIRS, so the struct that looks most printable is
the one that crashes. Observed on that guard's own path before choosing:

#+begin_example
Enumerable.impl_for(%MapSet{})       = Enumerable.MapSet  -> routes to print_str_map
print_str_map CRASHES: FunctionClauseError
Enumerable.impl_for(%Date.Range{})   = Enumerable.Date.Range
Enumerable.impl_for(%RuntimeError{}) = nil
#+end_example

The merge keeps the total form, and the pair-shaped alternative declined above
is now doubly dead: pairs cannot be DETECTED without forcing the enumeration,
and forcing it would read a Stream — or a file.
