* Reproduced by the actual product inventory
knowledger.identity/resolve was rejected solely because its ordinary definition
name matched Core.resolve. Forward declare forms in agent.tools,kx and library
were counted as duplicate definitions. Removing these legitimate definitions or
exempting their namespaces would hide compiler/validator defects.

* Shared fix
Count only actual definitions as duplicate candidates. Treat declarations as
provisional namespace bindings and require a final checked definition before
publication. Prelink ordinary definitions and expanded definition groups, so a
forward application call never accidentally resolves an implicit Core binding.
Compare reflected SDK calls by exact compiler-resolved namespace/body-module
identity, including macro-emitted calls. An application function named resolve
is harmless; an actual Core.resolve remains refused before publication.
