* Symptom

    (into {} [[:a 1]])      => {:a 1}      ; vector entry, works
    (into {} '((:a 1)))     => CRASH       ; list entry
    (conj {}  '(:a 1))      => CRASH

    no function clause matching in BeamLisp.RT.conj/2

* Expected

Clojure accepts any two-element SEQUENTIAL as a map entry, not only a
vector:

    (into {} '((:a 1)))  =>  {:a 1}

This matters beyond literals: anything that produces seqs of pairs
(`partition 2`, `map` over pairs, a destructured seq) feeds `into {}`
naturally in Clojure and crashes here.

* Cause

`lib/beam_lisp/rt.ex` matches map-entry conj on the vector shape only:

    def conj(m, %BeamLisp.Vector{items: {k, v}}) when is_bl_map(m)
    def conj(%SortedMap{} = m, %BeamLisp.Vector{items: {k, v}})
    def conj(%{__struct__: mod} = m, %BeamLisp.Vector{items: {k, v}})

A two-element list falls through to the generic clause and raises.

* Fix

Accept a two-element list wherever a two-element vector entry is
accepted, for plain maps, sorted maps, and records. Reject a wrong-length
sequential with a CLEAR message rather than a FunctionClauseError \u2014
`(conj {} '(:a 1 2))` should say what it wanted.

* Tests

    (is (= {:a 1} (into {} '((:a 1)))))
    (is (= {:a 1} (conj {} '(:a 1))))
    (is (= {:a 1 :b 2} (into {} '((:a 1) (:b 2)))))
    (is (= {:a 1} (into (sorted-map) '((:a 1)))))   ; sorted too
    ; and a wrong-length entry fails with an actionable message
