#+title: Compiler eager traversal must delegate to logical Vector traversal
* DONE Representation audit after native JSON defect
CompilerData.eager_to_list decoded Vector.items via tuple_to_list directly.
Persistent vectors above 32 elements yield the five internal trie fields,
not the source elements. Eager compiler helpers can therefore visit wrong
arguments or return malformed transforms. Not claimed as measured warm-nav cost.
* Fix
Delegate finite vector enumeration to BeamLisp.Vector/to_list, which owns
representation changes. Lazy or malformed inputs retain the existing refusal.
* Validation
Regression checks sizes 32, 33, 65, 1025: every logical element visited once,
in source order, and transformed values correct. Existing compiler helper suite
included. Capped test triggers boot-tier rebuild and is still in progress.
* Related audit
Native datom_fjall's flat tuple helper only handles five-element datoms, so
persistent storage does not apply there. Runtime hash metadata normalization
also special-cases dense vectors; larger trie nested metadata deserves a separate
correctness audit before any metadata-sensitive value caching is generalized.

Installed-host test run reproduced arithmetic failure for a >32-element vector:
the pinned helper visits internal fields. Two unrelated source-generation
assertions also fail because the installed floor predates this source generation.
The installed test intentionally tests committed seed bytes, NOT host source;
restored its original test content and moved the new regression to a dedicated
fresh-source probe module via AOT/compile_host_file. No shared seed overwritten.
Source probe validation pending; release must publish a coherent rebuilt seed.

Fresh-source probe passed all 8 order/value assertions at 32/33/65/1025.
375.2 MB peak, no swap. Installed helper remains the old pinned seed until
a coherent release build/seed step; this commit does not claim deployment.
