#+TITLE: Generation initializer validation and execution could use different macro expansions
#+DATE: 2026-10-14
#+STATE: FIXED — native regression accepted in the 251-assertion source batch

* Defect
reload.generation evaluated a value definition by compiling its initializer for
purity analysis, then calling Compiler.eval_form on the original definition.
That compiled the initializer again. A trusted macro with changing expansion
could supply a safe callback during validation and execute File.write! during
actual initialization. Structural source validation could not bind these two
executions. This is an exact-code authority bug, not missing application checks.

* Fix
Compile the complete definition once, specialize literal native apply from its
actual expanded ANF, extract and validate the initializer from that exact compiled
registration, then execute that same IR through lower/eval-anf. Ordinary defn and
native owner descriptors use the same compilation path. Literal application data,
patterns and annotations remain data; only compiler-defined code carriers open.

* Regression
expanded_native_call_test.bl includes a macro returning a pure callback on its
first expansion and a file write on its second. Accepted code expands once,
returns :safe and never creates the HOME-local file. Other regressions compare
actual unmodified native execution and exception/effect traces, shadowed list
refusal, explicit native authority and quoted-data preservation.
