example used the API the way its name invites and broke immediately.

* Symptom

    (def c (connect [{:db/ident :p/n ...}]))
    (install-schema! c [{:db/ident :p/x :db/valueType :db.type/long}])
    (transact! c [[:db/add e :p/x 1]])
    ;; => transaction rejected by schema

| check                      | result |
|----------------------------+--------|
| original conn knows `:p/x` | false  |
| RETURNED conn knows `:p/x` | true   |

* Cause

`install-schema!` builds and returns a NEW `Conn` record:

    (defn install-schema! [conn defs]
      (->Conn (:store conn)
              (datom.schema/install-all (:schema conn) defs)
              (:basis conn)))

The trailing `!` promises mutation. The function is pure. Every caller
who follows the naming convention silently loses their schema, and the
error surfaces later at an unrelated `transact!` complaining about an
attribute the caller believes they installed.

* Why this is worse than an ordinary bug

The failure is DISPLACED. The call that is wrong succeeds silently; a
different call fails, with a message about schema validation that points
at the data rather than at the missing install. That is the failure mode
this project keeps finding and fixing elsewhere (stale headers,
`to-list` vs `seq` disagreement) \u2014 a component that quietly disagrees
with what its interface claims.

* Fix

Make it honest. The connection already holds mutable state (`:basis` is
an atom), so the schema can live in an atom too and `install-schema!`
can genuinely mutate, matching both its name and `transact!` beside it.

That also makes schema-as-datoms coherent: installing schema should be a
TRANSACTION (it writes datoms now), and a transaction mutates the
connection. A pure `install-schema!` cannot write datoms to the
connection's own store and have the caller see them.

Alternative considered and rejected: rename to `with-schema` and keep it
pure. That is defensible in isolation, but `transact!` next to it is
genuinely mutating, so a database whose two write paths have opposite
semantics is harder to hold than one that mutates consistently.

* Tests

    (let [c (connect [])]
      (install-schema! c [{:db/ident :p/x :db/valueType :db.type/long}])
      ;; the ORIGINAL connection, not a returned copy
      (is (some? (get (schema c) :p/x)))
      (is (some? (transact! c [{:db/id -1 :p/x 1}]))))

    ;; and the schema change is itself visible as data
    (is (seq (q '[:find ?a :where [?a :db/ident :p/x]] (db c))))
