* Symptom

`live.session.test / session-conn-dies-with-owner` fails in the full suite:
`(= pid (ets/info tbl :owner))` → `actual: :undefined`, preceded by
"undefined var: live.session.test/cart-schema" raised inside a spawned child
(BeamLisp.Env.fetch!/2).

* Root cause (evidence-backed, agent://0-SessionConn)

A latent defect in the TEST, not in the engine:

- test/bl/live/session_test.bl:63-89 spawns a RAW `erlang/spawn` child whose closure
  dereferences the top-level test var `cart-schema` (defined at :18).
- A bare top-level symbol lowers to a RUNTIME var deref: ANF `:global` node
  (priv/boot/anf.bl:27/64) → `BeamLisp.Env.fetch!(ns, name)` (priv/boot/lower.bl:225).
- Raw `:erlang.spawn` starts the child with an EMPTY process dictionary by design
  (lib/beam_lisp/refs.ex:287-308), so `Env.env_id/0` = `:global` and `Env.chain/0` =
  `[:global]` (env.ex:95/104). ward runs each test FILE in an isolated env fork, so
  `live.session.test/cart-schema` lives only in the fork and is invisible to the child.
- The child raises at fetch! (env.ex:1354-1357) before sending `[:tbl tbl]`; `tbl`
  stays nil in the parent and `(ets/info nil :owner)` = `:undefined`.

Provenance: PRE-EXISTING — the test file is byte-identical at f90293b (Sep 13 base),
at branch tip 70c03f0, and at merged HEAD; env.ex resolution semantics unchanged by
the merge. The repo already documents this limitation and works around it in
test/bl/system/mcp_conn_memo_test.bl:52,69 ("a spawned process resolves no test-file
var") and test/bl/live/socket_test.bl:324 (closes only over locals). session_test is
the sole violator.

* Fix (one token)

In session-conn-dies-with-owner, replace `erlang/spawn` with core's env-conveying
`spawn` (priv/boot/core.bl:271, BeamLisp.Refs.spawn_exec — captures + binds the env
token, plain/unlinked, so the [:die]/receive choreography is unchanged). Equivalent
alternative: pass the schema in as an argument to a top-level defn (the
mcp_conn_memo_test pattern).

* Lint opportunity

The static model already treats an un-conveyed spawn body as escalated to
:opaque-world/:global authority (priv/lib/system/core.bl:377-396). Consider a
ward/lint rule: `erlang/spawn` whose body references a top-level var of the current
(test) ns = named error. That would have caught this at write time.
