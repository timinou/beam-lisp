* Symptom
`bl self-build` of commit 1cf72d26 / d1d1cd18 never finishes. It prints the harness banner and serves:

    harness  http://127.0.0.1:42347/mcp
    config   /tmp/w4-wt/.local/harness/mcp.json  (url + bearer token for an MCP client)
    vm       none — cold; serving until interrupted

It was observed 2026-09-24 in a detached worktree of d1d1cd18, built by PLAN-144's builder: the beam.smp process was still serving after 15 minutes, until it was killed.

* Cause
`priv/lib/harness/serve.bl` (added in 1cf72d26) is `(ns harness.serve …) (hm/run)`: a top-level call. `priv/lib` is a compiled tier, so every build that compiles or loads that namespace starts the server and parks.

* State in the main checkout
The UNCOMMITTED working tree already moves the file to `priv/tasks/harness-serve.bl` (outside the compiled tiers) and points `env.bl :tasks :harness :run` at it. That move is the fix. Until it is committed, every automatic build of `main` (PLAN-144's hook and `latest`) hangs.

* Done when
- the move is committed;
- a lint/test rejects a top-level side-effecting call in a compiled tier (`priv/{boot,std,lib,compat,build}`), so this cannot recur;
- PLAN-144's builder deadline (`BL_BUILD_TIMEOUT_MIN`, default 45) is the backstop, not the fix.
