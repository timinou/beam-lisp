* What was observed

    $ rm -rf /tmp/bl-empty-cache
    $ XDG_CACHE_HOME=/tmp/bl-empty-cache ./bin/bl deps fetch
    … EXIT=0
    $ ls /tmp/bl-empty-cache/beam_lisp/lib | wc -l
    0
    $ ls ~/.cache/beam_lisp/lib | wc -l
    48

Redirecting `XDG_CACHE_HOME` empties the EBIN cache (the compiled-library address,
`~/.cache/beam_lisp/ebin/<name>-<vsn>-<sha8>-<runtime>`) and does NOT redirect the
STORE: `bl deps fetch` answered "everything is present" while the store under the
redirected root was empty, and it had in fact read the default
`~/.cache/beam_lisp/lib`. `priv/build/store.bl` documents its root as
`$XDG_CACHE_HOME/beam_lisp/lib` (line 29), so at least one caller resolves the
store root by a different spelling — the two disagree, and the one that is wrong
is whichever the fetcher uses.

Why it matters beyond tidiness: the store is where a lock's tarballs live, and its
whole design is "a machine that has the store needs no network". If `bl deps
fetch` consults a different root than `bl deps verify` and `bl deps compile`, then
"all present" can be answered about a store the build will not read — and a CI leg
with a cold cache would silently skip the fetch and fail at compile time instead,
with the wrong diagnosis.

* Acceptance

One function answers the store root and every caller asks it (fetch, verify,
compile, doctor, `bl deps list`), and the answer follows `XDG_CACHE_HOME`. A test
that redirects `XDG_CACHE_HOME` to an empty directory must see `bl deps fetch`
download the whole lock, `bl deps verify` report 48 present, and `bl deps
compile` build them — all in that redirected root.

* How it was found

Running CI's first step against an empty cache, which is the state a runner is in.
That exercise also found the real bug it was meant to find — `bl deps fetch`
could not run at all on a machine with no libraries, because the application's
`.app` names them and `ensure_all_started` was a hard stop (`{:error, {:x509,
{…"x509.app"}}}`). That one is FIXED (the provisioning verb boots the language
without the application); this item is the part of the same exercise that is not.
