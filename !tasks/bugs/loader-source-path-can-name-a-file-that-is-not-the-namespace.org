#+CUSTOM_ID: BUG-086-loader-source-path-does-not-apply-the-de

* Symptom

`BeamLisp.Loader.source_path/1` answers with a file that does NOT declare the
namespace, while the loader refuses to load from that file. Two functions, one
question, two answers:

```
BeamLisp.Loader/source_path "bus"     ; => .../examples/bus.bl
BeamLisp.Loader/source_content "bus"  ; => nil      (find_file skips it)
```

`examples/bus.bl` declares `(ns example.bus)`. It shares the FILE name `bus.bl`
with the namespace `bus`, and `source_relatives("bus")` is `["bus.bl", …]`, so
`source_path` — which only asks `File.regular?` — hands it back. `find_file`, the
function the LOADER actually uses, applies the extra rule and skips it:
`priv/std/loader`'s own comment says "a file serves `ns` only if it DECLARES
`ns`". `examples/fence.bl` is the same trap for `fence`.

* Why it matters

`source_path` is the answer to "which file did this namespace actually come
from", and its one in-tree consumer is the reload monitor
(`priv/std/reload.bl`, `source-row`), which prints the path per namespace and
judges drift against it. So a monitor can name a file that is not the namespace's
source, and the reader has no way to tell. It is also the natural first call for
anyone writing a test that pins a namespace's home (the guard test added for
FUP-097 had to use `source_content` instead).

* Fix direction

Make `source_path` apply the same rule `find_file` does — either by delegating
(the ns check is the same code) or by returning the resolved path from
`find_file` itself, which already returns `{:ok, path, content}`. Keep the
`nil`-when-absent contract so the drift-gate callers are unaffected.

* Evidence

Measured 2026-09-20 in this tree:

```
./bin/bl eval '(println (BeamLisp.Loader/source_path "bus") (BeamLisp.Loader/source_content "bus"))'
# => /home/user/.../examples/bus.bl   nil
```

- `lib/beam_lisp/loader.ex` — `source_path/1` (no `declares?` check),
  `find_file/1` (has it).
- `examples/bus.bl`, `examples/fence.bl` — the same-named decoys.
- `priv/std/reload.bl` — `source-row`, the consumer.
- `test/bl/proc_home_test.bl` — the test that worked around it, with the reason
  written in a comment.
