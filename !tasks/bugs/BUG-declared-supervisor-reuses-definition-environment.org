* Reproduction
Environment-scoped proc.instance names exposed an existing host-context bug.
server/4 captures the descriptor creator's Env for direct OTP/dynamic-supervisor
child specs. start_link/1 rebased declared tree children only when a managed
generation existed. An ordinary tree reused its definition environment: the
caller looked for an Env-scoped registry while the child registered elsewhere.

supervisor-boundary-before-floor.log reproduced wrong child Env,names absent in
the caller,and second-tree collision/worker exit against the actual installed
old host. Existing explicit creator-context tests passed10assertions.
Source-product-focused-08.log reproduced unavailable library registries after
the same naming fix. These failures are retained,not counted as acceptance.

* General fix
Declared start_link trees rebase every first-party child start to the starter's
Env token,including ordinary development/application environments and OTP
restarts. Managed trees still refuse raw child MFAs; ordinary raw MFA semantics
remain explicit. Direct server/4 specs handed to an existing DynamicSupervisor
continue to preserve their creator context. No application workaround or process
reassignment is used. The two API boundaries have distinct native regressions.
