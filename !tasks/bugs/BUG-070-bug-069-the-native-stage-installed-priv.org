* Symptom

`bl build`'s native stage reported every crate "built" and installed each cdylib
at `priv/native/<crate>` — with NO extension — while `BeamLisp.Native` asks
`erlang/load_nif` for `priv/native/<crate>.so` on every platform
(`priv/std/vm/native.bl`). So a tree that built its natives from scratch had six
crates and not one of them loadable.

Found by the release pipeline, on all four targets:

    ok   version → beam-lisp 2026.4.0
    ok   language → 3
    FAIL datom_fjall: expected 'true', got 'false'

while the build log immediately above said:

    beam-lisp native: code_embed built
    beam-lisp native: datom_datalog built
    beam-lisp native: datom_fjall built
    beam-lisp native: datom_vector built
    beam-lisp native: lazy_memo built
    beam-lisp native: wry_webview built

* Why it survived every machine that had one

The `.so` files are stale build outputs from before the naming, and
`priv/native/*` is gitignored — so a developer's tree keeps a set that answers
the loader's question, and nothing re-derives the name. On a fresh runner there
is no earlier set, and the failure is total and immediate.

The give-away is the single survivor: `lazy_memo` was the ONE crate that loaded,
and only because the pipeline's bootstrap step had installed it by hand at
`priv/native/lazy_memo.so` — the name the loader wants. That the hand-installed
one was the only one that worked IS the proof of the naming, and it went unread
for a full release attempt.

* Fix

`priv/build/build.bl` — `native-one`'s install path is `priv/native/<crate>.so`,
and the comment above the stage and `build-native`'s docstring are corrected:
they both said `priv/native/<crate>` (the obvious reading of "no `lib` prefix"),
which is how code and loader came apart.

* Verified

Reproduced exactly, and fixed, by putting `priv/native` into the runner's state
(`lazy_memo.so` alone) and running `bl build`:

    # BEFORE                       # AFTER
    priv/native/                   priv/native/
      lazy_memo.so                   code_embed.so
                                     datom_datalog.so
    datom.store-fjall/             datom_fjall.so
      available? → false           datom_vector.so
                                     lazy_memo.so
                                   datom.store-fjall/
                                     available? → true

Then end to end: a freshly built drop passes all eight checks `release.yml`'s
cold smoke test makes, from a directory with no beam-lisp sources in it —
`version`, `language`, `datom_fjall`, `explorer`, `lazy_memo`, `z3`, `mcp`,
`lsp serve`.

* Class

Every `.so` in `priv/native` on a developer machine is a lie about what the
current build produces, because the directory is ignored and never cleaned.
BUG-067 was the same shape on the `.beam` side: a build output that outlives its
producer and is never checked against it. The artifact gate must assert the
natives LOAD, not that the build said "built" — the release smoke test does, and
that is why this was found at all.
