#+CUSTOM_ID: BUG-087-an-implicit-alias-for-a-dotted-namespace

* Symptom

A require WITHOUT `:as` on a DOTTED namespace makes the short alias resolve to a
module named after the ALIAS, not after the namespace:

```clojure
(ns probe.alias
  (:require [proc.reg] [proc.server]))
(proc.server/defserver probe-reg (registry (keys :id)))
(def s (start probe-reg nil {:name :probe-reg}))
(reg/register s (erlang/self) {:id 1})
;; error: function :reg.register/3 is undefined (module :reg is not available)
```

The call compiles to `BeamLisp.Ns.Reg`, i.e. it treats the alias `reg` as a
namespace of its own. Two spellings that WORK, measured in the same tree, same
session:

```clojure
(:require [proc.reg :as rr])   (rr/register s ...)        ; => :ok
(:require [proc.reg])         (proc.reg/where s {:id 1})  ; => [#PID<…>]
```

So: an explicit `:as`, and a fully-qualified name, both resolve the target
namespace correctly; only the IMPLICIT alias is wrong.

* Why it hides, and why it just started to matter

With a FLAT namespace the alias equals the namespace, so the bug is invisible:
`(:require [reg])` + `reg/register` happens to compile to `BeamLisp.Ns.Reg`,
which is right. It only bites when the namespace is dotted AND the caller uses
the implicit short alias — exactly the shape the bundle tier now has
(`proc.reg`, `proc.bus`, …). The move of `flow`/`bus`/`reg`/`super`/`fence` under
`proc/` found it by making two live call sites dotted (`priv/std/vm/owner.bl`,
`priv/lib/live/app.bl`); both were fixed by spelling the alias
(`(:require [proc.reg :as reg])`).

* Blast radius

Any consumer that writes `(:require [proc.reg])` and then `reg/whereis` hits a
runtime undefined-function error naming a module that was never meant to exist.
The std's own `[proc.server]` requires are safe only because they always use the
FULL name (`proc.server/defserver`).

* Fix direction

Resolve the alias through its target namespace when the compiler interns the call
site's link — the alias is a local spelling, the namespace is the identity. The
relevant side is the reader/compiler (alias registration) and `BeamLisp.Link`
(module for a qualified symbol); both are `priv/boot/*` / `lib/beam_lisp/*.ex`,
which were OFF LIMITS to this session.
