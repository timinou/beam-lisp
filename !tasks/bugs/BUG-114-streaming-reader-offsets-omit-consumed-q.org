* Cause and constraints
priv/boot/reader.bl wrap-prefix deliberately preserves reader.ex's legacy line/column quirk by reading payload at pos0 rather than the position after the prefix. It also fails to advance the newly added absolute codepoint offset for consumed prefix characters. Offset is an independent source count and must advance even while preserving line/column parity. Ordinary quote, syntax-quote, unquote, deref consume one char; unquote-splicing consumes two; var quote has already advanced its position at the read-dispatch call site and must not be counted twice.

* Fix and tests
Advance absolute offset only for the consumed prefix width, keep AST outer start offset and legacy line/col untouched. Add permanent streaming read-next-string/read-next tests over every prefix, repeated forms after prefixes, comments and Unicode codepoints. Verify exact returned source slices, remaining stream and absolute offsets; preserve existing reader-position tests and compiled frontend/BEAM source differentials. One rebuild batches this reader fix with reviewed rt performance edits.
