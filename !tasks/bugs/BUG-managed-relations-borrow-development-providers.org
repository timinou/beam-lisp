* Counterexample
The consumer's synthetic declaration-ownership-probe prepares two graphs with
an explicitly trusted datom.query.relation boundary. Registering the candidate's
provider causes the old graph to return new rather than old. Native code leases
preserve the graph's code but cannot preserve a mutable global dispatch table.

* Implementation
A small reload.execution leaf preserves the existing native admission/lease/
nested-call behavior without depending on graph planning or datom. The existing
SDK defrelation macro emits a checked spec and a named provider when expanding
managed source. reload.declaration captures compiler-owned identities only in a
scope-bound preparation,collects values after actual initializer ANF validation,
and stores bounded metadata and logical named callback references in the graph.
The temporary preparation context is restored after both success and failure.

Managed relation reads resolve their exact graph and callbacks re-enter that
same graph with normal execution/retirement checks. Runtime registration refuses;
absent managed entries never borrow development providers. Fixed SDK analytic
builtins use immutable descriptors and named analytic functions;the legacy
registration adapter reads the same descriptor table. No SDK startup exception
allows arbitrary business namespace registration. Ordinary source/AOT DSL syntax
is preserved. Development Agent replacement remains its explicit legacy behavior.
