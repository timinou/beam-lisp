* Symptom

    (to-list #{1 2 3})
    ** (Protocol.UndefinedError) protocol Enumerable not implemented
       for BeamLisp.Set (a struct)

`to-list`'s own docstring promises it handles "vector, list, lazy seq,
set, or nil" \u2014 and its `(set? c)` branch calls `Enum/to_list`, which is
exactly what a set cannot do.

* Cause

`BeamLisp.Vector` implements `Enumerable` (vector.ex:222). `BeamLisp.Set`
does not, so every `Enum.*` call on a set raises. `seq` and `count` work
on a set because they are handled in `RT` directly; only the `Enum`
route is missing.

* Two fixes, both worth doing

1. `to-list`'s set branch should not go through `Enum` at all \u2014 the
   members are already a `MapSet`, so `MapSet.to_list/1` answers
   directly. Smallest correct change.

2. `BeamLisp.Set` should implement `Enumerable` regardless. Vectors do,
   and the asymmetry means any Elixir-side `Enum`/`Stream` call on a set
   fails: `Enum.map`, `Enum.into`, `Stream.filter`, and any interop a
   user writes. The moduledoc for Vector calls Enumerable "interop in
   both directions"; a set deserves the same.

* Tests

    (is (= 3 (count (to-list #{1 2 3}))))
    (is (= 3 (count (vec #{1 2 3}))))
    (is (= [1 2 3] (sort (to-list #{3 1 2}))))
    ; and from the Elixir side
    assert Enum.sort(Enum.to_list(set)) == [1, 2, 3]
    assert Enum.count(set) == 3
