* Symptom

`bl.install`'s `read-json` reports two very different failures as one:

```clojure
(defn- read-json [path]
  (if (File/regular? path)
    (try (Jason/decode! (File/read! path))
         (catch e {:unreadable (str e)}))
    {}))
```

A caller that gets `{:unreadable why}` is told, by `claude-register`, that the
file "does not parse as JSON — fix it, then re-run". But the same branch catches
a missing module, a permission error, and an `UndefinedFunctionError` — which is
exactly how BUG-065 hid for as long as it did: the JSON path was dead, and the
verb's own error message blamed the user's config file.

    $ ./bl-v2026.4 install mcp DIR     # before BUG-065's fix
    error: function Jason.encode!/1 is undefined …
    # …while a VALID .mcp.json was reported as "does not parse as JSON"

* Why it matters

The message is the only diagnostic a user gets, and it points at THEIR file. A
tool that says "your config is broken" when the tool is broken costs the user an
afternoon and costs the maintainer the bug report that would have found it.

* Fix (proposed)

Narrow the catch to what the parse can actually fail with — a JSON syntax error —
and let everything else propagate. `Jason.decode!` raises `Jason.DecodeError` for
malformed input; anything else (undef, `:enoent`, `:eacces`) is NOT a statement
about the document and must reach `run-argv`'s handler with its own message.

Acceptance: a `.mcp.json` that is not JSON still reports "does not parse as
JSON"; a failing `Jason` call reports the failure, not the user's file.

* Severity

Low now that BUG-065 is fixed (the failing-module case no longer occurs on that
path), which is why it is filed rather than fixed in the same change: the fix is
a narrowing of a rescue, and it wants the regression test above with it.
