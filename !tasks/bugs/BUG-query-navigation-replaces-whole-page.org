#+TITLE: Query navigation replaces the entire page rather than updating its state
#+STATE: DONE

* Cause
live.app route-boundary keys the entire page by the full target including
query parameters. Opening an inspector, changing page, sort, locale or basis
therefore removes/reinserts the whole page and chrome instead of patching the
changed descendants. Knowledger Activity's baseline patch is 906 KB / 10766
DOM nodes; replaying that on an inspector click amplifies CPU and wire work.

* Fix
Use URL PATH for component lifetime. Distinct pages/entities retain distinct
keys; query-only state changes reuse the page and the structural differ.
Full applied target is retained in data-live-route, separating identity from
state and making applied-route observation precise. Theme installation and
stylesheet shipping are unchanged. No downstream opt-in or configuration.

* Checks
New context regressions assert query-only changes emit only attrs/text,
round-trip to the exact new tree, and expose the full query target. Different
entity paths still emit remove/insert and round-trip correctly.
Capped checkout ./bin/bl: context21, app3, resume14, refusal42 = 80 assertions,
four files green;18.775s;233.1MB peak;no swap. Existing protected principal and
configuration state, resume lifecycle, refusal semantics remain covered.
New route attribute is understood by Knowledger's optional performance probe;
older runtimes still work with its full-target-key fallback.
