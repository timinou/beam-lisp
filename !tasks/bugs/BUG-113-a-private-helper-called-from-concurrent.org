** Cause (established, 2026-10-04)
BUG-112's forwarding shim keeps its state per env: ~{env :shim_state ns}~ (pending count), ~{env :fwd ns fname arity}~ (routes) and the def table. ~Link/settle~ walked EVERY env's ~:shim_state~ rows but rebuilt each shim from the CALLER's chain. So any env that finished a load (a test's own fork, a sibling) rebuilt another env's pending shim over an empty ~ns_defs~ and deleted that env's routes: the shim then exported nothing, and every def of that namespace, public or private, was ~undefined or private~. A test file loads its namespace in one env and its tests run while other forks finish loads.
Two further gaps in the same code: ~forward/3~ looked a route up only through the CALLER's chain, so a process with no env (a raw ~spawn~) or a sibling env could not reach a route another env wrote.
Reproduced deterministically (no timing): env A evaluates ~(defn a1) (defn a2) (defn- hidden)~ form by form; env B calls ~Link/settle~; ~hidden/0~ and ~a1/0~ are then undefined (before B settles, ~hidden~ already failed from a process in another env).

** Fix
priv/host/link.bl: ~settle/0~ settles only the calling env's rows; ~forward/3~ falls back to a route in any env. Gate: ~test/bl/link_test.bl a-def-behind-the-shim-survives-a-sibling-envs-settle~ (red 4 assertions before the fix, green after).
