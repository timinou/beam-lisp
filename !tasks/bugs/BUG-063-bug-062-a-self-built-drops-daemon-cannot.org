* Initial Message

vendor librarium so someone with just `bl` and this repo can run knowledger

** Symptom
A drop sealed from a CHECKOUT (`bin/bl self-build --bin <launcher> --out /tmp/bl-new`) boots and runs commands, but its DAEMON cannot start:

#+BEGIN_EXAMPLE
  $ BL_DAEMON=off /tmp/bl-new daemon start
  ** (EXIT from #PID<0.95.0>) an exception was raised:
      ** (UndefinedFunctionError) function ThousandIsland.start_link/1 is undefined
         (module ThousandIsland is not available)
          ... BeamLisp.Daemon.HTTP ... BeamLisp.Daemon.Server.serve_ui/2 <- start_ui/1 <- init/1
#+END_EXAMPLE

Measured 2026-09-16, beam-lisp tree at `db79585` + a self-build sealed from a copy
of it (139,971,782 payload bytes, "195 tier sources rebuilt"). `ThousandIsland` is
a Bandit dependency; the payload carries the library sources
(`~/.cache/beam_lisp/lib/bandit-…/lib/bandit.ex` appears in the trace) but the
dep's ebin is not on the sealed drop's code path, so the UI listener dies inside
`Server.init/1` and the daemon never binds — `bl daemon start` reports
"did not become ready", and `bl daemon status` says `:econnrefused`.

** Impact
- `bl self-build` (W6) is the documented way to rebuild a drop from a checkout;
  the result is unusable for anything warm. The fixpoint claim ("a generation
  builds the next with the compiler it was built by") holds for the compiler, not
  for the payload's code path.
- Anything that needs the daemon (dashboard, `bl watch`, the fast path) silently
  takes the COLD route instead, which is exactly the confusion class this
  codebase keeps paying for.

** Not a regression from PLAN-118
The same payload was sealed before and after that change, with and without the
launcher rebuilt; the daemon failure is identical. The daemon used for PLAN-118's
measurements was started from the SOURCE (`bin/bl daemon start`,
`BL_DAEMON_ROOT=…`) while the CLIENT was the sealed drop — i.e. the protocol was
exercised across the two.

** Likely shapes of the fix (one of)
1. The seal's payload should carry the deps' EBIN dirs the app's `.app` names
   (Bandit pulls ThousandIsland; the runner-up would be any other transitive dep).
2. Or `bin/bl` inside a drop should compute the same `-pa` list it computes in a
   checkout (see `bin/bl`'s CACHE/TAG block: it already resolves
   `~/.cache/beam_lisp/ebin/<name>-<vsn>-<tag>/ebin`, tagged by runtime — a drop
   built by another ERTS must not be given another runtime's beams).
3. Or the daemon should not hard-require the UI: `Server.init/1` starting the HTTP
   listener unconditionally turns a missing optional dep into "no daemon at all".
   (This is the smallest change and the best failure mode, independent of 1/2.)

** Acceptance
`bin/bl self-build --out /tmp/x` on a checkout, then `/tmp/x daemon start` in a
scratch tree → `daemon status` answers, and `FOO=bar /tmp/x eval …` shows the same
environment warm as cold. Re-seal twice and the second generation still works
(the fixpoint gate).
