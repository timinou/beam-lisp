           ** (EXIT) exited in: :sys.terminate(#PID<...>, :normal, :infinity)

The failure is in the `on_exit` TEARDOWN (allocation_test.exs:161), not
in the assertion. The test body passed; stopping the server afterwards
raced with something else shutting it down, so `GenServer.stop` exited
rather than returning.

* Isolated

`mix test test/beam_lisp/spell/allocation_test.exs` -> 7 passed.
Only fails under the full suite, and not on every run.

* Family

Same shape as BUG-006, which was fixed in this file's neighbourhood: a
globally-named GenServer whose lifecycle is managed by a test, where
another test (or the supervisor) can be shutting the same process down
concurrently. BUG-006 was about NAME registration being asynchronous;
this is about the stop itself racing a shutdown already in progress.

* Fix

Make the teardown tolerant of a process that is already going away:

    on_exit(fn ->
      try do
        GenServer.stop(pid, :normal, :infinity)
      catch
        :exit, _ -> :ok      # already stopping, or already gone
      end
    end)

`catch :exit` is the right tool: `GenServer.stop` on a dead or dying
process EXITS rather than returning an error tuple, so a `case` cannot
help. Note that BUG-006's fix already added a catch-`:exit` in one
teardown path in this file; this is a second path that did not get one.

Worth checking every `GenServer.stop` in `on_exit` across the test
suite at the same time, since the same race applies to each.

* Priority

Low. It is a test-harness defect, not a product one: the assertion under
test passed, and nothing about the allocation behaviour is in question.
But an intermittently red suite trains people to ignore red suites,
which is how real failures get missed.
