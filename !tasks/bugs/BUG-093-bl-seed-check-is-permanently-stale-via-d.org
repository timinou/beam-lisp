*Symptom.* After republishing the floor (843ab96f), `bl seed --check` reports:

#+begin_example
bl seed: the floor is STALE — 0 of 10 namespaces were built from other bytes
  cannot judge: data-readers — its beam carries no source hash
bl seed: fix with  bl build && bl seed
#+end_example

Zero namespaces *moved*, yet the verdict is STALE — driven entirely by the one
namespace the check "cannot judge".

*Root cause.* In =priv/build/seed.bl= the check aggregates
(around line 246):

: :ok? (and (empty? gone) (empty? unjudged))

`data-readers` carries a manifest key but **no source hash**, so its verdict is
permanently =:unjudged= (seed.bl:146-152, 177-178, 200). Because =:ok?= requires
=(empty? unjudged)=, the check can **never** return current while any namespace
is unjudged. `data-readers` (and `multi`, per the same comment) is structurally
unjudgeable, so `--check` is a permanent false-STALE.

*Impact.*
- `--check` cannot be used as the pre-commit gate it was built for — it always
  fails, so a hook using it would block every commit.
- The launcher (=bin/bl=) does NOT use =seed --check=; it gates on
  =AOT.beam_provenance/1= per boot namespace vs =current_compiler_key= (bin/bl:265-285),
  so **boot is unaffected** — this is a =seed --check= surface bug only. But a
  warm boot was observed at 126 s because a prior `--check` "cannot judge" run
  had nudged a rebuild; worth confirming the launcher never consults `--check`.

*Fix options.*
1. Treat unjudged as *reported-but-not-failing*: =:ok? (empty? gone)=, and print
   the unjudged list as an informational note rather than folding it into the
   verdict. "An unknown is not a yes" still holds for *moved* detection; but an
   unjudgeable-by-construction namespace should not be able to make a floor that
   is otherwise byte-identical read as stale.
2. Give =data-readers= (and =multi=) a source hash at seed time so they become
   judgeable — preferable if they *have* a stable source. =data-readers= has a
   source (=priv/boot/data-readers.bl=, 1900 bytes); investigate why its seed
   entry gets a key but no source hash.

*Evidence.* Committed floor 843ab96f (24 beams, key bf07de7d), boots to 42 with
the mixed-generation warning gone; only =data-readers= reported unjudged.

NOTE [2026-09-21]: Fixed in 3c156277 (v2026.4). seed namespaces follow the (ns …) declaration, not the filename; an action-only boot file (data-readers.bl) declares no namespace, so it is neither demanded as a namespace beam nor left permanently :unjudged by `bl seed --check`. Tiers.boot_namespaces rejects data-readers for the same reason. Covered by test/beam_lisp/boot_namespace_test.exs (3 tests, green).
