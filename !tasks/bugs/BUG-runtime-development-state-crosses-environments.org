#+TITLE: Development runtime state and late dependency cold loading
#+STATE: FIXED — native regressions accepted

* Reproduction
reload.state used unscoped persistent_term keys outside a managed generation.
Two environment forks asking for the same logical cell received one Atom;
plain writes in fork B overwrote fork A and were visible in their parent.
The development late-call API used ensure_ready for names never declared by
:require. That guard intentionally does nothing for undeclared names, so the
first by-name provider call failed even though its source was discoverable.

The new scope/cold-load tests failed on the previous implementation in
/home/user/tmp/product-online-20261014/dev-isolation-reproduction.log. The
application search-egress fixture also exposed the cold by-name load failure.

* Fix
Development state now uses exact-own Env keys and the existing native scope
commit/destruction fence. Cell creation is atomic under that fence, without
an auxiliary owner or global persistent update. Source reloads in the same
environment preserve cells; separate forks cannot read through to each other's
runtime values. Destruction removes the registry roots and refuses new writes.
Explicit physical-resource cleanup still belongs to the lifecycle owner.

Managed initializer-owned cells and their explicit inheritance are unchanged.
There is no automatic adoption of ambiguous old VM-global values. Convey the
same environment when deliberate development sharing is required. Production
runtime replacement and legacy physical resource adoption remain separate gates.

Development late calls and immutable reference-only provider registries now use
ensure_loaded, the actual ordinary by-name loader. Managed calls retain the
exact graph path and never use that fallback.
