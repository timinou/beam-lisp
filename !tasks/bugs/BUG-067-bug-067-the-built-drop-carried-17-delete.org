* Symptom

A drop built from this release carried 17 compiled `BeamLisp.Daemon.*` modules
and listed them in its own `beam_lisp.app`. The release's headline claim is that
the daemon IS beam-lisp; its artifact shipped the deleted Elixir daemon as loadable
code, and `Application.spec(:beam_lisp, :modules)` advertised every one of them.

Found by building the drop, not by any suite: the sunset gate
(`test/beam_lisp/sunset_gate_test.exs`) scans SOURCE, and the sources were gone.
Nothing watched the OUTPUT.

    $ ls ~/.local/share/drop/<hash>/lib/beam_lisp-0.1.0/ebin/ | grep -c '^Elixir.BeamLisp.Daemon'
    17
    $ sha256sum build/Elixir.BeamLisp.Daemon.Gateway.beam  ~/.local/share/drop/<hash>/lib/.../Elixir.BeamLisp.Daemon.Gateway.beam
    e08acfe15d7e9e83…  e08acfe15d7e9e83…          # byte-identical: the drop copies `build/`

* Root cause — the Elixir substrate was the one build stage that never dropped

`bl build` compiles `lib/**/*.ex` into the tree's `:out` (`build/`) with
`Kernel.ParallelCompiler.compile_to_path`, which writes beams for the files it is
handed and never removes beams for files that are gone.

The `.bl` side already handled this: `build-ordinary` computes
`gone = (keys (:sources st0)) − sources`, emits `[:build/dropped …]` for each, and
calls `delete-beam`. The substrate side (`build.bl`'s `build-substrate`) had no
such step — it only asked `sub/stale` which of the CURRENT sources needed
rebuilding, so a deleted `.ex` was invisible to it.

A second, quieter half: `build-log.bl`'s `:build/dropped` handler cleared only
`:sources`. Elixir sources are tracked under `:ex`, so even a drop fact would not
have removed them.

* Fix

- `priv/build/build.bl` — `build-substrate` now computes the `.ex` sources the log
  records but the tree no longer has, applies `dropped-fact` for each, and deletes
  their beams, all BEFORE `sub/stale` is asked. Mirrors `build-ordinary`.
- `priv/build/build-log.bl` — `:build/dropped` clears whichever namespace recorded
  the path (`:sources` and `:ex`), because a path is one or the other.

* Verified

    $ bl build            # BEFORE: 17 daemon beams in build/  AFTER: 0
    $ bl self-build …     # rebuilt artifact: 0 dead daemon modules, 0 in .app

The drop's `.app` now names `Elixir.BeamLisp.Ns.Bl.Daemon` and
`Elixir.BeamLisp.Ns.Body.Bl.Daemon` — the NEW beam-lisp daemon, which is correct.

* Class

Any source deletion in `lib/` had the same shape. `.bl` deletions pruned; `.ex`
deletions did not. The gate that should exist is on the ARTIFACT (a release must
not carry a module whose source is absent), not only on the source tree — see
the release-gate follow-up in the v2026.4 changelog.
