#+CUSTOM_ID: BUG-079-hex-bl-looks-for-a-package-name-with-a-k

* Initial Message

what would be the advantages of rolling our own json library instead of relying on jason?

* Symptom

`priv/build/hex.bl` decides whether a hex package document is usable, and it
looks for the package name with a KEYWORD lookup on a decode result that has
STRING keys:

```
113:      (let [j (try (bl.json/decode (:ok r)) (catch _ nil))]
115:          (nil? j) {:error (str "hex: unusable package document for " name)}
116:          (nil? (:name j)) {:error (str "hex: package document has no name: " name)}
```

`(:name j)` is nil for a map keyed by binaries, so the second branch always
takes: a WELL-FORMED package document is reported as having no name. The
`:releases` check below it is never reached.

* Evidence (observed, not inferred)

```
old path (Jason/decode, which returns {:ok, map}):
  returns a tuple?   true
  (:name old)        nil      <- cond sees nil -> "has no package name"
new path (bl.json/decode, which returns the map):
  keys are strings   ("name" "releases")
  (:name newv)       nil      <- ALSO nil, so same branch
with {:keys :keyword}:
  (:name ...)        plug     <- the fix is one option
```

So the defect PREDATES the bl.json cutover and the cutover is
behaviour-preserving there (both forms reach the same branch). It was found by
auditing the cutover, not by running it: the failure needs a live hex fetch.

* Why it was not fixed with the cutover

The cutover's contract was "same behaviour, one implementation". Fixing this
also changes an error path and needs a hex response to verify against; mixing
the two would make a 24-file mechanical change unreviewable. Filed instead.

* Acceptance

`bl deps fetch` / whatever resolves a package through this path reports the
package's releases for a well-formed document. A test pins the branch: a
document with `"name"` reaches the release list, not the "has no name" error.
The fix is `(bl.json/decode (:ok r) {:keys :keyword})` plus the same for
`:releases`, `:version`, `:checksum` and `:retired` — the whole fn assumes
keyword keys, so it is one option and not four lookups.
