#+TITLE: Server guards disagree between source model, native compiler and JS lowering
#+DATE: 2026-10-12
#+STATE: FIXED — native and emitted JS acceptance 2026-10-13

* Reproduction and impact
At Beam main 972c1809, system.model recognizes both:
#+begin_src beam-lisp
(handle-call [:amount n] :when (and (int? n) (> n 0)) [_ state] (reply true state))
(handle-call [:amount n] [_ state] :when (and (int? n) (> n 0)) (reply true state))
#+end_src
Native server-clause-defs only consumes split-when immediately after the message
pattern. In the second form, :when and its predicate become ordinary body
expressions. The handler replies true for 0 and a string. Its guard is not enforced.
The first form enforces the guard and rejects the invalid fixture inputs.

JS actor lower-arm expects the parameter vector immediately after the pattern.
The first form therefore refuses as a malformed parameter vector; the second
lowers :when/predicate into the ordinary body rather than a receive guard.
These JS findings are checked at actual lower-arm output, not emitted JS execution.

No claim is made that Hera exercises this spelling. The confirmed defect matters
to contract-derived admission: a modeled guard cannot be treated as runtime
authority while compiler/backends disagree about whether it executes as a guard.

* Desired structural fix
Use one canonical callback descriptor/parser for analysis, native emission and JS
lowering. Normalize supported guard placement or reject unsupported/malformed
placement explicitly; never silently lower a purported guard as body expressions.
Include contributed clauses after expansion. Separate message-only shape checks
from state-dependent readiness; a guard requiring state must run with the correct
owner state and cannot be copied blindly into an input-only matcher.

Validate permitted pure guards, binding scope, missing/duplicate guards, wrong
parameter counts and source positions. Reuse compiler pattern semantics rather
than adding an independent matcher with divergent collection behavior.
