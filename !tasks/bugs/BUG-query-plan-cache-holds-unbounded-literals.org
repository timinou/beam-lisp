#+TITLE: Bound plan-cache entries and prevent duplicate FIFO keys
#+DATE: 2026-10-07
* DONE Bounded admission with pure FIFO policy
A 1024-form cap did not bound retained data: literal values and small slices
could hold arbitrarily large parent binaries. Cold concurrent misses could also
append one key repeatedly, breaking correspondence with eviction order.
Pure data.cache-ring admits each key once and keeps order/entries aligned.
Engine charges finite query plus parsed/planned entry only on misses, declining
resources and >64KiB entries while still executing the query normally. Together
with 1024 entries: <=64MiB conservatively charged retained data. This is not a
whole-VM RSS guarantee. No query-author annotation or API change required.
Numeric stats expose declines and largest entry size without query contents.
