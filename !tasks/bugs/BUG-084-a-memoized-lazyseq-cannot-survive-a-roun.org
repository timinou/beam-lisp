* Root cause (reproduced with a private clean store)

    run 1  (cold, memo miss)  →  OK
    run 2  (memo hit)         →  raises :badarg

Stack: `code.semantic:merge-memo!` → `core/mapv` → `LazySeq.new` →
`LazyMemo.create` → `LazyMemo.nif_id(:badarg)`.

The memo file contains a serialized `LazySeq` whose cell holds a NIF resource.
`term_to_binary` writes a reference to it; `binary_to_term` reads back a
DANGLING one, and the first touch of the memo raises inside the NIF. So the memo
is a *cache that reliably poisons itself on the second run* — which is exactly
the shape that hides: the first run after any cache clear works, and every run
after that fails.

* The move (attempted, not shippable as written)

Force the values before they are stored:

    :facts (vec (concat (entity-facts …) (codebase/requires-facts …)))

and bump `MANIFEST-VERSION` so already-poisoned memos are read as ABSENT rather
than trusted. That is the right *direction* — a memo is a persisted artifact, so
it wants data, never a thunk only this process can run — but the hunk as written
did not parse (an unclosed paren), and it was reverted rather than shipped
unverified.

The real fix is one level up: **nothing lazy may be memoized.** A store whose
job is to survive a round trip must refuse a value it cannot serialize honestly —
`vec` at every memo boundary, and a check at the boundary that says so, so the
next lazy value added here fails loudly at the WRITE instead of silently at the
read. Then bump the version and re-run the two-run probe.
