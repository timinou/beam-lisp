* Symptom

With `BL_DAEMON=auto` and no daemon running, the FIRST command's stdout gets an
extra line prepended: `beam-lisp 0.1.0`.

    $ cd /tmp/dropx && BL_DAEMON=auto ./bl-v2026.4 eval '(println "MARKER")'
    beam-lisp 0.1.0        <- not ours
    MARKER
    :ok

For `bl version` it reads as the command having run twice (two identical lines);
for anything else it is a spurious line ahead of the real output.

* Cause

`tooling/drop/src/launcher.rs`, `daemon_ready/1` decides reachability by
ATTACHING and running the cheapest command:

    fn daemon_ready(root) -> bool {
        ep.sock.exists() && matches!(try_attach(root, &["version".to_string()]), Attach::Exit(_))
    }

The attach is a real round trip, and the daemon writes the command's stdout to
the wire — which lands on the launcher's own stdout, i.e. the caller's terminal.
The call site is a READINESS PROBE; it must not speak to the user.

(The probe is also re-run by `wait_ready`'s 200 ms poll, so a slow start can leak
more than once.)

* Why it matters

- It corrupts pipelines: `--json`-shaped output, or anything parsed by a script,
  gets a line that is not part of the answer. `bl ask ... | jq` breaks.
- It makes `bl version` look non-deterministic.
- It is the kind of noise that trains a user to distrust the output.

* Fix

The probe's output must be discarded — a hello/ping that asserts reachability
without a command payload, or an attach whose stdout is sunk to `Stdio::null()`.
Prefer a real ping over `version` if the protocol has one; otherwise suppress.

* Acceptance

    BL_DAEMON=auto <drop> version            # exactly one line

NOTE [2026-09-18]: ROOT CAUSE (2026-09-18): daemon_ready probed readiness by RUNNING A COMMAND through the protocol — try_attach(root, &["version"]) — and try_attach streams the daemon's stdout/stderr frames to the caller's streams. Correct for a real command, wrong for a probe: wait_ready polls it every 200 ms inside a process about to print the caller's own result, so the caller saw `beam-lisp 0.1.0` before its own output. FIX: the handshake moved into one `fn hello(root) -> Hello::{Ready(stream),RestartRequired,No}` in tooling/drop/src/daemon.rs; try_attach matches on it, and `daemon_ready(root)` is now `matches!(hello(root), Hello::Ready(_))` — the probe sends no request at all, so it cannot write. The local daemon_ready in launcher.rs was deleted (include!("daemon.rs") puts the new one in scope). Also cheaper: wait_ready makes up to 600 polls, each of which used to run a full command in the daemon.
