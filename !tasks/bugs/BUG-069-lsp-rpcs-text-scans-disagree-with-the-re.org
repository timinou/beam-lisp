* What is wrong

`priv/lib/lsp/rpc.bl.md` answers two positional questions by scanning TEXT
where the reader already knows the answer. Both are wrong on input that occurs
in this tree.

Measured (`./bl run -p priv/build -p priv/std -p priv/lib` on a scratch file):

  (rpc/ns-of "(def s \"(ns evil)\")
(ns real.ns)
")      → "evil"
  (sg/header* the-same-source)                             → "real.ns"

  (rpc/find-defn ";; (defn ghost [x] x)
(defn real [x] x)
" "ghost")
    → {:line 1 :col 10}                     ; a defn inside a COMMENT is found

  (rpc/find-defn "(defn
  spaced [x] x)
" "spaced")
    → nil                                   ; a multi-line head is MISSED

* Why it matters

`ns-of` decides the namespace every diagnostic is attributed to, and it is the
namespace a rename will key on. Two readers of the same fact that can disagree
are two facts — the failure `reload/image-kind` already names ("two copies of a
signal are two signals"). `find-defn` supplies the `Location` that
`textDocument/definition`, `references` (includeDeclaration) and
`documentSymbol` all return, and the range a rename's `WorkspaceEdit` will use:
a range pointing into a comment, or a null where a definition exists, is a
wrong edit.

* The fix

One shared, host-only token stream — `priv/boot/tokens.bl`, sibling of
`source-graph.bl` (no `core` vars, so it is callable at any point of boot):

  (tokens src) → [{:text :kind :line :col :end-col :off :end-off} …]

skipping whitespace, `;` comments and string literals, emitting delimiters and
reader prefixes as their own one-character tokens. Then:

  · `ns-of` is `(first (sg/header* src))` — one reader, not two.
  · `find-defn` finds the name token immediately before the first `[` at depth
    1 inside the `(defn …)` list, using the list's own span (lists DO carry
    positions) to bound the search.

A prototype of the tokenizer exists at
`tmp/rename-proto/rename_proto.bl` (`tokens`, `decl-name-token`) and is
exercised on the cases above.

* Acceptance

  · `ns-of` on a source whose first form is a string containing `(ns evil)`
    answers the namespace the reader answers.
  · `find-defn` answers nil for a name that appears only in a comment, and a
    real position for a defn whose head spans two lines.
