#+TITLE: datom/watch T2a is blind to attributes read inside rules, not/not-join, or/and, and computed relations
#+STATE: ITEM
#+CUSTOM_ID: BUG-100-datom-watch-is-blind-to-attributes-read-in

* Symptom

A T2a watch (a full query) does not fire when a commit changes the query's answer
through an attribute that is read ONLY inside a rule invocation, a
=[:not …]=/=[:not-join …]=, an =[:or …]=/=[:and …]=, or a computed relation. It is
silent — no error — while the answer has changed.

Reproduced 2026-09-22 (knowledger Drive-sync design), evidence in
=!tasks/evidence/BUG-100/= (=owed-probe.bl=, =owed-probe.out=,
=stale-probe.bl=). Run: =BL_DAEMON=off bl run '!tasks/evidence/BUG-100/owed-probe.bl'=

#+begin_example
file added under sub  → {:removed #{}, :added #{[10 "r1"]}}   ✓
job recorded (not-join) → :silent                               ✓ (answer unchanged)
rev bumped             → {:removed … :added …}                  ✓
moved INTO root (parent only) → :silent                         ✗
truth after move       → [[10 "r2"] [12 "x"]]                   ← the answer DID change
#+end_example

The query: =[:find ?f ?rev :in $ % ?m :where [?m :m/root ?r] (under ?f ?r) [?f :f/rev ?rev] [:not-join …]]=
with =under= a recursive rule over =:f/parent=. The move changed only =:f/parent=.

* Cause

=priv/lib/datom/watch.bl=:
- =query-attrs= → =pattern-clauses= keeps only clauses where
  =datom.query.parse/pattern-clause?= holds — top-level data patterns.
  Rule invocations (list first element), rule operators (keyword first element)
  and their sub-clauses are skipped.
- =touches?= then discards any commit whose datoms touch none of those attributes,
  WITHOUT running the query. Its docstring promises "correctness over the
  optimisation" for variable attributes; the same promise is not kept for
  attributes it cannot see.

* Fix (PLAN-142 W0)

1. =query-attrs= walks the WHOLE query: recurse into =:not :not-join :or :or-join :and=
   sub-clauses, and into the bodies of every rule in the =%= input (the watch
   already receives it in =inputs=; locate it by =parse/input-forms= position).
2. A computed relation contributes its declared =:reads= (new optional relation
   axis, =docs/connectors/mirror-and-reconcile.md= §3.2); a computed relation WITHOUT
   =:reads= makes the prefilter answer "always relevant".
3. Anything else the walker cannot classify → "always relevant".

* Acceptance

- =owed-probe= becomes a test in =test/bl/datom/watch_test.bl=: the parent-only
  move fires =:added #{[12 "x"]}=.
- Four more cases, one per construct: an attribute read only inside =[:not …]=,
  =[:or …]=, a rule body, and a =:reads=-declared computed relation — each fires.
- A commit touching an attribute the query reads NOWHERE stays silent (the
  prefilter still prefilters).
- The existing watch and watch_rls suites stay green.

* Blast radius

Every T2a watch over rules or negation — any live view that shows "what is not yet
done" (a =not-join= against a record of doneness) can miss the moment an item
BECOMES undone through a joined attribute. Grep consumers before closing:
=datom/watch=, =live= subscriptions, =proc.queue='s own listen path is T1-free
and unaffected.
