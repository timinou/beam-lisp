#+TITLE: datom/watch T2a is blind to attributes read inside rules, not/not-join, or/and, and computed relations
#+STATE: DONE
#+CUSTOM_ID: BUG-100-datom-watch-is-blind-to-attributes-read-in

* Symptom

A T2a watch (a full query) does not fire when a commit changes the query's answer
through an attribute that is read ONLY inside a rule invocation, a
=[:not …]=/=[:not-join …]=, an =[:or …]=/=[:and …]=, or a computed relation. It is
silent — no error — while the answer has changed.

Reproduced 2026-09-22 (knowledger Drive-sync design), evidence in
=!tasks/evidence/BUG-100/= (=owed-probe.bl=, =owed-probe.out=,
=stale-probe.bl=). Run: =BL_DAEMON=off bl run '!tasks/evidence/BUG-100/owed-probe.bl'=

#+begin_example
file added under sub  → {:removed #{}, :added #{[10 "r1"]}}   ✓
job recorded (not-join) → :silent                               ✓ (answer unchanged)
rev bumped             → {:removed … :added …}                  ✓
moved INTO root (parent only) → :silent                         ✗
truth after move       → [[10 "r2"] [12 "x"]]                   ← the answer DID change
#+end_example

The query: =[:find ?f ?rev :in $ % ?m :where [?m :m/root ?r] (under ?f ?r) [?f :f/rev ?rev] [:not-join …]]=
with =under= a recursive rule over =:f/parent=. The move changed only =:f/parent=.

* Cause

=priv/lib/datom/watch.bl=:
- =query-attrs= → =pattern-clauses= keeps only clauses where
  =datom.query.parse/pattern-clause?= holds — top-level data patterns.
  Rule invocations (list first element), rule operators (keyword first element)
  and their sub-clauses are skipped.
- =touches?= then discards any commit whose datoms touch none of those attributes,
  WITHOUT running the query. Its docstring promises "correctness over the
  optimisation" for variable attributes; the same promise is not kept for
  attributes it cannot see.

* Fix (PLAN-142 W0)

1. =query-attrs= walks the WHOLE query: recurse into =:not :not-join :or :or-join :and=
   sub-clauses, and into the bodies of every rule in the =%= input (the watch
   already receives it in =inputs=; locate it by =parse/input-forms= position).
2. A computed relation contributes its declared =:reads= (new optional relation
   axis, =docs/connectors/mirror-and-reconcile.md= §3.2); a computed relation WITHOUT
   =:reads= makes the prefilter answer "always relevant".
3. Anything else the walker cannot classify → "always relevant".

* Acceptance

- =owed-probe= becomes a test in =test/bl/datom/watch_test.bl=: the parent-only
  move fires =:added #{[12 "x"]}=.
- Four more cases, one per construct: an attribute read only inside =[:not …]=,
  =[:or …]=, a rule body, and a =:reads=-declared computed relation — each fires.
- A commit touching an attribute the query reads NOWHERE stays silent (the
  prefilter still prefilters).
- The existing watch and watch_rls suites stay green.

* Blast radius

Every T2a watch over rules or negation — any live view that shows "what is not yet
done" (a =not-join= against a record of doneness) can miss the moment an item
BECOMES undone through a joined attribute. Grep consumers before closing:
=datom/watch=, =live= subscriptions, =proc.queue='s own listen path is T1-free
and unaffected.

* Resolution (2026-09-22)

Fixed in =priv/lib/datom/watch.bl= (=query-attrs=, the T2a prefilter) and
=priv/lib/datom/query/relation.bl= (the =:reads= axis). The closing commit is
recorded below.

** What changed

- =query-attrs parsed inputs= now walks the WHOLE query. It recurses into the
  =:not= / =:not-join= / =:or= / =:or-join= / =:and= sub-clauses (skipping the
  join-variable vector of the =-join= spellings, which names no attribute) and
  folds in every body of the =%= rules input — located by =parse/input-forms=
  position, which lines up with the =inputs= the watch already holds. One body
  per rule is enough: the union over ALL bodies is exact, so rule-calling-rule
  and recursion need no fixpoint.
- A computed relation contributes its declared =:reads= (relation.bl axis 8).
- Anything the walker cannot NAME yields =ALWAYS-RELEVANT=, a sentinel
  =touches?= reads as "run the query": a variable attribute, an unrecognised
  clause form, a call form taking =$= (a database builtin — =get-else=,
  =missing?= — which reads attributes the walker cannot name), an undeclared
  computed relation, a =%= argument that is not a rule set. ONE unclassifiable
  clause makes the whole query always-relevant, because a partial set would
  drop the firings of the piece it missed. A plain predicate still contributes
  nothing (it reads no attribute, it filters bound values), and an empty read
  set is still "always relevant".
- One implementation, not two: =pattern-clauses= and =clause-attr= are gone;
  =clause-attrs=, =rules-attrs= and =rules-argument= replace them, and the
  docstrings state the fail-open contract.
- =register-relation!= gained the optional =:reads= — a non-empty set/vector of
  attribute keywords. A malformed or EMPTY declaration throws at registration
  rather than silently meaning "never relevant". =catalog-datoms= emits
  =[rel :relation/reads attr]= so the axis is askable, and the file header went
  from seven axes to eight.

The =job recorded (not-join)= line also moved from =:silent= to a real diff. That
step had been annotated correct in the Symptom as "the answer did not change" —
it does: recording the job takes =a= out of the owed set (={[10 "r1"]} → {}=). The
old watch missed that firing too. =rev bumped= now reports only the new row,
because the watcher's basis advanced at the previous commit.

** Blast radius (checked — nothing relied on the silence)

- =priv/lib/live.bl= (=register-live!=) — the gated live view. It hands a
  monotone query plus inputs to =datom/watch= and consumes the ={:added
  :removed}= diff. A wider read set only means the query RUNS more often; the
  diff suppresses a no-op fire, so no firing is fabricated and none is lost.
  (It also rejects =:not=, so the negation half of this bug never reached it.)
- =priv/lib/datom.bl= — re-export of =datom/watch= / =datom/unwatch=; docstrings only.
- =priv/lib/mcp/tools.bl= =code/subscribe= — a T1 pattern
  (=[?c :call/callee …]=), which never reaches the T2a prefilter.
- =priv/std/proc/queue.bl= — a comment naming the design; =proc/reconcile= does
  not exist yet (PLAN-142 W4), so there is no caller to break.
- =priv/lib/datom/time.bl= and =docs/datom-as-a-broadcast-substrate.md= — prose only.
