#+CUSTOM_ID: BUG-059-a-fresh-doom-machine-cannot-get-the-beam

* Initial Message

how does a new user generate the tree sitter mode

* Symptom

On a machine where Emacs has never installed a tree-sitter grammar — a fresh
Doom install — three things fail, in this order.

1. `bl install doom` reports the grammar step as failed and stops there:

     ok   module   ~/.config/doom/modules/lang/beamlisp (7 files)
     --   grammar  no Emacs tree-sitter grammar directory found
     ok   init.el  ...

2. Opening a `.bl` file errors, and Emacs leaves the buffer in fundamental-mode:

     File mode specification error: (error tree-sitter grammar ‘beamlisp’ not
     available; see beamlisp-ts-mode.el commentary)

3. `gd` on any symbol then answers:

     Could not find rules for ’.bl file’.

* One chain, three defects

The symptoms are one causal chain, and each link is its own defect.

- A tree-sitter grammar directory is created only by
  `treesit-install-language-grammar`, so a machine that never ran it has none of
  the three places `grammar-dir` looked in. `grammar-dir` only *looked*; it never
  made one. A fresh machine therefore could not reach the grammar step's success
  — the installer had no way to install the grammar it exists to install.
- `beamlisp-ts-mode` called `(error ...)` when the grammar was missing, which
  aborts the mode function — and no major-mode hook runs from an aborted mode, so
  eglot/lsp-mode never attach. The language server needs no grammar at all; it
  was lost to a missing highlighter. Emacs's own tree-sitter modes do not do
  this: they wrap the treesit half in `(when (treesit-ready-p 'LANG) ...)`
  (c-ts-mode.el, js.el).
- With no server attached, `gd` fell through to dumb-jump, which keys its rules
  off a file-extension table with no `.bl` entry. Instead of searching, it
  answers "Could not find rules for '.bl file'." — a message about the searcher,
  read as a message about the code.

* Fixes

1. `priv/std/bl/install.bl.md` — `grammar-dir` takes `create?`. The doom target
   passes true: a directory that exists wins wherever it sits in the order,
   otherwise the first place whose Emacs is present (`~/.config/emacs`,
   `~/.emacs.d`) is made. `--check` passes false, because verifying an
   installation must write nothing — it reports the absence instead.
2. `editors/emacs/beamlisp-ts-mode.el` — the tree-sitter half is now
   `(if (treesit-ready-p 'beamlisp t) ... (beamlisp-ts-mode--missing-grammar))`.
   Without the grammar the mode keeps the half that needs none: syntax table,
   comment handling, `lisp-indent-line`, imenu, and the LSP registration. It
   warns once, naming `bl install doom` and the `cc` line.
3. Same file — `.bl` and `.bl.md` are added to `dumb-jump-language-file-exts`
   under the `clojure` language, whose rules ARE the `def` family that bl shares.
   A lookup with no server behind it now searches; when a server answers, the
   entry never fires.
