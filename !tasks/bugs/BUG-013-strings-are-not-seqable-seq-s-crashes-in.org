* Symptom

    (seq "ab")      => CRASH  (no RT.seq/1 clause for a binary)
    (into [] "ab")  => [nil]  <- SILENTLY WRONG
    (vec "ab")      => crash after the vec optimisation (was [nil])
    (to-list "ab")  => "ab"   (falls through the :else branch unchanged)

Clojure:

    (seq "ab")      => (\\a \\b)
    (vec "ab")      => [\\a \\b]
    (count "ab")    => 2       ; this one we DO get right

`(into [] "ab") => [nil]` is the worst outcome available: no error, a
plausible-looking vector, and a nil that surfaces somewhere far from the
cause.

* Cause

`RT.seq/1` has clauses for nil, list, Vector, LazySeq, SortedSet,
SortedMap and Set — but not for a binary. `to-list`'s `cond` has no
string branch either, so a string falls through `:else` and is returned
AS a string, which then breaks whatever expected a list.

`count` works on strings, so the language is already half-committed to
strings being countable collections; seqability is the missing half.

* Design question to settle first

What is an element of a string here?

- Clojure/Java: a character. beam-lisp has no character type.
- Erlang/Elixir: a binary has no natural element — `String.graphemes/1`
  gives user-perceived characters, `String.codepoints/1` gives
  codepoints, `:binary.bin_to_list/1` gives bytes.

`count` already answers this: it is char-based (its `subs` docstring says
"Indices are char-based, matching count (so multi-byte characters are not
split)"), so `seq` MUST agree with it or `count` and `seq` disagree about
the same value — worse than either choice alone.

=> elements are single-character STRINGS, matching `count` and `subs`.

* Fix

1. `RT.seq/1`: a binary seqs to its graphemes as 1-char binaries; the
   empty string seqs to nil (Clojure's contract: `(seq "")` is nil).
2. `to-list`: add a string branch doing the same, so `vec`/`mapv` and
   every `Enum` bridge agree.
3. Check `first`/`rest`/`next`/`nth`/`last` on a string follow from
   `seq`, and that `(into [] "")` is `[]` not `[nil]`.

* Tests

    (is (= ["a" "b"] (vec "ab")))
    (is (= ["a" "b"] (into [] "ab")))
    (is (= 2 (count (seq "ab"))))
    (is (nil? (seq "")))
    (is (= [] (into [] "")))
    (is (= "a" (first "ab")))
    ; multi-byte: count, seq and subs must agree
    (is (= 2 (count "\u00e9\u00e8")))
    (is (= ["\u00e9" "\u00e8"] (vec "\u00e9\u00e8")))
