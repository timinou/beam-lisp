#+TITLE: Preserve nested execution context with constant-cost named calls
#+STATE: FIXED AND BENCHMARKED — synthetic native mechanism, not page SLO

* Reproduced bugs
A named call inside an already-owned execution acquired another lease for every
physical module and rebound the captured graph context. The regression observed
2 registrations instead of1 and lost the active diagnostic operation ID.
nested-baseline.log records the two failing assertions before the fix.

* Implementation
An execution records a private process-local identity (scope,digest,state-cell)
while holding its real native graph lease. invoke! reuses that ownership only
when both current graph identity and environment match. It invokes the exact
sealed target without another graph-sized acquisition or context reset.
The marker is restored on throws and is absent from Env capture/bind tokens.
Another graph,another scope or another process takes the normal leased path.
Explicit with!,slot admission and retained callback run! keep their original
framework context/execution boundaries. No app changes or config are required.

* Native benchmark
Same33namespace/162module synthetic graph,one warmup then5samples of1000
nested named calls. Baseline and final scripts are identical. Median wall
638.536ms -> 9.650ms per1000calls (66.17x); median process
reductions 27,062,805 -> 590,372 (45.84x fewer). Registrations return to0.
This isolates graph-binding cost on a busy host; it is not a measured Knowledger
page speedup. The nested path no longer scales with the graph's module count.
