#+title: Cached namespace initializers omitted implicit runtime dependencies
#+date: 2026-10-10
#+state: FIXED — native cold artifact replay validated; final seed pending

* Observed failure
A cold source-launcher run replayed Foundry's cached application binder and then
failed with undefined =BeamLisp.Ns.Clojure.Re.re-pattern/1=. The same preparation
through the complete executable SDK succeeded. A warm source VM could also hide
the problem by having already initialized the regex namespace.

* Cause
The reader expands a regex literal into a qualified =clojure.re/re-pattern=
call. The compiler resolves and loads that namespace during source compilation,
and emits its ordinary =Loader/ensure_ready= guard on the compiled direct call.
The AOT initializer previously captured only explicit =(ns ... :require ...)=
declarations. In a fresh replay VM an implicit dependency had no deferred
record, so =ensure_ready= did nothing and the compiled call reached missing code.
Qualified function calls and exact global value fetches share this class.

* Repair
=priv/host/aot.bl= walks the actual compiled ANF of owned function definitions
and value initializers. It collects the compiler's literal =ensure_ready= owners
and global namespace references, ignoring quoted literals and source annotations.
Own namespace, boot substrate and already explicit requirements are excluded.
The emitted initializer declares the remaining namespaces lazily, before value
initialization; it installs no aliases and does not eagerly execute providers.
This keeps compile-time-only macro calls out of runtime requirements and avoids
introducing eager initialization cycles. No app declarations or call sites change.
The ordinary loader implementation remains untouched.

* Cold regression
=test/bl/aot_implicit_dependencies_test.bl= compiles the edited host emitter as
an independent exact-named probe and emits real consumer/provider artifacts.
Before a fresh consumer VM starts, the consumer source and compile-only macro
source/artifacts are removed: interpretation cannot conceal a replay failure.
The child proves provider side effects stay lazy, a qualified function and value
produce 42, regex literals match/reject correctly, a compiled-away macro remains
usable without its provider, and a dormant mutual-qualified graph remains lazy.
The VM and its child are capped together; scratch lives under HOME.

* Automatic invalidation and bootstrap witness
=AOTCache/codegen_modules= already includes =Elixir.BeamLisp.AOT= and
=pinned_host_source= maps it to =priv/host/aot.bl=. =live_codegen_digest= hashes
those actual source bytes; =codegen_part= feeds that digest into
=compute_compiler_key=. =fetch= addresses entries beneath the resulting compiler
key and verifies the embedded compiler/source provenance as well as file digests.
Thus an ordinary emitter source edit invalidates previous keyed consumer caches
without app configuration or manual cache deletion.

There is a second bootstrap case: the source launcher stages the old pinned host
by its manifest SHA, then rebuilds boot namespaces with that host. Editing AOT's
source changes the live key before replacing the pinned AOT emitter. The old
emitter can therefore stamp old-format output with the new source key. Matching
source/compiler stamps alone cannot prove which initializer format was emitted.

New namespace shims carry =bl_aot_replay_version = 1=. Current AOT provenance
and AOTCache provenance readers require that emitted witness. Missing or unknown
versions cannot pass cache publication/fetch or the boot freshness verdict, even
with current source/compiler keys and a valid digest manifest. Source-present
namespace drift repair rebuilds old-format artifacts; generic/native cache
clients retain their digest-only contract. The witness is checked while loading
or validating artifacts, with no extra work on ordinary compiled function calls.
Legacy sourceless package trust is preserved: a source-present checkout repairs
old replay formats, while an older complete package retains its existing
compatibility contract. Final rebuilt SDK acceptance proves the current format.
Future incompatible initializer formats must advance this emitted version and
its matching readers; the source key still handles ordinary implementation edits.

The existing =codegen_provenance_test.bl= pins AOT membership, checks production's
key against the live input rule and mutates every copied source leaf to prove
digest movement. =aot_cache_host_test.bl= already rejects wrong embedded
provenance. The new replay test additionally fabricates old-format artifacts
with the *current* compiler/source keys and digest-valid manifests, rejects
absent/unknown replay witnesses, then replaces them with a current artifact.
This covers the bootstrap poison case rather than duplicating membership tests.

* Bootstrap destination repair
The first official combined floor was correctly emitted with replay witnesses,
but its first source-launcher acceptance failed before tests. An earlier source
boot had already written old-format local boot beams carrying the current key.
=Bootstrap/fresh_generation?= independently compared only that key and preserved
those poisoned destination beams even after the new seed became available.
The new AOT gate refused them; attempting to compile a replacement reader before
the compiler's constants were initialized exposed =compiler/special-forms=.
The failed launcher run is not accepted validation evidence.

=Bootstrap/stamped_key= now requires the same emitted replay witness before a
namespace shim can preserve its generation unit. =install!= snapshots preservation
decisions for every shim/body/initializer *before* copying any files. A newly
restored shim therefore cannot retroactively legitimize an old companion with
an equal filesystem timestamp. This fixes local bootstrap staging as well as
the shared-cache repair above; no loader bypass or manual cache deletion is used.
The unused per-file preservation helper was removed so installation has one
decision path.
