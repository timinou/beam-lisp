#+TITLE: Retained queue work fails across real generation environments
#+DATE: 2026-10-13
#+STATE: FIXED — native regression 16 assertions; durable demo 30 assertions

* Counterexample
Continuity queued a real v1 job, activated v2 and later ran the retained v1
handler. The job failed with "diagnostics: captured scope belongs to another
environment". proc.queue captured the current dispatcher's full diagnostics
scope, bound the retained handler Env, then attempted to install that foreign
scope. A running old job can also finish after dispatcher activation and hit
the same mismatch in settlement-event emission, potentially killing the queue.

* Repair
Keep diagnostics/with-captured-fn's environment check strict. Same-Env paths
retain their exact scope. Cross-generation queue boundaries convey projected
durable linkage plus the claim's existing trace/attempt IDs using existing
detached/context APIs. Sinks, event schemas and capabilities stay owned by the
executing Env. Both worker invocation and later dispatcher events use this rule.

* Acceptance
queue_generation_context_test uses two real immutable generation Envs, a running
old job, a pending old job claimed by the new dispatcher, and new work. Assert
correct old/new handler and code identities, diagnostic linkage, queue liveness,
and continued refusal of arbitrary cross-Env diagnostic captures. The durable
Continuity demo must also complete the original v1 job before retiring v1 code.
