* TODO BUG-109 A qualified call to a project fn that shadows a core name runs CORE on the first (cold) call
:PROPERTIES:
:CUSTOM_ID: BUG-109-a-qualified-call-to-a-project-fn-shadowing-core-runs-core-on-first-call
:REPORTED_BY: omega (~/code/undefine/omega), 2026-10-01
:END:

** Symptom
A namespace defines a function whose name also exists in core (=run!=, =count=, =first=, …). Another namespace requires it with an alias and calls it QUALIFIED. In a fresh VM, the *first* call runs the core function. Later calls run the project function. There is no error, just the wrong function: core =run!= returns =nil=, and core =count= returns the count.

Observed in omega: =(loop/run! sys id)= silently returned =nil= on the first turn of every fresh VM. The executor then wrote =:task/status nil= ("transaction rejected by schema"). It looked like flakiness for an hour.

** Minimal reproduction (beam-lisp main 59cdb542, =bin/bl=, running from source)
#+begin_src sh
mkdir -p /tmp/lz/src/lz && cd /tmp/lz
cat > src/lz/d.bl <<'E'
(ns lz.d)
(defn count [x] :mine)
(defn first [x] :mine-first)
E
printf '(ns m4 (:require [lz.d :as d]))\n(println "cold:" (d/count [1 2]) (d/first [9]))\n(println "warm:" (d/count [1 2]) (d/first [9]))\n' > m4.bl
~/code/undefine/beam-lisp/bin/bl run -p src m4.bl
#+end_src

Output:
#+begin_example
cold count: 2 first: 9
warm count: :mine first: :mine-first
#+end_example

The same with =(defn run! [sys id] …)= gives =cold: nil= and then the right answer.

** Not affected
- =:refer :all= of the same names: the referred project function wins on the first call.
- Names not in core.

** Likely area (guess, unverified)
Demand loading / lazy namespace resolution (=9a48e5bd perf: complete demand loading=). On a cold call, a qualified symbol whose target namespace is not yet loaded seems to fall back to core resolution before the alias's namespace loads.

** Workaround in omega
Renamed =omega.loop/run!= to =turn!=.
