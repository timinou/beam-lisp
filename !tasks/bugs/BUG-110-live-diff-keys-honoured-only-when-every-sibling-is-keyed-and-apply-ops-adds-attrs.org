* TODO BUG-110 live.diff: keys are honoured only when EVERY sibling is keyed; mixed lists graft a new keyed subtree onto the old node
:PROPERTIES:
:CUSTOM_ID: BUG-110-live-diff-keys-honoured-only-when-every-sibling-is-keyed-and-apply-ops-adds-attrs
:REPORTED_BY: omega (~/code/undefine/omega), 2026-10-02
:END:

** Symptom
In omega's UI (a =live.app= in a wry window), switching from the overview screen to a task screen left an overview row inside the task screen, after the header. The page showed a "Waiting · 1" list beside the task's details. The DOM held the old row because the diff morphed one screen into the other POSITIONALLY. Each screen root carried a different =:key=, but its sibling (the header) had none.

** Minimal reproduction (beam-lisp main 04614e87)
#+begin_src clojure
(ns repro (:require [live.diff :as diff]))
;; all siblings keyed → correct: remove + insert
(diff/diff [:div [:div {:key "overview"} "o"]] [:div [:div {:key "task:t-1"} "t"]])
;; => [[:remove [] "overview"] [:insert [] "task:t-1" 0 [:div {:key "task:t-1"} "t"]]]

;; one unkeyed sibling → keys IGNORED: the new keyed node is a text edit of the old one
(diff/diff [:main [:header "h"] [:div {:key "overview"} "o"]]
           [:main [:header "h"] [:div {:key "task:t-1"} "t"]])
;; => [[:text [1 0] "t"]]      ← data-key stays "overview" in the DOM
#+end_src

The positional path then diffs two unrelated subtrees child by child. With realistic screens (different lengths, nested lists), the client ends up with leftovers from the old subtree.

** Expected
A child whose =:key= differs from the node at the same position is a different node, whether or not its siblings are keyed. It should =replace= (or =remove=/=insert=), never morph. Keys should be honoured per-child, React-style. "All keyed or none" is too coarse for real views, where a keyed list sits beside a header.

** Also
=apply-ops= (the reference semantics the client mirrors) does not round-trip on trivial inputs. =(diff/apply-ops (diff/diff [:div "y"] [:div "x"]) [:div "y"])= gives =[:div {} "x"]=: it adds an empty attrs map and drops =:key= attrs. The docstring's property "(apply-ops (diff a b) a) == b, for every pair" does not hold as stated. It may hold modulo attr normalization, but then the property test should compare normalized trees, and this bug is invisible to it.

** Workaround in omega
The screen is the only child of a =display:contents= wrapper, and keyed (=src/omega/ui/screens.bl.md=, "The whole view").
