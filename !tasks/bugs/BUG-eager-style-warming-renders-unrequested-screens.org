#+TITLE: Eager CSS warming renders unrequested screens before serving
#+DATE: 2026-10-07
* DONE Collect first-paint CSS from the actual request
live.app/serve rendered every :warm sample route and serialized its whole HTML
before opening the listener. Apps had to maintain routes, identities and sample
states for CSS coverage; missing states could still have incomplete first paint.
SSR now resets its process-local sheet, realizes the requested body, and emits
that sheet plus the request theme's base into the head. Existing live.socket
realization/style delivery sends newly reached rules before mount/patch, so
serve need not execute arbitrary sample screens. :warm/:warm-me remain accepted
and are ignored; no caller edits or opt-in. Public router retains its legacy
three-argument extra-CSS form and gains the simpler two-argument form.
SSR theme setup now happens exactly once through dispatch instead of twice.
* Validation
20 SSR checks cover lazy child rules, isolation across requests and themes,
animations, responsive rules, custom shell, both router arities, and an actual
listener launch whose forbidden warm screen would throw if evaluated.
Existing socket118 and app3 checks pass, including CSS-before-patch ordering,
lazy patch classes and live theme transitions. Total141 assertions,14.904s,
253.3MiB peak,no swap. No shared bootstrap rebuild or production deployment.
Startup costs disappear for skipped screen renders; browser remeasurement is
required before claiming any particular app startup or initial-paint timing.
