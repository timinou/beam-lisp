#+TITLE: Keyed live lists have quadratic reconciliation and lazy capture overhead
#+STATE: DONE

* Cause and fix
live.diff's LIS used a quadratic dynamic program even for an unchanged order
with one updated row. Lazy mapcat/concat closures captured complete old/new
child lists at every cell. Any app with a growing feed paid this tax.
Replace LIS with binary-search patience sorting and predecessor reconstruction;
strict vector accumulation handles attrs, indexing, keyed and positional ops.
Child extraction uses subvec instead of constructing drop/rest lazy cells.
No app-developer changes or configuration. Keys still minimize DOM moves.

* Same-VM source comparison, 2026-10-06
Original namespace loaded from Git HEAD before edits, separately named. Both
versions receive identical trees, changing only the final row's text:
| Rows | Original ms | Strict ms | Original reductions | Strict reductions |
| 512 | 459 | 10 | 66913291 | 1987883 |
| 1024 | 1962 | 35 | 261121052 | 4023244 |
At 1024 rows the differ uses 64.9x fewer reductions. Doubling list size costs
~2x instead of ~4x. These are differ costs, not end-to-end page timings.

* Guards
- Exhaustive five-row permutations (120 cases): diff/apply round-trip against
  normalized target, and minimal move count against independent exhaustive
  subsequence oracle. No dependence on a particular tie choice of LIS.
- Reduction scaling budget: 1024-row cost < 3.2 times 512-row cost.
- Existing keyed/unkeyed/metadata/wire properties retained.
