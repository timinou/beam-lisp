| harness cap                   | 300 s    | — |

The pair cannot complete inside one synchronous call, and the gate
matcher requires exactly that: a non-timed-out execution of the literal
string. Six approaches were tried \u2014 backgrounded via `nohup`, via the
tool's own async, output filtered through `grep`/`tail`, precompiled
first, run as separate halves, run warm \u2014 and none satisfied it, because
each either exceeds the cap or no longer matches the literal command.

* Why this matters beyond bookkeeping

A gate that cannot pass trains people to mark things verified anyway,
which is exactly the habit gates exist to prevent. It is worth fixing
properly rather than working around.

* Options

1. *Make the suite faster.* `mix test` at ~295 s is the real problem;
   the gate is only the messenger. Much of it is beam-lisp example
   files and AOT fixtures recompiling. Worth profiling
   (`mix test --slowest 20`) before assuming.
2. *Split the gate* into two nodes, each with one command, so each
   fits. Loses the "both together" semantics, which is a small loss:
   they share no state.
3. *Let the harness accept an async job's exit status* as gate
   evidence. The job DID complete with exit 0; the matcher just does
   not look at background results.
4. *Scope the gate* to what the node actually covers, e.g.
   `mix beam_lisp.test test/bl/datom --path priv` for datom work, which
   runs in ~60 s.

Option 4 is the honest one for most nodes: a wave that touched the
datom layer does not need the whole Spell/LSP suite as its gate, and a
narrower gate that actually RUNS is worth more than a broad one that is
routinely bypassed. Option 1 is the real fix and helps everything.
