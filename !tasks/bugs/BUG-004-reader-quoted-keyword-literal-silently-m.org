* Initial Message

how hward would it be to support datahike in beam lisp?

* Symptom

Clojure's quoted-keyword literal =:"foo bar"= (a keyword whose name is not a
valid bare symbol) does not read as one keyword. It produces TWO forms: the
empty keyword =:""= followed by the string ="foo bar"=.

Observed while writing =priv/datom/store-ets.bl= (PLAN-033 wave 1), where the
natural spelling of the ETS sentinel is =:"$end_of_table"=.

* Reproduction

#+begin_src clojure
(ns probe.kw2)
(println (pr-str :"hello world"))
#+end_src

#+begin_example
** (UndefinedFunctionError) function BeamLisp.RT.print_str/2 is undefined or private
    (beam_lisp 0.1.0) BeamLisp.RT.print_str(:"", "hello world")
#+end_example

The arity-2 call is the tell: =pr-str= received TWO arguments because the
reader emitted two forms where the source has one.

In a =defn= parameter/clause position the same input fails differently:

#+begin_example
** (RuntimeError) invalid fn clause: {:symbol, "$end_of_table"}
#+end_example

* Why this is a bug and not a missing feature

The failure is SILENT at the read stage. =:"x y"= is well-formed Clojure, and
the reader neither produces the right value nor rejects the input — it
produces a DIFFERENT, plausible-looking form pair that then fails somewhere
downstream with an unrelated-looking error (a wrong-arity call, or an
"invalid fn clause" naming a symbol the author never wrote).

That is the same class as the =sort-by= return-type bug recorded in
=test/bl/core_additions_test.bl=: a plausible-looking parse that is wrong in a
way no hand-probe reveals.

* Where

=lib/beam_lisp/reader.ex= — the =:= dispatch path. It reads a bare symbolic
name after the colon and has no branch for a following double quote, so the
name terminates immediately (yielding =:""=) and the string is read as the
next form.

* Fix sketch

In the keyword branch: after consuming =:=, if the next char is ="=, read a
STRING and use its contents as the keyword's name (=String.to_atom/1= via
=BeamLisp.AtomGuard.to_atom/1= — this is user input creating an atom, so it
must be accounted against the atom-table budget per PLAN-009).

Namespaced form =:foo/"bar baz"= is NOT valid Clojure and should stay
unsupported.

* Test

=test/beam_lisp/reader_test.exs=:
- =:"hello world"= reads as ONE keyword equal to =(keyword "hello world")=
- =:"$end_of_table"= equals the ETS sentinel atom (the motivating case)
- round-trip: =(pr-str :"a b")= reads back equal
- the empty case =:""= still reads as the empty keyword
- atom accounting: a quoted keyword goes through AtomGuard

* Workaround in use

=(keyword "$end_of_table")= — verified equal to the ETS sentinel. Used in
=priv/datom/store-ets.bl=; replace with the literal once this lands.

* Severity

Low frequency, but silent-wrong rather than loud-wrong. Any Clojure code
pasted in that uses a quoted keyword misparses into something that fails
later with a misleading message.
