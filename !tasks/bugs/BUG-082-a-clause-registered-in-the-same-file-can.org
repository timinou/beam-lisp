* Symptom (measured, cold AOT cache)

    $ ./bin/bl test test/bl/tick_test.bl
    error: defserver composite: unknown clause `slice` — accepted here:
           handle-call handle-cast handle-continue handle-info init invariant
           sched terminate tick

The file registers the clause and then uses it, twelve lines apart:

    test/bl/tick_test.bl:97   (proc/extend-clause! :slice
                               (fn [clause _ctx] {:init {:slice (second clause)}}))
    test/bl/tick_test.bl:100  (proc/defserver composite
                               (slice 42)          ; ← the registration has not run yet

* Why it appeared only now (inference, labelled)

`proc/server.bl`'s `defserver` is a MACRO: it resolves a clause head against
`@registry` at EXPANSION time (server.bl:127). `extend-clause!` is a function
call, i.e. an EVALUATION. So the two are ordered by *compile vs run*, not by
line number: a whole file compiled as one unit expands every `defserver` before
any of its top-level calls have run.

That is consistent with everything measured: this test was green in a run
earlier today and red on the same source afterwards, and what changed between
the two was `priv/boot/core.bl` — the other session added `ex-original`, which
moves the compiler tier key, which forces a full recompile. **The test was green
because it was CACHED, not because it worked.** (That is BUG-048/BUG-058's
family: the tier key moved and the beams did not.)

* Why it matters beyond one test

`priv/std/proc/server.bl`'s header promises *"an OPEN vocabulary of clauses"*,
and `priv/std/proc.bl` documents `extend-clause!` as the way a user adds one. The
promise is real for a clause registered in an EARLIER-loaded namespace
(std's own `:tick`, `:sched` do exactly this and work), and **false for a clause a
user registers in the same file that uses it**. A Clojure-shaped language
evaluates top-level forms in order even when compiling ahead of time; here it
does not, and the failure surfaces only on a cold cache — i.e. for a new user,
always, and for a maintainer, never.

* The move

1. Prove the shape (the failing test is the proof): register the clause from a
   *required* support namespace, run COLD, and the same file passes.
2. Decide the semantics, because there are two defensible answers:
   * **fix the compiler**: evaluate top-level forms in order during AOT (Clojure's
     contract) — the real fix, and the one that keeps the "open vocabulary"
     promise unconditional;
   * **or make it a stated rule**: a clause must be registered by a namespace
     that is loaded before the file that uses it, reported by the ERROR — which
     should say *"registered clauses are resolved at compile time; register this
     clause in a namespace loaded first"* instead of listing the accepted set.
   Either is honest; the current state is neither.
3. Whatever the answer, the error message should name the rule, not only the set.

* Acceptance

    why it cannot and what to do;
  * verified COLD (a tier-key move, or a cleared AOT cache, is the test);
  * `test/bl/tick_test.bl` passes cold, and its intent — "a user's own clause
