* Initial Message

how hward would it be to support datahike in beam lisp?

* Symptom

A =\"= inside a docstring terminates it, and the remaining prose is then parsed
as CODE. The error names a word from the sentence, giving no hint that a
docstring is involved:

#+begin_src clojure
(defn indexes-for
  "Enforcing uniqueness means asking \"does this value exist?\", which is
   an AVET lookup."
  [schema attr]
  …)
#+end_src

#+begin_example
** (RuntimeError) invalid fn clause: {:symbol, "does"}
#+end_example

Observed while writing =priv/datom/index.bl= (PLAN-033 wave 2). The message
points at =does=, a word in the middle of an English sentence, so the actual
cause (an unescaped quote several lines earlier) has to be found by reading.

* Expected

Standard string escapes inside docstrings, as Clojure has: =\\\"= for a literal
quote, =\
=, =\\\\=. The reader already handles escapes in ordinary string
LITERALS — the gap appears to be specific to the docstring path in =defn=/=def=.

* Investigation

Check whether the reader's string scanner is shared between the docstring
position and the expression position. If the docstring path re-scans or slices
raw source rather than reusing the escaped-string reader, that would explain it.

Worth testing at the same time: does a docstring survive =\
=? An embedded
backslash? A trailing backslash before the closing quote?

* Improving the error regardless

Even once escapes work, "invalid fn clause: {:symbol, \"does\"}" is a poor
message. When a =defn= body contains bare symbols that look like prose (several
consecutive non-callable symbols), the compiler could suggest an unterminated
docstring. Cheap heuristic, and it points directly at the real mistake.

* Workaround in use

Backticks in place of quotes throughout =priv/datom/=, which reads acceptably in
this codebase's docstring style anyway.

* Related

FEAT-003 (=deftest= drops docstrings), BUG-004 (quoted keyword literals
misparse). Three separate reader gaps found in two waves; the reader's string
and literal handling may deserve one consolidated pass rather than three
patches.
