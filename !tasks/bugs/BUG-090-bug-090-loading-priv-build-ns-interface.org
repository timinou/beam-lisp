* The bug, exactly

`priv/build/ns-interface.bl:108` is

```clojure
(def ^:private defining-heads
  (maps/from_list
    (list (erlang/list_to_tuple (list "def" "value")) ...)))
```

`list_to_tuple` is handed a **reader meta wrapper whose inner is a bare list of
item forms** — `{:meta, ["def", "value"], %{offset: 5801, "end-offset": 5821}}` —
rather than the evaluated list `["def", "value"]`, or a proper node
`{:meta, {:list, [...]}, pos}`. The inner being `["def", "value"]` (binaries, not
nodes) and the position map using `"end-offset"` as a STRING key identify it as a
reader/boot-tier artifact: the bl reader's own maps are keyword-keyed
(`priv/boot/reader.bl:210`), while `lib/beam_lisp/reader.ex:81` is the Elixir
side. Offset 5801 lands on exactly that `(list "def" "value")` form.

It is NOT caused by `c9202152` (the seed check) or by the boot-tier rebuild: the
same driver loaded from source FINE at 18:24 (the rebuild's `ensure_loaded
"build"` reached `ns-interface` through `build-plan`/`source-graph` and
completed, `built: 9`), and crashed at 18:28.
