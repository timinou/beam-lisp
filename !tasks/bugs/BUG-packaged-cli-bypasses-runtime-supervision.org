#+TITLE: Packaged CLI bypasses native application supervision
#+DATE: 2026-10-13
#+STATE: FIX VALIDATED — fresh complete SDK rebuild pending

* Reproduction
Clean source SDK47c38fa4, payload75f2ecd0, passes full selfbuild verification.
Invoke stock drop CLI from isolated HOME scratch/XDG roots. A native probe
reports BeamLisp.Supervisor=nil, owner collector=nil, application mod=undefined,
despite Env and its native index existing. Native owner inventory is unavailable.
A managed source actor also refuses its native registration bridge in a fork.
No product pins or production were changed.

* Root cause
tooling/drop/src/common.rs CLI_ENTRY enters bl.cli/main through release eval.
Eval mode starts no applications. bl.cli/main calls AOT.boot directly, which
starts unsupervised Env/Loader processes and seeds the language. It never starts
the runtime application, so Application.start's supervised services are skipped.
The source launcher correctly uses Launcher.start_app! and does not expose this.

* Fix and acceptance
Enter the PINNED HOST Launcher.start_app! directly from Rust's CLI_ENTRY. A BL
namespace shim may auto-boot Env BEFORE its body, so changing only bl.cli/main
is too late and fails application startup with an already_started Env. Share startup, provisioning fallback, native
readiness, command dispatch and exit handling; remove the duplicate boot path.
Test an unpublished dirty prototype artifact before committing/fresh full SDK
assembly. Require native Supervisor/collector presence and table ownership,
managed actor registration in a fork, ordinary CLI exit codes and existing
provisioning fallback regressions. Do not patch Knowledger or Foundry startup.

Dirty native-entry prototype now reports actual Supervisor/collector PIDs,
loaded application mod and valid inventory. It successfully registers actors
inside a private Env fork in the alternating startup probe. Native entry/fallback
batch passes110 assertions, including a fresh child VM that enters the pinned
host before any namespace and validates a real fork-owned actor. Rust launcher
tests:82passed. CLI_ENTRY now calls Launcher.start_app! directly; bl.cli/main is
a compatibility delegate for already-started callers. Full SDK47 was rejected
and never imported or selected by either consumer. Rebuild from the committed
fix, then run packaged native/consumer acceptance before updating source pins.
