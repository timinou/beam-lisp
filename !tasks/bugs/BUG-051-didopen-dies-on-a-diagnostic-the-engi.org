* Initial Message

bl lsp serve: handler raised: textDocument/didOpen: no function clause matching
in String.codepoints/1

— reported while working in =blueprint=, on the shipped drop in PATH.

* Symptom

Opening one file in an editor (or the harness's LSP) produced:

```
bl lsp serve: handler raised: textDocument/didOpen: no function clause matching in String.codepoints/1
```

and **no** =textDocument/publishDiagnostics= for that document at all: the
notification carried the raise out of the handler, so the editor saw a file with
no diagnostics rather than a file with a squiggle.

* Repro (measured 2026-09-15, blueprint at src/printflow/kpi.bl)

=kpi.bl= carries exactly one diagnostic, from the emission-linearity engine:

```
$ bl lsp check src/printflow/kpi.bl
── printflow.kpi ──
  diagnostics (1):
    0:0  snapshot: emitted IR duplicates a 9-node subtree ×2 (…)
```

=0:0= is the whole story: the position is 0. A minimal LSP client that sends
=initialize= + =textDocument/didOpen= for that file gets two messages back
(initialize, shutdown) and the stderr line above. The same client on
=src/blueprint/stock.bl= gets its publish normally.

* Cause

=system.linear/diagnostics= stamps a body annotation without a line as
=:line (get ann :line 0)= *(and =typed/warn!= spells a warning with no node to
point at the same way: =:line (if (nil? pos) 0 …)=)*. The LSP's position
converter then did this:

```
l (if (and (int? line) (<= line (count lines))) (get lines (dec line)) "")
```

=line 0= passes =<= (count lines)=, so the index is =-1= — and beam-lisp's =get=
answers *nil* off the end of a list rather than raising. The nil travelled one
call further into =String.codepoints(nil)=, which is where it finally raised, in
a handler that owes the editor an answer. =publish-diagnostics= wrapped the
ANALYSIS in a try but mapped =diagnostic->lsp= over the results *outside* it, so
the lowerings of every diagnostic were the unprotected half.

* Fix (this branch: priv/lib/lsp/rpc.bl.md + test/bl/system/lsp_rpc_test.bl)

The conversions are now TOTAL, which is what a protocol boundary owes its peer:

  * =line-text= is the single place a 1-based line meets the document: it clamps
    into =[1, (count lines)]= and returns =[line text]=. =bl->lsp=, =line-range= and
    =line-end= all go through it, so a position that cannot exist becomes the
    top of the file — what =diagnostic->lsp='s =(or (:line d) 1)= already
    intended — and never an exception. A column before the first codepoint
    counts 0 instead of driving a negative =take=.
  * =lsp->bl= clamps the CLIENT's line the same way (=line -1= is not an index
    off the end, and a =line= that is not a number has no =inc=), while a line
    the document does not have still yields no text — an empty result upstream.
  * =publish-diagnostics= lowers INSIDE the try with the analysis: the publish
    has one job, never take the didOpen down with it.

$ ./bl test test/bl/system/lsp_rpc_test.bl
  ✓ system.lsp-rpc-test  62 passed

# the same file with the fix reverted (undo of the two edits):
  ✗ a-line-outside-the-document-clamps            (4 assertions errored/failed)

The last test injects the positionless warning through =typed/warn!= — the
engine's own way of recording one — so it fails loudly if the merge path stops
carrying them rather than passing vacuously.

* Not fixed here (deliberate)

The ENGINES still spell "no position" as 0 (=system.linear/diagnostics=,
=typed/warn!=). 0 is a lie about a position, but it is a lie *below* the
protocol boundary: =bl check='s baseline and =bl lsp check='s report both read
those numbers, and re-spelling them as =nil= would move the term report and every
baseline with it. The boundary now absorbs it, one place, for every engine
present and future.
