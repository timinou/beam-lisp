* Symptom

    mods = AOT.compile_file("priv/datom/store-redb.bl", output_dir: out)
    #=> [BeamLisp.Ns.Datom.Store-redb]        # ONLY the ns module

    # purge the runtime-created host, load the AOT module, run its init
    host after purge:     false
    host after AOT init:  false
    available?:           false

So an AOT-compiled deployment starts WITHOUT its native backend, and
nothing says so. `datom.store-redb/available?` answers false, the layer
above quietly selects an in-memory store, and a database that was
supposed to be durable is not.

Silent loss of durability is the worst shape this could take. There is
no crash, no warning, and the only symptom is that data disappears on
restart — discovered in production, long after the deploy.

* Cause

`defnative` calls `BeamLisp.Native.declare/3`, which creates the host
module with `Module.create` at RUNTIME. `BeamLisp.AOT.emit_module/5`
emits only `BeamLisp.Ns.*` modules, so the host is never written to
disk, and the AOT module's `__bl_init__/0` does not recreate it either:
the `defnative` form was consumed at compile time and left no
instruction behind.

The runtime path works because `require`-ing the namespace re-evaluates
the form. AOT exists precisely to skip that, so the two disagree.

* Fix, two options

1. *Emit the host module too.* `declare/3` already knows the stub AST;
   AOT would need to write it out as a second `.beam` alongside the
   namespace module. Most faithful — the AOT output then contains
   everything the runtime path creates.

2. *Re-declare from `__bl_init__/0`.* Record the crate and signatures
   in the namespace module's init, so loading it recreates the host.
   Smaller change, and keeps the host's construction in ONE place
   (`Native.declare/3`) rather than duplicating the AST-building in
   AOT.

Option 2 is better on those grounds, and it also covers hot-reload:
`__bl_init__` runs on load either way.

* Tests

* Note

`mix compile.beam_lisp` (the AOT driver) is not currently run in this
repository's default build, which is why the whole suite passes with
this bug present. That is itself worth noting: an AOT path nothing
exercises is an AOT path that will break.
