#+TITLE: Ordered projection coalescing: queued navigation must supersede old-route work
#+STATE: DONE

* Evidence
Knowledger ORA 2026-10-06: first Library patch at 7213 ms (2635 ms initial
mount followed by navigation), Activity patch at 7049 ms, Inbox at 1302 ms.
Running runtime c2b52a46, source 54e4c613; new fixes are not deployed there.
Existing socket commits defer only to commits, never queued navigation;
every navigation in a burst projects intermediate routes. Existing assign
lookahead crosses intent/compound/call boundaries; synchronous navigation
can defer its promised projection to a future commit.

* Structural fix
live.projection is a pure ordered decision module. Only a guaranteed later
projection can subsume work. Commits and navigation coalesce ahead of queued
navigation; same-path assigns coalesce only before the first event barrier.
Calls, intents, compound gestures, transport/unknown messages are barriers.
Local call and intent feedback project immediately. Compound inner steps keep
their existing projection behavior. No timers, debounce, lost writes, opt-in
attribute declarations or downstream developer configuration.
Socket decoding stops at the first conclusive message; no mailbox-wide map
allocation/lazy capture walk is added. The final queued event always projects.
This does not cancel a render already running, bound a single expensive view,
or guarantee latency under an unbounded incoming message stream.
