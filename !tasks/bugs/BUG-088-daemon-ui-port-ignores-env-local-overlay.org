#+TITLE: daemon UI port ignores .env.local.bl :ports overlay
#+STATE: DONE
#+CUSTOM_ID: BUG-088-daemon-ui-port-ignores-env-local-overlay

* Report

`vm.spec`'s header documents the gitignored `.env.local.bl` overlay with the
exact example `{:ports {:ui 7700}}` — "a pinned port". But the daemon's UI
claim never sees it: `vm.session/project-ui-port` reads `bl.env/project`,
which loads ONLY env.bl (no overlay), so a local `:ports {:ui N}` silently
falls through to an ephemeral port. Observed 2026-09-20 in the repl worktree:
`.env.local.bl = {:ports {:ui 7860}}`, dashboard came up on 60479.

* Root cause

Two readers of the same declaration: `vm.spec/read` overlays
`.env.local.bl` (deep merge, local wins) and feeds `vm.manager`; the UI
claim bypassed it with a second, overlay-blind reader (`bl.env/project`).

* Fix

`project-ui-port` reads `(spec/read root)` → `:ports :ui` — one reader for
project declarations, the overlay applies everywhere. spec/read never
raises, so the bl.env ensure_loaded + try/catch dance goes with it.

* Found by

PLAN-135 Phase 1 (web REPL daemon mount), while pinning a UI port for the
repl worktree.
