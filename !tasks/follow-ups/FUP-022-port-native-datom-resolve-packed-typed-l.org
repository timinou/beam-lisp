** Context
The redb datom backend was removed (user preference; fjall is the durable
backend, passes full conformance). redb uniquely carried ONE capability with no
fjall equivalent: the native `datom_resolve` NIF (native/datom_redb/src/resolve.rs,
211 LOC) — a Rust-side inclusive range scan that decodes the packed TAG_DATOM
format into parallel typed e/a/v/tx/op columns in one crossing, and a Scan
protocol override (datom.store/Scan) that routed range materialization through it.

fjall's store returns range values and the generic `datom.store/scan-datoms`
falls back to reading the range in bl. So removing redb removes the packed-decode
FAST PATH, not correctness — every query still resolves correctly over fjall via
the generic scan.

If a datom workload over fjall shows range-materialization as a hot cost:

    datom.index/scan-datoms picks the native path;

    already present — reuse it.
