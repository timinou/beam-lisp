* Why

`crate-fresh?` in `priv/std/vm/native.bl` answers "is the installed
`priv/native/<crate>.so` newer than every source of the crate?". That is a
clock, not an identity: a foreign or stale artifact from another crate is newer
than the real sources and reads as fresh FOREVER (BUG-094 — a Vm.Cell library
installed as `lazy_memo.so` survived every rebuild and killed the boot on every
command, reported as a *missing* runtime).

* What to do

Make freshness a question about the artifact, not its mtime:

1. Read the module name the crate declares. Rustler crates name it in
   `native/<crate>/src/*.rs` (`rustler::init!("Elixir.BeamLisp.LazyMemo" …)`),
   so a scan of the crate's sources for `"Elixir.[A-Za-z0-9._]*"` yields the
   set of names the crate may declare.
2. Require the installed artifact to CONTAIN one of them (a byte scan of the
   .so is enough — that is exactly how the mismatch was found by hand:
   `strings -a <so> | grep -o 'Elixir\.BeamLisp\.[A-Za-z0-9._]*'`).
3. Not containing one ⇒ NOT fresh ⇒ rebuild, overwriting the foreign file.

A crate that declares no such name should be skipped (conservative), not
failed: the rule must never turn into "every boot rebuilds every native".

* Acceptance

- With a foreign library copied over `priv/native/lazy_memo.so`, `bl build`
  rebuilds the crate instead of leaving it (today: it reports "from cache").
- With a correct artifact, `bl build` still reports "from cache" — no
  regression in boot time.
- `bl native build` (the remedy the new lazy_memo message prints) repairs a
  foreign artifact without needing the `rm` first.
