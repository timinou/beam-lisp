**What happened.** PLAN-106 step 3's cheap rung searches a small box of assignments and answers `sat` when one satisfies every parsed assertion. That is sound *only as far as `guards`/`holds?` read the assertion correctly*: a term that parses into a guard but is evaluated wrongly turns a non-model into a "sat". Measured, not suspected: with the rung on the default path, `test/bl/system/z3_pool_test.bl`'s concurrent soak reported **1 wrong answer of 200** (`= 0 (reduce …)` → `actual: 1`).

**What was done instead of shipping it.** `system/decide/decide` is the oracle only (records the fragment, no shortcut). The ladder lives in `decide/decide-native` and is opt-in: the rung is the thing *under test*, not a prover. Provenance is closed by construction: a `"holds"` verdict means an unsat was proved, and the rung never claims unsat, so a proof reports `:z3` whatever the per-process trail saw.

**Work needed.** 1. A minimal counterexample: find the assertion pair the rung mis-answers. Candidates, in order: `and`/`or`/`not` nesting that parses partially; operator precedence in `holds?`; an assertion whose guard is parsed but whose *term* is not (so the guard is checked against the wrong variable); `Int` vs `Real` division. 2. **FOUND, FIXED, PINNED (2026-09-13) — a1a7282.**

The counterexample hunt was enumeration, not inspection: every guard pair over a small guard set answered by BOTH the rung and z3. 256 pairs → **12 disagreements**, all one shape. Minimal:

    (assert (> x 5)) and (assert (> (- x) 5))       x > 5 and x < -5 — unsatisfiable
    rung: SAT (witness {"x" -2})                    z3: unsat

**Root cause, three holes with one cause** — a value the rung does not have read as a satisfied guard:

 1. `guard-of` took ANY 2-arg comparison whose right side was a number, so `(> (- x) 5)` became a guard over a variable named by the printed form of `(- x)`. That key can never occur in an assignment → `(get assign …)` → nil → and **Erlang sorts atoms ABOVE all numbers**, so `(> nil 5)` is TRUE. The guard passed vacuously.
 2. `holds?` compared against nil for a variable that was never assigned, where `>`, `>=` and `distinct` answer TRUE.
 3. `declared` collected every `declare-const` whatever its sort (a Bool-sorted name was modelled as an integer), and `guards` silently DROPPED an assert it could not read and answered about the rest.

Fixed at all three levels: a guard now requires a bare name; `holds?` requires the key to be present; a variable whose sort cannot be evaluated is not modelled at all; and a question is all of its assertions or none of them.

**Measured after:** pairs 256 → **0 disagreements** (was 12); triples **8000 → 0**; a Bool-sorted variable → rung silent (was a free `sat`); `z3_decide_test` 22 → **27 passed**, with the counterexample, the undeclared name, the unmodelled sort and the unreadable assertion all pinned as regression tests.

**Still opt-in, deliberately.** Soundness is now an argument plus a measurement, not a proof, and switching the rung on is a change of VERDICTS — that wants a measured benefit. Structurally the benefit is thin where it would run: the rung can only ever answer `sat`, and the verifier's obligation questions are discharged by `unsat`. Its real home is the repair/counterexample direction, which is what "is another native rung worth building?" should now be asked about.
