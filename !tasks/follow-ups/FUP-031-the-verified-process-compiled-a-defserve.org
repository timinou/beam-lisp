* What this is, from zero

beam-lisp is a Lisp on the Erlang VM. =defserver= declares a supervised
process (an OTP GenServer) as message-handling clauses over a state map, with
an optional invariant:

#+begin_example
(defserver ^{:invariant (>= balance 0)} account
  (init [] (ok {:balance 100}))
  (handle-call [:withdraw amt] [_ {:keys [balance]}] :when (<= amt balance)
    (reply :ok {:balance (- balance amt)})))
#+end_example

=priv/lib/system/model.bl= reads such a process down to ONE normalized object
— a set of TRANSITION CLAUSES ={:label :pattern :guard :next :body}= — and
=priv/lib/system/core.bl= (the model checker) asks z3 whether the invariant
holds under EVERY transition, for EVERY reachable state. When it says
=:holds true=, that is a proof over all states, not a test over some inputs.
(=docs/what-is-possible.md= shows six such proofs in a few lines each.)

Separately, beam-lisp now has a pipeline that takes a function the compiler
proved pure + terminating, lowers it to a small integer IR, and JIT-compiles
it with Cranelift (measured ~145–800× vs the interpreter, byte-identical).
Today it lowers two shapes: a scalar fold loop and a byte-store loop.

This item joins the two: a =defserver= whose clause bodies are all in the
arithmetic fragment (counters, phases-as-enums, bounded integers — most
protocol state machines) lowers AS A WHOLE to one native step function
=(state, message) → state'=. Because the invariant was PROVED for all
states, the native step needs no runtime checks at all; because each clause
is proven pure + terminating, the step is a straight-line dispatch over
integer arithmetic. The same source is a supervised OTP process AND a
~10-nanosecond native transition. "Proved correct, therefore fast" — the
proof is what licenses removing every check.

* Why it is gated

- New lowering SHAPE: multi-clause dispatch. Today's lowerer
  (=research/lowerers_spike/lower2.bl=) handles one counted loop; a step
  function is a =switch= on the message label, then per-clause guard
  (=:when=) and next-state arithmetic. The IR (=research/j1_probe/src/main.rs=
  =parse_ir=) has no branch/compare/select ops — they must be added
  (=icmp=, =br=, =select= or a =blocks= notion) and the JIT extended. That is
  the bulk of the work and it must stay small and sound.
- State representation: a map ={:balance :phase}= must be laid out as a
  fixed struct of i64 slots; enums (=:idle :open :closed=) as small ints. The
  model checker ALREADY assigns sorts/discriminants (=system.smt=
  =sort-of-tags= / =variant-ctor=); reuse that assignment so the native layout
  and the proof agree by construction.
- Needs the in-VM JIT host (FUP-028) to actually dispatch from a running
  GenServer to the native step.
- Messages with non-integer payloads (strings, nested maps) are out of the
  fragment; such a server is simply refused (named reason), like today.

* The concrete work (in order)

1. =system.model= → clause list is the INPUT. Write =lower-step= that takes
   the clause list + the model checker's sort assignment and emits IR for:
   dispatch on label int → guard (arithmetic compare) → next-state slot
   writes. Refuse with a named reason on anything outside the fragment.
2. Extend the IR + JIT with =icmp= (eq/lt/le), =br= (conditional jump to a
   labeled block), =select=. Keep the text IR format; add a
   =--run-step IR STATE_FILE MSG_FILE= probe mode.
3. Oracle test (compiler-dev only): for the six =docs/what-is-possible.md=
   servers that are in-fragment, drive 10k random message sequences through
   the interpreter's =handle-call= and through the native step; assert
   identical state after every step. Also assert the INVARIANT holds at every
   native step — a second, independent witness that the proof and the
   lowering agree.
4. Wire =(defserver ^{:invariant … :native true} …)=: at define time, run
   the model checker; if =:holds true= and =lower-step= accepts, compile via
   FUP-028 and route =handle-call= through the native step (the GenServer
   shell stays; only the state transition goes native). If either fails,
   stay interpreted and print the theorem that failed.
5. Measure: transitions/sec interpreted vs native on the =account= and
   =conn= examples. Doc: =docs/tools/NN-the-verified-process-compiled.bl.org=.

* Acceptance

- The =account=, =conn=, and =job= servers from =docs/what-is-possible.md=
  run their transitions natively with identical results to the interpreter
  over 10k random sequences (test), and the invariant holds at every step.
- A server with a string payload or an effect in a clause is refused with
  the reason named; it keeps running interpreted.
- Measured transitions/sec, both ways, in the doc.

* Non-goals

- Lowering =handle-info= / =receive= with timeouts or process effects — the
  step is pure state arithmetic; everything else stays in the OTP shell.
- Replacing the model checker — it is the INPUT, unchanged.
- Any end-user oracle step: the random-sequence comparison is a TEST.
