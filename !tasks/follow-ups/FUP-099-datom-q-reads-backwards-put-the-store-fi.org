* The ask

Switch `datom/q`'s first two arguments. Today:

```clojure
(datom/q '[:find ?e :where [?e :schedule/id ?i]] (datom/db conn) :night-audit)
         ^^^ the question                                  ^^^ the store
```

The store should come FIRST:

```clojure
(datom/q (datom/db conn) '[:find ?e :where [?e :schedule/id ?i]] :night-audit)
```

* Why it is not a taste question

The current order was inherited from Datomic's `(d/q query db)`, and it fights
the rest of this language. Every collection verb here is SUBJECT FIRST —
`(get m k)`, `(assoc m k v)`, `(get-in m path)`, `(update m k f)`, `(contains? m k)`.
The store is the subject; the query is what you ask it. `q` is the one verb that
reads backwards, and the cost is real rather than cosmetic: writing the P2c probe
this session, `(datom/q conn '[...])` compiled and failed with **"invalid query"**
— the arguments swapped and the error named neither. A reader who has just
written `(get db …)` four times will write `(datom/q db …)`.

* Scope: ACROSS BEAM-LISP REPOS, so it waits

`datom/q` is called from every repo that uses the database — the tree here,
knowledger, blueprint — so this is a cutover, not an edit. The user's call:
file it and let it wait until the repos can move together.

* Shape of the change

1. `priv/lib/datom.bl`: `q`, and its siblings that share the shape —
   `q-df`, `pull->df`, `explain`, and anything else taking `(… db & inputs)`.
   Check each rather than assuming the family is uniform.
2. A **deodorant smell** to do the mechanical part, which is exactly what
   FUP-095 (the tail rest-pattern) and FUP-096 (a smell that can edit the `ns`
   form) were filed for:
   ```clojure
   (defsmell q→db-first :migration
     (datom/q ?q ?db) => (datom/q ?db ?q))
   ```
   The pattern is EXACT ARITY (rewrite.bl:141-145), so `& inputs` cannot be
   captured by the pattern — the rule needs the rest-pattern from FUP-095, or it
   must be written as one rule per arity actually seen in the call sites. Count
   them before choosing.
3. Because the arities are variadic (`q`, `q-df` take `& inputs`), the smell's
   coverage must be MEASURED, not assumed: run it across the tree, then grep for
   `datom/q` with 2+ args and confirm every hit was rewritten or deliberately
   skipped.
4. One commit per repo, in the order the repos can absorb it, with the old order
   accepted for exactly one release (an arg-order change is silent and total:
   every caller that is not rewritten becomes a query against the wrong value,
   so the transitional period is when `q` should ACCEPT BOTH and warn — the same
   trick as a database column rename, and it makes a missed call site loud).
