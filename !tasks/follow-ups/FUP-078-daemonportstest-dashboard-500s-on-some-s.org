* Root cause (hypothesis, evidence-backed)

The FUP-074 shared-global-name class. `BeamLisp.Daemon.Server.init/1` calls
`Workers.ensure_started(root: root)`, and `ensure_started` returns the EXISTING
globally-named `Workers` supervisor on `{:already_started, pid}`
(workers.ex). The dashboard test starts a fresh `Server` on a TEMP root but
reuses whatever `Workers` (hence `Executor`) is already registered. When a
prior test in the same file has torn its `Workers` down (or it is mid-shutdown),
the dashboard test's intent runs `GenServer.call(Executor, ...)` against a name
whose process just died -> `no process` -> the HTTP handler 500s. Seed order
decides whether the prior teardown overlaps this test's call.

* Fix directions (not yet done)

  1. Have the dashboard test (and the ports setup) OWN a fresh Workers for its
     temp-root Server rather than reusing the global one -- the same lifecycle
     ownership `daemon_index_worker_test`/`daemon_workers_test` adopted
     (`start_supervised!({Workers, root: ..., build: false})`), so ExUnit tears
     it down deterministically and no test inherits another's dying supervisor.
  2. OR make `Server.init` verify the reused Workers is healthy (Executor alive)
     before proceeding, restarting it if not.

Direction 1 is the established pattern and the smaller blast radius. Left as a
follow-up because it touches main's own test file and the failure is main's, not
the branch's -- the three failures this turn set out to fix (BootBuildBarrier
tier list, SelfBuildGate aws_signature .app dup, DaemonPorts MCP cold-index
timeout) are all resolved.
