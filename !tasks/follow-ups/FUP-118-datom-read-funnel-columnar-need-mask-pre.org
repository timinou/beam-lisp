* S1 RESOLVED — the read tax is a per-row LOOKUP on a large value, and here is what that changes
** Measured law (beam-lisp 889e6cad, audit 10 / S1)
A key lookup on a large structure costs reductions in proportion to its SIZE, and a bl
function call costs ~100-150 reductions whatever it does. So a hot loop that reads a field
off `db`/`store`/the schema pays per row for the whole structure:
- integer 159 red/row; 1-entry map 171; +200 entries 448; +2 000 entries 3 079;
  +20 000 entries 28 889 (semantica/benches/probe-arglaw.bl)
- the fjall-backed `db` 919 red/row versus the ets fixture's 218 for the SAME call;
  capture and argument are equal (2 996 vs 3 079) — it is the lookup, not the call.
`filter-datoms` read `basis-t`/`:since-t`/`:valid-at`/`:valid-between` off `db` inside its
per-row loop through `visible? -> within-basis? -> basis-t`. Fix: hoist the scalars, call
less, delete the near-copy helpers. Result, in reductions:
- `db/datoms` :chunk/src 67 400 879 -> 16 601 261 (-75%); :chunk/text 94 254 359 -> 41 163 093 (-56%)
- whole-column `q` 250 967 236 -> 198 352 268 (-21%); read share of `q` 43% -> 24%
- clean process, real column, filter alone: 1 008 -> 217 red/row (4.6x)
** What this does to W2b / W2c (their justification was wrong, their work is still right)
S3 showed the read LAYER costs the same in `:columns` mode as in `:datoms` mode, so
"never decode 64 708 chunk texts" buys far less than this file originally claimed. What is
left, and is now measured, is TERM CONSTRUCTION AND CALLS: every per-row predicate and
every per-row field read is ~100-150 reductions, times 64 708 rows. W2b/W2c therefore buy
*behaviour, not decode* — restate their acceptance as "rows that never become terms", count
them at the NIF boundary, and do not claim a decode win.
