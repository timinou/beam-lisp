* The three measured constraints

  1. **The runtime can never be COMPILED, only LOADED.** `BeamLisp.Set.member?`
     (`lib/beam_lisp/set.ex:39`) hashes through the runtime, and the host
     compiler calls it on every node. So compiling `rt` needs `BeamLisp.Ns.Rt` —
     the module being compiled. `bl build` compiles every namespace in a built
     tier, so `rt` under `priv/std/` breaks the build (measured: exit 70 there,
     exit 0 moved back out). **The runtime can only arrive as a BEAM — the seed,
     or the AOT cache.**

  2. **The boot order cannot simply be reversed.** `seed_core` must precede the
     prelude; the prelude enables the reader; the reader calls `not=`, a
     `core.bl` defn. Loading `rt` before `seed_core` dies with
     `undefined var: core/not`.

  3. **Boot-tier code reaches the runtime at COMPILE time** — `anf.bl`
     (`BeamLisp.RT/vector?`), `reader.bl:794` (`BeamLisp.RT/data_reader`),
     `compiler.bl` (`RT/invoke`, `RT/call_shape_error`). These must go to a HOST
     module: the compiler must not depend on the language it bootstraps.

* The work, in order

  (a) Re-point the boot-tier call sites above at host modules
      (`BeamLisp.Vector/…`, `BeamLisp.Env/…`) rather than the runtime.
  (b) Staged bootstrap, ~3 build+seed cycles in a fixed order:
        i.  build with the OLD `lib/` (so `BeamLisp.RT` still answers the
            compile-time callers), carrying `rt` as beams;
        ii. switch to the new `lib/`, rebuild, regenerate the seed — so `rt`'s
            own beams are built by the new compiler;
        iii. delete `lib/beam_lisp/rt.ex`, rebuild, verify the fixpoint.
      `priv/build/seed.bl` already has the mechanism to carry a family into the
      floor — see `runtime-namespaces`, which this session wrote and reverted.
      `priv/std/multi.bl` is the precedent for a seeded prelude layer.
  (c) Drop the bootstrap crutch from `lib/beam_lisp.ex`, letting `init` load `rt`
      BEFORE `seed_core` — correct once `rt` is seeded, because a seeded
      namespace is loaded, never read.

* Sharp edge found while diagnosing

  Changing a `priv/boot/` file changes `compiler_key`, which invalidates the AOT
  cache, which forces the prelude to be evaluated FROM SOURCE. In that path the
  reader reads `core.bl` and hits its own dependency on `core.bl`'s `list`
  (reader-node.bl:123). Symptom: `undefined var: reader-node/list`, naming a file
  not at fault, from a one-line edit. `boot-deps.bl` makes this visible before it
  bites.

* ATTEMPTED: put the runtime in the seed FIRST, then flip (the cheap route)

The idea — and it is the right shape — is that the runtime only has to be
COMPILED once, before the rename, when `BeamLisp.RT` still exists and
`BeamLisp.Set.member?` still hashes through it. After that it lives in the
floor as beams, and the flip never has to read it. That removes the staged
three-cycle bootstrap entirely: two steps, not three.

So the trigger is specifically the runtime's presence in the library tier.
Prime suspect: adding the runtime's own defns to the Env while the driver
compiles its neighbours changes what a bare name resolves to — `rt` exports
`invoke`, `hash-key`, and a great deal more. Second suspect: the driver's wave
ordering changing with 16 new namespaces. Neither is confirmed.
