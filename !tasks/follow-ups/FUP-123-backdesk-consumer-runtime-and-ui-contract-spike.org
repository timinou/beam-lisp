* Finding B — nil is absent in the model but was a DOM node in the client

Confirmed minimal browser reproduction against the served unpatched client:

#+begin_src javascript
const el = Live.render(['div', {}, null, ['button', {}, 'Send']]);
el.childNodes.length; // observed 2; model/diff expects 1
#+end_src

live.diff normalizes/splices nil children away. live/client.js render(null)
created an empty TEXT node. Later path-indexed set-attr operations therefore hit
the wrong child: a conditional dialog looked plausible but its Send button
remained disabled or its click handler was not updated. Nested sequences exhibit
the same structural disagreement. This is not an application business-rule bug.

Local corrective patch (not yet landed upstream):

#+begin_src diff
- if (node === null || node === undefined) return document.createTextNode("");
+ if (node === null || node === undefined) return document.createDocumentFragment();
#+end_src

Consumer commit 881c869 carries tooling/backdesk-client-null-child.patch and
14 browser regressions in test/film/client-render-test.mjs. Apply the patch only
to an isolated payload's priv directory with -p1. The tests cover leading and
trailing nil, nested sequences, path-indexed updates, boolean attributes and
on-click -> data-ev-click translation. They pass on the patched served client.
No upstream fix commit is claimed: history search found no corresponding
createDocumentFragment change when this was filed.

* Finding C — a correct upstream input primitive must be adopted by the app

The app initially embedded a draft string into the button's rendered payload.
Typing followed promptly by clicking could submit an earlier prefix: the input
had arrived at the server, but the newly rendered button had not returned yet.

Verified upstream fix: 25b799c41b9df0185184b0937be7d53a78150e08,
"client locals cannot forge identity, and an intent reads live state without
racing the render". git tag --contains reports v2026.4. That commit:
- moved authenticated identity and privileged closures outside editable locals;
- added recursive [:live/local key-or-path] resolution against CURRENT locals,
  before authorization, plus [:live/literal value] escaping;
- preserved literal view keys on payload conflicts;
- introduced a keyed route boundary.

Consumer bf266cc adopts [:live/local ...] for report, reply, correction and
handover text and picker values. No custom client business model was added.
Locals remain untrusted UI data, not identity or authority. A related gotcha:
JSON/query values are strings while native keys/families may be keywords; the
consumer normalizes those at its boundary rather than relying on equality
between representations. The default picker also needs a value before the first
change event; that is an explicit consumer fallback, not invented client state.

Research question: can the framework make a rendered mutable-local snapshot in
an intent visibly suspect, or document/test the safe idiom so applications do
not rediscover the race? Do not reimplement the already-shipped primitive.

* Finding D — missing prelude name is not necessarily a missing library

Bare ffirst and re-seq both failed with undefined-var errors in the consumer.
Inspection distinguished two cases:
- ffirst was absent from the loaded core: implemented once as (first (first xs)).
- re-seq ALREADY exists in priv/compat/clojure/re.bl, but is not automatically
  referred. Reimplementing Regex.scan locally would duplicate the language.

Consumer 4e975b3 adds src/blueprint/compat.bl: ffirst plus an eager vector facade
that REQUIRES and DELEGATES to clojure.re/re-seq. Its 22 assertions cover empty
and nested firsts, absent/repeated/captured matches, compiled patterns, malformed
patterns and terminating zero-length matches. The UI suite now passes 21 checks.

The contract is deliberately narrower than JVM parity: the Regex backend may
elide trailing nonparticipating groups rather than return nil placeholders; the
suite records that limit. Do not upstream a misleading claim of full Clojure
compatibility. Research discoverability/prelude policy and optional-capture
fidelity separately. Related but not the same failure: current HEAD fb34c7d0
fixes std namespace visibility in the durable ANALYSIS Env; our undefined names
were runtime/import issues, not proof of that analyzer defect recurring.

* Research spike — execute this next, before proposing broad implementation

** 1. Artifact capability matrix

In disposable XDG_DATA_HOME roots, compare the published binary, a current clean
self-build and the minimal overlay. Record executable hash, source commit,
application versions and closure. Probe: doctor, HTTP GET, WebSocket 101, one
intent and a second independently authenticated view receiving its effect.
Use an ephemeral/captured port; do not borrow a developer's live server. Determine
whether missing application closure, stale assembly metadata or another measured
cause explains the released payload. Also test occupied-port/readiness failure:
a printed URL must not be mistaken for a listener that actually started.

** 2. DOM/model differential contract

Build a tiny generic live fixture with no hospitality data. Compare SSR/model
normalization, Live.render and patched DOM after dynamic insertion/removal.
Exercise nil, nested child sequences, mixed text/elements, boolean attributes,
changed event payloads, focus, navigation while connecting and reconnect.
Pin the law: the model's child path identifies the same node in the DOM after
every generated transition. Use deterministic traces/shrinking where practical;
do not settle for a screenshot of the initial page.

** 3. Input and namespace ergonomics

Type a distinctive multiword value and click immediately under delayed render
responses. Compare embedded snapshots with :live/local, including nested picker
paths and literal escaping; verify authorization sees the resolved payload but
identity cannot be replaced through locals. Propose a minimal lint, example or
contract that makes misuse visible. Investigate absent-name diagnostics that
suggest an existing namespace rather than inviting a duplicate implementation.
Run optional/empty/Unicode regex cases before deciding the upstream ffirst and
regex compatibility surface.

** 4. Real application boundary fixtures

Use distinct opaque IDs for submission, media, revision and actor. Verify the
actual native projection against the actual view: failed image lookup must not
masquerade as valid evidence; changing a persisted source must change the library.
Produce a small reusable testing pattern, not a second business framework.

** 5. Deliver a measured decision

Write a research report with the artifact matrix, minimal reproducers, exact
fixing/introducing commit IDs where established, passing regression commands,
remaining unknowns and a prioritized implementation proposal. Separate:
(a) runtime bugs to fix; (b) already-fixed primitives needing adoption/docs;
(c) consumer mistakes; (d) unverified hypotheses. Name the release gate that would
have prevented each confirmed defect. Prefer one shared contract over another
adapter or cache. Do not mark this FUP DONE merely because Backdesk's local patch
works: the packaged upstream artifact and the generic regression must pass.

* Acceptance and budget

- Fresh packaged artifact serves and upgrades a minimal live app with no donor

- Generic nil/sequence differential tests fail before the fix and pass after it.
