* What is already true (so this item does not re-litigate a fixed bug)

BUG-083 was root-caused and FIXED on main. The cause was not "concurrency" in the
abstract: `lower.bl`'s `write-beam!` wrote a beam IN PLACE at a path that
`AOTCache.link_beams` had hardlinked to the cache's own inode, so a rebuild
rewrote the cache underneath every other VM reading it. Measured without a boot:
20 in-place writes over a hardlinked path produced **641 torn-or-missing reads
out of 668** in a concurrent reader; the same writes as sibling temp + rename
produced **0**. It now publishes atomically, and the lock that used to serialize
every short-lived verb was deleted, with the reasoning recorded in `bin/bl`:

  "If a shared writer is ever added here again, make IT atomic rather than
   restoring the lock: serializing every command is what made one process able
   to stop all of bl."

That conclusion is right, and it is the shape this FUP should protect. What
follows is what REMAINS, i.e. why the class can still recur.

* Root causes

**1. The cache ALIASES inodes; it does not share values.**
`AOTCache.link_beams` still hardlinks cache inodes into a checkout's compile
path ("hardlinks them into the local compile path on a hit"). A hardlink means
the local path and the cache path are ONE inode. Atomic publication protects the
cache from the writers that exist today; it does not remove the aliasing that
made the class possible. Any future writer that writes through a local path in
place — a rebuild path, a formatter, an editor save — re-creates BUG-083 exactly,
and the 641/668 measurement is the price of ONE such writer.

**2. The lock is gone; the flag that guarded it is not.**
`BL_NO_LOCK=1` is read by **nothing** in the tree. It survives in the documented
invocation, in a plan's evidence commands, and in the operating instructions
given to agents. Its cost is not runtime, it is SEMANTIC: it teaches every
reader that the cache is unsafe without a flag, which is the belief that leads
people to add locks — and the lock is what let one process stop all of bl. Stale
guidance is how a fixed bug comes back.

**3. An artifact SET has no unit of publication.**
BUG-083 was one file; the seed is 26 files plus a manifest. Measured today: after
merging main, the seed directory was a MIX (this branch's beams, main's manifest)
whose manifest could match neither side, and the failure did not name the set —
it named `beam-lisp bootstrap seed is corrupt`, then `undefined var:
compiler/special-forms`, i.e. an unrelated downstream symptom. The manifest is a
checksum RECORD but not an AUTHORITY: nothing verifies a generation as a unit on
read, and nothing repairs it.

**4. Failures are attributed downstream of their cause.**
Both bugs surfaced inside `priv/boot/reader-node.bl` / the compiler. A corrupted
cached artifact is DETECTABLE — the tree already computes digests for the seed
manifest — so a load that fails should name the artifact and treat it as a miss.

**5. Contention arrives WITH the bootstrap, it does not leave with it.**
Today the concurrent writers are agents, servers and the shipped drop; after the
bootstrap they are the language's own build tooling, and N-parallel builds are
the norm rather than an experiment (this session ran seven). A language whose
compiler cannot run twice at once has a structural defect, and it will be
exercised more, not less.

**6. The cache root is host-global and cross-checkout.**
Keyed by (compiler_key, ns-hash) under one per-user directory. Observed on this
host: a `drop`-based `serve` process from a DIFFERENT product's checkout sharing
the same user cache. Sharing immutable content-addressed values is fine; the
hazard is that unrelated trees schedule the same GC sweep and can collide on the
same keys without either knowing.

* Structural fix, ranked

1. **Make aliasing impossible, or prove it is harmless.** Keep the hardlink for
   speed if it matters, but make it a READ-ONLY alias (link, then drop write
   permission on the cache inode), so no writer can reach the cache through a
   local path; or drop the hardlink and pay the copy. Then ASSERT it: a test that
   writes through the local path and proves the cache inode's st_ino and digest
   are unchanged.
2. **Delete `BL_NO_LOCK` and every mention of it** — docs, plan evidence, agent
   instructions. Correctness must never depend on a flag, and a flag nobody reads
   is a lie about the design. If a lock is ever needed, make it per-artifact and
   advisory: a stale lock may cost duplicate work, never a hang.
3. **Give a generation an identity and verify it as a unit on READ**, not only at
   install. A mismatch means regenerate that generation. This is the same fix as
   (1) one level up, and it is what today's seed mixing needed.
4. **Self-heal a bad cached artifact**: if a cached beam fails to load, name it,
   invalidate it, recompute. Corruption becomes a cache miss, and the error moves
   from the reader to the cause.
5. **A gate, because right now atomicity is protected by a comment.** N
   concurrent compiles of the same fresh namespace, repeated; afterwards every
   artifact's digest must match and every process must have exited 0. Cheap to
   write, and it turns a heisenbug into a test that fails if the class returns.
6. **Keep the GC's `:global.trans`** — it guards a sweep BUDGET, not data: if it
   misbehaves, the store deletes slightly more or less, never corrupt. Document
   it as the one surviving lock and why, so it is not mistaken for a violation of
   (2).

* Evidence from this session

- Seven concurrent workers porting the runtime into `research/rt-cutover/`, each
  given its own `BEAM_LISP_AOT_CACHE_DIR`: **every command reproducible**; the
  only two workers that reported hangs or "AOT corruption" were the two that did
  not use their own directory. That is the whole argument for (2) and (5) in one
  observation.
- The seed-generation mix (root cause 3), fixed by taking one whole generation
  and regenerating from it: `bl seed --ebin build`, then `bl seed --check` →
  "the floor is current — 10 namespaces, every one built from the bytes on disk".

* Acceptance

- No in-place writer can reach a cache inode through a local path (test (1)).
- `BL_NO_LOCK` appears nowhere in the tree.
- A mixed generation fails as a NAMED generation with a repair path, not as a
  downstream compiler error.
- The concurrency gate (5) runs and passes in CI.
