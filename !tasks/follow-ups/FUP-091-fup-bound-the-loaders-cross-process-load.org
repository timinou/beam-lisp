* Context
BUG-064's instance is fixed and its class is now caught statically at three altitudes (PLAN-125: reload's commit gate holds a cycle, the build fails on one, codebase/require-cycles answers one). What remains is the loader mechanism itself: one process holds a `:global` `{:bl_load, mod}` lock while `Loader.Server` runs that namespace's `__bl_init__` in another process, and `:global.set_lock` retries forever — so a cycle that slips past every static gate (or arises through a path the static graph cannot see) still hangs silently instead of failing.

* The two candidate fixes (from BUG-064's own analysis)
1. BOUND the lock acquisition: wrap the `:global.trans` in `lib/beam_lisp/aot.ex` (`ensure_loaded`, around line 238) so a lock that cannot be acquired within a bound FAILS — and names the cycle. The name is now free: `BeamLisp.SourceGraph.cycles/2` (PLAN-125 commit b5b13626) answers it from the same `reqs` the loader already knows. Hang → error with the closed path.
2. MOVE the lock to the process that runs the init (the Loader.Server), so lock owner == actor and the in-process `:bl_loading` guard can see re-entry again. Deadlock → no deadlock, by construction.

BUG-064 deliberately did neither: "it is a change to the bootstrap and needs its own proof."

* Proof obligations (why this is its own item)
- A forced-cycle drop test: introduce a require cycle into a fixture tree, build a drop from it, show the cold load FAILS NAMED (fix 1) or the cycle guard cuts it (fix 2) instead of hanging. The PLAN-125 build gate will now refuse that drop at build time — the fixture must reach the loader through a path that skips the build gate (hand-rolled AOT image, or a runtime ensure_loaded) to exercise the mechanism.
- No regression on the async-fork replay invariants the lock + `:global` wrap were introduced for (PLAN-047 W1: interned vars landing in the right fork under BL_ASYNC=1).
- The retry-forever `set_lock` may have OTHER legitimate long waits (slow compiles under load); the bound must be a deadlock detector, not a timeout that fires on slow-but-fine loads (e.g. detect "the lock holder is blocked on ME" via the Loader.Server's caller set, not a wall clock).
