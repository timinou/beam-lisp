how do i turn spell (the one in spell/) into an actual program I can use?

The seam emits `@data subscribe`, `@data signal`, `@data stream` and `@data inline`, but NOT `@handle` — the form verse's own proven page (elixir/spacetime_lv/frontend/board.st) uses to consume a signal's reply or a stream:

    @handle $fx { receive { Flash(message) => { $toast <- message; } } }
    @handle $dec { optimistic { … } receive { Bumped(n) => { $count <- n; } } }

Consequences observed 2026-08-15 while verifying the live loop end to end:

1. The composer's draft is never cleared after a successful send. The contract replies `ok "accepted"` and the page has no way to act on that reply, so the sent text stays in the input — visible in the screenshot of the working loop.
2. `@data stream $fx` is decoded by the bundle, published as a signal, and consumed by nobody. The seed view works around this by rendering `@partial` (a server-owned assign the contract now assembles) instead. That is a legitimate design — the transcript is server state — but it means every declared push currently reaches the browser and renders nothing unless an assign mirrors it. verse reports the unconsumed stream as W0201.
3. Optimistic update + rollback (the pattern the bridge documents as its continuity surface) is unreachable from a contract.

Work: add an `edn-handle` emitter to spell/src/spell/contract.bl beside edn-signal/edn-subscribe/edn-stream, and a view-clause spelling for it (e.g. `(st/handle @send [:ok (st/set! @draft "")])`). Shapes must be taken from real printer output (`spacetime edn elixir/spacetime_lv/frontend/board.st`), the way every other emitter in that file was derived — not from the grammar read by eye.

Acceptance: the seed view clears `@draft` on `ok`, verified in a browser through scripts/serve_live.exs (type, send, input empties, message renders).
