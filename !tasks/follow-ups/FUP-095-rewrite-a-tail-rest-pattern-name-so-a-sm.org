* Context

`rewrite` matches a pattern against a form with **exact arity**:

```clojure
; priv/std/rewrite.bl:141-145
(list? pattern)
  (if (and (list? form) (= (count pattern) (count form)))
    (match-each pattern form binds)
    nil)
```

There is no rest/sequence pattern (`?k…`, `?*xs`, `&`), and `subst*` has nothing
to splice. So a rule must enumerate every arity it matches, and a rule whose
right-hand side needs "the remaining forms" cannot be written at all.

* Why it matters

Every "this form became that form" migration is a rule whose arity VARIES:

```clojure
(srv/defserver ?name ?*clauses) => (defserver ?name ?*clauses)
(defn ?name ?*tail)             => (defn ?name {:private true} ?*tail)
(reg/defregistry ?name ?*)      => (srv/defserver ?name (registry ?*))
```

The first is FUP-094's follow-on smell, and without it the qualifier can only be
dropped by hand across a codebase. The second is the standard way to write a
hygiene fix. Today deodorant can express truth-table rewrites (fixed arity) and
cannot express *shape* migrations. This is the single gap on that path.

The workaround in use — bind a whole sub-form as ONE variable and guard its shape
(`?keys` holding `(keys :id)`, FUP-094) — works only when the varying part is
already a single form. It cannot express "zero or more trailing clauses".

* Design

Add ONE convention, tail-only, so no backtracking is needed (mirroring a reader's
`&` in a destructuring vector, which this language already has elsewhere):

- **`?*name`** in a pattern position binds the REMAINING elements as a seq — and
  is legal only in the LAST position of a list/vector pattern.
- In `subst*`, `?*name` SPLICES its elements inline rather than inserting a seq.
- `?name` (single) is unchanged: it binds one element and may repeat for
  unification. The star is what distinguishes them; two conventions would be a
  trap, so the star must not be allowed anywhere but the tail.
- A pattern with `?*x` at a non-tail position is a DECLARATION-TIME error, not a
  silent never-match — deodorant's own doctrine ("the honest contract is that
  every correction is a RULE you can read").
- Empty tail is legal: `(f ?*xs)` matches `(f)` with `?*xs` = `()`.

Length is then checked as `(>= (count form) (dec (count pattern)))` for a
starred tail, and `match-each` must stop one short of the end and bind the rest.
Repetition/unification for `?*x` appearing twice is *deliberately not supported*
in v1 — refuse it loudly rather than guess at sequence unification.

* Acceptance

- `(defsmell t :safe (srv/defserver ?n ?*c) => (defserver ?n ?*c))` rewrites a
  0-clause, 1-clause and 7-clause server identically, and `bl fix` output loads.
- `?*x` outside the tail is refused at declaration with a readable message.
- **Zero behaviour change for existing rules**: every smell in `deodorant.bl` and
  the deodorant test suite still match exactly as before (exact-arity patterns
  take the same path they always did). This is the gate — a matcher change that
  perturbs a `:safe` rule is a correctness regression, not a feature.
- A starred pattern binds an empty seq at the shortest arity and does not match
  one element shorter (off-by-one is the whole risk).
