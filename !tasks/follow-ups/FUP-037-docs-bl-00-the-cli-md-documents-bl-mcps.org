* What is missing

`docs/bl/00-the-cli.md` §`bl mcp` lists the six tools and stops. It does not
mention that the server also answers `resources/list` and `resources/read` (the
`code://beam-lisp/schema` and `code://beam-lisp/namespaces` URIs), nor that the
tool table is served over a codebase the server MOUNTS ITSELF — indexing
`priv/std/codebase.bl` and `priv/std/typed.bl` from the installed priv tier on
the first `code/list`. A reader of the docs cannot tell:

- that `bl mcp` needs no checkout, no arguments and no `--path` (it resolves
  its sources through the load path, so it serves the same facts from any
  directory a user happens to be in);
- that the first request pays the mount (a few seconds), and later ones are
  instant (the conn is memoised in an atom);
- that `code://beam-lisp/namespaces` reports the mounted namespaces, so the
  answer changes if `MOUNTED` does.

`docs/04-editors-and-agents.md` is the other place an MCP client is described;
check whether its worked example exercises `resources/*` at all.

* Why it matters

The failure this documents (FUP-036, fixed 2026-09-11) was invisible from the
docs: nothing said the mount resolves through the load path, so "it works here
and not there" had no documented invariant to test against. The contract is
worth one paragraph: *the server serves the codebase it can load, under the
same search rules as a require.*

facts, still takes 6.5 s in a drop — that is the mount. The prose says startup
and reuses that number's shape ("the mount is paid once, at startup (a few
seconds)").
