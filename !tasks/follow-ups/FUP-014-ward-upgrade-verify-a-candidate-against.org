* FUP ward --upgrade: verify against previous commit / CI

PLAN-057 W2 shipped `reload.upgrade/verify-upgrade` + the `assert-safe-upgrade`
test verb (in-test, in priv/reload/upgrade.bl). The NEXT step, deliberately left
out of PLAN-057 scope: a ward MODE that verifies a candidate process against its
PREVIOUS version automatically — the CI use.

Design sketch:
- `mix beam_lisp.ward --upgrade DIR` (or a git-aware flag): for each process
  source in the working tree, fetch the SAME file's content at HEAD (or a named
  baseline ref) via git, and run verify-upgrade(baseline, candidate). Report a
  per-process safe/unsafe/unknown verdict; exit non-zero on any :unsafe.
- The pairing is git-based (old = the committed version, new = the working tree),
  so a developer/CI gets "does this diff preserve every process invariant?" as a
  build gate — the upgrade-rehearsal turned into a pre-merge check.
- Reuses verify-upgrade wholesale; the only new work is the git baseline fetch
  (tool/git show HEAD:path) and the file/process discovery + reporting.

Why deferred: PLAN-057's brief was the in-test verb (per user steer: "ward
--upgrade is in relation to the previous commit/CI. mention it, add an FUP, but
leave it out of scope"). The verb is the primitive; this is the CI packaging.

Honesty carries over: z3 absent → :no-z3 (skip, not pass); non-process files are
ignored; :unknown never counts as a pass.
