#+TITLE: The drop ships bandit but not websock_adapter: every live.app WebSocket upgrade 500s in a release
#+STATE: ITEM
#+CUSTOM_ID: FUP-042-the-drop-ships-bandit-but-not-websock-adapter

* Symptom

A `live.app` console served from a built drop renders (SSR is fine) and is
completely dead: every intent travels over the WebSocket, and the upgrade
answers `500`.

#+begin_example
$ bl serve app.bl                      # the app starts, pages render
$ curl -si -H 'Connection: Upgrade' -H 'Upgrade: websocket' \
        -H 'Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==' \
        -H 'Sec-WebSocket-Version: 13' http://localhost:4046/ws/
HTTP/1.1 500 Internal Server Error
connection: close

[error] ** (UndefinedFunctionError) function WebSockAdapter.upgrade/4 is undefined
        (module WebSockAdapter is not available)
    WebSockAdapter.upgrade(%Plug.Conn{…}, BeamLisp.WebSocket, %{…}, [timeout: 120000])
    (bandit 1.12.4) lib/bandit/pipeline.ex:136: Bandit.Pipeline.call_plug!/2
#+end_example

The browser's socket closes (`readyState 3`); a click that should commit an
intent and re-project the page does nothing but change the URL.

* Why

`priv/lib/web.bl` names four Elixir modules and requires them at load:

#+begin_example
(def ^:private Bandit …) (def ^:private Conn …) (def ^:private WSA (… "Elixir.WebSockAdapter"))
(def ^:private Adapter …) (ensure! Bandit) (ensure! Conn) (ensure! WSA) (ensure! Adapter)
#+end_example

`ensure!` swallows the failure (`Code.ensure_loaded/1` returns `{:error, :nofile}`),
so the module is captured as an atom and only dies at the first `web/upgrade` —
which is every live app's first socket. `web.upgrade` is the only path to a live
page: `live.app`'s router calls it for `/ws`.

The payload carries `bandit-1.12.4`, `plug-1.20.3`, `websock-0.5.3` — and no
`websock_adapter`:

#+begin_example
$ ls <drop>/lib | grep -i 'websock\|bandit'
bandit-1.12.4
websock-0.5.3
#+end_example

Bandit depends on `websock` (the BEHAVIOUR) but not on `websock_adapter` (the
implementation that answers `upgrade/4`). `mix.exs` declares bandit and
file_system "so a drop that advertises `bl serve` can run it" — the same
argument applies to the adapter, and it was missed. In a *downstream* project
this was invisible: the consumer could declare `{:websock_adapter, "~> 0.5"}`
itself (the djinn-bl console did exactly that, with a comment saying why). On
the drop there is no consumer to declare it, which is the whole point of a drop.

* Why nothing caught it

`bl doctor` probes the language, the native tier and the solver, and nothing
about the web tier. `bl serve`'s example in `docs/bl/00-the-cli.md` is a plain
`router` returning a map — no socket. The release smoke test in
`.github/workflows/release.yml` runs `bl version`, `bl eval`, `bl mcp`,
`bl lsp serve` — none of which upgrades. So the one tier a served app cannot do
without is the one tier nothing exercises in the artifact.

* Fix

1. Add `{:websock_adapter, "~> 0.5"}` to `mix.exs` beside bandit, with the same
   "a drop that advertises `bl serve` must be able to run it" reason. It is
   already in `mix.lock` (0.6.0, transitively) and `deps/`, so no new fetch.
2. Make the failure legible even if it recurs: `ensure!` in `web.bl` should
   raise a named error at load time — "web/upgrade needs websock_adapter"
   — instead of leaving a nil-ish atom to explode at the first socket.
3. Add a socket to the artifact smoke test: a drop must be able to answer a
   WebSocket upgrade (a `101`), because that is the tier `bl serve` exists for.
   `bl doctor` should carry a `websock_adapter` probe next to `datom_fjall`,
   `explorer` and `wry` — it is the same kind of optional-native line that, when
   absent, silently removes a whole capability.

* Acceptance

- `curl -si -H 'Connection: Upgrade' -H 'Upgrade: websocket' … http://host/ws/`
  from a built drop answers `101 Switching Protocols`.
- A `live.app` page's click commits an intent and re-projects (the browser's
  `WebSocket.readyState` is 1).
- `bl doctor` reports the adapter, and the release smoke test upgrades a socket.

* RESOLVED 2026-09-12 — fixed, and verified in a rebuilt drop

Landed as the one-line dep, and nothing else of the sketch was needed to prove
it:

```elixir
# websock_adapter answers the upgrade bandit hands it: bandit depends on
# `websock` (the behaviour) but NOT on the adapter (the `upgrade/4` call),
# so `web.upgrade` — and with it every live.app socket — dies in a release
# without this line. It ships for the same reason bandit does. (mix.exs)
{:websock_adapter, "~> 0.5"},
```

Verified by rebuilding the drop (`mix bl.build --out …`, which prints
`==> websock_adapter / Compiling 4 files` in the release step) and asking the
rebuilt artifact both questions:

```
$ ls <drop>/lib | grep -i 'websock\|bandit'
bandit-1.12.4
websock-0.5.3
websock_adapter-0.6.0                       # was absent

$ curl -si -H 'Connection: Upgrade' -H 'Upgrade: websocket' \
        -H 'Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==' \
        -H 'Sec-WebSocket-Version: 13' http://localhost:4046/ws/
HTTP/1.1 101 Switching Protocols            # was: 500
```

The app that found it (djinn-bl's banking console, a live.app page whose every
click is an intent) now patches live in a real browser: the socket opens
(`readyState 1`), a typed turn commits, the bank's policy answers, and the four
layers — ledger, actor, entity, orchestration — re-project.

Two tests in that tree pin it from the outside, because the artifact's own
smoke test still does not:

- `test/infra/live-socket-test.bl` — a real Bandit server with one `web/upgrade`
  route, one hand-run handshake, `101` or red. ~2 s.
- `test/loom/console-test.bl` — `bl serve` the console on its own port, assert
  the gallery renders and the socket upgrades. ~50 s.

Both also pin a rule that cost an hour to learn: **a server started while a test
file LOADS does not survive into its test bodies.** `web/serve` LINKS the
listener to the starting process, and the loader's process is torn down before
the tests run — so the listener dies and the assertions meet a closed port.
Side effects belong inside the test body, never at the top level of the file.

Still open from this item, deliberately: (2) `ensure!` in `web.bl` should raise
a named "web/upgrade needs websock_adapter" error at load instead of leaving the
failure to the first socket, and (3) `bl doctor` should carry the adapter probe
beside `datom_fjall`/`explorer`/`wry` — the release smoke test that would have
caught this is still missing.
