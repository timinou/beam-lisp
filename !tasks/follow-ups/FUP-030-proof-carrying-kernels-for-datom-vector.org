* What this is, from zero

beam-lisp is a Lisp on the Erlang VM. Its compiler can PROVE a function is pure
(no side effects) and terminates, and — given that proof — a pipeline lowers
the function to a small integer IR and JIT-compiles it with Cranelift at
native speed, with output byte-identical to the interpreter (measured ~145×
on a pixel blend; see =research/native-offload/README.md= and
=docs/tools/09-native-offload-pipeline.bl.org=).

=priv/lib/datom/vector.bl= is beam-lisp's vector index: a Rust NIF
(=native/datom_vector/=, HNSW) that finds nearest neighbours. Its distance
metric is FIXED in Rust (cosine / L2 / whatever the crate ships). If you want
a domain metric — weighted dimensions, a learned kernel, a metric over
quantized bytes — you must write Rust, rebuild the crate, and trust it.

This item: let a user write the metric as an ordinary beam-lisp =defn=,
have the compiler prove it pure and terminating, lower it to native, and hand
the resulting function pointer to the HNSW index as its distance function.
The proof is exactly what makes handing a raw function pointer into a
long-lived native index SAFE: the index calls it millions of times with no
runtime checks, and the compiler has shown it cannot diverge or touch
anything.

Users get custom similarity at native speed without touching Rust. That is
what the vector swarm work (PLAN-087) wants and cannot have today.

* Why it is gated (do this after, not now)

- The lowerable fragment today is INTEGER-only with =u8= loads
  (=research/j1_probe/src/main.rs= =parse_ir=: =imm add sub mul addimm subimm
  udivimm load store zext mov loop ret=). A metric over =f32= vectors needs
  =load32f / fmul / fadd / fsqrt= (or a quantized-u8 path first). The lowerer
  (=research/lowerers_spike/lower2.bl=) also REFUSES =nth= — vectors are
  reached via =binary/at= only. Widening the fragment is real work with its
  own correctness burden (float non-associativity means "byte-identical to the
  interpreter" becomes "within ε" — decide and document the oracle rule).
- Needs the in-VM JIT host (FUP-028): a function pointer must live in the same
  process as the index; shelling out is not an option here.
- =datom_vector='s Rust API must accept a metric callback (a =extern "C"
  fn(*const u8, *const u8, usize) -> f32= or an i64 variant for quantized
  vectors). Investigate the crate's distance trait first; adding a
  =Custom(fnptr)= variant is the likely smallest change.

* The concrete work (in order)

1. Quantized-u8 path FIRST (no float work): metric over two =u8= vectors
   returning i64 — e.g. weighted L1 =(sum w_i * |a_i - b_i|)= with weights as
   a third buffer. Prove it (=native.eligible=), lower it (add =abs= or emit
   the two-branch max idiom via arithmetic), JIT it, oracle-test byte-identical
   vs the interpreter (compiler-dev test only, per the rule that oracles are
   not end-user pipeline steps).
2. =datom_vector=: add a custom-metric variant taking a fn pointer + a
   =metric-kind= tag; expose =(vector/index {:metric {:native handle}})= from
   =vector.bl=. The handle comes from FUP-028's =compile= NIF.
3. End-to-end: build an index with a bl-defined metric, query it, compare
   the k-NN result set against the interpreter-computed brute-force answer
   (test). Measure queries/sec vs (a) the built-in metric, (b) a bl metric
   run in the interpreter via a callback (which will be catastrophically slow
   — that is the point of the comparison).
4. Float fragment (=f32= loads, =fadd/fmul/fsqrt=) with an ε-oracle rule,
   then cosine / L2 written in bl to show parity with the built-ins.
5. Docs: =docs/tools/NN-metrics-in-lisp.bl.org= — write a metric, see the
   proof, see the speed. Note the ε rule.

* Acceptance

- A weighted-L1 metric written as a bl =defn= runs inside HNSW natively; the
  k-NN results equal brute force in a test; queries/sec within 2× of the
  built-in metric and ≥100× the interpreter callback.
- A metric containing an effect (=println=) or an unbounded loop is REFUSED
  at index-build time with the theorem named — never silently run slow.
- The float path (step 4) has a written ε rule and a test enforcing it.

* Non-goals

- SIMD (PLAN-087 probe is separate; a scalar native metric is the goal).
- Changing the HNSW algorithm; only its distance function becomes pluggable.
- Any end-user oracle step: the interpreter comparison is a TEST.
