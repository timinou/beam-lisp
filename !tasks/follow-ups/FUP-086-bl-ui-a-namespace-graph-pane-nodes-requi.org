please tell me how you'd implement the rename lsp action to work on functions and on namespaces and make sure the namespaces are still working across a whole daemon's envs (rename affects all downstream apps so that e.g. when I want to reorganise the beam-lisp namespaces, my downstream apps follow and it gets shown nicely), and how that would be done in the beam-lisp maximalist way. if you find any other improvements that need to be done, tell them to me. try to ascertain questions with a prototype. look at the primitives/patterns/bundles if they are any useful

* Why

The dashboard (`vm/http.bl` → `GET /`), the session's one read-model, has panes
for Tasks, Ports, Index, Image, Session and Transport. There is no view of the
namespace GRAPH — what depends on what — and nothing shows a rename landing.

PLAN-124 (rename) needs exactly that view: a namespace rename re-labels edges in
that graph, and the honest report of "my downstream apps follow" is the re-label
plus a per-tree convergence status. The spike already computes both:
`rename/ns-graph` (nodes with in/out degree and var count, plus require edges)
and `rename/graph-diff` (the edges re-labelled / added).

* What to build

  · `vm/inspect` gains a `:graph` field, so `bl daemon status` and the page
    cannot disagree (the existing rule: a pane here is a field there).
  · `GET /graph` returns the JSON (the shape `/index` already uses).
  · A `Graph` pane rendered from it: nodes as namespaces, edges as requires,
    degree and vars-per-ns; a rename's diff highlighted while the rename's
    status is `:applied`.
  · Data comes from the index the session ALREADY holds: `vm.index/built` →
    `code.index/ensure-tree`, whose facts include the require graph
    (`source-graph`). No new index, no new cache; `source-graph/header*` over the
    tree's sources is the whole computation, and the tree walk is the part the
    index has already paid for.

* Precedent

`index-pane` is the pattern to copy: it reads `vm/index/progress` off a PUBLIC
ETS row, so the pane never queues behind the build it reports on. The graph pane
should read a memoised per-tree value the same way.

* Acceptance

  · `bl ui` shows a Graph pane listing every application namespace in the tree,
    its in/out require degree, its var count, and its un-declared requires
    ("external": `core`, `clojure.core`, …).
  · `bl daemon status` prints the same numbers.
  · After a rename the pane shows the re-labelled edges — the pane and the
    rename report must not disagree about what moved.

* Not in scope

Layout beyond a legible list/graph; the rename's own per-tree status row
(belongs to PLAN-124).
