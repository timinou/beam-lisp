* Idea
The reader and compiler (priv/boot/reader.bl, compiler.bl) are now BL, so they can be compiled to JS and run in a Worker. That gives a browser REPL, .bl.md notebooks, and editing with no server.

* Blockers
- core.bl calls Erlang BIFs and Elixir modules. Each needs a JS leaf or a build-time refusal (the host-op registry from PLAN-157 W1.1).
- The compiler uses process-dictionary state: the fresh counter `bl_fresh_seq` (PLAN-157 W1.2).
- Macro expansion evaluates code. That needs eval on the JS target, which the split client deliberately lacks (quoted-view-core.bl:1-50 explains why).
