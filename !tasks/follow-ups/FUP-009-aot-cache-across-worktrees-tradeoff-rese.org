* Question

Should FEAT-002's global AOT cache (lib/beam_lisp/aot_cache.ex) share
compiled artifacts across git worktrees of the same repo?

Today it cannot: closure_key mixes in the source's ABSOLUTE PATH
(aot_cache.ex:21-23), because emitted beams embed the absolute source
path (aot.ex ~line 110) for debug info and error locations. A worktree
at a different path compiles the full datom closure cold (~8-12 min on
first test/run) even when the main checkout's cache is hot.

* Decision (user, 2026-08-28)

KEEP the current behavior: absolute paths stay embedded, worktrees do
NOT share cache. Rationale: correct source paths in beams are worth more
than cross-worktree cache hits; worktrees are expected to pay one cold
compile each.

* Research spike (if this is ever revisited)

Document the tradeoff with numbers so the decision is revisitable:

1. Measure the actual cost: cold compile time in a fresh worktree vs
   warm in main (one number each, same machine).
2. Option A — relative paths at emit: if the embedded path derives from
   the path handed to the compiler, relativizing makes beams
   path-independent and the closure key content-only. Cost: error
   messages/debug info show relative paths; verify nothing in the
   toolchain (stacktrace rendering, editor jump-to-source) depends on
   absolute paths.
3. Option B — path rewriting on fetch: keep content-only keys, rewrite
   the embedded absolute path inside fetched beams. Cost: beam surgery
   on a binary format; must rewrite every chunk that can hold the path
   (debug_info, docs); fragile across OTP versions.
4. Option C — status quo (chosen). Cost: one cold compile per worktree;
   ~8-12 min, amortized to zero afterwards since the worktree's own
   cache entry then serves it.
