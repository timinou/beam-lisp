** THE BLOCKER (precise root cause)

With genesis deleted, cold boot fails: BeamLisp.init → enable_bl_backend →
ensure_loaded("compiler") does NOT intern the compiler ns from the seed beam,
so it falls to the SOURCE path → tries to compile compiler.bl → no compiler →
CompileError "compiler seed is not loaded".

Root cause localized: AOT.ensure_loaded/1's fast path requires
`function_exported?(BeamLisp.Ns.Compiler, :__bl_init__, 0)`. The ON-DISK seed
shim HAS __bl_init__ (verified via :beam_lib.chunks). But in the running VM,
`BeamLisp.Ns.Compiler` resolves to an IN-MEMORY shim (`:code.which` returns
`[]`, not the disk path) that does NOT export __bl_init__ — created by an
earlier Link.defvar/Module.create before the seed is consulted. So the fast
path's function_exported? check is false → skips to source. A purge+reload of
the module in enable_bl_backend did NOT fix it (the in-memory shim re-shadows,
or the disk seed's __bl_init__ doesn't fully intern on replay). Also: mix run
does NOT run the installer (only compile.beam_lisp does), so the ebin seed
state on a run-only path depends on the last compile.
