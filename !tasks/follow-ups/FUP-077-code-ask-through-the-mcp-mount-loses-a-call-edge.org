* Where to look

`mcp.tools/index-groups!` (`priv/lib/mcp/tools.bl`) is the seam the served
surface uses, and it has TWO paths: reuse the tree's own index (`covers?`), or
build the mount here. The counts come from `:per-source`; the ANSWER comes from
`:core-names`, which `group-metadata` derives from the per-source rows' `:names`:

    :core-names (into (set (BeamLisp.Env/public_names "core"))
                      (mapcat (fn [r] (:names r)) (vals counted)))

Two candidate mechanisms, in order of likelihood:

1. a path that answers `:entities` but not `:names` — the counts survive the
   reuse and the name set does not, so `callers` measures its row against an
   empty set of defined names and drops it;
2. the reuse path hands back a conn whose facts came from the OTHER path's
   analysis (the tree index vs the mount's own `codebase/index-source`), and the
   call edge is in one and not the other.

Distinguishing them is cheap: print `core-names` and the mount's `:per-source`
rows for the fixture in `the-served-surface-answers-about-the-tree`, and see
which is empty.
