* What is missing, and what an attempt at it already learned.

**Why.** Two things need the same instrument:
1. S12's remainder: nothing rolls `decide/cost` up over a corpus, so the 10 s
   ceiling (z3pool/z3-timeout-ms) is a default rather than a decision.
2. S11's second half (FUP-059): changing which sort a field gets can move a
   VERDICT, so it needs a before/after differential over a corpus — "every machine
   decided the same thing, before and after".

**What an attempt measured (2026-09-13, not shipped — see below).**
- `examples/system/*.bl` — 29 files, 16 of which mention `defserver`… but as
  STRINGS: `(def machine "(defserver …)")`. A walk that looks for literal
  `defserver` FORMS finds nothing (measured: `examples/system/01_extraction.bl`
  parses to 23 top-level forms, none of them a machine). So the harness must also
  parse the STRING literals, which means a recursive walk for `:string` nodes plus
  a tolerant re-read (comments and docs are strings too, and `read_string` throws
  on them).
- `(BeamLisp.Reader/read_string src)` answers the file's TOP-LEVEL FORMS (26 of
  them), not one wrapper form holding them — assuming the wrapper yields a
  cheerful `machines verified: 0`.
- `File/ls!` needs the `(to-list …)` idiom; entries include directories, so filter
  with `File/dir?`.
- Scanning `examples/datom/live` (live/reactive defservers) gave `rc=141` — SIGPIPE
  with ZERO output, even redirected to a file, with the daemon off. A known-good
  example runs `rc=0` in the same shell, so it is that scan, not the toolchain.
  Unexplained; the next attempt should bisect it (most likely candidate: a machine
  shape in that directory that `verify-process` cannot model, dying in a way that
  closes the port).

**Not shipped on purpose.** The script existed and was removed rather than
committed half-verified: it reported `machines verified: 0` with a green exit
code, which is the most dangerous shape of instrument — a measurement that says
nothing and looks like it said something.

**Acceptance.** A file that prints, per machine: file, name, `holds`, `undecided`,
ms — and a footer with count/median/worst — and whose `holds` column is
diff-stable across an engine change. Run it before and after the sort change in
FUP-059 and require the columns to match except where a sort correction is the
stated reason.
