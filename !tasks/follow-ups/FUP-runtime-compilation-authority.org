#+title: Follow-up: one captured authority for planning, compilation and cache publication
#+status: proposed; not part of current production acceptance

* Evidence and today's repair
SDK 13071213 passed functional gates but failed strict AOT on env. Offline
artifact/build-receipt comparison found 11 mismatches among 374 stamped outputs.
Declaration-aware path resolution fixes config/example filename collisions;
cache admission verifies exact embedded source/compiler keys; freshness checks
library facades; an accidental executable documentation example was corrected.
These safeguards do not make separate filesystem reads atomic, and one file's
build key cannot represent every legitimate namespace header independently.

* Design
1. Capture each selected source's loadable bytes once, with its canonical path,
   content digest and ALL namespace headers. Resolve namespace names from this
   captured inventory using declared ownership and explicit root precedence.
2. Plan namespace nodes independently, retaining a file compilation-unit group.
   Namespace A and namespace B in one file keep their own require closures and
   facade stamps. The unit's rebuild receipt owns every emitted artifact.
3. Pass that immutable authority into AOT compilation and macro/dependency
   resolution. Emit stamps from the captured plan, without reopening the root
   path or silently resolving dependencies from a different ambient project.
4. Cache manifests record provenance per facade, with byte digests per module.
   Accept old v2 entries only when one supplied key justifies every facade;
   otherwise miss. Validate semantic and byte authority before publication.
5. Build receipts record the complete emitted module set and its planned keys.
   A missing/unplanned/mismatched facade fails the build before packaging.
   Keep the final strict execution gate: metadata consistency alone is not
   proof that initialization, registration and reload work.

* Prototype and validation gates
- Two namespaces in one file, with disjoint dependencies; both graph closures,
  cache hits and source-free strict initialization must agree with their plan.
- Source edit between capture and emission, controlled by a barrier: compile
  the coherent captured revision, or explicitly retry; never mixed provenance.
- Same filename with wrong namespace in a higher-priority root; path, bytes,
  compiler inputs and emitted stamps must select the same declared source.
- Dependency body versus interface changes retain the documented invalidation
  boundary; changing root precedence creates a new authority, not a stale hit.
- Cache poison, interrupted publication and concurrent readers/publishers;
  complete old/new entries or misses, no partly trusted module set.
- Full SDK artifact audit, strict library/application closure and authenticated
  navigation. Benchmark bytes read, parse/plan counts, cache hit rates,
  compilation counts and cold/warm startup separately.

* Developer cost and delivery boundary
CLI build/serve/self-build construct the authority automatically; ordinary apps
need no custom declaration list or lifecycle hooks. Production still preloads
before readiness; development retains lazy/after-startup choices.

Implement after the current release passes its corrected SDK and app gates.
This changes compiler emission inputs and cache schema, so it deserves a
separate generation transition and migration receipt. Do not hide that cost by
calling an incompatible artifact fresh.

* Build-time follow-up: reuse a verified native floor
The final driver-only guard adjustment changed build key a324e45a... to
9a77dbb8..., with codegen still 715b12a6.... Regeneration compiled the host set
again, but all 97 beam files were byte-identical; only manifest build_key changed.
This is a candidate for automatic reuse, not a measured startup speedup.

Seed should reuse a host beam only after its manifest digest, raw source stamp,
compiler-generation stamp and baked input requirements are verified. Missing,
changed or unverifiable inputs compile normally. Publish one complete verified
floor atomically. Test driver-only edits (zero host recompiles), one host edit
(only its necessary rebuild), codegen edits (invalidate the affected whole
floor), poisoned manifests/beams and interruption/concurrent readers. Preserve
source-root/baked-path semantics rather than assuming byte reuse is always safe.
