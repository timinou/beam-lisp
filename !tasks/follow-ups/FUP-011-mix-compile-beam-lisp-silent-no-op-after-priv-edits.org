* Symptom (verified 2026-08-29)

After editing priv/env.bl (adding `convey`), the AOT beams under
_build/test/lib/beam_lisp/ebin stayed stale (00:03 vs source 00:25) —
`undefined var: env/convey` at runtime. None of these refreshed them:

    mix compile                       # :beam_lisp IS in compilers chain
    mix compile.beam_lisp --force     # rc=0, zero output, no beams
    mix compile.beam_lisp --force --out /tmp/aotout   # dir never created

The --out probe never creating its directory means the task bails at one
of the `{:noop, []}` branches — yet from the same cwd `priv` exists and
`Path.wildcard("priv/**/*.bl")` finds 55 files, and --force bypasses
up_to_date? anyway. Unexplained; possibly an interplay with the
foreign session's in-flight manifest/build state (they own /tmp/blwt
and churn this tree).

* Workaround (proven)

    MIX_ENV=test mix run --no-start -e \
      'BeamLisp.init(); BeamLisp.AOT.compile_file("priv/CHANGED.bl", output_dir: Mix.Project.compile_path())'

* Why it matters

Every priv/*.bl edit (env.bl, auth/*, datom/*) risks running stale
bytecode with errors that name missing VARS, not staleness — this cost a
debugging round inside PLAN-047 W1 and will cost every contributor one.
