* Leading hypothesis (not yet proven)

The supervisor's NAME is shared with the daemon's: both files call
`BeamLisp.Daemon.Workers.ensure_started()` in `setup` and then assert on
`BeamLisp.Daemon.Workers` and its three children, while a daemon started by
another test in the same VM registers the same names and TAKES THEM DOWN when it
stops. `EXIT shutdown` is what a `GenServer.call` to a supervisor that is
shutting down looks like; `no process` is what it looks like one moment later.
So these tests are racing a lifecycle they do not own.

Confirming the mechanism means reading `BeamLisp.Daemon.Workers.ensure_started/0`
and the daemon's teardown, and deciding which side should own the names. That is
the self-build/daemon session's API, and a wrong guess here is a name-ownership
bug in the daemon itself, not in the test — so it is filed rather than patched.
