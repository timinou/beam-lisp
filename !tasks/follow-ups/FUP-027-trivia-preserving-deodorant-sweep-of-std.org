* What this is (zero context)

beam-lisp now has a code-cleanup tool called **deodorant**. It reads a source
file, finds tired idioms ("smells") — e.g. `(= x nil)` instead of `(nil? x)`,
`(if (not c) a b)` instead of `(if-not c a b)`, `(+ x 1)` instead of `(inc x)` —
and rewrites them to the idiomatic form. The new part (PLAN-098 Phase A) is that
it does this **without disturbing formatting**: comments, indentation, and
blank lines survive, because it edits the exact source byte-spans rather than
re-printing the file from the parse tree.

We already ran it successfully over the **boot** layer (the compiler's own
foundation, `priv/boot/`): 68 idiom fixes across 8 files, and the compiler still
compiles itself through them. That was the smallest, highest-risk blast radius,
so we did it first and verified hard.

This item is the **remaining sweep**: apply the same cleanup to the three larger
layers — `priv/std/`, `priv/lib/`, `priv/compat/` — landing each as its own
`style(...)` commit once the full test suite is green.

* Why it was deferred (the whole point of gating it)

A naive "sweep everything at once" is unsafe for two concrete, proven reasons —
both discovered the hard way during Phase A:

1. **A rewriter must never sweep its own source.** deodorant's smell rules are
   themselves written in the idioms they rewrite. When the blind sweep hit
   `deodorant.bl` and `span-rewrite.bl`, the rules rewrote *their own
   definitions* — e.g. the rule `(= ?x nil) => (nil? ?x)` got rewritten to
   `(nil? ?x) => (nil? ?x)`, silently disabling itself. Any sweep MUST exclude
   the rewriter's own files (`priv/std/deodorant.bl`, `priv/std/span-rewrite.bl`
   and anything they load).

2. **A bad rewrite in one file can corrupt the whole in-process run.** The
   reader raises an *uncatchable* error struct on malformed source, so if a
   single file gets mangled mid-sweep, the batch can die without a clean report
   of which file broke. The fix is **per-file OS-level isolation**: run each
   file's fix in its own OS process, so one bad file fails alone and the rest
   proceed. (During Phase A a whole-tree sweep did break the reload suite — 59
   failures — from one spanless-string-capture defect; that specific defect is
   now fixed and regression-tested, but the isolation discipline stands.)

The seven rewriter defects the boot sweep surfaced are ALL fixed and
regression-tested (commits 6cee3e7, eec7dfa, d0c6cdb, 5166d0e, 6736ec4, plus the
self-corruption restore 5f941c1). So the tool is trustworthy per-file now; what
remains is running it safely at scale.

* How to do it

For each layer in order — `std`, then `lib`, then `compat`:

1. List the layer's `.bl` files, EXCLUDING `priv/std/deodorant.bl` and
   `priv/std/span-rewrite.bl` (the rewriter's own source).
2. For each file, in its OWN OS process (fresh `mix beam_lisp.run` invocation),
   apply `deodorant/fix-file-preserving!` with the default ruleset
   (`deo/all-rules` = safe + idiomatic; NOT `deo/every-rule`, which includes the
   riskier "reinvention" tier).
3. After each layer, run the FULL system suite (`mix beam_lisp.test test/bl`),
   plus `data`, `tooling`, and `reload` suites. Green ⇒ commit as
   `style(<layer>): deodorant fix --all — N trivia-preserving idiom fixes`.
   Red ⇒ identify the one mangled file, restore it with `git show HEAD:f > f`
   (NEVER `git checkout`), add a regression test if it's a genuine rewriter
   defect, fix the rewriter, re-run.

Prior measured sizes (from the reverted blind sweep, for scale estimate only):
std ~141 fixes / 25 files, lib ~285 fixes / 59 files, compat ~7 fixes / 4 files.
lib is the largest — run it with a higher memory cap (≥11G) and watch for
LazySeq/`concat` budget in a fresh process per file.

* Acceptance

- `std`, `lib`, `compat` each swept and committed separately.
- Full suite (`test/bl` + data + tooling + reload) green after each layer,
  matching or exceeding the pre-sweep baseline (system 187/421, 0 failures).
- The rewriter's own files (`deodorant.bl`, `span-rewrite.bl`) left untouched
  by the sweep (they are edited only by hand, with tests).
- Each commit message records the file count and fix count.

* Non-goals

- Not the `deo/every-rule` reinvention tier (longer/riskier rewrites like
  `op-of`); default ruleset only.
- Not any behavior change — this is pure idiom normalization, diffs must be
  semantically identical.
