** Context

datalog recursive queries (reaches/reachable/impact and every :~relation-backed
rule) go through fixpoint.bl's `build-ir`, which interns the ENTIRE base relation
(every edge) into native i64 tuples on EVERY query. Profiling the self-hosted
compiler's call graph (129 fns / 1193 edges): build-ir dominates at ~1.3-1.5s;
the native fixpoint itself is ~10ms. So the demand-scoped magic path (t3, done)
helps only modestly here — the cost is upstream marshalling, not the fixpoint.

The real lever: cache the interned EDB (and the fixpoint state) across queries
on the same db basis, and MAINTAIN it under deltas instead of rebuilding.

** What exists

- native/datom_datalog has `dl_eval_incremental(rules, idb, edb_before, new_edb,
  query_pred)` — maintain the fixpoint under new base facts. Wrapper:
  datom.datalog/eval-incremental. ONLY caller today: bench/datalog_axes_bench.bl.
  The bench notes it is currently "reload-dominated" (it re-decodes the EDB), so
  the NIF alone is not the whole win.
- defrelation carries `:maintenance :incremental` as CATALOG METADATA only
  (relation.bl emits [id :relation/maintenance :incremental] as a datom); NO
  executor reads it.
- fixpoint.bl now has `build-ir` (shared IR compile) — the seam a cache slots
  into.

** The work

1. A maintained-view store (process-wide, keyed on [store-of-db, rule-set-hash]):
   holds the interned EDB + the last fixpoint state + the basis-t it was built
   at. First query builds it (build-ir); subsequent queries at the SAME basis
   reuse it (zero re-intern).
2. Under a newer basis: extract the delta (new/retracted base datoms since the
   cached basis-t via datom.time), encode only the delta, call
   dl_eval_incremental to maintain — instead of a full rebuild.
3. Wire `:maintenance :incremental` so a defrelation declaring it opts into the
   maintained store; `:recompute` (default) keeps today's behavior.
4. Invalidation: retractions / a basis older than the cache → rebuild (sound
   fallback); the cache is an optimisation, never a correctness dependency.

** Acceptance (TDD)

- test/bl/datom/reach_incremental_test.bl: build a graph, query reachable (warms
  the cache), transact a new edge, query again — result equals a full recompute
  on the new basis (the maintained view is CORRECT), for both a connecting edge
  and a disconnected one, and for a retraction (falls back to rebuild, still
  correct).
- Benchmark: N-edge graph, first query vs a second query after a 1-edge delta —
  the second must be materially cheaper than the first (no full re-intern),
  measured across N in {100, 1000, 10000}.
- All existing datom tests stay green (reach_demand, rules, fixpoint, relation,
  query, hnsw).

** Non-goals

- Do not make the cache a correctness dependency: a cold cache, a retraction, or
  a basis mismatch must always be able to fall back to a full build-ir.
