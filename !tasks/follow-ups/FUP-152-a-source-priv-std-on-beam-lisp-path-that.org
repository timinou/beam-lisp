** Defects
1. A std on the search path that is older (or newer) than the payload shadows the payload's namespace and the VM dies with no message: the exit is a bare 'killed'. Whatever kills it (an init process timing out? a supervisor?) must say which namespace failed to load and why.
2. BEAM_LISP_PATH containing priv/std is an unsupported shape from outside a tree (a tree's own bin/bl is the supported way to run its std), but nothing says so.

** Not verified
- Which process kills the VM, and on which load.
- Whether the skew is in the compiler/seed or in the proc runtime.

** Workaround for Foundry
Do not put <repo>/priv/std on BEAM_LISP_PATH from outside the tree. Either run the deployment payload with the packaged std, or merge main into the spike so proc/* match the payload.

** Gate
A test that puts a deliberately mismatched priv/std on the path and asserts a named error and a nonzero exit, never 'killed'.

* FUP-152 investigation (2026-10-04, realm 191611df)

** What kills it (observed, erl-level trace of the drop ee095b33 `bin/bl eval`)
- The dying process is `#PID<0.95.0>` — the Elixir `--eval` process running `BeamLisp.Ns.Bl.Cli.main(System.argv())` (`initial_call {:erlang,:apply,2}`, `links []`).
- `:erlang.exit/2` trace: `{:exit_call, #PID<0.1.0>, #PID<0.95.0>, :kill}`; the caller's stack is `erts_code_purger:do_soft_purge/2` / `wait_for_request/0` → `<0.1.0>` is the ERTS code purger, so the kill is an OTP module purge.
- `erts_internal:purge_module/2`, in order: `[BeamLisp.Ns.Vm.Client, :prepare]`, `[BeamLisp.Ns.Bl.Cli, :prepare]`, `[BeamLisp.Ns.Bl.Util, :prepare]`, `[BeamLisp.Ns.Bl.Env, :prepare]` — exactly the namespaces the loader reloads from the shadowed source.
- Load trace: the loader source-loads `bl.cli`, `vm.client`, `bl.util`, `bl.env` from the shadowed dir (`LOADBIN BeamLisp.Ns.Bl.Cli` then `PURGE-PREP BeamLisp.Ns.Bl.Cli`), looping on `ensure_ready "build-plan"` first.

** Cause
The payload's compiled `BeamLisp.Ns.Bl.Cli` (and the namespaces it requires) is judged stale against the shadowing `priv/std` source, so the loader reloads it from source; when the older generation of the executing module is purged, OTP kills the CLI process with `killed` and Elixir prints only `** (EXIT from #PID<0.95.0>) killed`. The kill is untrappable, so the loader's `load_attribution`/`catch` never runs.

** Not pinned
The exact caller of the hard `code:purge` — the failure stopped reproducing once the concurrent `latest` rebuild settled (the compiler-key/staleness state is the hidden variable); a `code:purge/1` trace shows no hard purge in a passing run.

** Blocker
Hard-purge sites in the run path are all host/boot: `priv/boot/lower.bl:392` (`reload-descriptor!`, emitted by `priv/boot/compiler.bl:3205` for `defserver`), `priv/host/bootstrap.bl:411/531/610`, `priv/build/seed.bl:139`, `priv/host/record.bl:402`, `priv/std/vm/hotpatch.bl:61`; the AOT-or-source decision is `priv/host/aot.bl` + `priv/host/loader.bl`. `aot.bl`/`loader.bl`/`compiler.bl` are off-limits here → no fix landed.

** Next step
Refuse to reload a namespace the running image already has loaded. In `priv/host/loader.bl::ensure_loaded_in` (or the AOT staleness decision), raise carrying the namespace + source path: `bl: LOAD FAILED — <path> (namespace <ns>): source on BEAM_LISP_PATH belongs to another image; refusing to reload a namespace this VM is executing`. Alternative: run the source load in a monitored child and, on `killed`, print the namespace + path.
