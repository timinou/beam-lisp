* Initial Message

how hard would it be to bootstrap beam lisp fully?

** Problem

Running the FULL ~mix test~ suite, ~28 tests fail with:

  (exit) exited in: GenServer.call(BeamLisp.Env, {:get, ...})
     (EXIT) no process: the process is not alive ...
  BeamLisp.init/0 (lib/beam_lisp.ex:62)

The same tests PASS when their file is run alone (wave22_server 7/7, etc.).
Reproduces both parallel and serial (~max-cases 1~ still shows ~23 no-process
failures). Present at the branch point 63305db and on main (main's full run
also crashes, exit 2). This is the flake PLAN-022 already recorded ("one mix
test run in 38 failed").

** Root cause (hypothesis, needs confirmation)

BeamLisp.Env is a supervised child under :one_for_one with the DEFAULT restart
intensity (max_restarts: 3 in 5s). Something in the test run (likely the
PLAN-046 sandbox checkout/checkin fork machinery in BeamLisp.ExUnitCase, or a
defserver/OTP crash test) makes Env crash repeatedly. Once >3 crashes land in
5s the SUPERVISOR itself terminates the whole tree, and Env is gone for every
subsequent test — each of which calls BeamLisp.init/0 -> Env.seeded?() ->
GenServer.call to a dead process.

~ensure_env/0~ only starts Env when ~Process.whereis(Env)~ is nil; it does not
detect a supervisor that has given up, and ~init/0~ has no retry. So a downed
Env is never revived within a run.

** Scope

1. CONFIRM the cause: instrument Env.terminate + the supervisor to log why Env
   crashes and when the tree gives up. Identify the first test that crashes it.
2. FIX at the root: either (a) make Env not crash under the sandbox fork/checkin
   path (preferred — a crash is the real bug), or (b) raise restart intensity +
   make ensure_env/0 + init/0 resilient to a dead/again-registered Env (revive
   rather than assume-present). Both may be warranted.
3. Add a regression test: the full suite (or a stress harness that forks/crashes
   Env N times) must leave Env alive and answering.

** Acceptance

- Full ~mix test~ completes with no ~no process~ failures.
- Env survives a burst of fork/crash cycles (a direct stress test asserts it).
