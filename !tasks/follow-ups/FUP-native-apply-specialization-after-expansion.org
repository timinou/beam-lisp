#+TITLE: Consolidate provable native apply specialization into compiler ANF
#+STATE: ITEM
#+DATE: 2026-10-12
#+RELATED: reload.static-call managed-generation native-authority

* Why
The conservative source-span pass specializes native apply without changing the
original source/digest. It intentionally leaves unknown calls/macros opaque so
it cannot change code inspected by a macro. Actual Knowledger graph admission
still stops at unsupported =erlang/apply= contexts such as =librarium.ingest=.
Do not widen traversal or exempt that source from authority checks.

A single post-expansion compiler pass can see actual evaluation and resolved
binding identity. It could eliminate more argument-list allocations and dynamic
MFA dispatch, and make more ordinary product source sealable automatically.
This is a follow-up design, not an implemented or benchmarked speedup.

* Pipeline and safety prerequisites
1. Source precheck must explicitly defer a native-apply proof obligation to the
   compiler, rather than treating defer as authorization. Record origin/span.
   Dynamic or unresolved apply must still fail the final sealed-graph gate.
2. Trusted macro expansion produces staged compiler ANF. Existing compile-time
   macro execution is a trusted compiler boundary, not a sandbox. Preserve that
   explicit limitation; arbitrary macros must not gain new runtime authority.
3. Prove all deferred obligations and initializer safety before evaluating a
   top-level value, invoking a domain initializer or publishing any graph.
   Compilation must not execute the very initializer whose safety is pending.
4. Require literal module/function values and exact nonnegative arity. Normalize
   only lowercase OTP modules or explicitly qualified Elixir modules. Resolve BL
   namespace/alias conflicts through compiler binding identity, never spelling
   heuristics or new dynamic target atoms.
5. Require a compiler-known Core proper-list constructor whose resolved identity
   is the built-in, with a statically known finite arity. A local/global function
   named list, arbitrary list-valued expression, improper tail or unresolved
   dynamic list must refuse. No general partial evaluator is required.
6. Reuse ANF argument temporaries in their original order, exactly once. Preserve
   earlier effects when a later argument throws; do not duplicate or move any
   computation. Literal MFA values have no evaluation effects. Keep source spans
   and the original source/digest as authoritative provenance.
7. Reuse the existing exact native inventory and native-hazard checks on the
   lowered target, then run the final complete ANF authority audit. No separate
   target whitelist, runtime evaluator or bypass for generated direct calls.
8. Bound constant/list proof work, with explicit refusal on budget/ambiguity.
   Unproved obligations must prevent initialization/publication, not fall back
   to ambient dynamic dispatch in a sealed graph.

* Consolidation
Once equivalent coverage exists, make the compiler pass the single mechanism.
Remove source rewriting or retain its analysis only as a diagnostic precheck;
do not maintain two independent native-apply optimizers with differing rules.
Keep native authorization in the existing final audit. Preserve source identity
separately from compiler IR/compiled-code identity in artifact/cache manifests.

* Validation and measurements
- Positive direct/let/nested forms and unknown macro wrappers expanded by the
  real compiler; real execution counters prove left-to-right exactly-once work.
- Quote/comments/Unicode unchanged; macro observes its original AST before
  expansion; original source hash stays identical.
- Dynamic MFA/arity/list values, shadowed/renamed Core list, BL alias conflicts,
  improper lists and proof-budget overflow refuse before initializer effects.
- Forbidden spawn/Env mutation/reflection remain forbidden even after a direct
  call is synthesized. A deferred proof failure cannot run a side-effecting
  initializer or publish a serving slot; test both boundaries explicitly.
- Use current source-pass/integration fixtures as differential semantic cases,
  then remove duplicate implementation. Validate wrong-arity/throw diagnostics
  and retain original spans; do not promise identical native stack internals.
- Measure direct call versus dynamic apply allocation/runtime in one warm VM,
  compiler time and IR size, then actual graph refusal/frontier reduction and
  cold startup on the same exact assembled SDK. Report safe refusal reductions
  separately from production application enablement and page-navigation SLOs.
