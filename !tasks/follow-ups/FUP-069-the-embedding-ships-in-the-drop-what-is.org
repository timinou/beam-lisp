* What landed (this is context, not the ask)

The embedding is now part of the default distribution, so a shipped `bl` answers
semantic queries with no network, no Mix and no cache on the box:

  * `BeamLisp.Model` resolves the weights across three roots, first that holds a
    COMPLETE copy (`DIGEST` present, written last by the fetch):
    `$BEAM_LISP_MODEL_DIR` (an explicit pin — SET MEANS ANSWER, no fallthrough)
    → `priv/embed/<name>` (the BUNDLED copy) → `$XDG_CACHE_HOME/beam_lisp/models`
    (the ambient cache a fetch fills). `Model.tier/1` names the tier in use.
  * `mix bl.embed.fetch --bundle` writes into `priv/embed/`;
    `mix bl.build` runs it BEFORE `mix release` (a release packed without the
    weights cannot be fixed by packing harder) and prints the size;
    `--no-embed` builds without them.
  * `.github/workflows/release.yml` fetches them for the shared cache and warns
    that a stale entry is re-verified against the pinned sha256.
  * A `PROVENANCE` file (upstream URL, date, licence, the three pinned digests)
    is written beside the weights so the notice travels with a redistributed
    copy. Verified inside a built drop's payload.
  * Measured: `priv/embed` is 32.0 MB; the drop went 99 MB → 130.4 MB.

* What is left

1. **The build depends on huggingface.** `mix bl.build` (and so the release
   workflow) now reaches `resolve/main` at build time. The sha256 pins make a
   changed artifact LOUD, but a runner without egress cannot build the default
   artifact at all. Mirror the three files somewhere the pipeline controls (or
   vendor them as a release asset) and pin the fetch to it; the task's `@files`
   digests stay the contract either way.
2. **`resolve/main` is a moving target in the URL**, held still only by the
   digests. Pin the revision sha in the URL too (`resolve/<rev>/…`) so the
   request itself is stable and the digest check becomes a second, independent
   guarantee. The revision fetched on 2026-09-14 was `e9d2a44ca6a05ac6685f3b23709ea57eb7352d5b`.
3. **The cache key ignores the pin.** `priv/embed` is cached under
   `hashFiles('mix.lock', '**/Cargo.lock')`, which does not change when the
   model is re-pinned in `bl.embed.fetch`. A stale cache is caught by the
   digest check (it refetches), so this is a wasted download, not a wrong
   artifact — but the key should include the pinned shas.
4. **Is a slimmer artifact wanted?** `--no-embed` exists; whether to also
   PUBLISH a no-embed drop (33 MB smaller, `bl search` degraded to a message) is
   a distribution decision, not a build one. Now that the flag exists, the
   question is just whether anyone needs that artifact.
5. **Licence text.** The upstream model card declares MIT but the repository
   ships no `LICENSE` file (checked 2026-09-14 via the HF API), so the
   PROVENANCE file states the licence and the source rather than reproducing a
   text that does not exist upstream. If a distribution needs the full MIT text
   in-tree, that is a one-line addition to the fetch task.
6. **Tests still assume absence is the normal case.** `bl.search.test`,
   `code/semantic_test` and `index_parallel_test` guard on the model being
   present or absent, and the suites read differently depending on the machine.
   With the weights bundled in every drop, the *drop* path is always the
   present case — a build that carries them and a checkout that fetched them
   should be the tested default, with absence the odd case.
