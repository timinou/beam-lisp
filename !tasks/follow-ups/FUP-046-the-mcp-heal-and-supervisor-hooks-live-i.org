* Hook 1 — the consumer of `alive?` (the actual fix for `bl mcp` through the daemon)

File: `priv/lib/mcp/tools.bl`. Replace the memo's body in `conn` (keep the
`instr/mount!` lines above it and the `the-conn` atom; only the body changes):

```
(defn conn
  "The self-indexed codebase: one datom conn over every MOUNTED source."
  []
  (let [c @the-conn]
    (if (and (some? c) (datom/alive? c))
      c
      (let [_ (when (some? c) (datom/release! c))
            fresh (mount!)]
        (if (compare-and-set! the-conn c fresh) fresh @the-conn)))))
```

was:

```
(defn conn
  "The self-indexed codebase: one datom conn over every MOUNTED source."
  []
  (or @the-conn
      (let [c (mount!)]
        (if (compare-and-set! the-conn nil c) c @the-conn))))
```

Also worth carrying: the comment above `the-conn` explaining WHY (the daemon's
worker is younger than the memo). It is in the working tree now.

* Hook 2 — the supervisor hook (one line)

File: `lib/beam_lisp/daemon/server.ex`, in `init/1`, replacing the two bare
`start_link` blocks (`{:ok, _exec} = case Process.whereis(BeamLisp.Daemon.Executor) ...`
and the same for `WatchRegistry`):

```
      {:ok, _workers} = BeamLisp.Daemon.Workers.ensure_started()
```

Measured in a drop without it: kill the command worker mid-command and every
later command fails `:noproc` forever, while `bl daemon status` stays healthy.
With it, the next command runs.

* Hook 3 — one cache, not two

File: `lib/beam_lisp/daemon/http.ex`, `mcp_state/1`. That session's version
caches the whole MCP state (and therefore the mounted conn) in
`:persistent_term`, never invalidated; a dead conn cached there is served
forever and no healing below can help, because the dead state is what the
function returns. Delete the cache and build the state per request — the mount
is still paid once, by `mcp.tools/conn`'s memo, which is the level that can
tell whether what it memoized is still alive.
