* Initial Message

is there a way we could make the bl binary let us access through a local name (as in https://xxx.yyy instead of remembering the port name), and then we can have a name that's resolved from a combination of the env.bl and some other stuff? this is to remove port management from a developer's everyday struggle

* What happens

A gateway is found through ONE file — `<runtime>/beam_lisp/gateway`, holding its pid and port (`BeamLisp.Daemon.Gateway.endpoint/0`). Lose that file while the process lives and the gateway becomes invisible in the only way that matters:

    $ bl gateway stop     → "bl gateway: not running"    # while it serves every name
    $ ss -ltnp | grep 7777
    LISTEN … users:(("beam.smp",pid=2276026,fd=17))       # still there
    $ bl gateway start     → a SECOND gateway, on an ephemeral port

Observed for real on 2026-09-12 (PLAN-105): gateway pid 2276026 kept 7777 and kept routing while `bl gateway status` reported nothing, and the next `bl gateway start` came up on 32873 instead of 7777 — names then answered on two ports, and `bl gateway stop` could only stop the one it could see.

The file was removed by the test suite: an EPHEMERAL gateway (`port: 0`) used to write and then delete the shared endpoint on exit. That specific cause is fixed (only a gateway that chose its port — or the unpinned default — publishes the file; `terminate` deletes only a file naming our pid), so this is now a rarer situation, not an impossible one: a killed gateway (`kill -9`), a wiped `$XDG_RUNTIME_DIR`, or an older build still does it.

* What it needs

Something other than the file to find a running gateway. Two shapes, either is enough:

1. **Ask the OS**: the gateway already listens on loopback; a `bl gateway` that finds no endpoint could probe `127.0.0.1:80` and `127.0.0.1:7777` (both are "the gateway's ports" by definition) and, if a listener answers with the gateway's own `x-bl-gateway` header (the index page already sends one), adopt it — or report `a gateway is on 7777 but has no endpoint file: pkill -f 'gateway run'`.
2. **A lock file that cannot be duplicated**: hold an exclusive `flock` on the endpoint path for the gateway's lifetime, so a second start can see "someone holds the gateway slot" even when the file's *contents* are stale or gone.

The banner already prints the fallback-port hint when it degrades past 7777 ("port 7777 is held by a process that is not the gateway this machine knows — an older one, most likely: pkill -f 'gateway run'"), which is the human remedy; what is missing is a verb that ACTS on it.

* Acceptance

With a gateway running on 7777 and its endpoint file deleted:

- `bl gateway` names it (port and pid) rather than saying "not running";
- `bl gateway stop` stops it;
- `bl gateway start` does not create a second one.
