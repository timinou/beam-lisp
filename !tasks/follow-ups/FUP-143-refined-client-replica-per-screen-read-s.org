* Why v1 is whole worlds
- Safe: the replica is exactly what `:worlds` returns after the auth.bl guard, so placement cannot widen visibility.
- Easy: no read-set inference. The server streams the tx reports it already computes for `datom/listen!`.

* Refined version
1. Read-set inference. For each portable screen, infer the datom patterns it reads: the attributes and entity paths in its `datom/q` / `pull` calls. Queries are data (quoted vectors), so a large class is statically analysable. Store the read-sets as codebase facts beside the placement facts.
2. Partial replicas. Replicate only the union of read-sets for the screens a tab can reach. Today `:listen :attrs` is a commit filter only (priv/lib/live/socket.bl); it becomes the replication filter.
3. Lazy fetch. Navigating to a screen whose read-set is not yet replicated fetches the missing facts first. The screen renders on the server until the facts arrive, so there is never a blank or wrong screen.
4. Soundness gate. A screen whose read-set cannot be bounded statically (a dynamic query, an attribute chosen at runtime) falls back to whole-world replication or to server rendering. It is never served a partial replica it might read past.

* Acceptance
- For every example app: replica bytes go down against v1, and the rendered output is identical to server rendering. This is a property test over random intent sequences.
- A screen with a dynamic query is detected and handled by the fallback.
