* Initial Message

prototype the feasiblity and simplicity of a `deodorant` beam lisp package: a package that uses Specter or optics.bl to detect common cases of code constructs that agents did (e.g. used a long version of a function instead of something already available), and to correct it. This should be fast and efficient. Look at recent code in ~/code/ora/relay and ~/code/ora/mesmo  for examples

* Goal

beam-lisp AOT-compiles priv/ sources into BEAM modules. AOT captures value-defs
by matching the LITERAL `(def name init)` shape BEFORE macroexpansion
(lib/beam_lisp/aot.ex `capture_value_def`). A macro whose expansion CONTAINS a
`(def …)` is invisible to this capture: neither the generated var nor any
side-effect in its initializer is replayed in the compiled `__bl_init__/0`.
The var simply does not exist at load in a compiled consumer.

Deodorant hit this concretely: smells declared via a `defsmell` macro vanished
from compiled builds (registry empty at runtime; `undefined var:
deodorant/if->if-not` from a consumer), while the same declaration written as a
literal `(def …)` survived. Worked around by declaring built-ins as literal
`(def name (smell '…))` and reserving `defsmell` for interpreted user code.

* Proposed fix

Teach AOT to macroexpand top-level forms (or replay a MARKED macro's call
sites) before capturing value-defs, so a macro that produces a value-def is
handled like a literal one. `@replayed_forms` (currently a closed allowlist:
defmacro defserver defrecord deftype defprotocol defmulti extend-type
extend-protocol) is the seam — generalize it, or add a `^:aot-replay`
registration a defmacro can opt into.

* Why deferred

It is a core compiler change touching every priv/ consumer (datom, auth,
specter, spell). The workaround (literal defs) is correct and low-cost for
deodorant's built-ins, so the risk of touching shared AOT was not justified in
the prototype. But any library that wants a definitional macro (defn-with-
registration, defsmell, a `defroute`, etc.) will hit the same hole.

* Evidence (reproduced in session 2026-08-27)

  - Injecting `(def diag-literal (register! {…}))` into priv/deodorant.bl →
    registry count 1 at runtime in a compiled build.
  - The same declaration via the `defsmell` macro → count 0, and
    `deodorant/if->if-not` undefined from a consumer.
  - `capture_value_def` matches `{:list, [{:symbol, "def"} | _]}` and the
    @replayed_forms heads; a `(defsmell …)` list matches neither.

* Acceptance

  - A macro that expands to `(def …)` (e.g. deodorant's `defsmell`) produces a
    var that EXISTS and whose initializer side-effect runs at load in an AOT
    build.
  - No regression to existing priv/ consumers (datom data-reader!, specter
    navs, auth, spell contract stack).
  - Deodorant's built-ins reverted to `defsmell` (single ergonomic path).
