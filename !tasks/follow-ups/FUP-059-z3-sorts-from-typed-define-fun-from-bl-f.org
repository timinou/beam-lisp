* Deferred out of PLAN-110 (S11) — a verdict-changing change that wants its own sweep.

**What it is.** Two halves, both of which feed z3's inputs:

1. **Sorts from `typed`.** `verify-process` derives each state variable's SMT sort
   from the INIT literal (`system.smt`'s inference). A variable whose first value is
   `0` becomes `Int` whether or not the machine intends a `Real`, and a var with no
   readable init has no sort at all. `typed` already holds `^{:args :ret}` tag sets
   for every fn, so the sort could be READ rather than guessed — and a machine whose
   annotation says `Real` would stop being modelled as `Int`.
2. **`define-fun` from bl fns.** `system.smt` translates a bl helper by INLINING its
   body (measured: `anf_smt_test` exists precisely because translation sees through
   a call). Emitting a `define-fun` for a pure helper instead would keep the script
   small and give z3 a named symbol — which matters for `get-unsat-core`, where a
   name is what a repair message can quote.

**Why it was not done in this change-set.** Both halves change which formula z3 is
handed, i.e. they can move a verdict from `unsat` to `sat`. The rest of the cutover
was safe to land because its answers could not change (a verdict is re-encoded, a
prelude is sent once, a script is memoised by its own bytes). This one can. It wants
a differential: every machine in `examples/` and `test/` verified BEFORE and AFTER,
asserting the same `:holds`/`:status` for each, plus a new test that a `Real`-tagged
field stops being modelled as `Int` (a *soundness* bug today: an int model of a real
field can prove a false invariant).

**The integration points, exactly:**
- `priv/lib/system/core.bl` → `verify-process`: the `sorts` map it builds and passes
  to `joint-prelude` / `establishes-joint?` / `step-obligation`.
- `priv/lib/system/smt.bl` → `of-node-*`: where a term's sort and its translation
  are decided today.
- `priv/lib/smt.bl` → `emit`: already handles `(Array Int Int)` and user-defined
  sorts; a `define-fun` emission would go through `system.smt`'s fn translation.
- `priv/std/typed.bl` → `sigs-from-env` / `type-of`: the tag sets to read.

**Do not** wire it as a silent default: the fallback path (unknown tag → current
inference) must stay, so that a machine with no annotations verifies exactly as it
does today. The measurable acceptance criterion is a differential over the whole
`examples/system/` corpus, not a green smoke test.
