#+TITLE: The console marks a realm that shadows a library (a chip on the realm's row)
#+STATE: ITEM
#+CUSTOM_ID: FUP-157-the-console-marks-a-realm-that-shadows-a-library

* Initial Message

(from the 2026-10-04 realm-ns review) A project may shadow a std/lib namespace within its realm, declared in env.bl with =:shadow=. "Mark that in the UI FUP as something to add to the chip of whatever component shows that."

** What
Wherever the console shows a realm (the VM tree's realm row on =/=, the realm page =/realm/<alias>=, and =bl realm show= in the terminal), a realm that shadows one or more tier namespaces carries a CHIP:

#+begin_example
shadows 2: datom.query.plan, proc.server
#+end_example

- It is text plus a mark (=◇=), never colour alone (docs/design/realm/console.md: a status is a word and a mark).
- It names the shadowed namespaces (collapsed past three: "shadows 5: a, b, c, +2"), and links to the diff of each against the tier's version (=bl realm diff NS= prints it; the page links to the same data).
- The point of the chip: a shadow is a LOCAL IMPROVEMENT waiting to merge into main. Showing it keeps it from being forgotten, and the diff is the merge.
- A shadow whose tier namespace has changed since the shadow was written (the tier's closure hash differs from the one recorded when the realm opened) gets a second word: "shadows 2 (1 behind)". That is the "main moved under your fork" signal.
- A realm with no shadows shows no chip (the empty case is silence, console.md rule).

** Where the data comes from
The loader already knows the home of every namespace (=:shadow= in =namespace-home=). The control frame =:realm-show= carries ={:shadows [{:ns :path :tier-hash :local-hash}]}=; the console and =bl realm show= both render that one list (one truth, two renderers, like =bl vm= and the page).

** Gate
- the frame carries the list for a realm with a declared shadow and an empty list otherwise;
- =bl realm show= prints the chip text; the page renders the same string (a test compares them);
- impeccable detect on the page stays at 0 findings.
