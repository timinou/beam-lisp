* What this is now

The Drive CURSOR moved into PLAN-137 phase 6 — all three services are in wave one,
because the headline deliverable is ONE query across Gmail + Calendar + Drive.
Drive is still built LAST within that wave, for the reason below. So this
follow-up is no longer "add Drive"; it is the three things Drive uniquely brings
that the other two do not.

* Why Drive is still last in wave 1 (do not reorder without reading this)

Drive is the EASIEST of the three Google sync contracts, which is exactly why a
broken cursor fold would PASS on it. =changes.getStartPageToken= returns a token
the docs call non-expiring; =ChangeList= carries =newStartPageToken= "only if the
end of the current changes list has been reached"; there is no documented 410 or
expiry path. Gmail fails with a 404 and Calendar with a 410 =fullSyncRequired= —
build those first, then add Drive as the THIRD instance.

**Acceptance for that ordering: adding Drive touches ZERO lines of =page.bl=,
=budget.bl=, =transport.bl=, or =relation.bl=. One spec value + one thin
namespace. If =page.bl= changes, the fold was not a fold — that is the finding.**

* What remains genuinely Drive-specific

** 1 · Media: resumable upload and download
=files.export= and the media variants are the first NON-JSON results. NO BEAM
client ships resumable upload (verified across httpc/Finch/Mint/Req/gun/hackney):
the protocol is a session-URI handshake (POST to start → 308 + =Range= headers →
chunked PUT), and a lost chunk must resume from the last acknowledged =Range=,
not from zero. This is a new transport verb, and it belongs behind =proc.fence=
like everything else so a stalled chunk is a ={:timeout}=, not a hang.

** 2 · The validated cache, past the trivial case
=files.get= is the cleanest =:cache :validated= case in the whole design: store the
response with its =etag=, send =If-None-Match=, and a 304 costs **5 units instead
of 100** and zero bytes. The research confirms =googleapis-common= teaches its
validator to accept 304 as a success (=validateStatus= accepts 2xx OR 304) — follow
that. Then the depth questions: what invalidates a cached entry when the mirror
says the file changed; how does =files.list='s =:none= policy interact with
=files.get='s =:validated= policy for the SAME entity; does a 304 refresh the
cached blob's provenance timestamp.

** 3 · Measure =:keep= retention on a real corpus
PLAN-137 phase 6 makes the mirror lossless — a =:db.type/term= blob column plus
declared-field projections — and states the cost honestly: a 100 000-file Drive at
~2 KB each is ~200 MB of blobs PLUS datom history. That estimate needs a real
measurement on a real Drive before =:keep :all= is affirmed as the default. This
is the one place a guess would quietly become a policy.

* Explicit non-goals

- Do NOT add a second transport path for media. Same =proc.queue= admission, same
  budget line, same =:~drive/export= relation with an ordering column — a resumable
  upload is a job whose body happens to stream.
- Do NOT revisit the Drive cursor semantics; they are settled in the research
  below.

* Research already done (do not re-derive)

- =changes.getStartPageToken= → =StartPageToken.startPageToken=; "The page token
  doesn't expire."
- =changes.list= =pageToken= is set from the previous =nextPageToken= OR from
  =getStartPageToken=.
- =ChangeList= props: ={changes, kind, newStartPageToken, nextPageToken}=;
  =newStartPageToken= present ONLY at end-of-run ⟹ COMMIT ONLY AT END-OF-RUN.
- =pageSize= default 100, max 1000 (above coerced).
- No documented 410/expiry path — UNVERIFIED whether a stale token can be rejected
  server-side. Code the =:stale= branch anyway: =:stale nil= means "not expected",
  never "cannot happen"; treat an unexpected 4xx on a resumed run as a resync.
- Quota: 1,000,000 units/min/project; 325,000 units/min/user. Per method: get 5,
  list 100, download 200, edit 50, other (e.g. generateIds) 5.
- Errors: 403 =usageLimits/rateLimitExceeded= · 403 =usageLimits/userRateLimitExceeded= ·
  429 =usageLimits/rateLimitExceeded= · 403 =global/storageQuotaExceeded= (user
  storage full — NOT retryable) · 403 =global/insufficientPermissions=.
