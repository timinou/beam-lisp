* Initial Message

Please look at the various modules available and tell me what `bl` should ship with to be a complete interface to programming in beam-lisp

* Symptom

`mix bl check priv` reports `priv/boot/core.bl` as `:unreadable` (no metrics at all: 0 fns, 0 diagnostics), so the language's own core is invisible to the gate — a file that cannot regress because it is never measured.

The failing pass is the DIAGNOSTICS checker, not the parser: `bl lsp check priv/boot/core.bl` aborts with

#+begin_example
:diag-error if-let requires a vector for its binding in user:
#+end_example

while `lsp/document-symbols priv/boot/core.bl` succeeds (137 symbols) and `deodorant/report-source` succeeds (7 smells). So exactly one analyzer rejects the file.

* Hypothesis (not yet verified)

`core.bl` DEFINES the core macros (including `if-let`); the diagnostics pass almost certainly walks a defining form as if it were a USE — e.g. it consumes `(defmacro if-let [binding form & body] …)` or a `(defmacro …)`-shaped form whose binding slot is a plain symbol, and the "requires a vector for its binding" check fires on the macro's parameter vector being absent. The `in user:` suffix suggests the analysis namespace is `user` at that point, i.e. the ns form was not applied to this pass — a second, smaller bug in the same area: diagnostics should key its analysis by the file's declared namespace (the `(ns …)` form is at the top of core.bl).

* Reproduce

#+begin_example
mix bl check priv/boot/core.bl                     # prints the file as unreadable (0 metrics)
mix bl eval "(lsp/diagnostics (BeamLisp.Loader/read_source \"priv/boot/core.bl\") \"core\")"
mix bl eval "(count (lsp/document-symbols (BeamLisp.Loader/read_source \"priv/boot/core.bl\")))"   # 137, so the file parses
#+end_example

* Why it matters

`bl check` is the pre-commit gate over proofs, and `priv/boot/core.bl` is where the language is defined. Any regression in it (a lost `pure`/`terminates`/`eligible` proof on a core fn) is exactly what the gate exists to catch, and today it cannot.

* Acceptance

- `bl check priv/boot/core.bl` measures the file (non-zero `:fns`) and `:unreadable false`.
- `bl lsp check priv/boot/core.bl` prints diagnostics instead of raising.
- A test pins it: `check/analyze-source` on a source that DEFINES a macro with a symbol binding slot (minimal repro distilled from core.bl) returns metrics, not `:unreadable`.
