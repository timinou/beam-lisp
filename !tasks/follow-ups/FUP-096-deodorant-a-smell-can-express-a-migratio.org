* Context

`deodorant` has three tiers, and all three describe **rewrite safety**:

```
SAFE        value-identical for all inputs. Apply blind.
IDIOMATIC   value-identical under a mild, near-universal assumption.
REINVENTION a hand-rolled stdlib function. Exact, but restructures the form.
```

None of them can express a **migration** — a rewrite that is correct but whose
target is only *sometimes* available, and which brings a second edit with it.
That is exactly the shape FUP-094 needs, and today there is nowhere to put it.

* Three gaps, all hit while writing FUP-094

**(1) A smell cannot edit the `ns` form.** The `defregistry` migration is
mechanically perfect — one pattern, one replacement — and still leaves the file
broken, because the rewritten form needs `[srv :as srv]` on the require line.
`bl fix` today produces code that does not compile, and says nothing. A tool
whose output must be hand-repaired is worse than no tool, because the repair is
invisible.

**(2) A smell has no notion of "is the target available".** FUP-094's rules must
NOT be registered until `priv/std/server.bl` lands, because "a rule may only
rewrite to a word that resolves" (deodorant's own `ffirst` note). That constraint
is real and correct — but it is enforced by a human remembering, not by the
system. Register the rule early and every `bl fix --tier every` in the org
silently breaks. This is a *guard*, not a tier.

**(3) A deprecation is invisible until someone writes a smell.** `reg/defregistry`
and `bus/defbus` now carry `^:deprecated` in source (2026-09-18) and NOTHING
reads it. A consumer learns about the deprecation by reading a docstring, or by
running a smell that does not exist yet.

* Design

**(1) A smell may declare a require it needs.**

```clojure
(defsmell defregistry→registry-clause :migration
  (reg/defregistry ?name ?keys) => (srv/defserver ?name (registry ?keys))
  :when (fn [b] (let [k (get b '?keys)] (and (list? k) (= 'keys (first k)))))
  :ensure-require [srv :as srv])
```

`bl fix` then: if the file's `(ns …)` already requires `srv`, do nothing further;
if not, APPEND the entry to the existing `:require` vector. Conservative rules,
because `ns` is structural: append only, never reorder, never merge two requires
that differ in `:as`, and if the file has no `:require` at all, refuse with a
message naming the line to add rather than inventing one.

**(2) A smell may declare its PREREQUISITE.**

```clojure
:requires-ns srv/defserver     ; inert unless this resolves
```

An inert rule is reported as `⊘ skipped (target not available)` by `bl lint`, not
silently ignored. It makes FUP-094 registrable *now* with the honest behaviour,
and turns "do not register this yet" from a convention into a mechanism.

**(3) A new tier, `:migration`,** for exactly this: correct, but it restructures
the form AND may touch the header. Opt-in via `--tier every` (never in the
default ruleset), and reported by `bl lint` with the tier named so a reader knows
the output is a diff to review, not a cosmetic tidy. Distinct from
`:reinvention`, which never needs a second edit.

**(4) `^:deprecated` becomes a source of smells.** `bl lint` reads def metadata
and reports a deprecated var/form at its USE site, so a deprecation is visible
before anyone writes a rule for it. This is the generic mechanism the three
hand-written migration smells are then a special case of — and it means a future
deprecation costs a docstring, not a rule.

* Acceptance

- `bl lint examples/registry.bl --tier every` reports the `defregistry` use,
  names the tier and the successor, and (with the rule registered) `bl fix`
  produces a file that LOADS — including the require edit.
- A file with no `:require` gets a refusal naming the line, never a broken write.
- A rule with `:requires-ns` whose target is absent is reported as skipped, and
  `bl fix --tier every` is a no-op on that file.
- A `^:deprecated` use is reported with no smell declared.
- **No change to the default ruleset**: `bl lint` with no `--tier` is byte-identical
  before and after for every existing fixture.
