#+TITLE: code/query cannot be called over the wire: a JSON array of strings is not a datalog query
#+STATE: ITEM
#+CUSTOM_ID: FUP-041-code-query-cannot-be-called-over-the-wire

* Symptom

`code/query` is dead for every real MCP client. It works in-process (and the
tests only test it in-process), and over stdio it answers `-32602 Invalid
params` for any query a client can actually express in JSON.

#+begin_example
$ printf '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"code/query","arguments":{"query":["find","?ns","where",["?d",":fn/ns","?ns"]]}}}\n' | bl mcp
{"error":{"code":-32602,"data":{"reason":"Tool arguments or query are invalid"},"message":"Invalid params"},"id":1,"jsonrpc":"2.0"}

$ bl eval '(datom/q ["find" "?ns" "where" ["?d" ":fn/ns" "?ns"]] (datom/db (mcp.tools/conn)))'
error: a query must begin with a section keyword
#+end_example

* Why

`code-query-handler` (`priv/lib/mcp/tools.bl`) hands the decoded JSON array to
`datom/q` unchanged. JSON has no keywords and no symbols, so a client's
`"find"` is the STRING `"find"`, never `:find`; `"$"` is never `'$`; an `:in`
clause is never found by `in-tokens`. The handler's own guards make the failure
certain: `in-tokens` compares against the keyword `:in`, so a JSON query never
binds `$`/`%`, and the terminal `(apply datom/q query-vec inputs)` raises — the
raise is caught by `call-tool`, which reports it as `-32602` with no reason a
client can act on.

The query language is reachable through exactly two doors and both are shut
over the wire: `code/ask` (the named questions) works; `code/query` — documented
as "the floor of maximum power, the hatch an agent drops to when a question is
not yet named" (`docs/mcp-codebase-surface.md` §2) — cannot be called at all.

* Why nothing caught it

`test/bl/system/mcp_test.bl:146` drives `code/query` with
`(quote [:find ?title :where …])` — a beam-lisp vector of keyword symbols passed
straight to `server/request-response`. That value exists only in the VM: no JSON
client can produce it, so the test exercises a path no client has. It is the
same shape of gap FUP-036 closed for `resources/*` (in-process green, on-the-wire
red).

* Fix sketch (any one of them closes it; the first is the smallest)

1. **Accept EDN as a string.** If `query` is a string, `read-string` it before
   `datom/q`; a string is the one JSON type that can carry a keyword, and the
   descriptor's `:type` becomes `["array" "string"]`. `bl ask`'s own door and
   the CLI already read `.bl` source this way.
2. **Keywordize the array** — walk it and map every string that starts with `:`
   to a keyword and every `?x` to a symbol. Cheap, but it invents a second
   grammar for the same language (strings that are not quite strings, in a
   position where `"foo"` is a legitimate value).
3. **Advertise a `query/edn` variant** so the array form stays the structured
   case and the EDN case is named.

Whichever lands, the wire test must send what a client can send. A test that
constructs a keyword query in the VM proves the handler, not the surface.

* Acceptance

- `bl mcp`, from a built drop, answers `code/query` for a query sent as JSON —
  the same query `bl ask` answers.
- `test/bl/system/mcp_test.bl` drives it through the transport (or through a
  JSON-shaped payload), so a regression is red.
- `docs/mcp-codebase-surface.md` §2 and the `beam-lisp/usage` prompt describe
  the encoding a client must use, not "raw datalog" without saying how.
