* The gap

`codebase`'s schema (`priv/std/codebase.bl`) carries `:fn/*`, `:call/*`, `:instr/*`,
and `:~reaches` as a derived relation over the CALL graph. There is no
namespace-level relation: no `:ns/name`, no `:ns/requires`, no `:ns/references`.

Consequence, measured on this repo's own prism (222 `.bl` files):
`sg/header*` over the whole corpus is 3.9 s, and it is unavoidable for any question
of the form "which files name namespace X" — a rename's observer set, a rename's
candidate filter, and the namespace graph a `bl ui` pane wants (FUP-086) are all the
same question. The per-source analysis CACHE (`codebase/analyze-cached`, content-
addressed, `facts-for`/`read-facts`/`write-facts!`) cannot help, because the fact
being asked for is not one it stores.

Contrast: `build-plan/plan` over the same 222 sources is **5.65 ms** — the machinery
that already consumes these facts is three orders of magnitude cheaper than deriving
them.

* The change

Two attributes in `SCHEMA`:

    {:db/ident :ns/name     :db/valueType :db.type/string :db/index true}
    {:db/ident :ns/requires :db/valueType :db.type/string :db/index true}

and, in `index-forms` (which already sees the `(ns …)` form — it has a dedicated
`is-ns` branch for the `^{:instr …}` case), emit one `:ns/name` fact for the
declared namespace and one `:ns/requires` per require target, read from the same
reader forms `source-graph/header*` already derives them from.

No new cache, no new file format: `index-forms` is the function whose output is
already persisted per content hash, so both new facts are cached for free and every
door that opens a store gets them.

* Why it is worth it

  · A rename's candidate set becomes a prefix query instead of a corpus parse
    (measured: 222 files → 6 candidates for `core -> kernel`, 15 for `datom -> …`).
  · FUP-086's namespace graph becomes a query over an index the session already
    holds, instead of its own walk.
  · `bl ask` gains a class of question it cannot currently answer at all
    (ns-level impact: "who requires typed", without going through the call graph).

* Edge cases to settle in the change

  · A source with no `(ns …)` form contributes no `:ns/name` — and must not be
    silently invisible to the require graph either; today `build-plan` treats it as
    compiling into `user` with no closure.
  · `:refer :all` must stay distinguishable from a name list if `:ns/references` is
    added too — `build-plan/covered?` already refuses the `:all` edge and the same
    refusal has to survive the move into facts.
  · One `(ns …)` per file is the assumption everywhere else in the tree; a second one
    in a file should be a check, not a silent last-wins.

* Acceptance

  · `(datom/q '[:find ?ns ?r :where [?n :ns/name ?ns] [?n :ns/requires ?r]] db)`
    over an indexed tree returns the same edge set as
    `(sg/header* …)` over its sources — pinned by a test, edge by edge.
  · A second run over unchanged sources answers it from cache: `code.index`'s stats
    report `:analyzed 0`.
  · A rename's observer query over a 222-file tree runs without reading a single
    source file.
