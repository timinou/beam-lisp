* OPEN FUP-010 Sandbox.warm!/2 races a concurrent :global load: empty base cached forever

Found 2026-08-28 while running spell's suite against PLAN-046 (beam-lisp HEAD 744c915).

** Defect

`Sandbox.warm!/2`'s docstring claims a concurrent double-warm is "wasteful,
never wrong". It is wrong in one case: when another thread is concurrently
loading the same namespaces into `:global`.

Mechanism: `Env.loaded_ns?/1` walks the caller's whole read-through chain
(base → … → `:global`). `warm!` evaluates its sources inside the base env, so
a namespace the other thread already marked loaded in `:global` reads as
loaded inside the warm — the warm SKIPS it — and the base env never gets the
vars. `warm!` then caches that base in `persistent_term` under its name. The
empty base is served to every suite for the rest of the VM run; every fork of
it misses every app namespace ("no beam-lisp var spell.seed/contract-term").

Observed shape in spell: three async suites flipping to per-test forks
(`mix test`): 14–22 tests fail with missing-var errors, deterministic loser
per seed, each suite green in isolation and in most pairs.

** Why it matters

The failure looks like a flake (suite-order-dependent, green in isolation) but
is structural: any app that both (a) forks warm bases in async tests and
(b) loads the same namespaces into `:global` for non-async suites or app
boot has a bootstrap-order constraint the library neither enforces nor
documents. The chain read-through that makes forks zero-copy is exactly what
makes a second load silently produce an empty image.

** Candidate directions

- Make namespace loading idempotent PER ENV rather than consulting the chain
  in `loaded_ns?/1` during a warm (e.g. warm! binds a flag that narrows the
  loaded-check to the current env), so a base always gets its own rows.
- Or document the bootstrap contract: "warm all bases BEFORE anything loads
  into :global, under one lock" — the fix spell landed in
  `apps/spell/test/support/spell_case.ex` (`ensure_loaded!`: warm first,
  then :global, both inside one `:global.trans`).

spell-side fix: spell repo, uncommitted as of filing, `SpellCase.ensure_loaded!/0`.
