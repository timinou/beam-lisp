* Context

The process bundles live loose at the root of `priv/std`:

```
priv/std/flow.bl   (ns flow)      priv/std/reg.bl    (ns reg)
priv/std/bus.bl    (ns bus)       priv/std/super.bl  (ns super)
priv/std/fence.bl  (ns fence)     priv/std/tick.bl   (ns tick)     ← new
                                  priv/std/server.bl (ns server)   ← P1.5
                                  priv/std/sched.bl  (ns sched)    ← P2
                                  priv/std/jobs.bl   (ns jobs)     ← P5
```

`priv/std` is a FLAT root, so `flow.bl` is `(ns flow)`. That is fine for three
files and wrong for ten: the bundle tier has no name, no place, and no single
door. A consumer writing a process system today must know which of six
namespaces to require, and `defserver` itself arrives from nowhere in particular.

Everything else in the tree already has this solved: `priv/std/vm/*` → `vm.*`,
`priv/std/bl/*` → `bl.*`, `priv/std/reload/*` → `reload.*`. The bundles are the
one group without a folder because they grew one at a time.

* Design

**Folder `priv/std/proc/`** — the process bundles, all of them:

```
priv/std/proc.bl        (ns proc)         ← the umbrella: the public API
priv/std/proc/flow.bl   (ns proc.flow)
priv/std/proc/bus.bl    (ns proc.bus)
priv/std/proc/reg.bl    (ns proc.reg)
priv/std/proc/super.bl  (ns proc.super)
priv/std/proc/fence.bl  (ns proc.fence)
priv/std/proc/tick.bl   (ns proc.tick)
priv/std/proc/server.bl (ns proc.server)  ← the clause vocabulary (PLAN-126 §4.6)
priv/std/proc/sched.bl  (ns proc.sched)   ← later
priv/std/proc/jobs.bl   (ns proc.jobs)    ← later
```

**The umbrella is a ONE-LINE file per module** — verified, not assumed:

```clojure
;; priv/std/proc.bl
(ns proc
  (:require [proc.flow :refer :all]
            [proc.bus :refer :all]
            [proc.reg :refer :all]
            [proc.super :refer :all]
            [proc.fence :refer :all]
            [proc.tick :refer :all]
            [proc.server :refer :all]))
```

A refer IS a re-export in this runtime: `BeamLisp.Env/refer_source` records where
a referred name came from (`compiler.bl:2332, 2496`), so `proc/fence-fn` and
`proc/tick-delay` resolve from the outside. Probed this session:

```
(ns zzumbrella (:require [tick :refer :all]))
(ns scratch.umbrella (:require [zzumbrella :as z]))
(z/tick-delay 100 {} 0)   → 100        ; a fn through the umbrella
(z/tick-gen :nope)        → 0          ; …and another
```

So a consumer writes ONE require and gets the whole pattern language:

```clojure
(ns app.jobs
  (:require [proc :as proc]
            [proc :refer [defserver registry bus tick fence]]))

(proc/defserver workers
  (registry (keys :id))
  (bus (demand 8))
  (tick 15 :minutes [st] (reap!)))
```

**Which modules move, and which do not.** The criterion is *is this a process
bundle* — a namespace whose content is clauses plus verbs over a running
process:

- **moves**: flow, bus, reg, super, fence, tick, server, and later sched, jobs.
- **stays**: `deodorant`, `rewrite`, `span-rewrite`, `typed`, `optics`, `multi`,
  `errors`, `env`, `test`, `reload` — analysis and language layers, not bundles.
  Filing them under `proc/` would be the same mistake in reverse.

**Migration.** A namespace rename touches every caller, so it is a cutover with
shims, and the shims are one line each (verified above):

```clojure
;; priv/std/flow.bl — kept, deprecated
(ns ^:deprecated flow
  (:require [proc.flow :refer :all]))
```

`flow`, `bus`, `reg`, `super`, `fence` keep working with zero churn; deodorant
smells move callers to `proc.*` and then to the umbrella (FUP-094/095/096 carry
the machinery, and this is the largest consumer of it — six namespaces and every
example). The shims are deleted one release later.

* Risks

- **A rename that outruns the smells is churn.** Order matters: land the folder
  and the shims (no caller changes), THEN the smells, THEN delete the shims.
- **`proc` vs the docs.** `docs/the-process-pattern-language.md` is the
  authority for this tier; whichever name wins, that document must say it. The
  alternatives considered: `pattern/` (matches the doc, longer to type),
  `bundle/` (matches `the-five-bundles.md`, but "bundle" is a *count* in that
  doc, not a noun for the tier), `proc/` (short, unambiguous, and already the
  word used in the tree for a running process).
- **The umbrella must not become a wall.** A program that wants one bundle
  should still be able to require just that one (`proc.tick`), so the umbrella
  is a convenience, never a requirement.

* Acceptance

- `proc` exists, the umbrella resolves a fn and a macro from every member
  namespace, and `bl test` is green with the shims in place.
- No caller change is required by the move itself: `examples/` runs unchanged.
- Each shim is `^:deprecated` and names `proc.<x>` as the successor.
- `docs/the-process-pattern-language.md` and `docs/bl/00-the-cli.md` name the
  tier and the umbrella.

* Evidence

- Flat std root + dotted subdirectories: `priv/std/vm/`, `priv/std/bl/`,
  `priv/std/reload/` — the convention this FUP applies to the bundle tier.
- Re-export probe: recorded above, run 2026-09-18 from the tree root.
- The clause-isation that makes `server` a bundle at all: PLAN-126 §4.6, §4.6.1.
- `docs/the-process-pattern-language.md` — the tier's own document.

NOTE [2026-09-18]: CORRECTION (2026-09-18, same session) — the umbrella works for FUNCTIONS, not for MACROS.

The re-export probe in the body was run with two functions and passed. Probing
further after P1.5 landed:

    (ns a) (defmacro m [] `(do 7))
    (ns b (:require [a :refer :all]))
    (a/m)   → 7                       ; direct qualified: a macro ✓
    (b/m)   → cannot call {:"$macro", #Function…} — a value is not a function

So a REFERRED macro resolves as an unqualified NAME inside the referrer (which
is why `(:require [tick :refer [defbeat]])` + `(defbeat …)` worked), but a
QUALIFIED head `b/m` goes through a path that does not consult the referrer's
macro table. `macro-lookup` for a qualified head sees the ns's own defs.

Consequences for this FUP:

1. `proc` as an umbrella is correct for the VERBS (every `reg/*`, `bus/*`,
   `flow/*`, `tick/*` fn) and for the fn half of the API. It CANNOT carry
   `defserver` — nor any other macro (`defregistry`, `defbus`, `defsupervisor`)
   — which means a macro lives in exactly ONE namespace and a consumer requires
   that namespace directly.
2. So the clause-isation (PLAN-126 §4.6.1) has a second payoff nobody planned:
   once `defregistry`/`defbus` are CLAUSES rather than macros, the only macro a
   consumer needs is `defserver`, and the umbrella's inability to re-export it
   stops mattering — everything else is a fn or a clause name.
3. The PLAN-126 §4.6 boot rename (`defserver` → `defgen`) makes that last macro
   referable unqualified, which is the other half of the same fix.

Net: the umbrella's job is the VERB surface plus the namespace home; the FORM
stays in `server`, and this FUP's acceptance should not assume `proc/defserver`
can exist.

NOTE [2026-09-20]: NOTE [2026-09-20]: DONE — the move landed as a cutover, with no shims.

What changed:

- `priv/std/{flow,bus,reg,super,fence}.bl` → `priv/std/proc/{flow,bus,reg,super,fence}.bl`, each declaring `(ns proc.<name>)`. The tier was already half-moved (`server`, `tick`, `sched`, `table`, `queue`); this finishes it, so nothing sits loose at the root of `priv/std`.
- Callers repointed in the same cutover: `priv/std/proc.bl` (the umbrella), `priv/std/z3pool.bl`, `priv/std/reload/ward.bl`, `priv/std/vm/owner.bl`, `priv/lib/live/app.bl`, `priv/std/reload.bl`, 8 examples, 2 test files, and the docs/guidebook.
- NO shims at the old paths, deliberately (the ticket's constraint): a leftover that resolves is two answers to one question. `test/bl/proc_home_test.bl` fails if a bare `flow`/`bus`/`reg`/`super`/`fence` resolves again (26 assertions, ward + shared both green).
- Where a bundle lives is now stated in `docs/the-process-pattern-language.md` ("Where a bundle lives"), enumerated in `priv/std/proc.bl` (the door), and named in `docs/bl/00-the-cli.md`. The rule: `priv/std/proc/<name>.bl` declares `(ns proc.<name>)` — the file name and the namespace are one fact. `proc` is the door; `[proc.tick]` still loads one bundle.

Evidence: `./bin/bl test --shared test/bl/{reg,bus,table,tick,sched,queue,proc_home}_test.bl` → 72 tests / 266 assertions, 0 failures; the 8 touched examples → all green; the top-level suite (42 files) → 468 tests / 1842 assertions, 0 failures.

Two things the move SURFACED, filed separately: BUG-087 (an implicit alias for a dotted namespace compiles to a module named after the alias — two live sites had to spell `:as`), and BUG-085 (`bl build` loses every load-time registration, so a BUILT image cannot compile a clause `defserver`; the tier's beams are absent from `build/` for that reason). Also FUP-109 (deodorant's three `:migration` prerequisites still name `reg/registry-clause` / `bus/bus-clause`) and BUG-088 (a beam whose source vanished still loads, which is why the old names kept working until `bl build` pruned them).
