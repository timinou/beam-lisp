#+TITLE: merges can produce nested #() fn literals and unbalanced forms that nothing catches before boot
#+STATE: ITEM
#+CUSTOM_ID: FUP-166-nested-fn-literals-from-merges

* What

Merging the backdesk runtime line into main (209f0309, then the v2026.6 release
merge) produced source the reader or compiler rejects, and boot only showed the
first error each time:

| file | defect | fixed in release/v2026.6 |
|---|---|---|
| `priv/lib/datom/conn.bl` `run-guards!` | `#(… (with-native-command-callback! #(pred report)) …)`: nested `#()` | inner literal → `(fn [] (pred report))` |
| `test/bl/reload/guard_reservation_test.bl:48,86` | nested `#()` in `generation/with!` | inner → `(fn [] …)` |
| `test/bl/reload/store_opening_test.bl:36,60` | nested `#()` around `d/connect-with` | inner → `(fn [] …)` |
| `test/bl/aot_declaration_staging_test.bl:12` | nested `#()` in `original` | inner → `(fn [] …)` |
| `priv/std/proc/queue.bl` `launch!` / `launch-selected!` | one `)` too many after the split; `claim-opts` dropped | arity restored, paren removed |

The reader rule itself is correct: Clojure forbids nested `#()` too. The gap is
that no check runs on merged sources before a boot, and boot surfaces one file
at a time, so each failure needed a full ~15 min floor regeneration to reach.

* Follow-up

1. Add a cheap pre-commit or CI read of every tracked `priv/**/*.bl` and
   `test/**/*.bl` with the boot reader (read only, no compile), reporting ALL
   failures at once. The text heuristic I used (`/tmp/findnest.py`, a paren and
   `#(` depth scan) found these but reports false positives where a `(fn …)`
   sits between two literals; the real reader is the authority.
2. Make the error for a file loaded at boot name the file. The nested `#()`
   error printed only reader frames, so finding `conn.bl` took a repo-wide scan.
3. Sweep the rest of the tree, which the scan skipped: `apps/`, `examples/`,
   `projects/`, `prototypes/`.
