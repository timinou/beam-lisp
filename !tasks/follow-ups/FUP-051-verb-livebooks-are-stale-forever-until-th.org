* Initial Message

* Symptom

`bl doc run <verb>.bl.md --check` reports staleness for the verb livebooks under
`priv/std/bl/`, and the verdict is not caused by any edit — it holds for the
COMMITTED file too:

    $ git show HEAD:priv/std/bl/ports.bl.md > /tmp/head_ports.bl.md
    $ mix bl doc run /tmp/head_ports.bl.md --check
    bl doc run: /tmp/head_ports.bl.md — stored results are stale; run `bl doc run` to refresh

Sampled 2026-09-13: `env.bl.md`, `ask.bl.md`, `mcp.bl.md`, `ports.bl.md`,
`test.bl.md` all stale. These are the tool's own livebooks, so the gate reads as
"the docs are broken" for anyone who runs it.

* Mechanism (observed)

A livebook whose cells are DEFINITIONS has nothing to show, but the doc runner
treats every non-`frozen`, non-`silent` cell as one that must carry a stored
result. Refreshing therefore writes noise into the manual — on a copy of
`ports.bl.md`:

```bl-result list-ports
&BeamLisp.Ns.Bl.Ports."loopback-url"/1
```

```bl-result pad
&BeamLisp.Ns.Bl.Ports.run/2
```

Function references, one per cell. Storing them would make every future code
move look like a doc break, and the result would be truth only by accident.

* Fix (confirmed, mechanical)

The token already exists and does exactly the right thing: `silent` cells RUN
(so the gate still verifies they compile and evaluate) and store no result.
Verified on a copy:

    $ mix bl doc run /tmp/silent_probe.bl.md        # every fence marked `silent`
    bl doc run: /tmp/silent_probe.bl.md — 5 cells, 0 cell errors
    $ diff /tmp/head_ports.bl.md /tmp/silent_probe.bl.md | grep -c bl-result
    0
    $ mix bl doc run /tmp/silent_probe.bl.md --check
    bl doc run: /tmp/silent_probe.bl.md — 5 cells, 0 cell errors (checked, unchanged)

Applied to the three livebooks PLAN-103 owns (`bl.env`, `bl.test`, `bl.ports`),
each now gates clean: 6 / 3 / 5 cells, 0 cell errors.

* What remains

Every other `priv/std/bl/*.bl.md` whose cells are definitions: mark the
definition fences `silent`. Mechanical, no runner change:

    python3 - <<'EOF'
    for path in [...]:
        src = open(path).read()
        assert "bl-result" not in src
        open(path, "w").write("
".join(
            l + " silent" if l.startswith("```beam-lisp") and "silent" not in l else l
            for l in src.split("
")))
    EOF

Do NOT "fix" it by running `bl doc run` on them: that stores function
references as results.

* Non-goal

Changing the runner to infer "this cell is a definition". `silent` is an
existing, explicit, author-owned token; inferring intent from a cell's shape
would hide a real case — a cell that defines AND prints.
