Found in the post-PLAN-029/PLAN-031 cross-review (2026-08-19). Two defects, one fix.

* Problem 1 — recogniser drift, verified

The emitter (`spell.contract/hole-name`) recognises TWO hole node shapes: `(deref x)` reader nodes AND bare `$sym` symbols. `spell.machine/undeclared-template-holes` recognises only the first. A template body `[:span $typo-hole]` is emitted by the emitter (as a `` `$typo-hole` `` hole verse will resolve to nothing) but NEVER flagged by the check. Verified by a failing probe: `machine-findings` on a view whose template contains `$typo-hole` (undeclared, unreadable) reports no undeclared-hole for it (the `@m.text` sibling IS flagged). This is the blank-render bug (BUG-368 family) back through a new spelling — exactly the drift `hole-name`'s own docstring warns against. The gap originated in PLAN-029's `tree-holes` (deref-only) and was carried by 6d4c031's inline copy.

* Problem 2 — the recogniser exists four times

- `spell.contract/hole-name` — emitter's, also used by `spell.live/machine-shell-holes` (the good pattern)
- `spell.machine/view-bindings` — inline `(deref name)` 2-elem predicate with base-through-the-dot projection
- `spell.machine/undeclared-template-holes` tree branch — byte-identical copy of the same predicate (6d4c031 inlined it where PLAN-029 had one shared `tree-holes` fn)
- `spell.machine/hole-roots` — the string scanner, kept by 6d4c031 for check-layer totality (raw `parse-view` can still hand the machine a string body; `run` refuses strings at rung 1)

* The fix (one PR)

One fn in machine.bl, e.g. `template-hole-roots`:

#+begin_src
(defn- template-hole-roots
  "Root names of every hole in a template body, whatever its representation:
   a STRING body is scanned (`hole-roots`); a TREE body is walked with
   `spell.contract/hole-name` — the emitter's own recogniser, so check and
   emitter cannot drift — projected to the base name through the dot."
  [t] ...)
#+end_src

Then: `undeclared-template-holes` uses it for both branches; `view-bindings`' markup plane uses it (binds plane keeps its own walk — different need, binding sites not holes). `$sym` holes become visible to the check automatically because `hole-name` sees them. Delete the inline copy. Keep `hole-roots` only as the string branch of this one fn.

While there: `hole-roots`' docstring references `hole-markers` in contract.bl — deleted in 53942e2; stale pointer.
