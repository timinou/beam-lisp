#+CUSTOM_ID: FUP-109-deodorant-migration-prerequisites-still

* What

Three `:migration` smells in `priv/std/deodorant.bl` gate themselves on a
qualified symbol that the bundle move just invalidated:

```
:requires-ns reg/registry-clause      (defsmell defregistry→registry-clause)
:requires-ns bus/bus-clause           (defsmell defbus→bus-clause)
:requires-ns bus/bus-clause           (defsmell defbus→bus-clause-default)
```

`reg` and `bus` are now `proc.reg` and `proc.bus` (the bundle tier lives under
`priv/std/proc/`, namespace `proc.<name>` — FUP-097). The vars themselves are
unchanged; only the namespace in front of them moved:

| now reads | should read |
|---|---|
| `reg/registry-clause` | `proc.reg/registry-clause` |
| `bus/bus-clause` | `proc.bus/bus-clause` |

* Why it matters, and how loudly

`deodorant/available?` resolves the prerequisite with
`BeamLisp.Loader/ensure_loaded` + `BeamLisp.Env/fetch`, so the moment `reg` stops
resolving these three rules become INERT. They are then reported as skipped by
`bl lint --tier every` — honest output, but the migration stops firing for
consumer code that still writes `(reg/defregistry …)` / `(bus/defbus …)`, which
is exactly what those rules exist to rewrite.

* Why it was not done in the same commit

`priv/std/deodorant.bl` was OFF LIMITS to the session that did the move (a
parallel session was mid-edit on it, Vocab096). The move could not wait for it:
the file move and the namespace rename are one cutover, and every caller in the
tree had to be repointed at once.

* Acceptance

- `priv/std/deodorant.bl` names `proc.reg/registry-clause` and
  `proc.bus/bus-clause`.
- `bl lint --tier every` on a file holding `(reg/defregistry x (keys :id))`
  reports the rule as AVAILABLE (not skipped) and `bl fix` rewrites it.
- `test/bl/deodorant_test.bl` is green (it asserts registration, not
  availability, so it does not catch this today — consider adding the
  availability assertion).

* Evidence

- `priv/std/deodorant.bl:231-253` — the comment and the three `:requires-ns` lines.
- `priv/std/deodorant.bl` `available?` / `var-resolves?` — the gate.
- `priv/std/proc/reg.bl`, `priv/std/proc/bus.bl` — where the two vars live now.
