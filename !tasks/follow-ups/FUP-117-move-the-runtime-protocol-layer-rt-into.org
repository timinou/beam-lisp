* Initial Message

my friend, can you tell me why the fuck `rt` is still in elixir and not in beam lisp, and how that affects the current work on the repl/play interfaces? design+arch+infrastructure, no impl

* Goal

`BeamLisp.RT`'s protocol layer stops being Elixir, so the bootstrap seed no
longer floors on it. Prototype and measurements: `research/rt-selfhost/`
(see `RESULTS.md`).

* Measured starting point

Import tables of `priv/bootstrap/seed/*.beam` (`beam_lib:chunks(F,[imports])`)
show the boot tier needs exactly:

- `BeamLisp.RT` — 57 functions
- `BeamLisp.Vector` — `__struct__/1`, `new/1`, `to_list/1`
- `BeamLisp.Set` — `new/1`, `to_list/1`
- `BeamLisp.LazySeq` — `from_fun/1`, `lazy?/1`
- `BeamLisp.Record` 4 · `BeamLisp.Num` 8
- `BeamLisp.Env` 21 (separate: the evaluation substrate)

* The concrete blockers, each located

1. `priv/boot/compiler.bl:167` — `mod-rt`, the one place the compiler hard-codes
   `BeamLisp.RT` as the target of every dynamic call (`RT.invoke/2`).
2. `priv/boot/compiler.bl:561-593` — literal lowering emits
   `Elixir.BeamLisp.Vector:__struct__/1`, `Elixir.BeamLisp.Set:new/1` and
   `Elixir.BeamLisp.RT:hash_key/1`.
3. `lib/beam_lisp/set.ex` (and map membership) call `BeamLisp.RT.hash_key/1` for
   normalisation — a one-call re-point once the kernel provides it.
4. BL has no `cons` or tuple constructor primitive: `(tuple a b)` is a prelude
   def (`priv/boot/core.bl:1575`) and `cons` is a runtime def. A kernel must
   build lists with `make_tuple`/`setelement`/`tuple_to_list` +
   `lists:append/1` (O(1) cons), or the compiler gains a `cons` special form.

* Prototype status (not the cutover)

`krt/kind.bl`, `krt/seq.bl`, `krt/eq.bl` — classification, the seq protocol,
and one comparison with `=` derived from it. Compiled beams carry no
`BeamLisp.RT` calls; parity with the Elixir runtime is 18/18 values on
seq/first/rest/count; cost is 1.28-1.59x on leaf ops and 0.86x on comparison.
Still missing: `invoke`, the printer, lazy map/filter/range on `lazy-seq`,
`hash-key` normalisation, refs/transients/OTP, sorted collections beyond
seq/count.

* Acceptance

- `bl build` of the boot tier under a krt-seeded core produces beams whose
  import tables contain no `Elixir.BeamLisp.RT`.
- The toolchain (compiler, reader, lowerer, prelude) rebuilds from source on
  that core and `bin/bl doctor --deep` plus the focused suites pass.
- `bl seed` stages the new generation; a fresh clone boots from it.
- `priv/bootstrap/seed/manifest.exs` records the new toolchain key.
