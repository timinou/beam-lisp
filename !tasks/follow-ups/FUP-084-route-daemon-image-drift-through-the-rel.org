* Question (user, 2026-09-16)

When the daemon's booted image drifts from the tree, shouldn't the RELOAD mechanism
check which updates are safe and apply them warmly, instead of a restart? (BUG-052
residual.)

* What exists today

- The SAFETY half already exists and is exactly the right gate: reload.reconcile
  computes per-namespace HOLD reasons — dangling (undefined var), removal (would break
  a live caller), promise-never-defined, policy (BEAM_LISP_RELOAD) — and holds the
  bundle, old code still serving (observed verbatim in reload.reconcile-test output).
- The WARM-APPLY half exists for source edits: the watcher submits a reload commit to
  the single Executor FIFO (Daemon.Executor.run_reload, workers.ex:61-72) so a commit
  never races a running command.
- The DRIFT half does NOT route through it: aot_cache.ex refuses to link stale
  artifacts ("must force a restart, not a stale reuse", aot_cache.ex:186-199), and the
  daemon's answer to toolchain drift is a blunt restart. Toolchain/tier drift (seed
  beams, priv/boot tier-1, lib/*.ex substrate) is precisely the case reconcile was not
  built for: a restart is currently the only safe answer when the COMPILER ITSELF moved.

* The sound split

Two drift classes, two answers:
1. TREE drift (priv/lib, priv/std, project sources — anything ABOVE tier-1): route
   through the existing reconcile gate warmly. Stage changed namespaces as a bundle;
   HOLD reasons already name what is unsafe. This is a small step: the watcher already
   does it for file events; drift detection just needs to synthesize the same bundle.
2. TOOLCHAIN drift (tier-0/1: compiler.bl, reader.bl, core.bl, the seed, lib/*.ex):
   warm-applying a new compiler with the OLD compiler's beams resident is the BUG-048
   deadlock class. Here the safe move IS a restart — but it can be a WARM restart:
   rebuild the changed tiers, spawn the successor VM, hand over the socket/endpoints,
   drain in-flight Executor FIFO entries, retire the predecessor. The reconcile gate
   still runs as the verifier of the new image before handover.

* Acceptance sketch

- `bl daemon status` reports drift class: none | tree (N namespaces applicable warmly)
  | toolchain (restart required, warm-handover available).
- A tree-drift case applies warmly with the reconcile verdict visible.
- A toolchain-drift case never silently runs stale (the BUG-052 gate) and never
  cold-drops in-flight work (handover drains the FIFO).
- Tests: reload.reconcile-test-style coverage for both classes.
