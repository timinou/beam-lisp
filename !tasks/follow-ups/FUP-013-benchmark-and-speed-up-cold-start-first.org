* Initial Message

how hard would it be to bootstrap beam lisp fully?

** Problem

A fresh worktree/clone shares no ~_build~, so the first ~mix compile.beam_lisp~
must AOT-compile all ~468 prelude ~.beam~ modules from ~.bl~ source. Measured on
this host (AMD Ryzen AI 7 350): partial build reached only 112/468 modules in
~15min wall, i.e. the full cold build is on the order of 30-60min — and it is
SILENT (no progress output) and dies opaque under any timeout. Discovered while
setting up the PLAN-057 self-hosting worktree; it read as a hang.

Incremental rebuilds are fine (content-hash manifest); this is purely the COLD
path.

** Why it matters

- DX failure: "clone → first run" taking up to an hour with zero feedback is the
  kind of gotcha that makes a self-hosting language feel broken on first contact.
- It is adjacent to the PLAN-057 frozen-seed work (~priv/bootstrap/*.beam~): a
  committed seed largely removes this for the reader+compiler, but the ~130-ns
  prelude AOT cost remains.

** Scope

1. BENCHMARK the cold build honestly: wall time, per-namespace cost, where the
   time actually goes (reader? compiler? Code.compile_quoted? signature
   inference — note PLAN-006 already disabled infer_signatures for a 93s→63ms
   case, so re-confirm it is off on this path). Follow AGENTS.md benchmarking
   protocol: >=3 samples, report spread.
2. IDENTIFY the dominant cost and the cheapest honest win. Candidates (verify, do
   not assume): parallelize independent namespaces across schedulers; cache/commit
   a prebuilt prelude beam set as a build artifact; batch Code.compile_quoted
   calls (aot.ex L849 already notes "~130 body modules with one
   Code.compile_quoted call each" — a batching lever); skip re-AOT when the .bl
   sha + compiler sha are unchanged (provenance already exists via
   __bl_provenance__).
3. PROGRESS OUTPUT regardless of the speedup: per-namespace line with count/total
   so the cold build is legible, not a silent wait. Overlaps PLAN-057 task
   aot-dx; if that lands the progress UI, this FUP keeps the pure perf mandate.

** Acceptance

- A documented benchmark (numbers + spread + bottleneck) committed under docs/ or
  research/.
- Cold first-build wall time materially reduced (target: state a number after the
  benchmark says what is achievable), OR a committed-artifact path that makes a
  fresh clone boot fast without the full recompile.
- Cold build shows progress; never a silent multi-minute hang.
