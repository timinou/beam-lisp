#+TITLE: datom conn registry must bind the caller's env per action (async tests)
#+STATE: ITEM

* Background (zero-context)

PLAN-046 (env isolation) gave beam-lisp process-scoped environments: every
test can fork a private env, ExUnit cases run async, and `mix
beam_lisp.test --async` runs bl suite files concurrently. Env bindings live
in the process dictionary; bl's own spawning (future/promise) propagates
them, and host code opts in with `BeamLisp.Env.capture/0` + `bind/1`.

* Problem

`priv/datom/conn.bl` keeps a NAMED singleton Agent
(:"datom-conn-registry") whose actions are compiled bl fns
(`datom.conn/store-cell` etc.). The Agent applies those fns in ITS OWN
process, which has no env binding → they evaluate at `:global` →
`undefined var: datom.conn/store-key` the moment a forked env (async test)
opens a connection. Observed 2026-08-28 in BOTH `mix beam_lisp.test
--async test/bl/auth` and `BL_ASYNC=1 relay/.local/bltest` (full suite);
serial mode is unaffected because everything shares `:global`.

Two distinct defects:

1. The env crash above: fns applied inside the Agent resolve vars in the
   wrong environment.
2. Even past the crash, a shared named registry leaks connection state
   ACROSS forked tests — an isolation violation (tests would see each
   other's conns).

* Proposal

Per-call env binding in conn.bl's registry actions: capture
`BeamLisp.Env.capture()` at the CALL site (the process calling
connect-with / transact / …), pass the token alongside the action fn, and
`BeamLisp.Env.bind(token)` inside the Agent's apply. That fixes (1) with
Clojure-dynamic semantics intact (vars resolve in the caller's env, as if
no process boundary existed).

For (2), either key the registry per env (registry name or row keys carry
the env id), or document that conns are shared across concurrently-running
test files (acceptable when tests use distinct store keys — relay's suite
mostly does).
