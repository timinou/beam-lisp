#+STATE: ITEM

* Initial Message

(carried over from PLAN-163 item 4 / PLAN-158 steps 12-13, 2026-10-04) The gateway serves realm pages itself, asking the owning VM over control frames (decided). Built so far: the gateway starts lazily when a name is claimed, and the =:show= control frame, =realm/describe= and the shadow chip exist and print in =bl realm show=. The pages do not.

** What exists (reuse, do not rebuild)
- =vm.machine= (293 lines): Host guard, token, =/machine=, =/api/vms=, POST stop. Wrapped by the session router so every route is Host-guarded. =vm.inventory= rows are what both =bl vm= and the page render.
- Control frames: =:status :stop :realms= and ={:op root}= for =:close :members :restart :show=. =client/show=, =client/members=, =client/realms=.
- =realm/describe= -> ={:alias :key :root :shadows :uses :members}=; =realm/shadow-chip= -> "◇ shadows N: a, b, c, +k" or nil.
- docs/design/realm/console.md (target IA and design rules), docs/design/realm/gateway-and-control-frames.md (why and how).

** To build
1. Move =/machine= and =/api/vms= from the per-VM session into the gateway (machine-wide, outlives every VM). The gateway reads every VM's token file (same user, mode 0600) and keeps the Host guard and 127.0.0.1 bind.
2. =/realm/<alias>=: the gateway resolves the alias through the registry, asks the VM with =:show= (and =:members=), and renders. Add the =:realm-log= frame (tail of the realm's log) for the page's log section.
3. The shadow chip on the realm's row and page (FUP-154): text plus the =◇= mark, never colour alone; the diff link calls =bl realm diff NS= (not yet written: prints the shadow against the library's version).
4. Live updates: poll every 2 s with an ETag first; SSE only if polling shows a layout or cost problem.
5. Keyboard (j/k/enter/s), aria-live status, narrow screens, light and dark from one token set, contrast >= 4.5:1 computed; =impeccable detect= = 0 findings (console.md rules).

** Gate
- the page and =bl realm show= render the same strings (a test compares them);
- a shared VM's realm page is served though that VM serves no dashboard of its own;
- a stop from the page ends exactly that VM, and the page shows it gone;
- a request with a foreign Host header is refused on every gateway route.

** Not in scope
A health score, a start button, replacing the REPL/catalog/schedules pages (console.md "does not").
