* What

PLAN-143 item 2 removes the duplicate row build INSIDE one projection. It does
not stop a projection from rebuilding every row when one row changed.

Measured: one Backdesk row costs ~24 ms to build (`work/detail` for a single
assignment = 25 ms on the seeded fixture; a row is ~20 index reads: status,
owner, revision steps + per-step check, media, submissions, decisions,
handovers, incidents + replies, events). The fixture has 2 assignments, so the
cost hides; a book of 40 assignments makes one click's re-projection
O(40 × 24 ms) ≈ 1 s. Every click pays it, for every viewer.

* Why it matters

This is the only change on the list that makes the click cheap as the data
grows, instead of constant-factor cheaper.

* Shape of the mechanism (measured constraints, not a design)

- The delta is already in hand at the socket: the commit message is
  `[:datom/tx basis tx-datoms]` — the entities that changed are `(map -e datoms)`.
  Nothing needs plumbing through `datom` for that.
- A row's dependencies are NOT just its own entity: it reads the revision,
  people, events, incidents, submissions, media. So the dep set must be
  RECORDED at build time. The cheap way: wrap the store (a delegating store
  that notes `-e` of every datom it hands back), scope the recording to the row
  build, and store `{eid → {:row r :deps #{eid …}}}`.
- Invalidation is then exact and cheap: evict every cached row whose `:deps`
  intersects the commit's entity set. No declared attribute set to keep in sync
  (which is why this is the preferred mechanism over per-route attr subsets).
- A basis-keyed cache does NOT work: any commit advances the store basis, so
  every row misses. Entity-granular invalidation is required.
- Where the cache lives matters: per socket process (per viewer) keeps it
  single-writer and bounded by the rows that viewer can see.

* Acceptance

A click that changes one assignment rebuilds exactly that row (assert the
rebuild count, not the wall time), the rendered tree is identical to a full
re-projection, and a burst of N commits costs at most one rebuild per affected
row. Measure against the 2-row fixture AND a scaled one (≥40 assignments).
