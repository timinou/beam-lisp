* Initial Message

how does localias do it?

* What is wrong

`bl install gateway --check` is the verb a developer runs to answer "is a name reachable without a
port here, and if not why". Its port-80 step (`priv/std/bl/install.bl.md`, `check-gateway`) is
built from the BIND verdict (`port-80-verdict`: can an unprivileged process bind 80 — `:ok`,
`:eacces`, `:eaddrinuse`, …) and then names the two ways to fix it:

```clojure
{:name "port 80" :ok answered
 :detail (if answered
           "a name needs no port here"
           (str (pr-str verdict) " — " (port-80-pointer)))}
```

When a FOREIGN server already holds port 80 (nginx, a stray dev server, caddy), the verdict is
`:eaddrinuse` and the line reads `:eaddrinuse — run: bl install redirect (loopback only,
removable), or: sudo sysctl -w …` — the tool recommending the paste without saying that the
redirect's rule is unconditional for loopback destination port 80, so it would TAKE port 80 away
from that server on loopback for as long as it stays installed.

* Why it is not fixed already

`port-80-step` (same file) now renders the honest three-way line — `:ours` / `:other` / `:closed`
— and `bl install redirect --check`, `run-redirect` and `remove-redirect` all use it.
`check-gateway` was deliberately left alone in that change: it also reports the bind verdict,
which is a *different* question ("could a user bind 80" — what says whether the gateway could take
the port itself), and folding the two into one line without being able to re-run the suite would
have been an unverified edit — this host hit btrfs metadata exhaustion at that moment (see
PLAN-105's 2026-09-13 entry), so `mix` could no longer write and no test could be re-run.

* The change to make

In `check-gateway`, keep the verdict for the `:closed` case (it is what tells a developer "the
gateway could take 80 itself if it restarted") and route the live answer through `port-80-step`:

```clojure
(port-80-step (answer-on-80) "a name needs no port here")
```

so the `:other` case reads as it does in `bl install redirect`. Then pin the wording in
`test/bl/system/install_test.bl` (`check-reports-the-unit-the-service-and-the-port`), and verify
by hand in a network namespace with a foreign server on 80 —
`~/.cache/bl-verify/other-on-80.sh` is the shape that already does it for `bl install redirect`.

* Acceptance

With a plain `python3 -m http.server 80` holding port 80 in a netns, `bl install gateway --check`
names the foreign server and what the redirect costs, and does not print a bare `:eaddrinuse`
followed by an unqualified recommendation.

NOTE [2026-09-16]: 2026-09-16 — `bl install gateway --check` (and `bl gateway`'s banner) currently recommend `bl install redirect` whenever port 80 is not answered. PLAN-117-ports-are-not-a-number-derived-destinati makes that recommendation wrong as a default: portless URLs come from the PAC + proxy, and the redirect (an unconditional rule for ALL loopback :80, which TAKES the port from whatever holds it) becomes the opt-in for "I want :80". The check wants a third row — the proxy/PAC/CA state — and the redirect line should say what it costs rather than lead.
