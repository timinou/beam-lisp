The first draft of this item said "migrate to thin wrappers, existing green tests
are the safety net." BOTH premises were false, verified 2026-08-30:
- There are ZERO test/bl suites for mock/fuzz/fault. The only "green" was their
  DEMOS (examples/). The only test suite in this space is test/bl/veritas/.
- veritas does NOT subsume these modules. It generalises their quantifier CORE

  DELETE real capability.

* What each module uniquely provides (NOT in veritas)

- priv/mock.bl (ns mock):
  - synth-seeded  — DETERMINISTIC response keyed by input ⟹ a mock SERVER that is
    a pure fn input→response. veritas has no server notion.
  - synth-boundary — z3 minimize/maximize ⟹ min/max valid response. veritas has
    no optimize path.
- priv/mock/fault.bl (ns mock.fault):
  - THE DATALOG ANALYSIS LAYER — build-db + faults-per-clause + redundant-mutants
    (signature grouping) + uncovered-clauses (not-join) + independent-laws.
    Violations are MEASURED (re-check every mutant × clause), not assumed. This is
    the z3-generates / datalog-analyses engine-division thesis. veritas/faults is
    only the z3 half.
  - serve / error-for / errors — a mock server that injects an error requested by
    the LAW NAME it breaks.
- priv/fuzz.bl (ns fuzz):
  - hypothesis — a property over the function's OUTPUT: call the fn, check a
    `result` predicate, SHRINK the counterexample (QuickCheck-style). veritas only
    checks predicates over generated INPUTS; it never calls a target fn.

* What IS redundant (veritas reimplements the easy half)

- veritas/faults   ≡ mock.fault/isolate + independent-laws (the z3 half only)
- veritas/covers   ≡ fuzz/check + prove + lint (coverage)
- veritas/exists   ≡ mock/synth + synth-invalid + satisfiable?
So the quantifier core is currently written THREE times (mock, fault, fuzz) plus
once in veritas.
