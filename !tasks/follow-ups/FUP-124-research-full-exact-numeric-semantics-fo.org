* Initial Message

look at tinyjs (whatever fabrice bellard did), and squint. especially squint. could we use bl-ANF to convert beam lisp to Js?

* Question
What is the smallest BL-written target representation and dispatch layer that makes Beam Lisp numerical behavior equivalent on JS for unbounded integers, IEEE-754 floats and exact scaled decimals? This is a research spike; do not silently turn a prototype into a production numeric runtime.

* Current baseline
research/js-actors/host.mjs carries values as JS Number. Compiler literal emission rejects integers outside ±(2^53−1); host arithmetic rejects unsafe integer inputs/results. That avoids some silent rounding but does not preserve integer vs float identity (e.g. 1 and 1.0), exact decimal literal 1.50M vs 1.5M scale, arbitrary BEAM big integers, target equality/hashing and mixed-number dispatch. lib/beam_lisp/decimal.ex stores unscaled integer + nonnegative scale; equality distinguishes scales despite numeric equality. FEAT-047 may prove a safe subset; everything else needs representation, fallback or diagnostic.

* Spike deliverables
1. Document numeric contract from BL source/compiler/Decimal/RT/typed dispatch, including literal type, operations, promotions, division, remainder, equality, ordering, map-key hash, printing/serialization and exception behavior.
2. Compare candidate target designs: JS BigInt with tagged integers, BL-written Decimal {unscaled BigInt, scale}, JS Number for floats, and a tagged variant for boundary preservation; isolate irreducible JS primitives. Explicitly cover browser/QuickJS portability and MicroQuickJS absence of BigInt as a separate constrained profile rather than silent degradation.
3. A BL-written experimental numeric dispatch (or a precise proof why host support is necessary) compiled by the existing BL→ANF→JS compiler; do not fork the parser or create second actor runtime.
4. Differential corpus executed on native BEAM and target JS: safe and unsafe integers, negative zero, NaN/Infinity where accepted, decimal scale, rounding modes, mixed operations, map-key and equality collisions, overflow, division exceptions. Use a lossless typed codec; JSON Number is not sufficient.
5. Size/performance and bundle budget measurements, traced to exact inputs. Clear recommendation and migration path from the current Number gate without retaining two publicly exposed arithmetic implementations.

* Acceptance and scope
A reproducible spike command, benchmark/test artifacts, a written tradeoff decision and an implementation FEAT drafted from it. No production parity claim, no auto-merge of a partial numeric tower. Coordinate with FEAT-047 proof rule so that proven Number cases remain fast while unsupported cases are either exact or explicitly rejected. No dependency on browser inbox or OTP lifecycle.
