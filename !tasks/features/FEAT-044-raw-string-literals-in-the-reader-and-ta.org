* Initial Message

what is the most canonical way to have multiline strings wihtout having to escape " in lisp stuff and clojure

* Goal
Add an inline, escape-free, multiline string form to the beam-lisp reader:

  #|verbatim " text, 
 is two chars, no escaping|        → a string
  #|| contains a single | pipe ||                          → a string
  #html|<div class="card">…</div>|                         → (reader-fn "<div class=…>")

Pipe count on the OPENER defines the CLOSER: N pipes must be matched by a run of
exactly N pipes. A longer run is body text (so #|| bodies may contain lone |).

* Why
Clojure/bl has exactly one string literal (`"…"`, escapes `\" \\ 
 	 \r \b \f
\0 \uXXXX \u{…}`). Literal newlines are free, but a `"` inside text must be
escaped, and that is where real bugs come from (the tree's own journal records a
large .bl file with inline CSS/JS mangled by DOUBLE escaping). The `#tag` payload
set is `[` `{` `"` (verified cold in priv/boot/reader.bl read-dispatch/read-tag),
so no payload shape gives a delimiter-free body. Verified cold this session:
`#time "2026-06-15"` (space) → "#time expects a collection or a string";
`#nope[1 2]` → "undefined var: user/#nope"; `#"a\"b"` → "undefined var: user/#".

* Semantics (decided)
- Body is VERBATIM: no escapes at all. `
` in the source is backslash + n.
  Newlines, tabs, indentation are preserved byte-for-byte; nothing is dedented
  or trimmed (consistent with `"…"` preserving indentation).
- Closer = first run of pipes of exactly N. EOF first → reader diagnostic
  (`:unterminated-raw-string`, names the opener position and the closer).
- `#|…|` evaluates to a STRING (bare binary node, like `"…"` — strings are
  unwrapped scalars in this reader).
- `#tag|…|` (and `#tag||…||` …) → `(reader-fn "<verbatim body>")`, the same
  shape `#time"…"` produces.
- Opt-in by registration for the tagged form: a `|`-suffixed tag resolves ONLY
  when that tag is registered (`data-reader!`), so `#a|b` with `a` unregistered
  reads exactly as it does today (symbol `#a|b`). The bare `#|` form is new
  unconditionally — check the corpus for existing `#|` first.
- Payload adjacency stays the rule: no whitespace between tag and pipes.

* Constraints
- The live reader is SELF-HOSTED: `priv/boot/reader.bl` (lib/beam_lisp/reader.ex
  is only a facade). The floor that rebuilds the boot tier is a PREVIOUS
  generation's reader, so this syntax must NOT appear in priv/boot/*.bl until the
  floor is regenerated (`bl seed`); tests and user code only.
- Source-level string scanners must learn the new opener or they will desync:
  priv/lib/lsp.bl (~:243, "Scanned from the start of the source, so a multi-line
  string's…"), plus any other char-level .bl scanner found by grep.
- Clojure divergence — document it in docs/babashka-compat.md (confined to a form
  Clojure rejects today, but it is a divergence).

* Acceptance
- `./bl test test/bl/reader_raw_string_test.bl` green: bare/tagged, N=1,2,3,
  verbatim newlines/tabs/quotes/backslashes, pipe runs inside a body, unicode,

* DELIVERED 2026-09-22
Raw string literals are live in the self-hosted reader, plus every source-level
consumer that had to learn them.

**Reader — `priv/boot/reader.bl`** (+3 helpers, one new fn, two new dispatch clauses):
- `#|…|` (bare) reads to a STRING, verbatim: no escapes, literal newlines,
  indent/tabs preserved byte-for-byte.
- `#tag|…|` reads to `(reader-fn "body")` for a tag REGISTERED with
  `data-reader!` — opt-in by registration, so an unregistered `#a|b` still reads
  as the single symbol `#a|b` (compatibility invariant, pinned by a test).
- `#||…||`, `#|||…|||` … the opener's pipe count is the closer's, EXACTLY: a run
  of any other length is body text (so `#||a|b||` is `a|b`).
- Unterminated body → `:unterminated-raw-string` with `:closer` = the pipe run
  the opener asked for and a caret on the `#`.
- Helpers: `pipe-chars`/`pipe-run` (count + consume runs), `read-raw-string-body`
  (the body, verbatim; one position walk), `split-tag-at-pipes` (tag vs pipes,
  with take-token's delimiter set INLINE + the pipe — bootstrap rule), and
  `read-raw-tag` (registered tag + raw body, else nil).

**Consumers taught** (each was a real desync, not a nicety):
- `priv/lib/lsp.bl` — `lex-state-at` was a quote toggle; now a state machine
  (`lex-advance`: `:string`, `:esc`, `:comment`, `:raw` pipe count, `:hash` tag
  run, `:run`). A raw body answers as ONE string, so hover/definition/symbols
  inside and AFTER one stay correct. The extraction also REMOVED a pre-existing
  tier-3 duplication diagnostic that the inline reduce carried.
- `priv/std/deodorant.bl` — `all-spans` (the span scanner behind `fix-source`:
  parens/quotes/semicolons in a raw body are content, or the fixer splices the
  wrong text). `tag-delims` is built from `String/codepoints` STRINGS, not
  integer codepoints: the scanner walks one-char strings, so a set of integers
  answers `contains?` false for every one of them (measured).
- `priv/std/repair.bl` — `:unterminated-raw-string` closes with the diagnostic's
  own `:closer` (a `#||` body gets `||`, not one pipe) at line end or EOF.

* TWO TRAPS RECORDED (cost a session hour each)
1. In a checkout, `./bl` is the shipped DROP (its own embedded priv, HEAD's
   reader) — edits under `priv/boot/` are INVISIBLE to it. Use `./bin/bl`.
   `docs/dev/which-bl.md` says exactly this; it was still re-derived.
2. Registration is READ-TIME and a unit is read before any of its forms evaluate,
   so a file cannot register a tag and use it: the tag must come from the boot
   registry or from a namespace required EARLIER in the same `:require` list. A
   warm daemon leaks registrations between runs, so a program can be green warm
   and dead cold (a `file` tag leaked into this tree's daemon during the work;
   `bl daemon stop` cleared it).
