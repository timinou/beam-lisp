* Initial Message

explain Reel from zero context in simple language, and explain the implementation alongside that

* The defect

`Phoenix.PubSub` is started in reel's supervision tree
(`lib/reel/application.ex`, `{Phoenix.PubSub, name: Reel.PubSub}`) and
NOTHING EVER PUBLISHES TO IT. Two browser tabs on the same board diverge
permanently: tab A creates a task, tab B keeps showing the old list until
somebody reloads it.

This is not partially implemented. It is a supervised process with no
callers, which reads as a feature that exists.

* Why it was not done in this pass

The fix does not belong in reel. The real `Reel.Web.BoardLive` is
GENERATED from the contract term by `spell.contract/machine-module`; the
file in `lib/reel/web/board_live.ex` is a placeholder that `Reel.Boot`
replaces in the code server at boot. So a `handle_info` hand-written
there would be overwritten, and a subscription hand-written there would
not exist on the module that actually serves the page.

∴ this is an upstream beam-lisp feature touching three layers:

1. `spell.contract` — a contract needs to DECLARE its topic, the way it
   declares assigns and events. The `on-info` form already exists
   (contract.bl:110, and `ex-info-head` generates a `handle_info/2` head
   per pattern), so the seam is there: the missing half is subscribing.
2. `BeamLisp.Spell.Server.mount/2` — the generated mount delegates here
   (contract.bl:613), which is where `Phoenix.PubSub.subscribe/2` belongs
   so every generated page gets it without a per-app copy.
3. `reel.intent/perform` — broadcast the fresh board after a successful
   write, which is the one reel-side change.

* Why it is blocked right now

ANOTHER SESSION is mid-flight in this repo on an AOT-prelude change:
`lib/beam_lisp.ex`, `priv/core.bl` and `lib/beam_lisp/aot.ex` are
modified and uncommitted. `priv/core.bl` gained an `(ns core)` head so
`mix compile.beam_lisp` emits `BeamLisp.Ns.Core`, and the macro closures
in that AOT'd prelude do not survive reload:

    ** (BadFunctionError) function #Function<320.23143100/4 in
       BeamLisp.Ns.Core> is invalid, likely because it points to an old
       version of the code

`mix beam_lisp.test` cannot run to completion while that is in the tree
— a full `rm -rf _build/dev/lib/beam_lisp` and rebuild does NOT clear it,
so it is their source change and not a stale artefact. Editing
`spell/src/spell/contract.bl` blind, with no way to run the suite that
covers it, is how a second defect gets committed on top of a first.

* What to do when unblocked

1. Confirm `mix beam_lisp.test` runs green at HEAD.
2. TDD the contract declaration: a contract with `(topic :board)` emits a
   subscribe in its mount and nothing when absent.
3. TDD `perform`: a successful write broadcasts; a refusal does not.
4. Prove it with TWO mounted sockets in one test — one writes, both see
   it. A single-socket test cannot fail for the reason this exists.
5. Browser check: two tabs, create in one, watch the other.

* Adjacent, same file, cheaper

`@board`, `@components` and `@leads` are computed on every refresh and
rendered by nothing (`check.exs` reports all three as
`unrendered-assign`). `@board` is load-bearing — the refresh handler
destructures it — but `@components` and `@leads` are pure waste on every
board read. Either render them or stop computing them.
