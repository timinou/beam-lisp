* Initial Message

how hward would it be to support datahike in beam lisp?

* Gap

=deftest= does not accept a docstring. Writing one:

#+begin_src clojure
(deftest raw-tuple-keys-do-not-support-prefix-bounds
  "Pins the CURRENT, known-wrong behaviour so wave 2 must consciously change it."
  (let [s (open-store)] ...))
#+end_src

compiles, runs, and passes — but the string is evaluated as a dead expression
in the body, producing a compiler warning:

#+begin_example
warning: code block contains unused literal "Pins the CURRENT, known-wrong behaviour…"
#+end_example

* Why it is worth having

=defn= takes docstrings (PLAN-001 wave 5c) and =priv/core.bl= uses them
heavily to record CONTRACTS and hazards, not descriptions. Tests have exactly
the same need: the most valuable thing a test carries is *why this assertion
exists and what regression it guards*, and today that has to live in a
preceding =;= comment, which no tooling can reach.

Observed while writing =test/bl/datom/store_test.bl= (PLAN-033 wave 1), where
several tests pin deliberately-odd behaviour and the reason is essential —
e.g. a test that asserts a KNOWN-WRONG result to keep BUG-005 visible.

Clojure's own =deftest= does not take a docstring (it uses =testing= blocks),
but beam-lisp already diverges toward docstrings-everywhere, and the warning
makes the current state strictly worse than either supporting or rejecting it.

* Proposal

In =priv/test.bl=, =deftest=: if the first body form is a string AND more
forms follow, treat it as the test's doc rather than a body expression.

- store it in the test registry alongside the name, so a failure report can
  print it (a failing test that explains itself is the whole point)
- =(doc some-test)= should retrieve it, matching =defn=
- a lone string body stays a body expression (an assertion-free test is legal
  and a bare string is its value)

* Alternative considered

Reject a leading string with a clear compile error. Cheaper, and strictly
better than today's silent dead literal — but it forfeits the failure-report
win, which is the actual value.

* Acceptance

- =(deftest name "doc" body…)= compiles with NO unused-literal warning
- the doc is retrievable and appears in the failure output for that test
- =test/bl/= suites using docstrings run clean
- a test whose entire body is one string still behaves as today
