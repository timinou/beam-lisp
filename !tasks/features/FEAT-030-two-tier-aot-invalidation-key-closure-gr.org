* Problem (measured 2026-09-01, 16-core, cache off, --force)

Editing ANY single `.bl` prelude source triggers `building 116 source(s)` — a full
rebuild. Measured cold serial build = 511s (~8.5 min). The daily edit→compile loop
pays near-full cold cost on every keystroke-level change.

Root cause: `BeamLisp.AOTCache.compiler_key/0` (aot_cache.ex:87) hashes the ENTIRE
prelude (`priv/**/*.bl`) into a single global "toolchain" key. That key feeds THREE
coupled consumers, so any prelude edit rotates it everywhere:
  1. Mix manifest freshness — `up_to_date?/5` (compile.beam_lisp.ex:386) demands key match
  2. Runtime boot gate — `stale?/2` (aot.ex:941,950): every beam is STAMPED with the key
     at emit (aot.ex:557 `__bl_provenance__/0`) and re-checked against the live key on load
  3. Shared content-addressed cache — `compiler_key × closure_key` addressing

Because the runtime stamp re-checks the global key, the manifest CANNOT be refined
alone: refine it and the runtime rejects all un-restamped beams → recompiles from
source every boot (the exact bug the run/1 comment says was closed).

Second defect (latent O(N) per boot): `compiler_key/0` is NOT memoized and re-reads
every `priv/**/*.bl` on each call; `stale?/2` calls it once PER NAMESPACE at boot.

* Design — two-tier key (verified sound)

** toolchain_key  (coarse; change ⇒ invalidate ALL)
  elixir version + otp release + :beam_lisp vsn
  + @codegen_modules beams (AOT, AtomGuard, Emit, Link, Native, Ns, Reader)
  + COMPILER-tier `.bl` sources — the self-hosted compiler that affects every
    emitted byte: `priv/compiler.bl` + its transitive requires (`priv/reader-node.bl`).
    (compiler.bl ns=`compiler` requires `reader-node`; verified aot line-scan.)
  MEMOIZE per VM via :persistent_term — keyed on nothing (recompute only on VM restart;
  a codegen/ compiler edit means a recompile of the app anyway).

** ns_closure_hash(ns)  (fine; per-namespace)
  sha256 over sorted "<dep-ns>:<source-sha256>" for the set:
    { ns } ∪ transitive `:require` closure(ns) ∪ AMBIENT
  AMBIENT = {core, sugar} — verified the ONLY implicit namespaces: env.ex:762 falls
  every unqualified lookup through `core` then `sugar`. `core.bl`=`(ns core)`,
  `sugar.bl`=`(ns sugar)`. Nothing else is ambient.
  Rationale for whole-file closure (not just own source): cross-ns `defmacro` +
  compile-time `expand_macro` (compiler.ex:1811, 364) means a dependent's beam
  genuinely goes stale when a REQUIRED ns changes even if the dependent's own bytes
  are untouched. Closure hash restages dependents correctly.

** stamp / gate / manifest all switch to  {ns_closure_hash, toolchain_key}
  - emit stamps {ns_closure_hash(ns), toolchain_key} into the beam
  - runtime stale?/2 recomputes ns_closure_hash from LIVE dep sources + compares
    (Option A / SOUND: catches REPL-edit-a-dependency-without-recompile; the narrow
    Option B — own-source only — was REJECTED: under-invalidation ⇒ wrong runtime code)
  - manifest up_to_date?/5 compares the same pair
  - cache closure_key already ≈ this; align it to reuse across prelude edits (Lever 3 win)
