* Binding publication protocol and guarantee limits
A compilation unit first builds descriptors and proposed Env/Link updates as local data, validates every descriptor, and compiles every module to binaries. No canonical namespace/store/link publication occurs during these steps. A validation/Core-compilation failure leaves the old published definition intact. After all binaries succeed, install new body/companion modules, then public forwarding modules, then commit the associated namespace definition/link/value bookkeeping through the existing serialized writer path. Check every load result; never return success after a failed load. Retain old body modules needed by closures; do not purge them as cleanup. If loading fails before public forwarders change, old public definitions remain in place; record/clean only unreferenced newly staged modules where safe. If failure occurs after public installation begins, return an explicit publication failure with affected module IDs and do not mark the namespace loaded. Do not pretend arbitrary BEAM code loads and ETS updates form one atomic transaction. Use an existing atomic/bundled load primitive if the loader already supplies one, but this task does not promise linearizable multi-namespace publication or rollback of arbitrary external effects. Tests distinguish pre-publication compile failures from post-publication installation failures. All participating definition writers serialize through the existing loader/reload owner; do not introduce an independent writer lock that races that owner.
For disk output, compile all bytes first into a staging directory. Publish the completion/freshness manifest only after all artifacts are installed; loaders must not trust an incomplete artifact set. Inject a failed module compile and failed write to prove no new successful manifest is published. Reuse existing AOT cache/manifest publication conventions.
Initialization boundaries: a direct eval of a top-level form is a new execution every time, including repeated identical source; do not deduplicate language effects by source hash. AOT ensure_loaded initialization runs once per namespace generation in each Env instance, using the existing loaded-namespace marker as authority. A fresh VM/Env must initialize independently. Explicit successful reload/hotpatch installation starts a new generation and executes that generation's required initializers in source order. Mark loaded only after initialization succeeds. A failed initializer returns an error and leaves the namespace unmarked; already performed user effects are NOT reversible. Existing explicit caller retry may rerun those effects, so do not automatically retry within the compiler. Pin this behavior in tests and document the failure boundary; neither an at-most-once initializer promise on failures nor a global content-hash deduplication rule is introduced.
