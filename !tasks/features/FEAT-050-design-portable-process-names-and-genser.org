* Purpose
A basic mailbox is not a registry or a server protocol. Current BL prototype has no named process discovery, unique references for call/reply, `handle_call`/`handle_cast` conventions or auto-cleanup of names. Research baseline: research/js-actors-future/02-registry-and-supervision.md (sections names and GenServer, invariants I2.x; precise caveats on current priv/std/proc/{reg,server}.bl).

* Design deliverable
Specify atomic register/unregister/whereis, unique name scope (one Worker first), owner death auto-retraction, stale name/reuse races and behavior if two actors register same name. Define BL GenServer call/cast/info event envelopes, unique request refs, reply correlation under selective receive, timeout versus late reply, cancellation, crash and caller death. Deliberately compare existing priv/std/proc/reg.bl and proc/server.bl to avoid parallel public APIs; map their contract onto target actors only after lifecycle semantics settle. Decide whether a browser DOM event sink is a named actor or an explicit capability, without making host JS the registry authority.

* Acceptance
An implementation blueprint and BL tests for same-name races, death while registered, re-registration, overlapping calls, late replies left in mailbox, server crash while caller waits, nested callbacks and 17/41-step fairness. Compare observable call/reply/timeout traces with native BEAM on selected scenarios; do not claim GenServer equivalence from naming alone. Browser view can send to a named actor and show BL receipt/reply after process restart when supervision is available. Document protocol framing and target deviations. Scope out multi-node global names until distribution design.

* Dependencies
Name cleanup depends on FEAT-049 death/monitor transaction. Call/cast protocol can be explored earlier over refs/timeouts and existing receive. Supervision design follows both and is a separate feature. research/js-actors-future/02-registry-and-supervision.md is the detailed research sheet; this org item is the durable entry point.
