* Minimal API, data contracts and ownership
Implement a local dev.change namespace with these operations. They are proposed names, not existing APIs:
- plan(spec) -> immutable plan. spec contains a stable edit ID, explicit workspace root, target relative file and namespace/top-level definition selector (or a registered structural rewrite rule), replacement source text, expected full-file hash, and an allowlisted verification command descriptor. Capture old/new bytes, their hashes, resolved span, operation kind and toolchain identity. No source writes or user-code execution.
- preview(plan) -> data: textual diff, resolved targets, diagnostics, affected namespace. No mutation, no macro evaluation, no source module loading. Read using the existing parser/scanner. Refuse malformed, missing, ambiguous or unsupported targets instead of falling back to broad text replacement.
- verify(plan) -> receipt tied to the exact candidate hash, command argv/cwd/environment, compiler generation, exit status and checks. Run against an isolated temporary candidate workspace using an allowlisted process invocation, timeout and OS memory limits. Missing runner, timeout, skipped required test or nonzero status is refusal. Tests may execute arbitrary code; isolation and path restrictions are part of the runner, not guaranteed by the Lisp evaluator.
- apply!(plan, verified-receipt, authorization) -> durable applied/conflict/refused receipt. Authorization explicitly names the edit ID and candidate hash. Re-read the basis under the workspace writer lock, reject drift, require successful matching verification, then install the exact verified bytes. A repeated already-applied ID returns its existing receipt only if the target still has the recorded after-hash; later edits are reported, never overwritten.
- receipt(edit-id) -> durable current state, basis/after hashes, verification evidence and recovery status. Rendering that receipt into the .bl.md result span is a projection, not the commit authority.
- undo!(edit-id, authorization) -> a new inverse proposal, NOT unconditional restoration. Require current content equal to the recorded after-hash, then go through normal preview/verification/application with a new edit ID. Refuse concurrent drift.

* First implementation boundary
Single file, .bl source, one unambiguous top-level def/defn replacement or one existing registered rewrite rule; local workspace only. Resolve namespace/name from reader-backed structure and spans from the text-preserving scanner; replace supplied text, not pr-str of the whole file. Preserve all bytes outside the selected span, including comments, strings and Unicode. Multiple arities within one top-level definition remain one span. A rename affecting callers, multi-file edit, .bl.md target cell edit, dynamic macro-generated definition or boot compiler target is initially unsupported and explicitly refused. Extend later with tests, not heuristics. .bl.md is the DRIVER from day one; it need not be the edited TARGET.

* Path and transaction safety
Canonicalize the workspace root; reject traversal, outside-root paths, symlink targets/parents and non-regular files for the initial version. Allowlist target roots and verification commands. Coordinate via one writer lock for participating tools; compare hashes inside the lock. This protects cooperating writers, not hostile external processes; document that boundary. Use same-directory temporary writes plus atomic rename for the single source file. Write an intent journal before replacement, and an applied receipt after it, flushing as required for the documented durability level. On restart compare old/new hashes: old means not applied, new means applied and receipt can be completed, neither means conflict requiring explicit resolution. Test each crash point. Do not claim source file, receipt file, Markdown document and running VM commit atomically together.
First version is source-only. Runtime reload is a later opt-in phase after source application; record image status independently as pending/applied/held. Never evaluate production namespace initializers during preview. On verification failure leave source unchanged. On a failure after source application do not blindly roll back; use the journal and guarded inverse proposal. Global filesystem or external side effects of evaluated code are not reversible.

* Acceptance matrix
- Preview has zero source, registry or external side effects.
- Correct single-definition edit changes exactly its span and passes behavior checks in the candidate workspace.
- Comments/string delimiters/Unicode/sibling definitions survive; ambiguous target and invalid source refuse.
- Stale basis refuses before writing; wrong candidate receipt and missing authorization refuse.
- Repeated edit ID is safe; replay after unrelated later changes does not restore old output.
- Test failure, timeout and absent required environment leave source unchanged.
- Crash before rename, after rename and before receipt completion recover deterministically by hashes; drift refuses.
- Undo requires the current after-hash and normal verification.
- Running the trusted fixture twice leaves source and owned result bytes unchanged on the second run.
- Policy mode refuses arbitrary executable cells; UI render/transcript replay cannot commit.
