* Initial Message

how hward would it be to support datahike in beam lisp?

* Gap

The reader supports decimal integers only. Both of these fail:

#+begin_src clojure
(println 0x10)      ; ** (RuntimeError) undefined var: ns/0x10
(println 16rFF)     ; same shape of failure
(println 2r1010)    ; same
#+end_src

=0x10= is read as a SYMBOL, so the failure surfaces as "undefined var" at
evaluation rather than as a read error naming the real problem.

* Why it matters

Discovered while writing =priv/datom/codec.bl= (PLAN-033 wave 2), an
order-preserving key codec. Byte-level code is the canonical place hex belongs:

#+begin_src clojure
(def TAG-NIL 0x10)      ; reads as intent
(def TAG-NIL 16)        ; reads as a magic number
#+end_src

Any binary protocol, byte tag table, bitmask, or colour constant has the same
need. The workaround (decimal + a comment stating the hex value) is strictly
worse: it puts the meaningful representation in a comment where nothing checks
it against the value.

Clojure supports both =0xFF= and the general =RADIXrDIGITS= form (=2r1010=,
=16rFF=, =36rZZ=). jank inherits them. beam-lisp targeting jank compatibility
means a vendored slice using either form would fail to load.

* Proposal

In =lib/beam_lisp/reader.ex=, number scanning:
- =0x= / =0X= prefix → parse remaining as base 16
- =NNrDDDD= → parse =DDDD= in base =NN= (2..36), case-insensitive digits
- optional leading =-= for both
- keep the current decimal path unchanged

=Integer.parse/2= does the work; the reader only needs to detect the prefix and
strip it.

Also worth fixing regardless of this feature: an unparseable numeric-looking
token should be a READ error, not a symbol that fails later as "undefined var".

* Test

=test/beam_lisp/reader_test.exs=:
- =0xFF= = 255, =0x0= = 0, =-0xFF= = -255
- =16rFF= = 255, =2r1010= = 10, =36rZZ= = 1295
- case: =0XFF= and =16rff= both work
- =(= 0xFF 16rFF 255)=
- a malformed literal (=0xGG=, =37rA=, =16r=) raises a READ error naming the
  token, rather than silently becoming a symbol

* Workaround in use

=priv/datom/codec.bl= uses decimal tag constants with the hex value in a
comment. Replace once this lands.
