* Initial Message

how do I run the examples?

* Intent
Lean ships compiled ANALYSIS (.olean) beside compiled code, so a downstream
module imports proven facts without re-elaborating. beam-lisp already produces
exactly the contents of such an artifact — the evidence table (invariant 9),
open-world fingerprints (§5.4), effect signatures (invariant 10), and z3/logic
proofs (MVP-C) — but they live only in-memory per session. This FEAT persists
them as a first-class artifact the AOT cache emits and consumes.

* Why (and why AFTER FEAT-028)
FEAT-028 makes the cache KEY sound (fingerprint invalidation). This FEAT makes
the cache VALUE complete: not just "is the cache fresh" but "here is the whole
analysis, portable, so a consumer ns imports my signatures/effects/proofs
instead of re-deriving them." It is FEAT-028's natural superset — do 028 first
(the key), then this (the value). Together they are beam-lisp's .olean.

* Design
** The artifact (one per ns, beside the .beam)
  ns.blanalysis =
    { :fingerprint      <content-hash ⋈ consulted-fingerprints>   ; FEAT-028 key
      :signatures        {fn-name → {:args [tag…] :ret tag :effect eff}}
      :evidence          {form-pos → tag}                          ; invariant 9
      :effects           {fn-name → effect-lattice-value}          ; invariant 10
      :proofs            [{:claim … :status :unsat|:assumed :model …}] ; MVP-C
      :open-world-deps   #{consulted multi/protocol tables}        ; the dep edges
      :deferred          [unresolved constraints]                  ; invariant 3/L7
    }
Stored as datoms (it IS codebase-as-data), so cross-ns queries — "show every fn
proven pure", "which proofs rest on an assumption", "what's still deferred
repo-wide" — are datalog, not file parsing.

** Consumption (import proven facts)
When ns B requires ns A: B's checker reads A.blanalysis :signatures instead of
re-analyzing A. A deferred constraint in B against an A callee resolves from the
artifact (this is L7's require-DAG retry, now backed by a persistent table).

** Trust boundary
The artifact is EVIDENCE, not a kernel proof (the doc's honest framing: warnings
not kernels, evidence not proof terms). Importing it inherits A's soundness
contract. A ^:opaque fn contributes its DECLARED signature, not its body — trust
is auditable (which fns were trusted-by-annotation is a field).

* Cool example
#+begin_src clojure
;; Build the world once:
$ mix beam_lisp.aot lib/**/*.bl        ; emits *.beam AND *.blanalysis

;; A downstream tool asks the WHOLE codebase, from artifacts, no re-analysis:
(q '[:find ?fn :where [?fn :effect :pure]] (load-analysis "lib"))
;; => every provably-pure function in the repo, in one query.

(q '[:find ?fn ?model :where [?p :status :assumed] [?p :fn ?fn] [?p :model ?model]])
;; => every promotion that rests on a z3 assumption, with the countermodel
;;    that justifies it — an audit trail for the proof layer.
#+end_src

* Acceptance
- mix AOT emits ns.blanalysis (datom-encoded) beside the .beam.
- A requiring ns reads a required ns's :signatures from the artifact; re-analysis
  of the required ns is SKIPPED on a fingerprint hit (measured: analysis count).
- Three repo-wide datalog queries work off loaded artifacts: provably-pure fns,
  proofs-under-assumption, still-deferred constraints.
- ^:opaque fns contribute declared (not inferred) signatures, flagged as trusted.
