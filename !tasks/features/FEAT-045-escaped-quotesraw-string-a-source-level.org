* DELIVERED 2026-09-22 — `escaped-quotes→raw-string`, and the rule KIND it needed

A smell that rewrites `"…\"…"` as `#|…|`, plus the machinery a rule over a
STRING LITERAL requires — because a literal is the one shape the reader does not
wrap with a position.

**The rule** — `priv/std/deodorant.bl`
```
(deftextsmell escaped-quotes→raw-string :migration
  (fn [src] → [{:offset :remove :insert} …]))
```
Fires when: the source is a plain `"…"` literal (not already raw, not a
`#`-dispatch payload like `#file"…"`); it holds `\"` (there is escaping to
remove); every escape is `\"` or `\\` (a shape-changing `
`/`	`/`\u…` would
have to be written as the CHARACTER and re-flow the file — a layout decision,
not a spelling one); and the VALUE holds no `|` (which would close the raw body
early). The replacement is built from the VALUE, never by editing text: removing
escapes by hand would be a second implementation of the reader.

**Why a new rule KIND, not a pattern/replacement pair**

The reader wraps only LIST nodes with a position (`priv/boot/reader.bl`), so a
literal has no span to splice, and bl's `pr-str` of a binary drops its quotes —
which is exactly why span-rewrite's `capture-ok?` refuses a binary capture
today. So: `deftextsmell` declares `{:name :tier :text}` where `:text` answers in
CODEPOINT offsets, the `{:offset :remove :insert}` vocabulary `repair` already
uses. `text-smell?`/`text-smells`/`form-smells` split the registry; the same
tiers, the same `bl lint` report and the same `bl fix` sweep select both kinds.
Stated, not hidden: the form-level API (`smell-match`/`scan`/`report-source`/
`deodorize`) has no source text, so it cannot judge a text smell and never
reports one — `smell-match` answers nil for one.

**The scanner is one implementation, not two** — `priv/std/deodorant.bl`

`all-spans` gained a sibling from the SAME pass: `scan-source` now returns
`{:spans [list spans] :strings [{:start :end :tagged}]}`, with `all-spans` and
the new `string-literals` as thin readers of it. `:tagged` is the subtle one — a
`"` that follows a `#`-tag run at zero distance is the TAG's payload
(`#file"LICENSE"`, `#"…"`), never a literal this file owns. Comments, `"…"`
escapes and pipe-run raw bodies were already states in that loop.

**Where a text rule is applied**

- `bl.fix` (`deodorant/fix-source-preserving`) → new `apply-text-edits`: one
  right-to-left splice pass, overlapping edits dropped rather than guessed at,
  then the trivia-preserving span passes over the result.
- `bl.lint` (`priv/std/bl/lint.bl.md`) → `text-smell-entries` maps offsets to
  lines via `span-rewrite/line-offsets`, so a text smell reports the same four
  fields a form smell does (`:name :tier :line :before :after`) — with
  `:before`/`:after` as SOURCE text, not `pr-str` of a form. Both kinds merge
  into one list in source order; `smell-count` counts both.

**Tier: `:migration` — opt-in, for a measured reason**

`bl lint priv/lib --tier every --json` over 145 files: the rule fires **177
times in 60 files**, and it is the LARGEST rule in that report — more than
`if→when` (161) and `+1→inc` (66). Top files: `mcp/instructions.bl.md` 13,
`tooling/pulse.bl.md` 13, `live/hiccup.bl` 11, `tooling/catalog.bl` 11,
`web.bl` 9. A python scan of `priv/` + `test/` puts the tree-wide ceiling at 611
literals in 113 files. As a default rule it would dominate every report in the
codebase AND invalidate `.bl-check.edn`'s per-file `:smells` baseline
everywhere; `--tier every` is the opt-in the CLI already has.

**What it does NOT touch** (each pinned by a test): a literal with no escaped
quote; a value holding `|`; a `
`/`	` escape; an already-raw literal
(idempotent); a literal inside a comment; a literal inside a raw body; a
`#`-dispatch payload.
