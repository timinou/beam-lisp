* Intent
Two things the P13b/MVP-D spike proved but never carried to production:
1. SURFACE backwards synthesis at the hole in SOURCE (the L2 "holes as
   interactive workflow" story) — a `_` in a program becomes a postponed goal
   that miniKanren answers with typed inhabitants, shown with local context.
2. CHARACTERIZE search cost at real recursive depth, and wire miniKanren as the
   discharge engine for element-type flow (FEAT for B3) where the lattice returns any.

* Record correction (measured 2026-08-28)
The prior record ("backwards synthesis is slow, goal-ordering, deferred loose
end"; doc §14 #6) OVERSTATES the problem. Re-measured against the real recursive
typeo relation:
  run 3  ((+ 1) _)            → 3 answers, 29 ms
  run 10 ((+ 1) _)            → 10 answers, 47 ms
  run 3  ((+ 1) ((+ 1) _))    → 3 answers, 40 ms (depth-2 nesting)
The earlier 100–370 ms readings were namespace compile/warmup on FIRST call,
not search cost. So this is NOT "fix slow synthesis"; it is "characterize search
at depth ≥4 recursive programs, where fair-interleaving cost could plausibly
bite, and decide whether goal-ordering heuristics are worth it." Honest, bounded.

The doc's docs/typing/beam-lisp-type-system.typ §14 #6 should be corrected to say
this rather than assert a pathology that does not reproduce.

* Design
** Hole surfacing (the interactive half)
- The typed checker already finds a hole and its expected type (evidence table,
  invariant 9). Feed (expected-type, local-context) to typeo run-backwards.
- Local context = the env the checker already carries at that position → env
  spine [[sym type] rest] that lookupo consumes. No new inference; reuse the
  evidence table's per-position env.
- Output: N typed inhabitants delaborated to source shape (P11's errors/delaborate).
- Deliverable: a REPL/one-shot artifact — `(holes/at src line col)` → inhabitants.

** Characterization harness (the honest half)
- research/p13b_minikanren gains a bench: synthesize programs of depth 1..5,
  record answers-per-second and time-to-first-answer.
- If depth ≥4 degrades, evaluate ONE goal-ordering heuristic (most-constrained
  goal first) — but only if the numbers justify it. Sound-first: a slow answer
  is still a correct answer; never trade correctness for speed here.

** Engine role for element-type flow
- When a higher-order seed (map/filter/reduce) cannot be discharged by the
  lattice, hand the element relation to typeo (a → b over seq). This FEAT ships
  the miniKanren side of that contract; the lattice side lives in the B3 FEAT.

* Cool example
#+begin_src clojure
;; A program with a hole is a question.
(defn scale [x]
  ((* 2) _))            ; x : int, * : int → int → int; hole expects int

(holes/at "scale.bl" 3 12)
;; => the hole expects: int
;;    in context:       x : int
;;    inhabitants:      x  ·  (* 2 x)  ·  ((* 2) x)  ·  2
;;    [37 ms]

;; sideways still refutes: a string filler yields NO answer (untypeable-by-emptiness)
#+end_src
