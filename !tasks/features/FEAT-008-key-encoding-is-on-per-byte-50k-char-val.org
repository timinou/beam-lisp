* Measurement

A single attribute value of ~50,000 characters:

| step                | measured |
|---------------------+----------|
| key encoding        | 8.053 s  |
| the transaction     | 14.653 s |

The value round-tripped CORRECTLY — this is purely a cost problem, not
a correctness one. Measured on a heavily loaded host (load avg 13, deep
into swap), so treat the absolute numbers as an upper bound; the SHAPE
is what matters.

* Cause

`datom.codec/escape-nul` maps over every byte of the value to escape
0x00 (needed because 0x00 terminates a string component, so an embedded
NUL could otherwise forge a component boundary — see the wave-2 fix).
The map allocates per byte, in beam-lisp rather than in Elixir.

Every datom is written to at least two indexes, so a large value is
encoded at least twice per transaction.

* Why it matters more after wave 6

Hobbes is a networked store. Key size drives both encoding cost and
per-round-trip payload size, so a multi-kilobyte key is expensive twice
over. Large values are also exactly the case where a distributed store
would want a value POINTER rather than the value inline in the key.

* Options, roughly in order of appeal

1. *Do the escape in Elixir.* `:binary.replace/4` with `[:global]` does
   this in one native pass. Substrate is where byte-level work belongs;
   this is consistent with the maximalist-.bl doctrine (Elixir keeps
   only substrate).

2. *Skip the scan when it cannot help.* Most values contain no 0x00. A
   single `:binary.match/2` decides in native code whether any escaping
   is needed, so the common case costs one scan and zero allocation.

3. *Hash long values in the key.* Beyond some threshold, encode a hash
   plus a disambiguator rather than the whole value. Changes the
   ordering guarantee for long values, so AVET range scans over them
   would no longer be meaningful — needs thought, and probably belongs
   with the Hobbes work rather than before it.

Option 2 is the cheap immediate win; option 1 is the principled fix.
They compose.
