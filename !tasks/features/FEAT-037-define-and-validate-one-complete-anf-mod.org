* Purpose
A compiler translates source into executable modules. Today Beam Lisp has ANF expressions and new function-clause maps, but disk compilation still constructs Elixir trees for forwarding functions, initialization and provenance. A function-body contract is insufficient. Define one complete module input shared by interactive and disk compilation, then make one emitter consume it. This is not a new backend or a rewrite of working expression compilation.

* Contract to implement
Use a plain data module descriptor with an explicit schema version and fields for module name, ordered function clauses, explicit exports and module attributes. Function clauses use the existing node vocabulary: :op :defn-clause, :fname, :params (ordered ANF patterns), :guard (ANF or nil), :body (ANF), :ann. Choose :params consistently; repair PLAN-086 documentation rather than supporting both field names. Preserve fixed/variadic link metadata in its existing definition envelope; do not create duplicate authoritative arity metadata.
Initialization, forwarding and provenance reader functions are ordinary clauses with ANF bodies. Represent their ordering and exported names explicitly; do not create a second executable AST for these functions. An optional companion module uses the same descriptor. Keep existing topology and closure-lifetime requirements; one emitter does not require one physical BEAM module.
Reuse ANF constructors and lower-anf. The canonical module builder groups clauses by name/arity, preserves clause order, validates export existence, resets fresh names per module, carries source annotations and emits Core Erlang. Explicit attributes must support behavior/provenance requirements without quoted Elixir syntax. Existing module_info synthesis belongs to this one emitter.

* Binding schema and bootstrap decisions (implementation contract)
The descriptor is exactly {:op :module :version 1 :name module-atom :clauses [clause ...] :exports [[function-atom arity-integer] ...] :attrs [[attribute-atom literal-value] ...] :ann annotation-map}. Sequences are eager vectors or proper lists accepted through one constructor and normalized there to proper lists. Unknown descriptor keys are rejected. :ann follows existing ANF annotation keys; absent source information is an empty map, not fabricated positions. Clause fields are exactly :op/:fname/:params/:guard/:body/:ann as above. Existing anf.bl op constructors define the executable and pattern vocabulary: inventory them into the validator and document that table; do not invent a second expression grammar. A :lit value may contain ordinary user data including tuples, but no unevaluated compiler-owned LazySeq or host function closure.
Exports are nonnegative integer arities paired with atom names; duplicate pairs refuse. Module_info/0,1 are synthesized once by the emitter and included in final exports; a caller-supplied clause/export using these reserved names refuses. __bl_init__/0 and __bl_provenance__/0, where required, are explicit ordinary clauses/exports, not emitter magic. Attributes use atom keys and Core-literal-compatible values; preserve values without Elixir escaping. Disallow duplicate attribute keys and compiler-generated reserved keys (module/export/import/file); source file metadata lives in :ann. Behavior and custom freshness attributes are allowed. Validate actual Core attribute conventions with the module_info integration test before finalizing constructor code.
Reproducibility means identical source bytes, logical source paths, descriptor, deterministic AOT module names, OTP/compiler version and compiler key yield identical binaries across two fresh VMs. Runtime unique generation names are intentionally outside byte equality. Normalize host absolute checkout roots using the existing AOT logical-filename convention, not by stripping meaningful user locations. Sort grouped functions/exports/attributes deterministically; retain clause order within each function and authored initializer order. Do not include timestamps, runtime counters or machine-local temp paths in deterministic AOT metadata.
The only allowed importer input is an existing Env.ns_defs entry's clause slot containing the recognized legacy {:def, metadata, [head, [do: body]]} shape (including its guarded/default-argument heads already handled by the old reader). It is not a general walker over source values or macros. Implement one normalize-generation-defs! boundary, called once after old seed initialization and before new-generation compilation/publication begins, that converts all stored clauses to canonical clauses using the existing transition reader and atomically replaces each namespace's definition store under the existing writer serialization. Mark the imported generation in the receipt. Pure new-generation boot must not call this importer. Retain it only while producing the new seed; after a fresh new-seed boot and regeneration test proves all definition stores canonical without it, remove the importer and transition reader.
