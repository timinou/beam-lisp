* Goal
Each cell of a .bl.org runs where it is safe and fast. Pure, terminating cells re-evaluate instantly in the browser on every edit. Cells with effects run on the BEAM, as today. The author writes one file and never chooses. This is PLAN-157's split placement applied to a notebook.

* Design
research/bl-ed/next-4-5.md §5 (full). Summary:
1. Classify per cell using `system.analyze` over the whole document program. A cell is *local* when its footprint is {}, it terminates and its callees are local; otherwise it is *beam*, with the analyzer's reason, rendered in the gutter in the split gate's reason format.
2. The classification runs on the BEAM first (`/api/place`, cached per cell content hash), because termination proofs use z3.
3. Evaluation: an edited local cell recompiles in the FUP-134 Worker, re-runs with its downstream local cells (the analyzer's `:edges`), and shows results live. They are written on save. Beam cells keep `/api/eval`.
4. Values cross as data on the split wire (priv/lib/split/wire.bl). A local cell that needs a fn or a process is classified beam, with a reason.
5. A notebook differential, `bl js test --doc FILE`, runs every local cell on both targets.

* Waves and gates
- 5a: `/api/place` plus gutter reasons. Gate: every cell of docs/**/*.bl.org is classified and its reason renders.
- 5b: local re-run on edit. Needs FUP-134. Gate: under 50 ms p95 on a 1k-line doc.
- 5c: values across the line. Gate: a map from a beam cell is right; a fn value is refused with a reason.
- 5d: notebook differential. Gate: green on docs/**/*.bl.org.
