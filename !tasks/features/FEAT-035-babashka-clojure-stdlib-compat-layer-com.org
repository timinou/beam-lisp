how far would we be from making any babashka app compatible with beam lisp?

* Goal
Make unmodified Clojure/Babashka stdlib namespaces load and behave on beam-lisp, graded by real upstream tests. Method mirrors docs/jank-compat.md: vendor real source/tests, run, measure; a needed edit is a FAIL recorded, fix goes in beam-lisp not the vendor.

* Hard constraints (from user)
- New `priv/compat/` tier (NOT `host/`). Add to loader tiers.
- Do NOT patch priv/boot/compiler.bl (seed risk). If a compiler hook is unavoidable, do it OUTSIDE boot (worst case a require from compiler.bl — avoid).
- Autonomous, commit as you go, only stage own new files (repo has unrelated WIP).
- Finish with .bl.md docs + guidebooks + wow-level showcases.

* Architecture decision
`(.method obj)` lowers ONLY to deftype field access (1-arg) in compiler.bl — Java instance methods do not work and we cannot patch boot. Therefore:
- Reimplement each namespace's PUBLIC API natively in beam-lisp using existing `Module/fn` interop (String/, Enum/, Regex/, :erlang, :re) which already works.
- Namespace files declare `(ns clojure.string)` etc. → load via canonical `(require '[clojure.string :as s])`, exactly like existing priv/std/clojure/core/async.bl precedent.
- Vendor upstream TESTS (behavior oracle), adapt only host-specific harness bits (StringBuffer./NullPointerException/#"") — record every adaptation.
- Provide regex as FUNCTIONS: re-pattern/re-find/re-seq/re-matches/re-matcher/re-groups over Elixir Regex. The `#"..."` reader literal is a boot/reader change — gated LAST, optional.
