make wry first-class and exceedingly simple to set up in beam-lisp. show me the syntax and how you'll do the first prototype.

Make wry (cross-platform WebView) a first-class, exceedingly-simple capability in beam-lisp, via the existing `defnative` NIF mechanism.

## Target syntax
(ns app (:require [wry]))
(def w (wry/open {:title "Hi" :html "<h1>hi</h1>" :width 480 :height 320
                  :on-message (fn [msg] (println "js:" msg))}))
(wry/eval w "document.body.style.background='rebeccapurple'")
(wry/close w)

## Components
- native/wry_webview/{Cargo.toml,.cargo/config.toml,src/lib.rs} — NIF crate.
  - Host module BeamLisp.Native.Wry (matches host_module("wry")).
  - Thread per window: tao EventLoop (with_any_thread + with_user_event),
    WebViewBuilder.build_gtk(window default gtk container) for Wayland safety,
    run_return so a window close never process::exits the BEAM.
  - IPC: with_ipc_handler → OwnedEnv.send_and_clear({:wry-ipc, body}) to caller pid.
  - Init script exposes bl.send(x) → window.ipc.postMessage.
  - NIFs: webview_open/6, webview_eval/2, webview_close/1, __nif_loaded__/0.
- priv/wry.bl — (defnative "wry_webview" …) + open/eval/close/available? and the
  :on-message receiver process.
- examples/wry_hello.bl — runnable demo.

## Versions (verified)
wry 0.55.1 → tao 0.35, gtk 0.18, webkit2gtk v2_38 (host has 2.52). cargo 1.91.
run_return returns i32 control; with_any_thread bypasses main-thread assert;
OwnedEnv.send_and_clear delivers to a BEAM mailbox from a Rust thread.

## Scope / honesty
Prototype #1: ONE window driven robustly (open/eval/close/IPC). Multi-window
concurrency is a known next step (gtk global init per-thread), not claimed here.
