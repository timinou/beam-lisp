## Outcome
A BL-written actor persists in a browser module Worker while blocked indefinitely, receives later DOM-origin messages via a minimal Web Platform input adapter, and sends visible output back to the page. Browser observers can press buttons, type distinct values, see each delayed event and BL reply on the page and inspect window.actorDemo. Existing 104 acceptance checks remain green. This is not OTP inter-worker transport.

## Boundary
Browser page DOM owns Worker, button and text field. Worker installs onmessage before loading generated demo module and passes allowlisted strings to host.mjs. Host merely queues typed event values, wakes an outstanding wait (including a timed receive), and exposes input-size/take-input/wait-input leaves; it must not choose a process, select mailbox clauses, or install a JS actor. BL runtime owns rt-register-input!, sink identity, draining FIFO host events into BL mailbox via rt-send, scheduling and selective receive. BL demo.bl registers itself and performs source receive loops and BL output. Build emits demo.mjs alongside existing test bundle using one emitter, with no source-only JS mini-app.

## Correctness gates
Event before BL registration is retained and delivered in order; event after indefinite park wakes the actor; event during timed sleep wakes promptly without waiting for timer; no lost wakeup at registration/wait boundary; no busy polling; actor remains alive across two UI events; per-message values and order are visible in page; stop event releases and completes; user can send manually. Browser smoke must drive controls with browser tool and inspect visible text/actorDemo. Node tests exercise early queue and timed wait wake. Existing Node verify.mjs and browser.html 104 checks still pass. Explicit error handling and bounded input restrictions. Host queue accepts only strings; no arbitrary JS objects/functions crossing into BL. Document startup, serve command, screenshots optional, and lifecycle limits (single Worker/runtime; no cross-worker codec or persistent storage). Avoid Canvas tool per user instruction.
