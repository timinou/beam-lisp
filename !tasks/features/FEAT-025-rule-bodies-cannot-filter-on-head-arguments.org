#+TITLE: Rule bodies cannot filter on head arguments (needs magic-set adornment)
#+STATE: ITEM
#+CUSTOM_ID: FEAT-025-rule-bodies-cannot-filter-on-head-arguments

* Observed

A rule whose body carries a predicate over a HEAD argument silently
derives nothing:

    (def R '[[(live3 ?v ?date)
              [?v :version/valid-from ?from]
              [(<= ?from ?date)]]])
    (datom/q '[:find ?v :in $ % ?date :where (live3 ?v ?date)] db R 20220601)
    ;; => [] even though matching versions exist

Predicates against CONSTANTS in the same position work:

    [[(live2 ?v) [?v :version/valid-from ?from] [(<= ?from 20230101)]]]  ;; ok

So do pure-pattern rules, recursive closure, and vector clauses
(`similar-to`) — verified in
`spell/apps/librarium/src/librarium/rule-debug.bl` (all six probes).

* Root cause (from reading priv/datom/query/rules.bl)

Rules are materialised BOTTOM-UP to a least fixpoint: `eval-body` runs
each rule body against an EMPTY initial binding set, because head args
are OUTPUTS of the relation being computed. A predicate like
`[(<= ?from ?date)]` where `?date` is only bound at the CALL SITE can
never fire during materialisation — the call-site binding is joined
afterwards (`relation->rows`), too late for the predicate.

This is the textbook bounded-recursion problem; the standard answer is
MAGIC SETS (adorn the rule with the call's binding pattern, push the
constant down before fixpoint). `datom.query.magic/rewrite` exists but
has NO CALLER — wiring it (or sideways information passing through the
semi-naive loop) is the fix.

* Why it matters now

Library schema packs (librarium prototype) want to ship TEMPORAL rules
as data — `(in-force ?version ?date)` is the legal domain's core move,
and every "aging/stale/closing-soon" rule across packs has the same
shape: pattern + predicate over a caller-supplied date. Without
adornment, packs ship pattern-only rules and every call site repeats
the window clauses — the semantic-datalog promise ("reasoning patterns
as reusable data") is exactly what leaks.

* Acceptance

    [[(in-force ?v ?date)
      [?v :version/valid-from ?from] [(<= ?from ?date)]
      [?v :version/valid-to ?to]   [(> ?to ?date)]]]

returns the in-force versions when invoked with `?date` bound at the
call site, and the same program's results are unchanged when `?date` is
free (no binding-pattern regression). Magic-set rewrite covers at least
bound-head-argument predicates; recursive rules with bound first args
(the case magic.bl already describes) keep terminating.
