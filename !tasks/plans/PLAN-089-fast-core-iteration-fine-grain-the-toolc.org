* Problem (measured 2026-09-06)

Editing ANY file in =priv/boot/*.bl= makes the edit→test loop ~2m23s.

Chain of causation (all verified in-repo):
1. =BeamLisp.AOTCache.compute_compiler_key/0= hashes the CONTENT of every
   =priv/boot/**/*.bl= (13 files) + the codegen Elixir module bytes into ONE
   global "toolchain key".
2. A one-char edit to any boot file rotates that key.
3. The per-source freshness gate (build.bl =fresh?=, aot.ex =stale?=) stamps
   every beam with the toolchain key. Key rotated ⇒ ALL 142 beams stale.
4. The shared AOT cache (=aot_cache.ex=) is keyed =<compiler_key>/<closure_key>=.
   Rotated compiler_key ⇒ 0 cache hits. (Evidence: ~/.cache/beam_lisp/aot holds
   37 orphaned compiler-key dirs, 433 MB — one full closure per past iteration.)
5. =mix compile.beam_lisp= eagerly rebuilds all 142 beams up front; =mix test=
   runs =mix compile= first. So the full 2m23s is paid before a test starts.

Measured facts:
- warm no-op =mix compile= after a boot edit: 2m23s (full-tree rebuild)
- VM boot alone (=mix run -e :ok=): 12.5s
- shared cache: 433 MB, 37 orphaned compiler-key namespaces
- DevHotpatch (existing workaround): anf ~1.5s … compiler2 ~29s per ns

* Key insight

=compiler_key/0= conflates two inputs with opposite change-frequency/impact:
- CODEGEN (compiler, lower, anf, reader, reader-node + Elixir Emit/Link/AOT/Ns):
  code that RUNS at compile time to PRODUCE bytes. Its body is load-bearing —
  a body edit changes every emitted beam ⇒ rotate-all is CORRECT.
- AMBIENT PRELUDE (core, sugar, data-readers): library code CALLED at runtime
  by compiled beams. A caller's beam reaches these by name/arity; the body is
  invisible to the caller (this is exactly what ns-interface.bl already proves
  for the std/lib tier). A body edit here changes NO dependent's bytes ⇒
  rotate-all is NEEDLESSLY conservative.

core.bl is 67 KB and the most-edited boot file. Today a one-char body edit to
core rebuilds all 142 beams. It should rebuild zero.

* Fix 1 — interface-key the ambient prelude into the toolchain key (biggest win)

In =compute_compiler_key/0= / =toolchain_source_contents/0= (aot_cache.ex):
for the ambient-prelude boot files (core, sugar, data-readers) hash their
INTERFACE (ns-interface/hash-forms) instead of raw content; keep raw content
for the genuine codegen boot files.

Result:
- edit a fn BODY in core/sugar          → key unchanged → 0 rebuilds
- add/rename/re-arity a core/sugar fn    → key rotates   → full rebuild (sound, conservative)
- edit compiler/lower/anf/reader body    → key rotates   → full rebuild (correct — codegen)

Soundness: identical argument to ns-interface.bl's std/lib keying — a body a
caller cannot observe cannot invalidate the caller. The prelude's ambient
(edge-less) reachability only matters for WHICH names resolve; the interface
hash already captures the name/kind/arity/macro-def surface that governs
emitted bytes. Macros in the prelude are interface-captured whole (body
included), so macro edits still correctly rotate.

Effort: small, single Elixir function + a boot-vs-prelude partition. Must run
below the var registry (this executes in Bootstrap.install! before init) — so
reuse the reader-node/ns-interface path the drift gate already uses pre-core,
or precompute prelude interface hashes via a minimal reader. Pin with a test:
core body edit ⇒ compiler_key stable; core arity edit ⇒ compiler_key moves.

* Fix 2 — lazy invalidation for genuine codegen edits (medium win)

When the codegen key legitimately rotates (you edited the compiler itself),
don't eagerly rebuild all 142 in =mix compile=. The drift gate + loader already
fall back to per-namespace source compilation on demand
(=AOT.ensure_loaded → :no_module → Loader.ensure_loaded_source=). A dev-mode
=mix compile.beam_lisp --lazy= (or =BL_LAZY_AOT=1=) skips the full build and
trusts the runtime gate: =mix test foo= then recompiles only foo's require
closure, not the whole tree. Cost moves from "every codegen edit = 2m23s
upfront" to "pay per namespace the test actually exercises."

Risk: cold from-source load is slow (datom: 3m20s src vs 14.7s AOT), so this
only wins when few namespaces are touched — i.e. exactly the dev inner loop.
Keep eager build as the CI/commit gate.

* Fix 3 — persistent dev daemon with in-place boot hot-swap (loop-latency win)

Generalize DevHotpatch from a manual env-var one-shot into the =bl daemon= watch
loop. Today =daemon/server.ex= =drift_fun= forces a FULL restart when the
booted compiler_key != live key. Instead, for a boot-ns save, hot-swap just that
ns in-VM (=:code.purge= + =:code.load_binary=, the DevHotpatch mechanism) via the
Executor FIFO, keeping the substrate warm (saves the 12.5s boot) and skipping
rebuild. This is the structural, watched form of the existing hotfix — the fast
path becomes the default, not a manual invocation.

* Hygiene — GC orphaned cache keys

Fix 1 slashes key churn, but add a cheap sweep: on store, drop compiler-key dirs
older than N days / beyond K generations. 433 MB of orphans today.

* Sequencing

Fix 1 is independent and highest-leverage — land it first, pin with a
compiler_key stability test. Fix 2 layers on top (dev-mode lazy build). Fix 3 is
orthogonal (daemon loop) and can proceed in parallel. Hygiene is a small add.
