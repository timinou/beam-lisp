* The reframe

Earlier draft: a tool proposing a DELTA to one fixed chat contract
(`add_assigns`/`add_events`/`add_style`). That is a patch tool. It closes the
loop for one page and teaches the system nothing.

The better unit is the MACHINE: a set of contracts and views that accumulate.
One tool, `define`, appends a whole `defcontract` or `defview` to it. The
interesting checks then fall out of ACCUMULATION rather than being special-cased:

- an assign nothing renders          → dead state
- a view binding no contract declares → orphan binding
- a `fire` no contract handles        → event into the void
- a styled selector no markup renders → the (1) gap, now a machine-level query
- a template declared, never invoked  → dead markup

Every one is a JOIN over two sets. None needs a new mechanism — `seam.bl`
already has `disagreements`; it becomes machine-wide instead of page-local.

* Ground truth (all verified, this session)

** Contracts and views are already data
`chat.bl` planes extract cleanly: style selectors are strings, binds are
`[selector (st/… @binding &template)]`, markup is `(template &name [params] html)`.

** Verse can answer "which classes actually exist" \u2014 no regex
`inspect --layer emit --format json` returns BOTH:
  - `css.content` \u2014 every styled selector
  - `js.content`  \u2014 template markup survives into `registerTemplate` calls

Verified on a deliberately-broken page:

| token | in JS (rendered) | in CSS (styled) |
|---|---|---|
| `real` | yes | yes |
| `ghost-never-exists` | NO | yes |
| `also-missing__elem` | NO | yes |

∴ the style check is a join over Spacetime's own output, NOT a hand-rolled HTML
parse. This matters: a regex over our own template strings would be measuring
the emitter against itself \u2014 the exact tautology this project keeps finding.
Verse compiling the markup is independent ground truth.

** `check --deny-warnings` exits 0 on that page
No E-code covers "styled selector matches no element". E0916 covers undefined
TEMPLATE refs only. The gap is real and ours to fill.

Why ONE tool rather than `define_contract` + `define_view`: the machine's
invariant is that the two halves agree. A single entry point makes "you added a
view whose binding no contract declares" the natural response, rather than an
error raised by whichever tool happened to run second.

* Validation ladder (each rung REJECTS, with the reason returned to the model)

1. *schema*     \u2014 malformed args
2. *emit*       \u2014 term \u2192 EDN \u2192 `.st`; a throw here is our bug, surfaced not swallowed
3. *compile*    \u2014 `spacetime check --deny-warnings`, verse's own diagnostics
4. *machine*    \u2014 the cross-plane joins (below). THIS is the new work.
5. *load*       \u2014 render + DOM-verify

Rung 4 questions, all set-difference over the accumulated machine:

| question | join |
|---|---|
| binding with no contract | view `@x` \u2212 ∪ contract assigns |
| assign nothing renders | contract assigns \u2212 view bindings |
| event into the void | view `fire` \u2212 contract events w/ handlers |
| reply nobody decodes | `reply-tags` \u2212 view arms (exists) |
| ghost selector | CSS selectors \u2212 JS-rendered classes (verse emit) |
| dead template | declared \u2212 invoked |

Note the ASYMMETRY: "binding with no contract" is an ERROR (page reads
something nobody publishes). "assign nothing renders" is a WARNING (a server may
legitimately publish before a view consumes it). Collapsing the two would make
the check unusable during incremental building \u2014 which is the whole point of a
machine that GROWS.

* Retry: 3, visible in the chat

On rejection the tool result carries the failing rung + the verbatim diagnostic;
the model retries, up to 3 attempts. Every attempt renders in the chat as a
`&proposal` bubble with its verdict \u2014 not hidden in stdout. A rejected attempt
is the most informative thing the loop produces and it belongs on screen.

After 3 failures: the machine is UNCHANGED and the chat says so. Fail loud.
