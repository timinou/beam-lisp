#+TITLE: Preserve safe migration refusal reasons across deployment layers
#+DATE: 2026-10-15
#+STATE: SOURCE IMPLEMENTED — native acceptance pending

* Problem
An actual failed invariant check in datom.migrate/apply! returned :blocked and
the detailed :breaking report without a :reason. Foundry intentionally excludes
that private report, so operators saw only the unhelpful category "blocked".

* Change
Return the fixed :migration-invariants-violated reason for residual invariant
failures. Preserve the detailed SDK report for the trusted direct caller.
Foundry's existing online adapter selects :reason and its application adapter
projects the fixed category; no application integration is necessary.

Never project entity IDs, values, callbacks or the raw :breaking report into the
deployment journal or UI. Native refusal still leaves the migration unapplied
and does not install its requested schema tightening.

* Validation
The existing real duplicated-email migration regression now also requires the
fixed reason and a nonempty private violation report. It already verifies that
the migration ledger and uniqueness schema remain unapplied.

Whitespace checks pass. The focused native migrate test and Foundry adapter/UI
tests await the coherent SDK gate; this source checkpoint is not a native pass.
The packaged sandbox harness will exercise a real value-type violation against
tenant data and assert refusal before candidate publication.
