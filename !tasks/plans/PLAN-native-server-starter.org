#+title: Native server starter identity and accepted-start code custody
#+state: Source checkpoint; coherent native floor and root-serialized tests pending

* Problem and exact boundary
A genuine compiled init frame plus a copied Env token used to be sufficient for
native server registration. The child acquired its own graph lease and registered
itself, so the original starter was not authenticated. live.lifecycle then used
child-mutable OTP $ancestors as constructor attribution. Checked Source already
refuses raw OTP start and direct Env interop; the native runtime still must not
treat a copied context as an ownership capability.

* Implemented source mechanism
- Prepared graphs carry :server-classes from the actual validated canonical
  defserver descriptor/evaluated class. Whole graph membership alone is not a
  declaration proof. Independent SDK actors require existing exact SDK evidence.
- Standard Server.start/start_link first require actual native executing graph
  proof before SDK preparation effects. Ordinary development remains unchanged.
- Existing graph entry tickets are exposed through the native execution extent;
  no new whole-graph ticket is added per callback/request just for the extent.
- Env admits a unique native creator PID + fresh start attempt, exact graph/class,
  original context and opaque one-shot capability BEFORE OTP start. It is distinct
  from compiler initializer attempts and is never in Env capture/bind.
- Pending capabilities/context live in the PRIVATE Env-owned fixed ETS table
  beam_lisp_server_starts, bounded at4096 entries. Only native Env internals read
  it. Public native owner evidence carries immutable attribution, no start cap.
- Env itself owns the pending full-graph physical ticket. An independent guardian
  observes creator/claimed child DOWN but does not own that ticket. Guardian or
  creator death cannot make code retention vanish after an accepted/unknown start.
- OTP start/start_link still executes in the actual starter, preserving its real
  parent/link/name behavior. A five-field internal envelope carries the capability.
- Generated bind_init claims once BEFORE binding supplied context or user init.
  It uses the stored original context, authenticates actual generated init class,
  registers the child and its full graph ticket, installs native callback proof,
  then hands off Env custody after exact monitored membership/lease verification.
- Legacy copied four-field generation envelopes refuse before user init. A class
  frame, bound scope, retained-only lease or forged ticket is insufficient.
- Owner registry rechecks the exact live pending claim before publishing starter
  evidence. Lifecycle attributes direct ownership through that immutable receipt
  and rechecks it before drain; it never reads $ancestors for authority.

* Completion, failure, and unknown acceptance
Before launch, actual creator DOWN can release unused code custody. After launch,
creator DOWN without a claimed child leaves indexed uncertain custody. A genuine
child may still claim that one-shot launch and complete its native registration.
A claimed child's actual DOWN proves its physical init execution ended and can
release pending code custody; this says NOTHING about external effects, detached
work or store cleanup. Accepted detached work requires its existing own leases.

A normal monitored child/full-G lease handoff releases pending custody before user
init. A native duplicate-name response proves no new child and releases it. Other
unclaimed errors/ignore/exceptions remain held conservatively: no generic error
or timeout is treated as physical completion. There is no broad cleanup/unlock API.

If the guardian dies, Env's indexed custody remains active even after the creator
dies. This can intentionally retain an unknown attempt until exact native/journal
reconciliation or VM shutdown. Automatic reconciliation for unreachable unknown
starts is NOT implemented. Restart never replays a held initializer as if no effect
occurred. Fixed SDK/runtime hot replacement remains a separate VM handover issue.

* Explicit limits
- Managed native Supervisor starts now use the same one-shot custody/receipt
  engine through a separate fixed-kind entrypoint (see below). Newly observed
  supervision trees still require a safe explicit drain/custody contract and
  remain refused by live.lifecycle; actor creation proof is not provider drain.
- Stable SDK framework adoption after initialization may replace an app owner
  index role. This starter batch does not claim arbitrary resource-family adoption
  or volatile mailbox migration; actual retained callbacks keep their old graph.
- A start receipt attributes native actor creation, not every external resource or
  effect a constructor may create. Unknown constructor outcomes remain uncertain.
- Pending custody adds transient startup ticket/guardian work. Request entries now
  validate their already acquired native ticket; measure actual startup/navigation
  and actor-entry workloads before making an overhead or latency claim.
- Trusted unrestricted native code remains outside the checked Source authority
  boundary. The Source checker already rejects arbitrary native Env operations;
  no token/claim/namespace-prefix exemption was added.

* Startup allocation follow-up
Private-table capacity is checked with native ETS size in O(1), refusing an
unavailable/noninteger size. It never copies4096 complete pending graph/context
rows just to count them. Actual begin/claim still copy graph/context through Env
RPC and private ETS; measure source actor startup before redesigning that cost.

* Complete readiness attribution
The initializer/background adapter now refuses a fresh peer/nested native owner
rather than quietly omitting it from a ready drain inventory. Without a proven
constructor/tree custody contract, delegated construction returns uncertain with
ownership unavailable; it never cleans up the peer or replays the constructor.
Background error projection also catches failed secondary inventory so it returns
a bounded uncertainty receipt instead of losing the original unknown outcome.
The actual peer-owned background fixture checks it stays alive and honestly owned.
This conservative boundary does not replace future generic supervisor/tree support.

* Native death recheck
The internal departed handler independently requires an actually dead local PID
inside Env's serialized decision before any release. A supplied reference/PID or
forged notification cannot treat a living creator/child as departed. The actual
pending-custody fixture checks a live-PID call refuses and retains Env's ticket.

* Managed native supervision: coherent adaptation
The old supervised child callback restored only an Env token; the real supervisor
was registered after children had started. Actual starter proof correctly refuses
that incomplete path. The upstream adaptation now has a fixed pinned Supervisor
init callback: claim the one-shot supervised-start capability before context bind,
retain the exact full source graph in the native supervisor, register monitored
membership from its real OTP init frame, install private execution proof, hand off
Env pending custody, and return exact specs to the REAL OTP supervisor.

Initial starts and every later restart enter start_server through the actual
indexed supervisor's private full-G ticket. A child-spec token carries context;
it grants no rights by itself. Supervised child source actors get ordinary distinct
one-shot Server admissions, with immutable creator=actual native supervisor PID.
Root parent/link/name behavior and OTP's original restart logic remain native.

Bounded depth64/4096 child metadata validation walks the complete first-party
subtree before the first child starts. Only fixed start_server/start_named_sup
MFAs are supported, with real canonical Source class inventory or exact SDK class
proof and valid native names. Standard first-party pool subtrees use the same
native supervisor admission; no arbitrary child callback becomes trusted. Public
supervise shares the managed start path; unmanaged development/probe routes stay
unchanged. Internal init/start callbacks/metadata walker and Server.native_start
are refused by checked Source before execution; copied token cannot manufacture
native owner proof even through an internal call.

Physical supervisor tickets use the same indexed native retention selector as
actors, retaining through logical close until actual native DOWN. No remote full
PDict copy is added to ordinary unrelated task/callback tickets. Child start borrows
the supervisor's existing graph ticket; no extra full ticket just for each restart
execution extent. The pending start guard remains Env-owned across any uncertainty.

New supervisor_starter_test.bl uses real generated Source trees to check native
ownership before child init, start_link parent links, actual OTP restart with a fresh
start attempt and preserved context, fixed native pool custody, copied-context
refusals and Source internal-entry refusals. Existing supervisor factory/context/
start-context/host ABI tests must pass on the coherent new floor as well. These
source fixtures and actual native stack-frame assumptions are UNRUN. No deployment,
provider cancellation, generic tree drain, head migration or performance is claimed.

* OTP ignored-child protocol
Native Supervisor child-start adapters now translate Server.start_link's unchanged

Actual managed and unmanaged ignored-child controls assert the supervisor starts,
its ignored child entry is undefined, and the real observed child reaches DOWN.
Managed startup still performs ordinary native child ownership/lease handoff before
user init returns ignore; the adapter does not prematurely release that ticket.
Native assertions remain pending with the rest of the coherent floor batch.
