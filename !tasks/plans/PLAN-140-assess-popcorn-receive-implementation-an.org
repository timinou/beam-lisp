** Popcorn's implementation
The current README distinguishes stable 0.3 (AtomVM compiled to Wasm) and 0.4 prerelease (Erlang/OTP compiled to Wasm, running in a Web Worker). Stable architecture docs describe an iframe plus postMessage bridge. These are different release architectures and must not be conflated. Source: https://github.com/software-mansion/popcorn/blob/main/README.md ; https://popcorn.hexdocs.pm/architecture.html ; https://github.com/software-mansion/popcorn/blob/main/popcorn/js/src/worker.ts . The 0.4 setup requires cross-origin isolation headers and currently a CSP permitting unsafe-eval: https://github.com/software-mansion/popcorn/blob/main/popcorn/js/README.md . This is not a requirement inherent to a proposed AOT JS actor runtime.

Popcorn does not replace selective receive with a browser event listener. It preserves VM process/mailbox/scheduler semantics and adapts the host. Its current AtomVM build script defaults to software-mansion-labs/FissionVM branch swm (https://github.com/software-mansion/popcorn/blob/main/scripts/build-atomvm.sh). The inspected fork's src/libAtomVM/opcodesswitch.h implements OP_LOOP_REC (peek candidate), OP_LOOP_REC_END (advance mailbox cursor without removing), OP_REMOVE_MESSAGE (cancel timeout and remove selected message), OP_WAIT (save/resume instruction location through scheduler), OP_WAIT_TIMEOUT (validate timeout, arm once, handle wakeups/expiry), and OP_TIMEOUT (reset mailbox receive state). src/libAtomVM/mailbox.h has receive_pointer and receive_pointer_prev distinct from the ordered mailbox contents. src/libAtomVM/scheduler.c moves waiting processes off the running set, schedules ready processes, and maintains monotonic timers. Browser platform src/platforms/emscripten/src/lib/sys.c enqueues bridge events, wakes a condition variable, and delivers them with globalcontext_send_message. Sources: https://github.com/software-mansion-labs/FissionVM/blob/swm/src/libAtomVM/opcodesswitch.h ; https://github.com/software-mansion-labs/FissionVM/blob/swm/src/libAtomVM/mailbox.h ; https://github.com/software-mansion-labs/FissionVM/blob/swm/src/libAtomVM/scheduler.c ; https://github.com/software-mansion-labs/FissionVM/blob/swm/src/platforms/emscripten/src/lib/sys.c . Inspected moving branches, not a historical release-pinned build.

** BL seam and proposed runtime
priv/boot/compiler.bl compile-receive already emits a canonical :recv containing clause patterns/guards/bodies, optional timeout expression, and timeout body. priv/boot/lower.bl currently delegates to cerl/c_receive. This is a suitable compiler suspension boundary. Unlike a try/finally after, the receive timeout body's value IS the receive expression's value. A timed receive with no clauses is a sleep, not an infinite wait. priv/self/anf.bl rejects receive; behavioral comparison must use actual BEAM execution.

Proposed architecture: a dedicated Web Worker hosts many lightweight logical BL processes, each with pid, explicit resumable frames/continuation, mailbox and scan cursor, receive generation/deadline, runnable/waiting/dead status, and eventually monitor/link state. Compile ANF into executable JS state-machine blocks; this need not interpret ANF at runtime. Plain proven non-suspending helpers may retain native direct calls; otherwise calls use a resumable ABI. Prefer conservative handling of unknown/higher-order targets. Existing system.footprint/system.analyze machinery is reusable for analysis structure, but its resource/effect summaries are not currently a sufficient sound may-suspend classifier. Keep process context explicit across suspension; do not rely on a single ambient global current process.

Web APIs supply hosting and transport, not Erlang semantics: Worker isolates CPU from DOM; MessageChannel/postMessage connect host and worker and schedule task turns; performance.now plus timers support deadline wakeups; fetch/WebSocket/DOM adapters enqueue BL messages. Within one worker, sends can enqueue locally, avoiding a browser event per logical message. One worker per BL process is not the default: it adds isolation/transport costs and complicates closures. A single-worker actor runtime need not require shared memory or cross-origin isolation. Additional workers are optional scheduler partitions later.

** Compatibility obligations
Selective receive must be message-major, then clause-order: choose the earliest queued message matching any clause, try that message's clauses in source order, remove only it, retain all skipped messages in order. Guards use BL/BEAM guard semantics (including guard failure), not arbitrary JS callbacks. Pattern matching must reuse the BL value model and compiler-expanded tuple/vector alternatives. Timeout expression evaluates once; unmatched arrivals never restart its deadline; after 0 scans queued messages before choosing the timeout branch; infinity means no timer. No lost wakeups between scan and wait registration. Each receive has a generation/token; message selection or timeout commits at most once and stale timer events are ignored. Exact timeout/message races require conformance tests against BEAM rather than assuming Promise.race provides a spec.

Compiler must preserve suspended caller frames, exceptions and finally cleanup, and lower tail calls/recur to transitions so repeated receives do not grow the JS stack. Scheduler needs budgets at compiled backedges/calls and mailbox scans, plus chunking for long runtime operations. Merely yielding at receive starves peers under CPU-bound code. Yield back to browser task turns, not only Promise microtasks. Arbitrary blocking/uninstrumented JS cannot be preempted in a single worker; document and isolate such FFI.

Message ownership must preserve BL isolation. Immutable BL data can be shared within one worker; mutable foreign objects must be copied, restricted, or represented as explicit capabilities. Cross-worker structured clone cannot serialize JS functions or preserve custom prototypes; a BL codec and code-id/environment representation would be required for closure messages. Do not transfer buffers implicitly because transfer detaches the sender's buffer. Sources: https://developer.mozilla.org/en-US/docs/Web/API/Worker/postMessage ; https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm . Web timers can be delayed/clamped and have bounded delay arguments; large BL timeouts need chunking and browser lifecycle suspension remains outside language runtime control: https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout .

** Scope and verification
Core spawn/self/send/receive/make_ref/sleep is feasible in this design. Links/monitors/trap_exit/exit signals/registry are additional actor-runtime work, and supervisor/server protocols can be layered over that; full OTP, ETS, ports, native libraries and distribution do not follow automatically. If broad OTP behavior is the priority, explore BL's existing BEAM output on Popcorn 0.4 instead of recreating OTP in JS. This route remains untested for BL: toolchain/bytecode compatibility, package reachability, native NIFs, loader/AOT assumptions and browser host restrictions need an audit.

Proof gates: source-to-JS browser Worker ping/pong; nonmatching mailbox prefixes retained; message-major versus clause-major discriminating case; after 0 and no-clause timed receive; once-only timeout expression; unmatched message flood cannot reset timeout; timer/message race and stale wakeup; dynamic function calls which receive; exception/finally around suspension; long receive/recur with bounded stack; CPU-bound loop does not starve another process/timer; sender mutation cannot alter receiver value. Compare semantic results/traces with BEAM under controlled causal schedules, allowing legitimate race nondeterminism rather than demanding identical timing. Later gates cover DOWN/EXIT/link and death cleanup. Existing relevant BL sources/tests: test/bl/core_backend_test.bl, test/bl/vm/guarantees_test.bl, test/bl/executor/sandbox_test.bl, test/bl/system/model_test.bl, priv/std/proc/flow.bl, priv/std/clojure/core/async/impl.bl.

Conclusion: revise prior 'reject receive initially' from architectural exclusion to scope choice. Compatible selective receive is feasible with ANF coroutine lowering plus a real actor runtime using Web Platform services. It is more than a thin postMessage/Promise shim, but does not require embedding a full BEAM VM.
