* C — host compiles in one VM
** Baseline (main = e6303e31)
- 8 hosts (aot_cache bootstrap loader source_graph build_plan link tiers
  optimize), byte-identical serial vs parallel in every run.
- Serial uses ONE core: scheduler busy 1.0-1.07 of 10 in every serial run.
  Parallel reaches 1.6-2.9 cores. Fresh-VM parallel vs fresh-VM serial on the
  same load: 22.9 s vs 22.0 s, 32.3 s vs 36.6 s — no real gain.
- One loader.bl compile: 2026 =code:priv_dir= calls, all from =Tiers/priv_root=,
  2024 of them via =Tiers/dirs= ← =Loader/search_dirs= ← =Loader/resolvable?=.
  11187 =code:ensure_loaded= calls are protocol dispatch (=Enumerable.impl_for=)
  on loaded modules: no code_server round trip.
- =search_dirs= costs 296 us per call: =Tiers/dirs= 290 us, of which
  =priv_root= 48 us and five =File/dir?= checks 180 us. =code:priv_dir= alone is
  8 us. Under 8 procs every part slows 8-17x (code_server, file server, the
  Env Agent for =load_paths=).
- Where 8 concurrent compiles wait (share of scheduled-out time):
  | code_server ← Tiers/priv_root            | 12-14% |
  | code_server/gen ← Loader/search_dirs     | 9-11%  |
  | code_server ← lower module->beam         | 7-9%   |
  | code_server/gen ← lower release-eval-module! | 7%  |
  | compile:do_compile (erl compiler server) | 7-15%  |
  | Emit/load_binary! via publish_binaries!   | 3%     |
  | Env local lock + global:trans backoff    | 3-10%  |
- A second compile of the same host in the same VM costs 2x: Optimize 114M →
  213M reductions; =compile:forms= 136 → 194 calls (58 more modules emitted),
  =LazyMemo/deps_walk= 2.4k → 66k. Output bytes identical. Serial 8-host rounds
  in one VM: 24.6 s → 42.3 s → 53.3 s.
** Design
1. Resolve the tier dirs ONCE per declaration pass. =with_declaration_snapshot=
   already defines the scope ("the next pass sees edits and newly appearing
   files"); keep =Tiers/dirs= in that pass state, like the resolvable? answers
   it already keeps. No global state, nothing to invalidate. Callers outside a
   pass keep the live lookup.
2. Pass =root= explicitly where a call site already has it (=Tiers/dirs root=,
   =floor_source=) instead of re-deriving =priv_root=.
3. Find why compile #2 emits 58 more modules and walks LazyMemo deps 27x more;
   fix the leak. This hits every VM that compiles more than once (bl test,
   =seed_test= compiles 70 hosts 14 times).
4. Then re-measure. Only if code_server is still the top wait, batch eval
   modules per namespace (=lower/eval-anf= load + release per form).
** Results
- Step 1 landed (=559fb949=): tier dirs kept per declaration pass.
  loader.bl compile: =code:priv_dir= 2026 → 3. Floor fixpoint 104/104 +
  manifest. Pointed loader tests green (6 files, 306 assertions).
- Wall time did not move (same-load A/B, old vs new image):
  | | serial | parallel |
  | old, load 20 | 19.6 s | 14.8 s |
  | new, load 20 | 18.6 s | 18.0 s |
  | old, load 42 | 36.0 s | 34.7 s |
  | new, load 42 | 37.2 s | 33.4 s |
  priv_root was the top single wait, but only ~12% of the waiting; the rest is
  spread across many serial points that remain: erl =compile= (7-10%),
  eval-module release (7-10%), =Emit/load_binary!= (4%), =find_file= file
  reads (6-11%), =ambient_dirs= =File/cwd!= (3-7%), Env locks (3-8%).
  Removing one at a time will not make one VM scale; sharding across VMs does.
- Compile #2 cost found: =Link/defvar= rebuilds the whole namespace shim on
  every REdefinition of an exported name. The first compile of a namespace
  forwards new names (one rebuild at =settle=); compiling it again redefines
  every name, so every def rebuilds the shim: O(N²) in defs. Optimize: 63
  defs → 63 shim rebuilds (=Emit/shim_clauses= 5 → 63, =LazySeq/new= 125 →
  4038). Hits every VM that loads a namespace twice: reload, =bl watch=,
  =seed_test= (14 × 70 host compiles), regeneration steps in one VM.
  Fix design: on the first redefinition in a unit, rebuild the shim ONCE with
  no exported defs (handler only) and write =:fwd= rows for every current def,
  so later defs forward; =settle= rebuilds once at the end. Two rebuilds per
  unit instead of N. Calls during the load still reach the newest body.

* 1 — first run from a drop compiles nothing
- Release drops are built with =self-build --reuse-floor=
  (=.github/workflows/release.yml:228=); =selfbuild/do-reuse-floor= deletes
  every =Ns.*= beam and =priv/sdk-code.term=, so a fresh machine compiles every
  std/lib/compat/build namespace on first use (v2026.6: 345 s).
- Plan: add a library-compile stage after floor reuse that runs the same path
  as =do-compile=, writes =sdk-code.term=, regenerates =beam_lisp.app= after.
  Loader trust is unchanged (=stale_by_provenance?=: compiler key + closure
  hash). Keep the build manifest out of the payload.
- Acceptance: first =bl run hello.bl= from a freshly extracted drop, empty XDG
  cache, before/after, ≥3 samples.

* 2 — SDK class preparation at start
- Boot prepares one class (=proc.owner-registry=). Its first
  =retain_sdk_runtime!= wildcards and reads every tier source for =defnative=,
  loads =vm.native=, and builds the whole-SDK inventory certificate over
  =code:all_loaded=. =inventory_term= re-reads =sdk-code.term= on every call.
- Plan: add a counter seam around =Env/prepare_sdk_class!= first. Then:
  memo the parsed =sdk-code.term= by path+size+mtime; replace the source scan
  with the native rows already in =sdk-code.term=; persist the runtime
  inventory under the AOT cache keyed by compiler key + sha256(sdk-code.term),
  revalidating live module md5 on use.
- Acceptance: =scripts/cold-start-profile= before/after, ≥3 samples.
