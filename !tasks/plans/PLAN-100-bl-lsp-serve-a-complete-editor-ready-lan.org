* What this is, from zero

beam-lisp is a Lisp on the Erlang VM. Its compiler proves facts about code:
return types (inter-procedurally), purity (no side effects), termination,
native-compilation eligibility, dead code, change impact. All of that is
already exposed as plain functions in =priv/lib/lsp.bl= (namespace =lsp=),
one function per editor feature, each taking a source string and returning
data. There is a test file, =test/bl/system/lsp_test.bl=, and a terminal
renderer, =bl lsp check FILE=.

What is missing is the wire. Editors (VS Code, Neovim, Helix, Zed, Emacs)
speak the Language Server Protocol (LSP): JSON-RPC 2.0 messages framed with
=Content-Length= headers over the server's stdin/stdout. Nothing today
speaks that protocol. So the intelligence exists but no editor can reach it.

Goal: =bl lsp serve= is a COMPLETE, well-tested LSP server. Every standard
LSP feature that =lsp.bl= can answer is wired; the proof-only features that
LSP has no request for are surfaced through the closest standard mechanism
(hover text, code lens, diagnostics tags, custom requests) so an editor shows
them without a plugin. The test suite drives the server through the actual
JSON-RPC interface — framed bytes in, framed bytes out — so a green suite
means "an editor can use this", not "the functions work".

* Vocabulary (read once)

- =priv/lib/lsp.bl= (ns =lsp=). Signatures, verbatim:
  - =(hover src line col)= → string like ="call erlang/* : (:int)"=
  - =(diagnostics src ns)= → list of ={:msg :line :col :end-line :end-col :file}=
  - =(document-symbols src)= → list of ={:name :returns :terminates :pure :calls}=
  - =(definition src line col)= → ={:resolves-to name :kind :user-fn|:host}= or nil
  - =(references src target-name)= → list of caller fn names
  - =(completion src line col)= → list of ={:label :detail :kind}=
  - =(signature-help src line col)= → ={:label :returns}= or nil
  - =(inlay-hints src)= → list of ={:fn :hint}=
  - =(document-highlight src target-name)= → list of ={:line :col :end-col}=
  - =(code-actions src ns line col)= → list of ={:title :kind :at}= / ={:title :kind :fn}=
  - beyond-LSP: =(proof-hover src fn-name)= → ={:fn :pure :footprint :terminates :returns :calls}=;
    =(native-eligible src fn-name)= → ={:eligible :reason …}=;
    =(impact src fn-name)= → vector of transitively reachable fn names;
    =(dead-code src roots)= → unreachable fn names.
  Lines are 1-based, columns are 1-based, from the reader's =:ann=.
- LSP positions are 0-based line AND 0-based character, where "character"
  counts UTF-16 code units. A line with an emoji shifts every later column.
  One conversion layer, both directions, is required.
- =priv/std/bl/cli.bl=: the =bl= CLI. =cmd-lsp= (≈ line 393) currently handles
  =check=; add =serve= beside it. =cmd-*= functions return an exit code and
  never halt.
- JSON: =(interop/->json x)= and =(interop/json-> s)= in =priv/std/interop.bl=
  (Jason underneath). Keywords become strings; maps become objects.
- stdin/stdout: the =bl= binary runs commands inside a warm daemon whose
  group-leader proxies stdin/stdout over its socket (=lib/beam_lisp/daemon/io.ex=).
  =IO/read=, =IO/binread=, =IO/write= on =:stdio= work through it. A
  long-running server must therefore be run as a FOREGROUND process, not via
  the daemon: =serve= must be dispatched with =bl --no-daemon lsp serve= OR the
  launcher must special-case =lsp serve= to run standalone. Investigate
  =lib/beam_lisp/daemon/executor.ex= and the launcher first; pick the smallest
  change; document it. (Editors spawn the server process themselves, so a
  standalone run is the natural fit.)
- =priv/lib/system/incr.bl= (ns =system.incr=): =(analyze-incremental cache
  src)= re-proves only changed functions + dependents. Use it under
  =didChange= so a keystroke costs a re-proof of one function, not the file.
- =priv/std/span-rewrite.bl=: =(rewrite-source src rule)= and
  =deodorant/fix-source-preserving= produce formatting-safe text edits; the
  =codeAction= → =workspace/applyEdit= path uses them.
- Tests: =.bl= files under =test/bl/= with =deftest=/=testing=/=is=. Run:
  =mix beam_lisp.test test/bl/system/FILE.bl=. Existing pattern for a

* Architecture (three files)

** =priv/lib/lsp/rpc.bl= (ns =lsp.rpc=) — pure protocol layer, no I/O
- =(decode-frame bytes)= → ={:msg map :rest bytes}= or ={:need N}= (partial)
- =(encode-frame map)= → bytes with =Content-Length: N\r
\r
= prefix
- =(handle state msg)= → ={:state state' :out [msg…]}=: the ENTIRE dispatch,
  as a pure function of (server state, one inbound message). Server state
  holds: open documents ={uri {:text :version :ns :cache}}=, client
  capabilities, =initialized?=, =shutdown?=.
- position conversion: =(bl->lsp text line col)= and =(lsp->bl text line
  character)=, UTF-16 aware.
Because =handle= is pure, every test drives it with maps and asserts on maps —
fast, deterministic, no process.

** =priv/lib/lsp/server.bl= (ns =lsp.server=) — the stdio loop
- reads stdin in binary chunks, feeds =rpc/decode-frame=, calls =rpc/handle=,
  writes each =out= message with =rpc/encode-frame=.
- =exit= notification → stop the loop, return 0 (or 1 if =shutdown= was never
  received, per spec).
- publishes diagnostics after =didOpen= / =didChange= (debounced: coalesce
  changes within 150 ms; a test proves two rapid changes yield ONE publish).
- errors inside a handler become a JSON-RPC error response (=-32603=) with
  the message, never a crash of the loop; a test proves this.

** =cmd-lsp= in =priv/std/bl/cli.bl=
- =bl lsp serve= → =lsp.server/run= → exit code. =bl lsp check= unchanged.

* The full request surface (every row is a test)

** Lifecycle
| =initialize= | returns capabilities (below) + serverInfo ={name "beam-lisp" version}= |
| =initialized= | notification; no reply |
| =shutdown= | reply null; mark |
| =exit= | loop ends; exit 0 if shutdown seen else 1 |
| unknown method (request) | error =-32601= MethodNotFound |
| unknown method (notification) | ignored silently |
| request before =initialize= | error =-32002= ServerNotInitialized |

Capabilities advertised: =textDocumentSync {openClose true, change 1 (full),
save true}=, =hoverProvider=, =definitionProvider=, =referencesProvider=,
=documentHighlightProvider=, =documentSymbolProvider=, =completionProvider
{triggerCharacters ["(" " "]}=, =signatureHelpProvider {triggerCharacters
["(" " "]}=, =inlayHintProvider=, =codeActionProvider {codeActionKinds
["quickfix" "refactor"]}=, =codeLensProvider {resolveProvider false}=,
=workspaceSymbolProvider=, =renameProvider {prepareProvider true}=,
=executeCommandProvider {commands [...]}=. Only advertise what is implemented
below; a test asserts the advertised set equals the handled set.

** Documents
| =textDocument/didOpen= | store text+version; derive ns from the leading =(ns …)=; publish diagnostics |
| =textDocument/didChange= | full-sync: replace text; re-analyze via =system.incr= (only dirty fns); publish diagnostics |
| =textDocument/didSave= | re-publish |
| =textDocument/didClose= | forget; publish empty diagnostics to clear squiggles |

** Standard features → =lsp.bl=
| =textDocument/hover= | =lsp/hover= → ={contents {kind "markdown" value …}}=; APPEND the proof card: if the cursor is inside fn F, add a second section from =proof-hover= ("pure · terminates · returns (:int) · calls a, b") and the native verdict from =native-eligible=. This is where the beyond-LSP intelligence lands for every editor. |
| =textDocument/definition= | =lsp/definition= → =Location= of the defn (find the =(defn NAME= span in the text; for =:host= kind return null) |
| =textDocument/references= | =lsp/references= → =Location[]= (one per caller's defn span) |
| =textDocument/documentHighlight= | =lsp/document-highlight= → =DocumentHighlight[]= |
| =textDocument/documentSymbol= | =lsp/document-symbols= → =DocumentSymbol[]= with =detail= = "→ (:int) · pure · ↓" |
| =textDocument/completion= | =lsp/completion= → =CompletionItem[]= with =detail= and =kind Function= |
| =textDocument/signatureHelp= | =lsp/signature-help= → =SignatureHelp= |
| =textDocument/inlayHint= | =lsp/inlay-hints= → =InlayHint[]= placed at the end of each defn's first line |
| =textDocument/codeAction= | =lsp/code-actions= → =CodeAction[]=; a =quickfix= carries a =WorkspaceEdit= computed with =deodorant/fix-source-preserving= over the smell's span; the "compile to native" =refactor= action carries a =command= (below) |
| =textDocument/codeLens= | one lens per defn: text = the proof badges ("pure · terminates · ◆ native" or "impure: stdout"); zero-arg command (informational). This is the most visible beyond-LSP surface. |
| =textDocument/prepareRename= / =rename= | for a top-level defn name: edit the defn and every =document-highlight= span (whole-file, text-safe). Refuse (=null=) on anything else. |
| =workspace/symbol= | across all OPEN documents: =document-symbols= filtered by query |
| =textDocument/publishDiagnostics= | from =lsp/diagnostics=; severity Error for type errors; ADD deodorant smells as severity Hint with =tags [Unnecessary]= where applicable, source ="deodorant"= |

** Beyond-LSP, as custom requests (namespace =$/beamlisp/=)
| =$/beamlisp/proofHover= ={uri fn}= | =lsp/proof-hover= |
| =$/beamlisp/nativeEligible= ={uri fn}= | =lsp/native-eligible= |
| =$/beamlisp/impact= ={uri fn}= | =lsp/impact= |
| =$/beamlisp/deadCode= ={uri roots}= | =lsp/dead-code= |
| =workspace/executeCommand= ="beamlisp.impact"= | same as above, reachable from a code action / command palette |
| =workspace/executeCommand= ="beamlisp.deadCode"= | publishes Hint diagnostics "unreachable from roots" on each dead defn |
| =workspace/executeCommand= ="beamlisp.nativeReport"= | returns the per-fn eligibility table for the document |

Each custom request ALSO has a standard-mechanism twin (hover section, code

* Gotchas already known

- =SyntaxError= from the reader is uncatchable with =try=: guard =didChange=
  by attempting the read in a spawned process (=erlang/spawn_monitor=) and
  publishing a single "parse error" diagnostic on failure, keeping the last
  good analysis. A test injects an unbalanced paren and asserts the server
  stays alive and reports it.
- Hyphenated namespaces need hyphenated filenames; =lsp/rpc.bl= is fine.
- =bl.cli= is AOT-compiled; =mix compile= after editing it.
- =lsp/completion= ignores line/col today (whole-program names) — document
  it, do not fake locals.
