#+TITLE: Immutable executable declarations without an application registry
#+DATE: 2026-10-14
#+STATE: IN PROGRESS — upstream integration; sandbox only

* Observed bug and acceptance boundary
The native Knowledger declaration-ownership-probe reproduces old graphs reading
new relation providers and proc clause transforms after candidate registration.
Code leases alone preserve code bytes,not mutable dispatch. Do not snapshot the
mutable Agent/Atom table and call it a sealed catalogue.

* Ordered implementation
1. Extract exact generation execution/leases into a small leaf module requiring
   only env. Keep public generation APIs,lock identities,nested execution marker,
   callback acquisition and retirement semantics. This removes the dependency
   cycle between datom/proc catalogues and generation planning.
2. Have existing SDK declaration macros emit named callback bindings and pure
   immutable values while preparing managed source. Capture compiler-owned
   descriptor identities in an ephemeral preparation context. Collect values
   only after actual ANF validation;reject duplicate identities,wrong schemas,
   unsealed callbacks and effectful factories before publication. Restore the
   preparation context on every failure. Ordinary source/AOT syntax stays valid.
3. Resolve relation and clause declarations from the exact graph;never consult
   mutable development tables for an absent managed declaration. Preserve fixed
   SDK builtin initialization separately,without allowing application namespace
   prefixes to grant trust. Runtime mutation of a managed catalogue must refuse.
4. Integrate delayed reconciliation descriptors through the same boundary;
   keep state and resource lifetime separate from executable declaration data.

* Checks and measurements
Preserve all generation/lease/nested-call/registry tests. Turn both probe rows
into preservation assertions. Include cold SDK builtins,real datom queries and
proc compilation,two applications,development scopes,old delayed callbacks,
retirement,duplicates,invalid forms and refusal before effects. Measure warm
lookup and candidate preparation against a controlled baseline. Use typed/system
facts only where they describe the executed compiler IR;native runtime tests
remain authoritative for leases,loading and dispatch.

Build one clean source-identified SDK after a tested batch. Validate the actual
packaged host/JavaScript ABI before either consumer changes its env.bl selection.
No production deployment or full-product-readiness claim follows from a leaf
refactoring or a passing declaration-map test.
