* Problem
Erlang binary_to_term with safe prevents new atoms but can reconstruct functions,
processes, ports and references. SDK decoder wrappers can otherwise admit those
values even when Source code cannot call the raw primitive. Local-fun module
identity or a factory label does not prove that a value came from the factory.

* Shared kernel boundary
CompilerData/check_closed_etf! walks ETF bytes before decoding, without creating
atoms, runtime values or invoking callbacks. Default limits are16MiB input,
1million structural nodes and128levels. The pending stack holds grouped child
counts, so forged huge container headers refuse before proportional allocation.
The allowlist covers scalar data, binaries/bitstrings, ordinary tuples, lists
(including improper tails) and maps. Runtime/distribution/future unknown tags,
compressed envelopes, truncation and trailing payloads refuse. The native BIF
still validates ordinary encoding details after this capability grammar check.
CompilerData/decode_closed_etf! then uses safe to prevent new atom creation too.
Reference: https://www.erlang.org/doc/apps/erts/erl_ext_dist.html

* Integration and compatibility
Actual Source context must choose this guard at public first-party decoder
entry points and transitive storage/cache readers. Trusted native framework
storage retains its existing decoder/options ABI. Source raw binary_to_term
remains denied. A decoded tuple is data, not permission: callable descriptor
arms, native target checks and protected resource cells still require actual
provenance. Compression support for untrusted Source can follow a separately
bounded inflater; guessing size from an untrusted header is insufficient.
No application annotations, bespoke decoder or Knowledger-only workaround.

* Validation
Five permanent cases exercise ordinary ETF roundtrips, nested runtime identities
and functions, raw capability/distribution tags, malformed/huge headers, depth,
node/byte limits and every prefix of a real nested encoding. Native independent
Host probe, actual SDK Source ingress and native compatibility are distinct gates.
The current source-only probe must not be reported as ordinary CLI/SDK acceptance.
Warm parser/decoder overhead is to be measured against the same BIF input in the
same VM; these are security-boundary costs, not startup speedup claims.

and multi-prefix scans select native data modes using the private physical Source
extent predicate. Native framework reads preserve their any-term ABI; packed
scalar lanes preserve their existing direct decoder. The ETF lane proves the

This native entry supports compressed ETF using the existing bounded inflater:
charge advertised expansion before inflation, then verify exact stream/length
and the complete data grammar. Ordered-page preflight also clamps the caller's
budget to the Source ceiling before any inflation. The public CompilerData entry
continues to refuse compression. Neither entry admits runtime capabilities.
