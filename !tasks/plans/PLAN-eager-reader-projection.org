#+TITLE: Concrete syntax projection without lazy runtime callbacks
#+STATE: Reader projection accepted in native component tests and ABBA; coherent SDK pending

* Evidence and problem
Native planner control 120 failed with a shadowed Core/list. Diagnostic 121
locates Reader.unwrap-deep calling lazy map and then the ambient list function.
This syntax projection already promises a concrete result; allocating a lazy
memo cell and forcing it for every nested collection adds work and accidentally
depends on mutable runtime values. Reader-node/form has the same pattern.

* Method
- Use native eager list mapping with explicit local reader-helper closures for
  deep stripping and the outer read-all projection.
- Assemble anonymous-function rest parameters from their existing lists directly.
- Convert reader-node lists and vectors eagerly, preserving exact output kinds.
- Keep the positioned parsing loop and author metadata rules intact.

* Validation
Focused tests cover nested lists, vectors, maps, sets, records, quoting, author
metadata and anonymous rest arguments under effectful shadowed Core values.
Reader-node conversion checks exact native list/vector representation even when
temporary helper namespace values are unavailable. Existing reader, reader-meta,
source-graph and interface controls remain required.

Benchmark the actual old and new native reader artifacts on one frozen source
corpus in alternating order, require matching output digests, and retain source,
artifact and runtime identities. Report parsing cost, not page-navigation or
whole-application startup ratios. Rebuild and commit the coherent floor before
ordinary startup or release acceptance.
