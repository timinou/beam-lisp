* The thesis
The oracle's INPUTS are already language values (smt.bl: forms, one printer). Its
OUTPUTS are not — the verdict is a string compared at 44 sites in 10 files, the model is
text parsed at 39 sites (veritas owns a private parser; core.bl matches `define-fun`
textually ×14). Its LIFETIME is a bundle (z3pool). Asking it is a bare call that can't
be handled, memoised or fanned out. The cutover makes every one of those a value, a
bundle or an effect — so a consumer moves with a function-call change.

* BUG FIXED ON THE WAY — FUP-055's root cause, and it was a lie all along
`priv/boot/build.bl`'s retry called `(Thread/sleep 150)`. There is no `Thread`
module (`Code.ensure_loaded(Thread)` → `{:error, :nofile}`), so the retry ITSELF
raised `Thread.sleep/1 is undefined` and MASKED the error it existed to report. The
"AOT build blocker" that blocked `mix bl.build` for days was this catch reporting
itself. `Process/sleep` now, and the AOT reports real errors — which is how the
cutover could proceed at all. `bl check <file>` (not the AOT's message) is the
instrument that names the file; the AOT attributed a broken `core.bl` to three mcp
files, twice.
