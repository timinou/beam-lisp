* The finding

Six of this session's defects are **one defect**: a single source of truth was
restated somewhere else, and the restatement drifted. Not "similar bugs" — the
same bug, six times.

| restated fact | where it was declared | where it was restated (wrongly) | defect |
|---|---|---|---|
| the artefact's installed name | `vm.native/installed-path` | `build.bl` literal `(str crate ".so")` | BUG-070 |
| how to install without disturbing a mapping | `vm.native/build!` (rename) | `build.bl` `File/cp!` | BUG-074 |
| how to prune beams for gone files | `build-ordinary` | `build-substrate` (absent) | BUG-067 |
| the daemon readiness handshake | `tooling/drop/src/daemon.rs` | `launcher.rs` (a second copy) | BUG-066 |
| what the native key hashes | `native-key`'s docstring ("plus the cargo version") | the code, which hashed `"cargo"` | key bug |
| the loader's path | `vm.native/installed-path` | `native_test.bl`'s literal assertion | BUG-070 fallout |

The last row is the tell. A **test** restated the path — so when BUG-070 moved
the truth, the test kept asserting the lie, and went red behind the fix.

* Why it keeps happening

The contracts in `vm/native.bl` are already well named: `host-module` is
documented as "THE rustler::init! contract", `lib-path` as "the path
`erlang/load_nif` wants", `installed-path` as "Where the built .so lives". The
declaration is not the problem.

**Nothing binds a declaration to its consumer.** A name in a docstring and a
literal in another module look equally authoritative to a reader, and only one
of them runs. `build.bl` does not require `vm.native`, so it could not have used
the contract even if its author wanted to — the module boundary made the
duplication the path of least resistance.

* The four classes

  A. re-derivation — a fact named once, restated elsewhere. Six instances above.
  B. unbound declaration — a contract is stated; nothing checks observance.
     (`defnative` declares a boundary; nothing asserts the install matches it.)
  C. the wrong artifact measured — tests assert a restated path; a build is
     verified against a dirty tree, not the commit a release is cut from.
  D. out-of-band death — a boundary kills the VM with no stack (BUG-074).

* The program

Each fix must be **enforceable by a test**, or it is documentation that will rot
the same way.

**1. One name, one module — and the consumer requires it.**
`vm.native` gains a root-aware path constructor; `installed-path/1` delegates to
it. `build.bl` requires `vm.native` and calls it. The build can then no longer
disagree with the loader, because it asks the loader's module. Delete
`build.bl`'s literals — do not keep them "in sync".
*Kills:* BUG-070's class. *Proves it:* the test asserts via the same function.

**2. A gate that fails on a restated contract.**
A test in the shape of the existing `sunset_gate_test`: `"priv/native"` and
`".so"` may be constructed only in `vm/native.bl`. Any other module naming the
artefact layout fails the gate.
*Kills:* the whole class, not one instance — including the next one nobody has
written yet.

**3. Tests derive, never restate.**
An assertion about a path calls the function that computes it. An assertion
about a name calls the function that names it. Where a test must hardcode
something, that hardcoding is a finding, not a convenience.
*Kills:* BUG-070 fallout, structurally.

**4. The release is a value, not a ritual.**
`bl release` computes and cross-checks: the tag, the changelog, the artefact
hash, and the set of fixes it claims to ship — asserting every fix is an
**ancestor of the tag**, and that the artefact was built from a clean tree at
that commit. PLAN-127's landmine (a tag 35 commits stale, silently rebuilding a
fixed bug) is precisely a missing assertion.
*Kills:* the stale-tag class.

**5. Verify the artefact, not the tree.**
A release gate builds in a clean worktree at the tag and runs the produced drop
from a directory with no beam-lisp sources. This is already how the drop smoke
test works; it was not how the fix was verified.
*Kills:* class C.

**6. Instrument the declared boundaries.**
`defnative` already declares every point where beam-lisp can die without a
stack. Extend the declaration to carry the recorder, so the instrumentation
travels with the boundary instead of being an env var a human must remember.
`BeamLisp.NifTrace` exists; it needs attaching.
*Kills:* class D's diagnosis cost.

* Sequencing

4 and 5 before the next release attempt; they are release-machinery, not

* CORRECTION (same day): the barrier decides which fix is available

Fix 1 said "delete the second copy — do not keep them in sync". Attempting it
proved it impossible for this contract, and the attempt is the evidence.

Making `build.bl` require `vm.native` was **refused by the build**:

    beam-lisp AOT: toolchain source priv/build/build.bl requires ordinary
                   source priv/std/vm/native.bl

`partition-plan` defines toolchain as `priv/boot/` + `priv/build/` and rejects a
toolchain source requiring an ordinary one. That is sound — the driver must not
depend on what it builds. The other two directions are closed as well: the
runtime must not require a build source (a drop ships no `priv/build/`), and
`priv/boot/` is codegen, where a NIF filename is a category error.

**So a contract that spans the toolchain/ordinary barrier provably cannot have
a single definition.** The barrier did not cause the duplication as an accident;
it made the duplication the only available shape. The choice is between a copy
and a copy that is *checked*.

∴ **For barrier-crossing contracts the fix is a CHECK, not a require.**
Landing today as `c57a8570`: `vm.native/artifact-name` (loader's half),
`build/nif-artifact-name` (installer's half, carrying the barrier in its
docstring), and `test.native/the-installer-and-the-loader-agree-on-the-name`
(the gate). Proven to fail rather than asserted to pass — diverging the two
deliberately fails 6 assertions.

* What this changes about the program

- Fix 1 is narrowed: **collapse duplicates only within a layer.** Across the
  barrier, gate them. Anything else is either an illegal require or a category
  error.
- Fix 2 is promoted from a nicety to **the only available enforcement** for
  this whole class, and should be written as a general gate over
  contract-bearing literals rather than one fact at a time.
- The 6 rows in the finding table must be split by this rule: which restate
  something in a *requirable* layer (collapse them), and which cross the
  barrier (gate them). BUG-074's install rule and BUG-067's pruning are
  same-layer and collapse for real; BUG-070's name and BUG-066's handshake
  cross a boundary and need gates.

* Worth recording about the barrier itself

The build system already had the enforcement machinery — it just had it pointed
at *imports* and not at *duplication*. `partition-plan` proves the project is
willing to refuse a build over a layering violation. The same willingness,
pointed at a restated contract, is Fix 2.
