* Intent

A bl user should be able to type ~bl~ and have it fast, see everything bl is
running on the machine, and stop any of it, without learning that "the daemon"
meant three things. Five nouns, one question each:

| vm     | what is running on this machine?   | one registry record per VM       |
| realm  | what is my project doing?          | vm.manager's table, in the VM    |
| member | what work is in flight?            | vm.owner's registry              |
| route  | how do I reach it?                 | a claim file per name            |
| build  | which code is this?                | an immutable drop directory      |

~bl realm~ is the project in front of you; ~bl vm~ is the machine. Everything
else is a verb on one of those two.

** DONE 6. Make auto-start safe

* Decisions (from review)

1. ~bl ui~ becomes ~bl vm ui~ and forwards. Nothing stays as a special top-level exception.
2. ~BL_DAEMON~, ~BL_DAEMON_ROOT~, ~BL_DAEMON_READ_TIMEOUT~ are GONE: ~--cold~, ~--warm~, ~--root DIR~, and a ~:warm~ declaration ("off"|"attach"|"start") in env.bl or config.bl. Precedence: flag, env.bl, config.bl, default. The default is ~attach~ (use a warm VM if one runs, never start one); flipping it to ~start~ is one constant, ~DEFAULT_TRANSPORT~, and waits on step 7's log files.
3. Why each old use of BL_DAEMON=off existed, and what became of it:
   | reason | status |
   | a daemon ran requests in ITS OWN environment (FOO=bar answered nil warm) | FIXED earlier: the client's env travels with the request. No longer a reason. |
   | a silent long command looked like a lost connection | FIXED: the VM sends a heartbeat every 5 s while a request runs; the client's patience is 60 s of NO frame. BL_DAEMON_READ_TIMEOUT deleted. |
   | testing a packaged image itself | KEPT, and it is what ~--cold~ is for. |
   | a child bl under ~timeout~ (xberg): the client dies, the warm VM keeps running the command | STILL TRUE. Kept as ~--cold~ with the true reason. FUP-133 fixes it structurally. |
4. Wider sweep: findings are recorded as FUP-133..136 rather than added to scope.
5. Documentation is literate: ~priv/std/bl/{vm,realm,deprecated}.bl.md~ are the verbs themselves, and their ~Live~ cells read the machine when run (~bl doc run~). Live results are NOT stored in the files: they would be one machine's pids and paths.
6. Rust is written to a table, not a string soup: ~transport.rs~ holds the precedence as one pure function over (argv, env.bl text, config text), the start spellings as data, and named consts for every file name and store key.

* Security (summary — full text in docs/design/realm/security.md)

Two attacks need two defences. A token in a custom header stops a cross-site POST;
a Host check stops DNS rebinding (where the page, token included, is readable).
Both are required, both are tested, and a refused page carries no token. No CORS
headers are set. Stopping needs the token; nothing signals a pid it cannot prove.

* Risks

- Blast radius of one VM per user: a native fault or runaway allocation reaches
  every realm in it. Mitigated by the isolated escape hatch; not yet measured.
- Adoption cannot prove a legacy pid was not reused; it signals only beam.smp.
- The Rust launcher and vm.paths share naming contracts; change both or neither.
- Auto-start without step 6 can orphan a daemon (measured above).
