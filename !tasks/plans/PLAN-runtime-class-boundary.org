#+DATE: 2026-10-15

* Installed mechanism
reload.execution/runtime-inspection walks raw native maps/tuples/lists with a
100,000-node/128-depth budget. It never calls a domain Enumerable/Seqable/query,
forces a lazy value, or returns inspected data. Per-pass class proofs are threaded
purely; there is no new Atom/cell allocation per validation. Repeated instances
of the same class cause at most one full SDK attestation in that pass.

Registered Beam Lisp record/deftype values require this graph's actual admitted
:classes set or independent AOT.sdk_generated_class? evidence (canonical source,
compiler/unit metadata, actual MD5 and established fixed SDK lifetime). Fields
and deftype arity are checked. Matching old/new fields never silently retag a
nominal code identity. Existing unknown native structs keep their former raw
nonexecutable treatment; this is not a universal foreign-struct sandbox.

bind-runtime! and inherit-runtime! validate BEFORE modifying bindings. Explicit
migration can create fresh target cells/nominal values while accepted old
callbacks retain their original cells and old graph until actual drain.
check-runtime! is the final mandatory point-in-time observation before source
publication. Parent owns generation's actual :classes producer and publication
hook; Foundry additionally needs a compatibility/pre-transition check before any
owner state mutation, plus this final fresh publication check.

Known LazySeq/Delay/Derived/Future/Promise and native transient continuations are
refused instead of forced or inherited. Keep them in their owned old task/callback
and drain them explicitly. PID/reference/port native resources retain existing
resource-ledger obligations; this scan does not prove their hidden data or accepted
external work was migrated. No path/name or registry row grants SDK authority.

* Hot path and mutable alias limit
runtime-resource is byte-for-byte unchanged: live initializer/key lookup only.
No full Datom/query traversal was added to requests. Raw store fields may be
observed at binding/publication, but backing NIF data is not queried.

Atom/Volatile contents are checked at the observation point. A later direct alias
write can change them, including between observation and publication. This does
NOT prove universal postpublication protection, freeze shared cells, or replace
native typed message/data migration and owned-resource fences. reload.state
validated writes receive the new class check; direct raw writes still need a
separate mutation policy/validated cell capability for a stronger guarantee.
Opaque continuity is never claimed adopted merely because an observation passed.

* Root-only focused gate
./bin/bl test test/bl/reload/runtime_class_test.bl test/bl/reload/runtime_handle_test.bl test/bl/reload/generated_class_test.bl

Requires coherent canonical Record/compiler/AOT hosts, ordinary fixed SDK lifetime
adoption and parent's generation class/publication hooks. Tests cover old/new
records/deftypes, rejection without candidate mutation, explicit fresh-cell
migration with retained old callback, fixed SDK Conn positive, malformed/foreign
class negative, alias change caught before publication, and no domain/lazy forcing.
Static delimiter/direct exception-parent checks only have passed so far.

* Root-only regression benchmark
./bin/bl run research/reload-contracts/runtime-class-lookup-bench.bl

One VM uses the same prepared graph and payload for old getter copied verbatim
and current getter. Four alternating baseline/current pairs measure20,000lookups
for10/1,000/20,000element payloads after both routes warm. Validation is measured
separately with3groups of5bounded scans and reports actual raw node/class/SDK
check counts. This is an unchanged-hot-path regression benchmark, not an app
speedup claim. Preserve source/floor hashes, raw pairs and resource metrics when
root runs it; no native or benchmark results are claimed at this checkpoint.

* Publication integration checkpoint
Prepared graphs now retain the actual compiler-collected :classes set. Serving
publication checks current/reload/expected state under a short slot lock, scans
candidate runtime values outside that lock, then repeats the comparison before
any slot/state mutation. Stale, disabled and already-applied operations return
without the scan. This keeps old-generation request admission independent of
the potentially large bounded scan. The existing alias-change refusal fixture
also checks stale publication; native acceptance still pending the SDK gate.
