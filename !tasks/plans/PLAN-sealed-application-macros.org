#+TITLE: Compiler-owned eager application macros
#+DATE: 2026-10-14
#+STATE: IN PROGRESS

* Problem
The complete Knowledger source diagnostic refuses diagnostics and observability
at defmacro. Their macros are conventional syntax-quoted wrappers. Exempting
application namespaces or trusting an empty immediate footprint would admit
arbitrary compile-time effects, lazy forcing and unbounded recursive transforms.

* Implementation boundary
Preserve source syntax and normal development behavior. In managed preparation,
compile the exact macro initializer once, prove its actual anonymous-function
scaffold and executable bodies before installing it, and retain its companion
modules until that graph retires. Inspect exact native targets after expansion.
Source admission projects templates to evaluated unquotes; it does not evaluate
the template or treat quoted symbols as executable authority. Generation source
rewriting seals explicitly qualified template references and preserves quotes.

The initial constructor subset is intentionally narrow: finite first-order
data, compiler-owned parameters, eager collection construction, branches and
exact reviewed constructors. Unknown remotes, globals, dynamic calls, callbacks,
lazy values, loops and recursion refuse. Generic Enum splice fallback is not a
proof: only proper eager sequences may be spliced.

First-order data excludes all native tuples except compiler symbol descriptors.
Transient/remote handles can be forged without embedding a native function.
Validate vector metadata too, and reject opaque/dynamic map keys that could
manufacture a foreign __struct__ before a later get/protocol operation. Native
vector storage tuples remain private to the exact compiler constructor.

* Validation and remaining gates
Native validation belongs to the root session, serially under its memory cap.
Fixtures cover actual diagnostics/observability shapes, old/new graph behavior,
exact expanded native apply, quotes and lexical locals, effectful/unquoted/latent
effects, reflection, producers and opaque resource values.

The implementation also bounds macro input/output traversal AND constructor
allocation from actual IR. A finite constructor expression can duplicate shared
syntax or repeatedly splice a previously constructed list; purity alone does not
bound its expansion. reload.syntax-size uses system.ir's exact child vocabulary
and counts duplicated occurrences, splice input copying, and consumer work.
Inputs are checked before invocation; output before compiler data->form. A shared
per-compilation counter refuses pure macro expansion cycles. Root's focused
native run passed macro32 + constructor-boundary16 + module-inventory10 +
clause-declaration35 assertions. The preceding broad batch also passed132
generation,25expanded-native,6definition,17lexical,37relation and27proc-clause
assertions; its unrelated lifetime fixture was incoherent, so that broad command
was not green. The first macro run exposed two corrected fixture defects.

The actor-only namespace inventory defect is separately committed718e4b3a:
derive bridges/body modules from actual emitted ns_defs, retain the real actor
module, and check all expected modules are loaded. A deleted real callback still
refuses a lease. Do not invent a bridge or ignore arbitrary missing code.

This does not establish full Knowledger closure. Diagnostics also contains an
environment/random initializer; unrelated actor/resource/catalogue refusals have
their own ownership and migration contracts. Trusted fixed SDK macros retain
their existing explicit compiler boundary; this change adds checked application
macros instead of broadening that boundary.
