* Initial Message

I want to create a beam-lisp package that is part of its 'standard library' (think about the hierarchy).

this beam lisp package reuses datom, biscuit and ideas from ash's oauth to make a combined ACL+RLS+IAM+OAuth gateway kind of thing that answers all the possible issues that this should need. let's explore the problem space first.

* What this is

The foundational layer of `auth`: a beam-lisp standard-library package that
folds ACL + RLS + IAM + capability-tokens onto ONE substrate — the datalog
engine `datom` already runs. The novel part is a wire-compatible Biscuit
(offline-verifiable, attenuable capability tokens) implemented in *pure
beam-lisp*; everything else is a thin, data-shaped layer over `datom`.

Full design rationale lives in =docs/auth-the-application-authorizes-itself.md=
(read it first — it argues every decision below and shows the downstream
syntax). This PLAN is the build order that doc's §5/§Build-order sketches,
expanded so any agent can execute it without re-deriving the design.

Downstream ergonomics (shape-declared auth, SAML/SSO config) are a SEPARATE,
later concern tracked in its own design doc — see "Explicitly out of scope".

* Thesis (one sentence)

ACL, RLS, IAM, and OAuth are four QUESTIONS asked of one value — a set of
datalog facts about who is asking — and the engine that answers them is the
one =datom= already has. =auth= is not a new engine; it is a vocabulary of
facts plus a cryptographic trust boundary laid over that engine.

* The load-bearing decision: BUILD, do not wrap

Rejected: a Rust NIF over the =biscuit-auth= crate (feasible — =native/datom_redb=
already ships a =rustler= NIF in this repo — but WRONG here).

Reason it is wrong: the whole value of =auth= is ONE datalog shared between a
token's =check if …= and the RLS =:where= injection. A NIF puts the token
engine behind an FFI wall, forcing TWO datalog engines that are required to
agree on authorization. =docs/trust-boundary.md= already names this exact
anti-pattern ("a guard that disagrees with itself … would be worse than no
guard at all"), here at privilege-escalation stakes. It also kills the
"extensible" requirement: you cannot add a beam-lisp predicate (e.g. one
reaching into a live =datom= db-value) to a policy evaluated inside Rust.

Why "fully compatible" is CHEAPER to build than to wrap: Biscuit ships an
adversarial conformance corpus (=biscuit-rust/samples/=, ~90 signed =.bc=
tokens + a JSON manifest of expected verify results). Compatibility becomes a
GREEN TEST SUITE, independent of implementation language. Passing all ~90 ⇒
compatible by demonstration.

* The security spine (the invariant every step must preserve)

Attenuation is MONOTONIC WEAKENING: appending a block can only ever RESTRICT
what a token authorizes — no append sequence grants a right the token did not
already carry. Three mechanisms, all must hold together:

1. Crypto append-only — each block signed by the previous block's key; edit or
   reorder breaks the chain (corpus: test004 random-block, test006 reordered).
2. Datalog block-scoping — a rule in an appended block, by default, trusts only
   facts from the authority block, the authorizer, and its own block. Appending
   adds CHECKS (=check if …=), never grants.
3. Checks fail closed — a failing =check if …= rejects the whole token.

Block-scoping is the ONE genuinely new evaluation rule. =datom.query.engine=
has no notion of fact ORIGIN today; =engine/origin.bl= is where it is added.

* Build order (waves — each ends at a runnable gate)

** Wave 0 — vendor the oracle + decide the origin seam  [gates everything]

- Vendor =biscuit-rust/samples/= (=.bc= files + README manifest) under
  =test/fixtures/biscuit-samples/= (or =priv/=). This is the conformance oracle.
- DECISION TO MAKE (first real fork, flagged in doc §5): fact-origin /
  block-scoping needs a hook in =datom.query.engine=. Two options:
  (a) add an origin-aware resolver hook to =datom= proper (a small, deliberate
      extension point — cleaner, benefits any datom user needing provenance);
  (b) a private origin layer inside =auth/engine/origin.bl= (no datom change,
      but re-implements part of the resolver).
  Recommendation: (a) if the hook is genuinely small and general; else (b).
  Resolve by prototyping the resolver touch-point before committing.
- Gate: sample files load; a written decision record for the origin seam.

** Wave 1 — crypto chain  [biscuit/crypto.bl]

- =keypair=, =public=, Ed25519 over =:crypto= (=:eddsa/:ed25519=, verified).
- Block signature chain: build authority, =append= (sign next key with prev
  secret), =verify= (walk root->authority->…->last, then proof-key match),
  =seal= (final-signature variant, no further append).
- Gate: round-trip build/append/verify in-process; a tampered block fails.

** Wave 2 — wire codec  [biscuit/codec.bl]

- proto2 encode/decode for the =schema.proto= message set. CANONICAL
  serialization is load-bearing: signatures are over serialized bytes, so
  re-serializing MUST be byte-identical to what was signed.
- Symbol table: blocks store strings once, reference by integer index. Keep
  symbols as TAGGED BINARIES (={:string, "read"}=) on the decode path — never
  intern on raw decode (atom-exhaustion; see hazards).
- Gate: decode every corpus =.bc=; re-encode is byte-identical; base64
  round-trips.

** Wave 3 — conformance green  [conformance.bl]  [the compatibility proof]

- For each sample: decode, verify against the given root key, compare decision
  to the manifest (Unauthorized / InvalidSignature / deserialization-error / …).
- Gate: ALL ~90 samples pass. Until green, "compatible" is a goal not a fact.
  THIS WAVE IS THE DEFINITION OF DONE for the Biscuit half.

** Wave 4 — datalog bridge + origin scoping  [biscuit/datalog.bl, engine/origin.bl, engine/expr.bl]

- Map Biscuit facts/rules/checks/policies <-> datom clause vectors.
- =engine/origin.bl=: tag facts with origin block, filter per block-scoping
  trust rules (authority + authorizer + own block by default; =trusting
  {public_key}= for third-party blocks).
- =engine/expr.bl=: the =OpBinary=/=OpUnary= operator set (=<,>,<=,>=,==,!=,
  contains, starts_with, ends_with, matches, +,-,*,/, &&, ||, set ops, length,
  negate) over datom's predicate-clause resolver.
- Gate: corpus cases that exercise expressions/sets/dates/scoped-rules
  (test007 scoped_rules, later expression samples) pass THROUGH the datom
  engine, not a parallel one.

** Wave 5 — the authorizer  [authorizer.bl, facts.bl, policy.bl]

- =(authorize db token request) -> {:verdict :allow|:deny :filter <clauses|nil> :why <facts/checks>}=.
- Biscuit decision semantics: ALL checks (token + authorizer) pass AND some
  =allow= matches before any =deny=; ordered, first-verdict-wins.
- =policy.bl=: ACL as datalog data; expose BOTH =:deny-overrides= and
  =:allow-overrides= orderings (the app picks; library does not bake one in).
- =facts.bl=: principal/resource/context fact constructors, datom-shaped.
- Gate: the doc §9.3 example runs; wrong-shaped request denies closed; =:why=
  names the deciding facts.

** Wave 6 — RLS  [rls.bl]

- Residual row-filter -> =:where= clause injection via =rewrite.bl=. The
  caller's query is spliced with principal-scoping clauses BEFORE it runs.
- Enumeration-safe: forbidden rows are ABSENT, never an error (the Ash
  filter-check semantics — filter, don't forbid).
- Compose with time-travel: filter clauses evaluate against whatever basis the
  caller holds; a grant scoped "current only" is expressible as a =basis-t=
  check. (doc §7.2.)
- Gate: doc §9.5 example — identical query returns only the bearer's rows;
  works against =as-of= views uniformly.

** Wave 7 — strategies + revocation  [strategy.bl, revocation.bl]

- =strategy.bl=: identity strategy = a FUNCTION =params -> authority-facts=
  (password verify, oauth-claims->facts, api-key = sealed token). NOT a
  behaviour module. (doc §9.6.)
- =revocation.bl=: optional online oracle. Nil ⇒ pure offline (TTL only).
  Provided ⇒ consult a revocation set. Revocations are FACTS in datom, so "is
  this revoked as-of T?" is a temporal query. Compare revocation-id BYTES,
  never base64 (non-canonical — spec warning). (doc §8, §9.7.)
- Gate: doc §9.7 + §9.8 gateway example runs end-to-end.

** Wave 8 — facade + docs  [auth.bl]

- =auth.bl= re-exports the public surface: =keypair/public/issue/encode/decode/
  attenuate/seal/authorize/policy/guarded-q/defstrategy/run-strategy/mint/
  revoke!/datom-oracle=. One require for a downstream app.
- Getting-started tutorial built from doc §9 snippets, each RUN.

* Hazards this repo already taught us (hard requirements, not nice-to-haves)

** Atoms — the VM-abort vector, now weaponizable

A token is the most hostile machine-generated input there is (crosses trust
boundaries by definition; attacker controls block contents). =docs/trust-boundary.md=
discipline is MANDATORY:
- keep token symbols as tagged binaries on decode; never intern on the raw path;
- materialize atoms ONLY at bounded intern sites, via =String.to_existing_atom/1=
  first (an unknown predicate name in a token is DATA that fails a check, never a
  new atom);
- =BeamLisp.AtomGuard= high-water sampling covers residual intern — a hostile
  token approaches a clean error, never a crash dump.

** Crypto construction risk is ours

Ed25519 via =:crypto= is audited C, but the CONSTRUCTION (canonical block
serialization, what-signs-what, the sealed-token final-signature variant) must
match exactly or tokens silently fail cross-impl. Mitigation: Wave 3 corpus is
the DAILY gate — divergence shows up as a red sample, not a production incident.

** Spec drift

Pin =biscuit-auth "6.0"= / block version 3. Vendor the samples. Treat a spec
bump as a normal dependency update (same discipline =mix.lock= imposes).

* Definition of done (foundational layer)

1. Wave 3 green: all ~90 conformance samples pass — Biscuit is wire-compatible
   BY DEMONSTRATION.
2. Waves 4-6 green: token checks and RLS =:where= run through the SAME datom
   engine (no second datalog).
3. Wave 8: =auth.bl= facade + a getting-started tutorial where every §9 snippet
   runs.
4. Attenuation-is-monotonic invariant holds (corpus tampering cases + a
   property test that no append grants a new right).
