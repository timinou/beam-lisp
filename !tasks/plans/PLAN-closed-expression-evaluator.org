#+TITLE: Closed expression evaluation for model-written cells
#+DATE: 2026-10-14
#+STATE: SDK ACCEPTED / APPLICATION ACCEPTANCE PENDING

* Goal
Replace inherited compiled evaluation with an SDK interpreter for a documented
expression subset. Never compile source, create a namespace/module, resolve an
ambient var, or invoke a user-defined macro. Applications supply only explicit
approved host operations and their existing trusted context binder.

* Boundaries
Read reader-node AST without keyword interning: existing atoms only; unknown
keywords refuse and callers can use string keys. Resolve callable names through
fixed reviewed SDK primitives and the explicit operation map. Lexical bindings
must refer to interpreter values, not Env vars. Quoted symbols remain inert data.

Bound source bytes, reader/tree depth and width, interpreter steps, collection
size, stdout/result bytes, process heap and wall time. Use proc.fence's owned
worker and automatic generation retention. Capture output in bounded interpreter
state, not StringIO. Refuse opaque/forged host args/results before any protocol
dispatch, including functions, pids, refs, native runtime descriptors and fake
structs. Closures/regex/lazy sequences are worker-owned internal capabilities.

* Initial compatibility target
The actual Knowledger offline agent harness uses arithmetic, borrowed +, let,
println, loop/recur timeout, keywords/maps/vectors/quote, count/boolean/vector,
regex literals/re-pattern/re-find/re-seq, string replace/upper-case and format,
plus its 11 public kn operations. More vocabulary in its prompt (map/filter/
reduce/group-by/frequencies/sort-by) must be implemented explicitly or refused;
do not imply a complete Clojure evaluator.

Maintain demand-driven sequence semantics: map/filter may contain approved host
calls, so eagerly evaluating the entire input before take would introduce extra
external effects. Native lazy callbacks are not imported into the interpreter.

* Separate host operation obligation
An explicitly approved operation may itself interpret data as code. In particular
kn/query and generic kn/call pass Datalog queries to library/query. The existing
query resolver must independently reject unauthorized predicates/functions; a
closed expression evaluator is not proof of safety inside a trusted host service.

* Validation
Inherited slurp/spit, globals in every collection/map-key/value position, inert
quote, dynamic names, malicious host return descriptors, atom/code growth over
repeated runs, deadline/heap/stdout bounds, lazy host-call counts, actual tenant
context and old graph retention. Native validation runs serially by root; no
production deployment. Keep unsupported syntax and remaining gates explicit.

* Implementation
The SDK exposes eval.closed/check and run. The checked reader-node tree is
interpreted directly; callable lexical values are private worker-owned
capabilities, never inherited Beam Lisp functions. Reviewed primitives are a
fixed explicit dispatcher. Ordinary variadic functions work; recur in variadic
functions, destructuring and unimplemented forms deliberately refuse. Regex
values and demand-driven, memoized sequence nodes cannot cross host boundaries.
The host table and optional trusted binder are the entire application adapter.

Shared data.first-order/check! validates arguments/results and final output by
raw native shape, without protocol dispatch. Error diagnostics also use only
raw fields and bounded scalar text; arbitrary thrown details never escape and
Exception.message/Inspect callbacks never run on untrusted thrown values. Unknown
effectful host operations retain submitted state until a safe result arrives;
throw, opaque result, deadline and child kill report operation-uncertain.

The first native acceptance run exposed borrowed vector/take-nth helpers absent from the default core/sugar prelude;
explicit closures/base operations replace them. Direct reductions also replace
fnil (which is available through sugar).
A permanent system.ir audit walks actual compiled definitions and checks every
global binding with the compiler-selected exact/fallback lookup. An intentionally
unbound compiled value is its positive control. This is dependency evidence,
not a formal effect or safety proof. Runtime fixtures remain the acceptance gate.

* Pending acceptance
Root reruns the focused evaluator and real application cells in one serial VM.
Fixtures cover the existing agent vocabulary, lazy host-call counts, bounded
resources, host exceptions/opaque values, no atom/module growth over repeated
runs, tenant binding, and actual prepared-graph retention through retirement.
No production deployment or unsupported-language compatibility is claimed.

* Worker state and scaling
All private counters, stdout and capability registries now reside in the owned
worker's process dictionary. Persistent maps stay on the process heap and update
structurally, instead of copying the full registry through native OwnedEnv on
each lookup/update. This removes quadratic retained-map copy work and native
closure/cell cycles, and puts retained model state under the worker heap ceiling.
Only the parent's bounded submitted-operation marker uses a shared atom, so
timeout/worker death can still report uncertainty. Runtime benchmarks compare
the saved native-cell implementation and this one in the same serial sandbox VM.

* Lost-result uncertainty
A verified intermediate write does not prove the final cell response arrived.
The parent keeps the last unknown/effectful-operation marker until successful
whole-cell completion. Later reads cannot overwrite it. A pure tail failure,
deadline or lost final reply after that operation reports uncertainty and must
not trigger replay. Effect metadata is normalized to the closed :read/:unknown
enum before it enters the bounded shared marker; arbitrary configured values
never escape into that state or execute as policy callbacks.

* Native acceptance (2026-10-14)
Root core-04 accepted all250 evaluator assertions, including actual compiler
global-binding audit and its negative control, raw exception data refusal,
real native worker leases, tenant context, step/stdout/deadline/regex limits,
process heap and shared-binary accounting, demand-driven host effects, and
completed-write/lost-final-result uncertainty. Cache11, inventory10, macro32,
constructor-boundary16 and clause35 also passed. Whole batch3m43.503s wall,
4m2.952s CPU,469.7MiB peak and zero swap; it was not wholly green because the
supervisor factory fixture omitted its explicit SDK/native dependency grants.
The application adapter and real agent fixtures remain a separate gate.
Controlled same-VM registry benchmark and application endpoint acceptance are
pending; no throughput ratio or production sandbox guarantee is claimed.
