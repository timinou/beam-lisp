* Problem and design
A fixed SDK server class is outside an application's sealed module graph. It must
not retain an obsolete whole application graph merely to own a queue, and must not
be invisible to application owner inventory or survive its initializer forever.
An application class being global or outside that graph does not make it SDK code.

Use compiler-produced executable evidence, a stable SDK runtime lease, one exact
class lease per framework actor, and separate application lifetime membership.
Accepted job callbacks continue to retain their exact application code/context.
No application-specific actor wrapper, native allowlist, synthetic generation,
namespace-prefix permission, or manual developer-maintained inventory is added.

* Compiler and package producer
- AOT finds only the canonical compiler-generated lower/reload-descriptor! call
  defining this exact namespace/name's server module. Module-shaped literal data
  is never scanned as executable provenance.
- Emit the class alongside namespace, body and initializer companion artifacts;
  normal build manifests and v2 cache SHA256 digests now include its bytes.
- Class attributes bind namespace/name, actual compilation input SHA256, source
  closure key and compiler key. Initializer replay checks executable MD5 and uses
  the ordinary class artifact before considering descriptor compilation.
- AOT publishes source-mode evidence only after the complete successful unit,
  under the SDK's global definition environment, and only when the actual input
  equals the physically resolved SDK source. Symlink escapes and claimed filename
  inputs do not gain ownership. Cache/build receipt recovery never reruns source.
- Selfbuild derives deterministic priv/sdk-code.term from its authoritative
  manifest, validating source input stamps, module identities, bytes and duplicate
  ownership. Paths are relative to the SDK root. Module identities serialize as
  binaries so safe decoding does not intern an unverified inventory's atoms.

* Native framework boundary
- Adoption authenticates the actual generated init frame immediately before
  gen_server, not the forgeable initial_call process-dictionary entry.
- Verify class executable MD5 against compiler/image evidence, exact declaration
  namespace/name and its actual SDK-owned global binding before changing context.
- Preserve app identity in an explicit conveyed field; use the authenticated SDK
  definition context for steady code. Clear the old app generation, admission,
  closed query context and app loader/OS overlays from the framework actor.
- Pin SDK code once in the existing Env process; each actor adds one class lease.
  SDK replacement is a separate runtime handover boundary. Shared SDK inventory
  is limited to 8192 modules; native ledger capacity still bounds admission.
- Shared lease publication executes inside Env's existing Agent and catches
  failures into a tagged reply. Caller death cannot orphan a transferred lease;
  a capacity error must not crash Env. Recheck executable identities under physical
  module locks. An old live SDK identity cannot silently become a different one.
- Monitor the explicit initializer and refuse dead-owner admission. proc.dispatch
  stops on that exact DOWN, retains independent accepted workers as before and
  releases native/index ownership on exit. App-owned classes already in g.modules
  keep ordinary whole-generation ownership; unbound development stays ordinary.

* Inventory and application integration
- proc.framework supplies adopt/alive/down/close and native read-only evidence.
- The existing monitored owner-index row is also the ONLY native framework
  evidence record. No separate provisional PID map can leak if a process dies
  between native preparation and registration. The collector independently
  authenticates the actual waiting generated-init process and SDK artifact.
- proc.owner-registry gains an authenticated :framework role, with exact class
  ticket and application/initializer identity. Regular app registration cannot
  claim this role through its existing register! API.
- proc.inventory reports :application-lifetime capability for that proven role.
- proc.instance reads the explicit application identity when generation is nil.
- The existing SDK dispatcher adopts automatically after obtaining its declared
  instance table and initializer. Knowledger's ordinary resource/name options
  remain its only integration; no app-only deployment machinery is introduced.

* Runtime boundary
Actor close and application-generation retirement do not release the shared SDK
lease. SDK replacement is a separate runtime handover; outstanding accepted native
tasks must drain before terminating the old VM. This implementation does not claim
live SDK replacement safety from an admission-time active-handle check alone.
=Env/sdk_runtime_retained_modules?= exposes only read-only executable evidence,
never the shared release/transfer capability.

* Mutable export surfaces and immutable executable authority
- Isolated producer/role/actual-instruction proof accepted: 26 assertions,
  106.073s wall, 106.262s CPU, 300.4MiB, zero swap (parent batch 16).
- Every new AOT artifact has a compiler-owned role: stable body, initializer,
  generated actor, or mutable namespace forwarder. Image inventory format 2
  records full artifact SHA/input/owner/role provenance separately from leases.
- Stable bodies, initializers and actors are retained once by Env. A native
  generated-code publication that changes their executable MD5 refuses before
  any load, even if it would otherwise fit the BEAM's two code generations.
- Mutable namespace surfaces are not retained as whole immutable modules.
  Their original SDK export routes are checked from actual BEAM instructions.
  The finite symbolic checker permits argument save/restore and the exact
  readiness guard, then an unchanged-argument tail call to the attested body.
  Branches, changed destinations, argument swaps and arbitrary effects refuse.
  Additional unrelated exports are allowed; no Core/Rt namespace exemption.
- Publication checks all changed members before loading any. After a compatible
  shim load it records only first-order routes and actual loaded MD5, bounded by
  the authoritative SDK module inventory. It does not store callbacks or PIDs.
- Root's actual shim disassembly confirmed both plain Core/Rt forwards and the
  guarded proc.attempt save/readiness/restore sequence. The isolated fixture
  verifies emitted artifact roles and actual positive/negative instructions.

* Source startup without a whole-SDK prerequisite
- Reuse the authoritative bootstrap seed manifest and actual loaded SHA/MD5 for
  initial boot/native dependencies. Derive bootstrap shim roles from their
  actual executable surface and compiler-owned namespace owners.
- Completed source/cache SDK units publish full compiler receipts automatically;
  declarations cannot claim trust from a path or module prefix alone.
- Follow actual emitted imports and resolve a missing SDK dependency only via
  its authoritative seed or complete source/cache unit receipt. A physical SDK
  source path merely selects evidence discovery, never grants authority.
- Cached unit receipt publication precedes initializer replay. Lazy units extend
  an existing Env-owned SDK proof before their executable consumers can run.
- Existing retained class membership makes subsequent framework actor admission
  cheap: no repeated whole-SDK verification per actor. New source unit completion
  refreshes the single shared lease, rather than making another graph per job.
