* Goal

Bring the reader's four contracts (options-as-value, span, failure-as-value,
one-loop-two-views) to `priv/std/proc/super.bl` — supervision trees as data —
so a supervision failure renders like a type warning instead of a BEAM tuple.

Design + evidence: `research/supervision-contracts/README.md`.

* Why (the gap, from the source's own words)

`super.bl` says its state is "the child set AND THE RESTART LEDGER — both of
which OTP keeps for us", but `children` returns only the child set and admits
"OTP does not expose per-child restart counts". So the declared policy
`(intensity 3 5000)` — 3 restarts per 5s, then give up — is enforced but never
REPORTABLE. A policy nobody can read back cannot be tested, alerted on, or
explained after an incident.

* The three diagnostic vocabularies (converge them)

- reader (now): `{:bl_diag true :kind :msg :line :col :offset :end-line
  :end-col …}` — errors.bl-compatible
- checker (`typed` + `errors`): `{:msg :line :col :end-line :end-col :form}` +
  caret — the best one, and the target shape
- supervisor / OTP: `{:EXIT, pid, reason}`, `{:badmatch, …}`, SASL lines — an
  L12 violation in the user's face

* Change list (ordered; each independently verifiable)

1. `(proc.super/events s)` -> the stream (`[:ok event sidecar']` / `[:eof …]`,
   the `read-next` shape), sidecar process, filters by `:id`.
   Accept: one induced crash -> exactly one `:child-exit` with `:id`,
   the failing incarnation's `:pid`, `:reason`, and running `:restarts`.
2. `(proc.super/ledger s)` -> `{:id {:restarts n :window ms :last-reason r
   :last-at ts}}`, from OUR counters. Accept: after k induced crashes the
   reported count is k with no OTP introspection.
3. `(proc.super/render s event)` -> delegate to `errors/render`.
   Accept: the caret layout is byte-identical to a type warning at the same
   position; `(errors/delaborated? out)` is nil (no `{:badmatch` reaches a human).
4. `typed` evidence in the event: an event whose `:where` is a call site with
   `:ann` and whose args are in the evidence table renders with the argument
   types. Accept: "called with n arguments — a <type> takes <arity>".
5. The intensity event: the 4th crash in a 3-per-5000ms window emits
   `:intensity-exceeded` BEFORE the tree gives up.

* Measured facts already in hand

- Macro arguments carry NO positions: `(child :acct account 100)` reaches
  `defsupervisor` as a bare form (measured with a printing macro). So a tree
  clause cannot stamp a span; the event's `:where` must come from the runtime's
  `:ann` — the same channel `errors/node->warning` and `typed/eff-pos` read.
- The tree's `proc.super` DOES load from source: `./bl -p priv/std run` ->
  "proc.super loaded: true".
- Whether a tree can be STARTED in this venue is NOT established: the probe
  referenced `BeamLisp.Supervisor` as a value instead of calling it, so it failed
  for a probe reason. Step zero of item 1 is settling that.

* Scoping rule (do not repeat BUG-041)

`typed`'s state is per-PROCESS in the process dictionary precisely because
VM-global atoms made one check's warnings land in the next caller's report
("phantom diagnostics"). A restart budget is a safety mechanism: a VM-global
ledger would attribute one supervisor's restarts to another's and make trees give
up early or never. Copy typed's `state-key`/`ambient-key` split; do not reinvent.
