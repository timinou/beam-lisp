The five load-bearing invariants (all reproduced in bl, none dropped):
- ONE CRATE ↔ ONE NAMESPACE: rustler::init! names the host module at compile time
  (`Elixir.BeamLisp.Native.Datom.StoreFjall`), so the host-module name is a CONTRACT.
  native.bl MUST derive the identical name (`ns → BeamLisp.Native.<CamelSegments>`), or
  the crate's exported module name won't match and load_nif returns {:bad_lib}.
- KEBAB↔SNAKE: var keeps `compare-and-swap`; NIF fname is `compare_and_swap`.
- ABSENT = ABSENT: no toolchain → on_load fails → available? false → calls raise. Never
  present-but-degraded.
- DECLARE IS A VM-WIDE CRITICAL SECTION: `:global.trans({host_module, self}, …)` guards
  two envs racing host publication. native.bl MUST keep this (call :global.trans).
- THE DECLARATIONS TABLE OUTLIVES ITS DECLARER: owned by the pinned Loader.Server, else a
  parallel-build worker's exit drops the AOT replay silently (BUG-021). native.bl's ETS
  table MUST be created inside `BeamLisp.Loader.Server/run` (bl-callable) exactly as now.
Plus two guards: no duplicate name (one var = one arity), no core-shadowing (a native
`get` poisons the ns).

* The design — the `native` public namespace (priv/std/native.bl.md)

Maximalist + clean: ONE namespace, capability-first. The verbs read as questions and
declarations, not plumbing.

Declaration (defnative lowers onto declare):
- (native/declare ns crate signatures) → host-module. signatures = list of [name arity].
- (native/host-module ns) → the BEAM module atom for ns (THE contract with rustler::init!).

Capability:
- (native/available? ns) → bool, never raises.
- (native/declaration ns) → {:crate c :sigs [[n a]…]} | nil.
- (native/declarations) → [{:ns … :crate … :sigs …}] (what AOT replays).

Build (folds native_task + cargo):
- (native/build! crate) → cargo build one crate → installed .so; returns path | error.
- (native/build-all!) → discover priv/native/*/Cargo.toml, build each (skip fresh).
- (native/fresh? crate) → mtime: is the .so newer than every source? (skip cargo?).
- (native/lib-path crate) → resolve .so across loaded apps (consumers first, beam_lisp last).
- (native/installed-path crate) → priv/native/<crate><nif-ext>.

* The private arch — the substrate shim (priv/std/native/host.bl OR inline in native.bl)

The ONLY irreducible substrate, ~30 lines, three BIFs bl already calls:
- module synthesis: build the host descriptor via anf/module (load-clause with an
  erlang/load_nif body + a __nif_loaded__ predicate + one nif_error stub per signature),
  compile via lower/descriptor->beam, install via code/load_binary. (The spike is the
  exact template.)
- the on_load body: `(erlang/load_nif (charlist lib-path) 0)` with a case that on {:error,r}
  calls a bl warn (native/nif-load-failed) and otherwise returns the load result.
- availability: `(code/ensure_loaded mod)` + calling `mod:__nif_loaded__()` (stub raises,
  real returns true) inside try/catch.

NB the host module has TWO reserved fns beyond the stubs: `__load__/0` (the on_load target,
calls load_nif) and `__nif_loaded__/0` (a stub the NIF overwrites to return true). Both are
in the spike.

* Bootstrap ordering (the one care item — clean-D)

native.bl depends on: anf, lower (both priv/boot, load first), erlang/*, System, code/*,
BeamLisp.Loader.Server, BeamLisp.Tiers, :global. All available at the boot/std tier. native.bl
lands in priv/std/ (NOT priv/boot — it is not needed to build the compiler; the defnative MACRO
is in the compiler, which only EMITS a call resolved at the consumer's load time). The first
defnative CONSUMER is lib-tier (wry/store-fjall), which loads long after std. ∴ native.bl must
be loadable by the time ANY defnative ns loads — guaranteed because ensure_loaded pulls it as a
dep. Add `(:require [native])`? NO — defnative is a macro; its EXPANSION references native/declare,
so the consumer ns must have native loaded. The compiler's defnative expansion MUST ensure-load
native (add `BeamLisp.Loader/ensure_loaded "native"` to the emitted init, or make the emitted
call self-loading). VERIFY this in the corpus step: a cold VM running `bl run wry-consumer.bl`

* Verification — what to enshrine

- UNIT (test/bl/native/): declare→available? round-trip against a real crate; absent→false;
  duplicate-name guard raises; core-shadow guard raises; host-module name equals the
  rustler::init! contract for the four consumers (golden: derive the name in bl, assert it
  equals the string each crate's src/lib.rs exports).
- PROPERTY (veritas): kebab↔snake is a round-trip bijection on valid identifiers;
  host-module naming is injective on distinct ns.
- REGRESSION: the corpus — wry.bl, datom/store-fjall.bl, datom/vector.bl, code/embed.bl load
  and available?-gate identically pre/post. A cold-VM `bl run` of a NIF consumer works.
- GATE: the allow-list test (S6 mechanism) fails on any BeamLisp.Native reference under lib/.

Kinds of verification and their honesty: declare/available?/guards are DETERMINISTIC unit tests.
kebab↔snake + host-naming are PROPERTY laws (pure functions). NIF actually loading + calling is
INTEGRATION (needs the .so built) — witnessed, not proven. The one thing NOT formally verifiable:
that a future crate's rustler::init! matches native.bl's derived name — that is a runtime contract
(load_nif returns {:bad_lib} on mismatch), so the test is: build fails loudly, never silently.

* Risks

- The host-module NAME is a compile-time contract with rustler::init! in each crate's Rust
  source. If native.bl's derivation differs from native.ex's by even one char, EVERY existing
  crate fails to load with {:bad_lib}. Mitigation: port host_module/1 CHARACTER-FOR-CHARACTER
  (String.split "." → Macro.camelize(replace "-" "_") → Module.concat [BeamLisp.Native | segs]);
  golden-test it against all four consumers BEFORE deleting native.ex.
- The declarations ETS table lifetime (BUG-021). native.bl MUST create it inside
  Loader.Server/run, not in the calling process. Test: declare from a spawned process, then read
  the declaration from the parent — it must survive.
- on_load attr shape (found in the spike): value is a LIST [{fname,arity}]. A bare tuple crashes
  the Core compiler. Locked in the spike; keep it.
- AOT replay shape: aot.ex must emit a call to the bl native/declare at the SAME init position
  the current Emit.remote(BeamLisp.Native,:declare) lands, or a replayed module loads without its
  native backing (BUG-021's exact class). Test: `bl build` a defnative ns, load the .beam in a
  fresh VM, available? is true.
- Where defnative expansion ensure-loads native.bl: if it doesn't, a consumer ns compiles but
  native/declare is unresolved at its init. Verify with a cold VM.
