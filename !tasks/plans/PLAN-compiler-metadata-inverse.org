* Preserve intentional callable state during SDK materialization
Expanded declarations now retain an independent final callable kind alongside
privacy. Exact old-function equality alone is insufficient: a final private or
per-environment value may intentionally store that exact function. Rebinding
requires both a final function declaration and an exact original linked value.
Old four-argument declaration producers remain compatible but grant no final
function kind. Unknown Env overwrites invalidate both indices.
Fresh initializers bind final functions to stable providers, while preceding
function definitions needed by final value/macro/class initialization retain
their original ordered semantics. Six materializer cases now expect80assertions;
these additions are native UNRUN. The per-env test captures the preceding fn
under a distinct remembered binding and forces the original per-env instance;
a direct self-initializing per-env definition would be an invalid fixture.

An SDK value initialized earlier as a partial of a private namespace-shim fn is
a separate compatibility issue: preserving state preserves its old private
capture too. Canonical SDK emission before first initialization is being
implemented for an actually verified current compiler. No initializer replay
or ambient private-MFA exception will be used to conceal that issue.
