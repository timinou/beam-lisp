Key property enabled by beam-lisp-on-phone: the SAME scoring ns runs both sides. Phone computes → sends only score+explanation. Desktop can RPC the phone for recompute/history. Raw health data never traverses the network and is never persisted (ETS only on phone; only computed score persisted on desktop).

* W1 spike RESULT (2026-08-11) — resolved, maximally favorable
- render/1 returns a PLAIN MAP component tree: %{type: :column, props: %{...}, children: [...]}. The ~MOB sigil is only sugar over this data. beam-lisp builds these trees natively (bl maps/vectors, keyword keys → atoms) — screens are 100% writable in .bl, zero sigil port, zero interop for UI.
- Mob.Screen contract: supervised GenServer per screen, Mob.Socket state; callbacks mount/3, render/1, handle_event/3 (event::String.t, params::map, socket), handle_info/2; optional terminate/2, screen_key/1, dump_state/load_state (persistence opt-in).
- Thin shim (the ONLY Elixir in app): `use Mob.Screen` per screen + defdelegate mount/render/handle_event to the .bl-compiled module (~6 lines/screen), plus the Mob.App entry module. `use` = Elixir macro injection (GenServer wiring + behaviour) — cannot be expressed in beam-lisp; defdelegate is the guaranteed-thinnest path. Stretch: inspect __using__ expansion in W2 for a 0-line pure-.bl screen.
- Tap handlers are {pid, tag} tuples — constructible from bl via (self).
- Env note: mob_new archive + Elixir 1.19+ + Java 17-21 + Android SDK/adb required on this machine; phone needs Developer Options + USB debugging + File Transfer mode. Deploy: mix mob.deploy --native --android.
