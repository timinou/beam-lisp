* Observed
A required namespace file with ONE unbalanced paren kills the VM with exit code 141 (SIGPIPE) and ZERO output on stdout or stderr — no parse error, no file:line. Reproduced 2026-09-18: priv/lib/gen/code.bl missing a single closing paren in one defn; `bl run` of any file requiring it exited 141 silently. A trivial file without the require ran fine; fixing the paren fixed the run.

* Expected
The reader/loader reports "unclosed form at line N" (the information is trivially available — a 20-line python paren scan located the exact form) and exits non-zero with a diagnostic.

* Impact
Cost ~15 min of bisection (stderr redirect, dmesg, trivial-file contrast) to distinguish "my file is malformed" from "the VM crashed". Any hand-edited .bl can hit this.
