* Proposal and intent

User asks what to do with the successful fusion experiment and wants a bold direction. Proposed next feature, not yet implementation authorization: make pure bounded data regions an ordinary compiler execution unit. Users write BL; semantic analysis determines fusion/representation and a runtime planner chooses generated BEAM or a resident native worker. All frontend analysis, region IR, orchestration, cost selection, diagnostics and tests are BL. Existing native backend remains a small mechanism. Do not introduce native-map/fast-reduce parallel APIs or move the whole RT into native code.

* Target architecture

One BL region descriptor records operations, input/output sorts and layout, effects/exception behavior, numeric semantics/ranges, bounds, cardinality, reduction order, ownership/escape and dependency versions. It must describe a general small fragment rather than compare against one frozen descriptor. Shared admission returns a verdict with reasons; backend capability is separate from language meaning. The generic BL implementation is reference/fallback; generated BEAM is the baseline optimized execution; resident native workers handle profitable sufficiently large admitted batches. Cost includes queue delay, boundary copies, output size and cold compilation. A worker queue is bounded; unprofitable/busy/unavailable routes use BEAM. Only fully pure regions permit replay after a worker failure. Compiled artifacts/cache entries keyed by region hash, semantic/representation version, compiler/backend version and CPU features. Descriptor changes and redefinitions invalidate dependent artifacts, not every module. No opaque raw executable pointers exposed to BL.

* Sequence and acceptance

1. Region extraction + generated BEAM: recognize a limited set of known/resolved map/filter/reduce and counted-loop forms in ordinary BL. Explicit byte/typed input views where required. Reuse ANF/Core. Refuse unknown/effectful callbacks; preserve evaluation/exception/early-termination order. Ordinary + remains exact: range proofs or declared numeric semantics are required for unboxing, never silently introduce u64 wrapping. Gate: unmodified source pipeline produces a visible region and no intermediate collections, with generic-vs-generated equality/refusal/effect tests.
2. Shared native lowering: region IR consumes existing arithmetic/native lowerer machinery, one verdict rather than separate copies. Generalize constants/composition inside the supported pure total fragment; do not add floats/GPU/general collection mutation yet. Gate: generated BEAM/native crosschecks on randomized inputs and malformed boundary tests, both derived from same region.
3. Managed resident worker + dispatch: BL-owned supervision, lifetime, bounded queue, warm code cache and cost decision. Start conservative, including cost of conversions and materialized results. Gate: small workloads stay BEAM; large profitable ones use native; queue pressure/worker death never corrupts state or causes effect replay. Timed whole-call distributions and multi-client responsiveness, not kernel-only timing.
4. Real consumer: first ordinary typed-byte pipeline; then evaluate one datom filter/aggregate on a typed batch. Preserve nil/grouping/overflow/ordering and count packing cost. Do not claim current datom relations are columnar or coerce arbitrary values into packed integers. Gate: existing query result and error suites plus end-to-end workload improvement.
5. REPL explanation and cutover: expose region boundaries, semantics, selected representation/backend, refusal reasons, code-cache dependencies and measured costs. Proposed UX must use actual analyzer verdict, not an independent registry. Deprecate/migrate overlapping offload entry paths once replacements cover their use cases; retain fixtures as tests. Gate: editing a referenced pure function invalidates/rebuilds only affected region; native crash falls back for pure input; no parallel production implementation remains.

* Non-goals and bold end-state

No immediate full RT rewrite, no immediate NIF host, no new Elixir/Python orchestration, no universal4KiB threshold, no promises that arbitrary collections/effectful lazy pipelines fuse. End-state: RT remains semantic reference and dynamic fallback while proven hot regions do not traverse it. The query planner and ordinary compiler can emit the same region language, avoiding separate query/collection/native optimization stacks. Native and BEAM are execution decisions, not user-facing dialects. Full self-hosted RT/seed work remains a distinct correctness/dependency cutover, not a prerequisite for harvesting fusion.
