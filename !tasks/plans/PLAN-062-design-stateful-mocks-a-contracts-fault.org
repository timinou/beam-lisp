* Intent

The mock stack (=priv/mock.bl= + =priv/mock/fault.bl=, docs
=docs/a-contract-is-a-mock.md=) mocks ONE response: a contract is a predicate
over fields, a fault is a value that breaks a clause, all stateless. Most APIs
worth sandboxing are STATEFUL — a cart, a login session, a payment flow, a
rate-limited key. The bug that matters lives in the SEQUENCE ("you called
=/checkout= before =/add-item="), not in any single reply.

This plan extends the same idea to stateful mocks by REUSING the guarantee
engine beam-lisp already ships (=priv/system/core.bl=, =priv/system/model.bl=),
which was built to VERIFY state machines and can be driven BACKWARD to GENERATE
faulty sessions — exactly the forward/backward duality that made the stateless
mock work.

  stateless mock : contract          = predicate over ONE response
  stateful  mock : transition system = states + guarded transitions + an
                                        invariant over the whole run

The object under mock becomes a transition machine; a "fault" becomes a
transition that BREAKS the invariant; and the fault SPACE becomes the set of
REACHABLE such transitions, analysed with the same datalog the stateless tool
already uses (coverage anti-join, redundancy grouping, independence).

* Why this is an EXTENSION, not new theory (the mapping)

Every right-hand primitive already exists and is PUBLIC in system.core /
system.model. The work is a shape + a bridge, not new machinery.

| stateless (built, priv/mock/fault.bl) | stateful (this plan)                        | exists today                         |
|---------------------------------------+---------------------------------------------+--------------------------------------|
| error-for — value breaking clause i   | broken transition from preserves? :model    | ✓ preserves? returns {:preserved :model} |
| errors — catalogue per clause         | every invariant-breaking transition          | ✓ prove-box walks all transitions    |
| coverage anti-join (untested laws)    | untested REACHABLE bad states                 | ✓ shipped REACHABLE rule + not-join  |
| redundant-mutants (same violation set)| same lasso / same corrupting path             | ✓ find-lasso, phase-analysis         |
| independent-laws (breakable alone)    | unhandled-messages, nondeterministic-pairs    | ✓ both in system.core                |
| satisfiable? (spec realizable)        | verify-liveness (goal always reachable)       | ✓ AF least-fixpoint (system.gfp)     |

VERIFIED during design (measured, not assumed):
- =sys/prove-box port inv "items" decls "0" transitions= returns ={:holds
  :failures}=; a failure carries =:model= = the concrete z3 counter-model, e.g.
  for an UNguarded cart =remove= the model was =items=0, items2=-1= — the exact
  state+input that corrupts the session. This is the stateful =error-for=.
- =system.model/REACHABLE= is a shipped datalog rule
  (='[[(reachable ?a ?b) [?a :edge/to ?b]] …]=); magic-set demand propagation
  (=priv/datom/query/magic.bl=) and coverage anti-joins already run over it.
- =prove-box=, =preserves?=, =establishes?=, =candidates=, =abduce=,
  =repair-transition= are PUBLIC and take STRING-level args (inv as a fn
  name→SMT, guard/next as SMT strings) — so the engine drives from a DATA shape
  with no source form required.

* The three things this unlocks (that stateless cannot)

1. Adversarial SESSIONS, not values. "Give me the shortest reachable sequence
   of calls that drives the session into a contract-violating state" =
   find-lasso reading the fault space backward — a generated attack PATH. Tests
   "can a client corrupt my session by calling things out of order?" without
   hand-scripting the order.

2. Provably-sandboxed stateful hostility. The mock is a VERIFIED machine, so an
   injected fault is guaranteed to be one the real server's contract also
   forbids. Maximally hostile (replay, reorder, race) while every hostile move
   is a move the contract already declared illegal — and it runs in an env
   without egress, so the adversarial session provably never reached production.

3. The redundant-law finding, for protocols. Stateless caught a dead LAW
   (=temp>=-50= implied by =temp>=-40=). Stateful analogue: verify-liveness +
   phase-analysis catch DEAD STATES (a status the machine declares but can never
   enter) and STARVATION LOOPS (a cycle that never reaches the goal). Same "the
   fault space tells on the spec" move, now over the state model — before the
   server is written.

* The contract shape (new surface)

A stateful contract is a VALUE (mirrors the stateless {:fields :ensures}),
carrying transitions and a state invariant:

#+begin_src clojure
(def cart
  {:state     [["items" "Int"]]              ; state vars + z3 sorts
   :init      "0"                             ; initial state expr (per var, ordered)
   :invariant "(>= items 0)"                  ; the law over the WHOLE run
   :transitions
     [{:label :add    :guard nil          :next "(+ items 1)"}
      {:label :remove :guard "(> items 0)" :next "(- items 1)"}]})
#+end_src

- =:state= / =:init= / =:invariant= / =:transitions= are the FOUR fields
  system.core's prove-box already consumes (it takes inv-fn, svar, decls, init,
  transitions). The bridge is a thin translator, NOT a re-implementation.
- Multi-var state is the R2 joint case prove-box/verify-process already handle;
  Phase 1 targets single-var, Phase 2 lifts to joint (the engine already does).
- =:invariant= / =:guard= / =:next= are beam-lisp prefix predicates =
  valid SMT-LIB (same as stateless :ensures), translated through system.smt —
  the SAME translator the verifier uses, so mock and checker never disagree.

* Phase 1 — the bridge + a valid stateful mock (KEYSTONE)

** Build

1. =to-model [contract]= → the arg bundle prove-box wants: an inv FN
   (svar-name → SMT via smt/of-source over the invariant), the svar, the decls
   string (declare-const per state var), init, and transitions with guard/next
   already SMT (translate through smt/of-source; drop :untranslatable, honest).
2. =verify [port contract]= → wrap sys/prove-box; returns {:holds :failures}.
   This is the FORWARD check — does the machine preserve its invariant.
3. =synth-session [port contract n]= → a VALID run of length n: fold the
   transitions from init, at each step asking z3 (via mock/synth over a
   one-shot contract whose ensures = invariant ∧ the chosen transition's next)
   for a concrete next state. Deterministic-seedable like mock/synth-seeded.
   The stateful sibling of mock/synth — a legal session the mock can serve.

** Acceptance

- =verify= returns :holds true for a guarded cart, false for an unguarded one,
  and the false case's :failures carries the counter-model state.
- =synth-session= produces a length-n sequence of states each satisfying the
  invariant, reproducible under a fixed seed.
- Demencoded in examples/mock/04, prints green (:ok).

* Phase 2 — the stateful fault space (the payoff)

** Build

1. =broken-transitions [port contract]= → every transition whose preserves? is
   false, each with the z3 counter-model = the (state,input) that breaks it.
   The stateful =errors= catalogue, keyed by transition label.
2. =error-session [port contract label]= → a REACHABLE sequence init →…→ the
   state where transition =label= breaks the invariant. Uses REACHABLE
   (system.model) over the transition graph to confirm the bad state is
   actually reachable; returns nil when it is not (a dead fault — do not test).
   The stateful =error-for=: an adversarial session wrong for one NAMED
   transition.
3. =attack [port contract]= → the SHORTEST reachable error-session across all
   broken transitions (find-lasso backward). The generated attack PATH.

** Datalog analysis (reuse the fault/*.bl pattern verbatim, over transitions)

Load the transition graph + broken-transition facts as datoms
(schema: =:state/tag=, =:edge/from=, =:edge/to=, =:break/label=,
=:break/at-state=), then:
- =unreachable-breaks= — broken transitions whose precondition state is NOT
  reachable from init (a not-join over REACHABLE) = dead faults, do not test.
- =reachable-breaks= — the real session bugs; the test targets.
- =dead-states= — declared states unreachable from init (verify-liveness /
  phase-analysis): a spec finding, like the redundant law.
- =starvation= — a cycle that never reaches a goal state (system.gfp/af): a
  livelock in the API's own state model.

** Acceptance

- broken-transitions on an unguarded cart names =:remove= with a counter-model.
- error-session :remove returns a reachable sequence ending in items=0 then the
  illegal remove; returns nil for a transition whose break-state is unreachable.
- unreachable-breaks correctly separates dead faults from real ones on a machine
  crafted to have both.
- dead-states finds a declared-but-unreachable status on a crafted machine.

* Phase 3 — the injecting stateful server + sandbox selection

** Build

1. =make-session-server [port contract injections]= — mirrors
   fault/make-server: a mock server holding the machine's current state, valid
   transitions by default, an injected illegal transition when a request names
   one. Verdict {:ok? :reason :state} rides with each step.
2. =serve-step [server msg]= — advance the session; if =msg= is in :injections,
   serve the broken transition (contract says illegal, mock serves it anyway,
   flagged); else the valid next state. State threads across calls.
3. Env selection: identical to examples/mock/02 — a stateful mock is chosen when
   the real impl's capability is ungranted. The mock is a VERIFIED pure machine,
   so it is sandbox-safe; the adversarial session provably cannot escape.

** Acceptance

- serve-step drives a session through valid steps and one injected illegal one;
  the illegal step is flagged with its transition label and never silently
  applied without the flag.
- A test in test/bl/mock/ proves state threads correctly and the injection is
  observable.

* Honest scope / known hazards

- The seam is a SHAPE + BRIDGE (Phase 1.1), not new theory — but it IS the real
  work: system.model consumes a defserver SOURCE FORM, while this consumes a
  DATA shape, so to-model must build prove-box's args directly (bypassing
  system-model), which is why it targets the PUBLIC prove-box/preserves? rather
  than verify-process.
- Counter-model → runnable session (Phase 2.2): preserves? gives ONE bad
  (state,input); turning it into a concrete served response threads it through
  synth so the bad state becomes concrete fields. Mechanical, unbuilt.
- Nonlinear reachability is undecidable too: the same "unknown" honesty as the
  stateless engine applies, now over PATHS. A reachability/preservation question
  z3 cannot settle degrades to :unknown, never hangs. Every z3 call MUST carry
  the (set-option :timeout N) floor mock.bl already established.
- Multi-var joint state is deferred to Phase 2; Phase 1 is single-var to prove
  the loop, exactly as stateless started with integer fields.
