* Goal

Turn the raw commit stream (L2) into *filtered, per-principal, live queries*.
=datom/watch= takes an interest (a =:where= pattern, a full =auth/guard='d query,
or a =similar-to= clause) and fires a callback only when a commit affects the
answer. This is L3 in =docs/datom-as-a-broadcast-substrate.md=.

Blocks on: L2 (PLAN-044) — the broadcast + local report with =:tx-datoms=.

Design doc (authoritative): =docs/datom-as-a-broadcast-substrate.md= §§2–4.

* The central insight (why this is small)

The filter already exists. Three seams already in the tree compose:

1. =priv/auth/rls.bl= — a subscription's per-principal scope is the SAME datalog
   =:where= clause injection RLS already does. =auth/guard= ∘ =datom/watch=. The
   monotonicity proof in rls.bl (a conjunctive clause only REMOVES rows) is
   exactly the soundness a subscription filter needs: a feed can never carry a
   fact the filter excludes.
2. =priv/datom/query/engine.bl= — =unify-pattern= already matches one =:where=
   clause against one datom =[e a v tx op]=. A commit's =:tx-datoms= is a list of
   those. So the datom-level filter is: ∃ d ∈ tx-datoms . clauses unify with d.
   REUSE this matcher — do not write a second one (see the "second engine that
   must agree" anti-pattern in =priv/datom/datalog.bl=).
3. =priv/datom/vector.bl= + =examples/semantic/03-hybrid.bl= — =similar-to= in
   BOUND-?e mode is a FILTER (score only entities upstream clauses selected). A
   semantic subscription scores only THIS commit's touched entities, and
   time-travels for free via the db value's basis.

* Public surface (proposed)

#+begin_src clojure
;; T1 — precise pattern interest
(datom/watch conn '[?e :order/status :shipped] (fn [changes] …))

;; T2a — per-principal guarded live query (the auth seam)
(def feed (auth/guard '[:find ?id :where [?doc :doc/id ?id]]
                      [(auth/owner-filter '?doc :doc/owner principal)]))
(datom/watch conn feed (fn [changes] (push! principal changes)))

;; semantic — similar-to as a filter (bound ?e); time-travels via basis
(datom/watch conn
  '[:find ?e ?score :in $ ?q
    :where [?e :doc/embedding _]
           [(similar-to :doc/embedding ?q 0.85) [?e ?score]]]
  {:in [query-vec]}
  (fn [changes] …))

(datom/unwatch conn watch-ref)
#+end_src

The callback receives =changes= as datoms (or =[e v]= rows for a query), NOT a
rendered projection — FEAT-016 holds at L3 too: the reader derives its view.

* Reader-side re-derivation (FEAT-016 at L3)

A =watch= callback fires from the LOCAL report. The interest's =auth/guard=
clauses (which encode *who is asking*) are evaluated on the SUBSCRIBER's process,
against =(:db-after report)= (or =(as-of db basis)= on the cross-node path). The
writer never computes anyone's filtered answer.

* Soundness invariants (acceptance = each is a test)

1. *Filter soundness (no false positives).* A =watch= on =[?e :order/status
   :shipped]= fires iff a commit asserts/retracts a matching datom. TEST: commit
   =:order/status :pending= — no fire; =:shipped= — fires with the right =?e=.
2. *RLS monotonicity (no leaks).* =auth/guard='d watch for principal A never
   delivers a fact scoped to principal B. TEST: alice-guarded feed + a write to
   bob's doc ⇒ zero delivery to alice; a write to alice's doc ⇒ delivery. This is
   the security property; it must be a test, mirroring
   =examples/auth/05-rls-filter-your-rows.bl=.
3. *Matcher = query semantics.* The =tx-datoms= matcher agrees with running the
   full query over =:db-after=: if the matcher says "affected", the query result
   over db-after differs from db-before for that interest. TEST: property-style
   over a handful of interests — no divergence (guards against the "second
   engine" drift).
4. *Semantic bound-mode.* A =similar-to= watch scores ONLY the commit's touched
   embedding entities, not the corpus. TEST: commit one near + one far doc;
   callback sees the near one above threshold, not the far one, and does not
   rescan untouched corpus entities (assert via a scored-count probe).
5. *Retraction fires too.* A watch sees retractions, not just assertions (=op=
   false). TEST: retract a matching datom ⇒ callback fires with an
   added?/retracted flag.

* Resolution (implemented, commit 04e0654 on branch datom-broadcast)

Built on top of L2. Full datom suite 427 tests / 960 assertions / 0 failures
(+9 over L2's 418). Auth suite 56 / 190 / 0 failures (watch_rls uses auth, no
regression). All 13 live examples run clean under =--path priv=.

Decisions taken:

- *A watch is a PROCESS, not a callback registered in the writer.* =watch=
  spawns a subscriber that =listen!=s the L2 stream and runs the matcher in its
  own process. Reason: isolation (a crashing callback takes down only the watch,
  never the writer that holds the ordering guarantee) and backpressure (the
  callback's slowness is the watch's mailbox, never the writer's). =unwatch=
  sends =[:datom/watch-stop]=, which the selective =receive= matches after
  draining queued commits, and the watch =unlisten!=s on stop. A dead watch pid
  is also pruned lazily by L2's publish, so an un-=unwatch=ed crash self-heals.

- *T1 vs T2a dispatch by interest shape.* =query-interest?= = a =:find= vector
  or a map ⇒ T2a; anything else ⇒ a bare T1 pattern. T1 matches tx-datoms with
  =query.engine/unify-pattern= (callback gets change maps incl. =:added=). T2a
  prefilters on the query's pattern attributes (=touches?=), then re-runs the
  query over db-before/db-after and diffs (callback gets ={:added :removed}=).

- *No second engine (the DoD grep).* =pattern-matches= calls
  =query.engine/unify-pattern=; =query-diff= calls =query.engine/q=. grep
  confirms watch.bl reimplements no unify/match/pattern logic. The semantic tier
  is just a T2a query whose clause is =similar-to= — bound-?e turns it into a
  filter, so only the commit's touched embeddings are scored, and it
  time-travels via =as-of= (proven in 09-semantic-feed.bl).

- *The security property is a TEST.* watch_rls_test.bl asserts a guarded watch
  never delivers another principal's rows (the leak test), that two principals
  get disjoint feeds, and that a commit of only-forbidden rows leaves the feed
  silent. This is invariant 2, and it holds by RLS clause-injection
  monotonicity — the same property =examples/auth/05= relies on for reads.

- *T2b (incremental view maintenance over dl-eval-incremental)* was scoped out
  and remains a follow-up; T2a re-runs the query, which is correct and cannot
  drift, at the cost of a full re-derivation per relevant commit. A large
  materialized view that wants true delta-maintenance is the T2b upgrade.
