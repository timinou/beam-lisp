#+TITLE: Annotated native JavaScript interop for Beam Lisp
#+DATE: 2026-10-08
#+STATUS: implementing

* Contract
Use (ns ^:js name), shorthand for ^{:interop :javascript}, to permit native
JavaScript expressions inside a namespace. Requiring it grants no interop to
callers. Check expanded operations in the caller's compile environment. This
is an architectural boundary, not a security sandbox.

Support js/global, constructors, receiver-preserving .method, .-property,
set!, aget/aset, #js maps/vectors, callbacks, and bl->js / js->bl. Preserve BL
collections and exact numerics; reject lossy conversion. Null is nil;
undefined remains distinct. No raw-source injection. Promises compose with
.then/.catch; async suspension is a separate feature.

JavaScript callers acquire public BL APIs through a runtime bridge using the
existing calling ABI; private defs are excluded. Existing --host injection
remains compatible. Static and live compilation share structured ANF and emitter
operations. BEAM compilation reports an explicit unsupported-target error.

* Compile-time knowledge
Use system.ir's canonical traversal/annotation machinery for JS value evidence
and typed's type lattice for definite mismatches. Known JS-native positions
(object arguments, computed access, native literals) should reject provable BL
collections lacking #js or bl->js; unknown inputs remain allowed. Check native
object keys, operation arities, invalid assignment targets, duplicate converted
keys and statically known non-callable receivers where evidence permits. Never
claim a browser API signature from an unknown global. Do not import typed into
compiler boot (typed already depends on compiler); share a portable analysis
module below both instead.

* Implementation sequence
1. Reader representation and namespace annotation; shared compiler operations.
2. JS emitter and system IR traversal; conservative compile-time evidence.
3. Explicit conversions, callback identity and JS-to-BL public bridge.
4. Static/live differentials, negative compilation cases, existing regressions.
5. Documentation, feasibility findings and upstream commit.

* PELAGIC
Score, performance state and live compiler already run on JS. Browser APIs
still need an owning adapter, but orchestration can be written in annotated BL.
Server-free bl-ed also needs document/save/revision replacements. Omega's old
pin/output layout requires a separate migration; do not change the pin or write
to its live world during this work.

* Validation
Bound BEAM memory; batch tests in one VM. Exercise emitted JS under Node and
live compiler parity; verify evaluation order, this binding, callback identity,
annotation isolation including macros, conversions and structured analysis.
