#+TITLE: Owned SDK tasks and native extraction permits
#+DATE: 2026-10-14

* Scope and exact mechanism
The SDK's document.xberg in-process and batch paths used raw Task/async. That
creates work without captured Beam Lisp Env/query authority or selected
application code retention. Wrapping Task callbacks alone would convey context
but still leave code lifetime and a linked-start failure window unresolved.

proc.task exposes async, async-nolink, await, yield, ignore, shutdown and pid with ordinary
native OTP Task results/monitor semantics. Native Refs/task_exec factors the
already-owned Future startup instead of reaching through Future's private shape.
It validates callability, retains the actual callback arms and whole selected
application graph before spawning, transfers its lease under the native fence,
and publishes a private per-start ticket. async-nolink unlinks BEFORE publication.
The existing Future wrapper preserves its normal link/bounded-worker behavior.
Core spawn uses the same private-ticket startup, closing guessed-marker entry.

* Xberg effects and drain
The in-process path uses async-nolink; the batch uses linked async and awaits each
bounded window. The accepted native call owns cleanup of its permit and input.
Task yield timeout only stops waiting and still reports native-stopped? false.
Caller death after publication cannot kill the accepted native task or release a
permit early. Only the actual native return and finally cleanup return the permit.
After a yield timeout, standard Task.ignore abandons its result alias/monitor
without stopping work; a late large native reply cannot accumulate in a retained
caller's mailbox. No timeout triggers cancellation, provider replay, or an
inferred physical stop. The native Task.ignore contract is documented at
https://hexdocs.pm/elixir/Task.html#ignore/1 (present in the pinned1.20.2 source).
A successful native response and ordinary error results preserve existing shapes.

The fixed SDK's attested shared code lease and SDK scope last for the VM lifetime;
closing a framework actor does not release them. Application tasks retain their
selected graph independently. Live SDK/runtime replacement is NOT established by
this proof: handover must drain accepted native tasks before terminating the old
VM. Native kills/VM death and a lost pre-publication resource handoff are not
claimed to run arbitrary finally cleanup or authorize retry of unknown effects.

* Counter correctness and simplification
The previous update_counter/3 catch->insert0 fallback can reset another first
admission. Its tuple-of-rows initializer also did not create the expected rows.
The SDK now uses native update_counter/4 with default row: missing-row creation
and increment are atomic, and there is no reset/init fallback. The standard
proc.table keeper/heir retains the same counter rows through keeper death and
reclamation; accepted in-flight work is not reset to zero during that recovery.
Existing rows are preserved. Counter state remains VM-local, not durable across
node restart. A killed native task with unknown completion is not made retry-safe
by a counter cleanup guess.

* Focused controls
Native acceptance pending a root-managed official host-floor regeneration/batch.
- Actual private startup helper refuses old/guessed markers and exits when the
  unpublishing creator dies; existing spawn/future ownership tests regress.
- Native task callback-module rows, whole app graph retention, yield timeout,
  caller exit, actual Env/query policy capture, and safe explicit private shutdown.
- Counter negative control deterministically interleaves the former missing-row
  fallback and loses an increment; 32 simultaneous actual SDK increments produce
  the full unique 1..32 sequence with no lost admission.
- Real batch and injected native calls inherit a private Env/query policy.
- Actual injected native remains blocked after timeout or caller kill: its permit,
  input and original graph remain available. Reclaimed keeper preserves that
  real in-flight permit. Actual return releases resources and allows retirement.
- Existing document/xberg_test.bl covers config/egress/worker/timeout contracts
  without requiring the native carrier for the explicit injection seams.

* Native floor validation checkpoint
Official root-managed floor build17 exposed a native receive-guard compiler
restriction: qualified erlang/== is not admitted in :when guards. The private
startup ticket guard now uses the compiler's ordinary = guard form; ticket
identity, retained ownership and publication order are unchanged. All new task
and Xberg fixture guards already use ordinary =/and forms. This is a build fix,
not acceptance: the official floor and focused native tests must still pass.
