#+TITLE: Bootstrap and provenance for the shared pure freshness planner
#+STATE: Source integration; native validation and coherent floor pending

* Purpose
Compilation and runtime freshness checks share the same graph and interface
algorithms. Calculating a key must not require initializing a namespace, fetching
a mutable planner callback, creating its ETS tables, or touching its disk memo.
The Source build planner retains those caches as optional acceleration.

* Source integration
- The explicit seed inventory includes SourceGraph, NamespaceInterface and
  BuildPlan at their exact native module atoms: 70 host modules in total.
- The regeneration driver compiles these three hosts with the other changed
  native hosts before loading any replacement. The complete floor still checks
  every source fingerprint and installs its manifest last.
- All three pure sources participate in the codegen digest. Changing a graph,
  interface or planning rule cannot silently reuse old emitted provenance.
- Existing exact seed inventory and live-source provenance tests include the
  new modules. No alternative hash format or application configuration exists.

* Acceptance
Static delimiter/binding/try checks and git whitespace checks pass. Source
integration alone is not a coherent installed floor or successful cold startup.
Root native 116 snapshots and compiles the actual three hosts before fresh AOT,
then runs the real recursive SDK producer. Results are recorded separately.

Before release: run pure planner parity/no-initialization controls and original
graph/interface/build-plan suites; rebuild the whole floor; check every source;
commit the floor; run ordinary cold CLI and packaged sandbox acceptance. Both
consumer pins must identify the same final validated SDK source revision.
