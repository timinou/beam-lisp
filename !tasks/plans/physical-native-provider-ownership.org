* Chosen integration boundary
Env.publish_binaries! receives the entire already prepared compiler batch. It
acquires sorted unique module ownership before any mutation, freezes every scope's
reference to each loaded AOT literal provider, then admits code loading under the
current scope's retirement fence. Compiler-created bodies, shims and companions
share one admission. All normal lazy pointer constructors acquire the same module
ownership; missing providers become own empty tables instead of future-changing
pointers. Initializers and byte/file preparation stay outside these locks.

Lock order:namespace (where caller already owns it), sorted physical modules,
one scope at a time. Detachment must NOT acquire other namespace locks:those can
belong to readers or sibling loaders. Never hold one scope while acquiring another
scope/module/namespace. Private ownership markers are not conveyed; unique tickets
and exact-row deletion recover dead owners without deleting a new owner's lock.

Only already loaded literal providers require a variable-table scan. Fresh body
modules and ordinary live shims do not scan the table per definition; missing
providers cannot retain deferred pointers. This avoids introducing an O(N²) scan
into incremental compilation. Module ownership also protects complete stable-body/
shim batches from competing normal compiler publication during receipt assembly.

* Reader obligation
A reader may capture a lazy descriptor, then wait for its owner scope while the
physical publisher detaches that descriptor. Full/selected/count readers must
re-read inside the scope fence before dereferencing native literal code. Selected
legacy-map projection and constant descriptor counts remain supported. Deterministic
tests suspend only an owned reader after it waits at the scope lock; publication
must finish while that reader still holds its namespace lock, and resumed reads
must return the old table/entry/count. All tasks resume/reap in finally.
