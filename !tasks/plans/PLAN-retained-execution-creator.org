* Exact bug
A callback registration pins the whole selected graph and run_code! independently
retains accepted invocations. Native owned tasks transfer their actual ticket to
the worker before its exact start handshake. Both preserve graph/context but
reload.execution/owned? recognizes only generation.execute's separate private
marker. Consequently an actual connection created by these admitted executions
gets no immutable guard-creator. Existing inventory silently omits such an open
path-backed connection, potentially missing its migration checks.

* Minimal generic mechanism
- Env keeps a private executing-code ticket only around already-admitted native
  invocation or the Refs exact self-owned start handoff. It is absent from every
  Env capture/bind/convey token and restored on normal return and exception.
- Inside that admission, the callback enters its user function after its captured
  Env context is bound; the task enters after its exact native start and token
  bind. A second private snapshot records that exact graph+scope+execution ticket.
  Later env/bind cannot replace it. An in-invocation forged subset graph therefore
  fails even when its few modules happen to be covered by the real ticket.
- Read-only executing_generation? requires actual current graph equality,
  matching native environment scope, self-owned active native ticket, and every
  graph module covered by that ticket. No callback execution or new lease is
  allocated by observation. Malformed proof fails false. Module count is bounded
  by the native 65,536-row lease capacity. Existing prepared graph/state objects
  are the trusted SDK boundary; this introduces no user-map authenticity API.
- SDK owned? accepts that proof as well as its existing private synchronous
  execution boundary. Graph identity, a captured token, active registration or
  creator PID alone is never sufficient.
- Conn retains its original creator-capture point before the registry Agent;
  identity is not copied retroactively, guards are not adopted, native lifetimes
  and the single actual Fjall writer remain unchanged.
- Inventory refuses unclassified open under-root path-backed native rows unless
  the exact native connection/lifetime is explicitly declared. The path causes
  refusal; it never causes ownership or an implicit reopen.
