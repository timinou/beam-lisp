* Design invariants (agreed)

1. Types live at beam-lisp source level only; erased before codegen. Generated Elixir AST is byte-identical to today; `infer_signatures: false` (PLAN-006) stays.
2. Tag lattice, NOT set-theoretic: int<float? no — int<number, kw, string, bool, map, vec, set, fn/N, nil, any, never + simple unions. No negation/intersection types → no super-linear intersections by construction.
3. Sound-warnings-only: never a wrong warning, occasionally a missed one. Checker approximates pattern+guard dispatch conservatively; runtime semantics unchanged (generated BEAM clauses still do real dispatch).
4. Lattice is pre-designed by the runtime's value-tag discipline (examples/type_safety.bl: ~12 value kinds, struct-backed vs plain maps). That bug class is the primary target.
5. Guard narrowing via whitelisted predicates (int?, string?, map?, keyword?, ...) mapped to tags; unknown guard → no narrowing, no warning.
6. Gradual: default any; `(ns foo ^:typed)` opt-in; warn only on proven contradictions.
7. Inference follows the require DAG in topological order (compile.beam_lisp order_and_deps already computes it). Per-ns signature tables cached under the SAME closure key as FEAT-002's AOT cache → zero re-inference on cache hit.
8. Checker input = Env ns_defs (persisted arity/AST/meta per ns). Errors report .bl file:line:col via FormMeta.

* Design answers added (2026-08-28)

** Unions/intersections
- Types = subsets of the ~12-tag universe → bitmask (12-bit int). Union = bor, narrowing = band. Cheap by domain size, not by algorithm.
- Unions first-class: users write ^{:ret (or int nil)}.
- Intersections exist ONLY as lattice meets during narrowing (int ∩ number = int). True disjoint intersection (int ∩ string = ∅) is a BUG REPORT (contradictory annotation/guard), never a stored type. No intersection syntax; (and int string) → "impossible type" error.
- Negation absent: clause coverage is subsumption-only (warn when provably covered, else silent).
- RISK to measure in P8: map shapes reintroduce structure; shape intersection only lazy during narrowing, width > N keys degrades to `map`. If it blows up → shapes stay unions-only.

** Interval domain (the 'when x > 3 and x < 3' answer)
- Arithmetic contradictions are NOT a type problem → not paid for in the type lattice. Separate pluggable abstract domain (Cousot-style intervals) refined on the `number` tag only.
- Comparison predicates (>, <, >=, <=, =, zero?, pos?, neg?) → interval facts; and = intersect (max-lower/min-upper, O(1)); proven-empty → unreachable-clause / dead-branch warning. Unknown → top interval, silence.
- Checker architecture = framework of composable domains over one narrowing hook: tags (required) + intervals (optional) + later constants/literals. ~100 LOC per domain.
- Explicitly out of scope: symbolic arithmetic (x > y + 3), multiplication, string lengths.
- NEW PROTOTYPE P13 intervals :: does the interval domain catch (and (> x 3) (< x 3)) with zero FPs on examples? Experiment: implement domain, run over guards.bl + a seeded contradiction. Artifact: domain rules + FP audit.

** Deodorant integration (inspiration from priv/deodorant.bl)
- Deodorant's IDIOMATIC tier assumptions ("numeric argument", "boolean context") ARE type predicates. Types discharge them per call-site → type-directed promotion of IDIOMATIC rules to SAFE, per-site instead of per-invocation.
- New tier: TYPE-GUIDED smells — no-op coercions ((str x) where x : string), count-on-int bugs, dead branches from tag/interval contradictions.
- P12 is now THREE-WAY: optics traversals vs rewrite.bl pattern-rules vs plain recursion. rewrite already supplies positional matcher + fixed-point engine; type table supplies the guard; rule shape {:pattern … :when <type-guard> :report …}.
- Shared contract: rules over (AST × signature table × fact table), every finding provable, no guessing.
- NEW PROTOTYPE P14 deodorant×types :: implement one type-guarded rewrite rule end-to-end (=-0→zero? promoted by inferred number) + one type-guided smell (str-on-string). Artifact: promoted-rule demo + rule format.

* PIVOT (user direction 2026-08-28): P13 interval domain → FULL SMT/logic checker research spike

Intervals demoted from "the answer" to a possible fast-path tier. The spike investigates a real logic layer. Key facts:
- SMT-LIB is s-expressions: beam-lisp → solver encoding is nearly a pretty-printer. Lisp-native in the deepest sense.
- No SMT solver on host (z3/cvc5 absent) — external solver = new system dep, feeds backend bake-off.
- Escalation architecture: tag bitmask (fast path) → structural layer → logic engine, only escalating what cheap layers can't decide; solver results cached under FEAT-002 closure keys (pure functions of source).
- Encoding discipline: every value pairs with its lattice tag; tag domain discharges solver preconditions (>x 3 only meaningful when x : int).

** Three candidate backends (bake-off)
A. External SMT (Z3 via port): strongest theories (LIA, strings, quantifiers); costs = system dep, ms latency, worst-case exponential (tiny guards ⇒ practically fine).
B. miniKanren self-hosted (~200 LOC): relational checker runs FORWARDS (check), SIDEWAYS (infer intended type from error), BACKWARDS (synthesize expressions from type+tests — Barliman/Byrd literature). No arithmetic theories unless extended; backwards is slow — scope synthesis to 3-5 forms.
C. datom/datalog (already in-repo: priv/datom/query/ fixpoint, rules, magic-sets): industry-proven checker substrate (CodeQL/Doop/Soufflé); structural checks only (coverage, narrowing, protocol/multi resolution); monotone, weak arithmetic; zero new deps, dogfoods datom.
