* Design invariants (agreed)

1. Types live at beam-lisp source level only; erased before codegen. Generated Elixir AST is byte-identical to today; `infer_signatures: false` (PLAN-006) stays.
2. Tag lattice, NOT set-theoretic: int<float? no — int<number, kw, string, bool, map, vec, set, fn/N, nil, any, never + simple unions. No negation/intersection types → no super-linear intersections by construction.
3. Sound-warnings-only: never a wrong warning, occasionally a missed one. Checker approximates pattern+guard dispatch conservatively; runtime semantics unchanged (generated BEAM clauses still do real dispatch).
4. Lattice is pre-designed by the runtime's value-tag discipline (examples/type_safety.bl: ~12 value kinds, struct-backed vs plain maps). That bug class is the primary target.
5. Guard narrowing via whitelisted predicates (int?, string?, map?, keyword?, ...) mapped to tags; unknown guard → no narrowing, no warning.
6. Gradual: default any; `(ns foo ^:typed)` opt-in; warn only on proven contradictions.
7. Inference follows the require DAG in topological order (compile.beam_lisp order_and_deps already computes it). Per-ns signature tables cached under the SAME closure key as FEAT-002's AOT cache → zero re-inference on cache hit.
8. Checker input = Env ns_defs (persisted arity/AST/meta per ns). Errors report .bl file:line:col via FormMeta.

* Design answers added (2026-08-28)

** Unions/intersections
- Types = subsets of the ~12-tag universe → bitmask (12-bit int). Union = bor, narrowing = band. Cheap by domain size, not by algorithm.
- Unions first-class: users write ^{:ret (or int nil)}.
- Intersections exist ONLY as lattice meets during narrowing (int ∩ number = int). True disjoint intersection (int ∩ string = ∅) is a BUG REPORT (contradictory annotation/guard), never a stored type. No intersection syntax; (and int string) → "impossible type" error.
- Negation absent: clause coverage is subsumption-only (warn when provably covered, else silent).
- RISK to measure in P8: map shapes reintroduce structure; shape intersection only lazy during narrowing, width > N keys degrades to `map`. If it blows up → shapes stay unions-only.

** Interval domain (the 'when x > 3 and x < 3' answer)
- Arithmetic contradictions are NOT a type problem → not paid for in the type lattice. Separate pluggable abstract domain (Cousot-style intervals) refined on the `number` tag only.
- Comparison predicates (>, <, >=, <=, =, zero?, pos?, neg?) → interval facts; and = intersect (max-lower/min-upper, O(1)); proven-empty → unreachable-clause / dead-branch warning. Unknown → top interval, silence.
- Checker architecture = framework of composable domains over one narrowing hook: tags (required) + intervals (optional) + later constants/literals. ~100 LOC per domain.
- Explicitly out of scope: symbolic arithmetic (x > y + 3), multiplication, string lengths.
- NEW PROTOTYPE P13 intervals :: does the interval domain catch (and (> x 3) (< x 3)) with zero FPs on examples? Experiment: implement domain, run over guards.bl + a seeded contradiction. Artifact: domain rules + FP audit.

** Deodorant integration (inspiration from priv/deodorant.bl)
- Deodorant's IDIOMATIC tier assumptions ("numeric argument", "boolean context") ARE type predicates. Types discharge them per call-site → type-directed promotion of IDIOMATIC rules to SAFE, per-site instead of per-invocation.
- New tier: TYPE-GUIDED smells — no-op coercions ((str x) where x : string), count-on-int bugs, dead branches from tag/interval contradictions.
- P12 is now THREE-WAY: optics traversals vs rewrite.bl pattern-rules vs plain recursion. rewrite already supplies positional matcher + fixed-point engine; type table supplies the guard; rule shape {:pattern … :when <type-guard> :report …}.
- Shared contract: rules over (AST × signature table × fact table), every finding provable, no guessing.
- NEW PROTOTYPE P14 deodorant×types :: implement one type-guarded rewrite rule end-to-end (=-0→zero? promoted by inferred number) + one type-guided smell (str-on-string). Artifact: promoted-rule demo + rule format.

* Deep inspiration synthesis (2026-08-28): Formulog + Flix/λDat + Datafun → native mapping

** Formulog mechanisms (read in full, arXiv:2009.08361v2)
- SMT formulas are REIFIED GROUND TERMS (ADTs), manipulated/stored as data; only interpreted at is_sat/is_valid/get_model operator boundaries. beam-lisp gets this FREE from homoiconicity: a quoted form IS the formula; SMT-LIB is s-expressions.
- Bimodal type system: distinguish concrete vs symbolic during concrete evaluation (never get stuck), CONFLATE inside quoted formulas (expressiveness). Native mapping: `quote` is already a mode switch; the checker gains a "formula checking mode" entered at quote, checked against solver sorts instead of the value lattice.
- Formula variables as ground terms → facts can CONTAIN formulas without violating datalog's range restriction. Native: symbols are ground values already.
- Solver ops memoized for determinism → FEAT-002 content-addressed cache IS the memo table, persistent across runs (Formulog only memoized per-run).
- is_sat callable in RULE BODIES; constraints do not leak across calls (unlike CLP). → solver as ordinary fn callable from checker rules AND user macros.
- Magic-set transformation made their symbolic evaluator goal-directed: 12×. datom/query/magic.bl already implements magic sets → goal-directed checking ("check only what this edit/query needs").
- Case studies ≤1.5K LOC each, near-literal translations of published specs — and the closeness REVEALED BUGS IN THE SPECS. Checker-as-inference-rules is both concise and more trustworthy.
- Stratified negation required; P13c must verify datom's stratification support.

** Flix/λDat mechanisms (read in full, CS-2020-05)
- #{...} first-class constraint-set values, composed with <+>, solved with `solve`, projected, subset-tested with |=. Native: rule sets are quoted data, composition is `concat` — deodorant's tier composition (safe-rules concat idiomatic-rules) IS first-class constraint composition, already shipped.
- Row polymorphism (HM + rows) tracks WHICH predicate symbols a fragment mentions, so fragments type-check independently and compose safely. Their motivating bug: Edge ternary in facts, binary in rules — arity mismatch across composed fragments. Native: OUR tag/shape checker validates rule-set composition; the type system checks the tooling itself.
- Host fns callable inside rules as filters (if q(speedLimit)). datom datalog: verify expression-clause fn calls in P13c.
- Stratification of negation computed at COMPILE time across fragment compositions → a checker pass over quoted rule data, possible because engine + checker share the repo.
- Principle VI: well-typed programs don't get stuck (their example: true > 60 stuck in the engine) — exactly the tag-lattice bug class.

** Datafun (from literature knowledge; moderate confidence on details)
- Types track MONOTONICITY via tones (discrete vs monotone fns); semilattice types; fixpoints well-typed only when self-reference is monotone and result type is a semilattice.
- Native application: datom live queries (L3 filtered live) = incremental view maintenance, correct only when derived relations are monotone in base data. ^{:monotone true} annotation + checker → PROVEN incrementally-maintainable live queries. The type system verifies the streaming layer. New example for examples/typing/.

** User data point integrated: rewrite/deodorant are ALREADY logic programming
- rewrite.bl: rules are data maps; ?x pattern vars UNIFY (repeated vars = equality join); fixed-point evaluation = forward chaining. It is a unification engine over TREES.
- deodorant: tiered rule-set composition with plain collection ops = Flix principle II shipped in production.
- So beam-lisp already has THREE logic-flavored engines: rewrite (tree unification + fixed point), specter/optics (composable selection), datom (relational datalog + magic sets). The checker is built FROM these, not added beside them.
- Type-system upgrade path: rewrite rule shape gains a checked guard — {:pattern … :when <type-guard> :replacement …} — where the guard queries the signature/fact tables.

* P13b REVISED: the logic-engine chooser — strict non-overlap (user direction)
