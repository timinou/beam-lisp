clients make to a tree becomes a change with an actor and an intent, the history

* Components, in order

1. **`priv/std/vcs.bl`** — the language surface, no daemon knowledge.
   - `(vcs/bin)` — resolve jj: `VCS_JJ` env, then `<tree>/priv/jj/<os>-<arch>/jj`,
     then `PATH`. One place decides; everything else asks it.
   - `(vcs/available?)`, `(vcs/repo? dir)`, `(vcs/init! dir)` — a tree is a jj
     repo or it is not; init is colocated so git stays the interop format.
   - `(vcs/checkpoint! {:dir :by :why})` — describe (which snapshots) → read the
     operation id → `jj new`. Returns `{:op :commit}`.
   - `(vcs/mirror! {:dir})` — jj's op log, commit log and changed paths into
     datom, plus the request facts; watermark in `:meta/op-head`; idempotent by
     content-addressed id.
   - `(vcs/history {:dir :limit})`, `(vcs/touched {:dir :path})`,
     `(vcs/status {:dir})`, `(vcs/undo! {:dir :op})`.
   - `(vcs/gate! {:dir :paths :cmd})` — run the project's gate (default
     `bl check --changed`) and return `{:ok true}` / `{:ok false :output}`.
   - `(vcs/checkpoint+gated! opts)` — gate, then checkpoint. The one call the
     daemon and the CLI both make, so there is one definition of "recorded".
   - Registry of open mirrors per dir (an atom), so a long-lived daemon does not
     reopen the fjall store per call.
   - `:vcs {:gate [...] :actor "…"}` in `env.bl` overrides the gate command and
     the default actor.

2. **`bl vcs`** — `status | history | touched | checkpoint | gate | undo | init`.
   `checkpoint` takes `-m <why>` and `--by <actor>`; `gate` is non-interactive and
   exits 0/1, which is what CI calls.

3. **The daemon** (`lib/beam_lisp/daemon/`):
   - one mirror per tree, opened on demand and owned by the daemon;
   - after every command the Executor runs, if the tree's jj operation head
     moved, checkpoint with `by` = `$BL_VCS_ACTOR` (default the daemon's user)
     and `why` = the argv that just ran — the daemon's own command log becomes
     the intent, which no other layer can supply;
   - `BL_VCS=off` disables it per request; a tree that is not a jj repo is left
     alone (no surprise repos);
   - the gate runs before the checkpoint is recorded, so a failing tree is
     recorded as failing, never silently advanced.

4. **First-party jj** — `mix bl.jj.fetch` (the `bl.z3.fetch` shape): a lock file
   with version, url and sha256 per target, fetched into `priv/jj/<target>/jj`,
   carried by the drop's payload, reported by `bl doctor`, and pinned in
   `tooling/drop/make-drops.sh`'s prerequisites. The probe's `research/autovcs/jj.lock`
   is the source of the digests.

5. **Tests**
   - `test/bl/vcs_test.bl` — in-language: init, two checkpoints, mirror
     idempotence (incremental count == rebuilt-from-scratch count), `touched`,
     `undo`, gate refusal.
   - `test/beam_lisp/daemon_vcs_test.exs` — the daemon checkpoints after a
     command that changed the tree, and does not when nothing changed.

* Decisions already taken

- **jj is the change engine, datom is the fact layer.** Not the reverse: a
  durable datom store is single-writer-per-process, so a spawned jj cannot write
  one (`docs/jj-in-front-datom-in-the-back.md`).
- **The mirror is derived and rebuildable.** Every fact keyed by a
  content-addressed id; the watermark makes the common case free.
- **The mirror directory is ignored by the VCS it mirrors** (`.autovcs/`), or
  every checkpoint tracks the journal that describes the checkpoint.
- **The gate is one procedure, three callers.** daemon (automatic), `bl vcs
  checkpoint` (explicit), CI (`bl vcs gate`). Not three implementations.
- **jj ships as a pinned prebuilt binary**, not a cargo dependency — the seams
  are compile-time and the API is explicitly unstable.

* Known gaps to close inside this work

- The daemon-side cure for BUG-035 (a failed command must send its diagnostic)
  and the refusal to run a program that calls `(System/halt n)` in the shared VM.
- Changed paths currently come from the daemon's own testimony plus jj's diff
  summary; renames are not interpreted.
- The mirror re-reads the whole op log on a miss; page it (or use `--at-op`)
  before trees with long histories.

* Acceptance

- `bl test test/bl/vcs_test.bl` passes with `VCS_JJ` pointing at the pinned jj.
- A tree mutated by a served command shows one change per command in `jj log`,
  with the command's argv as the description, and `bl vcs history` answers why.
- `bl vcs gate` exits non-zero on a tree that fails `bl check --changed`, and the
  daemon does not record a checkpoint that the gate refused.
- `bl doctor` names the pinned jj version.

Four things the work established, three of them corrections to the plan:

1. **Request facts are PRIMARY, not derived.** The suite's rebuild test shows a
   wiped mirror comes back with zero `:req/*`. Today's assertion documents the
   boundary rather than hiding it. Two ways to close it, to choose between
   before the daemon depends on it: (a) derive the request from the commit —
   `by`/`why` are already in the description, `paths` come from jj's diff,
   `at` from the commit timestamp, and only `ms` (and the request↔commit
   mapping) would be lost, reconstructed by matching descriptions in order; or
   (b) accept it and give the mirror an explicit export before any rebuild.
   (a) is better: it makes jj the source of truth for everything except a
   duration.
2. **A re-derivation is a fixed point, not a count match.** jj's head moves
   between looks (every read is an operation) and jj abandons empty working-copy
   commits, so the mirror is deliberately WIDER than `jj log -r all()`. The test
   asserts "two rebuilds agree", not "rebuilt == incremental", which is a claim
   that cannot hold and should not.
3. **The gate is arbitrary argv, not a jj call.** The first implementation ran
   the gate through the jj boundary and the suite caught it. Worth keeping in
   mind when the daemon calls it: the gate runs in the tree's cwd, whatever the
   command is.
4. **`bl test` from a checkout binds only `priv/lib`.** A test for a `priv/std`
   namespace needs `-p priv/std` (the drop ships its own stdlib; datom reaches
   z3pool through priv/std).
