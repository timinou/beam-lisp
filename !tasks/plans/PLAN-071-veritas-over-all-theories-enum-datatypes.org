* Intent
docs/one-verb-over-generators.md claims veritas "inherits every theory
system.smt has" — true for the TRANSLATOR, false for the GENERATORS: a query
can only bind what a Gen can sample/constrain. Two translator capabilities are
unreachable from veritas today, so their predicates fall off the z3 rung to
sampling (losing :proven):

  1. ENUM DATATYPES (nullary + payload arms) — translator: variants-map /
     datatype-decl / (:tag v) accessor / (some? (:tag v)) discriminant
     (system/smt.bl R1a). veritas: no EnumGen; smt-of calls the 2-arity
     of-source (variants map never threaded).
  2. COLLECTION LENGTH ABSTRACTION — translator: translate-len / of-source-len
     (count/conj/rest/pop/empty? over a coll var → <var>_len arithmetic,
     P18 Rung 3). veritas: no CollGen.

* Non-goals
  - Array-theory CONTENT invariants (element reasoning, quantified arrays):
    owned by system.core/verify-content; its guarantee is :approximate —
    the veritas escalator cannot honestly give it a :proven rung. Documented
    as a boundary, not built here.
  - BitVec/Seq: no bl-side evaluator symmetry (smt_symmetry_test thesis) —
    out until the bl half exists.
  - No change to verdict semantics, escalator order, or existing gens' shapes
    beyond additive :smt opts on gen-constrain.

* Design
  - priv/system/smt.bl: + of-source-variants (source-string + variants →
    SMT | :untranslatable) — mirrors of-source, threads the 3-arity translate.
  - priv/veritas.bl:
    - EnumGen [tags arms] + enum-of: (enum-of :a :b) nullary;
      (enum-of {:on :int} :off) payload arm (sort kw ∈ int/float/bool/string).
      gen-constrain → datatype-decl("E_"+var) + declare-const; :smt
      {:variants …}. enumerate: finite (tags) iff ALL arms nullary, else
      :infinite. bl values: keyword | {tag 0-ish}.
    - CollGen [minlen maxlen] + coll-of: length-bounded vector.
      gen-constrain → declare-const <var>_len Int + bounds; :smt {:colls
      #{var}}. enumerate :infinite (elements open). bl values: (range 0 len)
      element vectors, deterministic lengths.
    - gen-constrain contract += :smt opts map; TupleGen merges (variants
      merge, colls union); a tuple mixing BOTH modes → sample rung (honest
      bail: the translator cannot do variants+len in one pass).
    - smt-of keeps (vars form); private smt-of-opts adds opts dispatch
      (variants → of-source-variants, colls → of-source-len, both → nil).
    - witness projection: z3 models render ctors as E_sort-tag symbols /
      (E_sort-tag payload) lists and colls as <var>_len — project-witness maps
      them back to bl values (:tag / {tag payload} / a vector of that length),
      so a :refuted/:exists witness is a REAL bl value, symmetrical with holds?.
    - OneOf: all-STRING members now also constrain (String disjunction) —
      strings are decidable; the old int-only gate was gratuitous.
  - test/bl/veritas/theories_test.bl: per-theory modality tests (z3-proven
    enum for-all, payload exists with projected witness, coll length law
    proven/refuted both rungs, OneOf strings, tuple mixed-mode bail).
  - examples/veritas/06-all-theories.bl: one demo, every sort, one verb.
  - docs/one-verb-over-generators.md: theory table + the two new gens.
