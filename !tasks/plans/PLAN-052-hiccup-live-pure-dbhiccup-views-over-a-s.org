* The one-sentence thesis
  LiveView invented =assigns= because it had no database under the socket. Every
  downstream cost (re-render the whole assign map, diff the *rendered strings*)
  is a consequence of that single absence. beam-lisp *has* the log. So a view
  becomes a **pure function =db → hiccup=**, an event becomes a **fact**, the
  socket's state becomes a **session-scoped datom conn** (the Clojure atom, made
  durable and time-travelling), and the DOM diff rides on **fact-deltas** gated
  for soundness by =live.bl=. Three of those (fact-delta diff, provable-sound
  incremental, time-travel render) are things LiveView structurally cannot do.

* What the repo ALREADY provides (verified, not assumed — 2026-08-29)
  This design is thin because the substrate is done. Traced this session:

  1. **In-memory live db already works.** =datom/connect= *is*
     =(connect-with (datom.store-ets/open) schema)=. The subscriber table lives
     in the per-store registry cell (=datom.conn/store-cell=), driven by the
     *writer*, not by redb (=datom.broadcast=). ∴ =listen!= / =watch= /
     =as-of= / =q= / =pull= all run on ETS **today**, unchanged. The only thing
     a "session db" needs is to be opened over an in-memory store — an *init*
     choice, zero API change. This directly answers the user's question.

  2. **A session db is self-cleaning.** =store-ets/open= makes the table
     =:public= but owned by the *creating process*; the docstring: "the table
     dies when that process does." Open the conn inside the socket =gen_server=
     and disconnect frees the ETS table with **no cleanup code**. Leak-free by
     process lifetime, the BEAM's native guarantee.

  3. **It is already an efficient cache.** ETS =:ordered_set= + the
     =walk-from= cursor (=store-ets.bl=) makes a range scan cost the size of its
     *result*, not the table — "why an index is faster than a scan." A
     session/read-model cache is exactly the intended use.

  4. **conn : db :: atom : value — already literally true.**
     | atom op        | datom conn op                       | note                         |
     | =deref=         | =(datom/db conn)=                    | O(1), "captures a basis"     |
     | =swap!=         | =(datom/transact! conn tx)=          | serialized single writer     |
     | =add-watch=     | =(datom/listen! conn opts)=          | commit stream, per-process   |
     | (past derefs)   | =(datom/as-of db t)=                 | time-travel, O(1) construct  |
     ∴ "port the datom API onto socket assigns" = **the assign IS a session
     conn**; the view is =q=/=pull= over it. The whole API lands for free.

  5. **The soundness gate exists.** =priv/live.bl= =register-live!=: a live
     query is monotone (sound-incremental) or **refused by name**. =watch.bl=
     already implements both tiers — T1 (bare pattern → matching datoms
     incrementally) and T2a (query → re-run before/after → ={:added :removed}=).

  6. **The fact→patch shape is already proven.** =examples/datom/live/11-reactive-diff.bl=
     holds an answer set and emits ={:added :removed}= rows per commit,
     per-principal, filtering at the reader. This design points that output at
     the DOM instead of at =println=.

  7. **The reader already parses hiccup shorthand.** Verified empirically:
     =:div#app.a.b= reads as ONE keyword ={:keyword "div#app.a.b"}= because =#=
     and =.= are not reader delimiters (=@delimiters= in =reader.ex=). ∴ full
     =:tag#id.class= shorthand needs **zero reader change**; the split lives
     entirely in =hiccup->html=. (My initial "probably not reader-legal" was
     wrong; corrected by running =BeamLisp.Reader.read_all=.)

* The comparison, honestly
  | capability            | LiveView                          | this design                              |
  |-----------------------+-----------------------------------+------------------------------------------|
  | socket state          | =assigns= map (denormalized cache)| a **session datom conn** — value, as-of  |
  | view                  | HEEx template (a DSL)             | pure fn =db → hiccup= — no template lang  |
  | event                 | =handle_event= (open closure)     | an **intent term** (data, closed vocab)  |
  | diff                  | re-render template, diff *strings*| **fact-delta → keyed tree patch**        |
  | unsound incremental   | impossible to express OR prevent  | **refused by name** (=live.bl=), T1 floor |
  | value into event      | =phx-value= / form params         | =(from …)= *or* a local — cost made legible|
  | component private state| =live_component= per-cid assigns  | key-pathed locals — **no new tier**      |
  | time-travel render    | separate code path                | same =db→hiccup= fn over =as-of=          |
  Honest costs are in "Tradeoffs" below — this table is not a victory lap.

* SYNTAX (the design surface)

** 1. The view — one pure function of a db value
   No =markup= / =style= / =binds= split, no =&shell=-with-no-holes. The entire
   docs/building-an-app.md §8 footgun list is *structurally impossible* here
   because there is no shell/template division — every node is one live
   expression.

   #+begin_src clojure
   (defview board
     "A live view is a pure fn of a database VALUE and this socket's LOCALS.
      db     = the shared/session world (a datom db value)
      locals = ephemeral per-socket state (draft text, ui toggles, role)"
     [db {:keys [role draft]}]
     (let [tasks (read/board db role)]          ; ONE query → ONE consistent value
       [:main.board
        [:header
         [:h1 "Tasks"]
         [:input.composer
          {:value           draft               ; input follows the signal
           :on-input        (assign :draft (from :value))
           :on-keydown.enter (intent :create {:title draft})}]]
        [:section.tasks
         (for [t tasks]                          ; a seq in child position SPLICES
           ^{:key (:slug t)}                     ; explicit identity for the differ
           [:article.task {:data-state (:state t)}
            [:h3 (:title t)]
            [:div.moves
             (for [m (:moves t)]
               [:button.move
                {:on-click (intent :move {:slug (:slug t) :to m})}
                (name m)])]])]]))
   #+end_src

   The one rule that deletes §8: **a vector with a keyword head is an element; a
   seq in child position is spliced; anything else in child position is text.**
   Kills "nested list throws not-markup", "bind must attach to a pre-existing
   empty container", "&shell holds no holes", "render the field not the row" —
   none can arise.

** 2. Events — closed vocabulary, three heads (data, never closures)
   #+begin_src clojure
   [:assign  path source]   ; mutate THIS socket's LOCALS — never the db
   [:intent  op payload]    ; request a FACT — becomes a transact!, host performs
   [:navigate target]       ; change this socket's route/params (locals-level)
   #+end_src
   Same discipline as the contract handler (=building-an-app.md= §7): a body is
   data walked by a closed interpreter; an unknown head is refused by name. A
   model may propose a view and its intents are auditable.

*** The inversion that is the whole concurrency model
    - =[:assign …]= renders **immediately** (socket-local; no other viewer cares).
    - =[:intent …]= does **NOT** render. It =transact!=s and returns. The commit
      lands as =[:datom/changed basis]=; the =handle-info= re-projects. ∴ N
      viewers converge on one fact, and a dropped patch replays via =(since db t)=
      (the =00-README= guarantee).
    In one line: **local mutation renders here; fact mutation renders everywhere,
    through the log.** LiveView's event→assigns→render never leaves one process;
    here the loop closes through the durable log.

*** Two ways a value crosses the seam — [DECIDED: keep BOTH]
    | you write            | captured                    | server sees between events? | cost                    |
    | =(from :value)=       | at event time, off the DOM  | no                          | zero until fire         |
    | a local (via =assign=)| continuously, server-held   | yes                         | round-trip per keystroke|
    =(from …)= = LiveView's =phx-value=/form serialization (fire-and-forget). A
    local is for a value the server needs *between* events (live validation,
    char counter, enabling a button); =:value= then follows the local, which is
    what closes §8's "firstsecond" bug by construction. Rule: **need it
    server-side before the next event → local; only at fire time → =(from)=.**
    Both kept because they have genuinely different costs; hiding either rebuilds
    a §8-style footgun (user decision).

** 3. Bind a view to a socket — a real supervised gen_server
   #+begin_src clojure
   (deflive board-socket
     :view    board
     :session {:schema read/ui-schema}   ; ← opens a SESSION conn (in-memory ETS)
     :shared  myapp.store/conn           ; ← the durable/shared world conn
     :listen  {:payload :basis})         ; §6.1 case A: a basis is all a re-render needs
   #+end_src
   =:session= is the new idea and the answer to the user's second question: the
   socket opens its OWN in-memory conn =(connect-with (store-ets/open) schema)=,
   owned by the socket process (self-cleaning on disconnect). The view's =db=
   argument is a **composed value**: shared world + session overlay (see
   "Composing shared + session" below). Locals that are richer than scalars
   (a cart, a wizard, an undo stack) become *datoms in the session conn* — and
   inherit =q=, =pull=, =as-of=, =watch= for free.

   =deflive= expands to a =defserver= (genuine =gen_server=; =:observer=/=:sys=
   see it), one per viewer:
   #+begin_src clojure
   (defserver board-socket
     (init [ctx]
       (let [shared  (:shared ctx)
             session (datom/connect-with (datom.store-ets/open) (:session-schema ctx))
             _       (datom/listen! shared  {:payload :basis})
             _       (datom/listen! session {:payload :basis})   ; local edits re-render too
             db      (composed-db shared session (:params ctx))
             locals  (:params ctx)
             tree    (board db locals)]
         (push! (:socket ctx) [:mount (hiccup->html tree)])       ; first paint = full tree
         (ok {:shared shared :session session :locals locals :tree tree})))

     ;; the world moved (shared OR session) → re-project THIS viewer, ship patches
     (handle-info [:datom/changed basis _attrs] [state]
       (let [db   (composed-db (:shared state) (:session state) (:locals state))
             next (board db (:locals state))
             ops  (hiccup/diff (:tree state) next)]               ; keyed structural diff
         (when (seq ops) (push! (:socket state) [:patch ops]))
         (noreply (assoc state :tree next))))

     ;; a browser event
     (handle-call [:event ev] [_from state]
       (cond
         (= :assign (first ev))                                   ; local: session transact! → its listen! re-renders
           (reply :ok (apply-assign state ev))
         (= :intent (first ev))                                   ; fact: transact! shared; DON'T render here
           (do (intent/perform! (:shared state) ev)               ; commit → [:datom/changed] → handle-info
               (reply :ok state)))))
   #+end_src

*** The mount trap is closed BY CONSTRUCTION
    building-an-app.md §7 bled over "a =do!= in mount is a write per page load,
    performed twice." Here =init= has no =intent= in scope — a write at mount is
    **unrepresentable**, not merely refused. Intents live only in event
    attributes, which fire post-connect.

** 4. Composing shared + session — [OPEN, W4]
   The view's =db= is one value combining the durable/shared world and the
   per-socket session. Two candidate mechanisms, both already in the tree:
   - =store-overlay= — a read-through store (session buffer over shared base).
     Reads consult session first, fall through to shared. But overlay is built
     for *speculative writes over ONE base store*, and here shared + session are
     two independent conns with independent bases/writers. Needs thought:
     overlay wants a base *store*, not a base *conn value*.
   - **Two db values, explicit join in the view.** =(board shared-db session-db
     locals)= — the view reads each where it needs it. Simpler, no new store
     type, and honest that they are two worlds. Leaning this way for W1;
     overlay-fusion is a W4 optimization if a unified =db= proves ergonomically
     necessary.
   DECISION DEFERRED to W4 — W1 ships the two-value form.

** 5. Tier gating collapses to ONE DOM path — [DECIDED: auto-degrade]
   Earlier framing had "tier-1 vs tier-2 DOM paths." Wrong — they collapse.
   Because a row template is =row → hiccup= (pure, no db), BOTH tiers produce the
   *same* thing at the DOM: a keyed row-set diff → insert/remove/text patches.
   The tier only decides *how the row-set diff is computed*:
   - **monotone query** → =watch= T2a fires ={:added :removed}= rows directly;
     an added row renders with zero store access → =[:insert path key subtree]=.
     Incremental. (=11-reactive-diff.bl= shape, aimed at the DOM.)
   - **non-monotone query** → =register-live!= refuses incremental *by name*;
     the region re-projects =row→hiccup= for the whole region on each basis and
     the keyed differ finds the minimal patch anyway. Correct, just not
     fact-incremental.
   [DECIDED] Default auto-degrades with a one-line warning; =^:incremental=
   metadata on a =live-for= *demands* the fast path and hard-refuses by name if
   the query is non-monotone (matches repo temperament: refuse, never silently
   mis-serve). The =live-for= region is the unit of gating:
   #+begin_src clojure
   (live-for tasks (read/board-q) [db (:role locals)]
     :key :slug
     (fn [t] (task-card t)))              ; row → hiccup, NO db access
   #+end_src
   T1 (full re-project + keyed diff of a *value*) is the always-on floor:
   nobody ships an unsound incremental view; worst case is a correct re-render,
   still better than diffing rendered *strings*.

** 6. Components & reuse — a component is a function; NO third state tier
   - **Pure component = a fn returning hiccup.** ~All UI. Composition is
     function composition. Testable in isolation: =(task-card {…})= → a vector.
   - **Slots = passing hiccup as arguments.** =(panel "Tasks" (task-list db) …)=.
   - **Reusable live region** = a =live-for=/=live-view= fragment parameterized
     by query inputs (per-viewer scoping is free — the socket already scopes).
   - **Nested live socket** (=deflive= embedded) = the escape hatch for a
     genuinely independent lifecycle/crash boundary. A real child gen_server,
     supervised. Expected RARE; stated as a boundary, not a default.

*** Private component state, answered by NOT adding a tier — [DECIDED: key paths]
    LiveView's =live_component= exists to give a component private state. Here
    there are exactly two state tiers and a component gets no third:
    - durable/shared → it's a **fact** (a datom).
    - ephemeral/per-socket → it's a **local**, addressed by the component's
      **key path** (=assign= takes a path, user decision):
    #+begin_src clojure
    (defn task-card [t locals]
      (let [open? (get-in locals [:ui (:slug t) :expanded])]
        [:article.task
         [:h3 {:on-click (assign [:ui (:slug t) :expanded] (not open?))} (:title t)]
         (when open? [:div.detail …])]))
    #+end_src
    =(assign [:ui slug :expanded] …)= writes a nested locals path namespaced by
    the row key. Two cards never collide; the key path IS the namespace. No
    component-instance state tier to invent — PLAN-027's "one place for each
    thing," held honestly (state is db or socket, never a secret third thing).
    Cost, stated: a repeated stateful component must be *given* its locals slice
    (pass =locals=, address by key). More explicit than =live_component='s hidden
    per-cid assigns — deliberately, because hidden per-component state is exactly
    the denormalized cache we refuse to rebuild.

** 7. The bonus LiveView needs a parallel path for — time travel
   View is =db→hiccup=; db has =as-of=. A history scrubber is the *same fn*:
   #+begin_src clojure
   [:input.scrubber {:type "range" :max (datom/basis db)
                     :on-input (assign :at (from :value))}]
   ;; elsewhere: (board (datom/as-of db (:at locals)) locals)
   #+end_src
   §1 of the app doc already brags "=as-of= is free" for queries; this extends
   it to the whole rendered page. LiveView needs a separate historical-render
   path; here there is no second path to keep in step.

* THE WIRE — a small deterministic patch protocol
  Because keys are explicit, the differ is simple and the client is small
  (~100 lines, no morphdom heuristics):
  #+begin_src clojure
  [:set-attr path k v]           ; an attribute changed
  [:text     path s]             ; a text node changed
  [:replace  path subtree]       ; node kind changed
  [:insert   path key subtree]   ; a keyed child appeared
  [:remove   path key]           ; a keyed child left
  [:move     path key idx]       ; a keyed child re-sorted
  #+end_src
  =path= = vector of keys from root. First paint is server-rendered HTML
  (=hiccup->html=), a real page before JS; patches take over on connect —
  progressive-enhancement parity with LiveView, minus HEEx. The client keeps a
  keyed DOM index and applies ops in order.

* TRADEOFFS & honest costs (not hidden)
  1. **T1 re-project cost.** A per-update re-render + tree diff is more runtime
     work than HEEx's compile-time static/dynamic split. T2a fact-gating recovers
     it, but only for monotone queries; non-monotone regions pay T1 cost. Real,
     stated. (Mitigated: we diff a *tree with real keys*, not rendered strings.)
  2. **Closed intent vocabulary is a constraint.** No arbitrary =handle_event=.
     Deliberate (auditability, model-proposability) but a genuine restriction vs
     LiveView's open handler.
  3. **Surface is net-new.** =hiccup->html= + =hiccup/diff= + JS client + the two
     macros are ~300–400 lines. LiveView has a decade of components/slots/streams/
     uploads/JS-commands. This starts at the core loop and grows one reviewable
     capability at a time (matching the closed-vocab discipline the repo holds).
  4. **Shared+session fusion (§4) is unresolved.** W1 ships the explicit
     two-value form; unified =db= via overlay is a W4 call.
  5. **ETS atomicity gap** (=store-ets.bl=): fine for a single-writer session
     conn (one socket process), which is exactly this use — but stated.

* AUTH — the half that makes "better than LiveView" structural (verified 2026-08-29)
  LiveView has NO authorization model: it is re-solved by hand in every
  =handle_event=. Here =auth= is the SAME datalog as the query and the feed, so
  authorization is not a layer bolted on — it is the view and the write,
  expressed in the one policy language. Traced this session: =priv/auth/rls.bl=,
  =authorizer.bl=, =examples/auth/05,08=, =examples/datom/live/08-guarded-feed.bl=.

** 1. The view's db is scoped by construction — RLS ∘ view
   =read/board= runs =auth/guard='d queries (=rls.bl/inject= splices =:where=
   clauses for the principal BEFORE the query runs). A viewer's view CANNOT
   render a row they may not see — the store never selects it. Not a template
   filter you can forget; a property of the query. =05-rls-filter-your-rows.bl=:
   one app query, disjoint results per principal, forbidden rows ABSENT
   (enumeration-safe — a hidden row is not an error to probe for).
   #+begin_src clojure
   (defn board [db principal]
     (datom/q (auth/guard '[:find ?slug ?title :where [?e :task/slug ?slug] [?e :task/title ?title]]
                          [(auth/owner-filter '?e :task/owner principal)])
              db))
   #+end_src

** 2. An intent is authorized before it commits — the "may you?" gate
   =[:intent op payload]= → =auth/authorize(root-pub, token, ctx)= →
   ={:verdict :allow|:deny :why}= BEFORE =transact!=. =authorizer.bl= is a PURE
   function (same token+authorizer+key ⇒ same decision, no I/O), so the
   fact-request path has a reproducible, testable, auditable gate — the =:why=
   names which check failed or which policy matched. In the socket:
   #+begin_src clojure
   (handle-call [:event [:intent op payload]] [_from state]
     (let [decision (auth/authorize (:root-pub state) (:token state)
                                    (intent-ctx op payload))]
       (if (= :allow (:verdict decision))
         (do (intent/perform! (:shared state) [:intent op payload])
             (reply :ok state))
         (reply [:denied (:why decision)] state))))   ; NEVER commits
   #+end_src
   LiveView's open =handle_event= has nothing equivalent — every app reinvents it.

** 3. THE ELEGANT COLLAPSE — the soundness gate IS the auth guard
   =live.bl= requires a live query be MONOTONE to drive incremental DOM patches
   (a non-monotone query's ={:added :removed}= is unsound as an incremental
   feed). =auth/guard= injects a CONJUNCTIVE =:where= clause — which is monotone
   by construction (can only REMOVE rows). =08-guarded-feed.bl= states the
   property: =auth/guard ∘ datom/watch= yields a feed "INCAPABLE of delivering a
   fact the guard excludes… a property of the query, not a runtime check you can
   forget." ∴ **the tier-2 incremental path (§5) is auth-safe for FREE** — the
   very property that makes an incremental view SOUND (monotonicity, gated by
   =register-live!=) is the property that makes it SECURE (the guard clause is
   monotone). One concept, two payoffs, zero extra machinery. This is the single
   sharpest reason the design beats LiveView rather than merely matching it.

** 4. The token is the socket's identity — attenuation → shareable views free
   =deflive :session= carries a biscuit token (offline-verifiable, =02-verify=;
   attenuation-only-narrows, =03=). "Share this board read-only" = ATTENUATE the
   token and hand it over: the shared socket PHYSICALLY cannot fire write intents
   (§2 denies them) or see more rows (§1's guard is derived from the token's
   facts) — no bespoke sharing code. This is the =10-reactive-socket.bl=
   per-viewer shape, but the principal is a real CAPABILITY, not a bare string.
   =deflive= gains:
   #+begin_src clojure
   (deflive board-socket
     :view    board
     :session {:schema read/ui-schema}
     :shared  myapp.store/conn
     :auth    {:root myapp.auth/root-pub          ; verify tokens offline
               :token-from :params}               ; socket's biscuit = its identity
     :listen  {:payload :basis})
   #+end_src

** 5. Time-travel render RE-AUTHORIZES historically
   =rls.bl=: "the injected clauses carry no basis of their own… a capability
   filters a historical view exactly as it filters the present one, with no extra
   machinery." So the §7 history scrubber renders AND re-authorizes the past
   through the same functions — =(board (auth/guard … principal) (as-of db t))=.
   No second path. LiveView would need bespoke historical-authorization code.

** The one line
   =auth/guard ∘ read = the view= · =auth/authorize ∘ intent = the write= · both
   are pure datalog over values · the guard's monotonicity IS the live-diff's
   soundness gate. =08-the-gateway.bl= already shows login→capability→row-filtered
   view "on one screen"; the socket is that gateway, made live and reactive.

** Wave impact
   - W3 (=deflive=): add =:auth= — verify the socket's token at =init=, derive the
     principal/filters from its facts, gate every =:intent= through =authorize=.
   - W6 (example): a THIRD example — one board, two principals with different

** W0 — LANGUAGE FIX: reader ^{:key} metadata reaches runtime collections
   *Root cause (located this session, exact):* the READER is correct — it emits
   ={:meta {:vector …} %{key "s1"}}=. The loss is ONE compiler clause,
   =compiler.ex= =compile/2= (line ~120): it peels the =:meta= wrapper only to
   thread SOURCE POSITION (=:line/:col/:file=) into the env, then compiles the
   bare inner form, discarding author metadata. The RUNTIME already supports it:
   =FormMeta.with_meta(%BeamLisp.Vector{}, m)= stores meta in the struct's =:meta=
   field; =meta= reads it back (=form_meta.ex:43,62-66=). VERIFIED end-to-end that
   the runtime half works TODAY: =(map (fn [x] (with-meta [:li x] {:key x})) …)=
   → =(:key (meta r))= returns the keys; a keyed reconcile map builds correctly.
   Only the reader-sugar→runtime bridge is missing.
   *The fix (surgical, one clause + one helper):*
   #+begin_src elixir
   {:meta, inner, m} ->
     {pos, user} = Map.split(m, [:line, :col, :file])   ; positional vs author meta
     ast = inner |> do_compile(pos_env(env, pos)) |> stamp_line(pos_env(env, pos))
     if user == %{}, do: ast,                            ; today's path, unchanged
       else: quote(do: BeamLisp.FormMeta.with_meta(
                        unquote(ast), unquote(Macro.escape(lower_meta_vals(user)))))
   #+end_src
   =lower_meta_vals= compiles keyword/string/number meta VALUES to runtime terms
   (a =:key= whose value is =(:slug t)= must compile as an expression, not a datum
   — so the general form lowers the value through =compile/2= too; the escape-hatch
   for literal values is the fast path).
   *Acceptance:* =test/bl/reader_meta_test.bl= — =^{:key "s1"} [:li "x"]= →
   =(meta …)= returns ={:key "s1"}=; =^{:key (:slug t)} [:li …]= evaluates the
   value; positional meta (=:line=) still does NOT leak to =(= or =pr-str= (the
   existing invariant, re-asserted); =(= equality still ignores meta
   (=meta.ex:109=). Guarded by the existing parse-regression gate. This is a
   clean language improvement independent of live views (Clojure-correct
   =^{:key}= on every collection literal), so it ships first and stands alone.
   *Impact on the design:* the idiomatic view row becomes
   =(for [t tasks] ^{:key (:slug t)} [:article.task {…} …])=; =hiccup/diff= reads
   the key via =(meta node)=, with =(:key attrs)= accepted as an alias for authors
   who prefer it explicit.

*** 11 — nested socket (syntax)
    #+begin_src clojure
    (deflive board-socket
      :view board :shared conn
      :children {:analytics (child-live analytics-panel     ; own gen_server
                              :listen {:attrs #{:metric/value}}   ; own cadence
                              :fallback [:div.panel--error "analytics unavailable"])})
    ;; board renders (mount-child :analytics) where the panel goes; the child
    ;; crashing swaps in :fallback and the parent NEVER sees the exit.
    #+end_src
    *Acceptance:* headless — start the parent, force the child to crash on a
    handle, assert (a) the parent still renders, (b) the child's slot shows the
    fallback, (c) the parent's other regions still patch on shared commits.

*** 12 — optimistic reconcile (syntax)
    #+begin_src clojure
    [:button {:on-click [(assign [:optimistic (:slug t)] :done)     ; render NOW
                         (intent :complete {:slug (:slug t)})]}     ; commit; reconcile on echo
     "Done"]
    ;; the view prefers the optimistic local if present, else the committed fact;
    ;; on the [:datom/changed] echo the optimistic key is cleared → authoritative.
    ;; on [:denied] the optimistic key is cleared WITHOUT a commit → rollback.
    #+end_src
    *Acceptance:* headless — fire an intent that will be allowed: assert the
    optimistic patch precedes the commit patch and the final render equals the
    committed fact. Fire one that will be DENIED: assert the optimistic patch
    appears then is reverted, and shared conn is unchanged.

*** 13 — undo/redo (syntax)
    #+begin_src clojure
    [:div.toolbar
     [:button {:on-click (assign :at (prev-basis @locals))} "↶ Undo"]
     [:button {:on-click (assign :at (next-basis @locals))} "↷ Redo"]]
    ;; the view: (board shared-db (as-of session-db (:at locals)) locals)
    ;; :at defaults to the session conn's current basis; undo decrements it.
    #+end_src
    *Acceptance:* headless — three session edits, assert undo renders each prior
    text, redo returns to head; a NEW edit after undo forks correctly (the basis
    advances from the undone point). Rests on the VERIFIED as-of prototype.
