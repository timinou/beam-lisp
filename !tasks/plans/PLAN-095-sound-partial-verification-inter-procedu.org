* Part A — Sound partial verification (model+smt). HIGHEST PRIORITY: soundness.

** The bug (measured)

system.core/keep-translatable-multi silently drops any transition whose
next-state is :untranslatable. A server that overdraws through a helper —
(reply :ok {:balance (unchecked-sub balance amt)}) — verifies checked=true
holds=true, having proven NOTHING about the withdraw (kept=0/1). A user reads
"proven" for unsafe code. Evidence: research/anf-engines/smt_completeness.bl,
/tmp/sndprobe.bl reproduction.

** A1. Completeness signal (do first — closes the unsoundness)

- verify-process returns {:total-transitions :modelled-transitions
  :unmodelled [labels]} alongside :holds.
- When unmodelled is non-empty, :holds becomes :partial (or :checked stays true
  but a new :complete false is set), and verify-process-report RENDERS the
  dropped labels as a warning: "invariant holds for N of M transitions;
  UNVERIFIED: :withdraw (next-state not modellable)".
- Acceptance: the buggy-helper server no longer reports a bare holds=true; it
  reports partial with :withdraw named. Existing all-translatable servers are
  unchanged (unmodelled=[]). Run test/bl/system in full.
- This is the soundness fix and MUST land even if A2 does not.

** A2. Pure-helper inlining (completeness — makes more provable)

- Before translating a next-state, if it is a call to a single-clause defn whose
  ANF body is PROVEN PURE (system.footprint/fp-anf = ∅ via system.prove), beta-
  substitute the helper body and translate the result.
- Purity gate is mandatory: inlining an effectful helper would be unsound (a
  hidden effect could change state opaquely). The ANF footprint IS the
  certificate. A non-pure or non-resolvable helper stays unmodelled → A1 reports
  it. Never inline unproven.
- Acceptance: correct-inline server verifies holds=true through the helper;
  buggy-inline (no guard) verifies holds=false (overdraw caught). Prototype
  already shows the post-inline verify flips true→false.
- Recursion guard: bound inlining depth; a self-recursive helper is not inlined
  (falls to A1 partial). No fixpoint needed for A2 — depth-limited unfold only.

* Part B — Inter-procedural type inference (typed). ADDITIVE to hover.

** The gap (measured)

typed/check-source returns warnings=[] for (+ 1 (mk)) where (defn mk [] :kw):
callee returns are opaque at the surface, so cross-call type errors are
invisible. Evidence: research/anf-engines/typed_interproc.bl (worker-verified).

** B1. Return-type map over the ANF call graph

- Pass 1: for each defn, infer its return tagset over its ANF body (reuse
  typed/t-meet/t-union/tag logic; a call to an as-yet-uninferred fn is `any`).
- Pass 2 (fixpoint): re-infer with callee returns resolved from the map; iterate
  to a fixpoint with widening on SCCs (recursion/mutual recursion). Acyclic
  corpora converge in 2 passes; cycles need the fixpoint.
- Pass 3: check host-op argument constraints (erlang :+ wants #{:int :float})
  against the now-resolved inter-procedural types; emit a warning when a call's
  resolved return violates a downstream constraint.

** B2. Preserve hover/evidence (the original objection)

- Hover stays surface-position based — do NOT move typed/check-source's evidence
  table onto ANF (ANF discards columns). B1 is a SEPARATE inter-procedural pass
  that ANNOTATES warnings with the surface node's :ann :line carried through
  compilation. Two views, one truth: surface positions for hover, ANF call graph
  for cross-call flow.
- Acceptance: the (+ 1 (mk)) corpus warns with a line; single-function checks and
  hover are byte-identical to today. Sound-only preserved: an unresolved callee
  is `any`, never a false positive.

* Part C — Higher-order transparency via 0-CFA (codebase, additive)

** The unlock (measured)

Prototype research/anf-engines/cfa.bl (committed fbc1638): 0-CFA over bl-ANF
recovers call edges through higher-order parameters that both surface extraction
and single-node ANF miss. Measured on three regimes: higher-order
(apply-twice→inc2 through param f), polymorphic (run→{dispatch,dbl}, both), and
honest opacity (runtime-chosen fn → no invented edge).

** C1. Flow-graph alongside the name-graph

- codebase keeps its surface :call/* name-graph (unknown-callees, arity, impact
  need surface names — PLAN-094 established this).
- ADD a :flow/edge relation computed by 0-CFA over the ANF bodies: caller→callee
  edges including higher-order dispatch. Two graphs, two purposes: names for the
  human queries, flow for whole-program reachability/dead-code/change-impact.
- Acceptance: a dead function reachable ONLY through a higher-order call is
  correctly seen as LIVE by the flow graph (the surface graph would wrongly call
  it dead). A function chosen by runtime I/O stays unknown (no false edge).

** C2. Production hardening (beyond the prototype)

- Closures: the spike resolves top-level fns and params; extend AV to closed-over
  free variables (a fn value captured in a let, returned, stored in a map).
- Control flow: propagate AV through :case/:recv/:if branches and :do sequences.
- Cost: 0-CFA is ~O(n²) worst case. Measure on the real corpus before considering
  k-CFA/CFA2. Context-insensitivity is the honest default; escalate only on
  measured false-merge harm.
- Soundness invariant (test): the flow graph is a SUPERSET of the surface
  name-graph's resolvable edges — it never drops a statically-known call.

* Part D — Position IN bl-ANF collapses the surface/IR split (the lean win)

** The premise I got wrong

Throughout PLAN-094 I treated "ANF discards columns → position engines must stay
on surface" as a LAW. It is not. It was an unpopulated field. Measured:
- The reader captures FULL position: {:line :col :file} (swap at line 2 col 5).
- ANF's :ann already carries {:line :file} and lower.bl turns it into the cerl
  line annotation → a runtime stack frame ALREADY names file:line (verified:
  /tmp/blsrc/crash.bl:3 in a real ArgumentError trace).
- The ONLY thing dropped was :col, thrown away by compiler.bl/stamp-pos.

** The fix (committed af76b01) — one function

stamp-pos now carries :col alongside :line/:file. Verified:
- ANF nodes carry per-node column: ROOT col 1, THEN col 5, ELSE col 5.
- The :ann boundary (anf.bl validate-ann!) requires only that :ann be a MAP —
  it accepts any keys, so NO boundary change was needed.
- lower.bl reads only :line/:file, so :col rides through emission untouched;
  module validates, emits, loads, runs.
- Full system suite 139/328 0-fail. Zero regression.
- Demonstrated a column-driven CARET pointing at the exact offending
  subexpression, sourced purely from ANF :ann.

** Why this is the lean/redundancy win, not just a feature

Position-in-ANF removes the REASON the engines fork into two worlds:
- typed.bl keeps a SEPARATE evidence table {[line col] → tagset} (7 refs) and
  its own node-pos plumbing (7 sites) PURELY because it could not read position
  from the IR. With position in :ann, the inter-procedural pass (Part B) can
  annotate warnings AND drive hover from ONE structure — the evidence table
  becomes a projection of annotated ANF, not a parallel bookkeeping.
- termination.bl retains a whole SURFACE location walk (find-loops over
  typed/node-* ) solely to recover the error line/col, while its PROOF already
  runs on ANF. With :col in :ann, the surface walk collapses — one traversal,
  ANF, carrying both the proof and the caret.
- model.bl carries surface node accessors (8 sites) + core.bl delaborate
  re-renders (5 sites): the node→string→node round-trips exist to move position
  and rendering across the surface/IR boundary. A position-bearing IR removes
  the boundary.

** End-to-end doors this opens

1. Runtime error reporting with CARETS, not just file:line. The BEAM frame is
   limited to file+line, but bl owns its error printer — an error value can
   carry the crashing node's {:line :col} from :ann and render a caret at the
   exact expression. This is the highest-value user-facing win: production
   stack traces that point AT the subexpression.
2. One position channel for: compiler errors, engine warnings (typed/footprint/
   termination), hover, and runtime traces. Today these are 3-4 separate
   position mechanisms.
3. Source-mapped proofs: a :footprint or :terminates annotation (system.prove)
   now sits on a node that ALSO knows where it came from — "this allocation,
   proven at foo.bl:42:7" — enabling per-span proof provenance and incremental
   re-checking keyed on span identity.

** Production hardening (beyond the column spike)

- End-span: the reader captures start {:line :col} but not end. Add
  {:end-line :end-col} at the reader for full-range carets (underline the whole
  expression, not just a caret). Reader change, separate from stamp-pos.
- :file is nil for read_string (in-memory) but correct for file loads — ensure
  the file threads through eval paths (the env already carries :file; stamp-pos
  should prefer env :file when the meta lacks it).
- Macro-generated nodes honestly carry no position (nowhere is the true answer);
  a macro COULD forward its call-site position to its expansion for better
  blame — opt-in, later.
- Migrate typed's evidence table to read ANF :ann as the single source; keep the
  {[line col]} query API as a projection (no consumer change). This is the
  redundant-path deletion, gated on Part B landing.
