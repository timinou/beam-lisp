* DESIGN REVISION [2026-09-03] — direct emit, neutral IR for MLIR/LLVM (user directive)

Two constraints from the user reshape this plan:

1. DIRECT EMIT, NO QUOTED LAYER. The destination is compiler.bl → Core Erlang
   with the Elixir-quoted intermediate DELETED — not CE1's "second reader of the
   quoted output". CE1 (research/ce1_core_erlang, proven: 7897 forms lowered,
   142 tests / 583 assertions zero divergence, 1.7–2.0× faster) is the SHORT
   PATH that de-risks the lowering; the deep path replaces compiler.bl's
   `ast-node`/`ast-mod-call` quoted constructors with bl-ANF emission, and
   cerl.bl lowers bl-ANF → Core. When done, no `Module.create` /
   `:elixir_compiler.quoted` / `Code.eval_quoted` on the compile path.

2. bl-ANF IS THE NEUTRAL IR — it must feed BOTH Core Erlang AND the native
   MLIR/LLVM path (PLAN-080), which already lowers a bl-ANF-shaped vocabulary
   through cranelift at 76–145× (research/j1_probe, lowerers_spike). So bl-ANF
   is the single IR the whole toolbench reads (typed/footprint/system/codebase/
   opt) and BOTH backends consume. Two IR levels, one pivot:
     - bl-ANF  = HIGH IR: let·fn·apply·call·case·receive·try·do·literal·var·
                 letrec·primop, every subexpr let-bound, every symbol resolved.
                 → cerl.bl lowers ALL of it to Core Erlang.
     - j1/MLIR = LOW IR: scalar SSA (imm/add/mul/load/store) for counted numeric
                 loops. native.bl lowers the PROVEN-ELIGIBLE bl-ANF fragment
                 (footprint ∅ ∧ terminating ∧ sorts ⊆ nif-sorts) to it.
   MLIR-readiness requirements on bl-ANF shape (design so as not to preclude):
     - SSA/named: every intermediate has a name (ANF gives this).
     - per-node annotation slot `:ann` (types from typed, effects from footprint,
       source pos) — mirrors cerl:set_ann; MLIR attributes map onto it.
     - structural regions: let-nesting = MLIR region nesting; case = a region-op.
   Do NOT build the MLIR attrs now; only keep the node shape annotation-carrying.
