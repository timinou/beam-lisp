* Confirmed correctness findings
** R1 — nil? no longer follows metadata-transparent equality
Location: priv/boot/core.bl:22-25, round 4.
Trigger: w = (tuple :meta nil {}); (= w nil) is true, but (nil? w) is now false and (some? w) true. The old spelling used the language equality protocol, which unwraps metadata. The new erlang/=:= shortcut does not. Although ordinary with-meta does not construct this nil wrapper, it is an explicit checked-in semantic oracle in test/bl/leaf_cost_test.bl:42,55-57; rejecting it as unreachable would change the existing contract.
Evidence: saved cls2-beam-lisp--js-actors.log:336-342 records nil-some-not-are-exact failing. This review's Node probe of the existing generated core observes eqv(w,nil)=true, nil?(w)=false, some?(w)=true.
Next fix: retain fast identity/non-tuple checks but send tuple inputs through existing equality. Do not weaken the oracle; check keep/some? behavior in permanent BEAM and compiled-core coverage.

** R2 — SeqCursor truncates a partially realized list at its lazy tail
Location: priv/lib/js/lazy.mjs:249 and input at 253-258, introduced in the self-host/cursor-shape work.
Trigger: (let [s (reduce (fn [a x] (cons x a)) (lazy-seq (list 99)) (range 40))] (count (map identity s))). Forty eager cons cells followed by a lazy element must produce 41 mapped elements. input counts the prefix and wraps it as a finite SeqCursor; cell returns nil when the cursor reaches a non-Cons lazy tail, losing the suffix.
Evidence: this review observes current lazy library counts direct=41, through input/cursor=40; the existing generated compiled rt map+count also answers 40. BEAM input uses length with improper-list failure handling, avoiding this finite cursor conversion.
Next fix: only cursorize proper finite lists, or preserve traversal into the lazy tail with the correct cursor protocol. Use the Cons proper-length marker rather than forcing tails or guessing from a prefix. Add chunk-boundary cases <=32 and >32, empty/nonempty lazy tails, mapped/filtered/concatenated consumers, and side-effect checks.

** R3 — Number-backed bit-not loses integer bits above 32
Location: priv/lib/js/host-leaves.mjs:86, new host-leaf implementation.
Trigger: (erlang/bnot 4294967296), and core bit-not through compiled rt. Numbers store safe integers up to 53 bits, but JS ~ coerces a Number to signed 32-bit.
Evidence: current leaf returns -1; exact BigInt complement is -4294967297. The existing corpus checks bnot 5 only.
Next fix: validate integer operands, complement as BigInt, normalize safe results. Include negative and 32-/53-bit boundaries plus invalid float/decimal inputs and BEAM error parity in leaf differential.

** R4 — seeded multi-arity function identity differs across namespaces
Location: priv/lib/js/build.bl:499-501; each emitted module has its own SEEDS cache; priv/lib/js/core.mjs blfnFn allocates a fresh dispatcher for a multi-fn tuple.
Trigger: b exports (defn get-map [] map); a asks (identical? map (b/get-map)). Both registry fetches refer to the same raw seeded value, but each module adapts it to a different function, so JS identity is false rather than true.
Evidence: this review runs the exact emitted SEED recipe twice against the existing self-host registry: raw registry identity=true, repeated same-module adapted identity=true, cross-module adapted identity=false. This tests the adaptation mechanism, not a newly compiled two-namespace BL fixture.
Next fix: preserve the seeded value itself for first-class values, or share an identity-preserving adapter at the runtime level. Also define/cache-test late binding: Env fetch invalidation does not invalidate per-module SEEDS. Add permanent multi-namespace identity and redefinition tests before default cutover.
