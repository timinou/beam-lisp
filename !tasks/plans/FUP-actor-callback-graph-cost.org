#+TITLE: Measure and narrow actual actor callback admission cost
#+STATE: READ-ONLY DESIGN — no runtime changes or native measurements

* Concrete current path
Compiler's actual app callback wrapper enters Env.with_server_execution!, whose
private server owner/full ticket was authenticated at startup. Its regular
entry uses the canonical ticket anchor and native owner membership. The input
hook then calls proc.contract/check-entry!; that requires execution/owned?,
which calls Env.executing_generation? and Env.execution_origin.

Current priv/host/env.bl execution_origin constructs MapSet/new from the entire
lease module list, converts G.modules with Vector/to_list, and checks every
module before accepting the private server extent. This is O(graph module count)
BEAM work for every hook, including fixed SDK callbacks retaining app G.
No extra NativeMemo/Atom cells does NOT mean no allocation, constant latency, or
allocation-free execution. No measured overhead or speedup is claimed here.

Exact review points: priv/boot/compiler.bl server-input-check/server-execution-body;
priv/std/proc/contract.bl check-entry!; priv/std/reload/execution.bl owned?;
priv/host/env.bl with_server_execution!, server_origin_live?, execution_origin,
executing_generation?. These sources remain frozen for the coherent floor.

* Narrow possible O(1) native server extent proof
The candidate fast path is an exact private native server execution extent,
not a public context flag. At actual authenticated registration, attest full
G.module set equality, exact graph/scope/class/owner and complete self-owned
physical ticket once. At callback entry reuse that immutable private identity,
canonical complete-ticket mutation anchor, actual owner membership and current
public G/scope equality. A regular entry must reject a logical release. An
already admitted extent may continue under its physical ticket until return;
terminate has only the existing exact private original-context cleanup law.

Only this genuine server-specific proof can avoid rebuilding the module set.
Generic task/callback execution must retain its own full-graph validation unless
an equally strong separate native proof is established. Marker-only evidence,
subset leases, namespace spelling, runtime SDK class names and Env.bind tokens
cannot create the fast path. Preserve fixed SDK adoption and accepted source
init extents through actual physical ticket release/DOWN.

Required native negative controls: copied context; copied/subset/extra-module
G; wrong scope, class, PID, lease or ticket; nested/borrowed wrapper action;
retention without admitted execution; transferred/released ticket; concurrent
external unregister/adoption; owner death; nil-G/foreign-scope bind; released
regular entry; and terminate before/after logical close. Actual authenticated
unmanaged nil-G development must retain its current behavior. No second whole
app lease per message, remote process-dictionary copying or mutable boolean grant.

Moving Proc.Contract class membership before owned? would skip work for SDK
callbacks, but would also let a bare copied context return :ok today. The current
explicit unowned SDK negative must keep refusing. A reorder alone is therefore
not the fix; an exact existing native admission proof must still be required.

* Read-only helper/epoch and first-load review
proc.input-domain/clause binds the global publication epoch across analysis;
system.publication/snapshot retries its own namespace read once. A first lazy
SDK definition publication during analysis can conservatively yield
:input-proof-unstable and retained-drain; clause itself does not retry. This is
an identified possible false-unknown path, not an observed runtime failure.
Normal require dependencies are initialized before the analyzer is invoked;
no extra eager application preload is proposed.

Runtime validity uses Env.namespace_generations for actual helper/binding
namespaces plus core/sugar, and native helper/remote MD5s. It does not compare
the global publication epoch on every message. Env.publication_key deliberately
excludes :per_env_instance rows, so ordinary per-environment materialization
alone does not invalidate definition certificates. An unrelated new SDK
namespace normally leaves those named epochs unchanged; unknown bulk mutation
increments :wide and invalidates them. First-use code that actually extends
core/sugar does invalidate existing proofs, even where that is conservative.

A genuine stale proof refuses before the handler; runtime code does not silently
recompute evidence or grant adoption. The final ordinary native actor suite must
establish cold first-use behavior, actual helper mutation refusal and zero new
NativeMemo cells separately. The latter is not a BEAM allocation measurement.

Epoch/code checks are point-in-time observations. Supported sealed app and fixed
SDK immutability/physical leases are still required; this does not prove atomic
protection against an arbitrary trusted native publisher racing after the check.
Ordinary actors remain retained-drain: state/message/reply migration, accepted
work and native owner/head authority are separate requirements.
