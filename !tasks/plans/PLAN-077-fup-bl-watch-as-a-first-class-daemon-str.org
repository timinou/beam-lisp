Deferred from PLAN-075 S5. The daemon-side mechanism is DONE:
BeamLisp.Daemon.WatchRegistry hosts one ReloadWatcher per canonical dir and
routes every stage->commit through the Executor FIFO (ordered against
runs/tests), with subscriber fan-out. Tests green (daemon_watcher_test 4/4).

What remains is the client-facing streaming UX: `bl watch DIR` against a warm
daemon should register with the WatchRegistry and stream `:watch` result frames
to the client's tty (staying subscribed until Ctrl-C), instead of the current
standalone `cmd-watch` that runs its own foreground VM. Requires: (1) the
executor/listener to treat a `watch` request as a long-lived subscription rather
than a one-shot FIFO command, (2) `:watch` frames wired through the launcher's
stream loop (the ETF decode already ignores them), (3) bl.daemon/handle to
special-case `watch` → registry registration keyed by {conn, id}, unsubscribe on
disconnect.

Also: windows daemon transport (named pipe) — AF_UNIX is unix-only, so on
windows `bl` always cold-boots today. And an auto-update channel feed (the drop
trailer is already version-tagged).
