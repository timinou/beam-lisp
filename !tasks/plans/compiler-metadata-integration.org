* Measured problem and compatibility boundary
Link.defvar currently calls ns_defs before deciding whether to rebuild its shim.
A forwarded definition therefore copies all earlier ASTs through ETS despite
compiling only one body. Existing selected metadata/publication optimizations do
not remove this copy. Preserve the full-map API and whole-namespace env shadowing.

* Candidate representation
Keep lazy AOT module-literal descriptors. For live incremental metadata, use a
constant-size namespace descriptor plus separately keyed definition entries.
Transition an inherited/map/literal table once; update only the new definition
and descriptor count afterward. Rebuilds may explicitly materialize the full map.
Full replacement, undefinition, shim detachment and destruction must reclaim rows.
Publish generation-tagged replacement entries and their descriptor in one ETS
batch. Incremental entry/count publication must also be one atomic batch. A lock
is released when its writer dies; sequential row edits under that lock alone are
not crash safe. Cleanup before/after replacement must bound retired generations
and tolerate interruption without deleting the currently visible generation.
No process dictionary or app-managed metadata is authoritative.

* Concurrency gate before adoption
Mutable rows require readers and writers to share the namespace publication lock.
A full read must not assemble entries across concurrent replacement/undefinition.
Use one reentrant helper for Link, AOT and Env operations: OTP global/trans does
not count nested acquisition by the same requester, so an inner raw trans releases
the outer lock early. A private process-local depth guard must never cross convey.
Selected reads can lock without copying unrelated ASTs. Optional certification
continues to decline during publication. Measure lock overhead and contention.
Environment destruction racing publication also requires an explicit test; do not
infer safety from happy-path fork tests.

* Validation and refusal
Prototype whole-table shadowing, empty own table, undefinition, full replacement,
AOT detach in multiple envs, interrupted writers, concurrent readers and destroy.
Use Veritas replay plus actual runtime barriers; finite histories are evidence,
not universal proof. Measure returned bytes, reductions and scaling separately.
Only integrate after the representation and lock protocol pass these gates.
Regenerate the official host seed and rebuild the clean SDK before app adoption.

* Destruction protocol refinement
Proposed scope commit lock is separate from namespace compilation locks. The
namespace lock always precedes the short scope commit lock; destruction takes
only the scope lock. Never acquire namespace locks from a destruction callback.
Check the existing ETS definition_lifetime inside the commit lock. A writer whose
scope has retired must fail or decline without registering a new scope. Full
metadata reads use the same short scope lock to exclude destruction while
materializing entries; selected reads retain whole-namespace shadowing.

For deletion, atomic insert of a tombstone plus descriptor count preserves the
full-map contract if a writer dies between publication and physical deletion.
A single pending tombstone name in the constant descriptor lets the next mutation
reclaim interrupted deletion without scanning the whole namespace on every def.
Replacement publishes all new-generation entries and its descriptor atomically;
cleanup excludes the visible generation and occurs before/after publication.
Bound abandoned generations and validate killed writers at both boundaries.
This refinement is a design proposal, not implemented storage or a proved fence.
