* Authorization and isolation

* Implementation sequence
1. Central immutable database view identity and safe auth memo reuse; preserve callers.
2. Authorized ordered paging with bounded substrate work, provenance and honest outcomes.
3. Automatic supported-query dependency capture and bounded reuse; unknown stays baseline.
4. Incremental models and live dependency consumption with expiry/fairness safeguards.
5. Adopt upstream mechanisms in Knowledger; remove redundant app mechanisms when parity holds.
6. Integrate verified structural compiler fixes without losing current bootstrap/native fixes.

* Contracts
Existing q/from/pull and auth syntax remain usable. No developer-provided purity or
completeness flag is authority. Store identity, schema, temporal view, inputs,
principal and permission expiry participate where relevant. Empty reads matter.
Permissions precede page admission. Partial results never claim exactness.
Retention and work are bounded. Unknown providers/effects remain conservative.

* Validation
Serial checkout VMs under memory/swap/time limits, inspect memory first. Focused
parity, negative controls and work counters before browser acceptance. Record actual
receipts and limitations here; no production deployment is implied.
