* Ownership and integration
The reusable implementation is =priv/std/reload/generation.bl=. Applications
declare one router entrypoint and the fixed runtime boundary; no per-function
generation manifest is needed. =project-plan= follows the native loader's
source graph. Foundry owns artifact authorization, durable activation decisions,
multi-owner compatibility, durable-job drainage and deployment policy.

* Implemented design
- =plan= validates source closure, namespace names, immutable resource data,
  cycles, explicit native/stable dependencies and dynamic-code refusal.
- Native reader stream slices rename declarations, require targets and direct
  qualified calls. Aliases resolve to fresh providers; comments, Unicode,
  strings and quoted symbols stay intact. Transitive helpers are versioned.
- =prepare!= reconstructs canonical input, compiles into a dedicated scope,
  audits the actual ANF graph after macro expansion, and freezes its namespaces
  against ordinary reload. Per-instance provider names prevent scope collisions.
- =slot/publish!/call!= separate short admission/publication fences from handler
  execution. Independent HTTP requests execute concurrently. Publication honors
  the existing native production reload policy and compares the prior digest.
- =capture!/run!/transfer!/release!= retain delayed work's complete graph and
  generation resource context. Executing callbacks hold their own native leases.
- =env/capture/bind= now convey =:bl_generation= through existing native worker
  callbacks and restore the previous worker context afterwards.
- Generation context includes sealed queue protocol versions, automatically
  stamped with its code digest, so an old producer cannot adopt a new queue
  declaration merely because publication occurred between calls.
- =evidence/retire!= report managed obligations and use native soft retirement,
  refusing collection while a slot, callback or executing lease still needs code.

* Exact boundaries
This is a conservative online graph facility, not a source sandbox. Sources
must use top-level =ns/defn/defn-=; mutable top-level globals, initialization
effects, dynamic code lookup, raw process/timer creation and listener creation
are rejected. Reader-prefix expansions unsupported by the source transform
also refuse; source is never guessed or silently rewritten. Supporting application startup
requires a separate initializer/resource lifecycle contract. A fixed runtime
namespace/native-module boundary is trusted and must remain fixed throughout
an application upgrade. Runtime replacement is a separate protocol.

An unregistered raw spawned closure is not proof of safe retirement. Foundry
must close registration inventory and durable-message obligations before it
calls retirement. This module provides no transaction across unrelated process
owners and makes no claim about persisting an activation decision across VM
restart; those are coordinator responsibilities.

* Admission and retirement hardening
=Env/retire_modules!= takes sorted physical module locks and preflights every
native executable lease before deleting any graph member. A native registration
that retains only the router therefore protects its unleased helpers from
partial retirement. =with-retirement-fence!= holds managed old admission while
the coordinator persists durable queue fences and attempts native retirement.
=with!/invoke!= execute candidate framework/domain work before serving
publication, keeping returned batch closures under the same complete graph
lease until their writer turn finishes. =selected= reads serving identity under
the admission lock.

Fresh namespace/module atoms cannot be reclaimed by the BEAM. A persistent,
node-lifetime budget admits at most 256 new prepare attempts and 4096 managed
namespace instances, also reserving 65536 atom-table entries as headroom.
Identical live prepared graph reuse costs no new admission. Failed preparation
consumes its reservation; retirement does not replenish it. Exhaustion refuses
with =:runtime-handover-required=. This bounds this facility's lifetime growth;
it does not claim infinitely many hot deployments or budget unrelated runtime
atom producers. =capacity= exposes the budget and a pure admission decision.
