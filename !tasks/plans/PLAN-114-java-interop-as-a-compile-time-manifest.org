* Why

Unmodified Clojure libraries reach the JVM through four syntactic doors: `(.method obj args)`,
`Class/static`, `(Class. args)` and `:import`. beam-lisp has none of them as *method dispatch*
today — `(.x o)` reads a DEFTYPE field and nothing else (`priv/boot/compiler.bl:546-560`
`deftype-field-name`; the call branch at `compiler.bl:676-682` requires exactly 1 arg),
`Foo/bar` is a capability-gated HOST call to `Elixir.Foo` (`compiler.bl:332-368`
`slash-target`, `gate-remote!`), `Foo.` and `new` and `..` do not exist.

Decision (user, 2026-09-14): **C1 — a closed compile-time manifest**, ptc_runner-shaped
(`priv/java_interop.exs` in andreasronge/ptc_runner 0.15.0: `references`/`classes`/`overloads`;
closed dispatch in `lib/ptc_runner/lisp/java/dispatch.ex`). The manifest is the *only* thing
that makes a Java name mean something; an unlisted class/method is a **compile-time** error
naming the class and method, never a runtime "undefined". And the **beam-lisp maximalist rule**:
every manifest entry projects onto a native beam-lisp value and, wherever there is polymorphism,
onto a **protocol** dispatched by `BeamLisp.Multi.type_of/1` (`lib/beam_lisp/multi.ex:45-66`) —
never a Java-shaped object model, never a second numeric tower, never strings-as-classes.

This plan is scoped by measurement, not by the JDK. Target: kontor kernel + substrate, 73
namespaces (`/tmp/kontorlive`), full interop census below. Out of scope: kontor's 47 modules
(PDF/XML/CSV, `java.io` streams, threads, reflection).

* Design

** D0 — one representation rule
Every Java class in the manifest resolves to exactly one of:
1. a **BEAM builtin** already meaning the same thing (`Date`/`Instant` → integer epoch-ms, which is also datom's `:db.type/instant`, `priv/lib/datom/schema.bl:250-255`; `String` → binary; `Long`/`Integer`/`BigInteger` → integer; `UUID` → binary of the canonical 36-char form, tagged by a protocol impl not a wrapper), or
2. a **beam-lisp record** defined in the shim namespace with `defrecord` (a real Elixir struct, `lib/beam_lisp/record.ex:90-108`) so `type_of` yields its module and protocols extend on it: `Decimal`, `LocalDate`, `Formatter`.
No `{:java-object …}` wrappers. No class registry at runtime. No reflection.

** D1 — the Decimal type (the biggest single piece; 165 of 250 method sites)
`(defrecord Decimal [unscaled scale])` in new ns `decimal` (`priv/lib/decimal.bl`). `unscaled` is a BEAM integer (unbounded — the JVM `BigInteger` is free here), `scale` a non-negative integer. This is exactly `java.math.BigDecimal`'s model and exactly kontor's own cljs lane (`money.cljc:34-125`, `fress Bigdec` = unscaled js/BigInt + scale) — so **kontor's cljs arithmetic is the reference implementation**, byte-for-byte checkable against the JVM oracle.

Exact API (all pure, all take/return Decimal unless noted; rounding modes are keywords):
- construct: `of` (int | float-REJECTED-with-ex-info | string "123.45" | Decimal), `ZERO`, `ONE`, `TEN`, `parse` (string, raises `:decimal/parse` for the `NumberFormatException` mapping)
- arithmetic: `add`, `sub`, `mul` (scale = s1+s2, exact), `div` (a b scale mode — the only rounding division; `div` without scale raises `:decimal/non-terminating` unless exact, matching `BigDecimal.divide(x)`), `neg`, `abs`, `signum`, `rescale` (scale mode), `strip-zeros`, `move-point-left`, `move-point-right`
- compare: `compare` (scale-insensitive, like `compareTo`), `=` MUST remain value-equal on the record, which means `1.0M ≠ 1.00M` — same as Java `equals` — and `==`/`compare` are the numeric equivalences. Extend core `compare` via protocol so `sort-by` works.
- convert: `->double`, `->long` (truncates; raises on overflow? no — BEAM ints don't overflow, so `->long` = `->int` = truncate), `plain-str`, `scale`, `unscaled`, `precision`
- rounding modes: `:half-even :half-up :half-down :ceiling :floor :down :up :unnecessary` implemented once in `round-unscaled` over integer `div`/`rem` (the cljs `bd-round` at `money.cljc` is the template)
- **printer**: `pr-str` of a Decimal prints `123.45M` so round-trips read; `str` prints plain. Extend the printer protocol (find where `pr-str` dispatches on structs — `lib/beam_lisp/printer.ex`).
- **reader**: `M` suffix on a numeric literal → `(decimal/of "…")` at read time (`reader.bl` `whole-number`/`classify`). Also `N` suffix → plain integer (BEAM ints are big). This is the one reader change in this plan.
- **numeric tower integration** — the maximalist part: extend core arithmetic so `(+ dec dec)`, `(- dec)`, `(* dec int)`, `(< dec dec)`, `zero?`, `pos?`, `neg?`, `compare`, `max`, `min` work on Decimal. Today `+ - * /` are seeded prims folding through `Kernel.+` (`rt.ex:2407-2424`) with direct-call links to `:erlang` BIFs (`rt.ex:2800-2840`). Mechanism: a `Num` protocol (`-add -sub -mul -div -neg -compare -zero?`) with the prims' *slow path* dispatching to it when either operand is not an integer/float; the BIF links stay for the int/float fast path. Mixed int+Decimal promotes the int (`of`). float+Decimal RAISES (`:decimal/inexact-operand`) — the JVM does the same (`ArithmeticException`? no — JVM `(+ 1.5 1M)` yields double; but kontor rejects doubles explicitly, `money.cljc:164-176`, so raising is the stricter, safer choice; document it).
  `rt.ex:1524` `decimal?` currently hard-false → becomes `is_struct(x, Decimal)`.
- deps note: `deps/decimal` (the Elixir hex `Decimal` lib) is present as a transitive dep. NOT used: it carries a context/precision global (`Decimal.Context`) and its own rounding names; projecting onto it would inherit that global — the exact wart the user ruled out. The record above is ~300 lines of bl and it is the language's own.

** D2 — `.method` dispatch: a new compile branch, closed over the manifest
In `compile-call` (`compiler.bl:608-710`) insert, BEFORE the deftype-field branch at 676:
- head symbol starts with `.` and is NOT `.-` and the **manifest has a method row for that name** → compile to `(manifest-fn receiver args…)`. The receiver's *class* is not known statically (Clojure has no types), so the manifest row is keyed by **method name**, and its target is either (a) a single fn when the name is unambiguous across the 15 classes, or (b) a **protocol method** when two classes share a name (`compareTo`: Decimal vs Date-integer; `add`: only BigDecimal in this census but `LocalDate.plusDays` etc. are distinct names). Protocol dispatch is beam-lisp's own (`Multi.dispatch_protocol`), so the runtime cost is one `type_of` — no reflection, no class table.
- head symbol starts with `.-` → existing deftype field path, unchanged (`.-a` on a datom vector must ALSO work — PLAN-datahike adds `.-e/.-a/.-v/.-tx` rows that project to vector `nth`; the branch order is: manifest row first, then deftype field).
- head symbol `.x` with 1 arg and NO manifest row → existing deftype-field behaviour (preserves every current `.bl` file). With >1 arg and no row → compile error `"no Java method .x in the interop manifest"` naming the ns/line.
- `(Class. args)` (trailing dot) → manifest `ctor` row or compile error. `(new Class args)` → same.
- `Class/static` and `Class/CONSTANT` → today `slash-target` treats an uppercase prefix as `Elixir.Class` host module. New rule: **if the prefix is an imported class alias (from `:import`) or a fully-qualified class in the manifest, consult the manifest first**; else fall through to today's host-module behaviour. Statics compile to the target fn/value directly — `RoundingMode/HALF_EVEN` becomes the literal `:half-even` at compile time.
- `:import` in `ns` (`compile-ns`/`ns-clauses`, the W2 work): `(:import [java.math BigDecimal RoundingMode])` and `(:import java.util.Date)` register **class aliases** in the compiling ns: `BigDecimal` → `java.math.BigDecimal`. Unknown package/class → compile error with the manifest's known list. This is the same 24-namespace blocker measured in the triage (`ns supports only :require`) and it is where `:refer-clojure :exclude` lands too (an `:exclude` list = names the ns's own `def`s may shadow without the "redefining core" warning/refusal — find the current refusal path in `compile-def`).
- Type hints `^BigDecimal x`: reader meta; compiler must drop symbol hints it cannot resolve (verify current behaviour in W0; the 185 `^java.math.BigDecimal` hints must be a no-op, not a resolution attempt).
- `catch` mapping (`compiler.bl:1319-1356`): manifest `exceptions` rows: `Throwable`/`Exception`/`RuntimeException` → untyped catch-all; `clojure.lang.ExceptionInfo` → `BeamLisp.ExInfo`; `NumberFormatException` → ExInfo with `:type :decimal/parse`; `ArithmeticException` → `:decimal/non-terminating`. Unlisted class → compile error.

** D3 — the manifest itself
One data file `priv/lib/java/manifest.bl` (bl data, read at boot like `priv/boot/data-readers.bl`), shape:
```
{:classes  {java.math.BigDecimal {:type decimal/Decimal
                                  :ctor decimal/of
                                  :statics {ZERO decimal/ZERO ONE decimal/ONE valueOf decimal/of}
                                  :methods {add decimal/add subtract decimal/sub … compareTo Comparable/-compare}}
            java.math.RoundingMode {:statics {HALF_EVEN :half-even DOWN :down …}}
            java.util.Date {:type :integer :ctor now-ms :statics {from identity}
                            :methods {getTime identity before < after > compareTo compare toInstant identity}}
            java.time.LocalDate {:type time/LocalDate :statics {parse time/parse-local-date}
                                 :methods {getYear time/year … plusDays time/plus-days atStartOfDay time/start-of-day}}
            … (all 15)}
 :exceptions {Throwable :any Exception :any clojure.lang.ExceptionInfo BeamLisp.ExInfo NumberFormatException [:ex-info :decimal/parse]}
 :methods-by-name <derived at load: name → single target | protocol>}
```
Closed set, versioned, loaded once; the compiler consults it via one fn `java.manifest/method-target`. Adding a class = adding a row + its bl implementation + a conformance test against the JVM oracle. **No entry without a differential test** (the `clojure -M -e` oracle harness from the reader work, `/tmp/rc_*` method, generalised to `test/beam_lisp/java_oracle_test.exs`).

** D4 — java.time, minimal and honest
Kontor's `:clj` lane uses: `LocalDate` (parse/year/month/day/plus{Days,Weeks,Months,Years}/atStartOfDay), `Instant` (= epoch-ms), `ZoneOffset/UTC` only, `atZone`→`toLocalDate`, `DateTimeFormatter/ofPattern` (2 sites — read the patterns in W0; if they are `yyyy-MM-dd`/ISO only, `formatter` supports exactly that subset and raises on anything else), `ChronoUnit` (1 import; find use in W0). Projection: `(defrecord LocalDate [year month day])` in `priv/lib/time.bl`?? NO — datom already owns temporal values (`priv/lib/datom/time.bl:137+` Interval, ISO-8601 reader). Put `LocalDate` and calendar math in a new `calendar` ns that datom.time can also use; `:db.type/instant` stays integer ms. Calendar math (plusMonths end-of-month clamp, leap years) is the classic bug farm → oracle-tested against the JVM for a 200-date matrix. Zones other than UTC: **rejected at compile time** (`ZoneId/of` not in manifest).

** D5 — rejected / rewrite-required (say so in the compile error)
- `java.util.Calendar` + `TimeZone` (2 files): mutable calendar; replaced by `calendar` fns. The compile error names the file and says "use calendar/…".
- `AtomicLong` (1): `(atom 0)` + `swap! inc` — the manifest maps it (ctor → atom, `incrementAndGet` → `swap! inc`, `set` → `reset!`) since it is pure sugar.
- `.getBytes`/`StandardCharsets/UTF_8`: binaries are already UTF-8 bytes → identity, `:utf-8` ignored.
- `java.io.File`, threads, `locking` (1 site — becomes a no-op macro with a warning; BEAM has no shared mutable memory to lock), `future` (18 — beam-lisp HAS `future`, `rt.ex:2533`).
