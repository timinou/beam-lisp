* Findings and chosen consolidation
** Compiler evidence and safe reuse
Actual codebase/dependency-cone finds qualified cross-module edges and refuses
unknown callbacks. system.analyze propagates effects; system.incr currently
caches LOCAL summaries only. The prototype changed a leaf while its caller
remained a local cache hit; dirty-set correctly included both leaf and caller.
Read-only footprint {state R} admitted by footprint/pure? still returned 1 then
2. Therefore graph completeness + typed shape + read-only is not a reuse proof.

Implement one publication-time evidence registry consumed by system.prove,
query planning, loader and render admission: normalized compiler IR identity,
compiler/runtime generation, closed dependency cone, effect/resource summary,
termination/work evidence and explicit unsupported reasons. Use old AND new
reverse graphs, deleted definitions and SCC fixpoints. phash2 alone must never
be authoritative equality. Unknown callbacks and resource identity conservatively
miss. Existing source call graph is useful discovery, not expanded compiler IR.
Do not run whole-corpus dependency-cone or SMT per render.

** Concrete proof-gate defect
system.smt/sort-of-tags documents ambiguous tags as unknown but #{:int :string}
currently maps to Int. Actual native.eligible/eligible on
(defn choose [x] (if x 1 "text")) returns eligible true, sort Int.
A prototype gate requiring a singleton supported tagset rejects that same
summary. Fix the shared sort functor upstream; audit system.core and native
consumers and prove mixed/compound/any refusal plus existing singleton cases.
No actual native kernel execution or memory-safety exploit demonstrated here.
Production libraries remain unchanged by this research branch.

** Physical user/firm scoped pagination
A fixed-shape tuple AVET prefix derived from the EXISTING vector codec (strip
only the closing terminator of a partial tuple) reads five firm7 rows on both
ETS and Fjall. Growing firm8 rows 32 ->160 changes neither returned rows nor
charged bytes: ETS6650, Fjall26970. These are backend charges, not comparable
resident memory or latency measurements. Naive encoding of [firm] yields zero
rows because a complete partial vector is not a component prefix.

Implement a typed compound-bound API in datom.codec/index, and planner admission
in datom.query.page when schema proves tuple arity, component types/cardinality,
ordering/ties, root uniqueness and complete derivation coverage. Authorization
must still filter before pagination, including multi-user overlapping policies.
Infer physical scope from the authorized handle/planner; developers should keep
ordinary queries. Foreign-row independence does NOT imply total-query independence:
COUNT, joins, permissions and residual filters remain outside this experiment.
Installing tuple schema after one existing entity produced zero derived rows:
conn/derived need versioned derivation backfill before compound admission.

** Durable index publication/recovery
Unsafe Veritas recovery shrank to [schema,reopen]. Guarded recovery was witnessed
for250 histories, seed17, max-len20, all five commands covered. SMT found unsafe
SAT and guarded UNSAT for the explicit Boolean/scalar publication obligations.
This is a restricted abstract protocol, not proof of filesystem durability.

Implement hidden shadow generation with build intent, schema/derivation epoch,
base basis, durable progress and coverage certificate. Reopen refuses incomplete
or mismatched coverage and resumes/rebuilds. Publish only after complete history
and post-snapshot deltas are committed with the certificate. Reuse datom.projection
and reconcile's existing pending-intent/stale lifecycle where appropriate rather
than creating a second general lifecycle framework. Actual production hooks:
datom.conn schema install/recovery, datom.derived, store ETS/Fjall capabilities.
Validate actual process termination between batches/publication/fsync, reopen,
concurrent writes/retractions, same-flag retry, schema epoch changes and cursor
refusal; only then benchmark migrated large cold data. Not implemented here.

** Shared retained-data budgets, not a VM collector
Unsafe accounting shrank to [publish4,timeout,publish7]: queued11 exceeds limit10
because caller timeout forgot the first queued4. Guarded accounting witnessed250
histories, seed17, max-len20, all four commands covered. Scalar SMT safe admission
is UNSAT for overflow; unsafe timeout admission is SAT. Actual Datalog policy
keeps queued6 for a live owner, reclaims dead caller's UNSENT3 and dead owner's4.
Actual veritas.ledger stored four witnessed/refuted verdicts.

Implement atomic global reservations across registered bounded-cache owners,
with explicit reserved/enqueued/retained/released ownership and process monitors.
Dead caller before send releases unsent intent; dead caller after send does not
release until owner acknowledges/discards or dies. Admission must charge key,
value, owner metadata and retained sub-binary parents. Reserve before enqueue.
Datalog expresses policy and diagnostics; compile/index policy and use cheap
atomic accounting on admission, never a whole fact query on every hit.
BEAM process GC and unregistered VM/native allocations remain outside the bound.
Validate actual kill/timeout/scheduler races, multiple owners, duplicate release,
restart/epoch reuse and large sub-binaries. Model units are synthetic, not MB.

** Runtime render validity
Prototype combines actual datom.cache-validity/read-stamp with explicit principal,
policy generation and expiry. An empty query with historical attr mark remains
reusable across an unrelated write and misses on first current insertion. Principal
switch, policy change and exact expiry all miss. Missing attribute markers fall
back to basis (more conservative invalidation), not missing-dependency reuse.

Implement dependency collection at authoritative reads and model/render entry
boundaries; publication-time eligibility supplies allowed read classes. Include
store/view identity, temporal filters, inputs, exact code dependencies, principal,
policy and earliest clock boundary. Unsupported I/O/dynamic resource reads refuse.
Existing q reuse is query-local; this certificate prototype does NOT automatically
cache full renders or hook every application read. Differential uncached rendering,
empty joins/negation, as-of/since, auth revocation, reload, clock rollover and
unknown callbacks are required before automatic adoption.

* Other unfinished work outside these executable prototypes
- Cold loader/realms: namespace planning alone does not remove compile cost. Compare
  genuinely cold staged builds and warm shared realms with identical authority;
  realm branch exists but one-VM-per-user/build and automatic startup are unfinished.
- Route interruption: queued pure navigation already coalesces upstream. Do not
  count that as a new win. In-progress expensive rendering needs generation-based
  discard/cancellation while preserving writes and barriers; validate side effects
  and browser address-bar-to-visible-page latency. Not prototyped this turn.
- Full incremental rendering: existing entity-local watch deltas do not incrementalize
  every model, HTML diff, count or join. Start with declared supported fragments and
  differential oracle, not an arbitrary transparent memoization rewrite.
- deodorant/codebase detect actual helper-mediated N+1 in the prototype. Automatic
  batching needs purity, snapshot/order/failure semantics and finite materialization
  evidence; diagnostics alone do not authorize semantics-changing rewrites.
