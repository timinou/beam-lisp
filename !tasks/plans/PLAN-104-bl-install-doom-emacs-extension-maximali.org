* Resolution (2026-09-12, LSP internal-error hunt)
Manual protocol-level testing (raw Content-Length frames against =mix bl lsp serve=) found three real defects behind the user's "internal server error for many actions":

1. =textDocument/codeAction= crashed on every request: handler read =params["position"]=, but the spec (and lsp-mode, on every post-command-hook) sends a =range=. → -32603 per cursor move — the exact log spam reported. Fixed: fall back to =range.start=.
2. Mid-edit unparseable text made EVERY position feature raise: hover, documentSymbol, inlayHint, codeAction all re-raised the reader error per keystroke. Fixed: doc state records =:parseable=; a dispatch guard answers each feature's empty result while the parse-error diagnostic explains why. (Diagnosed with unbalanced ="(defn f [x]
  (let [y (+ x"=.)
3. The error boundary swallowed exceptions: bare "Internal error", no method, no cause, silent stderr. Fixed: catch logs =handler raised: <method>: <ex>= to stderr always; detail rides in the error's =data= field (message stays the spec's constant → fn stays proven-pure, check baseline intact; =str= would have cost the proof — prover treats =str= as effects).

Also fixed a latent Emacs-side bug found by live verification: every subprocess spawn (=beamlisp--call=, REPL, run, check, doc-run, babel) now runs with =default-directory= at the checkout root — =mix= does not walk up to mix.exs, so buffers in =examples/= or =docs/= failed with "The task bl could not be found".
