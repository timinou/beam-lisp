* Goal

Make beam-lisp datalog fast at the SUBSTRATE — no size-based routing. Two fixes,
BOTH mandatory, ONE cutover, NO fallback path (delete the old per-datom
vector-of-maps engine entirely). One implementation of each thing, and it is the
fast one.

Full design + measured evidence live in the worktree scratch docs (gitignored):
- scratch-plan-datalog-native.md          (the implementation plan)
- scratch-plan-datalog-native-TRADEOFFS.md (losses/mitigations, final arch, downstream usage)
- scratch-proto-typed-values/              (the (b) prototype: scheme C, 37–100× decode)

Prototypes proved (real redb): ETF decode ≈40% of query time; typed tag-free
value slot removes it (long 37×, contiguous 100×, string 9× zero-copy); columnar
bindings remove a further ~5× in the join layer.

* Storage — DECIDED: scheme C, columnar tag-free typed values

Value slot = packed fixed-layout record, NO per-value type tag (dtype known from
schema per scan):

  [ e:8B i64 | tx:8B i64 | op:1B | v:<dtype-typed payload> ]

Two lanes, chosen per attribute by schema:
- typed lane  (long/ref/instant → 8B i64; float → 8B IEEE; boolean → 1B;
              string/keyword → raw UTF-8, zero-copy) — the fast path.
- term  lane  (:db.type/term, and bignum past i64) → 1-byte tag + ETF payload,
              handed back OPAQUE. Preserves zero-cost round-trip of ANY EDN/BEAM
              structure (proven bit-identical). codec.bl (the KEY) still orders
              every term, so term attrs stay indexable.

The NIF reads the VALUE slot only, by fixed offsets — it NEVER reverses the
order-preserving KEY codec (that coupling is rejected). `a` is constant per scan.

Recommendation adopted: float → typed lane; bignum → term lane (keeps fast lane
strictly fixed-width, preserves the contiguous-column fusion path).

* Fix A — the resolve NIF (Rust, crate datom_resolve)

(resolve db-handle index-tag prefix-bytes dtype) -> columnar frame
  1. range-scan redb (keys opaque; used only as range bounds)
  2. read packed value record [e|tx|op|v] by fixed offset, v per dtype
  3. retraction-filter IN RUST (supersede by later retraction of same [e v])
  4. build typed columns → one coarse BEAM crossing
Conformance: golden-vector suite over the PACKED-RECORD layout (not ETF), per
dtype, both directions, 0 disagreements; retraction parity vs a bl reference.

* Fix B — columnar binding frame (pure beam-lisp)

Binding set becomes {:vars [...] :cols {?v [...] ...}} not a vector of maps.
run-clauses / pattern-scan-once fold over the frame; join = int-keyed bucket;
unify = column mask; predicates vectorized where possible. q still returns a SET
of tuples (materialize at the end); q-df returns an Explorer DataFrame. Recursive
rules materialize rows only transiently inside the rule — one representation.

the query path (grep proves it). resolve is a hard dep of datom, peer to redb.
