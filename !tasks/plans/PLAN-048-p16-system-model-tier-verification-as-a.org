* The one-sentence vision (APPROVED by user 2026-08-29: "this is 100% the vision")
Verification is a property of the beam-lisp EVALUATOR, not of any macro. It
attaches to the primitives — receive / spawn / send / loop-recur / function
clauses / guards / defmulti dispatch. Names come from binding-or-content-hash;
invariants from annotations-as-DATA. Therefore it applies, unbidden and
UNMODIFIED, to every process in the language: today's code, defservers, and
every sugar that expands to those primitives.

No new process form. `defprocess` was proposed and REJECTED — deep verification
must fall out of the evaluator's own vocabulary, or it is a library feature, not
a language property. The naming trichotomy (binding-name / annotation-name /
content-hash) plus annotations-as-data on any meta-bearing form removes every
reason a blessed form seemed necessary.

* Why this is more than TLA+ (and why native, no JVM)
TLA+'s Next-state relation is written in a separate file, separate language, and
HOPED to match the code — the refinement gap. Here the Next relation IS the
source, extracted as data ⟹ zero refinement gap by construction. And the sender
set (message coverage) is a datalog join over the call graph — TLA+ structurally
CANNOT do this: it has no implementation, hence no callers.

Apalache is an ENCODER, not a solver: its pre-SMT pipeline (SANY, Snowcat, KerA,
SMT-encode) exists only to get from TLA+ TEXT to z3. We have DATA and already own
z3 (bundled priv/z3, 4.16.0). Same line the project already drew: baby-SMT
rejected (don't reimplement the solver), encoders reimplemented native. Apalache
is an encoder ⟹ reimplement native. Optional TLA+ EXPORT as a pretty-printer for
a TLC second opinion — never a dependency. (Apalache JVM tarball is 196MB.)

* Architecture: the state graph in the repo's OWN relation algebra
priv/datom/query/relation.bl's seven-axis thesis — STORED/DERIVED/COMPUTED are
one interface (provider db mode bound args)→tuples; the engine, planner,
magic-sets, and fixpoint cannot tell a computed edge from a stored one — maps
EXACTLY onto the model:

  STORED   :trans/* clauses — extracted from source, reusing what already exists:
           parse-clause (typed.bl:515) {:params :guard :body}, guard-tags
           (typed.bl:56) predicate→tag narrowing, defn-clauses (typed.bl:527)
           multi-clause+destructuring, and the defserver/defmulti walkers
           codebase.bl already understands. Named by binding-or-content-hash.

  COMPUTED defrelations — :~step / :~enabled / :~guard-sat. Provider expands a
           state through the stored clauses, calling z3 ONLY at the arithmetic
           guard leaf. :basis is a pure fn of the db value ⟹ the graph CANNOT
           drift from the code, and is :as-of safe (model-check any past commit —
           TLC cannot). The adornment MODE gives the checker its directions from
           ONE relation: :bf forward-explore (successors), :fb backward
           counterexample-trace (predecessors), :bb edge-check (refinement sim).

  DERIVED  fixpoints — :~reachable / :~deadlock / :~refines over the computed
           step, on the SHIPPED datom.query.fixpoint engine. Bounded results
           (BMC liveness) register with :relation/approximate true — honesty is
           structural, askable "which guarantees are exact vs bounded?".

Division of labor (project's strict non-overlap rule): datalog owns
structure/reachability, z3 owns the arithmetic leaf, miniKanren owns
synthesis/abduction.

* The effect model, redefined (retrofit NOW — user confirmed)
An effect is not a rung; it is a relation with a FOOTPRINT:
  effect ≜ {footprint {resource→mode}, pre, post}
  mode ∈ {R read · W write · A append/monotone · S send · K recv · X spawn/link/exit}
The ladder is recovered as rank(join of modes) — nothing regresses. The algebra
is the guarantees: purity (footprint⊆self-reads), monotonicity (all-A —
MVP-F becomes THIS special case), idempotence (e;e=e), commutativity &
SEPARATION-LOGIC FRAME (disjoint footprints ⟹ commute AND preserve each other's
invariants, decidable structurally, no annotation). Resource-lattice floor =
:opaque-world (un-nameable pids/messages collapse to a top that never commutes) —
precise where nameable (atoms/ETS/datom/named-proc), sound where not.

* Sandbox unification (examples/sandbox/ — the user's insight, pressure-tested)
Capabilities and effect-footprints are ONE lattice from opposite ends:
  granted-caps (UPPER bound, compile-time, fork narrows child⊆parent)
     ⊇  inferred-footprint (LOWER bound, effect inference)
Verifying a sandboxed process = proving footprint ⊆ caps; the sandbox already
enforces one half at compile time. Payoffs (verified against files 04/05/06):
  1. fork tree = FREE fleet non-interference (disjoint caps ⟹ disjoint
     footprints ⟹ all workers commute, zero per-pair z3).
  2. un-conveyed spawn = detectable effect escalation to :opaque-world (file 04
     trap, file 05 confused deputy, now machine-checked).
  3. ghost workers provably inert (destroyed env → ∅ caps → footprint⊆∅).
  4. the :global-wrapper doctrine (file 05) becomes a proof obligation.
