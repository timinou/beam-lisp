#+title: Exact source spans and bounded generation preparation
#+date: 2026-10-14

* Goal and scope
Make immutable generation preparation preserve exact source bytes and avoid
repeated scans. This is offline candidate preparation latency; these timings
are not browser navigation or production startup measurements. The full
Knowledger project preparation remains a required acceptance gate.

* Baseline and observed blocker
The source11 whole-project gate was explicitly stopped after 21m6.953s wall,
21m49.631s CPU, 2.2GiB peak and zero swap while still in FULL-PROJECT-PLAN. It
had not returned a plan. Knowledger receipt cb910c9a records this incomplete
result. Neither prototype success nor the changes below make that gate pass.

The reviewed baseline is Beam Git revision
6e09636737c5ed0b802270e7df258d8fa4b6a4e2. Source facts:
- reader/read-next-string reslices from the original :all charlist at every
  absolute offset, rescanning the already consumed prefix.
- reload.generation/rewrite-fragment and rewrite-source compute every end by
  taking the length of the entire remaining charlist.
- Each edit rebuilds the whole source codepoint vector, including unchanged
  top-level forms. Nested collections are recursively parsed again.
- String/length and String/slice count graphemes, whereas Reader offsets and
  source codepoint vectors count codepoints. Combining marks and ZWJ sequences
  can make even the first form start negative or consume text next to an ASCII
  prefix. This is a correctness defect, not just a possible optimization.
- The broader source graph performs repeated full parsing for headers,
  executable references, native checks and planning; positioned source facts
  are not yet shared across those passes.

Actual system.ir traversal of ns_definition clauses explains the distinction:
- Root24: Reader provider has no discoverable source, :loaded/:ready false,
  per-definition Ns.Fn body modules; read-until contains a global read-form
  forward-call edge.
- Root25/27: the same Reader provider source is discoverable and loaded/ready;
  Loader/AOT companion replay installs Ns.Body code, and read-until contains a
  direct read-form remote edge.
- Compiler.eval_string compiles/evaluates forms sequentially. It is native ANF,
  not an interpreter. AOT.compile_source prelinks the complete unit first.
- Source context therefore changes emitted/replayed callback code and readiness
  work despite identical source snapshots. Do not report a cross-context
  numerical gain or attribute it to the CST algorithm. Within-Root20 matched
  ratios remain valid. No claim that a product path has this synthetic penalty.

The integrated source-fact builder invokes the actual Reader once per selected
source and retains its positioned forms and physical spans only within that
plan. Header normalization touches only the selected ns header, including nested
metadata. Binding roots and native structural targets reuse those forms. Cycle
and order queries use cached required names. Fresh Env/Loader native ambiguity
checks still run on every call. Public plan ignores caller-supplied AST/cache
fields. Digest/source identity remains unchanged; facts do not become artifact
inputs or a mutable/global cache. Aggregate and per-file byte budgets and source
count limits refuse before malformed source reaches Reader.

Installed tests are prepared with handwritten expected source/identity,
current-file-byte and specific refusal controls. They contain no HOME-local
prototype loader. Official combined Reader floor, installed tests, full product
plan and sandbox publication remain pending.

* Public structural diagnostic API
A repository diagnostic was calling private five-argument source validators;
internal fact reuse correctly changed those signatures. Rather than reparsing
through backward wrappers or keeping tooling coupled to compiler internals,
reload.generation/source-readiness! now accepts :namespace/:source/:sources,
:stable-namespaces and :native-modules. It bounds the input before parsing,
computes actual source facts once, applies fresh native and structural checks,
and returns only status plus required/late-reference namespace strings. It does
not expose AST or release authority, rewrite, initialize or publish. Foundry and
Knowledger tooling can use the same SDK boundary.

The installed36-check source-facts fixture includes explicit summary output,
reflection refusal, native ambiguity before/after provider creation, oversized
source/aggregate/count/boundary refusals before malformed syntax is parsed.
This additional API is not covered by the earlier prototype29 results; its
installed native acceptance remains pending with the official Reader floor.
