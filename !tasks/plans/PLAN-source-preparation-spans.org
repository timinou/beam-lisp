#+title: Exact source spans and bounded generation preparation
#+date: 2026-10-14

* Goal and scope
Make immutable generation preparation preserve exact source bytes and avoid
repeated scans. This is offline candidate preparation latency; these timings
are not browser navigation or production startup measurements. The full
Knowledger project preparation remains a required acceptance gate.

* Baseline and observed blocker
The source11 whole-project gate was explicitly stopped after 21m6.953s wall,
21m49.631s CPU, 2.2GiB peak and zero swap while still in FULL-PROJECT-PLAN. It
had not returned a plan. Knowledger receipt cb910c9a records this incomplete
result. Neither prototype success nor the changes below make that gate pass.

The reviewed baseline is Beam Git revision
6e09636737c5ed0b802270e7df258d8fa4b6a4e2. Source facts:
- reader/read-next-string reslices from the original :all charlist at every
  absolute offset, rescanning the already consumed prefix.
- reload.generation/rewrite-fragment and rewrite-source compute every end by
  taking the length of the entire remaining charlist.
- Each edit rebuilds the whole source codepoint vector, including unchanged
  top-level forms. Nested collections are recursively parsed again.
- String/length and String/slice count graphemes, whereas Reader offsets and
  source codepoint vectors count codepoints. Combining marks and ZWJ sequences
  can make even the first form start negative or consume text next to an ASCII
  prefix. This is a correctness defect, not just a possible optimization.
- The broader source graph performs repeated full parsing for headers,
  executable references, native checks and planning; positioned source facts
  are not yet shared across those passes.

* Implemented first batch
- [X] Reader slices from its current token start tail by the already tracked
  codepoint position delta. Public stream, forms, text and metadata stay the
  same; :all remains for cursor compatibility.
- [X] Rewriter uses the native Reader end offset and only counts its consumed
  text. No remaining-source length scans.
- [X] Apply ascending nonoverlapping edits in one charlist traversal; skip
  unchanged forms. Invalid, overlapping, nested or unordered edits refuse.
- [X] Slice ASCII prefixes and collection delimiters by their known byte
  lengths; preserve following Unicode codepoints exactly.
- [X] Install 43-check actual-SDK fixture without a HOME prototype loader.
- [ ] Accept those 43 checks on the newly installed official Reader floor.
- [ ] Rerun full project planning with a bounded wall/memory receipt.

* Accepted isolated evidence, not installed-floor acceptance
Root13 executed reviewed HOME-local actual Reader and pure rewrite snapshots:
43 assertions passed; wall23.997s, peak222.6MiB. Coverage includes combining
marks, emoji/ZWJ, RTL, exact comments/regex/quoted self references, all ASCII
reader prefixes, nested collections, first/last codepoint boundaries, overlap
refusal, line positions, and continued reflection/native/dependency refusal.

Root14 bounded same-VM ABBA benchmark: wall48.507s, peak173.3MiB, zero swap.
Each pure sample is capped at five seconds; no application code is evaluated.
Every completed old/new exact output hash or Reader form count agrees. Every
observed sample has zero atom growth after the fixed warmup.

| Shape | Baseline samples | Candidate samples | Interpretation |
| Reader 2048 forms, 10239 bytes | 34.388/35.312ms | 16.606/21.860ms | 34.850 ->19.233ms; 1.81x |
| Rewrite wide32, 500 bytes | 670.970/586.742ms | 564.175/497.846ms | 1.18x, narrow fixture |
| Rewrite wide128, 1844 bytes | 2300.156/2035.057ms | 2059.237/1949.687ms | 1.08x, narrow fixture |
| Rewrite wide512, 7220 bytes | both >5000ms | both >5000ms | censored; no speedup claim |

Small nested fixtures are noisy, including regressions. These results establish
Reader improvement and correctness, not a general rewrite or whole-product
speedup. The wide512 timeout is evidence that the remaining nested reparse and
source-fact reuse work is necessary.
