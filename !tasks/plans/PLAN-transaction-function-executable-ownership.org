* The ownership defect
Datom transaction functions registered by name currently live in one VM-global
Agent. Re-registering a name changes later transactions from old callbacks to
new callbacks without changing the old worker's generation. A source-closure
proof does not close this late executable lookup. Knowledger reader publication,
tenant bootstrap,knowledge extraction and corpus repair use this ordinary API.

* Preserve the existing developer API
Keep register-tx-fn!/register-fn! as ordinary functions in development. During
managed compilation,inspect their compiler-resolved ANF targets. Literal named
registrations become compiler-owned immutable declarations automatically. The
registration expression evaluates to its identifier,as before,but does not write
a serving registry. No application wrapper,macro or migration-specific callback
map is required. Repeated identical declarations are idempotent;conflicting
callback/schema bindings for a name refuse before publication.

The generic reload.registration pass accepts fixed SDK contracts,not guessed
source names or namespace prefixes. It traverses only executable ANF and the
compiler's explicit definition/module carriers. Quoted app data,patterns and
annotations remain inert. Dynamic keys,anonymous/computed callbacks and using a
registration API as a callback value are not proven declarations and refuse in
managed code. Ordinary development retains its existing dynamic behavior.

* Descriptor and runtime boundary
A descriptor stores bounded identifier/schema data plus an exact qualified
managed callback name. Collect validates actual compiled callback arities and
its immutable named binding. It never invokes a candidate transaction callback.
The existing declaration catalogue and execution leases resolve each callback
against the caller's selected graph. Managed execution never consults the global
development Agent;runtime registration cannot mutate any managed catalogue.

Transaction callback results still enter Datom's existing schema/uniqueness and
atomic commit path. Static arity checks are not a proof of business correctness
or arbitrary output validity. Reject invalid outputs without partial sibling
writes. Add an independent finite nested-function expansion budget so a callback
returning another :db/fn cannot recurse forever before reaching validation.

* Validation gates
1. Read-only actual compiler probe of public/lower APIs,literal/dynamic inputs,
   named callback values and quoted inert forms. Never invoke registrations or
   callbacks to discover their shape.
2. Pure structural specializer tests for exact targets,inert quoted values,
   code carriers,dynamic refusal before descriptor publication and bounds.
3. Actual managed preparation with unchanged existing API;wrong arity,foreign
   callback,dynamic key/function and conflicting duplicate declarations refuse
   before any mutation or transaction. Identical duplicates remain compatible.
4. Real Datom old/new transactions plus two-app isolation and immutable current
   authority. Old admitted transactions retain old callback meaning;retirement
   waits for a live lease and refuses execution after release.
5. Schema-invalid result and recursive composition exhaustion roll back sibling
   writes. Existing txfn_test remains green;development registry compatibility
   is a distinct control,never the managed fallback.
6. Actual Knowledger publication/bootstrap/extraction use the same unchanged
   function API under sealed graph preparation;no business namespace exemption.
