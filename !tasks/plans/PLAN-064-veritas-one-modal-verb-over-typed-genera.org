* Intent

Four tools — mock (=priv/mock.bl=), fault (=priv/mock/fault.bl=), fuzz
(=priv/fuzz.bl=), and coverage — are ONE operation wearing four costumes:
=(quantifier [var generator] predicate) → verdict=. They fragmented only because
the GENERATOR was ad-hoc ranges, the PREDICATE was stringly-typed, and the
VERDICT hid its own confidence (a sample silently read as a proof).

=veritas= unifies them behind one verb =check= over three nouns:
- GEN  — a typed generator (a =defrecord=, so its TYPE dispatches a protocol
         GLOBALLY; multimethods are namespace-local and will NOT dispatch from a
         requiring module — verified this session). One generator feeds all three
         engines: =gen-sample= (fuzz), =gen-enumerate= (exhaustive), =gen-constrain=
         (z3), =gen-tag= (coverage completeness).
- SPEC — a predicate over the bound value; composes; evaluated as a lambda so it
         cannot leak the caller's scope.
- CHECK— one verb whose verdict carries a MODALITY, so honesty is structural:
           :proven    z3 or exhaustive-finite discharge — a real proof
           :witnessed sampled, no counterexample — NOT a proof
           :refuted   a definite counterexample (+ :witness +:shrunk)
           :unknown   undecidable / timed out — the honest nothing

=check= runs an ENGINE ESCALATOR: strongest modality the (gen,pred) pair
supports. constrain-able ∧ SMT-decidable → symbolic; else finite → exhaustive;
else → sample+shrink. This is exactly the engine division system.core already
names (z3 arithmetic / datalog structure / fuzz witnesses), now exposed as syntax.

* Why this fixes every honest limitation of the four tools

| limitation (in the four tools)          | dissolved by                                   |
|-----------------------------------------+------------------------------------------------|
| witnessed silently ≠ symbolic proof     | :modality — the verdict STATES which it is     |
| domain type-blind (misses float gap)    | gen/any + gen-tag — generators span their type |
| hand-written ranges                     | gen-from-type — derive domain from a type spec |
| guard vocab not self-contained          | specs attach to the defn, run in its namespace |
| unsat = "none in my grid"               | gen-constrain → z3 real ∀/∃; :proven explicit  |
| no strings/reals/nonlinear              | z3 theories via constrain; :unknown when it can't |
| mock ≠ fuzz ≠ coverage (three tools)    | one check; exists/for-all/covers differ only in quantifier |

* KEYSTONE — DONE (built + verified this session)

=priv/veritas.bl= ships the spine:
- =IntGen=/=AnyGen= records + =Gen= protocol (gen-sample/enumerate/constrain/tag).
- =smt-of= translates the linear-integer fragment (comparisons, +,-,*,mod,and,or,
  not, pos?/neg?/zero?/inc/dec) to SMT; nil outside it (honest fallback).
- =check= escalator with all THREE rungs firing, verified:
    ∃ temp>50 over int-of(-90,60)     → {:modality :proven :engine :z3 :witness 51}
    ∀ n>=0 over int-of(0,100)         → {:modality :proven :engine :z3}
    ∀ n<50 over int-of(0,100)         → {:modality :refuted :engine :z3 :witness 50}
    ∀ int?(x) over any-of()           → {:modality :refuted :engine :sample :witness 1.5}
    ∀ even?(n) over int-of(0,3)       → {:modality :refuted :engine :enumerate :witness 1}
- =exists= / =for-all= sugar.

The two hardest claims are proven: one generator feeds two engines, and
:modality correctly reads :proven (z3) vs :witnessed/:refuted (sample) on the
SAME verb. Architecture decision locked: records+protocol (global dispatch), NOT
multimethods (ns-local, do not cross require).

* Phase 1 — the generator algebra (compound + derived)

** Build (all in priv/veritas.bl unless noted)

1. Scalar gens: =real-of= (z3 Real sort + sample rationals), =bool-of=,
   =string-of {:prefix :len}= (z3 String theory via str.prefixof/str.len +
   sample structured strings), =one-of= (a finite value set — enumerate = the
   set, constrain = an (or (= var v)…) disjunction, tag = the common type).
2. Compound gens: =tuple-of [g…]= (multi-var; sample = cartesian of samples,
   constrain = conjunction of child decls/asserts with positional var names,
   enumerate = cartesian when all finite), =vec-of g=, =record-of {k→g}= (the
   response-shape generator — sample a map, constrain each field, tag :map).
3. =gen-from-type= — DERIVE a generator from a typed.bl type node, so a field's
   domain comes from its declared type, no hand ranges. Reads typed's lit-type /
   type lattice; a :int type → int-of over the type's bound (or a wide default),
   a variant → one-of its tags. This is the "no hand-written ranges" fix.

** Acceptance

- record-of over {:temp int-of :code one-of} SYNTHESISES a valid map (∃ proven
  by z3 when all fields constrain) and SAMPLES one otherwise.
- tuple-of drives a 2-var ∀ (e.g. safe-div's (a b)) with a joint z3 constraint.
- string-of "sk_" prefix synthesises a structurally-correct token (z3 String).
- gen-from-type on a typed field reproduces the same domain as the hand gen.
- Covered by test/bl/veritas/gen_test.bl.

* Phase 2 — spec composition + the SMT-widening seam

** Build

1. =defspec name [v] body= — a named spec (a bl fn source + its var), storable
   and composable. =spec-and= / =spec-or= / =spec-not= / =spec-implies= combine
   spec SOURCES into a new source (so composition survives to both the lambda
   evaluator AND the SMT translator).
2. Replace the keystone's hand =smt-walk= with a call into =system.smt/of-source=
   — the SAME translator verify-process uses — so veritas and the verifier can
   NEVER disagree about what a predicate means, and veritas inherits every
   theory system.smt already has (Real, String, enum datatypes). Keep the local
   fragment only as a fallback when system.smt returns :untranslatable.
3. =from-guards fn-src= — read a defn's OWN guard clauses (system.model) and
   build the spec "∃ a clause whose guard accepts v" — this is the COVERAGE
   query (=covers=), recovering priv/fuzz.bl's check as a veritas query.

** Acceptance

- (spec-and temp-sane code-known) both HOLDS-checks and z3-checks identically.
- A Real spec (0 < rate < 1) is :proven via system.smt, not the local fragment.
- covers over gen/any reproduces fuzz.bl's kind-partial gap (float/vec/map),
  with modality :witnessed (sample) — and :proven when the type is finite (enum).
- Covered by test/bl/veritas/spec_test.bl.

* Phase 3 — the =covers= quantifier + the fault space, unified

** Build

1. =covers [port fn-src gen]= — the third quantifier: ∀ input ∈ gen, ∃ clause of
   fn-src whose guard accepts input. Verdict modality as usual (proven when the
   gen enumerates/constrains, witnessed when sampled). Subsumes fuzz/check +
   fuzz/prove.
2. =faults [port contract]= — the fault space as veritas queries: for each law i,
   =(exists [v gen] (and (not law_i) (rest laws)))=. A :proven witness is an
   isolated mutant; an :proven :none (unsat) means law i is IMPLIED (redundant) —
   recovering mock/fault.bl's independence analysis with a MODALITY attached
   (z3-proven redundancy vs merely-unwitnessed). Load the faults as datoms and
   reuse the datalog coverage/redundancy queries verbatim.
3. =shrink= generalised: the witness for a compound gen (tuple/record) shrinks
   per-coordinate (already sketched in fuzz.bl) — lift it to veritas so a refuted
   multi-field property yields the minimal failing RECORD.

** Acceptance

- covers recovers every result priv/fuzz.bl produced (classify gap at 0, fixed
  → proven, kind-partial float gap) — with modalities.
- faults on a contract with a redundant law reports that law as :proven-implied
  (z3), the others as :proven-isolable — the mock/fault.bl finding, now modal.
- Covered by test/bl/veritas/covers_test.bl and faults_test.bl.

* Honest hazards / notes for the builder

- MODALITY DISCIPLINE is the whole point: never return :proven from a sampled
  run. run-sample yields :proven ONLY when gen-enumerate is finite (exhaustion).
  A reviewer should grep for every :proven and confirm its provenance.
- system.smt widening (Phase 2.2) is the highest-leverage item — it deletes the
  keystone's hand-rolled fragment and inherits Real/String/enum for free. Do it
  before adding more scalar gens by hand.
- Nonlinear stays undecidable: a nonlinear ∀ that z3 cannot settle MUST degrade
  to :unknown (z3 timeout) and THEN optionally fall to :witnessed sampling — never
  hang. Every z3 call carries (set-option :timeout N).
- Multimethods are NS-LOCAL — the Gen protocol MUST stay records+extend-type
  (global). Do not "simplify" it back to a multimethod on :gen/kind; it will
  silently fail to dispatch across the require boundary (this session's bug).
- env/eval leaks the caller's ns scope if given (ns X); the spec evaluator uses
  a bare lambda application ((fn [var] pred) v) with NO ns form — keep it that way.
- lit must: quote strings explicitly (pr-str does NOT quote them), pr-str
  keywords (str drops the colon), (quote …) collections. tuple/record candidates
  render each field through lit.
- The edit tool rejected every operation this session (harness glitch); use
  create force:true for whole files and python3 for targeted text edits.
