#+TITLE: Preserve SDK ownership evidence in precompiled releases
#+DATE: 2026-10-19
#+STATE: IN PROGRESS — packaging fix written; sealed-release validation pending

* Observed defect
The clean v2026.8.0 payload 33361ba4 (025cf4fd) loads Datom from empty private
caches in 23686 ms. Yet ordinary Foundry startup reports
=missing_sdk_compiler_inventory=. The release has =precompiled.term= but no
=sdk-code.term=. =selfbuild/do-library-compile= creates the genuine inventory at
scratch/library-attestation.term, outside the sealed payload. Source-cache
fallback cannot authenticate a precompiled SDK actor on a clean installation.

* Implementation
Write the existing compiler-produced ownership inventory to payload
priv/sdk-code.term, after source relocation. Keep the precompiled unit index
alongside it. No new proof format, fabricated receipt, relaxed verifier or app
configuration. Runtime authentication still checks actual source, artifact,
compiler generation, definition ownership and live module identity.

Add a standalone packaged SDK retention acceptance program. It requires the
shipped inventory, loads Datom and authenticates/retains the real SDK owner
registry class. The existing release CI startup runner executes it from a
neutral HOME scratch directory with private XDG state and no source overrides.
This complements the existing zero-compilation startup counter gate.

* Fresh sealed boot exposed nonportable derived routing data
The official bac82554 package contains 3943003 B of SDK ownership data and
558 compared tracked sources match that exact clean commit. Source packaging
passed in 2981.067 s (282 compiled, 177 cached). Consumed staging was removed
before cold acceptance. The VM refuses safe ETF decode before starting the app.

portable_sdk_row left lambda-routes and binding-routes in the wire record, with
executable module/function atoms. The fresh reader correctly refuses atoms it
has not already interned. image_sdk_entry! already reconstructs both fields
from SHA-verified BEAM bytes. Omit these redundant fields at the producer; keep
safe decoding, artifact/source hashes and executable reconstruction unchanged.

A two-process serialization prototype consumes the exact genuine producer
output. The fresh consumer refuses the original, then safely decodes the
projection without those derived fields. Producer 2.145 s; consumer 2.040 s.
This proves only the representation defect, not SDK/app/live acceptance.
Regression coverage now asserts omission and decodes a genuine generated-class
inventory in a separate Elixir process with only the existing AOT module loaded.
