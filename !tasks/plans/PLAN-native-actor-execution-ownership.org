#+title: Native managed actor callback execution boundary
#+date: 2026-10-15

* Status and exact boundary
Approved source checkpoint installed in main; native acceptance PENDING.
No native VM or deployment was launched by this agent. Root must regenerate one
coherent Env/Server/Compiler/AOT floor and run the focused acceptance command. This is execution
ownership, not automatic actor state/mailbox migration.

Ordinary managed Server.bind_init already captures the selected application
and retains its complete physical graph before monitored native registration.
The generated user callback currently executes without the private native
executing-generation extent. Conn consequently cannot attest a new store's
creator from the native owner alone. Bare Env.bind or a retained ticket must
continue to be insufficient.

* Design
- Actual generated init installs a private, nonconveyed attestation only after
  verify_server_start!, exact native/indexed monitored owner proof and exact
  sorted full graph module-set equality with the self-owned live ticket.
- Compiler wraps only user init/call/cast/info/continue/terminate bodies in
  Env.with_server_execution!(literal_class, literal_callback_kind, native_fn0).
  Init registration precedes the wrapper; destructuring/default evaluation is
  inside it. Guards, invariants, contract observers and client helpers do not
  obtain creator authority. Inert generated code_change remains unchanged.
- Callback admission validates exact class/fn module, graph/scope, original
  native membership and ticket anchor under its physical module fence. Full
  ticket mutations already hold that anchor. No extra full graph ticket and
  no graph-sized ETS insertion occurs per callback.
- Logical release closes ordinary callback admission immediately. A privately
  attested source owner keeps its physical full ticket through actual DOWN,
  allowing OTP terminate cleanup after logical close. Only literal terminate
  can enter this cleanup route; no new business callback can. The existing
  monitored owner collector releases after real DOWN. Death is not replay.
- Framework adoption removes the source attestation immediately. Its already
  accepted init extent keeps old physical helpers until finally; stable SDK
  owner then has nil source generation and cannot claim app creation authority
  merely from application identity/class retention. Actual retained source
  callback admission establishes its own selected graph and exact ticket.
- Sealed descriptor adapter strips only a matching outer compiler wrapper,
  preserving the init registration prelude. Ordinary ANF policy checks the
  returned body. Nested/borrowed wrappers and arbitrary native Env calls stay
  refused. No blanket native exemption.

* Performance validation
Compare immutable before/after compiler+Env snapshots on identical source actor
message workloads in one coherent VM per floor. Warm actor and imports first;
run alternating bounded 1/8/32-source-module graphs, 10k integer echo calls,
three repeats; record p50/p95 per call, wall/CPU, total code lease rows before,
blocked midcall, and after observed DOWN. Independently compare actor init
source planning/compilation time from callback runtime cost. Proposed complexity
is O(1) native entry admission after one O(graph size) init attestation; actual
execution/owned? still validates full graph on resource creation. No measured
speedup or application latency claim yet.

* Remaining live upgrade mechanisms, not claimed by this fix
- FUP165 cold shared resource claim and same-lifetime explicit guarded store
  handover, selected-graph journal transactions, writer-fenced policy adoption.
- Embedded application actor physical module replacement: current default
  code_change does not switch class or migrate custom state/mailboxes.
- Canonical pure firstparty queue/reconcile owners can use stable SDK owners
  from first start; existing app-owned actors require explicit drained handoff
  and native ownership CAS, with old queued/running handler leases retained.
- Message head/guard contracts are useful admission evidence, not guessed
  reply/body/state migration. Raw unversioned future mailbox traffic must be
  drained or kept on its old handler; no universal mailbox snapshot guarantee.
