* Key design decisions (first principles)

1. **Rollback artifact = compiled binary, not source text.** jank's
   known-good snapshot is a source string whose re-eval can fail against
   a changed sibling (its README discloses =:revert-error=). A remembered
   =.beam= binary cannot fail to compile — it already did. The failure
   mode ceases to exist rather than getting handled.
2. **defonce is the wrong primitive to port.** Named Agents survive
   module re-eval AND crashes, are inspectable via :observer/:sys.
   =state-ensure= is idempotent creation — the honest defonce.
3. **Rescue keys move from pump-convention to supervision structure.**
   jank put ctrl+r/ctrl+z in the pump by code-order discipline; here the
   renderer's OWNER process sees events before the possibly-broken
   handler — same invariant, structurally enforced.
4. **No defonce-port, no PUMP-port.** The two things a transliterator
   would build first are the two that must not be built.
5. **GUI: keep clayd (verified jank-independent, vendored static raylib
   builds here), add a pure-beam-lisp ANSI terminal renderer as renderer
   #2 to prove the wire is renderer-agnostic. Odin deferred** — official
   clay bindings exist (nicbarker/clay → bindings/odin) but odin isn't
   installed, it rewrites 1,416 working lines, and the wire makes it a
   drop-in whenever. wxErlang/Scenic rejected: in-VM coupling violates
   the trust boundary.

* Lessons earned (verified by running, recorded in spell/README.md)

- Task.async is the wrong fence primitive: it links; a callee crash
  before Task.yield's trap window kills the caller (observed).
  spawn+monitor is the honest shape.
- Monitors fire DOWN on :normal exit: the reply path must
  demonitor [flush], or the orphaned DOWN poisons the NEXT fence's
  receive (observed: fence N+1 reporting fence N's :normal exit).
- Zero-binding (loop [] (recur)) IS infinite when run directly
  (rc=124) — the demo's misleading {:exit :normal} was monitor residue,
  not a compiler bug. Verified by bisection.
- Maps not callable in call position; keywords are. No get-in, no mapv
  in core. No tuple literal → erlang/list_to_tuple over (list …).
