* Bugs found and fixed first

** BUG-371 (verse 8cf10477) — inspect re-guessed the macro parse had chosen
`inspect --layer expansion` gave FIVE different answers for one unchanged file,
including `drive-as-error`, the `%diagnostic` sibling whose job is to REFUSE
invalid syntax. Cause: it resolved by directive name (`on`, shared by six
`%macro` siblings) instead of honouring `FormMatch::matched_macro`, then fell
through to a `HashMap`-ordered lookup. Compilation was unaffected (it passes
`matched_macro` as `preferred`), so `check` passed and `emit` was byte-stable —
only introspection lied. Fix: `MetaRegistry::get_macro_for_match`.

** BUG-372 (verse 56f50585) — inspect saw 3 of 20 stdlib directories

directories define `%macro`s. `@view`/`@match` (stdlib/enum), plus all of
mobile, 3d, text, dnd, fields, … were invisible, reported as
`"expands_to": null` — indistinguishable from "binds nothing".

* (1) Style plane — what's actually missing

Verified gap: a page styling `.ghost-never-exists`, `.also-missing__elem`
passes `check --deny-warnings` with exit 0. Spacetime has E0916 for undefined
TEMPLATE refs but no diagnostic for a rule whose selector no element matches.

BUT the raw material is all there and now trustworthy:
- `inspect --layer parse --format json` → every `scopes[].selector`
- `inspect --layer scopes --format json` → every declared template
- template HTML is in the parse tree (class attributes extractable)

∴ the check is a JOIN over two JSON documents, not new compiler work. It belongs
in beam-lisp (`priv/seam.bl` already has `disagreements`/`agree?` vocabulary),
emitted from the same term, so a styled selector that no template renders is a
contract violation like any other.

* (2) `@status` → `&thinking` — the affordance exists

`@view $subject { pat => &tpl(args); }` — stdlib/enum/dispatch.st, binds
`dispatch-mount(reactive: true)`: re-mounts on every signal change. Exactly
"render this template when the server says thinking".

Verified: `check` ✓, expansion → `dispatch-mount`, stable across runs (only
visible AFTER BUG-372 — this is why the audit had to come first).

Alternative found: `@each(... , when: $expr)` (`each-filtered`) — works, but
models a scalar as a collection. `@view` is the honest fit.

Also noted: `data-subscribe-seeded` exists — directly relevant to the
"can't seed a subscribed assign" workaround currently going through
`window.SpacetimeLocal`.

* (3) Tool-calling — verified live

Live probe against `k3-256k`: tool calling WORKS —

returns empty string for these turns — it must learn `tool_calls`.
