* Intent

Replace the per-tree Elixir daemon (single serial Executor + per-tree Server) with the pure-beam-lisp global VM manager (priv/std/vm/*) in ONE clean cutover — not gradual, not beside. One node hosts many per-project VMs; each command is an ordinary BEAM process under its VM's capped env; the BEAM manages concurrency. Then MEASURE the after-state and ENSHRINE the guarantees as tests + formal invariants.

This plan is the SUPERSEDE+PORT half of the daemon migration. The PRESERVE half (transport/protocol/io/std_err/paths/gateway/ca fully to beam-lisp) is FUP-082's sunset (S1–S6); this plan wires vm.* behind the EXISTING transport and deletes the serial-worker machinery, leaving FUP-082 to remove the transport itself.

* The guarantees this cutover must deliver (and enshrine)

G1 CONCURRENCY — N commands across VMs run truly concurrently; no single serial worker; one slow/blocked command never wedges another.
G2 ENV-SCOPED HALT — System/halt is unnameable inside a VM (compile-gated by caps); vm.scope/halt tears down only the caller's VM; the node and every other VM survive.
G3 NO LEAK ON CRASH — a crashed VM member self-retracts (monitor); draining a VM kills exactly its process set and destroys its env; zero orphan rows/processes.
G4 COLLISION-PROOF IDENTITY — two worktrees of one project on the same branch get distinct VM ids (path-hash fallback); no silent hostname/route collision.
G5 PROCESS-LOCAL ENV — a command's OS-env view is process-local, not node-global; concurrent commands with different env do not race (see D1, the keystone defect).
G6 REPLACE-NOT-BESIDE — the Elixir serial worker + owns-process + BL_DAEMON tri-mode are DELETED, not wrapped; one need, one implementation.

* D4 — supervision of the manager

The manager process itself needs an owner (the old Workers gave the Executor one_for_one restart). The manager is a defserver; it must sit under a supervisor (super/defsupervisor) started at boot, so a manager crash restarts it. Note the trade: restarting the manager loses the {:vms} table (the VMs' envs/processes outlive it as owner-registry rows, but the table that indexes them is gone) — so the manager must REBUILD its table from the owner registry on init (the registry is the durable truth; the table is a cache). This is itself a guarantee to test: kill the manager, it comes back and re-lists the live VMs.
