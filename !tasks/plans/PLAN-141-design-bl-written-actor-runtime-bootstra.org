* Design decision
Implement the actor runtime in Beam Lisp and cross-compile it with the same ANF-to-JS backend used for applications. Keep one canonical BL-ANF vocabulary. The compiler owns explicit resumable control; BL libraries own process, mailbox, receive-selection, timeout and scheduling semantics. A very small JavaScript adapter provides irreducible host representations and Web APIs. This is a design proposal only; no executable files changed, no build or behavior verified. Source review by oracle agent 2-ActorBootstrapReview confirmed feasibility with the corrections recorded below.

** Scope and bootstrap
Compilation initially runs on the existing BEAM host. Existing macros and compile-time RT dependencies may execute there; generated target code must not depend on the BEAM. Compile canonical validated module descriptors, not an alternate parser/frontend or an ANF interpreter embedded in JavaScript. The existing self.anf interpreter is useful reference material only: it uses BEAM RT, host closures and erlang/apply and explicitly rejects receive.

The first backend must establish a target ABI registry over existing :remote/:global operations. Distinguish generated BL functions, target BL runtime implementations and trusted host intrinsics; reject unresolved host dependencies at build time. In current compiler.bl, :remote includes linked BL calls and RT.invoke, not just synchronous foreign primitives. RT.invoke also supports callable keywords/maps/vectors/sets; plain JS function invocation is insufficient. A manifest and transitive dependency check on expanded/emitted ANF must demonstrate a closed runtime bootstrap. This registry is a compile/link concern, not another user-visible implementation of the language.

Proposed module responsibilities (names provisional): target data/invoke/global support in portable BL; js.control compiler pass/emitter; runtime.machine for explicit frames/unwinding; runtime.process for pids/lifecycle/runnable queue; runtime.mailbox for indexed ordered mailbox and cursor; runtime.receive for bounded selection and wait registration; host.web adapter for JS/Web APIs. Paths must be fitted to actual repository naming before implementation. Do not blindly copy rt.ex; use existing portable BL helpers where their transitive dependencies are supported. Arithmetic leaf instructions/type tests/raw representation allocation remain target intrinsics, while higher-level numeric/collection semantics should remain BL. Preserve distinct tuple/vector/list/keyword/string values and supported numeric exactness; unsupported types fail explicitly rather than silently become JS values.

** Two code classes, one language/backend
User functions compile to one managed resumable ABI by default. A closed, checked scheduler/runtime kernel compiles direct-style; its loops lower iteratively and each entry performs bounded work or returns a resumable state. This is an internal backend specialization, not a public sync/async split or two alternative libraries. Kernel routines cannot call arbitrary managed callbacks. Existing footprint analysis cannot certify this property: purity, syntactic absence of receive, and decreasing annotations are not sufficient to prove non-suspension, stack safety or bounded work. Unknown/dynamic calls stay managed. Later direct fast paths require callee-aware proofs and stable callee identity.

Compile evaluation order and live bindings into explicit frames/resumption blocks. ANF currently permits non-atomic operand trees; transform every expression position rather than assuming operands are values. Control steps include Done(value), Call(target,args,continuation), TailCall(target,args), Raise(kind,reason,trace), Park(waitToken,continuation) and Yield(continuation). These are private runtime transport records, not new canonical ANF nodes. Brand them at the ABI boundary and wrap every normal return explicitly; a user's map/tuple resembling a step must remain data. A Done step resumes a saved caller if any, and ends the process only when there is no caller. Tail calls reuse return continuations but preserve active exception/finalizer scopes. Driver executes emitted JS blocks; it never interprets canonical ANF nodes.

** Receive in BL, not JavaScript
The frontend continues emitting :recv with ordered clauses, timeout expression and timeout body. Backend evaluates timeout once, produces a compiler-generated non-suspending pattern/guard probe and managed branch continuations, and routes selection through BL runtime.receive. That library owns mailbox scanning, scan cursor, request generation, wait registration, deadline handling and wakeup bookkeeping. Its only irreducible suspension is a private control intrinsic (represented by an existing target-resolved :remote call, not a new public source special form) that returns Park to the machine. Exact encoding may fuse the receive-entry call into a scheduler request, but semantic decisions must remain in BL.

Separate probe from body: probe(message) returns private NoMatch or Match(clauseId,bindings). Share the pattern/guard compiler with :case and :fn. Probe never runs clause body. BL receive removes the selected message before control enters the managed clause body, whose result is the :recv expression result. Timeout completion enters the timeout body, whose result likewise becomes receive's result. Guard success follows exact-true/guard-error semantics, not general BL truthiness; the backend must validate guard safety because canonical ANF validation currently admits more shapes than source guard compilation. Large nested match/equality workloads need bounded or resumable probing despite probes being non-suspending with respect to user effects.

Each actor has explicit pid/context, continuation/caller/handler frames, mailbox, active receive generation/cursor/deadline, lifecycle status and eventually link/monitor state. Begin each new receive at mailbox head. Scan message-major, clause-minor; preserve skipped message order. Retain cursor across scan-budget yields and incoming messages during the same receive. Atomically serialize mailbox check, wait registration, enqueue and wakeup through scheduler-owned state. A completed or dead actor invalidates pending receive generations. Use a monotonic deadline and do not reset on unmatched arrivals. after 0 must scan already-queued eligible messages even across a scheduling boundary; it must not be treated as immediate cancellation before the scan. Precise boundary eligibility/message-versus-timeout order must be specified and differentially tested against BEAM; continuing arrivals must not indefinitely extend a timed wait.

** Exception semantics
Normal JS try/finally cannot represent a BL dynamic scope spanning parking, because returning a control step would prematurely execute finally. Machine state stores catch/finalizer frames and pending normal/exceptional completion. Park/Yield preserve these frames. Remove a catch before running its handler; remove a finalizer before entering it. Finalizers execute once in LIFO order, may themselves suspend, discard their normal result, and replace pending completion if they raise. Translate current compiler-emitted Exception.normalize, ExInfo payload normalization, raw trace access and rethrow through the target ABI. Do not claim native JS Error.stack equals BEAM stack traces; preserve logical source frames under an explicitly specified target representation. External untrappable actor kill is a separate lifecycle operation, not automatically equivalent to a catchable Raise.

** Scheduling and host boundary
One dedicated Web Worker hosts many logical BL actors initially. BL scheduler owns fairness and a bounded total turn budget, charging calls/tailcalls/backedges, mailbox scanning and input-dependent runtime operations. It returns to a host task between turns so timers and I/O can run; endless microtask chaining is not sufficient. Collection helpers such as reduce must invoke potentially suspending callbacks through the managed protocol, never synchronously from the kernel. Unbounded synchronous foreign calls cannot be preempted; reject, bound or isolate them and document this limit.

Tiny host adapter: raw representation/numeric primitives; monotonic clock; schedule/cancel wakeup; enqueue next host task; I/O event registration; explicit foreign capability invocation. It contains no clause matching, mailbox selection, process registry, link/monitor policy or BL scheduling policy. Host callbacks enqueue scheduler events and request a turn; they do not re-enter user BL code. The BL scheduler can thread its state as a value; only host pump ownership needs a retained mutable root. No dependency on SharedArrayBuffer or one Worker per logical process is necessary. DOM stays on main thread behind a bridge; fetch/WebSocket completions become messages.

Immutable BL values may share storage within a worker without observable actor mutation; mutable foreign values must be copied or exposed as explicit capabilities. Cross-worker transport later needs a BL codec; structured clone does not carry JS closures/prototypes. Never implicitly transfer/detach sender buffers.

** Build sequence and observable gates
1. Portable target ABI plus :lit/:var/:let/:if/:do/:tuple/:map/:cons/:enil/:struct/:arith/:fn/:apply/:global/:remote/:case support for the kernel closure. Audit all emitted calls; no unresolved BEAM runtime dependencies. Numeric/value edge cases compare with BEAM. Runtime must bootstrap without calling native erlang spawn/send/receive/sleep.
2. Managed control conversion including :try, calls through RT.invoke and higher-order callbacks, tail transitions, handler/finalizer frames, Yield and Park intrinsics. Tests: evaluation order/once-only operands, nested suspend-capable arguments, return values resembling control records, large stack-safe recursion, receive/suspension inside try/catch/finally, finalizer exception precedence. All canonical op cases have explicit lowering or precise compile-time rejection during intermediate development; do not advertise full primitive coverage before target contracts exist.
3. BL scheduler/process/mailbox/receive modules compiled with that backend; :recv routes into this implementation. Test kernel dependency closure, bounded scheduler turns, no managed callback from kernel, send/self/spawn, ping/pong, selective ordering and skipped message retention, after 0 scan over a budget boundary, timeout evaluated once, stale timeout event, race around parking, unmatched flood, process exit cleanup and a CPU-bound peer making progress. Use an injected fake clock/event queue for deterministic BL state-machine tests on BEAM and JS, then real browser Worker integration. Portable runtime tests on BEAM must exercise this runtime as data, not accidentally delegate to native Erlang receive. Differential programs separately use native BEAM for the behavioral oracle; compare causal/semantic outcomes, not identical wall-clock timing.
4. Extend links/monitors/exit handling and registry to support existing BL flow/channel/server code. Audit reachable dependencies before claiming OTP compatibility. Full OTP/ETS/ports/distribution are not implied by core actor semantics.

** Key insight and non-goals
The bootstrap is data/control first, then a BL runtime compiled onto that substrate, then ordinary source receive using that runtime. There is no circular requirement to implement receive with native receive. The compiler supplies suspension capability; BL supplies what waiting for a message means. This is not a generic bytecode VM, another ANF, browser-hosted self-compilation, or a rewrite of all OTP. The semantic runtime remains BL and can be tested on both targets.
