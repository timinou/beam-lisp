** The gap
beam-lisp has **no source position tracking anywhere**. `lib/beam_lisp/reader.ex` never records a line or column; the compiler never puts `line:` into the quoted AST it builds. Consequences, both observed:

Runtime error in `examples/`-style code:
: ** (ArithmeticError) bad argument in arithmetic expression: 3 + nil
:     :erlang.+(3, nil)
:     lib/beam_lisp/link.ex:56: BeamLisp.Ns.Errdemo.boom/1
:     (elixir) lib/enum.ex:1725: Enum."-map/2-lists^map/1-1-"/2

Compile error:
: ** (RuntimeError) binding forms must be even, each a pattern and a value
:     lib/beam_lisp/compiler.ex:1039: BeamLisp.Compiler.compile_bindings/2
:     lib/beam_lisp/compiler.ex:435: BeamLisp.Compiler.compile_special/3

Neither names the user's file, line, or the offending form. The compile error does not even say *which* `let`. Every frame points into beam-lisp's own internals — the stack trace describes the compiler's execution, not the user's program. For a language that now runs 62 slices of real upstream code, this is the floor that is missing: the thing is featureful and undebuggable.

** Feasibility — PROVEN, not assumed
The BEAM will attribute a generated module's frames to an arbitrary file and per-expression line. Verified directly:
: ast  = {:+, [line: 42], [3, nil]}
: Module.create(:"Elixir.ProofNs", body, file: "/tmp/fake_source.bl", line: 1)
produces
: /tmp/fake_source.bl:42: ProofNs.boom/0
So the target output is reachable with the existing `Module.create` route — no new backend, no bytecode surgery. Two levers: the `file:`/`line:` location passed to `Module.create` (currently `Macro.Env.location(__ENV__)`, i.e. beam-lisp's own source — that is the bug in one line), and `line:` metadata in the quoted AST nodes the compiler emits.

** Use the affordance that already exists
Do NOT invent a parallel position channel. `BeamLisp.FormMeta` already implements `{:meta, form, m}` wrapper nodes over form data, and its own moduledoc states the intent outright: *"the metadata is source-location info that never reaches a runtime value."* It was designed for this and is already stripped before codegen. The work is to start *populating* it from the reader and *reading* it in the compiler.

This also closes the reader `^{}` metadata gap (previously tracked as a separate item) — same channel, same plumbing.

** Build sequence
1. **Reader records positions.** Thread a `{line, col}` through the tokenizer and attach to every form via the FormMeta wrapper. This is the invasive step: `reader.ex` is 462 lines and every construction site needs the position threaded. Keep `read_string/1`'s public shape.
2. **Compiler emits `line:`.** When compiling a form that carries position metadata, put `line:` into the emitted quoted node's metadata. Elixir propagates it into the BEAM line table.
3. **`Module.create` claims the real file.** Replace `Macro.Env.location(__ENV__)` with the source path of the form being compiled. Applies to both `eval_form/2` and the AOT path in `aot.ex` (AOT especially — those `.beam` files persist and are what a production stack trace hits).
4. **Compile errors carry position.** The `raise "…"` sites in `compiler.ex` should report file:line and the offending form. Consider a `BeamLisp.CompileError` with `file`/`line`/`form` fields rather than bare `RuntimeError`.
5. **Trim internal frames.** beam-lisp's own `eval_string`/`with_load_path`/`Enum.map` frames are noise in a user-facing trace. Consider `Exception.blame` or a custom formatter in `mix beam_lisp.run`.

** Payoff beyond error messages
Positions unlock, in rough order: usable `mix beam_lisp.test` failure output (currently a failing `.bl` assertion cannot point at its own line), debugger/tracing integration, coverage, and `^{:doc …}` reader metadata for free.

** Acceptance
- A runtime error in a `.bl` file names **that file and line** as the top user frame.
- A compile error names file, line, and the offending form.
- AOT-compiled modules carry `.bl` locations in their line table (check with a persisted `.beam`, not just an eval module).
- Positions survive macroexpansion: an error inside a macro-generated form points somewhere useful — ideally the call site.
- `mix test` green, `mix beam_lisp.test` exit 0, all `examples/*.bl` exit 0, `--warnings-as-errors` clean.
- A test asserts the stack trace content, so this cannot silently regress.

** Risk
Step 1 touches every construction site in the reader; the sha256-guarded jank fixtures are the safety net — they will catch a reader regression immediately. Do step 1 behind the existing suite, and do not change `read_string/1`'s return contract for callers that ignore metadata.
