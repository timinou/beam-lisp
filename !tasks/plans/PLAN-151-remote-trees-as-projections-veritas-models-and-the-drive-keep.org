* Scope decisions for this plan (2026-09-28)

1. Provider for the first end-to-end run is **Google Drive** (a client exists in
   =.env= and a grant is stored). Microsoft Graph follows on the same keep/feed shape
   (later plan) — nothing here may name Google outside =connector/google/*=.
2. The credential is a **person's** Google account (knowledger lets any firm admin
   connect theirs, as a firm integration of origin =:delegated=). Upstream is
   origin-agnostic: a grant is a grant.
3. Keys: =[:gdrive <namespace> <file-id>]=, namespace = the account's =sub= for My
   Drive (Drive ids are global, but the namespace keeps two accounts' views
   distinct until shared drives are supported). =:conn/seen-via= is NOT needed for
   one account per integration and is deferred.
4. Performance is a gate, not a hope: every wave that touches a query or a loop
   records its measured cost in its test output.
5. veritas first: the stateful model (U4) is built BEFORE the keep, and the keep's
   and executor's tests are veritas models, not hand-picked scenarios.

** V2 — veritas: one value-directed shrinker   (U3)   DONE
- Built as VALUE-directed =v/shrink-candidates= / =v/shrink= / =v/shrink-coords=
  rather than a protocol on Gen: a witness is a plain value (a history, a map),
  often with no generator of its own, and "simpler" is a property of its shape.
  Tuples shrink coordinate-wise (arity kept); veritas.property uses the same
  candidates (its int-only ladder removed).
- Gate: =test/bl/veritas/shrink_test.bl=: a vector property failing when it
  contains 7 shrinks to =[7]=; a tuple shrinks coordinate-wise; a string to its
  shortest failing prefix.

** V3 — veritas.model: stateful models with history shrinking   (U4)   DONE
- =priv/lib/veritas/model.bl=, =ns veritas.model=:
  - =(defmodel name doc spec)= → a model value; spec keys =:state :init :commands
    :invariants :eventually :cleanup=; a command ={:args gen-fn :pre fn :next fn :run fn}=
    where =:args= is =(fn [state] gen)= (state-dependent generators — =pick=/=fresh=).
  - =(check model {:seed :histories :max-len :budget-ms})= → a veritas verdict:
    =:witnessed= (or =:refuted= with =:witness= history, =:shrunk= history, =:broke=
    invariant name, =:at= step), =:tried=, =:coverage {:commands {…}}=, =:seed=, =:why=.
  - history shrinking: delete command runs (halves, then singles), then shrink each
    command's args via V2, re-validating =:pre= against the replayed model state.
  - =(replay model history)= runs one history deterministically and returns the
    trace (for debugging and for the ledger's replay).
  - predicates are FUNCTIONS here (=(fn [model-state sys] …)=), not quoted forms:
    they read a live system. Stated in the header (the quoted-form rule is for the
    symbolic core; a model is never symbolic).
- Gate: =test/bl/veritas/model_test.bl=: a counter model with a planted bug
  (decrement below zero after exactly 3 increments and a reset) is REFUTED and
  shrinks to the minimal 5-step history; a correct bounded queue model is
  =:witnessed= over 300 histories; the same seed reproduces the same verdict;
  =:coverage= counts every command.

** P3 — connector.feed + the Drive keep   (PLAN-142 W2, amended)   DONE
- =priv/lib/connector/keep.bl=, =ns connector.keep=: provider-neutral. A keep is
  ={:conn :db :feed feed-spec :roots-fn (fn [db] → [root-key …])}=. One =step!=:
  1. no cursor → read start token FIRST (store it as pending), then seed every root
     (BFS children listing), then commit the pending cursor;
  2. cursor → page the change feed; for each change: drop if not under a current
     root (M1, decided against the mirror + the change's parents), write
     =:file/*= facts, =:file/trashed=, =:file/gone= on removal; a folder that
     arrives under a root is seeded (BFS);
  3. commit the new cursor ONLY after the last page, in the same transaction as
     that page's facts;
  4. a root added since the last step (roots-fn grew) is seeded before paging.
- Feed spec = data per provider (=connector.google.gdrive/feed=): start-token url,
  changes url + fields, list-children url, item → facts fn, removed? fn. The keep
  calls =connector/get!= through an injectable =:get= (default =conn/get!=) — the
  seam the tests and the fake use.
- The cursor is a datom =[:feed/key [provider namespace]] :feed/cursor=.
- Gate: =test/bl/connector/keep_test.bl= is a veritas.model (V3): the model is a
  fake Drive (a map tree + a change log); commands =add move rename trash untrash
  delete edit add-root step crash-mid-step=; the real system is the keep over an
  in-memory db with =:get= answered by the fake. Invariants: mirror = the model's
  tree restricted to the root closure (after =step=); nothing outside the closure
  is ever written (M1); the cursor never moves past unwritten pages. 300 histories.
  Plus a fixed test: shared-drive root refused by name.

** P6 — proc reconcile clause: the projection executor   (PLAN-142 W4, amended; G2, G3)
- =priv/std/proc/reconcile.bl=: clause =(reconcile {:projection p :conn f :scopes f
  :rules r :apply f :retire f :level [n :unit] :paused? f})=, registered with
  =extend-clause!=, requiring a =queue= clause in the same server.
  - level: at init and every =:level=, for each scope run owed + stale, enqueue
    =[:owed scope src rev]= / =[:stale record]= jobs with =:unique= on the row.
  - edge: a =datom/watch= T2a on owed/stale (reads derived by BUG-100's walker);
    =:added= rows enqueue.
  - perform: re-judge the row against the current db (skip if no longer owed/stale);
    call =:apply= → ={:target t}= | ={:skip reason}= | throw (transient → queue
    retry); write target first (the consumer's apply did), record second
    (=record-tx=). Stale: =:retire= then =retire-tx=. Paused scope: owed not
    enqueued; stale jobs not performed (left queued).
  - =(reconcile-stats server)= → ={:owed n :stale n :queued :running :failed
    :last-level-at :last-error}= — a QUERY, like =proc.queue/stats=.
- Gate: =test/bl/proc/reconcile_test.bl=: (a) three owed → three jobs → converge;
  (b) owed twice while queued → one job; (c) watch dropped, level tick catches it;
  (d) perform crashes once → retried → converges; (e) row stops being owed while
  queued → skipped; (f) G2: kill between apply and record → rerun converges, one
  record, apply idempotent; plus a veritas.model with =crash= commands. 

** P7 — sync console: seeing the work   (dev visibility, prod-safe)
- =priv/lib/connector/console.bl=: pure read functions over the stores —
  =(keep-status db feed-key)= (cursor age, last step at, last error, roots,
  mirrored counts), =(projection-status db proj scope)= (owed, stale, applied,
  skipped by reason, retired, oldest owed age), =(recent-steps db n)=. The keep and
  the executor write =:sync.event/*= facts (bounded: last 200 per feed, pruned) —
  what happened, when, how long, how many items.
- =bl= CLI: =bl sync status [--store path]= prints the above as a table; used in
  dev and on a prod box over SSH (read-only; opens the store read-only or through
  the running VM's live module when present).
- =live=: a =live/pane= for the same data so an app can mount it on an admin route.
- Gate: =test/bl/connector/console_test.bl= over a keep + executor run: counts
  match the stores; events pruned at 200.
