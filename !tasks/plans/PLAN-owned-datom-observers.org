#+TITLE: Owned Datom observers and acknowledged drain
#+DATE: 2026-10-14

* Problem and implementation boundary
Datom watches previously used raw erlang/spawn, which drops the captured
namespace, selected generation and restricted query authority. unwatch returned
after enqueueing stop, allowing the connection/store to close while a previously
accepted query or callback was still running. Rank-query builders manually bound
Env but did not retain their selected executable generation.

This change composes core managed spawn, proc.callback registrations and the
connection-lifetime observer admission fence. It changes no application API
requirements: existing watch/unwatch calls gain context retention and drain.

* Implementation
- A watch retains the callback before spawn and transfers its exact ticket to
  the child. Startup is armed only after observer/listener admission and initial
  snapshot. A private creator ticket gates publication; creator death before
  publication admits no query/callback work. Reply aliases/monitors are cleaned.
- The child registers its own retained stop callback through
  datom.conn/register-observer!, under the same Agent fence as close->closing.
  Closing drains outside that Agent before deleting physical resources.
- unwatch waits for exact process DOWN. A bounded timeout reports :watch-draining
  without killing or replaying accepted effects. Self-stop returns :stopping.
  Stop takes priority over queued notifications not yet accepted by the loop.
- Query/callback work runs with the captured Env/query policy and original graph.
  Callback invocation borrows an independent lease; finally removes listener,
  observer ticket and callback registrations.
- Rank builders use core spawn and an unforgeable admission ticket after the
  connection claims the worker. Existing bounded internal atomic build/close
  semantics remain distinct from arbitrary external callback effects.

* Explicit limits
A failed/timed drain retains closing resources and requires operator retry after
the accepted work completes; it does not claim external callback replay is safe.
Watch callback backpressure continues to use the existing process mailbox; this
change does not add stream coalescing or a bounded mailbox overflow policy.
Observer stop callbacks are currently drained serially. If the first refuses or
times out, resources stay closing and other queued observers may continue until
retry; bounded all-observer stop initiation is a follow-up, not a claim of this
lifetime-safety gate.
Native abrupt death is cleaned by lease ownership/dead-subscriber pruning; user
finally blocks are not claimed to execute after an untrappable kill.
