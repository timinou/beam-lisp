* What each remaining wave needs (each is independent once started)

** W6 — `bl self-build` + the fixpoint gate

A verb that runs, INSIDE the shipped drop, the whole chain that produced it:
substrate (W3) → AOT waves (W1/W2) → `assemble` (W4) → `pack` (W5), writing
gen-N+1 next to gen-N. The gate is a FIXPOINT: successive self-builds must agree
— decide whether the comparison is the whole compound or the TAR, and say which
(W5 measured that the deflate stream differs from flate2's, so the tar is the
honest comparison today).
- Every piece already exists as a function; what is missing is the verb, its
  failure reporting, and the comparison.
- `BL_BIN` gives the running drop's own path (W0 P1a) — that is how self-build
  finds its launcher prefix without a Rust tool.

** W7 — the library store + hex client

Fetch a tarball, verify sha256, unpack into a content-addressed store, make it
visible to the plan. hex.pm's API and tarball endpoint both answer 200 from this
host (W0). Today `deps` is a symlinked Mix directory and `mix.lock` (47
packages) is the lock. Non-goal: replacing Mix's resolver.

** W8 — the build session + its claim (no `_build` lock)

Two concurrent builds must not corrupt a tree, without Mix's `_build` lock: a
claim with an owner and a liveness check, so a stale claim from a killed build
does not wedge the tree. The fact log (W2) already makes an interrupted build
resumable, so the claim only has to stop two WRITERS.

** W9 — env.bl: `:app` `:build` `:release` `:deps`; `bl seed`; `doctor --deep`

`priv/env.bl` becomes the project's declaration, which is what lets `bl release`
take its value from the project rather than from a caller. Plus a seed command
(the procedure is in `priv/bootstrap/gen_manifest.exs` and PLAN-108) and a deep
doctor: seed stamps, the log's agreement with the manifest, the compound's
trailer, the release's priv.
