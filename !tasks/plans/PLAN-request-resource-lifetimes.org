* Problem
A request-local finally block cannot run after an untrappable process kill.
Initializer-owned temporary scope entries therefore require owner-death cleanup,
not only a capacity limit. Separately, late OAuth/job replies must not overwrite
a newer attempt's outcome or cross an application boundary.

* Implementation
- =proc.lifetime/register!= starts one ordinary managed task, monitors the local
  owner and acknowledges arming before the registration may be published.
  Owner death and explicit release select one cleanup path. An exact completion
  cell records success/failure; task death without completion refuses disposal.
- Replies use short-lived Erlang aliases plus exact ticket/PID guards. Release
  waits for cleanup; timeout is uncertain, never a claim that effects stopped.
- Managed spawn retains the complete graph until cleanup completes. There is
  no VM-global collector, full-table sweep or application-specific mechanism.
- =proc.attempt= provides atomic begin/owner attachment/one terminal result in
  an existing declared =reload.state= cell. Stale and duplicate replies refuse;
  candidate generations inherit the cell, other application instances do not.
- These are local resource/metadata mechanisms. Neither retries external
  effects nor proves that a cancelled provider request did not execute.

* Application adoption
Knowledger document query scopes use bounded temporary handles in an owned
cell: 4096 entries, 8 MiB per value, 32 MiB aggregate serialized charge.
Each admitted scope arms a lifetime registration before publication and captures
its exact cell for release. A pressure-only bounded pass reclaims proved-dead
request owners from the reserve-before-arm gap; ordinary admission never scans
all active handles. Live handles are never evicted or expired by a timer.

spawn. Its local grant/result publication is serialized with replacement
admission. Microsoft fake Graph moves to an ordinary owning server, with only
its PID in the declared cell; executable fake handles remain in that server.

* Prepared callback handoff
Add =Env/handoff_code!= with a predeclared target ticket and optional admission
token checked inside the physical module fence. Existing =transfer_code!= keeps
its original API. The target is indexed before activation, so a producer dying
before handoff leaves an inactive target, while death after handoff leaves an
accepted exact target discoverable in the original owner's table.

=code_lease_active?= observes exact ticket evidence under its module fence without
allocating another executing lease or invoking application code. Recovery must
work even near the bounded native lease capacity. Invocation still requires
the existing =run_code!= path and its independent accepted-execution lease.

=proc.callback/prepare-transfer!= and =commit-transfer!= expose this protocol.
A second handoff attempt cannot cancel an already accepted target. Forged
module lists, dead owners and expired/wrong-owner admission tokens refuse.

** Crash-safe move ordering
Prepared handoff inserts its complete target row list with one atomic ETS insert
BEFORE removing any old source row. A killed mover before insertion has not
accepted work; a kill after insertion leaves the exact indexed target active,
even when old-row deletion is partial. Do not describe two sequential ETS
mutations as one crash-atomic transaction.

The native 65536-row capacity bound includes both source and target during that
brief overlap. A handoff therefore needs one source-sized transient reservation;
capacity exhaustion refuses before target publication. There is no promise of
equal-sized handoff at a completely full ledger. Dispatcher backpressure must
keep caller-owned durable work pending when admission cannot reserve this space.

The dispatcher fixture will compile an isolated copy of this actual host source
with fault exits after target insertion and after the first old-row deletion.
The running Env module remains intact; test probes must use its publication
lock identity. Recovery must execute the indexed accepted callback once.

* Deferred supervision configuration
=defsupervisor= now emits a named zero-argument children factory in an immutable
spec. The native owner-start boundary accepts exactly one children source,
validates callable shape, retains graph/factory code, evaluates configuration
once, validates all children, and captures the same context for OTP restarts.
Preparation never executes configuration reads. Child restart reuses its initial
arguments rather than rerunning the tree factory. Ordinary explicit child lists
and =native-spec= remain supported.

* Dispatcher retention pressure
=proc.callback/try-invoke!= distinguishes native code retention refusal before
callback entry from the callback's own later exception. A private per-call
process marker is removed in finally; provider capacity exceptions after entry
propagate. Callback results named =:cancelled= still count as completed effects.

The dispatcher defers before-entry capacity pressure using one 250ms retry timer,
without spinning or losing accepted slots. Failure settlement retains its slot
until its local durable callback succeeds. The run boundary is recorded inside
the retained event, after native invocation admission. Managed worker spawn also
runs inside that event's exact captured generation, not the dispatcher version.
