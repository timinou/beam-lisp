* Thesis

Authorization in this system is one package (`auth`, pure-bl Biscuit) and
one decision function, for ANY entity — human, service, agent, CI runner,
test. Sandboxing is the same decision at a different seam: an environment
fork is a delegation, its caps are the delegated rights, and the rights
are Biscuit policy data. There is no second rights system.

Layers, each with one structural invariant:

    token    — auth package: attenuation only ever narrows (crypto +
               block scoping + fail-closed checks)
    env fork — PLAN-046 + caps: child caps = parent ∩ spec (intersection
               ONLY, computed at fork, never walkable back)
    OS floor — per-node-class: systemd hardening now, Landlock when
               per-path fs nuance is needed (gVisor rejected: per-OS-process
               granularity cannot see in-VM env boundaries; the VM is not
               distrusted once the interop gate is total)

* What already WORKS (shipped, suite-green)

- Capability gate (a70b2e9): per-env `:caps`, structural attenuation,
  total enforcement over the 4-path interop surface (static remote calls
  compile-rejected; remote-fn handle forging refused; dynamic `$remote`
  invoke checked; defnative unavailable in capped envs). Fail-closed:
  bind re-derives caps from the registry; destroyed env → empty caps.
  Deny-corpus: test/beam_lisp/caps_test.exs (11 exs tests).
- env stdlib namespace (priv/env.bl): `(:require [env])` — fork, with-env,
  isolated, capture/bind, caps/allowed?, eval. The sandbox API is NOT
  itself a capability: wrappers compile at :global as trusted substrate.
  Module names intern via binary_to_existing_atom (fail-closed, no junk
  atoms) — same discipline as auth.biscuit.datalog's symbol handling.
- The Biscuit bridge (priv/auth/sandbox.bl, facade `auth/caps-for` +
  `auth/sandbox-fork`): full authorize (signature → checks → policies →
  revocation oracle), then project the authority block's
  `["right" module op]` facts into the caps set. Block scoping makes the
  authority block exactly the rights ceiling.
- Working use-case suite — test/bl/auth_caps_test.bl (7 tests, green):
  1. mint CI-runner token (String call; File read+write) → authorize →
     project → caps vector
  2. sandbox-fork: granted modules compile+run, ungranted compile-rejected
  3. revocation oracle: revoked token → {:error {:reason :revoked}}, no fork
  4. ambient deny-overrides policy: token grants System, runtime policy
     refuses → :deny-policy (capability = what bearer may ASK; policy =
     what runtime ever GRANTS)
  5. sealed token authorizes; attenuating it throws
  6. fork∩fork monotonicity below the token (child asks more → holds less)
  7. hostile symbol-table module names drop out, no atoms interned

* Known limits (stated plainly)

- Static interop in code compiled at :global (any priv/ or app namespace)
  bakes direct applies past the gate — by doctrine the base image is part
  of the parent's authority (setuid-helper semantics). The gate governs
  NEW compilation/forging in capped envs; rights over PRE-COMPILED code
  are namespace/var-level (what the env can resolve), which PLAN-046's
  env isolation already scopes. Audit implication: anything a sandbox must
  not DO must not be reachable through a :global-loaded wrapper either.
- Revocation is a callback (auth §8): offline+TTL or online+oracle. W4's
  TTL check is the offline stance.
