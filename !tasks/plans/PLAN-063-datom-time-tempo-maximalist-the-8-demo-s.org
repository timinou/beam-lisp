* The central insight (why these demos, in this order)

Tempo's hard parts each map onto a beam-lisp engine that already exists. The
series walks that mapping from the ground up: first the representation
(01–03), then the two audiences it unlocks (04 predicate + join, 05 set
algebra as a query), then the payoff of living in =datom.time= (06
bitemporal), then the two solver-backed frontiers (07 uncertainty, 08
ChronoLog). Each file proves ONE row of the doc's scorecard.

The load-bearing correction from the design discussion: an interval is a
packed VALUE (=:db.type/time=), NOT an entity-with-five-datoms. This is
the =priv/datom/vector.bl= playbook (a value type + packed shape, for
storage/meaning/safety) applied to time. 02 is the demo that proves it, and
it is the sturdiness answer — the interval rides the same value-codec lane a
native =:db.type/instant= does (8-byte LE i64 lanes; an interval is a
fixed-width 20-byte record), gets an order-preserving KEY codec so it
range-scans on AVET, and falls back to the ESC lane for day-one correctness
before the packed lane exists.
