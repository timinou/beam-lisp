## Symptom

After editing `priv/boot/compiler.bl` (toolchain key rotates), there is no working path to run the new generation:

1. `mix compile.beam_lisp` (plain and `--force`) **silently no-ops under staging** — exit 0, no output, boot beams unchanged (verified: rebuilt beam lacks the new code; a manual in-VM `build/run` with `force?: true` builds fine).
2. Every `mix` invocation's `Bootstrap.install!` **copies the committed seed over `_build` ebin** on a manifest-key mismatch, so freshly built boot beams survive only inside the compile VM. `mix run priv/bootstrap/gen_manifest.exs` is a *separate* VM — its boot re-installs the old seed over the fresh beams before the copy runs, so the documented two-command ladder (`compile.beam_lisp` then `gen_manifest.exs`) captures the OLD beams. Only an atomic build+copy in one VM captures the new ones.
3. Even with genuinely new seed beams and a matching manifest, **match mode crashes at boot**: `undefined var: reader/delimiters` from `Loader.do_load` → `Compiler.eval_string` → `Reader.take-token`. Something takes the SOURCE path in match mode where staging mode interns from beams, and the source path has no live reader behind it (genesis deleted). Reproduced with cleared AOT cache; `BEAM_LISP_AOT_CACHE=off` does not help.

Because of (3), the tree currently runs everything through the staging path (committed seed key 5b22a… ≠ any live toolchain key), which means **the committed seed compiler is what actually compiles user code** — and it predates the `invariant` clause partition. `examples/guards.bl` (which uses the clause since 344bdcb) crashes at section 4 with `:erlang.tuple_to_list(nil)` in `compile-defserver` until the new generation is blessed.

## Hypotheses to check (in order)

- H1: In match mode, `AOT.ensure_loaded("reader")` answers `:no_module` (drift gate: boot-tier branch compares beam provenance key vs `compiler_key()` — rebuilt beams may be stamped with the STAGED compiler's generation key rather than the current one), so the loader falls to the source path, which needs the reader → circular crash. Instrument `stale?/2` for boot ns in match mode.
- H2: The staged (previous-generation) compiler miscompiles *current* `reader.bl` (a def-capture regression of the `capture_value_def` class), dropping `delimiters` from `__bl_init__` — the atom is present in the beam (verified) but may not be interned. Check whether `Ns.Init.Reader`'s replay includes `delimiters`.
- H3: `compile.beam_lisp`'s in_runtime/build path skips boot-tier namespaces while `bootstrap_staging` is set — hence the silent no-op. Grep `build.bl`/`build-plan.bl` for a staging or boot-tier skip.
