* Initial Message

Design the beam-lisp livebook: the literate-programming README TODO,
implemented. Both .bl.md and .bl.org first-class; prior art mined; the
maximalist version named; challenges and linchpins extracted.

* Verdict

Design complete. The livebook is a namespace wearing prose: the file stays
plain markdown/org (text covenant), projects to hiccup, and runs as datom
facts. Three renderings — `bl live` (notebook app), `bl doc build` (static
site), `bl doc run` (CI) — of one object. Five linchpins and six waves named
below; every "exists" claim in the design is verified against the tree.

* The five linchpins (decisions everything hangs on)

1. L1 doc = namespace — cells are views over one ns; edits recompose ns
   source and stage through reload (the unit of coherence stays the ns).
2. L2 owned spans only — the tool writes `bl-result` fences / `#+RESULTS:`
   and nothing else; parse∘render = id is a tested fixed point.
3. L3 static coherence = notebook never lies — held bundles, old code
   serving, reasons next to the cell (reload.bl, as-is).
4. L4 results are facts — every run transacts {:run/cell status value
   stdout ms basis at}; file spans are projections; as-of + collab free.
5. L5 deterministic serialization — sorted-key inspect, bounded output;
   same code → same bytes → clean diffs.

* Waves

** W1 format + covenant — slicer/renderer for both dialects, ID minting,
   round-trip fixture tests (mangled, CRLF, Obsidian). Zero runtime risk.
   Accept: fixture corpus byte-stable.
** W2 `bl doc run` — ward-isolated eval w/ kill timer + stdout capture
   (spawned env-conveying process, group leader swap), result facts, owned
   spans written, deftest cells run, exit 1 on failure.
   Accept: tutorial doc green in CI; second run = empty git diff.
** W3 doc joins the ecosystem — find_file tries .bl/.bl.md/.bl.org
   (loader.ex:283 hardcodes ".bl" today); watcher extensions
   (reload_watcher.ex:111); pos-map translates coherence errors to doc lines.
   Accept: a .bl.md is :require'd by plain .bl and AOT-compiles.
** W4 `bl doc build` — md/org-subset → hiccup, loom theme, search over doc
   facts, hiccup->html. Accept: docs/ renders to a navigable site.
** W5 `bl live` — Pulse-style notebook app over run facts; session conn per
   viewer; result-viewer registry (hiccup passthrough first); as-of slider;
   two tabs converge. Accept: 05-two-tabs pattern on a notebook.
** W6 reactive close — impact-scoped re-run on save; `--check` doc-test CI
   mode; unify with explorer ^:catalog; MCP surface for agents.

* Known landmines (named in design §7)

- PLAN-009 atom-table hazard lands BEFORE bl live invites free-form evals.
- pos-map is the real W1/W3 engineering (errors must point at paragraphs).
- No print capture exists today (env/capture is env conveyance, not IO) — W2 adds it.
- Org support is the babel subset forever; no full org parser.

* Prior art mapped (design §2)

org-babel (owned spans), Jupyter (cell IDs, JSON lesson), Livebook
(text-first + Kino), Clerk (doc=program, viewers, static), Pluto (dep-graph
reactivity), Wolfram (notebook=expression), Smalltalk (image-view), Gorilla
(hiccup outputs in file), Quarto (freeze). Beam-lisp already owns each
system's missing half; the mapping table is the design's §2.
