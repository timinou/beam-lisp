* 1. Context — what exists today

`bl repl` (priv/std/bl/repl.bl.md) is a minimal loop: `IO/gets`, a paren-balance
scanner (`balanced?`), `*1/*2/*e` interned in `user`. No line editing, no
history, no completion, no color.

Assets this plan composes (all already in the tree):

- `bl daemon` — long-lived warm VM; `priv/std/bl/daemon.bl`,
  `lib/beam_lisp/server.ex`, `lib/beam_lisp/web_socket.ex`. The repl doc already
  says "the daemon can serve a session inside a warm VM".
- `priv/std/vm/` — session, wire, gateway, manager, ports: the daemon's
  session/eval machinery. The wire protocol for the REPL rides this or its
  shape.
- `BeamLisp.Env` — interned vars per namespace; the completion corpus.
- `priv/std/bl/doc.bl` — doc metadata (`:doc`, `:arglists`) for completion
  side-panels and arglist tooltips.
- `editors/tree-sitter-beamlisp` — the grammar; same source of truth for
  highlighting the editors use.
- `native/wry_webview` — webview native; the desktop shell for the web UI
  without Electron.
- `priv/lib/live/` — hiccup/diff/socket: prior art for browser ↔ daemon UI.
- LSP effort (`priv/lib/lsp/`, `research/lsp/`) — completion locals/static
  analysis later; the REPL index should share its corpus, not grow a second one.

Host constraint (verified in ~/.agents/AGENTS.md): this workstation runs the
Elixir VM with ONE dirty-IO scheduler (`+SDio 1:1`). Any blocking NIF (a
terminal line editor reading stdin) holds that scheduler hostage and stalls all
file-server ops in the VM. Terminal line editing must therefore be a separate
port process — or avoided, which the web path does. Also: no per-candidate file
round trips on the completion hot path; the index lives in ETS/memory.

* 2. Decision — web first, protocol is the product

**Web (browser tab or wry webview window), served by `bl daemon`.**

Rationale:
1. "Polished, feature-complete" is where the terminal caps out: dropdown
   completion with doc side-panels, arglist tooltips, collapsible value
   inspector (maps/vectors/lazy seqs), charts later. CodeMirror 6 provides the
   editing substrate; none of it is ANSI heroics.
2. The backend already exists: daemon + vm/session + warm VM. Cold-boot per
   command is `bin/bl`'s real cost; a daemon-backed REPL is warm → fast.
3. The dirty-IO scheduler hazard (§1) makes a *correct* terminal editor a port
   process, not a NIF — real work the web path simply does not need.
4. `native/wry_webview` gives a desktop window for the same UI.

Honest counter: a terminal REPL is the daily-driver over ssh/tmux. The design
keeps it reachable — the frontend is thin, ALL language knowledge lives behind
the wire protocol, so a reedline/rustyline port-process frontend is a later
add, not a rewrite. Not built first.

* 4. Architecture (post-spike target)

```
browser / wry webview
   │  WebSocket JSON ops: eval · complete · doc · interrupt · history
   ▼
bl daemon (existing Plug/WS layer)
   ├─ repl/session     one process per REPL session: own current-ns,
   │                   *1/*2/*3/*e; eval in a monitored task → interrupt = kill
   └─ repl/completion  shared index: Env vars × namespaces × doc meta,
                       memory-resident, invalidated on intern (proc/bus event)
```

Frontend is dumb: rendering, editing, keybindings. All language knowledge
(completion, docs, form-completeness for safety-critical paths) is server-side
behind the protocol. `balanced?` is ALSO ported to JS for keystroke-latency
gating, but the server re-verifies.

- Phase 1 — wire protocol + session core, IN THE DAEMON (spike proved the
  shape; `bl run` holds the AOT lock for life, so the server must be a
  daemon-class verb). Mount repl routes on vm.http (token auth seam exists):
  GET /repl (page), GET /repl/ws (upgrade). Session = a named eval context in
  the project VM (vm.manager/run × env/with-env), spike's model lifted:
  spawn_monitor worker + runner-owned DOWN cleanup, text group-leader proxy,
  one eval at a time per session, other ops concurrent. Acceptance: scripted WS

  `bl daemon` passes as-is.
- Phase 2 — completion index (REQUIRED, measured): materialised snapshot of
  Env/namespaces × public_names + doc/arity (doc_string info map + ns_defs),
  refreshed on intern (event if one exists — spike did not check for an intern
  hook; poll-diff fallback measured cheap: full rebuild 67–113 ms). p95 lookup
  <10 ms against a 1679-var corpus. Share the corpus shape with the LSP effort;
  one index, two consumers.
- Phase 3 — web UI, hardened from the spike page: committed esbuild bundle
  (395 KB — vendoring solved, no CDN, no build step), clojure mode, dropdown
  with ns + doc side-panel, keymap BEFORE basicSetup (spike trap #2), frames
  are bl Vectors [:text payload] (spike trap #1), balanced? gating with the
  FIXED scanner (BUG-087), persisted history.
- Phase 4 — polish: arglist tooltips (arities from ns_defs; full arglists need
  the def_ast walk — follow-up), collapsible value inspector, interrupt button,
  rainbow parens + auto-close, pprint truncation + lazy-seq realization caps,
  wry shell (`bl repl` opens a window — proven on this host; `--web` a tab),
  session reattach by id.
- Phase 5 — perf pass: no file I/O on completion/eval hot path (dirty-IO
  constraint), index warm in daemon, RTT budget eval <50 ms / completion <30 ms
  on localhost (spike warm numbers: eval 4–23 ms, indexed completion ~2.6 ms —
  budgets are realistic with margin).
