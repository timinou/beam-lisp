* Actual problem
datom.query.engine/ns-resolve resolves supplied predicate names with Env.fetch
in the querying namespace. That is intentional for trusted application programs,
but an external query can thereby acquire application callbacks. Restricting the
model evaluator alone does not close kn/query or MCP library/query.

* Implementation
Shared datom.query.functions/with-only surrounds the existing external handler.
It selects exact SDK pure functions with no namespace/reflection fallback.
Nested policies only narrow. Ordinary trusted queries preserve their semantics.
The authoritative engine preflights nested predicates and every supplied rule
body before execution and cache returns. Quoted data remains inert. Computed
relations resolve only fixed SDK providers inside this boundary; a development
provider shadowing a builtin cannot supply its implementation.

Require bounded first-order query literals as well: a forged foreign Enumerable
struct must not turn an apparently pure count/first into IO. Reuse a generic raw
data validator, not application exclusions or compiler proof module loading.
