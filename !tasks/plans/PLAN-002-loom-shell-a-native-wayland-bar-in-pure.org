═ DESIGN PROPOSAL — loom.bar ══════════════════════════════════════════

A Wayland statusbar as a beam-lisp app. No Quickshell, no QML, no C++, no
webview, NO NIF. The bar is a BEAM process tree speaking the Wayland wire
protocol directly, views are pure functions, state is datoms, crashes are
supervised, code is hot-swapped.

## VERIFIED ON THIS HOST (2026-09-01)

1. OTP 29 `socket:sendmsg` passes SCM_RIGHTS over AF_UNIX (tested: fd
   received as `ctrl => [#{type => rights}]`). ∴ fd handoff for wl_shm
   pools needs NO NIF — `file:open` a tmpfs file in $XDG_RUNTIME_DIR,
   `file:write` pixels, `sendmsg` the fd. Zero mmap on our side (the
   compositor mmaps).
2. `socket:open(local, stream)` + connect to `$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY`
   speaks to live niri. A 60-line pure-Erlang probe (`/tmp/wlprobe.erl`,
   bit syntax `/little`) decoded the full registry: zwlr_layer_shell_v1 v5,
   wl_shm v2, wl_seat v9, wp_cursor_shape_manager_v1, zwlr_gamma_control_manager_v1,
   zwlr_foreign_toplevel_manager_v1 v3, ext_workspace_manager_v1, wp_viewporter,
   wp_fractional_scale_manager_v1, ext_idle_notifier_v1, ext_background_effect_manager_v1,
   wl_output v4, zxdg_output_manager_v1. Everything a bar needs is advertised.
   NB wire words are little-endian; header word = op:16/low, size:16/high.

## THE ONE IDEA

**The request is a value; the protocol is data.** relay made the HTTP
request a value; the same move makes a Wayland request `[{req obj op args}]`.
The protocol XML projects to EDN protocol tables at boot; the codec is a
pure function over that data. No codegen, no C — a new protocol is a new
XML file in priv/wayland/protocols/.

## ARCHITECTURE (process tree)

bar.sup (supervise :one-for-one)
├── wl.conn — owns the AF_UNIX socket. recv loop → decode events → FACTS
│   (datoms :wl/* in the shared bar db). Requests are values it marshals.
│   New protocol object = row in the object table (process state).
├── output.<name> per wl_output (hotplug: niri event → child added/removed)
│   ├── surface — layer-shell lifecycle as defserver. ^{:invariant}
│   │   encodes the ack_configure-before-commit discipline → system.bl
│   │   PROVES we never commit a protocol error (compositor can't kill us).
│   └── pool — 2 buffers/surface (bounded, veritas obligation), double-
│       buffered, damage = changed rect from the tree diff.
├── niri.ipc — niri's own Unix-socket JSON event-stream → facts (workspaces,
│   focused window). Richer than foreign-toplevel on niri.
├── widgets.* — one process each: clock (receive after), battery (/sys),
│   brightness (/sys), volume (busctl --user monitor -j port, v1 seam),
│   gamma/night-light (zwlr_gamma_control IN-PROCESS — noctalia spawns
│   wlsunset with hand-rolled restart logic; we bind the protocol),
│   idle (ext_idle_notifier), toplevels (zwlr_foreign_toplevel).
│   A widget crash restarts; its facts repopulate; the bar never blinks.
└── renderer — PURE: db → view tree (loom box algebra + tokens) → canvas
    ops → iodata ARGB frame. Memoized (font,size,color,text) → binary
    segment cache; a frame is iodata concat of cached segments.

## THE VIEW (reuse, don't invent)

Same contract as live: view : (shared-db, session-db, locals) → tree.
The bar is `defbar` = `deflive` (a view IS a defserver — the screen
carries ^{:invariant}). loom/token + loom/box give the design system.
NEW: two render targets for one view value (the mesmo move):
  live/client.js applies tree-diff ops to the DOM
  wl/renderer    applies tree-diff ops to shm pixels
THE DIFF IS THE DAMAGE: live/diff's keyed tree diff yields exactly the
changed box bounds → damage rect → paint → commit. Hit-testing is the
same tree walked in reverse (boxes carry the widget's intent tag).
Pointer/keyboard events → facts → datom commit → view re-projects —
the click never renders the screen, the log does (live-architecture §3).

═ EXECUTOR ALTERNATIVES (GUI implementation decision) ═══════════════════

What stays FIXED (loom ideology, all alternatives share it):
  view : (shared-db, session-db, locals) → tree   (pure, =-testable)
  tree → canvas-ops                                (the hiccup of pixels)
  diff(tree₁,tree₂) → damage                       (the diff IS the damage)
  events → facts; defbar = deflive w/ ^{:invariant}; supervise; hotswap
  animation = flow demand-pull frames (spring = pure fn of t; compositor
  frame-callbacks are the backpressure; zero frames at rest)

The canvas CONTRACT (stable across executors):
  [:fill rect color] · [:border rect w color radius] · [:glyphs origin run color]
  [:clip rect ops…] · [:opacity α ops…] · [:shadow rect r color]  (tier-2)

Alternatives (the choice is ONLY the op executor):
A. FLAT-SHM — fill/border/glyph/alpha only; rounded corners via scanline
   coverage (~20 lines); frosted look FREE from niri's ext_background_effect
   (compositor blurs behind our translucent buffer). Deterministic frames →
   golden-hash pixel tests. Weekend-scale. This is the spike.
B. FULL-SHM — adds shadows/gradients/bezier in pure lisp (coverage
   rasterizer + memoized shape cache). 2–4 wk. Zero deps, full determinism.
C. SUB-SURFACES — wl_subcompositor (niri: v1): widget = process = sub-
   surface w/ own buffer + damage. Process tree IS the surface tree;
   per-widget damage isolation; costs cross-widget shadows/sync care.
D. GPU-NIF — canvas ops → dmabuf (niri: zwp_linux_dmabuf v5) via small
   Rust path-renderer NIF (vger-class). Same seam shape as datom NIFs
   ("what the VM cannot say"). Breaks frame determinism (golden OPS
   instead); adopt when launcher/overview/animations demand it.

Text sub-choices (orthogonal): atlas-as-data (v0) → pure-lisp TTF
rasterizer (v1.5, golden-hash vs freetype) → harfbuzz NIF only when
complex scripts actually demanded (bar v1 = Latin + nerd glyphs).

Rejected: webview backend (that's live's job; drags an engine in);
GTK/Qt via NIF (state lives in toolkit = ideological betrayal);
cairo/pango port process (external process owns our pixels — rendering
IS our domain here, unlike req_llm which was genuinely external).

Sequencing: contract first, A as reference executor (the test oracle —
pixel-deterministic), B/C drop-in upgrades behind the same contract, D a
documented seam. Matrix: time-to-bar A≪B<C; fidelity A<B≤D; purity A=B>C>D;
provability A=B (frames) > C > D (ops only).
