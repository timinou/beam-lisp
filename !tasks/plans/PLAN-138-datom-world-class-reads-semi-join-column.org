* Principles (beam-lisp maximalist)
- Remove the CLASS, not the instance: every fix lands as (a) a tier change, (b) a counting-store
  test in test/bl/datom/cost_test.bl asserting store-op COUNTS (never timings), (c) a
  `bl lint` smell or `bl ask` question that detects the pattern in application code.
- One read funnel: store-fjall `:columns` mode is the only decode path; `:datoms` stays for ETS parity.
- Caches are basis-discriminated (corpus.bl discipline) — never a bare Agent.
- No parallel implementations: `pull-many` replaces the mapv; `q` gains `:limit`, apps stop sorting.

* Waves
** W1 — join engine: semi-join by cardinality  (engine.bl pattern-scan-once)
When the join variable is bound in EVERY row (values differ), choose:
  |distinct(join vals)| ≤ K (default 4 096) → per-value prefix reads via ONE store call
  (new Store capability `MultiScan`: `-scan-prefixes [store prefixes]` → fjall NIF
  `fjall_resolve_prefixes`; ETS impl = mapcat of ranges) else column scan + hash join (today).
Tests: cost_test — `a-bound-join-over-N-entities-reads-N-prefixes-in-ONE-store-op`,
`a-join-wider-than-the-column-falls-back-to-one-column-scan`; conformance unchanged.
Explain: plan-trace reports :multi-prefix so `datom/explain` shows the choice.

** W2 — columnar read funnel + skip-filter + pushdown  (store-fjall.bl, db.bl, engine.bl, lib.rs)
- `-scan-datoms` takes a `need` mask `#{:e :a :v :tx :op}` and an optional native predicate
  `{:v-includes "…"}` / `{:v-in #{…}}`; requests `:columns`; materialises only surviving rows.
- NIF returns per-chunk `has-retractions?`; `filter-datoms` skips the retraction map when
  every chunk is assertion-only and no since/valid bound (`current?` fast path).
- `:limit` for non-aggregate finds stops the fold; `(count ?x)` over a single pattern →
  native count mode (no terms).
- adaptive chunk: 512 → ×4 up to 16 384 while chunks come back full.
Tests: cost_test counts NIF crossings (`a-full-column-read-is-⌈n/chunk⌉-crossings`), a
`:limit` test in query_test, includes?-pushdown parity test (same rows as post-filter).

** W3 — pull-many + plan/rule memo  (pull.bl, engine.bl, rules.bl, analytic.bl)
- `pull` = ONE eavt prefix read per entity, grouped by attr; `pull-many` = one MultiScan.
  cost_test: `pull-costs-ONE-range-per-entity` (replaces per-attribute), `pull-many-is-ONE-op`.
- parsed+planned query memo keyed by query value (bounded persistent map, 1 024 entries).
- rules memo: (store, rules-fingerprint, basis-t, filter-mode, since-t) → relations; only rules
  reachable from the :where invocation set are materialised.
- `ensure-registered!` guarded by an atom flag (no Agent hop on the hot path).

** W4 — vector lane + fjall config  (value-codec.bl, index.bl, lib.rs, store-fjall.bl)
- `LANE-VECTOR`: packed f32 with dim header; native decode → one refc binary, zero per-row terms.
- `:db.type/vector` attrs are NOT written to AEVT by value; the corpus assembles from an
  EAVT-keyed native reader (`fjall_resolve_column attr → [ids body]`), one crossing.
- fjall open options from store opts / env: `cache-mb` (default max(64, min(1024, store/8)),
  ONE shared cache per process), 32 KiB blocks, one partition per index tag, `fsync` policy
  explicit (`:journal` default = today; `:tx` = SyncAll per commit; measured +2–3 ms/tx on btrfs).
- store migration: `datom.migrate` step re-encoding vector values (dry-run via `with`).
Tests: value_codec roundtrip for the new lane, corpus_cache_test peak-memory bound, migrate test.
