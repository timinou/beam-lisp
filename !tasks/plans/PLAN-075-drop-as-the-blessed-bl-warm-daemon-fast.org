* Why (measured, 2026-09-03, branch feat/fully-self-hosted @ 138f5b6)

The escript is being deprecated in favour of `drop` (tooling/drop — a
self-extracting mix-release bundle carrying ERTS + the full native tier:
lang + datom Rust crates + z3 + Explorer). Two measured facts drive this:

1. **Escript cold-load is catastrophic.** `bl version` = 29s, `bl eval '(+ 1 2)'`
   = 36s, `bl run hello.bl` = 32s. Cause is NOT build-lock (the old W5 premise)
   — it is per-invocation loading of ~1073 beams / 2688 modules from the
   in-memory escript archive into a fresh BEAM. `BeamLisp.AOT.boot()` under a
   warm `mix run` is 29ms; the 29-36s is pure archive module-load.

2. **The mix-release path drop runs is 30x faster for free.** Release
   `bin/bl eval '(+ 1 2)'` = 1.2s (bare VM 0.35s + AOT.boot 0.6s + eval).
   `drop pack` → cache-hit run ~0.9-1.3s; first run 3.5s (extract 258MB).
   And z3/datom NIFs WORK in drop (measured: `z3/check` sat in 1.5s) — they
   CANNOT ride an escript archive at all. Drop is strictly better on every axis.

∴ Direction: make **drop the blessed `bl`**, and add a **warm daemon** so the
steady-state dev loop is ~instant (~30ms/call) instead of 1.2s. The drop
launcher is already a tiny native Rust binary (~1ms start) — it IS the thin
client the daemon needs, so the oracle's #1 risk (native-client floor) is
solved for free.

Scope chosen by user: **B** (drop-as-default + warm daemon fast-path).
Cross-target NIF staging for green bundles everywhere = **C**, deferred to a FUP.

* Architecture (drop-rebased from the oracle W5 design, agent://1-DaemonDesign)

** The three tiers of `bl`
| how invoked | cost | when |
|---|---|---|
| daemon attach (warm VM) | ~30ms | steady-state dev loop, daemon up |
| release cold boot (`bin/bl`) | ~1.2s | daemon down / first call / CI one-shot |
| escript (deprecated) | ~30s | legacy only; kept building until drop fully lands |

** Transport — AF_UNIX + {packet,4} + ETF[:safe]
- Pathname AF_UNIX stream socket under a 0700 user dir; socket 0600; 256-bit token.
- `:gen_tcp` legacy `inet` backend (OTP: socket backend unsupported for local domain):
  `:gen_tcp.listen(0, [{:inet_backend,:inet}, :local, {:ifaddr,{:local,path}}, :binary,
   {:packet,4}, {:packet_size, 16_777_216}, {:active,false}, {:send_timeout,5_000}])`
- ETF payloads decoded `:erlang.binary_to_term(p, [:safe])` + recursive schema validate.
- One logical request per connection. Handshake (hello→ready|reject) BEFORE any command;
  never replay after a request frame is sent (side effects may have happened).

** The launcher IS the client (drop-rebased — KEY divergence from oracle)
The oracle assumed escript + a NEW native client + a `bl-runtime` sibling. Drop
collapses this: `tooling/drop/src/launcher.rs` is ALREADY the native binary the
user runs. It gains the daemon fast-path:
  1. argv is `daemon start|stop|status` → native lifecycle.
  2. `BL_DAEMON=off` → skip straight to cold exec `bin/bl` (current behaviour).
  3. resolve tree-id = sha256(realpath of the run root — cwd for a dev tree,
     or the extracted payload dir for an end-user drop); probe socket.
  4. socket ready + hello ok → stream request/stdout/exit (~30ms).
  5. socket absent/refused → default: cold exec `<install>/<sha8>/bin/bl eval Cli.main(argv)`
     (today's path, 1.2s). `BL_DAEMON=auto` → acquire O_EXCL start-lock, spawn
     detached `bin/bl daemon start`, wait ready, retry once. Auto-start opt-in —
     no surprise multi-second background boot.
- Fallback is byte/exit-equivalent to today's launcher. The daemon is pure upside.

** Daemon launches from the RELEASE, not `mix run` (drop-rebased)
The oracle said `elixir -S mix run --no-halt` (checkout-only). Drop must work for
an end user with NO checkout, so the daemon boots from the extracted release:
`<install>/<sha8>/bin/bl daemon start` → `BeamLisp.Daemon.Server.start_from_env!`.
For a dev checkout the same `bin/bl` (from `mix release`) is used; source `-p`
dirs are client-supplied per request so the warm VM serves edits live via the
loader's ambient-dirs binding + the watcher.

* Risks (ranked, drop-rebased)
1. I/O fidelity + backpressure (stdout per-group-leader OK; :standard_error is a global named device) — permanent stderr multiplexer keyed by request GL; synchronous bounded writer; heartbeat; large-output/stdin tests. [was oracle #3; now #1 since native-client risk is gone]
2. VM-fatal user actions — System.halt/NIF crash kill the whole daemon; remove owned halt paths, detect EOF as unknown-outcome, never replay.
3. Global BEAM/module state across requests — ONE Executor worker at a time; Env.isolated for vars; pinned Loader.Server; explicit cleanup tests.
4. Version/restart races — handshake-before-enqueue; uncached current key; build-id sidecar; draining; generation-scoped start lock.
5. Watcher availability — file_system is dev/test-only; daemon from a release must degrade with a clear "watch unsupported in this build" if FileSystem absent (or ship it in the release).
