#+TITLE: Fence native publication against retired scopes
#+DATE: 2026-10-08
#+STATE: PROTOTYPE PREPARED; NOT INTEGRATED

* Concrete gap
The accepted scope fence prevents late metadata rows. Link.defvar still compiles
outside that short fence and loads native bodies/shims before fenced ETS writes.
A scope destroyed during compilation can therefore load code after retirement.
Link.settle and AOT emission/cache replay contain equivalent native-load seams.
Publication generations protect evidence readers; they do not undo code loading.

* Logic prototype
research/navigation-next/native-publication-retirement-protocol-test.bl contrasts
metadata-only fencing with short native commit admission over prepare/enter/load/
publish/destroy/owner-death histories. It includes an actual Env refusal probe.
It is prepared, NOT YET RUN: the owned four-run browser comparison holds the one
BEAM check lock. Run it through the capped source helper after that comparison.
A witnessed finite model is not proof of crash-atomic multi-module publication.

* Candidate implementation
Keep namespace ownership while preparing immutable compiled bytes. Detach other
scopes' lazy AOT references BEFORE acquiring the publishing scope's commit lock.
Load the prepared native batch under the existing short scope/destruction lock;
refuse retirement before any load. Keep user initializers, file I/O, compilation
and other scopes' locks outside this boundary. Existing metadata mutations retain
their own fence and publication generation protocol. Do not hold a scope lock
around a whole loader or an arbitrary callback.

A narrow shared prepared-batch seam can cover Link.defvar, Link.settle and AOT
emission/cache replay without moving inherited metadata reads into a child lock.
Inspect generated on_load behavior before treating code/load_binary as callback
free. Raw host/native loading remains a separate trusted boundary, with explicit
coverage rather than an unsupported claim of universal revocation.

* Required gates
- Delayed already-prepared batch after destroy: refusal, unchanged actual native
  MD5 and old behavior in another live scope, no new scope rows.
- Accepted native commit versus destroy: retirement waits until the owned native
  batch completes, without locking another scope or calling user initialization.
- Two scopes/two namespaces: detachment never nests scope locks; no inversion.
- Owner death and native load error: locks release; no claim that already loaded
  modules roll back. Dependency evidence declines incomplete publication.
- Actual Link/AOT/reload/parent-shadow/source/package gates; regenerate official
  host seed and build a clean SDK if host implementation changes.
- Repeat browser parity; compare new artifacts as bundles and preserve negative
  results. No cancellation authority is inferred from native retirement fencing.

* Explicit remaining limits
Already executing functions are not revoked. A killed process can leave an inert
loaded body; VM code-version leases and immutable executed call graphs remain
separate stage-seven/stage-four work. Multi-module loads are not transactionally
rolled back by the Erlang code server. Application developers configure nothing.
