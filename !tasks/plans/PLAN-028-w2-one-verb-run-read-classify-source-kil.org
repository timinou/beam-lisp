* Intent

The user: "define makes no sense, there should just be a run that does it all." machine/repl/agent = one GenServer (BeamLisp.Spell.Live, renamed Loop) with ONE verb: run.

* What changes

1. The tool the model gets: name `run`, schema `{source, rationale}`. The model writes the SAME source a human author writes: `(defcontract …)` / `(defview …)`.
2. spell.define → spell.run: the JSON-proposal machinery (proposal-keys, proposal->contract/view, template-form, bind-form, event-clause stubs) is replaced by READ + CLASSIFY + SANITIZE:
   - read exactly one top-level form (reader only — never eval; eval-in-image is W4's fence)
   - classify: head must be defcontract|defview
   - sanitize: `(on …)` handler bodies are SHAPE, not behaviour — extract reply tags, replace bodies with inert stubs (identical security boundary to the deleted JSON path: a model must not write server code through a rendering tool)
   - feed `(parse …)` / `(parse-view …)` — downstream cannot tell a model's definition from an author's (unchanged property)
3. Kill the sync turn (Live.ask/turn) and the no-loop fallback in Spell.Server.maybe_ask: the browser path REQUIRES the loop; absent loop = loud error, never toolless prose.
4. Spell.Live → Spell.Loop; define/2 → run/2 taking source text; ask_async stays the browser entry.
5. demo.exs drives the async path.

* What does not change

Rungs 2-4 (machine joins, verse candidate check, ghosts) are untouched. The atom-table safety of read (PLAN-009) is the reader's, already tested.
