* Goal

A live environment whose interface AND repl state update automatically through
LLM interaction: one browser tab + one long-running BEAM process; the model
grows the machine via a single `define` tool (PLAN-024); accepted definitions
re-emit → rebuild → the page reloads itself; the machine registry IS the repl
state, queryable by the model.

- priv/contract.bl — parse/parse-view, EDN + contract-JSON emission
- priv/seam.bl — pairwise contract↔view checks (events/assigns/reply-tags/disagreements)

** Phase 2 — spell.define: the tool
- JSON args → term via contract/parse | parse-view
- Validation ladder (MVP rungs, each rejects with the diagnostic as tool result):
  1. schema — arg shape

** Phase 3 — spell.live: the loop
- Driver owns: machine atom (registry), transcript.
- Turn: provider/stream-async with tools → assemble reply → on tool_calls

  served dir → version bump.

** Phase 4 — auto-reload, cheapest honest

  zero server change.
- State across reload: driver writes seed.json (transcript + machine/report)
  next to the bundle; host fetches it into SpacetimeLocal. This doubles as
  "repl state visible in the interface".

Recorded here because the stub is gone and the real `spell.provider`
implements only the first two items. These are LATER waves, not lost work:

- `(register-providers!)` → populate STORE's :registry cell: provider-id →
  {:ask fn :default-model "…"}. Data, not code sprinkled with defs.
- `(load-credential provider-id)` → {:kind :oauth :access … :refresh …
  :expires …} | {:error msg}. Read fresh each call (rotation-tolerant).
- `(ask provider-id cred prompt model)` → {:ok text} | {:error msg}, run
  inside spell.fence with a generous deadline. ✓ BUILT (as spell.provider/ask)
- streaming to a target pid ✓ BUILT (spell.provider/stream, stream-async)
- `(eval-tool! code)` → BOUNDARY-read the code, FENCE the eval on a SCRATCH
  namespace, or a separate NODE so a model's `(System/halt)` kills the scratch
  node and not the harness. Truncate output at 4000 chars.
- `(agent-ask history prompt)` → {:log [...] :reply text}: the multi-turn tool
  loop, bounded by max-turns (8). W3–W5 build this shape for the `define`
  tool specifically; the general eval-tool version remains future work.
- Cassette layer: SPELL_CASSETTE / SPELL_CASSETTE_MODE env, modes
  record | replay | auto. REPLAY fails loud on a miss; auto demotes to
  network — deliberate permissiveness, visible in the cassette log.
