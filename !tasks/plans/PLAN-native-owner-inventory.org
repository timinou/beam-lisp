#+TITLE: Automatic application-scoped physical owner inventory
#+DATE: 2026-10-13
#+STATE: IN PROGRESS — upstream infrastructure, sandbox only

* Outcome
Discover actual native registrations automatically from ordinary server starts,
versioned-owner initialization and queue-runtime initialization. Keep application
scope, physical PID, exact registration ticket and native authority separate from
source declarations. Products must not maintain a parallel list of live owners.

* Implementation batches
1. IMPLEMENTED: Env owns a dedicated ordered registry for the VM lifetime. Partition keys by
   application ID; bounded ordered pages must not scan the shared var table or
   unrelated tenants. App-specific lock/revision pairs prevent half registrations
   and stale paginated receipts. Exact-ticket removal never deletes a newer row.
2. IMPLEMENTED: Automatic native registration at existing lifecycle boundaries. Capture
   application/generation from bound runtime context, not an app-supplied label.
   Keep public observations free of callback functions, leases and secrets.
   Registration is discovery, not permission to migrate or stop an actor.
3. IMPLEMENTED: Join observations to existing generation/evolve/queue native authority; refuse
   unsupported owner kinds, dead/replaced registrations and stale receipts.
   Classify observed owners as transition-capable or requiring retained drain.
4. OPEN: Consume the inventory in the general reload/Foundry planning path. Actual
   candidate factories/contracts determine transitions; no product coordinator.
   Preserve old APIs during migration and retain code until native drain proves
   retirement safe. Cover spawned tasks, supervisors and sessions before calling
   the inventory complete for an application graph.

* Recovery design
The root Env owns both ordered membership and app-local seqlock counters. The
collector restarts against preserved rows; monitors/liveness are rebuilt and the
incarnation changes. No ephemeral collector-owned index can become falsely empty
after a crash. Exact-ticket close receipts also live in Env, so a role closed
while the collector is unavailable is pruned even if its containing PID survives.
Root Env replacement refuses rather than inventing an empty application; broader
runtime contexts/tables already require a fresh VM on that boundary.

* Safety boundaries
One paged observation is not a closed world. Native joins/deaths/updates invalidate
revision receipts. Recheck before publication; validate future admissions and
close old producer/factory admissions before retirement. Do not imply atomic
publication across several actors. A new kernel must preserve ordinary OTP
call/cast/info/continue, initialization/shutdown, physical resources and old-client
replies; prove code/state pairing at FIFO commit points before enabling it.

* Acceptance
Real native owners, two application instances with identical logical names,
pagination/limits, concurrent join/update/exit, stale tickets and stale cursors,
wrong-application attempts, callback/lease lifetime, registry owner lifetime and
application-local scan cost. Source/floor provenance, serialized capped VMs,
semantic commits and redacted evidence. No production or live Omega mutations.
