#+TITLE: v2026.7 — efficient compiler floors and cold starts
#+STATE: Proposed (written 2026-10-18 at the v2026.6 release; nothing implemented)

v2026.7 is scoped to two things only: making a compiler floor cheap to
(re)qualify, and making a cold `bl` start fast. Everything below was observed
while shipping v2026.6; numbers are measurements unless marked "estimate".

* Why: what v2026.6 cost
- One EtsStore fix (4602890c, a 12-line compiler change) needed THREE floor
  regenerations. Wall time per run: 35 min (load ~25–87), 19 min wasted on an
  unbalanced paren only detected at the boot build step, one run lost to a
  host reboot, then 23 min at load ~17 (CPU 23m40s, peak RSS 680 MB).
- Until the floor is regenerated, the checkout does not boot at all
  (`:stale_sdk_bootstrap_inventory`), and so does no probe, test or bisect.
  Bisecting old commits was impossible: each step needs its own floor, and old
  build images are refused ("this image is not usable as-is").
- Regeneration must run from a separate older checkout (`beam-lisp--rt`)
  through `.local/regenerate-seed-recovery.bl` (uncommitted recovery variant
  of `scripts/regenerate-seed.bl`). The v2026.6 drop cannot do it: run outside
  the tree, `(BeamLisp/argv)` lacks the script; inside the tree it mixes the
  tree's boot sources (`undefined var: compiler/list`); with
  `BL_BOOTSTRAP_SOURCE` it refuses ("Fresh native recovery required").
- Cold probes: each `bl --cold run` took minutes under load; at idle a warm
  command takes ~0.37 s (drop at 298392d3). Cold numbers in v2026.6 were never
  measured on a quiet machine — the first job of this plan is to do so.

* Current mechanics (read before changing anything)
- Floor = `priv/bootstrap/seed/` (106 files, 83 namespaces + manifest.term).
  Every beam is stamped with `compiler_key` (aot_cache.bl
  `compute_compiler_key`: elixir/otp/backend triple + codegen digest + tier-1
  toolchain source contents). Any toolchain source edit rotates the key and
  invalidates ALL 83 namespaces by design.
- `build_key` = compiler_key + `priv/build/` sources; drives per-build-tier
  parts (`priv/parts/<build-key>/`).
- `scripts/regenerate-seed.bl`: compile changed host ABI with the recovery
  compiler → load the replacement set → `build/run` boot units + `std/multi.bl`
  with `:jobs 2` (hard-coded) → `seed/run` → `seed/check` → install
  beams, app, manifest-last (`BL_BOOTSTRAP_INSTALL=1`).
- `seed/check` (priv/build/seed.bl `moved`) is ALREADY the incremental
  question: per namespace `:current`/`:moved`/`:unjudged`/`:absent` by
  comparing the beam's stamped source hash with the live closure hash. It
  compiles nothing. Takes seconds.
- `self-build --reuse-floor` (b1e3b0ce, priv/build/selfbuild.bl
  `do-reuse-floor`): runs `seed/check` + `Bootstrap/key_matches?`, SHA-256
  verifies and copies the committed floor into the drop, drops dev Ns outputs;
  refuses when stale. Library tiers ship as source, compile on demand.
- `scripts/check-runtime-hosts --work-dir DIR <tests>`: tests `priv/host`
  runtime-only edits against the EXISTING floor in two VMs (no regen).
- Cold-load reuse already in v2026.6 (950ef73e, b2b5b3a1, ad080d89): ns-header
  only reads, on-disk `replayable_source?` verdicts, primed parts, memoized
  seed/sdk-code digests, SDK receipt revision counter, `physical_sdk_path`
  lstat cache, command VM default for capable drops.

* Workstreams

** W0 Measure first (gate for everything else)
- Quiet-machine baseline (load < 2; `pkill` stale VMs; ≥3 samples, report
  spread): floor regeneration per phase (host ABI compile, boot build, seed
  run, seed check, install); cold `bl run hello.bl`, cold `bl test` of one
  file, warm equivalents, on checkout AND drop.
- Instrument regenerate-seed.bl phases with monotonic timestamps in its output
  (currently only the final maps are printed).
- Profile one cold start with the existing tprof scripts
  (`~/tmp/drop-try/prof5.bl`, `prof6.bl`, `callers.bl`). Last profile before
  ad080d89: physical_sdk_path 46k calls / 19.8 s, current_compiler_key 150
  calls / 2.9 s — re-measure to confirm those are gone.
Acceptance: a committed evidence file with the table; every later workstream
cites its delta against it.

** W1 Fail in seconds, not after 20 minutes (pre-flight)
- Before any expensive step: read every `priv/boot/*.bl`, `priv/host/*.bl`,
  `priv/std/multi.bl` with the reader (balanced forms) and compile
  `compiler.bl` ALONE with the recovery compiler; refuse with file:line.
- Also run the toolchain's own fast unit tests that do not need a new floor?
  (Explore: which tests can run against the recovery compiler + new host
  beams; record_declaration_test style compile-only checks qualify.)
Acceptance: an unbalanced paren in compiler.bl fails regeneration in < 60 s.

** W2 First-class floor qualification: `self-build --reuse-floor --qualify`
(user-requested direction) Extend --reuse-floor so a STALE floor is rebuilt
and qualified in the same command instead of refused:
1. `seed/check`; if current → today's reuse path.
2. else run the regenerate pipeline (W1 pre-flight → host ABI → boot build →
   seed/run → seed/check → manifest-last install into an OUTPUT dir, never
   in-place unless `--install`).
3. then package from the freshly qualified floor.
Questions to settle: who may install into the tree (CI vs local); keep
manifest-last atomicity; the drop must be able to host this (see W3).
Acceptance: one command takes a stale checkout to a verified drop; seed
--check on the result reports current; no `.local/` script needed.

** W3 Self-hosted recovery (retire `beam-lisp--rt` + `.local/` recovery script)
- Commit the recovery variant's real differences (native table evidence,
  `assert_fresh_native_recovery!` ordering, explicit project app) into
  `scripts/regenerate-seed.bl`, or delete whichever is obsolete.
- Make a release drop able to regenerate a checkout's floor: explicit
  `--source-root` that is NEVER mixed into the drop's own boot path; fix the
  `(BeamLisp/argv)` missing-script case; define what "fresh native recovery"
  requires and provide it from the drop.
Acceptance: `bl-v2026.7 floor regenerate --root <checkout>` works from any cwd.

** W4 Make the boot build faster
- `:jobs 2` is hard-coded in regenerate-seed.bl; derive from schedulers and a
  memory budget (observed peak 680 MB at jobs 2). Measure 2/4/8.
- Find the critical path in the boot unit dependency graph (compiler.bl is the
  largest); measure per-unit compile times from W0.
- Explore: reuse unchanged units when ONLY codegen-irrelevant inputs moved.
  compiler_key folds in all toolchain sources, so a comment/doc edit in a host
  file rotates every beam. Candidate: key on the emitted-codegen-relevant
  digest (e.g. normalized forms) rather than raw bytes. Must preserve the
  BUG-048 invariants and never accept a stale beam — design review required.
Estimate (not measured): W1+W3+W4 ⇒ a compiler change regenerates in ~10 min
on a quiet machine; a typo fails in seconds.

** W5 Host-only edits never need a floor regeneration
- Runtime-only `priv/host` edits do not rotate compiler_key but are checked
  by the pinned-host hash in seed/check. Make this path: recompile only the
  moved host modules, re-stamp, re-check — minutes, not the full pipeline.
- Generalize `check-runtime-hosts` into that tool.
Acceptance: editing one host function → floor current again in < 3 min.

** W6 Cold start
- From W0's profile: remaining per-start work in loader/AOT certificate,
  sdk inventory, replay verdicts. Options to evaluate:
  - Ship pre-primed `priv/parts/<build-key>/` and replay verdicts INSIDE the
    drop (release packaging), so first run on a machine is not a cold build.
  - Boot-image snapshot of a fully loaded VM state per drop (code + ETS
    tables that are pure functions of the drop) — measure vs current.
  - Lazy-load std/lib namespaces still eagerly loaded at boot.
- REJECTED in v2026.6, do not retry without new evidence: memoizing loaded
  module md5s in the certificate (unsafe); first physical_sdk_path chain
  memo; drop-hosted floor regen without W3's root separation.
Acceptance: cold `bl run hello.bl` on the drop measured before/after on a
quiet machine with the AGENTS.md protocol (≥3 samples, spread reported).

** W7 Make the floor bisectable
- A script that, given a commit, regenerates its floor in a throwaway
  worktree under a private TMPDIR/XDG_CACHE_HOME, cached by compiler_key in
  `~/tmp/bl-floors/<key>/` so revisiting a commit is free.
- Depends on W3 (old commits' build images are refused today).
