* Where this comes from

edamame (`borkdude/edamame`) is a mature, configurable EDN/Clojure reader. It is
**not** a dependency and never will be (JVM-only, and a second reader beside
`priv/boot/reader.bl` would be a second truth). What is worth taking is four
*contracts* it embodies. Each one deletes code or unblocks something we already
prototyped.

* The problem

`priv/boot/reader.bl` has exactly three entry points and no options:

    BeamLisp.Reader.read_string/2   positioned — LISTS ONLY
    BeamLisp.Reader.read_all/1      the same, positions deep-stripped
    BeamLisp.Reader.read_one/1      exactly one form, bare

The only difference between the first two is one boolean, and every downstream
consumer has to live with the same policy: no offsets, no streaming, no
`:preserve` reader conditionals, no restricted mode, and errors that carry a bare
message. The file's own comments record that several of these are **bug-for-bug
parity with the deleted Elixir genesis reader** (`#()` bodies, record literals
and data-reader payloads deliberately undercount their column). That reader is
gone; its implementation details are now frozen as if they were semantics.

* The four contracts, in build order

Ranked by value over blast radius.

**1. Errors are data (do this first).** `syntax-error` raises a message and
nothing else. Give it `{:line :col :file}` plus the open-collection state
(`:expected` / `:opened` / `:opened-loc` in our spelling), and put the position
in the *message*, because the CLI path loses the struct.

- Costs: ~30 lines in `reader.bl`, plus the CLI's error report.
- Deletes: the `bl run` silence (FUP-102: an unbalanced paren printed nothing and
  exited 141 — observed again this session, on `priv/lib/web.bl:479`, which
  edamame + an independent balance check both located in seconds while our own
  tool printed `unexpected )` with no file and no line).
- Unblocks: a repair rung (`fix-expression`, ported); `bl check` diagnostics;
  mid-typing LSP messages.
- Accept: `bl run FILE` on an unbalanced file prints
  `FILE:12:34: unterminated collection, opened ( at 12:30`, exit 1.

**2. Offsets in the span.** Thread a running codepoint offset beside the
position; the scan already walks every character once.

- Deletes: `span-rewrite.bl`'s `line-offsets` (a full second pass over the
  source) and the three copies of the line/col→offset arithmetic built on it.
- Unblocks: byte-exact slicing for the trivia-preserving rewriter and the LSP.
- Accept: `node-pos` carries `:offset`/`:end-offset`; `span-rewrite` slices from
  them with no `line-offsets` in the file.

**3. Span every collection, not just lists.** `wrap-list-pos` is called from the
list/prefix/dispatch paths and nowhere else, so a captured vector or map has no
span and Tool 1 falls back to `pr-str`, losing comments and shape.

- Do it as a reader option, on for tooling and off for the parse paths the
  compiler reads, so no existing tree shape moves by accident.
- Unblocks: the trivia cliff closes for every sub-form, not just list ones.
- Accept: a rewrite whose capture is a multi-line vector keeps the vector's
  comments byte-identically.

**4. `read` takes an options map.** One entry point; the existing three become
aliases:

    (read src {:file "a.bl"
               :location? :lists | :collections | :none
               :read-cond :select | :preserve
               :readers {...}      ; the dispatch table as data
               :read-eval false    ; the trust boundary, stated as a value
               :intern true})      ; the atom guard, stated as a value

- Deletes: `read_all` as a separate entry point; the post-hoc `unwrap-deep` for a
  caller that never wanted positions.
- Unblocks: a *restricted* read as the harness's admission contract —
  `trust-boundary.md`'s boundary stated in the reader call instead of enforced
  afterwards; `:preserve` for a formatter/rewriter over `.cljc`; a data-only mode
  that can never intern a novel atom.
- Accept: `read_all`, `read_string` and `read_one` are three lines each over
  `read`; the schema/tool-contract work (FUP-003) can derive from one reader
  value.

**5. Reading is a stream.** `(read-next reader)` / `(read-next+string reader)`
returning the next form and the advanced reader. Our `pos` threading already
models this — the returned position IS the head of the unconsumed source.

- Unblocks: form-at-a-time REPL evaluation; `bl watch` re-reading a suffix; a
  harness loop that reads what a model has written so far and answers per
  complete form instead of refusing the whole buffer.
- Accept: `(read-next+string r)` yields `[form "the form's own source text"]`
  with comments intact (edamame does exactly this; see the `:stream` rows).

**6. `:auto-resolve-ns`.** Read the `ns` form, keep its alias table, resolve
`::alias/kw` as the stream goes (edamame's `parse-ns-form` is ~40 lines).

- Unblocks: a cold, single-file LSP pass over an unsaved buffer.

* The oracle (independent of the above)

`bb research/edamame/oracle.clj rows|scan DIR…`. babashka ships edamame built in,
so this costs no setup. `rows` emits EDN rows a beam-lisp test asserts against;
`scan` reads every `.bl` and reports refused files with the reader's own error
data AND an independent balance verdict.

Measured today: `scan priv lib spell bin` → **237 files read, 14 refused, 0
unbalanced**; all 14 refusals are lexical rules where beam-lisp is deliberately
more permissive than EDN (`=/=` as a symbol, `+1→inc`, `\0` and `\(` string
escapes, `:"=<"`, `::foo`). Those rows are the dialect profile a real conformance
suite needs — the half that is still missing is comparing *acceptances*
tree-by-tree, which is what would catch a silent mis-read.

* Acceptance for the whole item

- `bl run` on a malformed file prints a positioned diagnostic and exits 1.
- `span-rewrite` slices without building a line-offset table.
- A read of a `.cljc` file in `:preserve` mode round-trips its reader
  conditionals through a rewrite unchanged.
- `grep -rn "read_all\b" priv/` shows only the alias.
- The oracle's `rows` corpus passes as a beam-lisp test, with `:dialect` rows
  asserting the difference rather than agreement.

* Round 3 — §2: a span carries the offsets that slice it (commit 41737f57)

`pos` gains a 4th slot; `pos-meta`/`pos-meta-span` emit `:offset`/`:end-offset`.
A span now slices its own source instead of being resolved through a table.

The unit is CODEPOINTS, measured rather than chosen: the one existing consumer,
`span-rewrite`, walks `(String/codepoints src)` and cuts with `subvec`, so
`(subvec cps (:offset pos) (:end-offset pos))` substitutes directly for
`(+ (get line-offsets line) (dec col))`. An earlier draft of the plan called for
BYTE offsets; that would have needed a conversion at every consumer to serve the
same slice. The plan and the spike README are corrected.

Measured: every top-level form's span slices back to its own text, including the
form after a multi-byte `→` and a form with an inner comment; three rich sources
(295 top-level forms) parse structurally identically modulo the two new keys.

* Round 4 — §4: the stream (commit 32bdb7a8)

`stream` / `read-next` / `read-next-string`, and `read-forms*` — the body of both
`read-string` and `read-all` — is now a loop over `read-next`. One loop, two
views, so batch and incremental cannot drift apart.

Measured: streamed forms == batch forms on priv/lib/web.bl (58); a form's own
text excludes leading trivia and preserves an inner comment; `:eof` after the
last form; the tree is unchanged modulo the offset keys.

A bug the first cut had, worth remembering because it hid: `read-next-string`
sliced the stream's REMAINING charlist by ABSOLUTE offsets — right for the first
form, silently wrong for every later one. The stream now keeps `:all`, the whole
source, and slices from that.

* Still open, and why (the four remaining steps)

1. §3's useful half — `:diagnostics :collect`, a failure returned as DATA — is
   blocked on the exception shape: `BeamLisp.Reader.SyntaxError` carries a
   message and nothing else, and the reader raises at the error site with no
   accumulator to thread through. Doing it properly means either a diag-carrying
   error term (a cross-language contract change with the host facade, which
   cannot be verified while the tree does not build) or threading a diag
   accumulator through the whole descent. The spike does the latter; the port
   needs a decision about the former.
2. §2's DELETION — removing `span-rewrite`'s `line-offsets` — is gated on every
   producer of a pos map carrying offsets. The compiler synthesizes positions for
   desugared macro nodes (`research/p2_positions`) outside the reader, and a
   synthesized position has no source to slice; so the fallback is permanent and
   the table can only go when the rewriter decides a span without offsets is not
   sliceable. That is a rewriter decision, not a reader one, and it needs the
   rewriter's tests — which cannot run here.
3. §5 (`:location :collections`) stays LAST, behind the three rules in the
   spike README: default off, audit the ~90 raw tag sites, gate on identical
   beams.
4. §6 (the repair layer) depends on (1): the forward check needs diagnostics as
   data.

* Round 5 — the failure becomes a VALUE (commit 8b794e65)

Prompted by the standing decision that Elixir goes: `SyntaxError` was an Elixir
struct that `reader.bl` reached UP to raise, so the language was borrowing the
host's vocabulary at 38 raise sites, and every consumer had to parse the message
back into structure.

Now `reader.bl` raises a DIAGNOSTIC MAP:

    {:bl_diag true :kind :unterminated-collection :msg "file:1:1: …"
     :line 1 :col 1 :file "…" :offset 0 :expected ")" :end-line 1 :end-col 2
     :end-offset 1}

— the shape `typed`'s warnings already have and `errors/render` already draws a
caret from. `:msg` is byte-identical to the old message, so nothing that reads
messages moved. `:kind`/`:expected`/`:closer`/`:opened-at` are filled in for the
four failures a REPAIR has a move for; the rest carry `:kind :syntax`.

`read` is the options entry: `{:file … :diagnostics :raise|:collect}`.
`:collect` returns `{:ok forms}` | `{:error diag}` — a failure with no raise.
`:raise` is the default, so `read-string`/`read-all`/`read-one` are unchanged
wrappers.

Measured: the six delimiter diagnostics carry their kind, `:expected`, `:closer`,
`:opened-at` and span with identical messages; `:collect` gives `{:ok forms}` and
`{:error diag}`; three rich sources parse structurally identically modulo the
offset keys; the host facade renders the value back into `SyntaxError` with the
same message (verified against the real `lib/beam_lisp/reader.ex` with the reader
ns and the atom guard stubbed), passes non-reader failures through untouched, and
still maps the atom guard.

A runtime fact worth keeping: beam-lisp's `catch` binds the runtime's
`%ErlangError{}` WRAPPER — `(catch e (:original e))` is the idiom, and even
`(erlang/error :boom)` arrives wrapped. `read`'s catch accepts either shape.

Consequence: §3's blocked half (`:diagnostics :collect`) is now DONE, and §6
(the repair layer) has the structured input it needed — no accumulator threading
through the descent was required, because the failure already carried its data.

* Round 6 — the same contracts, applied to the supervisor (PLAN-136)

Design transfer: `research/supervision-contracts/README.md`. The finding is that
the tree has THREE diagnostic vocabularies (reader diag map; checker
`{:msg :line :col …}` + caret; supervisor/OTP raw tuples) and the supervisor's is
the worst — an L12 violation. Its own source admits the gap: `super.bl` says its
state is "the child set AND THE RESTART LEDGER — both of which OTP keeps for us",
but `children` returns only the child set, so the declared policy
`(intensity 3 5000)` can be enforced and never REPORTED.

Measured while writing it: macro arguments carry NO source positions (a clause
reaches `defsupervisor` bare), so a supervision event's `:where` must come from
the runtime's `:ann` — the channel `errors/node->warning` and `typed/eff-pos`
already read. And the tree's `proc.super` loads from source under `./bl -p
priv/std`.
