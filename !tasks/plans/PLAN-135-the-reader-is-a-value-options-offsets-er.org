edamame (`borkdude/edamame`) is a mature, configurable EDN/Clojure reader. It is
**not** a dependency and never will be (JVM-only, and a second reader beside
`priv/boot/reader.bl` would be a second truth). What is worth taking is four
*contracts* it embodies. Each one deletes code or unblocks something we already
prototyped.

* The problem

`priv/boot/reader.bl` has exactly three entry points and no options:

    BeamLisp.Reader.read_string/2   positioned — LISTS ONLY
    BeamLisp.Reader.read_all/1      the same, positions deep-stripped
    BeamLisp.Reader.read_one/1      exactly one form, bare

The only difference between the first two is one boolean, and every downstream
consumer has to live with the same policy: no offsets, no streaming, no
`:preserve` reader conditionals, no restricted mode, and errors that carry a bare
message. The file's own comments record that several of these are **bug-for-bug
parity with the deleted Elixir genesis reader** (`#()` bodies, record literals
and data-reader payloads deliberately undercount their column). That reader is
gone; its implementation details are now frozen as if they were semantics.

* The four contracts, in build order

Ranked by value over blast radius.

**1. Errors are data (do this first).** `syntax-error` raises a message and
nothing else. Give it `{:line :col :file}` plus the open-collection state
(`:expected` / `:opened` / `:opened-loc` in our spelling), and put the position
in the *message*, because the CLI path loses the struct.

- Costs: ~30 lines in `reader.bl`, plus the CLI's error report.
- Deletes: the `bl run` silence (FUP-102: an unbalanced paren printed nothing and
  exited 141 — observed again this session, on `priv/lib/web.bl:479`, which
  edamame + an independent balance check both located in seconds while our own
  tool printed `unexpected )` with no file and no line).
- Unblocks: a repair rung (`fix-expression`, ported); `bl check` diagnostics;
  mid-typing LSP messages.
- Accept: `bl run FILE` on an unbalanced file prints
  `FILE:12:34: unterminated collection, opened ( at 12:30`, exit 1.

**2. Offsets in the span.** Thread a running codepoint offset beside the
position; the scan already walks every character once.

- Deletes: `span-rewrite.bl`'s `line-offsets` (a full second pass over the
  source) and the three copies of the line/col→offset arithmetic built on it.
- Unblocks: byte-exact slicing for the trivia-preserving rewriter and the LSP.
- Accept: `node-pos` carries `:offset`/`:end-offset`; `span-rewrite` slices from
  them with no `line-offsets` in the file.

**3. Span every collection, not just lists.** `wrap-list-pos` is called from the
list/prefix/dispatch paths and nowhere else, so a captured vector or map has no
span and Tool 1 falls back to `pr-str`, losing comments and shape.

- Do it as a reader option, on for tooling and off for the parse paths the
  compiler reads, so no existing tree shape moves by accident.
- Unblocks: the trivia cliff closes for every sub-form, not just list ones.
- Accept: a rewrite whose capture is a multi-line vector keeps the vector's
  comments byte-identically.

**4. `read` takes an options map.** One entry point; the existing three become
aliases:

    (read src {:file "a.bl"
               :location? :lists | :collections | :none
               :read-cond :select | :preserve
               :readers {...}      ; the dispatch table as data
               :read-eval false    ; the trust boundary, stated as a value
               :intern true})      ; the atom guard, stated as a value

- Deletes: `read_all` as a separate entry point; the post-hoc `unwrap-deep` for a
  caller that never wanted positions.
- Unblocks: a *restricted* read as the harness's admission contract —
  `trust-boundary.md`'s boundary stated in the reader call instead of enforced
  afterwards; `:preserve` for a formatter/rewriter over `.cljc`; a data-only mode
  that can never intern a novel atom.
- Accept: `read_all`, `read_string` and `read_one` are three lines each over
  `read`; the schema/tool-contract work (FUP-003) can derive from one reader
  value.

**5. Reading is a stream.** `(read-next reader)` / `(read-next+string reader)`
returning the next form and the advanced reader. Our `pos` threading already
models this — the returned position IS the head of the unconsumed source.

- Unblocks: form-at-a-time REPL evaluation; `bl watch` re-reading a suffix; a
  harness loop that reads what a model has written so far and answers per
  complete form instead of refusing the whole buffer.
- Accept: `(read-next+string r)` yields `[form "the form's own source text"]`
  with comments intact (edamame does exactly this; see the `:stream` rows).

**6. `:auto-resolve-ns`.** Read the `ns` form, keep its alias table, resolve
`::alias/kw` as the stream goes (edamame's `parse-ns-form` is ~40 lines).

- Unblocks: a cold, single-file LSP pass over an unsaved buffer.

* The oracle (independent of the above)

`bb research/edamame/oracle.clj rows|scan DIR…`. babashka ships edamame built in,
so this costs no setup. `rows` emits EDN rows a beam-lisp test asserts against;
`scan` reads every `.bl` and reports refused files with the reader's own error
data AND an independent balance verdict.

Measured today: `scan priv lib spell bin` → **237 files read, 14 refused, 0
unbalanced**; all 14 refusals are lexical rules where beam-lisp is deliberately
more permissive than EDN (`=/=` as a symbol, `+1→inc`, `\0` and `\(` string
escapes, `:"=<"`, `::foo`). Those rows are the dialect profile a real conformance
suite needs — the half that is still missing is comparing *acceptances*
tree-by-tree, which is what would catch a silent mis-read.

* Acceptance for the whole item

- `bl run` on a malformed file prints a positioned diagnostic and exits 1.
- `span-rewrite` slices without building a line-offset table.
- A read of a `.cljc` file in `:preserve` mode round-trips its reader
  conditionals through a rewrite unchanged.
- `grep -rn "read_all\b" priv/` shows only the alias.
- The oracle's `rows` corpus passes as a beam-lisp test, with `:dialect` rows
  asserting the difference rather than agreement.

* Not in scope

- Adopting edamame, or porting its internals. The four contracts are the
  deliverable; the metadata channel, syntax-quote expansion and `tools.reader`
  layering are not.
- Any change to what the compiler sees: items 3 and 4 must default to today's
  shapes for the compile path, and the cutover is proven by the existing reader
  suites (`test/beam_lisp/*reader*`) plus the 309-file corpus gate in
  `research/sh2_reader/corpus_gate.bl`.

* Round 1 — the prototype (research/reader-contracts/)

Built and RUN this session, as a script (no Mix, no .bl, nothing in the tree
touched): `elixir research/reader-contracts/test.exs` → **29 passed, 0 failed**;
`elixir research/reader-contracts/run.exs` → the demo, whose output in the README
is verbatim.

What it implements, in the order this plan asks for:

- **§1 (error data)** — %RC.Diag{kind, span, expected, opened, opened_span,
  eof_span, unclosed} + `read!/2` raising an RC.SyntaxError that still carries
  the position. FUP-102's acceptance is printed by the demo:
  `priv/std/proc/sched.bl:2:3: unterminated ( …`, exit 1.
- **§2 (offsets)** — every span has offset/end_offset; `slice/2` is the form's
  own text; `read_next_string/1` returns a form AND its source with comments.
- **§3 (options)** — :location :lists | :collections | :none (default :lists,
  i.e. today's shapes), :read_cond :select | :preserve, :diagnostics :collect |
  :raise.
- **§4 (stream)** — read_next/1, read_next_string/1 over a threaded reader.
- **§5 (wider location)** — implemented, but it is the LAST thing to turn on for
  a compile path; see the README's "Why the tree shape is the risk", which counts
  the affected sites (~90 raw tag matches, 88 raw tuple_to_list uses in priv/)
  and records that p2_positions already paid for getting the peel wrong once.

Beyond the plan, and worth keeping: **the repairs are verified forward.**
Candidates are ranked by edit count, then each is applied and the result RE-READ
(`solves?/3`). That collapses false ties (`(when x [1 2)`: replace-] vs insert-]
are both one edit, only one parses) and leaves real ones standing, where the
message says "N different repairs each balance the file — which did you mean?"
and `choose/1` still decides but returns `policy:` and `others:`. `fix_all/3` is
the loop for a source with two independent defects (an unterminated string AND
unclosed openers takes 2 rounds) — a one-pass "repaired" claim would be a lie.

Acceptance now observable, with the command: the six cases in run.exs and the 29
assertions in test.exs. Two bugs were caught by the suite during the build and
are worth remembering: the delimiter stack must POP on a successful close (a
stale entry misreports WHICH opener is unclosed), and `nil > 0` is TRUE in
Elixir's term ordering (an absent :invalid field read as a failure).

Still open: the port itself. No .bl file changed. §1 is the first cut and is
~30 lines plus the CLI's report.
