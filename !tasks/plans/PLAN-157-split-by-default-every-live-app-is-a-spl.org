* Goal

Make split the DEFAULT way every Beam Lisp web app runs, and make it production-ready. A developer writes a Loom/live.app exactly as today. The toolchain proves which screens and intents can also run in the browser and ships them there. That gives SPA reactivity (instant optimistic UI, offline queue, rebase) while the BEAM stays the only authority. Zero developer glue: no :wire schema, no :predict, no :agrees?, no page.json, no registration, no separate build step.

Everything that makes Loom great is preserved, because split BECOMES live.app plus a client tier, not a second app model. That keeps: pure views of db values, server authority, auth in datalog ("absent, not filtered"), as-of time travel, keyed diffs, a supervised process per viewer, resume instead of remount, the a11y guarantees, and events as data.

Scope decision (user, 2026-10-02): "the browser is another BEAM node" stays in research and FUPs (see * Deferred). This plan covers production split only.

* Target architecture

** One app model
A live.app map is the only declaration. Placement is decided per screen and per intent, never per app:
- A portable screen (pure over db values + locals, renderable by compiled Loom) is rendered in the browser from a local replica. Otherwise it is rendered on the server exactly as today (patch ops over the socket).
- A portable intent performer also runs in the browser against the replica, as the optimistic prediction. The server runs the same performer authoritatively.
- An app with nothing portable is today's live.app, byte for byte. That is what "default on everything" costs an app that cannot benefit: nothing.

** Performers take a db VALUE
Cutover: the performer signature (fn [conn payload principal]) becomes (fn [db payload principal]) and returns tx-data. Every existing performer immediately calls (datom/db conn) (e.g. examples/data/studio.bl vote), so the cutover is mechanical. With this signature the same fn is both the server's authority and the client's prediction. :predict and the :check/:apply duplication go away.

** The wire is the log
"They meet at the database" (docs/live-architecture.md:9) becomes literal:
- server -> client: guarded tx reports (datoms) for the principal's worlds, plus patch ops for server-rendered screens.
- client -> server: [intent op payload nonce basis].
- ack: the authoritative tx (with :tempids). Client provisional ids reconcile through the tempid map, and the client rebases its pending queue on the authoritative basis. This removes :agrees? entirely.
- Types come from the datom schema (:db/valueType, cardinality). The payload is bounded EDN-like data with size/depth limits (the wire.bl limits, generalized). No hand-written :wire.
- One transport: live's WebSocket (resume via live-sid already exists). Split's SSE + POST routes are deleted.
- The contract digest covers the schema plus the content hash of every client-placed fn. A mismatch triggers an automatic reload, with pending intents re-proposed.

** Security invariant
The client replica only ever contains facts that the principal's guarded worlds expose (the auth.bl guard / RLS rewrite already produces "absent, not filtered" worlds). A screen whose read-set cannot be bounded to guarded worlds is rendered on the server. Placement never widens what a principal can see; it only moves computation over what they already see.

** The browser runtime is compiled BL
- Compiled from their real sources to JS:
  - priv/boot/core.bl and rt.bl;
  - Loom: hiccup + diff (priv/lib/live/diff.bl);
  - datom's BL query engine (the nested-loop engine);
  - the wire limits and the client loop.
- Hand-written JS shrinks to host leaves: DOM, socket, timers, storage.
- Deleted:
  - runtime.bl's 700-line prelude;
  - the remote-map/core-map ABI tables;
  - split-codec.mjs (a second wire implementation);
  - showcase-page.mjs (a second renderer);
  - most of client.js's applyOp.

* Compiler lessons from the JS research (they apply beyond JS)
1. ANF is structurally neutral but not host-neutral: :global resolves via Env.fetch! with an ns->core fallback, :remote targets Ns.Rt atoms, and defn goes through Link:defvar. Fix with the host-op registry (W1.1) and a written :global resolution rule.
2. ANF local names come from a process-global counter, so compilation was not a pure function of source (PLAN-150 found emitter bytes depended on build order). See W1.2.
3. Loops and named fns are recovered by pattern-matching scaffolds in every consumer. See W1.3.
4. system.analyze lacked:
   - function-value effects (:latent, now landed);
   - closure escape and value provenance (still app-local in compiler.bl). Provenance is also a security tool: it catches a secret flowing into client-placed code.
   See W1.4.
5. Lazy forcing is an effect channel nobody had modelled; main and the branch collided on it. See W0.
6. The :lit int/float tag is real IR information, and :arith needs a declared numeric domain. JS destroyed the tag; any future native tier will too.
7. Differential testing found semantics nobody had written down:
   - Equality is looser than hash-key equality: (= [1 2] '(1 2)) holds, but the two are different map keys.
   - Small-map key order is atom-table dependent. Observed 2026-10-02: (keys {:b 1 :a 2 1 3 "s" 4 1.0 5}) -> (1 1.0 :b :a "s").
   - String count is graphemes on BEAM, while the wire uses codepoints.
   - Sort comparator call order is observable: rt-sort had to port lists:sort/2.
   -> FUP: a core semantics spec + the G-diff harness.
8. Receive, signals, atomic death and the call protocol were re-derived in BL with stated invariants (research/js-actors/README "Receive in BL", runtime.bl:1195-1260). That spec is valuable for proc.* on BEAM too.
9. Vectors are maps on BEAM, so generic `get`-based walkers silently skip vector contents (security fix 61760c8f). Every ANF walker must use ir/child-nodes.
