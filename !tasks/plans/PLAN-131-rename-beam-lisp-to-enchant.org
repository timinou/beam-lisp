* 4. Findings that shape the design

** Fence is `beam-lisp`, not `bl`. ** No ```bl fence exists today.
** Extension resolution is centralized. ** Loader/@doc_extensions is THE registry, and bl code
reads it back (`bl/util.bl.md source-file?` → `(BeamLisp.Loader/doc_extensions)`). But ~26 files
carry bare `".bl"` suffix filters (catalog, semantic, z3corpus, doc/html, code/index) — those are
glob/filter sites, not the resolution rule.
** doc_content/2 dispatches on Path.extname/1 ** — ".org"→org cells, else md cells, plain→raw.
`.ec.md` ends ".md" and `.ec.org` ends ".org", so literate needs ZERO new dispatch; only `.ec`
joins @plain_extensions.
** The generated module prefix `BeamLisp.Ns.` is a SEPARATE knob from the substrate modules. **
It is produced by `Emit.module_for/1` (`Module.concat([BeamLisp.Ns | segments])`) and inlined at
7 more sites — this is what makes the seed swap hard (§5).

* 5. THE BOOTSTRAP CLIFF (the crux of Tier C)

A fresh clone has no source-compiled toolchain. `Bootstrap.install!/1` copies a committed seed
(`priv/bootstrap/seed/`) into ebin: 19 beams `Elixir.BeamLisp.Ns.{Anf,Reader,Compiler,…}.beam`
+ `beam_lisp.app` + `manifest.exs` (sha256 per beam, `compiler_key`, `build_key`, schema
"beam-lisp-bootstrap-seed-v2"). With no seed and no genesis fallback, the tree CANNOT boot.

After a full rename the tree asks for `Elixir.Enchant.Ns.Compiler`, but the committed seed holds
`Elixir.BeamLisp.Ns.Compiler`. The mismatch is fatal: `seed_module_to_ns/1` returns nil for every
old-named beam, so nothing is staged/trusted, and `enable_bl_backend/0` finds no compiler.

Sites that hardcode the generated prefix (must all become one constant):
- lib/beam_lisp/emit.ex:12,18              (module_for — the knob)
- lib/beam_lisp/aot.ex:820,854             (Module.concat for Init/Body)
- lib/beam_lisp/compiler.ex:45             (@compiler_ns)
- lib/beam_lisp/compile_diagnostic.ex:293  (String.starts_with? "Elixir.BeamLisp.Ns.")
- lib/beam_lisp/generation.ex:10           (@loaded_modules)
- lib/beam_lisp/bootstrap.ex:186,251       (seed filename prefix)
- priv/boot/compiler.bl:166                ("Elixir.BeamLisp.Ns.Body.Lower", a raw string in .bl)

TWO escape hatches that avoid a bootstrap deadlock:
(a) **Stage the prefix rename separately (RECOMMENDED).** W1 renames every SUBSTRATE module
    (`BeamLisp.Loader`→`Enchant.Loader`) while `Emit.module_for` still returns `BeamLisp.Ns.*`.
    The seed's module names are unchanged, so the tree still boots. Only W2 then changes the
    generated prefix — a small blast radius (the 7 sites above + the seed).
(b) **Transitional bootstrap window.** One commit where `Bootstrap` accepts BOTH
    `Elixir.BeamLisp.Ns.` and `Elixir.Enchant.Ns.` seed filenames, and `enable_bl_backend/0`
    resolves the loaded compiler by ns (either prefix). Then: old gen-N seed boots the new tree →
    rebuild emits Enchant.Ns.* → `ec seed` writes the new floor → the transitional branch is
    REMOVED in the next commit. This is literally the "compatibility layer" the rename asks for,
    but it is temporary and must not survive.

W2 is go/no-go on spike S1: prove (b) boots and seeds, in a scratch worktree, before landing W1/W2.
