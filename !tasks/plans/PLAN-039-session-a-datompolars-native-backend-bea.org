## THE design decision (user directive resolves it)
"another Rustler NIF compatible with both datom and explorer that makes the stream thing happen
directly from Rust" ⇒ the NIF reads redb, DECODES datom values into typed columns, BUILDS Arrow,
hands to Polars. The datom VALUE CODEC (today only in datom.bl) must be SHARED Rust↔beam-lisp.
- Chosen: a Rust value-codec mirroring datom.bl, locked by a golden-vector conformance suite
  (beam-lisp encodes N values, Rust decodes identically, and reverse). Reject term round-tripping.

## Modules / crates
1. native/datom_arrow (new crate or datom_redb feature): reads EAVT/AVET over the same redb file
   (or a passed DbHandle); projection spec = eid set (from a beam-lisp where-pass) + attrs + value
   types → one Arrow column per attr → Arrow IPC bytes (one crossing) → Explorer.load_ipc_stream.
   Shared codec decodes bytes → Arrow dtype (string/i64/f64/bool/instant/ref); nil = Arrow null.
   DirtyCpu for the build (measure; maybe split scan-IO + encode-CPU).
2. priv/datom/frame.bl (new ns): (q->df db query)→DataFrame ; (pull->df db eids attrs)→df ;
   lazy variants where Explorer LazyFrame allows. PURE fallback (datom/q→list→Explorer.new) behind
   the SAME API when NIF absent, so callers never branch.
3. Conformance: test/bl/datom-frame-test.bl + Rust↔bl codec golden-vector test.

## Contracts
- q->df agrees value-for-value with (datom/q) then hand-built columns — fast path and fallback

- NIF never interprets datom semantics (cardinality/refs) — raw attr values into columns; joins
  and aggregation are Explorer's or a 2nd datalog pass.
- A df is built from a db VALUE (a basis) = consistent snapshot (redb MVCC read-txn at that basis).
