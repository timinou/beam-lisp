* Model reuse: publish evidence for the function that actually runs
** Finding
Actual compiler defn emits literal clause descriptors. Walking them distinguishes
parameter selection, all arities, guards and fixed/variadic dispatch. A source
analysis of a synthetic fn is not enough: direct linking, macro expansion, closure
environments and body module attachment influence actual code identity.
codebase/index-source finds source facts; typed/check-source returns observations.
Neither is itself a runtime publication certificate. Zero observations is unknown,
not proof. Existing system.evidence is still a source-level candidate contract.
** Implementation seam
priv/host/link.bl defvar compiles immutable body modules and a namespace shim,
loads both, then publishes definitions/link/value. Publish normalized emitted
clause identity, dispatch shape, exact body-module identity and dependency edges
with that successful value publication. Failed loads must publish no certificate.
Ordinary global/namespace generation changes are the conservative initial fence;
selective old/new cones can narrow it after correctness is established.
Captured/dynamic functions decline until finite environment identity and execution
binding are proven. A module name alone is not a durable reusable identity.
** Runtime contract
At datom query/read boundaries, capture world identity, immutable view/schema,
attribute read stamps INCLUDING empty reads. Every resource is mapped to the
actual guarded world, not just a source symbol. Include inputs, principal, policy
publication and expiry. Opaque/clock/style operations decline unless separately
versioned. Recheck before and after model evaluation and after retained lookup.
A query-only read collector is insufficient if another read API bypasses it.
Use bounded-cache finite data admission; do not retain compiler environments.
Retain model values below loom.token/sx and live.socket/render. Re-realize the
current stylesheet every render. A cached tree alone has no current sheet entries.
** Validation and benefit
Actual multi-world empty-read test refuses after other-world insertion, swapped
worlds, principal/policy/token change and exact expiry. App style test requires
identical fresh tree/CSS when reusing model data. Production validation must add
macro/helper reload, failed load, actual publication races, capability changes,
concurrent writes and opaque resource calls. Foreseeable gain: skip complete model
construction on unchanged revisits; no percentage promise from these prototypes.

* Exact count and numeric rank: maintain membership, not raw index cardinality
** Finding
Activity requires firm, timestamp, principal, verdict, operation and resource.
Removing a required field removes query membership while an indexed timestamp
may remain. Firm transfer moves membership. Optional inspector changes do not.
App differential prototype feeds touched IDs to an entity-bound full membership
query and replaces the entity's projection entry; this matches the real PAGE and
COUNT queries through all five mutations and retained old views.
** Implementation seam
Compile a narrow admitted query/policy shape into a projection descriptor at
schema/query publication. Initially only a single root with cardinality-one
required attributes, one proven static equality scope and deterministic scalar
order plus entity-ID ties. Residual/dynamic permissions decline rather than
counting unauthorized candidates. Descriptor includes query/schema/code/policy
identity; physical projection partition must represent authorized membership.
Discover eligible projections from ordinary prepared query plans, not app-managed
count keys. Register each finite descriptor once under global memory/storage
budgets; build asynchronously against a pinned basis. Until coverage publication,
execute existing exact query. Avoid eager projections for every user/ad hoc query:
proven stable policy partitions share one projection; dynamic scopes decline.
At datom.conn/run-tx-pipeline and bulk/excision paths, derive affected roots from
actual expanded datoms. Re-evaluate authoritative membership against the overlay
post-state. Atomically update member records, count and rank structure with source
write and coverage frontiers. Old-schema writes invalidate evidence. Multi-root
joins require reverse dependency maintenance and are outside first admission.
Read projection from the reader's certified generation; never substitute current
count for an old DB. Production needs persistent copy-on-write or equivalent
MVCC rank nodes, transactional root publication and reader-safe reclamation.
** Algorithm and benefit
AVL nodes carry subtree cardinality. Count reads root size; rank selection skips
whole subtrees. 10000-row experiment returns50 at offsets0/50/5000/9950 in
61/60/62/59 visited nodes, versus prefix traversal for deep offsets. Update work
is O(log N) per membership change, plus its predicate evaluation and durable node
writes. Bulk build has unavoidable O(N) work; projection storage is O(N).
App map/sort prototype tests semantics only. This is not yet an automatic durable
rank index or general authorization acceleration. If admitted, Activity count and
deep numeric pages cease scanning the accepted history on each cold request.

* Streamed tuple installation: hidden durable generation
** Finding
Unsafe begin/copy/copy/write/publish loses a source delta. Safe publication needs
complete snapshot, ordered replay through exact source basis, matching schema
epoch and an empty pending delta window. Source writes and delta capture must be
one atomic commit. Otherwise no later replay check can recover an uncaptured write.
** Implementation seam
Extend index-coverage and tuple schema installation with versioned hidden index
keyspaces. Copy immutable source basis in bounded batches; commit batch writes
and cursor together. Replaying writes must apply authoritative tuple derivation
including deletions and missing components, not tuple key copying alone.
Durable delta capture belongs in every writer path. Epoch mismatch invalidates
stage. Writer briefly fences publication and publishes generation pointer plus
certificate atomically. Current writer then maintains the published generation.
Old readers pin old generations. Restart resumes committed state. Cleanup must
wait for reader leases/epochs, not infer liveness from absence of a cache entry.
** Validation and tradeoffs
Abstract exploration18720 transitions across4612 states. SQLite experiment kills
an actual subprocess before checkpoint commit and resumes1100 rows with batches
<=17; update/delete/insert replay matches source. Fsync fault tests on Fjall still
required. Journal cap experiment aborts stage rather than refuse source writes;
constant write pressure can starve migration. Production needs disk-spill limits,
backpressure or a controlled final catchup fence with explicit liveness budgets.
Foreseeable benefit: bounded process allocation and recoverable large upgrades,
with disk and extra write cost during migration; no measured page speedup.

* Cancellation: separate obsolete pure model work from committed effects
Veritas unsafe trace navigate/effect/cancel loses committed effect. Safe sampled
model only cancels phase:model; phase:committed drains. No solver runs on clicks.
Proposed live.socket integration: generation-tagged pure model worker, result
acceptance compares current request generation; parent owns writes/audits/styles.
Preemption is only allowed when runtime/compiler evidence closes all effects.
An existing impure view continues normally. Cancellation cannot undo commits.
Worker world snapshots and capabilities must be bound as in model reuse; child
ownership, cancellation cleanup and timeout must not leak cache reservations.
Validate actual render/write/style race before changing live socket scheduling.
Benefit: rapid navigation spends less time on obsolete pure work. No latency
number; sampled protocol does not implement real worker interruption.

* Native execution: three independent obligations
Source candidate purity/termination/singleton result sort is necessary, not enough.
Actual candidate kernel uses erlang/div. Generic quot is not the same proof shape.
SMT example shows unbounded input admits an out-of-range witness; explicitly
restricted input interval and bounded work reject stated violations. 32-bit bounds
are an illustrative target contract, not BEAM's universal numeric representation.
Integrate native.eligible/system.evidence with emitted typed argument domains and
representation transfer rules; prove intermediate/result bounds per target, not
just input scalar tags. Bound recursive work using actual IR measures and maxima.
Runtime admission guards enforce inferred input domains and work thresholds;
out-of-domain falls back to BEAM. Unknown arithmetic/callbacks decline.
Validate boundary/bignum/overflow/parity, helper reload and timeout fallback.
Benefit depends on eligible hot kernels; no automatic offload or speedup measured.

* Cold startup and branch consolidation
Inspected realm and realm-ns without switching any checkout. realm-ns contains
realm module naming; its caveats state manager wiring is unfinished. Environment
bindings and registered process names still require isolation. PLAN-164 covers
this: consolidate that implementation, do not create another parallel daemon.
A warm VM default requires atomic singleton startup per user/build, realm-local
project code/environment/registries, aggregate resource controls and safe drain.
Build identity must reject incompatible attaches. One user's project must not
replace another project's module. Shared fault blast radius remains a tradeoff.
One serial capped cold entry +20 evals inside that VM will measure launcher/module
entry separately from warm expression evaluation. Single host sample is not an
address-to-visible production benchmark or a valid latency distribution.

* Recommended production order
1. Emitted publication identity plus complete guarded read capture; query/read
   differential correctness before enabling finite model reuse.
2. Narrow policy-preserving maintained count/rank; reuse certified generations
   and validate on actual Activity data, updates and old snapshots.
3. Streamed durable generations and migration delta capture; reuse this for
   projection builds, with real backend faults and reader lifetime tests.
4. Pure model worker cancellation after the purity boundary is established.
5. Consolidate realm-ns/PLAN-164 isolation and measure cold navigation phases.
6. Add target-specific native argument/work gates where profiles show benefit.
Deodorant may flag expensive eligible patterns for explanation; it cannot safely
rewrite arbitrary counts or invent permission/purity evidence. No mechanical
rewrite is needed for the first automatic framework integrations.
