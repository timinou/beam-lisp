* Goal

Two changes that reinforce each other, expressed in the vocabulary the repo already
uses (docs/the-five-bundles.md tiers, docs/patterns/*, docs/guidebook/*):

1. **A solver pool with conversations** — N z3 processes, leased per
   CONVERSATION (not per call), so the API can finally use z3's real power:
   `push`/`pop`, assumptions, unsat cores, incremental re-verification.
2. **Native decision tiers in front of z3** — decide in BEAM what BEAM can
   decide, keep z3 as the oracle of last resort, and RECORD which tier answered.

The instrument decides how much of (2) is worth building: obligations and their
tiers become FACTS, so "what fraction is native-decidable" is a datalog query
over the codebase's own fact space, not a script someone has to trust.

* Non-goals

- **No NIF / no libz3 in-VM.** A NIF blocks a scheduler thread and turns a solver
  segfault into a VM-wide outage; a z3 crash today is one process that the
  supervisor heals. Measured cost of the port protocol is not the problem: a
  `code/verify` is ~29 ms end to end over HTTP (1000 sequential calls, 29.4 s),
  and the port protocol itself is p50 ~2 ms by the p13a research note. Revisit
  only if profiling shows the text protocol dominating, or 10k+ queries/s are
  needed.
- **No new restart machinery.** OTP does Healing Edge and Governor (bundles §5).
- **No new pattern vocabulary.** Use `fence`, `pool`, `reg/*`, `super/*`,
  `system/verify` — all designed and built (PLAN-085, DONE).

* Why (1) and (2) are complementary, not competing

- (2) shrinks the DEMAND on the solver; (1) makes the remaining foreign calls
  safe, concurrent and incremental.
- (1) makes (2)'s value measurable: pool contention (queued leases, fenced
  timeouts) is evidence that a native tier should absorb that obligation.
- Both are gated by ONE instrument: the obligation, its tier, and the discharged
  proof travel as data (pattern 13, and exactly what `system/prove.bl` already
  does for native compilation: "the proof TRAVELS with the node", consumed by
  `native-eligible?`).

* Step 2 — the pool as a bundle, green

```clojure
(defsupervisor z3-pool
  (strategy  :one-for-one)
  (intensity 3 5000)
  (child :solvers (pool solver-srv 4)))       ; N solvers, one-for-one, healed

(defserver z3-leases
  (invariant (<= (count (keys leases)) 4))    ; verified by system/verify itself
  (invariant (every lease-returns? leases)))
```

- checkout = `call [:reg z3-leases] [:checkout]` (fence-bounded wait, so a
  saturated pool answers `{:timeout}` instead of hanging a caller);
- return is GUARANTEED by `monitor` on the borrower (a crashed caller's lease
  comes back — the Fence bundle's `demonitor :flush` discipline, applied to a
  lease);
- a fenced-out solver is terminated and healed by the supervisor, so a poisoned
  z3 process is never reused;
- `super/children z3-pool` is the observability surface; `system/verify
  'z3-pool` is the boot gate — and it is the SAME verifier the pool serves:
  recursive dogfooding, and the cheapest test of both.

Acceptance: `mix bl test test/bl/system/z3_pool_test.bl` (concurrent leases never
exceed N; a killed borrower returns its lease; a hung solver is replaced and the
next verify answers); `system/verify 'z3-pool` green; 8-thread soak → 0 failures,
and `(count (super/children z3-pool))` still 4 after a forced kill.

* Risks / gotchas known today

- `./bl` and `mix bl *` builds are blocked WHILE another session edits
  `priv/lib/mcp/*.bl` and `lib/beam_lisp/daemon/{ports,gateway}.ex`; the tree must be
  quiet for any acceptance here to run (observed: "unterminated collection"; a
  CompileError in gateway.ex).
- `map` is lazy in beam-lisp (side effects inside a mapped fn do not fire until
  the seq is realised) — a lease loop must force it, or leases leak silently.
- Spawned processes cannot see THIS-ns `def` vars: pass data through closure
  locals.
- `pool`'s designed front is Fan-Out over `cast` (fire-and-forget). A LEASE is
  not that: checkout must be `call` + monitor + fence. Do not overload `cast`.
- The 10 s port timeout currently raises `RuntimeError "z3 timeout (acc: \"\")"`;
  after step 1 it must be a value (`{:timeout}`), and `call-tool`'s catch-all
  (FUP-047) must stop translating it into "-32602 Invalid params".
