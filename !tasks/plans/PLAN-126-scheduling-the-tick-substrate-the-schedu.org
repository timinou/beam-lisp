* Goal

Give beam-lisp the one thing OTP does not ship and both products hand-roll: a
way to say "wake me later / on a boundary / after quiet" that is durable,
inspectable, and provable. Two bundles and a clause over primitives that already

Decisions settled with the user (2026-09-18):

1. FACT-FIRST. A declaration that a human can see or change is a fact in the
   store (`defscheduler`); a private per-process beat is a clause (`tick`).
   Both lower to the SAME trace — a Timeout Edge — so `system.model` sees one
   shape and `verify-liveness` already covers it.
2. SCOPE. Substrate + pane + cut the daemon's own housekeeping over. The pane
   is non-empty on day one because the daemon already hand-rolls four
   schedulers.
3. CLOCK IS A VALUE. Injected everywhere (a fn -> seconds); the daemon passes
   wall time; tests and the pane can time-travel. Reading the clock is `io`

4. DECLARATION HOMES. `env.bl :schedules` for the tree's; `defscheduler` for a
   namespace's; the pane unions them. (`:tasks` and `:ports` are the precedent.)
5. PANE SCOPE. A session-wide registry, like `ports/list-claims` — any app

THE OWNERSHIP PROBLEM, MADE STRUCTURAL. The old design was *careful*: a keeper created the table, but `ensure-store!` ALSO had a `(make-table)` fallback for the "keeper alive, table missing" case. That fallback WAS the bug — an ETS table dies with its owner, so the branch that reads like a safety net is the branch that hands the store to a transient process. Replaced by three ENFORCED rules:

  1. ONE CREATOR. `ets.new` appears in `store-keeper`'s init and nowhere else.
     `ensure-store!` starts a process; it never creates a table.
  2. AN HEIR. The table is created with `store-heir` named as its heir, so the
     keeper's death TRANSFERS it. The heir holds it and gives it back to the
     next keeper. Its whole life is two clauses, which is why it can be trusted
     to outlive one.
  3. CHECKED. Every entry point asserts the owner is the keeper or the heir;
     `proc/store-owner` and `proc/store-live?` are public because an invariant
     nobody can read is a comment.

Not "nobody may kill the keeper" but "killing it no longer costs anything".
Asserted: `a-transient-process-never-owns-the-store` (the scheduler that asks
first is NOT the owner) and `the-store-outlives-its-OWNER` (kill the keeper →
the store survives → the heir holds it → the next keeper reclaims it → a
one-shot that ran still does not re-run).

BUG CAUGHT WHILE WRITING IT: `ensure-store!` keyed the keeper's start off
`(missing? tid)`, so the state "the store exists, held by the heir, nobody able
to write to it" was PERMANENT. An heir holding the table is exactly the case
where the store is alive and unwritable. Both roles are now checked.
