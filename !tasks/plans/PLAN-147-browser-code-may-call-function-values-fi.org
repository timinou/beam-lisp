* Goal
Lift the split showcase's biggest limit: client (browser) code could not call a computed function value (`(f x)`, `((get table k) xs)`, a custom comparator). Admit it without weakening fail-closed placement (PLAN-146).

* Findings (probed 2026-09-23, /tmp/showcase-probe/probe9-15)
- The analyzer's `:footprint` DEFERS `fn` literals and treats named fns used as values as pure: `(mapv (fn [x] (println x)) xs)` → footprint {}. Effects of function VALUES were invisible (masked in the split gate only because ABI + edges also saw the println).
- `:terminates` only proves loops. Direct recursion was refused by ACCIDENT (opaque footprint on the first fixpoint round); recursion through a named value passed to a runtime HOF (`(defn walk [t] (mapv walk (:kids t)))`) already passed the gate. Anonymous self-application (`((fn [f] (f f)) (fn [f] (f f)))`) reports footprint {} / terminates true.
- BL `sort`/`sort-by` = `Enum.sort/2` = `:lists.sort/2` (identical comparator call sequences on 8 inputs, incl. strict `<` and duplicates). A strict comparator reverses equal keys — any other stable sort diverges.
- Client inputs are closed data: `enqueueData` admits no function; the codec decodes data only. Closed world holds in the browser.

* Design
1. Analyzer `:latent` (system.analyze): the footprint of every function value a function creates (fn literal), names (named fn / global as value) or gets back from a callee. Unknown global value → opaque; unshadowed first-order core value → its footprint; host fn ref (`RT/remote_fun`) → opaque. Fixpoint, fails closed. `compare` joins the first-order pure table.
2. Split gate — the VALUE DISCIPLINE replaces the blanket `:dynamic-call` refusal:
   - `:recursive` — a function on a cycle of the app's reference graph (calls AND value references, self included) is not portable. Explicit, no longer an accident.
   - `:higher-order-value` — a function VALUE (a lambda, or a named fn referenced as a value) may not call a function it receives: no computed call and no var passed to a runtime HOF's function argument, transitively through named calls. Named functions called directly may make computed calls (first-order values, rank-1).
   - effects oracle requires footprint {} AND latent {} AND terminates.
   - Soundness: closed world + acyclic reference graph + loops proven + values that make no computed call ⇒ every client computation terminates and performs no effect.
3. Runtime: `rt-compare` (BL compare ranks; strings by code point via new host leaf `str-cmp`; maps/sets raise), `rt-sort`/`rt-sort-by` as a faithful port of `:lists.sort/2` with `comparator_le`; `<`, `>`, `compare` as values. `hof-fn-args` table (prelude HOF → called arg positions) with a build-time derivation check.
4. Showcase: a local "Sort" control — `(orderings)` maps keys to function values (keyword keyfn, named comparator, lambda comparator), `arrange` makes the computed call. Worker accepts only events the last view offered (removes the hard-coded event list). encodeView handles lists.
5. Proof: sort/compare BEAM↔JS differential bundle (expected computed on BEAM at build time); split refusal fixtures for recursion, higher-order value, host fn value; analyzer tests; verify-split + browser.

* Non-goals
comp/partial/juxt/apply_variadic in the client; recursion in client code; ordering of maps/sets; mixed-type `<`.
