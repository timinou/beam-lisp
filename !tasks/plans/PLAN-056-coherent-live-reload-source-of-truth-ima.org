* Thesis (one sentence)

The running BeamLisp image is the single source of truth; a `.bl` file on disk
is a live handle to it, and every edit is a *transaction over the image* that
either commits atomically (identity or coherent) or is held pending — old code
serving, errors printed, listening — until the whole bundle of changes makes
sense. In-flight messages whose contract a bundle changes are migrated (quiesce
or reroute) by the SAME migration engine `datom` already ships.

* The load-bearing realization

A message queued in a mailbox is an UNFULFILLED PROMISE — the sender promised
the receiver a value of a shape it handles. Changing a module's message
contract breaks that promise for every queued message. So a contract-changing
bundle is INCOHERENT by the exact predicate the reload loop already enforces
(no unfulfilled promises), and a message-migration is what RESTORES coherence:
- quiesce = move TIME: wait until the promises resolve (mailboxes drain)
- reroute = move DATA: transform each promise to the new contract mid-flight

Message-migration IS datom-migration on the process plane, term for term:
  :migration/grows(schema delta)   ↔  :migration/modules(code contract changed)
  :migration/checks(data invariant)↔  {:check :message-compat :to handler}
  :migration/fn (db→tx-data)       ↔  :migration/fn (old-msg→new-msg)
  plan (walk db, commit nothing)   ↔  walk mailboxes, swap nothing
  plan-with(spec remediate, resid.)↔  spec migrate each in-flight msg, check accept
  apply! gate(:blocked on residual)↔  un-migratable msg ⇒ :blocked, old code serves
  apply-batched!(yield writer)     ↔  draining (yield to traffic awaiting calm)
  ledger is a QUERY not side table ↔  quiescence is a QUERY over live mailboxes

* States

Coherent(L) --save Δ--> Staging(L,Δ) [validate in fork]
  base-incoherent (dangling/type/promise) → print errors, hold, keep listening
  contract-change with live msgs, no migration → :blocked, hold
  identity(L→L') → swap silently
  coherent & not-identity → atomic commit L'
  strategy :quiesce → Draining(L,Δ,M): stop admitting new M-msgs; watch mailboxes;
     calm = (every? empty? (mailboxes-of M)) — queryable; termination provable via
     system.core/find-lasso; on calm → atomic swap
  strategy :reroute → Migrating: plan-with first (spec migrate all queued; any
     reject ⇒ :blocked); else swap now + interceptor rewrites old-shape on delivery;
     flush → remove interceptor
Old code serves throughout any hold — body modules BeamLisp.Ns.Fn.* are never
reloaded → never purged (emit.ex:58); in-flight callers finish on their captured
body. The incoherent window is unbounded and harmless.

** Wave 3 REVISION — verification is MANDATORY for :reroute, and dispatch-aware

Owner directive: ALL :reroute migrations MUST be verified BY DEFAULT. No
:migration/verify flag — verification is the DEFINITION of :reroute. commit
cannot produce an :applied state for a :reroute bundle without a discharged
proof; the only outcomes are :applied-verified or :blocked. "applied-unverified"
is unrepresentable (same discipline as the stale-beam: the dangerous thing is
not a valid image).

Default observability relation R (so verification is always-on with zero user
input): R_default ≜ the migration is OBSERVABLE-PRESERVING — ∀ branch b, ∀ msg m
matching b: observe(new_handler(migrate(m))) ≡ observe(old_handler(m)). That is
system.core/simulates? (priv/system/core.bl:209) with rel = equality-on-
observable, discharged PER BRANCH. User may override :migration/R for a
deliberate semantic change; default proves "you didn't change what anyone can
see." simulates? sig: [port rel decls a-var c-var a-next c-next extra].

SEAMLESS pattern-matching + multiple dispatch — the keystone. The verifier
enumerates BRANCHES, never surface syntax, by REUSING system.model/transitions
(priv/system/model.bl), which already lowers ALL FIVE dispatch forms to ONE
uniform clause {:label :pattern :guard :next :body}:
  extract-receive · extract-loop-receive · extract-defn (multi-clause defn,
  patterns+guards) · extract-defmethods (defmulti/defmethod) · extract-defserver
  (OTP handle-call/cast/info). transitions is the head-dispatched entry.
One obligation per branch; verified iff EVERY old-contract branch still
simulates under R after migrate. Three consequences that make dispatch seamless:
  1. GUARDS are premises: clause :guard (the :when form) rides into simulates?
     as `extra` SMT — verified only under the guard that reaches the branch.
  2. DROPPED BRANCH = proof failure: migrated msg matching no new branch ⇒
     :no-target (would raise no-method at delivery) — the multiple-dispatch
     analogue of a dangling ref; caught at commit.
  3. OPEN DISPATCH: defmulti fuses static extraction with the LIVE registry
     Multi.add_method / {:multi, ns, name} (lib/beam_lisp/multi.ex:107) so
     runtime-added methods (and isa?/derive hierarchy keys) are enumerated too.
Soundness-by-construction: reuse the SAME extractor system.core trusts for
deadlock/liveness/refinement — no second, weaker branch-enumerator that could
disagree. One extractor, one truth.

New module: lib/beam_lisp/reload/verify.ex — verify_reroute(migration,old_ns,
new_ns): transitions(old) × transitions(new) → per-branch discharge via
SystemCore.simulates?; returns {:verified, results} | {:blocked, breaks} with
named branch + countermodel. Non-termination bounded (verifier must not hang).

Reports:
  :applied  → {:verified true :branches [{:branch :inc :simulates true} …]}
  :blocked  → {:verified false :serving :last-coherent
               :failures [{:branch :reset :reason :diverges|:no-target|
                           :non-terminating :msg … :countermodel …}]}

** Wave 3 CORRECTION — R is DEDUCED from code shape, not a fixed relation

Supersedes the "default observability relation R = observable-equality" text
above. Owner directive: R is implied from the SHAPE of the code via the merged
invariant-inference tier (priv/system/core.bl, the P18/P19 Houdini work). A fixed
observable-equality R is too crude and misses semantic breaks (capacity, sum-type
arm coupling) that leave message shape unchanged.

The merged machinery this rides (all sound-by-construction, zero annotation):
- discover-invariant (core.bl:827) — Houdini fixpoint (Flanagan–Leino):
  miniKanren enumerates candidate predicates over the state vocabulary
  (candidate-invariants), z3 drops any a transition breaks (inductive-under?),
  iterate to fixpoint → the STRONGEST inductive invariant expressible in that
  vocabulary. HONEST: returns :discovered nil when the shape admits none (never
  a false one — example 14 `leaky`, example 22 unbounded queue).
- synthesize-capacity (core.bl:1019) — verifier run backwards: tightest inductive
  bound k (example 22 reads capacity 5 from (< (count items) 5), no annotation).
- migration-preserves? (core.bl:224) — inv(v1) ∧ v2=migrate ∧ ¬inv(v2) unsat ⟹
  migration safe. This is code_change verification (example 08).
- simulates? (core.bl:209) — per-branch refinement discharge, guard as `extra`.
- state-shape / system-model — read state vars + SORTS structurally from code
  across Int(14), payload sum-types(19), records(11), collections-by-length(12),
  strings(17), reals(16), protocol(13). A MESSAGE PAYLOAD is a sum-type over
  dispatch arms — already in the deducer's vocabulary (example 19: :paused
  nullary arm vs {:on lvl} payload arm → z3 datatype).

R-deduction chain for an implied :reroute verification:
  1. discover-invariant(old_handler) → I_old ; discover-invariant(new_handler)
     → I_new  (Houdini fixpoint, per dispatch branch via model/transitions).
  2. The proof obligation = migrate preserves the DISCOVERED I_new:
       migration-preserves?(port, I_new, decls, v1, v2, migrate-smt)
     R is thus the coupling under which I_old(s) ⟹ I_new(migrate(s)) — deduced,
     not hand-written.
  3. per branch b: simulates?(port, R, decls, …, old.next(b),
     new.next(migrate(b)), guard_smt(b)) — guard as premise.
  All branches unsat ⟹ verified ; any sat ⟹ :blocked + branch + countermodel.

Three HONEST outcomes (discovery returns nil when vocabulary is empty):
  I_new non-nil, migrate preserves ∀ branch      → :applied-verified
  I_new non-nil, some branch breaks it           → :blocked + branch + countermodel
  I_new = nil (no invariant of that shape)        → :applied under OBSERVABLE-EQ
     FALLBACK, flagged :r-source :observable-eq (degrade only here, and say so).
The fixed observable-equality relation is NOT the default — it is the honest
fallback for exactly the shapes whose invariant vocabulary is empty. For any
shape with real structure (counter, bounded queue, sum-type payload, record) R
is the DEDUCED invariant — strictly stronger, catches breaks observable-eq
misses (e.g. a migration exceeding a SYNTHESIZED capacity though message shape
is unchanged).

verify.ex composition (all existing merged fns):
  1. model/transitions(old), model/transitions(new)   — 5 dispatch forms → clauses
  2. discover-invariant per handler version             — R deduced (Houdini)
  3. per branch: migration-preserves? + simulates? with DISCOVERED invariant,
     guard as premise
  4. nil-invariant shapes → observable-eq fallback, flagged
  5. synthesize-capacity when a collection/bound is in play — catches capacity breaks

report gains :r-source ∈ {:discovered <smt> | :synthesized <k> | :observable-eq}
so a reader sees WHICH invariant R was deduced from (or that it fell back).
