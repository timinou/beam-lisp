* Initial Message

List the broadcasting/communications primitives of Erlang, then Elixir, then Phoenix, and show me how they look like with beam lisp (read the priv/ and the examples/ to see how Beam Lisp wants us to write them).

Then tell me how it would make sense for datom to interface with all these primitives. We want a clean architecture that can scale horizontally and vertically, and is at least as good at the guarantees that the BEAM gives us as BEAM itself.

* Goal

Give datom the one primitive it lacks: the ability to say *"it changed."* Add a
transaction-report broadcast at the connection writer, so any process can
subscribe to a store's commit stream. This is L2 in
=docs/datom-as-a-broadcast-substrate.md=. L3 (filtered/guarded/semantic watch)
is PLAN-044 and blocks on this.

Design doc (authoritative): =docs/datom-as-a-broadcast-substrate.md=.

* Why

datom already keeps a durable, totally-ordered fact log and lets any process
hold a consistent value for free. The only missing capability is notification.
Datomic answers this with a pull-based =tx-report-queue=; the BEAM-native
reframe is *push*: a commit is a message, the tx-log is the topic, and every
BEAM broadcast primitive (=:pg=, =Phoenix.PubSub=) is a transport for it.

* Payload: delta by default, never a projection (FEAT-016, corrected)

See =docs/datom-as-a-broadcast-substrate.md= §6. FEAT-016's real, load-bearing
rule is *the writer must never emit a PROJECTION* (a projection is a function of
(data, who is asking); a writer knows only its half). FEAT-016 ALSO chose a
basis-only payload — but that was right for a LiveView PAGE (whose only
subscriber-agnostic delta is a re-rendered board = a projection), and it is the
WRONG default for a datom subscriber, for which =:tx-datoms= IS the
subscriber-agnostic delta the store already produced. Basis-only there would
manufacture an extraneous re-query.

Three payloads; this item ships DELTA by default:

| payload | who emits | reader re-queries? | this item |
|---------|-----------|--------------------|-----------|
| moment (=basis=) | writer | YES (as-of + re-run) | KNOB (=:payload :basis=) |
| delta (=:tx-datoms= + basis) | writer | NO (filter locally) | DEFAULT |
| projection (rows for query×principal) | NEVER the writer | n/a | via a projector subscriber (§8.1, PLAN-045) |

This item MUST honour:
- *Writer never projects.* No per-principal answer, no rendered view, ever, on
  any path. (The kernel of FEAT-016 — preserved.)
- *Default payload = DELTA.* Same-node (:pg) ALWAYS carries the delta. Cross-node
  (Phoenix.PubSub) carries the delta too, UNLESS a subscriber chose
  ={:payload :basis}=. The delta is query-free for the reader — that is the whole
  point of not defaulting to basis-only.
- *Basis-only is a KNOB.* ={:payload :basis}= exists for large writes and
  replica/complex-view subscribers that re-derive anyway: they get
  =[:datom/changed basis changed-attrs]= and reconstruct =basis → (as-of db
  basis) → run interest=.
- Per-principal filtering (the reader-side =auth/guard= case) is L3 (PLAN-045),
  not here; but its payload need is the delta, which this item delivers.

* Where the code goes

- =priv/datom/conn.bl= — =publish-report!=, called from =transact-in-writer=
  AFTER the basis high-water mark advances (=swap! (:basis conn) max=). Inside
  the writer's serialized step, so report order = commit order (invariant 1).
- =priv/datom/conn.bl= — the pg group topic per store: =report-topic= keyed by
  =store-key= (same identity the registry already uses).
- =priv/datom.bl= — facade: =listen!=, =listen!/{:attrs}=, =unlisten!=,
  optionally =tx-report-queue= (a blocking Datomic-compatible pull wrapper over
  the same stream, for parity).
- =priv/datom/conn.bl= — =pubsub-server= resolver: reads an app-configured
  PubSub name (mirror =spell/server.ex='s =Application.get_env= pattern); nil ⇒
  local-only, never an error (invariant: a store with no web stack still works).
- =publish-report!= builds ONE delta term =[:datom/tx basis tx-datoms]= and
  =send=s it to every =pg/get_members= (local, always). Cross-node: the same
  delta on the store topic; a =[:datom/changed basis changed-attrs]= on a
  SEPARATE basis-topic for =:payload :basis= subscribers. Snapshot the member
  list, then send OUTSIDE the Agent's critical section so fan-out never holds the
  writer (invariant 4).

* Public surface (proposed)

#+begin_src clojure
(datom/listen!   conn)                            ; delta stream: [:datom/tx basis tx-datoms]
(datom/listen!   conn {:attrs #{:order/status}})  ; T0: only commits touching these attrs
(datom/listen!   conn {:payload :basis})          ; KNOB: basis-only, reader re-derives
(datom/unlisten! conn)
#+end_src

Consumer is a plain =receive= or a =defserver handle-info=, in the
=spell/server.ex= =spell/changed= family. DEFAULT path reads the delta with NO
store access:

#+begin_src clojure
(datom/listen! conn {:attrs #{:order/status}})
(receive
  ;; delta in hand — no re-query, no as-of
  [:datom/tx _basis tx-datoms]
    (doseq [d tx-datoms]
      (when (= :order/status (datom/datom-a d))
        (handle-status (datom/datom-e d) (datom/datom-v d))))
  (after 5000 :idle))
#+end_src

* The five invariants (acceptance = each is a test)

1. *Report order = commit order.* =publish-report!= runs inside the writer,
   after the basis advances. TEST: N concurrent =transact!=; every subscriber
   observes bases strictly monotonic and in the same order.
2. *No broadcast on failed/speculative tx.* =with= and =run-tx-pipeline= NEVER
   publish; only the real =transact!= path does, after commit. TEST: =(with …)=
   and a schema-rejected =transact!= produce zero notifications.
3. *No undetectable gap.* Every notification carries the new basis; a subscriber
   detects a jump vs last-seen =t= and can replay =(datom/since db last-t)=.
   TEST: drop a message (don't deliver), assert the subscriber reconstructs the
   missed datoms from the log.
4. *Backpressure is the subscriber's, never the writer's.* Fan-out is =send=
   (never blocks). TEST: a subscriber that never drains its mailbox does not slow
   or block a concurrent writer (measure writer throughput with 1 healthy + 1
   stalled subscriber).
5. *T0 filter is monotonic/sound.* =:attrs= membership: a subscriber is notified
   iff some tx-datom's attribute ∈ its set. TEST: a commit touching only
   =:order/total= does not wake an =:attrs #{:order/status}= subscriber; one
   touching =:order/status= does.

* Cross-node behaviour (Phoenix.PubSub path)

- Opt-in via configured PubSub server; =SpellWeb.PubSub= already runs in the
  supervision tree (=lib/beam_lisp/application.ex=).
- TEST (single-node stand-in, DEFAULT delta): subscribe via
  =Phoenix.PubSub/subscribe= to the store topic, transact, assert a
  =[:datom/tx basis tx-datoms]= arrives — the delta, query-free.
- TEST (basis KNOB): a =:payload :basis= subscriber on the basis-topic gets
  =[:datom/changed basis changed-attrs]= and NO =:tx-datoms= / =:db-after=.
- TEST (writer-never-projects): NO path — delta or basis — ever carries a
  per-principal or rendered value. FEAT-016's kernel is a test, not a comment.

* Risks / decisions to pin in review

- =:pg= requires =pg/start_link= under a supervisor. WHERE does it start? Either
  datom starts its own scope lazily (like the conn registry's named Agent in
  =conn.bl=) or the host app owns it. Prefer: a datom-owned named pg scope,
  started once, race-safe like =registry= — so a plain =mix run= script (no web
  stack) still gets local subscriptions. DECIDE in review.
- Writer hot-path cost: fan-out is off the critical section? Confirm
  =publish-report!= runs after the =swap!= but the =send=s do not hold the Agent.
  If they do, move the member snapshot inside and the sends outside.
- =changed-attrs= computation: a set over =:tx-datoms='s =a= positions — cheap,
  but confirm it excludes the =:db/txInstant= self-datom noise or documents why
  not.

- =06-projector.bl= broadcasts a PROJECTION (a rendered board) on a PubSub

* Resolution (implemented, commit fdd70db on branch datom-broadcast)

Built. Full datom suite 418 tests / 938 assertions / 0 failures (additive).
broadcast_test.bl: 11 tests / 31 assertions green. All examples 01–06,10–13 run.

Decisions taken on the review questions:

- *pg vs atom map.* Chose a lazily-pruned atom map ={pid -> opts}= per store,
  NOT :pg, for LOCAL subscribers. Reason: a subscriber carries options
  (=:attrs=, =:payload=) that :pg's membership cannot hold, so :pg would force a
  SECOND structure (a side table) for one fact. One structure beats two that
  must agree. The liveness check at publish IS the prune (invariant 4). Cross-
  node reach is Phoenix.PubSub, which keeps its own subscriptions, so :pg's
  cluster membership was never needed here. (:pg is still used in 13-presence.bl
  as the native MEMBERSHIP primitive — a different use than the feed.)
  ⇒ No datom-owned pg scope was started; simpler than the plan sketched.

- *Writer hot-path cost.* =publish!= runs after =swap! basis=, inside the
  writer, as the plan required. The fan-out is =erlang/send= (non-blocking µs),
  so doing the sends in the writer costs the next commit only O(subscribers)
  message copies, never a block — confirmed by the stalled-subscriber test
  (50 concurrent writes complete < 5s with a subscriber that never drains).

- *changed-attrs.* A set over =:tx-datoms='s =a= positions, EXCLUDING
  =:db/txInstant= (every tx writes one; including it would wake every attr
  filter). Verified in the-basis-knob-suppresses-the-delta test.

- *Cross-node topics.* delta on ="datom/tx"=, basis on ="datom/tx/basis"=, so a
  =:payload :basis= remote subscriber picks the smaller channel. Opt-in via
  =Application.get_env(:beam_lisp, :datom_pubsub)=; nil ⇒ local-only, never an
  error. Verified end-to-end with a standalone Phoenix.PubSub.

- *06-projector PubSub.* Self-contained: the example starts its own
  Phoenix.PubSub via =Supervisor/start_link= with the module atom
  =(erlang/binary_to_atom \"Elixir.Phoenix.PubSub\")=. Swapping for the app's
  PubSub (or Redis) is config, not code — narrated in the file.

- *13-presence.* =Phoenix.Presence= needs a compile-time =use= module, not clean
  from a runtime .bl, so the example uses =:pg= (the native membership
  primitive) and narrates Phoenix.Presence as the cluster CRDT upgrade of the
  same shape. Honest and self-contained.
