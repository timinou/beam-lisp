* Initial Message

Create a new app, unencumbered by the experiments in this repo: Spell, the
alive environment. On start it loads namespaces (MVP: core + stdlib + current
folder). It has (0) a chat chip for handoffs, (1) .bl.md/.bl.org claiming on
save → sessions launched from the file, (2) a conceptual model where sessions
are written as the concurrency patterns they are (transition relations,
proven by the system engine). Inspired by djinn-bl; scenarios specced with
blueprint's scenario module; cassettes + env-fork semantics adopted.

* Verdict

Design complete. The thesis: Spell is not an IDE over beam-lisp — it is
beam-lisp's own boot mode made visible. Nine organs already exist and are
example-proven; Spell generalizes catalog.bl's "evaluate + read a folder"
into one boot, unifies continuity into ONE handoff value (cassette + image
basis + env + cursor + branch), writes sessions as defprocess values, and
specifies everything through blueprint scenarios over a new in-process
:spell world. Ten realisations, five linchpins, six waves below.

* The ten realisations (see design for evidence paths)

1. Boot = generalization of tooling/catalog.bl's evaluate+read, through
   reload's coherent path.
2. File-claim = reload's bundle gate applied to prose; coherent → claim,
   incoherent → hold (old image serves, reasons printed).
3. Sessions are defprocess processes: transcript = log, undo = basis
   pointer, invariants proven by system.core.
4. Handoff = one content-addressed value: cassette-id + cursor + journal +
   env snapshot + branch parent. Cassette shape from spell_agent FEAT-006
   (digest-matched, raw SSE, replay/record_missing/record); env from
   relay.env (^:per-env overrides + tombstones).
5. Scenarios (blueprint) are the spec/test/demo trinity; new :spell world =
   the real boot, in-process; verdicts proven/witnessed/refuted/unknown;
   certificates are the demos of the spec.
6. Catalog is the navigation; ^:catalog for every view/tool/demo; coverage
   number is the honesty metric.
7. Vitals is the session view — sessions as process tiles, handoffs as
   message edges; no bespoke monitor.
8. Chips are edges: djinn's available(marking, role) unifies guard and
   affordance, so the UI cannot offer a move whose guard fails (provable).
9. App shape = djinn-bl (one Mix host, beam-lisp path dep, .local/blrun,
   ward suites); NOT the undefine/spell umbrella (Phoenix/Spacetime emitter
   is the encumbrance). Durability via datom.store-fjall.
10. MVP cut: boot/load/arm/index/serve/sessions/agent/scenarios; NOT
    multi-tenancy, MCP, branding, W6 reactive re-run.

* Waves

** W0 repo skeleton — fresh repo, djinn-bl-shaped mix host, beam-lisp path
   dep, .local/ scripts (blrun/bltest/ward), CI runs ward suites. Smoke:
   `blrun src/spell/main.bl` prints the loaded-ns manifest.
** W1 boot + load — spell/boot {:roots …} loads core+stdlib+folder through
   reload's coherent path; finds .bl/.bl.md/.bl.org; prints a manifest
   (namespaces, defns, coherence report). Accept: a folder with a
   half-broken .bl.md boots with the broken file HELD and the rest live.
** W2 serve + index — codebase facts, ^:catalog entries, coverage query;
   web/serve + live.socket serving catalog, explorer, vitals. Accept:
   catalog of the app itself renders with live demos; coverage query answers
   "which defns does no demo show".
** W3 file-claim loop — watcher predicate accepts .bl.md/.bl.org
   (reload_watcher.ex:111, PLAN-069 W3); save → staged bundle → claim or
   hold; owned-span results written back; @spell mentions parse to
   session-launch facts. Accept: scenario `save-claims-file` proven in the
   :spell world (hold→fix→claim round trip).
** W4 sessions + chat chip — sessions as defprocess (state/on/invariant);
   transcript = session datom conn; chips = available moves from the
   transition graph; session invariants checked by system.core. Accept: two
   browser tabs converge through the log; a session tile appears in vitals
   with a heartbeat.
** W5 handoff value — cassette record/replay at the fn-backend seam;
   relay.env fork overrides; handoff map (v1 schema + content hash); resume
   = load → journal → env → cursor; branch from any handoff. Accept:
   scenario `handoff-roundtrip` proven offline (no network; replay digest
   match; resume reproduces session state; branch diverges cleanly).
** W6 scenario certificates + hardening — blueprint scenarios for every
   feature live in scenarios/; `spell scenario run` emits deterministic HTML
   certificates; coverage + coherence badges on the catalog page. Accept:
   full scenario suite green offline in CI; certificates byte-stable.

* The scenario set (blueprint DSL, :spell world unless noted)

- boot-loads-namespaces — act boot; expect catalog facts for every root;
  pattern: stays.
- save-claims-file — author saves .bl.md → spell claims (ns live, spans
  owned); author breaks a cell → held + old image serves (isolated); fix →
  claims. patterns: isolated, stays.
- two-tabs-converge — two viewers, one write, both see it (converges;
  witnessed in browser world).
- handoff-roundtrip — chip → handoff value; fresh image resumes; state
  identical (stays); cassette replay offline.
- demo-stays-alive — kill a worker tile; supervisor restarts (lively;
  witnessed).
- session-invariant-holds — model world over the session's extracted
  transition graph: every ask answered; no handoff dropped (proven).

* Linchpins

1. Watcher predicate (.bl.md/.bl.org) — gates every file-stays-live claim.
2. Claim ≡ reload bundle gate — never a parallel parse check.
3. Session = defprocess from day one — retrofit = rewrite.
4. Handoff schema versioned + hashed before first consumer.
5. Per-env defs upstream (relay PLAN-060 req A) — verify landed before W5;
   else env restore degrades to global races (unacceptable).

* Landmines

- No umbrella / no AOT hang path (librarium regression note).
- Blueprint v1 scenarios are ordered-only; no interleaved actors yet.
- Cassettes never bill; replay isolates provider creds via env tombstones.
- W5 notebook work is shared between chat view and livebook — build once.

* Open decisions (human)

1. Repo location/name (recommend: fresh dir; archive undefine/spell).
2. Default boot manifest (recommend: core + tasteful stdlib set + ".", not
   all of priv).
3. MCP face timing (recommend: after handoff).
