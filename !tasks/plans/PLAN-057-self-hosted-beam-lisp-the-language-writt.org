* Initial Message

how hard would it be to bootstrap beam lisp fully?

** The one-sentence goal

beam-lisp compiles itself: the reader, the compiler, the runtime primitives,
and the data structures are all written in beam-lisp, bottoming out at Erlang/OTP
BIFs and one Elixir stdlib call (~Code.eval_quoted~), with a committed ~.beam~
seed to break the read-the-reader circularity. Nothing about the *language* is
maintained in Elixir. What remains Elixir is only the OTP *host application* (the
process that runs the language) and a frozen build artifact.

** The doctrine already exists in the codebase — this plan finishes it

~lib/beam_lisp/native.ex~ already states the rule, verbatim:

#+begin_quote
Yet it forced every native capability to enter the system through Elixir, which
contradicts the doctrine the rest of the project follows: as much as possible in
`.bl`, with Elixir keeping only substrate. A NIF is substrate. The *declaration*
that one exists is not.
#+end_quote

This plan applies that exact doctrine to the last, biggest Elixir holdouts: the
reader and the compiler themselves. "Substrate stays; declaration moves." The
compiler is not substrate — it is the most declarative program in the system (a
fold from forms to AST). It belongs in `.bl`.

** The floor, defined by a RULE not a file-list (the critical correction)

Earlier drafts parked rt.ex, env, emit, record, multi, server in Elixir "because
they are there." That confused *currently-Elixir* with *necessarily-Elixir*. The
true floor is only what cannot be `.bl`-expressed without (a) circularity or
(b) a benchmarked perf loss. Evidence gathered 2026-08-29:

- ~.bl~ already calls raw Erlang BIFs directly: 61 ~(erlang/…)~ sites in priv/,
  plus ~(lists/…)~, ~(maps/…)~. The tower bottoms out at OTP, not at us.
- ~.bl~ already calls uppercase Elixir modules by interop everywhere
  (~BeamLisp.Reader/read_string~ in 11 files). So ~(Code/eval_quoted ast)~ needs
  NO custom shim — it is stdlib, called, not written.
- A struct is ~Map.put(m, :__struct__, Mod)~ — ~record.ex~ L156 literally does
  this. The ~.bl~ compiler can emit that map shape directly. defstruct is a
  convenience, not a requirement.
- The persistent Vector is 231 LOC over ~:erlang~ bitwise/tuple BIFs — portable.
- rt.ex's 335 "primitives" are leaf ops over BIFs + our own data-structure
  accessors — ~.bl~-expressible, and once AOT-linked they compile to the SAME
  BEAM code as the Elixir version.

Therefore the floor resolves to EXACTLY:

1. ~priv/bootstrap/*.beam~ — the frozen seed. The AOT-compiled reader+compiler,
   committed as a build artifact. A fresh clone loads it, uses it to recompile
   everything from ~.bl~ source, and asserts the fixpoint. This is the ONE
   irreducible circularity (you cannot read the reader without a reader), and a
   committed artifact is the honest, standard answer (every self-hosted compiler
   ships a seed).
2. The OTP host app — ~application.ex~, ~supervisor.ex~, ~mix.exs~, the dev
   server, the ~mix~ tasks. This is the *process that runs the language*, not the
   language. Keeping it is correct, like Clojure keeping a JVM launcher.
3. ~:erlang~ / ~:lists~ / ~:maps~ / ~Code~ / ~Module~ — OTP + Elixir STDLIB,
   called via interop. Never written by us.
4. A benchmark-exempt handful of hot leaf ops — ONLY if a bench proves the ~.bl~
   version regresses. Default is migrate; exemption must be earned by a number.

Everything else — reader, compiler, all 30 special forms, macro/hygiene, the 335
rt prims, Vector/Set/LazySeq/Sorted/Transient, record/protocol/deftype,
defserver/receive/try — becomes ~.bl~.

** Why Elixir AST, not EAF (settled)

We emit Elixir quoted AST and let ~Code.eval_quoted~ / ~Code.compile_quoted~ do
AST→BEAM. We do NOT target Erlang Abstract Format. The only payoff of EAF is
dropping the Elixir compiler at build time; since the OTP stdlib call
~Code.eval_quoted~ is a one-liner we are glad to keep, targeting EAF would mean
re-deriving struct/protocol/gen_server lowering by hand — pure loss. If a
host-independent backend is ever genuinely needed, the right move is a
target-pluggable emitter (neutral IR → {elixir-ast | eaf}); do NOT build the
second backend until a real need exists (YAGNI).

** THE NUGGETS — recent code-as-data work makes this far more than a port

Reading typed / codebase / system / rewrite / deodorant / native surfaced
realizations that reshape the design. These are the "mind-blowing" payoffs the
user asked us to catch:

*** Nugget 1 — the compiler is the FOURTH fold over one form-walk we already have

~typed/walk~ (typed.bl L389) is a fold: form → tagset, dispatching on
~node-tag~/~node-name~, expanding unknown macros once via
~Compiler/macroexpand_1~, whitelisting special forms. ~codebase/walk-calls~ is
the SAME fold: form → datom facts. The type checker and the call-graph indexer
are two interpretations of one traversal. The compiler is a THIRD: form →
Elixir AST. So we do not invent a compiler traversal — we GRADUATE the shared
~node-form~/~node-tag~/~node-items~/~node-name~/~node-pos~ API (already in
typed.bl L211-238, re-exported by codebase.bl) into a first-class
~priv/reader-node.bl~, and the compiler becomes one more consumer of it. Three
existing passes prove the shape is right BEFORE we write the compiler.

*** Nugget 2 — the compiler can be its own codebase, checked by typed + queried by codebase

Once ~priv/compiler.bl~ exists, it is beam-lisp source. Which means:
- ~typed/check-source~ runs over the compiler and type-checks it (sound-warnings).
- ~codebase/index-source~ turns the compiler into a datom DB: "what breaks if I
  change ~compile-let~?" is a datalog ~impact~ query (codebase.bl L~impact~).
  arity-mismatches / unknown-callees run on the compiler itself.
- ~system/knowledge~ can project the compiler's clause topology as facts and ask
  cross-cutting questions no single checker could.
The self-hosted compiler is not just written in the language — it is the first
large program the language's own analysis tools consume. The compiler
type-checks the compiler. This is the realization: self-hosting closes the loop
that P13c/typed/system were building toward from the other side.

*** Nugget 3 — rewrite/deodorant give us a source-to-source layer the compiler can USE

~rewrite.bl~ has a full match/unify/subst engine (match*, subst*, apply-rules,
prewalk/postwalk, bounded fixpoint) over reader forms, with ~?x~ pattern
variables and rules-as-data. The compiler's macro expander and desugarings
(and/or/when/->/->>) are exactly pattern-directed rewrites. We can express a
chunk of the desugaring layer as ~rewrite~ rules — reviewable data, not buried
~cond~ branches — and ~deodorant~'s tier discipline (SAFE/IDIOMATIC/REINVENTION)
is a template for classifying which desugarings are unconditional. The compiler
gets to eat the language's own codemod engine.

*** Nugget 4 — the seed maker already exists (AOT)

~aot.ex~ already turns a ~.bl~ namespace into a real ~.beam~ on disk
(~write_beam~ L562, ~Code.compile_quoted~, ~__bl_provenance__/0~ self-certifying
the ~.beam~ against its ~.bl~ sha). The frozen seed is not new machinery — it is
~mix compile.beam_lisp~ pointed at ~priv/reader.bl~ + ~priv/compiler.bl~, output
committed to ~priv/bootstrap/~. And ~__bl_provenance__~ gives us the fixpoint
check for free: the seed carries the sha of the source it was built from.

*** Nugget 5 — defnative already modeled "declaration in .bl, substrate in the host"

~native.ex~ moved the *declaration* of a NIF into ~.bl~ (~defnative~) while the
Rust stays substrate. That is the precise pattern for the whole cutover: the
~.bl~ compiler DECLARES how forms lower; ~Code.eval_quoted~ (substrate) executes
the lowering. We are repeating a move the project already validated once, at the
scale of the compiler.

** Architecture — the tower after cutover

#+begin_example
  priv/compiler.bl   forms → Elixir AST         ← the language, in itself
  priv/reader.bl     text → forms
  priv/reader-node.bl the shared form API (graduated from typed/codebase)
  priv/rt/*.bl        the 335 primitives, as .bl over BIFs
  priv/vector.bl …    persistent data structures, as .bl over :erlang bitwise
        │ all of the above call ↓
  :erlang / :lists / :maps / Code / Module     ← OTP + Elixir STDLIB (interop)
        │ compiled by ↓
  priv/bootstrap/*.beam   frozen seed (breaks read-the-reader circularity)
        │ hosted by ↓
  lib/beam_lisp/application.ex + supervisor + mix tasks   ← the OTP host process
#+end_example

Two clean categories remain Elixir: a *frozen artifact* (the seed) and a *host
process* (the OTP app). Neither is language source. That is the maximalist
end-state — every idea about the language, expressed in the language.

** AMENDMENT (after reading optics.bl + specter/) — two-tier compiler

Reading optics and specter surfaced a tempting idea and a hard constraint that
together reshape the architecture.

*** The trap: "a compiler pass IS a specter transform*"

It is literally true — specter's ~transform*~ navigates to subvalues, transforms
them, rebuilds shape-preserving; its CPS ~vals~ accumulator is exactly the
compile env (locals/ns/tail) threaded with short-circuit; optics ~over~ is
exactly "rewrite every node of a shape". So the temptation is to BUILD the
compiler on specter/optics.

Load-order forbids it. The compiler is the BOTTOM of the tower: it compiles
reader.bl then everything else. optics/specter/rewrite/datom/typed are all ~.bl~
COMPILED BY the compiler. A compiler that imported specter would need specter to
exist before the compiler exists → circular, unbootstrappable. The compiler
KERNEL may import nothing but the reader, the node API, and raw BIFs.

*** The escape: TWO-TIER compiler (the real self-hosted shape)

- Tier-0 KERNEL — minimal reader + the ~15 special forms needed to compile the
  language's OWN source. Primitive ~.bl~ (BIFs + node API + a tiny inline
  matcher). Small, self-sufficient, correct-but-unoptimized. This is what gets
  frozen into ~priv/bootstrap/*.beam~ and what the fixpoint proves. Nothing in
  the kernel depends on any library the kernel compiles.
- Tier-1 RICH PASSES — everything optional, built ON TOP of the kernel, free to
  use the full library stack because by then it is compiled: optimization,
  source-analysis, AST post-processing. Correctness in the kernel; delight in
  tier-1. Turn tier-1 off and the kernel still emits correct code.

This is how real self-hosted compilers ship: a tiny bootstrap kernel plus the
full compiler written against the language's own libraries.

*** Nugget 6 — optimization is a datalog query over the program-as-facts (tier-1)

Once ~codebase/index-source~ turns a program into datom facts, OPTIMIZATION
DECISIONS become QUERIES, not ad-hoc analyses:
  - inline candidates: ~[?c :call/callee ?f]~ grouped, count = 1
  - dead code: a defn that is never a ~:call/callee~ and not exported
  - constant-fold sites: calls to pure fns with literal args (purity from
    system/footprint)
  - self-recursive tail loops, unused locals, etc.
The optimizer is a RULESET over facts. "Our optimizer is a set of datalog
queries over the program" is only sayable because self-hosting + datom + codebase
already exist. This is the coolest realization of the read: the language optimizes
itself by querying itself.

*** Nugget 7 — AST post-processing is an optics traversal (tier-1)

The line/meta-stamping the README documents ("thread {line,col,file} onto every
list node") is a traversal: ~(over all-list-nodes stamp ast)~. Tier-1 AST passes
compose like specter paths — a pass is ~path + transform~. optics/specter are
tier-1 dependencies (legal there), giving a principled, composable AST-rewrite
layer instead of hand-rolled recursion.

*** Named, not built — the reader as a prism

A prism is the optic for parse/print (~preview~/~review~). If the reader were a
prism, the pretty-printer would fall out and round-trip laws (~read∘print = id~)
would be testable optic laws. Character-level optics are awkward, so this is
flagged as a future direction, not scope.
