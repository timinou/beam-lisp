* Initial Message

what's the lightest way to do semantic similarity between code, code graphs, and text?

* Context

`priv/lib/datom/vector.bl` ships exact flat-scan similarity (`vec-search` NIF: optional binary-quantised Hamming coarse pass + exact rerank, default rerank width `max(200, 20*k)`). The HNSW NIFs are **declared** (`hnsw-new`, `hnsw-insert`, `hnsw-insert-packed`, `hnsw-tombstone`, `hnsw-search`, `hnsw-search-packed`, `hnsw-stats`) but the **persistent index lifecycle is NOT wired** (flagged as the gap in `docs/design-libraries-mcp-graphrag.md`). At library/corpus scale flat scan is O(n·dim) per `similar-to` clause — every query re-scans the whole corpus.

* Goal

`similar-to` datalog clause resolves through a maintained HNSW index → O(log n) query, while keeping the flat scan as (a) small-corpus path and (b) exact-recall escape hatch (`rerank 0` semantics preserved).

* Design sketch (from docs/design-libraries-mcp-graphrag.md §"index lifecycle")

1. An L3 watch on the embedding attr(s) (e.g. `:chunk/embedding`, `:proc/embedding`, `:doc/embedding`) maintains the HNSW NIF resource incrementally:
   - assert → `hnsw-insert-packed` (re-embed tombstones old entry per NIF contract)
   - retract → `hnsw-tombstone`
2. Index identity = (attr, dims) pair; one HNSW resource per distinct `:db.type/vector` attr.
3. `similar-to` planner: if an index covers the attr and corpus size > threshold → `hnsw-search-packed`; else flat `vec-search`. Expose opt-out (exactness) in clause options.
4. Cold start: rebuild index from current embedding datoms on first use (bulk insert from packed bodies — same corpus-concat path as `search`), persist or rebuild-on-open decision per store backend.
5. Reindex correctness: basis-aware — retracted datoms must not be searchable; the watch basis must match query basis (time-travel queries MUST fall back to flat scan over the historical basis — an HNSW index is inherently current-basis only).

* Edge cases

- Time-travel / as-of queries: index is current-state only → flat scan over basis-filtered datoms. Do NOT serve historical queries from the index.
- Tombstone growth: `hnsw-stats` surfaces live/tombstoned ratio; compaction/rebuild policy needed past a ratio threshold.
- Mixed dimensionality per attr: schema-enforced single dim per attr (`check-dim` already asserts at scan time; index construction must too).
- NIF resource lifetime: index owned by a long-lived process; DB close/reopen must drop/rebuild cleanly.

* Acceptance

- `similar-to` over a ≥100k-embedding corpus answers in O(log n) (bench vs flat scan; expect ≥2 orders of magnitude at 100k×768d).
- Assert/retract through normal transact path is reflected in subsequent `similar-to` results without manual index calls.
- Historical-basis query returns exactly what flat scan returns (test: same corpus, two bases).
- `hnsw-stats` observable; tombstone compaction path exists (even if manual).
