* Initial Message

explain Reel from zero context in simple language, and explain the implementation alongside that

* Why

Reel renders a database it cannot edit. Measured against the live page
(headless browser, 2026-08-24), the whole board carries TWO interactive
controls: a text input and an "Add" button.

| layer                  | can express | reachable in UI |
|------------------------+-------------+-----------------|
| schema attributes      | 36          | ~8 render, 0 editable |
| read.bl queries        | 27          | 8               |
| intent ops             | 7           | 1 (create-task) |
| contract events        | 5           | 1 (:create)     |
| lifecycle transitions  | 9 edges     | 0               |
| role permissions       | 3 roles     | 0               |

`work.bl` builds a lifecycle machine whose stated purpose is "an offered
action is a legal action by construction" — and nothing offers any action.

The root cause is NOT laziness in the view. It is that `spell.machine`
checks the seam in ONE DIRECTION ONLY:

  view fires :x, no contract handles it   → unhandled-fires → ERROR   ✓ exists
  contract handles :x, no view fires it   → (nothing)                 ✗ MISSING

machine.bl's own header, line 18, already names the missing check for
assigns ("a contract declares @x, no registered view renders it → dead
state") and `unrendered-assigns` implements it. The same reasoning was
never applied to EVENTS. Both halves already exist as functions —
`spell.seam/events` and `machine/view-fires` — so the check is a set
difference nobody wrote.

∴ the deliverable is two-part and the order matters: teach the checker to
SEE the gap (so it can never silently reopen), then close the gap it
reports.

* Contract

`unfired-events` is a WARNING, not an error, matching the existing
asymmetry: a handler may legitimately land before its control while a
page is grown one definition at a time. But warnings MUST be printed by
check.exs — silence is what let this reach me as "8/8 passed".

Severity rules, restated so they cannot drift:
  ERROR   = broken NOW (page reads a name nobody publishes)
  WARNING = incomplete (server offers what the page cannot reach)
