* Intent

Derive a complete, accessible form from a datom schema VALUE — the way the
Grammar of Graphics derives a chart axis from a scale. The schema is already a
vector of attribute maps; the form is a pure projection of it. Zero per-form
wiring. This is the flagship demonstration that loom's seven parts compose into a
real feature with NO new primitive.

Blocked on: loom WAVE A (loom.ui field components must exist first — form-for
emits them). This is PLAN-059's WAVE E, extracted to its own item so the core
grammar ships first and form-for is the first thing built ON the finished grammar.

* The one idea

A datom schema is a value: `[{:db/ident :person/name :db/valueType :db.type/string
:db/cardinality :db.cardinality/one} …]`. `datom.schema/valid-value?` already
validates a value against its declared type. So a form is DERIVED — one field per
attribute, its input kind chosen by `:db/valueType`, its validation by the same
predicate the database uses.

* valueType → loom.ui field

| :db/valueType     | field                                |
|-------------------+--------------------------------------|
| :db.type/string   | text input (textarea by :form/multiline hint) |
| :db.type/long     | number input                         |
| :db.type/boolean  | checkbox / switch                    |
| :db.type/keyword  | select (options from :form/enum hint)|
| :db.type/instant  | date/time input                      |
| :db.type/ref      | entity picker (select over a query)  |
| cardinality/many  | a repeatable field group             |

* The surface

: (form-for schema {:on-submit [:intent :save]
:                   :values  {:person/name "Ada" …}   ; current values, pre-fill
:                   :errors  {:person/name "required"} ; per-attr error → aria-wired
:                   :only    [:person/name :person/age] ; optional attr allow-list
:                   :edit?   true})                     ; unique-identity → read-only
→ a loom.ui form (loom/box column of fields + a submit button whose click is the
  given :on-submit intent). `:db/doc` becomes the field hint.

* Acceptance

- pure fn: (form-for schema opts) → hiccup, no side effects (effects.bl provable)
- one field per schema attribute, correct input kind per valueType (table above)
- `:values` pre-fills; `:errors` renders through the aria-wired loom.ui/field
  (aria-invalid + describedby + role=alert — inherited, not re-implemented)
- `:only` filters attributes; `:edit?` makes unique-identity attrs read-only
- a fixture schema in test/bl/loom/form_test.bl exercises every valueType branch
- one `^:catalog` entry (group "Data-driven") whose live example is a working
  form derived from a real schema — the thesis, demonstrated in the catalog
- rendered form is screenshot-reviewed (looks good, not just correct)
