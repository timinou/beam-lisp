* What happened

Wave 21 (optics + rewrite) and the wave-19 prelude work were built by four
parallel workers. Three of them independently hit bugs in beam-lisp itself and
*worked around them*. The workarounds were the finding: each pointed at a root
cause that ordinary code would hit too.

All three were fixed at the root and the workarounds deleted.

** 1. Closures died after three defns (severity: high, scope: the whole language)

Repro, eight lines of entirely ordinary code:

: (ns stale.demo)
: (defn mk [n] (fn [x] (+ x n)))
: (def add5 (mk 5))
: (println (add5 1))     ; => 6
: (defn other [] 1)
: (defn other2 [] 2)
: (defn other3 [] 3)
: (println (add5 1))     ; ** (BadFunctionError) ... points to an old version of the code

Cause: `Link.defvar/4` regenerated the ENTIRE namespace module on every `defn`.
The BEAM keeps exactly two versions of a module; loading a third purges the
oldest, and any closure whose code lived in the purged version becomes invalid.
So the third `defn` after a closure was created killed that closure. Any `.bl`
file with three `defn`s could invalidate a stored fn — which means every `def`
holding a partially-applied or returned function was unreliable.

It also made namespace loading O(N²) in defs.

Fix: split the layer that churns from the layer that holds code. Each `defn`'s
body compiles into an immutable, uniquely-named body module
(`BeamLisp.Ns.Fn.M<unique>`); the per-namespace module keeps only forwarding
shims. Redefinition makes a new body module and repoints the shim.

The constraint that ruled out the obvious alternatives: **direct-call linking
(a measured 26× win) and hot code replacement (a documented, tested headline
feature) both had to survive.** Versioning the module name would have kept
closures alive but broken hot-swap and every test that names `BeamLisp.Ns.*`
directly. The two-layer split is the only design that keeps a stable,
reloadable entry point AND an immutable home for closure code.

Verified: hot-swap still works (`examples/hotswap.bl` still shows v1 → v2
mid-flight with no restart), and the 8-line repro prints 6 twice.

** 2. A lazy-seq thunk could not return a seq (severity: high)

: (reduce conj [] (concat (lazy-seq (concat (lazy-seq (list 1)) (list 2))) (list 3)))
: ** (CaseClauseError) in BeamLisp.RT.concat_from/1

`LazySeq.realize/1` normalized `[]`, `%Vector{}` and `%Set{}` but let a bare
`%LazySeq{}` pass through; `concat_from/1` then matched only `nil` and `[h|t]`.

Clojure's `lazy-seq` bodies return other seqs *routinely* — it is idiomatic. So
this bit constantly: the optics worker and the prelude worker hit it
independently, and the prelude worker restructured `distinct`, `keep` and
`keep-indexed` around it with inner loops.

**When two independent callers break on the same invariant, the invariant is
wrong, not the callers.** Fixed at the single choke point every thunk value
passes through, bounded so a self-referential thunk raises a descriptive error
instead of hanging. Laziness preserved: only the head is normalized, and a test
proves `(take 5 …)` over an infinite seq still forces exactly 5 cells.

The contract is now written down in the moduledoc. Its absence is why the bug
existed — this is the second time in this project that a documented-but-untrue
or never-stated invariant has cost a wave (cf. `FormMeta.form_shape?` in wave
20, which documented a mechanism that had never worked).

** 3. A require resolved by filename, not namespace (severity: high)

`priv/` had just been added to the require search path so beam-lisp libraries
could ship written in beam-lisp. But resolution was by basename, so
`examples/optics.bl` doing `(:require [optics])` found *itself* — loaded the
example as the library, and every var was then missing.

A file's namespace is **declared by its `(ns …)` form**, not implied by its
path. Resolution now reads a candidate's declared ns and keeps searching if it
does not match; the not-found error names the file it found, what that file
declares, and what was wanted. Legitimate project-local overrides (same
basename AND same declared ns) still shadow `priv/`.

* Standing lesson, reinforced

Every one of these was found by **writing real programs in the language**, not
by testing the language. That is now 12+ bugs from this technique. A worker

workaround is the diagnostic.
