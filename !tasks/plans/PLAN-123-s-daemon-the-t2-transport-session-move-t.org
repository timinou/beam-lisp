* Design — the bl namespaces (priv/std/bl/*.bl.md)

Capability-first, maximalist, one namespace per responsibility. Each REPLACES its .ex.

- bl.paths — tree-id (sha256 of realpath), runtime dir (XDG), socket/token/pid/meta
  endpoint paths. Pure fns + :crypto + File. vm.spec already does the id half; this is
  the on-disk path arithmetic. Exit: bl computes its own endpoints; the session takes
  paths from this ONE computation.
- bl.names — DNS-label formatting (name → foo.test / foo.localhost). vm.spec computes the
  :id (name@instance); this is just the host-string half. Exit: gateway + ports read hosts
  from bl.names.
- bl.protocol — the ETF frame codec: encode/decode {:bl 1 :hello|:request|:stdout|:stderr|
  :exit|:stdin_req …}. term_to_binary/binary_to_term + a dispatch map. Exit: client + daemon
  frame through the same bl codec; protocol.ex deleted.
- bl.io — the group-leader proxy: a bl process running an io-request loop that turns
  put_chars/get_line into :stdout/:stdin_req frames, ≤64KiB chunked, synchronous (backpressure).
  Exit: a command's stdout/stdin cross the wire through a bl proxy.
- bl.stderr — the node-global stderr router (install once, route by writing process's group
  leader). Exit: std_err.ex deleted.
- bl.listener — gen_tcp AF_UNIX listen (the proven tuple-opts shape) + accept loop (a process
  per connection) + the 0o600 perms guard + hello/token auth + stdin routing to the io proxy.
  Exit: bl.daemon start binds + accepts in bl; listener.ex deleted.
- bl.daemon (EXISTS — extend) — already the request handler (handle-in-vm) + boot-manager.
  Absorbs daemon.ex's start/stop/status/hello session identity. Exit: bl daemon start/stop/status
  runs a namespace; the handshake + token path PORTED (byte-for-byte), crash-restart demonstrated.
- bl.ports — the claim registry + allocator (--names worktree has read+render+WRITE proven).
  Carry PLAN-117's broker (a listener handed over, not a number reserved — closes the claim→bind
  race). F6: drop [:safe] decode (silently empties the registry for VMs lacking :dest/:unix atoms).
  Exit: bl ports/gateway read a registry whose WRITER is bl; ports.ex deleted.
- bl.inspect — the read model over vm.manager/list-vms + owner counts (per-VM, not single-daemon).
- bl.http — the MCP/dashboard surface (Bandit over unix, proven E1), rendering the per-VM model.

* The private arch — what stays, and the shim

T1 stays (the language machine — RT/Env/AOT/Loader/reader/compiler/runtime types). The T2
substrate the bl namespaces call is a THIN set of BIFs, all proven bl-reachable:
gen_tcp (listen/accept/recv/send/controlling_process/close), ssl (handshake for the gateway),
:crypto, :erlang (term codec, group_leader, monitor, make_ref, send_after), File (chmod/paths),
:global (critical sections), Bandit (HTTP over the socket). None is Elixir POLICY — each is a
runtime capability with a bl name. No new shim module needed; these are BEAM/OTP, not
BeamLisp.Daemon.

* Crash-restart & hot-reload (K10 — the load-bearing care item)

A bl namespace has no OTP supervisor by default AND its namespace state does NOT survive a hot
reload (K10 measured: hits 2→0). Therefore:
- the LISTENER SOCKET, the PORTS REGISTRY, and any ROUTE TABLE live OUTSIDE the reloaded
  namespace — in a separate supervised process / ETS owned by a long-lived owner (the pattern
  vm.owner already uses: the registry is the durable truth, the namespace is a cache).
- the daemon namespace is a child of a super/defsupervisor tree; the accept loop's death is
  visible in the log the verb reads; a crash restarts with a sentence naming what died.
- crash-restart is DEMONSTRATED at D3 (kill the namespace, show the session returns + re-lists
  live VMs from the registry) or D3 does not close. This mirrors PLAN-121 D4 (the manager rebuilds
  its table from the owner registry).

- Two implementations during the move: forbidden. Each stage deletes the .ex in the SAME change.
- Stopping after D4 "because it works", leaving identity/protocol in Elixir. D6's gate makes that
