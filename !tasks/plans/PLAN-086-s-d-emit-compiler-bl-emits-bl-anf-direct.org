the two places where quoted-shape knowledge is deepest — budget them.

CONTRACT (decided 2026-09-04, grounded in compile-defn-clause L2955,

*** The one new node: :defn-clause

```
{:op :defn-clause
 :fname <atom>            ; real BEAM name (name, or name__bl_v for variadic)
 :pats  [pat …]           ; bl-ANF patterns (params; destructuring ALREADY
                          ;   lowered to :case/:let prelude inside :body)
 :guard node | nil        ; sees only head params (guardable-env rule stands)
 :body  node
 :ann   {:kind :fixed|:variadic :fixed-count n :line n :file s}}
```

One node per defn clause. This is exactly `def-head-anf`'s output shape,
made self-describing and attributed. It is the ONLY new vocabulary: every
other top-level form (def, defmacro, ns, defserver, defmulti, bare exprs)
is an ordinary ANF EXPRESSION whose evaluation performs the interning
(:remote nodes to BeamLisp.Env/Link — same as today, minus quoted shape).

*** Wire format preserved

`Link.defvar(ns, name, entries, location)` keeps its signature and its
entry 4-tuple `{kind fixed-count fname clause}`. Only elem 3 changes:
quoted `:def` AST → `:defn-clause` node. Elixir-side consumers
(attach_body_module, fixed_variadic, fn_value) read elems 0-2 — untouched.
`Macro/escape` on entries RETIRES: ANF nodes are already data (maps of
literals); the entries list travels as a `:lit` node whose :val holds the
def-clause nodes. Requirement: cerl literal embedding of nested maps with
atom keys — verify in E2 with one defn before scaling.
