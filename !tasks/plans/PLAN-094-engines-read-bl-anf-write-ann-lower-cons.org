* Goal

One meaning for a program: the proof engines under priv/lib/system/ (and
priv/std/typed.bl, priv/std/termination.bl) read the bl-ANF the backend emits,
write their findings into each node's :ann slot, and lower.bl consumes those
annotations for proof-directed emission. Today the engines re-implement a
fraction of the compiler over surface reader-node trees; they are conservative
wherever a macro is involved and unsound in a few local-naming cases.

* Contract

** Engine entry points keep their signatures

Every consumer today hands a reader node (typed/parse-clause, read1) or a
source string. Entry points keep accepting those; internally they compile to
ANF via compiler/compile-node with a scratch env and walk the ANF. New
ANF-native entry points are added alongside (fp-anf, model/from-descriptor)
for callers already holding IR (the compiler pipeline, dev.change verify).
∴ ~60 consumer files need no signature change.

** Answers change only in the documented direction

More precise (macro forms no longer :opaque-world) or more sound (locals are
not named resources). Any test asserting :opaque-world for a threaded or
macro form asserts a limitation; updating it is the acceptance criterion.

** :ann keys owned by engines

:footprint {resource → mode} · :rung · :terminates {:measure :dir} ·
:type sort · :bound closed-form heap bound. Engines only add keys; :line/:file
remain the compiler's. Values must be finite eager data (anf/module refuses
LazySeq).

** lower.bl consumption is opt-in per key

lower-anf reads :ann and may choose emission (e.g. unboxed arithmetic when
:type ⊆ Int with :bound). Absence of a key = today's emission. Never a
correctness dependency on an annotation; a wrong proof is a catastrophe, a
missing proof is the ordinary path.

** Alias environment

ANF names every intermediate. Engines carry {local → aliased global};
computed locals are :opaque-world; :case/:recv pattern vars and let
rebinding shadow. Reference implementation: fp-anf.bl.

* codebase re-examined: higher-order transparency via 0-CFA (2026-09-06)

The earlier codebase verdict ("defer holds") answered a WEAKER question than the
one that matters. codebase_reach.bl showed macroexpand-1 already handles nested
macros and that a SINGLE ANF node leaves (apply f x) opaque. But it did not try
FLOW ANALYSIS — the actual technique for higher-order transparency. Prototype
cfa.bl (committed fbc1638) does, and it works.

** Mechanism

0-CFA over bl-ANF: the abstract value of each flow variable is a set of top-level
function names that can reach it; least-fixpoint over constraints:
  (:global g) ⟹ {g} ⊑ AV(node)
  let x=e     ⟹ AV(e) ⊑ AV(x)
  invoke callee actuals, g∈AV(callee) ⟹ AV(actualᵢ)⊑AV(paramᵢ of g); edge→g
ANF is the enabler: alpha-renamed locals are free global flow keys, and every
call argument is an atom, so a function passed as data is a visible (:global g)
that the fixpoint propagates into the callee's parameter.

** Measured (three regimes)

- higher-order: (apply-twice inc2 5) → edge apply-twice→inc2 recovered — the call
  made through parameter f, invisible to surface AND single-node ANF, now found.
- polymorphic: run called with dispatch AND dbl → BOTH edges (sound over-approx,
  no target dropped).
- honest opacity: ((chooser) x) where chooser is an external value → NO edge
  invented (unknown stays unknown). Sound without being dishonest.
